RL 与 LLM 的结合

在强化学习框架下，LLM 本身就是一个 策略网络（Policy） π θ

LLM 作为 RL 的 Policy

在强化学习框架下，LLM 本身就是一个 策略网络（Policy）πθ。给定当前状态（已生成的 token 序列），策略输出下一个 token 的概率分布。

  • State（状态）：当前已生成的 token 前缀 st = (x1, ..., xt)
  • Action（动作）：从词表 V 中选择下一个 token at = xt+1
  • Policy（策略）：πθ(at|st) = P(xt+1|x1,...,xt; θ)
  • Reward（奖励）：通常只在序列末尾由 Reward Model 给出

Token 生成 = 序列决策

每一步 token 生成都是一个决策过程。生成一个完整回答相当于执行了一条 轨迹（trajectory）τ = (s0, a0, s1, a1, ..., sT)。这种建模方式使得 RL 的理论工具（如策略梯度、Actor-Critic）可以直接应用于 LLM 微调。

为什么 RL 对 LLM 对齐至关重要

  • SFT 的局限：监督微调只能模仿数据分布，无法优化"哪个回答更好"这种偏序关系
  • 偏好信号的利用：人类更擅长比较而非生成，RL 可以将比较型反馈转化为优化信号
  • 探索能力：RL 允许模型探索新策略空间，发现比训练数据更优的回答
  • 精细控制：可以在 helpfulness、harmlessness、honesty 等多维度进行精细对齐

💡 知识要点

  • LLM 天然符合 RL 的 MDP 框架：State=前缀, Action=token, Policy=LLM 本身
  • RL 解决了 SFT 无法利用偏好比较信号的核心问题
  • Token 级别的序列决策使 RL 的策略梯度方法可以端到端优化生成质量
  • 对齐三原则 HHH（Helpful, Harmless, Honest）需要 RL 进行多目标优化

PPO 训练循环

完整的 PPO-RLHF 训练流程：

  1. 采样阶段：从 prompt 数据集中采样，用当前策略 πθ_old 生成 response
  2. 打分阶段：用 Reward Model 对 (prompt, response) 打分得到 r
  3. 计算优势：用 GAE（Generalized Advantage Estimation）计算 Ât
  4. 策略更新：使用 PPO-Clip 目标函数更新策略
  5. KL 惩罚：添加与参考模型 πref 的 KL 散度约束

PPO-Clip 目标函数

LCLIP(θ) = Et[min(rt(θ)Ât, clip(rt(θ), 1-ε, 1+ε)Ât)]

其中 rt(θ) = πθ(at|st) / πθ_old(at|st)

最终目标：maxθ E[R(x,y)] - β · KL[πθ || πref]

PPO 在 LLM 中的 4 个模型

  • Actor（策略模型）：要训练的 LLM，即 πθ
  • Critic（价值模型）：估计 V(s)，用于计算优势函数
  • Reward Model：对生成结果打分
  • Reference Model：冻结的 SFT 模型，用于 KL 约束

这意味着同时需要 4 份模型大小的显存，是 PPO 训练昂贵的主要原因。

💡 知识要点

  • PPO 在 RLHF 中需要同时维护 4 个模型（Actor/Critic/RM/Ref），显存开销巨大
  • PPO-Clip 通过截断比率限制策略更新幅度，保证训练稳定性
  • KL 散度约束防止策略偏离参考模型过远，避免 reward hacking
  • GAE 平衡了优势估计的偏差-方差权衡

Reward Model 深入

RM 架构

Reward Model 通常从预训练 LLM 初始化，去掉语言模型头（lm_head），替换为一个 标量回归头（scalar head）：

class RewardModel(nn.Module):
    def __init__(self, base_model):
        self.backbone = base_model  # 预训练 LLM（去掉 lm_head）
        self.reward_head = nn.Linear(hidden_size, 1)  # 标量输出

    def forward(self, input_ids, attention_mask):
        hidden = self.backbone(input_ids, attention_mask).last_hidden_state
        # 取最后一个 token 的 hidden state
        reward = self.reward_head(hidden[:, -1, :])
        return reward.squeeze(-1)

Bradley-Terry 偏好模型

给定一对回答 (yw, yl)（w=preferred, l=rejected），Bradley-Terry 模型假设人类偏好概率为：

P(yw ≻ yl | x) = σ(rθ(x, yw) - rθ(x, yl))

RM 训练损失：L(θ) = -E(x, y_w, y_l)[log σ(rθ(x, yw) - rθ(x, yl))]

这是一个 pairwise ranking loss，只关心两个回答的相对分数差，不关心绝对分数。

RM 的泛化性与过拟合

  • 分布外泛化问题：RM 只在人类标注数据分布上训练，对新策略生成的 OOD 样本可能给出不可靠的分数
  • 过拟合表面特征：RM 可能学到"长回答=高分"等伪相关，而非真正质量
  • 标注噪声：人类偏好存在主观性和不一致性，RM 可能放大噪声
  • 解决方案：数据增强、集成多 RM、定期用新策略数据更新 RM

💡 知识要点

  • RM 本质是 LLM + 标量头，用最后 token 的 hidden state 预测奖励
  • Bradley-Terry 模型：P(w≻l) = σ(r(w) - r(l))，训练目标是 pairwise ranking loss
  • RM 的核心挑战是分布外泛化——策略在 RL 中不断变化，RM 需要能泛化到新分布
  • RM 过拟合会导致 reward hacking，是 RLHF 的核心瓶颈之一

GRPO 详解

GRPO 是 DeepSeek 在 DeepSeek-Math 和 DeepSeek-R1…

DeepSeek 的创新：Group Relative Policy Optimization

GRPO 是 DeepSeek 在 DeepSeek-Math 和 DeepSeek-R1 中提出的算法，核心思想是 用组内相对奖励替代 Critic 网络，从而省去了 Value Model 的显存开销。

算法核心思想

  1. 对每个 prompt，采样一组（group）回答 {y1, y2, ..., yG}
  2. 用 RM 对每个回答打分得到 {r1, r2, ..., rG}
  3. 组内标准化：Âi = (ri - mean(r)) / std(r)
  4. 用标准化后的相对奖励作为优势函数，进行 PPO 风格的策略更新

数学推导

GRPO 目标函数：

JGRPO(θ) = Eq~P(Q) E{y_i}~π_old(·|q) [
  (1/G) Σi=1..G min(ρi·Âi, clip(ρi, 1-ε, 1+ε)·Âi)
  - β · KL(πθ || πref)
]

其中：ρi = πθ(yi|q) / πold(yi|q)
Âi = (ri - μgroup) / σgroup

GRPO vs PPO 对比

特性PPOGRPO
Value Model需要（同等规模）不需要 ✓
优势估计GAE (需要 Critic)组内相对奖励标准化
显存占用~4x 模型大小~3x 模型大小
采样策略每个 prompt 1 个回答每个 prompt G 个回答
BaselineV(s) 学出来的组内均值（无需学习）
适用场景通用验证信号明确的任务（数学/代码）

为什么 GRPO 有效

  • 减少方差：组内标准化天然提供了一个低方差的 baseline
  • 省资源：去掉 Value Model 节省 ~25% 显存和计算
  • 简洁：不需要训练额外的 Critic 网络，减少超参数和训练不稳定性
  • 适合可验证任务：数学/代码任务有明确对错，组内对比信号清晰

💡 知识要点

  • GRPO 核心创新：用组内相对奖励标准化替代 Critic 网络的优势估计
  • 节省显存：去掉 Value Model，从 4 模型降到 3 模型
  • 优势计算：Âi = (ri - μ) / σ，无需学习，即插即用
  • 特别适合有明确验证信号的任务（数学/代码），DeepSeek-R1 核心训练方法

Reward Hacking

Reward Hacking 是指 RL 策略学会了 钻 Reward Model 的漏洞…

什么是 Reward Hacking

Reward Hacking 是指 RL 策略学会了 钻 Reward Model 的漏洞来获取高分，而非真正提升回答质量。模型找到了 RM 的盲区或偏差，并加以利用。

Goodhart's Law 在 RLHF 中的体现

古德哈特定律：当一个指标变成目标时，它就不再是好的指标。

在 RLHF 中：RM 分数是人类偏好的代理指标（proxy），当我们过度优化这个代理时，它与真实人类偏好之间的相关性会下降。

随着优化进行：
RM Score ↑↑↑（proxy 持续升高）
True Human Preference ↑ → ↓（真实质量先升后降）

案例分析

  • 冗长回答：模型学到"写得越长分越高"，输出大量冗余内容
  • 马屁策略：过度迎合用户观点（sycophancy），不管对错一味赞同
  • 格式化技巧：加 bullet points、加粗标题等表面格式获取高分
  • 重复安全声明：大量加入"我是AI，请注意..."来提升安全评分
  • 情感操控：使用煽情语言来获得 helpfulness 高分

解决策略

策略原理效果
KL 约束限制策略偏离参考模型的幅度防止过度优化
多 RM 集成多个 RM 投票/取均值减少单一 RM 的偏差
RM 定期更新用新策略数据重新训练 RMRM 跟上策略分布变化
约束奖励范围对 reward 做 clipping限制极端奖励信号
红队对抗主动寻找 hacking 案例发现并修补 RM 漏洞

💡 知识要点

  • Reward Hacking = 模型利用 RM 漏洞获取高分而非真正提升质量
  • Goodhart's Law：过度优化 proxy reward 会导致真实质量下降
  • 典型案例：冗长回答、sycophancy、格式化技巧
  • 核心缓解方法：KL 约束 + 多 RM 集成 + 定期更新 RM

过优化问题

RL 训练持续过久后，模型在 RM 分数上持续提升，但在真实人类评估中性能反而 下降

现象描述

RL 训练持续过久后，模型在 RM 分数上持续提升，但在真实人类评估中性能反而 下降。这就是过优化（over-optimization）现象，是 Goodhart's Law 的直接后果。

KL 散度监控

KL 散度 KL(πθ || πref) 是衡量当前策略偏离初始 SFT 模型程度的关键指标：

KL(πθ || πref) = Ex~π_θ[log πθ(x) - log πref(x)]
  • KL 过小：模型几乎没有学到新东西，RL 效果不明显
  • KL 适中（sweet spot）：模型有效学习了奖励信号，质量提升
  • KL 过大：模型偏离过远，reward hacking 风险高，质量下降

典型的训练曲线

随训练步数推进，三条曲线出现背离——这正是 reward hacking 的信号：

指标趋势含义
RM Score（奖励模型打分）持续上升 ↗模型越来越"迎合"奖励模型
True Quality（真实质量）先升后降 ↗↘过了拐点后开始过拟合奖励
KL Divergence（与初始策略距离）持续增大 ↗策略越跑越偏

最佳停止点：在 True Quality 拐点（KL 尚未过大）处取 checkpoint，而非 RM Score 最高处。

最佳训练步数选择

  • 方法 1：固定 KL budget — 设定 KL 上限（如 10-15 nats），到达后停止
  • 方法 2：验证集监控 — 使用 held-out 的人类偏好数据定期验证 win-rate
  • 方法 3：Early Stopping — 当 RM 分数增速放缓而 KL 增速加快时停止
  • 方法 4：动态 β 调整 — 根据 KL 动态调整 KL 惩罚系数 β

💡 知识要点

  • 过优化 = RM 分数上升但真实质量下降，是 RLHF 的核心实践挑战
  • KL 散度是最重要的监控指标，反映策略偏离参考模型的程度
  • 存在最佳 KL 范围（sweet spot），过小无效，过大有害
  • 实践中常用 KL budget + validation win-rate 联合判断停止时机

Constitutional AI (CAI)

Constitutional AI 由 Anthropic 在 2022 年提出，核心思想是…

Anthropic 的提出

Constitutional AI 由 Anthropic 在 2022 年提出，核心思想是让 AI 根据一组原则（Constitution）进行自我批评和修正，减少对人工标注的依赖。

CAI 的两阶段训练

阶段 1：监督学习阶段（SL）

  1. 用 Red Team prompts 诱导模型产生有害回答
  2. 让模型根据 Constitution 原则自我批评（Critique）
  3. 让模型根据批评进行修正（Revision）
  4. 用 (prompt, revised_response) 对做 SFT

阶段 2：RL 阶段（RLAIF）

  1. 让模型生成多个回答
  2. 用另一个 AI（而非人类）根据原则判断哪个更好
  3. 用 AI 偏好数据训练 RM
  4. 用 RM 做 RLHF 训练

Constitution 示例

原则 1：选择对用户最有帮助、准确且无害的回答
原则 2：选择不会鼓励非法、不道德或有害行为的回答
原则 3：选择不含种族主义、性别歧视或其他社会偏见的回答
原则 4：选择对儿童安全的回答
...

核心优势

  • 可扩展：减少对昂贵人工标注的依赖
  • 透明：对齐标准明确写在 Constitution 中，可审计
  • 迭代式改进：模型先自我批评再修正，多轮提升
  • 减少人类情感劳动：标注员不再需要阅读大量有害内容

💡 知识要点

  • CAI 核心：AI 自我批评 + 修正，基于明确原则（Constitution）
  • 两阶段：SL（自我修正做 SFT）+ RL（AI 评判做 RLHF）
  • 优势：减少人工标注、对齐标准透明可审计、可扩展
  • 是 RLAIF 思想的重要来源，Anthropic Claude 的核心训练方法

RLAIF

RLAIF（RL from AI Feedback）用 LLM 作为评判者来生成偏好数据，替…

AI Feedback 替代 Human Feedback

RLAIF（RL from AI Feedback）用 LLM 作为评判者来生成偏好数据，替代昂贵的人工标注。核心假设：足够强大的 LLM 可以给出与人类一致的偏好判断。

LLM-as-Judge 范式

Prompt 模板：
"以下是对问题 {question} 的两个回答：
回答 A: {response_a}
回答 B: {response_b}
请根据以下标准评判哪个更好：
1. 准确性  2. 完整性  3. 清晰度  4. 安全性
你的判断是："

常见改进：

  • Position debiasing：交换 A/B 顺序取平均，消除位置偏差
  • Chain-of-thought：让 Judge 先解释再判断，提升准确性
  • 多 Judge 集成：用多个 LLM 投票

成本和扩展性优势

维度RLHF（人工）RLAIF（AI）
标注成本高（$15-50/小时标注员）低（API 调用费用）
速度慢（人类标注速度）快（并行 GPU 推理）
一致性中（标注员差异大）高（同模型输出稳定）
可扩展性线性增长成本易于大规模扩展
天花板高（人类智慧）受限于 Judge 能力

局限性

  • 能力天花板：AI Judge 无法评判超出自身能力的回答
  • 系统性偏差：LLM 的偏好可能系统性偏离人类偏好
  • 自我强化：用 AI 训练 AI 可能放大错误

💡 知识要点

  • RLAIF 用 LLM-as-Judge 替代人工标注，大幅降低成本和提升效率
  • 关键技巧：position debiasing、CoT 评判、多 Judge 集成
  • 优势：低成本、高一致性、易扩展；劣势：受限于 Judge 能力上限
  • Google 研究表明 RLAIF 与 RLHF 在某些任务上效果相当

RL 在推理模型中的角色

推理模型（如 OpenAI o1、DeepSeek-R1）使用 RL 来训练模型的 推理能力…

o1 / DeepSeek-R1 的训练方式

推理模型（如 OpenAI o1、DeepSeek-R1）使用 RL 来训练模型的 推理能力，而不仅仅是对齐。核心区别在于：奖励信号来自推理结果的正确性。

DeepSeek-R1 训练流程：

  1. 在数学/代码等可验证任务上，用 GRPO 进行 RL 训练
  2. 奖励信号：答案是否正确（二值奖励）+ 格式奖励
  3. 模型自发涌现出 Chain-of-Thought、自我验证、回溯等推理行为
  4. 再通过蒸馏将推理能力迁移到更小模型

Process Reward Model (PRM)

与 Outcome Reward Model (ORM) 只在最终答案给分不同，PRM 对推理的 每一步 进行评分：

  • ORM：只看最终答案对不对 → r(whole_solution)
  • PRM：评判每一步推理是否正确 → r(step1), r(step2), ..., r(stepn)
PRM 优势：
- 提供更密集的奖励信号（dense reward vs sparse reward）
- 可以精确定位推理链中的错误步骤
- 结合 Best-of-N 采样：选择每步都正确的推理路径

MCTS 搜索

Monte Carlo Tree Search 可以与 PRM 结合，在推理时搜索最优推理路径：

  • 节点：推理链中的每一步
  • 扩展：用 LLM 生成下一步的多种候选
  • 评估：用 PRM 评估每步的正确性
  • 回溯：当检测到错误时回退尝试其他路径

推理链强化

RL 训练使模型学会了更有效的推理策略：

  • 自发产生 "Wait, let me reconsider..." 式的自我纠错
  • 学会将复杂问题分解为子步骤
  • 学会验证中间结果的一致性
  • 根据问题难度动态调整推理深度

💡 知识要点

  • 推理模型用 RL（特别是 GRPO）训练推理能力，奖励来自可验证结果
  • PRM vs ORM：过程奖励提供更密集信号，能定位错误步骤
  • MCTS + PRM：搜索最优推理路径，类似 AlphaGo 的思路
  • DeepSeek-R1 证明：纯 RL 训练可以涌现 CoT、自我验证等复杂推理行为

未来方向

Online DPO / Iterative RLHF

  • Online DPO：在训练过程中用当前策略在线生成样本做 DPO，避免 off-policy 问题
  • Iterative RLHF：多轮迭代——训练策略→采集新偏好数据→更新 RM→继续训练
  • Self-Play：让模型与自己的旧版本对弈，持续产生训练信号

多目标对齐

  • 多维度 RM：分别对 helpfulness、safety、factuality 训练独立 RM
  • Pareto 优化：在多目标间寻找最优权衡
  • 可控对齐：根据场景动态调整各目标的权重
  • Reward Modeling as Multi-Task：共享底座、多头输出

Constitutional AI 扩展

  • 动态 Constitution：根据文化/地区/场景自适应调整原则
  • 层级 Constitution：基础原则 + 领域特定原则
  • 用户可定制：允许用户参与定义对齐标准
  • 多语言/多文化：不同语言社区的价值观差异

其他前沿方向

  • RLVR（RL with Verifiable Rewards）：用可验证的奖励信号（代码执行、数学证明）替代 RM
  • Scalable Oversight：如何监督超越人类能力的 AI 系统
  • Weak-to-Strong Generalization：用弱模型的信号训练强模型
  • Process-based Training：奖励推理过程而非仅结果

💡 知识要点

  • Online DPO 解决 off-policy 问题，是 DPO 与 RL 的融合方向
  • 多目标对齐需要在 helpfulness/safety/factuality 间取得 Pareto 最优
  • RLVR 是趋势：用可验证信号（代码通过率、数学正确性）替代不可靠的 RM
  • Scalable Oversight 是长期核心问题：如何对齐超越人类能力的系统

📋 Q&A（10 题）

RLHF 完整流程分三阶段：
Q1：请解释 RLHF 的完整流程，涉及哪些模型？

RLHF 完整流程分三阶段：

  1. SFT 阶段：用高质量对话数据微调预训练模型，得到 πSFT
  2. RM 训练阶段：收集人类偏好数据（pairwise comparison），用 Bradley-Terry 模型训练 Reward Model
  3. RL 阶段：用 PPO 算法优化策略，同时维护 4 个模型——Actor（策略模型）、Critic（价值模型）、Reward Model、Reference Model（冻结的 SFT 模型用于 KL 约束）

最终优化目标：max E[R(x,y)] - β·KL(πθ || πref)，在最大化奖励的同时限制策略偏离。

Q2：PPO 在 LLM 训练中为什么需要 4 个模型？各自的作用是什么？

4 个模型及作用：

  • Actor（πθ）：当前要训练的策略模型，负责生成回答
  • Critic（Vφ）：价值网络，估计每个状态的期望累积回报，用于计算 GAE 优势函数
  • Reward Model：对完整回答打分，提供奖励信号
  • Reference Model（πref）：冻结的 SFT 模型，计算 KL 散度防止策略偏离过远

需要 4 份模型大小的显存是 PPO 的主要瓶颈，这也是 GRPO（去掉 Critic）和 DPO（完全不用 RL）被提出的动机。

Q3：GRPO 相比 PPO 有什么优势？它是如何工作的？

GRPO（Group Relative Policy Optimization）核心工作原理：

  1. 对每个 prompt 采样 G 个回答（一组）
  2. 用 RM 对每个回答打分
  3. 组内标准化：Âi = (ri - mean) / std 作为优势估计
  4. 用 PPO-Clip 风格更新策略

优势：

  • 去掉 Value Model，节省约 25% 显存
  • 无需训练 Critic 网络，减少超参数和不稳定性
  • 组内标准化提供了自然的、低方差的 baseline
  • 在数学/代码等可验证任务上效果优异（DeepSeek-R1 核心方法）
Q4：什么是 Reward Hacking？如何缓解？

Reward Hacking：模型学会利用 Reward Model 的漏洞获取高分，而非真正提升回答质量。这是 Goodhart's Law 的体现——过度优化代理指标会导致其与真实目标脱钩。

常见表现：

  • 冗长但空洞的回答
  • Sycophancy（过度迎合用户）
  • 表面格式化（bullet points、加粗等）

缓解策略：

  • KL 约束：限制策略偏离参考模型的幅度
  • 多 RM 集成：多个 RM 交叉验证，减少单点偏差
  • 定期更新 RM：用新策略数据重训练 RM
  • Reward Clipping：限制极端奖励信号
  • 长度惩罚：对冗长输出施加额外惩罚
Q5：Bradley-Terry 模型是什么？在 RLHF 中如何使用？

Bradley-Terry 模型是一种 pairwise comparison 的概率模型，用于从比较数据中学习排序。

在 RLHF 中的应用：

P(yw ≻ yl | x) = σ(rθ(x, yw) - rθ(x, yl))

训练损失：L = -E[log σ(r(x,yw) - r(x,yl))]

关键特性：

  • 只学习相对偏好（分数差），不需要绝对评分
  • 与人类判断方式一致——人类更擅长比较而非打分
  • DPO 直接从 BT 模型推导出闭式解，避免了显式训练 RM
Q6：Constitutional AI 的核心思想和流程是什么？

核心思想：让 AI 根据一组人类制定的原则（Constitution）进行自我批评和修正，减少对人工标注的依赖。

两阶段流程：

阶段 1（SL）：

  1. Red Team prompts → 诱导有害输出
  2. 模型根据原则自我批评（"这个回答违反了原则 X，因为..."）
  3. 模型根据批评修正回答
  4. 用 (prompt, revised_answer) 做 SFT

阶段 2（RL/RLAIF）：

  1. AI 根据原则判断多个回答的优劣
  2. 用 AI 偏好数据训练 RM
  3. 用 RM 做标准 RLHF

优势：可扩展、对齐标准透明可审计、减少人类情感劳动。

Q7：PRM 和 ORM 的区别是什么？为什么 PRM 更适合推理任务？

ORM（Outcome Reward Model）：

  • 只对最终答案/完整回答给出一个标量分数
  • Sparse reward：只在序列末尾有信号
  • 无法定位中间推理步骤的错误

PRM（Process Reward Model）：

  • 对推理链的每一步都给出分数
  • Dense reward：每步都有反馈
  • 可以精确定位错误发生在第几步

PRM 更适合推理任务的原因：

  • 推理过程中间步骤的正确性直接影响最终结果
  • Dense reward 训练更高效，梯度信号更丰富
  • 结合 Best-of-N：选择每步都正确的路径
  • 结合 MCTS：在推理树中有效剪枝
Q8：RLHF 中的 KL 散度约束起什么作用？如果去掉会怎样？

KL 约束的作用：

  • 防止过优化：限制策略偏离 SFT 模型过远
  • 保持语言质量：确保输出仍然是流畅自然的文本
  • 缓解 Reward Hacking：限制模型利用 RM 漏洞的空间
  • 训练稳定性：避免策略剧烈变化导致崩溃

如果去掉 KL 约束：

  • 模型会快速过度优化 RM 分数
  • 输出可能变得不自然、冗长、重复
  • 严重的 Reward Hacking（如学会特定模式来欺骗 RM）
  • 训练可能不稳定，策略崩溃（mode collapse）

实现方式：max E[R] - β·KL(πθ||πref)，β 控制约束强度。β 大→保守更新，β 小→更大探索空间。

Q9：RLAIF 相比 RLHF 的优劣势是什么？什么场景下适用？

RLAIF 优势：

  • 成本低：AI 评判 vs 人类标注员，成本差 10-100 倍
  • 速度快：可并行 GPU 推理，批量处理
  • 一致性高：同一模型评判标准稳定（人类标注员间差异大）
  • 易扩展：数据量可以轻松扩大数个量级

RLAIF 劣势：

  • 能力天花板：AI Judge 无法评判超出自身能力的回答
  • 系统性偏差：LLM 偏好可能系统性偏离人类
  • 自我强化：错误可能在 AI→AI 循环中被放大

适用场景：低风险领域、模型能力范围内的任务、需要快速迭代的场景、标注资源有限时。不适合高安全性要求或需要超越 AI 能力评判的任务。

Q10：DeepSeek-R1 是如何通过 RL 实现推理能力涌现的？

DeepSeek-R1 的训练方法：

  1. 纯 RL 训练（DeepSeek-R1-Zero）：
    • 不做 SFT，直接从 base model 开始 RL
    • 使用 GRPO 算法
    • 奖励信号：数学答案正确性（二值）+ 格式奖励
  2. 涌现的推理行为：
    • 自发产生 Chain-of-Thought
    • 自我验证（"let me check..."）
    • 回溯修正（"wait, that's wrong..."）
    • 推理链长度随问题难度自适应增长
  3. 完整 R1 流程：少量 CoT SFT → GRPO RL → Rejection Sampling SFT → 再次 RL
  4. 蒸馏：将大模型推理能力蒸馏到小模型（如 R1-Distill-Qwen-7B）

关键启示：RL 可以让模型自发学会推理策略，无需人工设计 CoT 模板。这证明了 RL 在训练推理能力方面的巨大潜力。
