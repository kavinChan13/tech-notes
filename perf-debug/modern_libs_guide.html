C++ 现代库选型指南

Boost · Abseil · Folly · TBB · Seastar · EASTL · 序列化 · 日志 · 引入策略。这是选型，不是各库 API 教程。

2026 实践 选型导向 四轴权衡 vs STL
01

引言

四轴 · Build/Use/Embrace · 评估维度 · 和其他页的分工

选型不是 API 教程

中等规模后端很容易挂上三十个库。本页只回答该不该引入、引入哪一个、代价是什么。CMake / vcpkg / Conan 的写法见 CMake & CI 与 CMake 心智模型；fmt / spdlog / 结构化日志见 可观测性。ABI 风险见 ABI 兼容性。

选库像进五金店：拧一颗螺丝不必把整间店搬回家。Boost 是货架，Abseil 是店里常备的那一箱工具，Folly 是带液压机的车间——后者能干活，但你得先有厂房和电。

1.1 四轴，不是谁最快

1.2 Build / Use / Embrace

策略含义典型
Build自己造，核心路径独家算法、业务协议
Use用库，但留适配层JSON / HTTP / 测试
Embrace绑死生态，不再迁移Asio / Protobuf / OpenSSL

Tech Lead 的判断是：哪些该 embrace，哪些只 use（可换），哪些根本不该进仓库。

1.3 八个评估维度

维度问什么
活跃度半年有没有 commit / 发版
LicenseMIT / Apache / BSL？GPL 过法务了吗
编译时长Spirit 一类模板能否 +10 min
体积静态链接涨多少 MB
CVE安全审计与响应速度
平台Linux / Windows / 嵌入式？MSVC？
退出成本停更之后多久能换掉
重复仓库里是否已有同类（absl + folly + boost 三套哈希）

03

Boost

按件取 · 别当框架 · header-only vs 编译库

工具箱不是框架

Boost 是 C++ 的「第二标准库」：shared_ptr / filesystem / optional 都从这里进 STL。2026 年仍有 150+ 子库，典型项目只用 5–10 个。按件取，不要 #include 全家桶。

3.1 仍值得用（2026）

子库何时用何时不用代价
Asio / Beast异步 IO、HTTP已有 Seastar / 自研栈头依赖深；可 standalone
Interprocess共享内存 IPC只用管道 / socket平台细节多
Lockfree无锁队列mutex 够用API 易用错
MultiIndex内存里多键查询一个 unordered_map 够模板重、编译慢
Containersmall_vector / flat_mapC++23 flat_map 已可用和 absl 功能重叠
PFRaggregate 反射等 C++26 reflect不能有虚函数
SpiritPEG 解析ANTLR / 手写编译时长杀手

3.2 已被 STL 取代

Thread / SharedPtr / Lambda / Filesystem / Optional / Variant / Any / Format / Atomic / Bind / Function —— 一律走标准库。看见 boost::thread 当遗留债清。

3.3 header-only vs 编译库

选型时先分清两种引入面：只 include 的库几乎没有 ABI 面；要链接 .a/.so 的库会钉版本、涨体积、把 Live-at-HEAD 的痛带到动态库边界。CMake 形态见 find_package。

# header-only：include 即用，无 .so ABI
find_package(nlohmann_json CONFIG REQUIRED)
target_link_libraries(app PRIVATE nlohmann_json::nlohmann_json)

# 编译库：链接实现，版本与 ABI 一起钉死
find_package(Protobuf CONFIG REQUIRED)
target_link_libraries(app PRIVATE protobuf::libprotobuf)

3.4 包袱

一个 boost::asio include 可拖上百个头；大项目几乎必上 PCH + ccache。跨 1.65→1.84 有 API 断裂。建议：① standalone Asio；② 只挑真用的子库；③ 能 STL 替代就替代。

04

Abseil

Google 生产子集 · Live at HEAD · 不要和 Folly 叠打底

新项目打底的优选

Abseil = Google 把内部 C++ 基础库开源的那一份生产子集：哈希、Status、字符串、时间。质量稳，比 Folly 轻，比「再造一套 STL」务实。

4.1 该拿什么

组件何时用何时不用代价
flat_hash_maphot path 查找需要指针稳定 / 节点插入rehash 使指针失效
StatusOr全项目统一错误已全面 expected宏风格与 STL 两套
StrCat / Cord大字符串拼接几段 format 就够多一套字符串类型
flags / logGoogle 系代码已有 CLI11 / spdlog生态绑死

4.2 flat_hash_map 取舍

#include <absl/container/flat_hash_map.h>
absl::flat_hash_map<std::string, int> m;
m["alice"] = 30;   // open addressing，cache 友好；rehash 后指针失效

要稳定指针用 absl::node_hash_map。成本：模板编译偏重；Live at HEAD，不要把 absl 类型送出 .so。

05

Folly

Facebook 更激进 · 依赖重 · MSVC 差

大厂 Linux 性能栈，不是中小项目打底

Folly = Meta 更激进的那一套：协程、F14、无锁结构、IOBuf。创新比 Abseil 多，编译依赖也重一个数量级（Boost、glog、OpenSSL、一堆编解码）。中小项目通常 Abseil 更合适；要协程/无锁再单拉组件，不要整库打底。

5.1 定位与代价

组件何时用何时不用代价
coro / FutureLinux 服务异步编排已有 Asio 协程 / Seastar整库依赖
F14 / ConcurrentHashMap比 absl 还要挤 CPUflat_hash_map 已够与 absl 重叠
Synchronized<T>强制「访问必加锁」已有清晰 mutex 纪律多一层封装
IOBuf / MPMC网络缓冲、无锁队列业务 QPS 一般心智贵
Folly 几乎不发「稳定 ABI 版」。Windows 团队、编译时长敏感、依赖审计严的，默认不选。
06

Intel TBB / oneAPI

任务图 · 工作窃取 · 别手写 thread 池

并行算法事实标准

TBB 把任务交给工作窃取调度器；std::execution::par 很多实现底下就是它。你要的是 DAG / 流水线 / 并发容器时用 TBB；只是 for_each 并行，STL 即可。

6.1 何时用 TBB

库何时用何时不用代价
std::execution::par简单 for_each / sort要 DAG、流水线零依赖，能力薄
TBB任务图 / 并发容器 / arena嵌入式禁外部依赖多一个运行时
SYCL / oneAPICPU+GPU 同一套只用 CPU工具链重
07

Seastar

共享无事 · 每核一线程 · 显式消息

数据库 / 消息队列这一档才考虑

Seastar 是 ScyllaDB 出品的 shared-nothing 异步框架：每核固定一条线程，跨核只发消息、不加锁。ScyllaDB / Redpanda / Ceph Crimson 走这条路。它不是「更快的 Asio」——编程模型和 Linux 线程池代码基本不兼容。

7.1 何时用 Seastar

库何时用何时不用代价
SeastarDB / MQ / 高吞吐网关，能接受无共享普通微服务、要混已有线程池范式税、生态窄
Asio通用异步 IO要每核打满且无锁共享内存模型
08

EASTL

无异常 · 无 RTTI · allocator 第一公民

游戏 / 嵌入式的 STL 替代

EASTL 是 EA 的 STL：默认不抛异常、每个容器强制 allocator、fixed_vector 一类走栈。API 接近 std::vector，约束相反。通用后端用 STL 即可。

8.1 何时用 EASTL

库何时用何时不用代价
EASTL游戏 / 主机 / 禁异常嵌入式普通后端、要标准异常模型方言、生态小于 STL
STL默认分配器必须帧级可控异常/RTTI 体积

序列化

文本 JSON → schema Protobuf → 零拷贝

先定契约，再定库

RPC 机制见 异步网络。这里只定光谱：要不要 schema、要不要零拷贝、要不要人能读。

9.1 Protobuf vs JSON

JSONProtobuf
schema无（靠文档和测试）有，跨语言生成代码
可读强弱（要 protoscope / 转 JSON）
体积 / CPU文本，解析贵紧凑；非零拷贝
何时用配置、REST、调试面跨服务 RPC、长期契约
何时不用热路径每秒十万次解析给浏览器直接看、没有 codegen 流水线
syntax = "proto3";
message User {
  int32 id = 1;
  string name = 2;
}

9.2 按场景选

场景推荐
跨语言 RPCProtobuf + gRPC

10

fmt / spdlog

格式化 vs 后端 · 细节去观测页

fmt 不是 logger

fmt（及 std::format）只负责把参数变成字符串。spdlog 才是 sink、异步队列、级别、滚动。异步 overflow 政策比再抄一份 demo 重要，见 可观测性 §4。

10.1 格式化不是后端

需求选何时不用
通用服务spdlog + fmt—
HFT 热路径quill要功能齐全的 sink 生态
Google 遗留glog / absl::log新项目
零依赖std::print + 自写 sink要异步、滚动、多 sink
11

JSON / YAML / TOML

配置与 payload 分开选

解析速度和易用是两条轴

11.1 配置与 payload

库何时用何时不用代价
nlohmann::json构造、配置、小流量 REST热路径解析header 重、解析慢
simdjson高吞吐解析还要方便 dump 对象API 偏底层，只擅长读
yyjson纯 C / 嵌入式、也要序列化已绑定 C++ JSONC API
yaml-cpp人写的配置热路径YAML 规格坑
tomlplusplus工具配置、header-only要与 JSON 生态互通生态较小

常见组合：配置 YAML/TOML，对外 JSON 用 nlohmann dump，进站热路径换 simdjson。不要两个 JSON 库在同一条调用栈上来回转。

12

HTTP 客户端 / 服务端

客户端事实标准是 curl · 服务端按体量选

不要为 hello 路由引一个框架

12.1 库 → 何时用

库何时用何时不用代价
libcurl / cpr出站 HTTP，全平台已在 Asio 里要零拷贝一体cpr 是皮，内核仍是 curl
Beast已吃 Asio，要 HTTP/WS只想要 Flask 式路由要自己组 router
Crow小服务、header-only要 HTTP/2、ORM、高并发功能薄
Drogon异步服务端、性能优先团队只写同步框架绑得深
uWebSocketsWebSocket 打满普通 RESTAPI 底层

跨语言 RPC 优先 gRPC，不要用 HTTP 框架再手搓 Protobuf 帧。样板代码略。
