引言

低延时场景对 C++ 的特殊要求

普通工程看 p99 / QPS；低延时看 最坏情况和确定性。均值好看、尾巴偶发卡顿，在 1M QPS 下每秒都是事故。

普通工程

  • p99 < 100 ms 可接受，偶尔长尾不致命
  • 动态分配、弹性扩容、测功能即可

低延时 / HFT / RAN 硬实时

  • p99 < 50 µs、p99.99 < 100 µs；任何抖动都是 bug
  • 启动期预分配，热路径零 malloc；用直方图测最坏情况

1.1 你的领域 — RPC / RAN

RPC 管理面多是毫秒级，但有实时分支：RU 控制面不能被慢路径堵住、心跳不能漂、告警 µs～ms、PM 要高吞吐且不伤主路径。不是 HFT 也一样：零分配、缓存友好、少锁。

02

延迟预算 (Latency Budget) 与 SLA

把 SLA 切成组件预算

2.1 为什么要做"预算"

先把 SLA 切成组件预算，再各自守住。超了先问是哪一段，不要整条链路一起调。

段预算常见抖动
网卡 RX / TX各 ~10 µs中断、软中断、协议栈
Reactor 分发~5 µs锁、跨核唤醒
解析 / 序列化各 ~15 µsmalloc、string 扩展
业务逻辑~30 µs分配、锁、异常
内核 / 调度余量~15 µstick、IRQ、迁移
合计 p99.99100 µs预算是上限，不是均值

2.2 关键数字 (低延时口径)

在 性能指南 的数量级表之上，低延时再记变异度：均值低但抖的，才是敌人。

操作典型变异
L1 / L3 / DRAM1 / 10 / 100 ns稳
无竞争 mutex / spin10–25 ns一阻塞就 µs
malloc 小块50–200 ns抖（锁、碎片、brk）
false sharing~200 ns/次抖
轻量 syscall / read 1B50 ns / ~1 µs稳，但会污染 cache
minor / major page fault~5 µs / ms极抖
调度 / timer slack / 本机 RTT1–5 µs / ~50 µs / 20–100 µs看配置

原则：先消抖，再削均值。

2.3 worst-case vs average

「平均 5 µs」不够。p99.99 才是用户看到的：1M QPS 下 0.01% 就是每秒 100 次卡顿。

抖动源对照后文：分配 → §3–§8；锁 → §9 与 内存模型 · 无锁；syscall → §12–§13；绑核/IRQ → §11 与 进程调度 · 绑核隔离；缺页 → mlock（§14）。

03

C++ 分配器全景

malloc 到零分配

3.1 默认 std::allocator 的问题

底层是 ::operator new → glibc malloc / jemalloc。有全局或 per-arena 锁，延迟随堆状态变；brk/mmap 时突变。均值 50–200 ns，最坏可到 µs。

3.2 分配器分类

类型分配 / 释放适用
std::allocator / jemalloc50–200 ns，仍抖通用、低频
monotonic / arena几 ns / 0（整体释放）请求、短生命周期
pool / slab~10 ns / ~10 ns固定大小、可回收
SBO / 静态预分配0 / 0小对象、消息缓冲

3.3 分配器选型决策

问选
生命周期跟请求走？arena / monotonic
大量同尺寸、会还回来？pool / slab
超小、栈上能塞下？SBO
每 µs 一次？必须零分配（§8）
多线程共用一池？per-thread arena，或 lock-free 池
长期、形状未知？jemalloc / tcmalloc 即可
04

std::pmr

多态 allocator (C++17)

std::pmr 让同一个容器类型运行时换分配器，是 C++17 的标准做法。

4.1 核心组件

类用途
memory_resourceallocate / deallocate / is_equal
polymorphic_allocator<T>包一层 memory_resource*
monotonic_buffer_resource只进不出，整体释放
unsynchronized_pool_resource单线程池
synchronized_pool_resource多线程池
new_delete_resource() / null_memory_resource()默认 new；分配必失败（测禁分配）

4.2 基础用法

#include <memory_resource>
char buf[8192];
std::pmr::monotonic_buffer_resource pool{buf, sizeof(buf)};
std::pmr::vector<int> v{&pool};   // 在 buf 上长，满了才 fallback new
v.push_back(1);

4.3 请求处理模式

每个请求一块栈上 buf + monotonic_buffer_resource，std::pmr::vector / map / string 全绑这个 arena。函数返回时析构 = 整体释放，零次 free。实测 RPC 路径默认分配器 ~5 µs 抖，arena ~1.5 µs 且稳。

4.4 默认 resource 切换

std::pmr::set_default_resource(&my_pool) 之后，不传 allocator 的 std::pmr::vector 也走你的池。只对 std::pmr::* 生效，普通 std::vector 不管。

4.5 std::pmr 的限制

  • 每个容器多一个指针；分配走虚函数（1–2 ns）
  • 不能跨 resource 移动；std::pmr::vector 与 std::vector 不是同一类型
请求级用 monotonic；长寿固定尺寸用 synchronized pool；不需要切换就别上 pmr。
05

arena / monotonic 分配器实现

只进不出，直到 reset

5.1 简化实现

void* allocate(size_t n, size_t align) {
    uintptr_t a = (reinterpret_cast<uintptr_t>(cur_) + align - 1) & ~(align - 1);
    char* p = reinterpret_cast<char*>(a);
    if (p + n > end_) throw std::bad_alloc{};
    cur_ = p + n;
    return p;
}
void deallocate(void*, size_t) {}   // no-op
void reset() { cur_ = base_; }

5.2 多块 chunk 扩展

固定 buf 会爆。生产用几何增长的 chunk 链：满了 grow() 一块更大的，reset() 丢全部 chunk。热路径仍是指针推进；grow 只应发生在启动或扩容期，不要在 p99 路径上第一次长块。

5.3 集成到 std::pmr

继承 std::pmr::memory_resource：do_allocate 调 arena，do_deallocate 空，do_is_equal 比指针。然后 std::pmr::vector<int> v{&mr}。标准库已有 monotonic_buffer_resource，自写只为控对齐/统计。

5.4 真实库

protobuf Arena、folly::Arena、std::pmr::monotonic_buffer_resource、boost polymorphic allocator。优先标准库，协议代码才跟 protobuf Arena。

06

对象池 · slab 分配器

freelist pop/push

6.1 固定大小对象池

同尺寸、会还回来：freelist pop/push，~10 ns，无碎片。

template<class T> T* acquire() {
    if (!free_list_) grow();
    Slot* s = free_list_; free_list_ = s->next;
    return new (&s->value) T;
}
void release(T* p) {
    p->~T();
    auto* s = reinterpret_cast<Slot*>(p);
    s->next = free_list_; free_list_ = s;
}

6.2 RAII handle 包装

析构调 release，禁拷贝、允许移动。性能在池，生命周期在 handle。

6.3 slab allocator (Linux 内核风格)

多个 size class 的池（8/16/32/…/4096），对号入座；更大走 malloc。jemalloc / tcmalloc / mimalloc 都是更复杂的 slab。

6.4 与 §9 (cpp_concurrency_patterns_guide) 对象池区别

并发篇的池偏 RAII 归还；这里偏 分配延迟。可叠：FixedPool 出内存，handle 管还。

07

SBO · 小对象优化

小对象住在容器内

Small Buffer Optimization：小对象直接住在容器里，不堆分配。std::string 的 SSO 是最常见例子。

7.1 经典案例

类型SBO 阈值
std::string (libc++ / libstdc++)≤ 22 / ≤ 15 字节
std::function / std::any~16–32 / ~16–24（实现差）
boost / folly small_vector用户指定 N

7.2 实现 small_vector

union：内联 alignas(T) char sbo_[N * sizeof(T)] 与堆指针。容量 > N 走堆。不要从零写，用 boost::small_vector / folly::small_vector。N 必须来自实测分布（绝大多数 case ≤ N）。

7.3 SBO 收益

RPC 字段常 4–8 个：SmallVector<Field, 8> 每次少 1–2 次 malloc（100–400 ns）。热路径上的短 std::string 也同理。

7.4 SBO 的代价

sizeof 变大；移动可能要拷内联字节而不能只 swap 指针；扩到堆后内联区浪费。阈值过大等于给每个对象塞一块冷缓存。

08

零分配编程 (Zero-allocation)

启动备好，热路径不再 new

热路径一次 malloc 都没有：延迟稳，也没有分配器锁。

8.1 怎么做

// ❌ 热路径每次 unique_ptr
auto pkt = std::make_unique<char[]>(len);
memcpy(pkt.get(), src, len);

// ✅ 启动期备好的缓冲
struct Hot { alignas(64) char buf[65536]; };
void on_rx(Hot& h, const char* src, size_t len) {
    memcpy(h.buf, src, len);   // 无 new
}

8.2 检测工具

手段看什么
LD_PRELOAD hook malloc热路径触发即 abort
strace -e brk,mmap / perf trace是否还在向内核要页
jemalloc stats / massifalloc 计数是否在涨
null_memory_resourcepmr 容器误用立刻失败

8.3 RAII guard 标记禁分配区

thread_local 深度计数：进入热路径 +1，hook 里 depth > 0 就 abort。只开在测试/金丝雀，生产不要真崩。

8.4 经典模式

启动时 std::array<Route, 4096> 填满，热路径只扫描已有槽。日志、告警、包缓冲同一套路：池在 main 前 init 完。

09

Lock-free 数据结构

CAS 循环 vs mutex

9.1 SPSC ring buffer (单生产单消费)

最快的无锁队列：head/tail 分属 cache line，N 为 2 的幂，release-acquire 配对。SPSC 不用 CAS。细节与 ABA / 回收见 内存模型 §14。

9.2 MPMC 复杂度

多产多消要 CAS 循环、处理 ABA、选对 memory_order。不要手写：moodycamel、folly::MPMCQueue、boost::lockfree。

9.3 lock-free 的代价

T expected = v.load(std::memory_order_relaxed);
T desired;
do { desired = compute(expected); }
while (!v.compare_exchange_weak(expected, desired,
        std::memory_order_release, std::memory_order_relaxed));

循环用 weak（允许伪失败）；失败时 expected 已是新值，不要再 load。序的语义不要在本页展开，去 内存模型。

10

缓存友好布局回顾 + 低延时增强

对齐、热冷分离、大页

缓存基础见 性能指南 §5–7。这里只补低延时更狠的几条。

10.1 极致 cache 优化清单

做为什么
热点 alignas(64)；每线程计数器独占一行防 false sharing
热字段靠前，冷字段另结构少拉进 cache
小函数 inline / 少分支减 ICache miss

10.2 prefetch 主动预取

顺序扫描交给硬件预取。哈希/链表这种跳跃访问才值得 __builtin_prefetch（提前若干步）。过度预取会污染 cache。

10.3 hot/cold 分离

fd、计数器放 ConnectionHot；peer、metadata、debug 缓冲放 ConnectionCold*。加载热字段时不要把 4KB 日志一起带进 L1。

10.4 大页 (Huge Page)

手段用途注意
THP always / never减少 TLB miss不要长期停在 madvise；有的负载 THP 反而抖
MAP_HUGETLB / jemalloc thp:always显式 2MB/1GB配合启动期预触
11

CPU 亲和性 (pinning) 与 NUMA

绑核挡不住 tick 和 IRQ

11.1 为什么 pinning

线程在核间迁移会丢 cache / TLB，还可能跨 NUMA。绑死以后延迟可预测。命令、cgroup、isolcpus 四件套见 进程调度 · 绑核隔离，这里不贴 chrt / grub 墙。

11.2 用 pthread_setaffinity_np

线程启动时 CPU_SET + pthread_setaffinity_np；命令行等价 taskset -c N。只约束「我不被搬走」，挡不住别人搬过来，也挡不住中断。

11.3 isolcpus + nohz_full

四件套：isolcpus + nohz_full + rcu_nocbs + irqaffinity。展开与测抖动见调度篇，不要只 taskset 完事。

11.4 NUMA

跨 socket 访存大约 2–3×。线程和内存绑同一 node：numactl --cpunodebind=0 --membind=0，或 numa_alloc_onnode。先 numactl --hardware 看拓扑。

11.5 中断绑核 (IRQ affinity)

把网卡 IRQ 写到管理核的 /proc/irq/N/smp_affinity_list。硬中断不受 SCHED_FIFO 保护，来了就抢你的核。

12

系统调用最小化

陷入要摊销

12.1 syscall 的代价

syscall量级备注
getpid / clock_gettime~20–50 nsvDSO，热路径仍少调
read/write 1B / epoll_wait~0.5–1 µs切内核 + 污染 cache
futex 慢路径1–10 µs锁睡下去
forkms热路径禁止

12.2 减少 syscall 的方法

手段作用
writev / sendmmsg / recvmmsg一次带多段
io_uring 批量 SQE共享环摊销陷入；轮询模式可零 syscall
SO_BUSY_POLL / DPDK / AF_XDP少切或不进内核栈
用户态时钟（RDTSC / 后台刷新 atomic）热路径不调 clock_gettime，精度换确定性

12.3 io_uring (Linux 5.1+)

共享内存环提交/完成，一次 syscall 可收几十个 IO。机制见 IO 与内核 · io_uring。

12.4 user-space timer

专用线程每毫秒写 atomic<int64_t> g_now，业务 load(relaxed)。精度掉到 ms，热路径省 syscall。要 µs 级墙上时间走 §17c 的 PHC，不要在热路径 clock_gettime。

13

批处理 (batching)

固定成本摊到一批上

固定开销（陷入、锁、cache miss）摊到 N 个事件上，吞吐和尾巴才能同时好看。

13.1 网络 IO 批处理

场景API
多包收发sendmmsg / recvmmsg
多段缓冲writev / readv
异步批量io_uring 一次提交一串 SQE

13.2 队列批量 pop

一次加锁 pop_batch(out, 32)，处理完再取。锁和 cache 都摊薄。无界队列会把延迟藏进长度，见 §18。

13.3 日志批量 flush

热路径只把条目推进预分配槽；满 N 条或到期再一次 write。不要每条 std::cout。

13.4 trade-off

min-batch + max-wait：凑满 N 或等到 t µs。低负载小批保延迟，高负载大批保吞吐。

14

系统调优 (kernel/cpufreq/RT)

频率、锁页、实时调度

14.1 CPU 频率

旋钮目的
governor=performance禁动态降频
关 turbo / 关 HT 兄弟核热降频、共享 cache 引入的抖
禁深 C-state唤醒延迟

14.2 内存锁定

mlockall(MCL_CURRENT|MCL_FUTURE) 禁止换出；启动时按页预写一遍，把 minor fault 做完。热路径再 fault 就是 p999。

14.3 RT 调度优先级

SCHED_FIFO / SCHED_RR 相对 CFS 绝对优先。优先级过高的死循环会冻机，必须配 runtime 配额。接口与陷阱见 进程调度 · 实时与 PREEMPT_RT。

14.4 PREEMPT_RT 内核

主线不是硬实时。抖动要从 ms 压到 µs，需要可抢占临界区（spinlock→mutex、中断可抢）。RAN 硬实时分支常用；平均吞吐大约掉 5–10%。不要在本页堆 cmdline，细节仍走调度篇。

RPC RAN 真实工程案例

arena、零 malloc、pin、直方图

17.1 案例 1: platform agent 的延迟优化

上万 RU、100k+ QPS、p99 < 5 ms。每个 RPC 一块 monotonic arena、解析用 string_view、路由 FlatMap、session 分片、异步日志。p99 50 ms → 3 ms，碎片消失。

17.2 案例 2: 告警 (Alarm) 上报路径

生成到 NMS < 100 µs：启动期 64K 槽对象池、中断线程→推送线程走 SPSC、推送线程 pin 隔离核、FIFO + PREEMPT_RT、io_uring 批发送、栈上 format_to_n。max 多数时候 < 50 µs。

17.3 案例 3: PM 数据采集

每秒百万 KPI：thread_local 缓冲无锁攒、秒级批量进 MPMC、aggregator SoA+SIMD、protobuf+zstd、io_uring 发送。主业务路径不碰采集锁。

17.4 经验总结

RAN 多数不是 ns 级 HFT，但不能偶发 500 ms。模式就五条：启动预分配、热路径零 malloc、关键线程 pin、IO 异步批量、直方图盯尾巴。
17B

内核旁路 (Kernel Bypass)

DPDK / AF_XDP 相对内核栈

普通 socket 一次往返约 10–30 µs。要更低，让用户态直接碰 DMA。路径位置见 内核网络栈 · XDP。

17b.1 四大主流方案

技术延迟代价
DPDK~1–3 µs独占网卡与核，自带栈
RDMA / RoCE~1–2 µsverbs；数据面可不经 CPU
XDP / AF_XDP~3–5 µs可留内核栈
OnLoad~1.5 µsLD_PRELOAD，应用几乎不改

17b.2 DPDK — 用户态网络全家桶

VFIO 接管网卡，PMD 轮询、大页 DMA、lcore busy poll。热路径 rte_eth_rx_burst。还要 SSH/监控走内核栈就改 AF_XDP，别独占网卡。

17b.3 RDMA — 远程内存直接读写

SEND/RECV 做控制面；WRITE/READ 碰远端内存；Atomic 做跨机 CAS。框架 UCX、libfabric。

17b.4 XDP / eBPF — 在内核里拦截，保留协议栈

驱动里、skb 之前：DROP / PASS / TX / REDIRECT。细节见网络栈篇，不贴加载命令。

17b.5 选型决策

HFT 最小改动 → OnLoad/DPDK；同机房 → RDMA；过滤 → XDP；UPF → DPDK；普通业务 → epoll，下一步 io_uring。旁路要自写 TCP、失去 tcpdump、核占满——pps 不够才上。

17C

硬件时间戳 · PTP / PHC

当 µs 级时间精度成为刚需

NTP 是 ms；软件 gettimeofday 还受调度和频率影响。µs 级因果要用 PTP + 网卡 PHC。

17c.1 三档时间精度

方案精度
NTP~ms
软件 PTP（ptp4l）~10–100 µs
硬件 PTP（网卡 PHC）~50–500 ns
White Rabbit / GPS~1 ns（交易所、实验室）

17c.2 PTP 工作原理（极简）

主时钟发 SYNC，从时钟测单程延迟和偏移，校准本地 PHC。时戳打在网卡上，不依赖 OS 调度。

角色做什么
主 / 从 ptp4l -H硬件时戳同步
phc2sysPHC → 系统时钟，让 gettimeofday 也准
pmc GET CURRENT_DATA_SET看 offsetFromMaster（收敛到几十 ns）

17c.3 C++ 代码读硬件时戳

打开 /dev/ptp0 得到 clockid，clock_gettime 读 PHC。收包时戳走 SO_TIMESTAMPING + SOF_TIMESTAMPING_RAW_HARDWARE，从 recvmsg 控制信息取。HFT 链路：GPS → grandmaster → 机柜 BC → 服务器 PHC，整段可到约 200 ns。

17D

CPU 隔离

细节见进程调度篇

核从调度器和 tick 里拔出。命令与四件套见 进程调度 · 绑核隔离，图在 §11.3。

17d.1 内核启动参数三件套

参数挡住挡不住
isolcpus被均衡过来的普通任务显式 pin、中断
nohz_full单任务时的 tick其它 IRQ、IPI
rcu_nocbs / irqaffinityRCU 回调 / 默认 IRQNMI、IPI

17d.2 业务程序如何使用这些隔离核

setaffinity → mlockall → 可选 FIFO → 预触页。新线程不一定继承，容器用 cpuset.cpus。

17d.3 IRQ 亲和性 —— 别让网卡中断打扰

网卡 IRQ 赶到 housekeeping 核。硬中断不听 FIFO。

17d.4 测量你的"抖动"

隔离核上跑 cyclictest：隔离前 max 常 50–500 µs，之后目标 ≤ 10 µs。该核 /proc/interrupts 不该再涨。

17d.5 PREEMPT_RT 内核 —— 终极硬实时

仍不够再上 PREEMPT_RT（实时调度）。可到 < 100 µs，吞吐掉一截。

17d.6 完整低延时部署 checklist

BIOS 关 HT/深 C-state → 内核四件套 → IRQ 赶到管理核 → 进程 mlock+pin+预触 → 网卡忙轮询或旁路 → cyclictest + 业务直方图。价值：隔核 > mlock > nohz > IRQ > FIFO > RT。普通服务前三条通常够。

19.4 速答示范（第 8 题）

问：怎么写一个零分配的 RPC 处理路径?

答：

  1. 启动期预分配：所有可能用到的 buffer / pool / 表 在 main 之前 init 完
  2. 请求 arena：每个 RPC 用 monotonic_buffer_resource，处理完整体释放
  3. 容器：std::pmr::vector / std::pmr::map 配 arena，不用 std 默认
  4. 字符串：函数参数 / 临时全用 string_view 引用 socket buffer
  5. 序列化：fmt::format_to_n 写入栈 / 预分配 buffer (不用 std::string)
  6. 错误处理：用 std::expected / 错误码，不用异常 (throw 会分配)
  7. 日志：异步 logger + 预分配条目池
  8. 验证：测试期 hook malloc, 关键路径触发 abort
  9. 监控：HdrHistogram 跟踪延迟分布; jemalloc stats 验证 alloc 计数
