01

引言

存量 C++ 只能硬化，不能立刻重写

洋葱模型

1.1 内存不安全语言的代价

MSRC / Chromium：约 70% 高危 CVE 是内存不安全。Android 新代码迁 Rust 后这类 bug 接近归零。存量几百万行还在，所以要硬化。

1.2 但你不能马上重写 C++ 代码

浏览器、数据库、内核、游戏、嵌入式还不了债。硬化：写、编、链、跑、运维每一层都钉死。

1.3 安全硬化的"洋葱模型"

三层不能互相替代。静态分析漏路径，编译缓解不修根因，sanitizer 上不了完整生产。缺一层，另外两层补不上。

1.4 本指南的覆盖范围

五类漏洞、编/链/跑开关、静态工具与规范、供应链。ASan 报告见 崩溃调试 §5.1 与 Sanitizers，本文不贴。内核权限见 Linux 安全模型。

1.5 与其他章节的关系

  • Sanitizers 指南 —— ASan / UBSan / Fuzz
  • 编译指南 · 现代链接器 —— 链接期开关
  • 内存泄漏指南 —— 资源泄漏也是安全问题
  • 崩溃调试指南 —— 触发后的取证

3.4 整数推广陷阱

int x = INT_MAX;
int y = x + 1;                 // ❌ 有符号溢出 = UB；优化器可删掉 if (x+1 < x)
size_t n = (size_t)(int)len;   // ❌ 窄化：负数 len 变成巨大 size_t

04

缓冲区溢出

栈 / 堆 / 全局，危险 API 换成带 size 的类型

栈 · 堆 · BSS

4.1 三种缓冲区溢出

类型位置利用第一道闸
栈溢出局部数组盖返回地址canary + NX + PIE（§10）
堆溢出malloc/new改相邻 chunk / tcacheASan CI + FORTIFY
BSS/全局全局变量盖函数指针RELRO 把 GOT 只读（§9）

4.2 经典栈溢出 (1996 Morris Worm 已用)

strcpy(buf, user) 无边界盖返回地址。今天还要同时打穿 canary / NX / ASLR，见 §10。

4.3 危险 C 函数 → 安全替代

检查目的判据
strcpy / gets无边界写仓里 0 处，改 std::string
sprintf / scanf("%s")溢出 + 格式串std::format
未校验 n 的 memcpy堆溢出n 对 dst 容量

4.4 现代 C++ 写法

用 std::array / span / string，不要手写 char buf[64] 再猜长度。

4.5 堆溢出与 chunk metadata

越界改下一个 chunk 的 size/fd，free 时解元数据。CI 用 ASan 抓，别靠「看起来没崩」。

4.6 防御

编译 -D_FORTIFY_SOURCE=2（§8）；运行 canary + ASLR（§10）；测试 ASan + fuzz（§12）。

05

UAF / Double-Free / Type Confusion

时间线短图；报告去崩溃调试 / Sanitizers

UAF · 类型混淆

5.1 UAF (Use After Free)

释放后仍用旧指针。报告与 shadow bytes 见 崩溃调试 §5.1；检测器见 Sanitizers §3。

5.2 经典 UAF 模式：异步回调持有"裸 this"

Asio / 线程池 [this]：对象先析构、回调后到。改 shared_from_this() 或 weak_ptr。

5.3 Type Confusion (C++ 多态独有)

把 DerivedA* 当 DerivedB* 用。运行时该 dynamic_cast。

5.4 Chrome 的统计

高危约一半是 UAF。工程侧 PartitionAlloc + MiraclePtr + GWP-ASan（Sanitizers §14b）。

5.5 防御

检查目的判据
禁裸 new/delete所有权进智能指针clang-tidy cppcoreguidelines-owning-memory
CI ASan抓隔离期内 UAF单测 0 条 ASan 报告
生产 GWP-ASan机群采样见 sanitizers §14b，不上完整 ASan
06

格式化字符串漏洞

用户串当格式 → %n 任意写

格式串写死
// ❌ 用户串当格式；%n 写任意地址，%x 泄栈
printf(user);
// ✅ 格式串写死；C++20 起用 std::format，编译期检查
printf("%s", user);
auto s = std::format("{}", user);

6.1 现代 C++ 永久解决方案

std::format / std::println 不接受运行时格式串（C++26 才有显式 runtime_format opt-in）。新代码不要再引入 printf 家族。

6.2 编译器警告

-Wformat -Wformat-security -Werror 会把 printf(user) 直接打成错误。这是 §8 那张表里必须开的几项之一。

08

编译期硬化开关 ⭐

旗标一张表，CMake 挂 target

生产 CXXFLAGS

最高 ROI：旗标挂在 target 上，不要拼全局 CMAKE_CXX_FLAGS（见 CMake CI）。

8.1 完整的"硬化" CXXFLAGS（生产推荐）

target_compile_options(app PRIVATE
  -O2 -g -Wall -Wextra -Wformat -Wformat-security -Werror
  -fstack-protector-strong -D_FORTIFY_SOURCE=2 -fPIE
  -fstack-clash-protection -ftrivial-auto-var-init=zero
  -fno-delete-null-pointer-checks -fno-strict-overflow)
target_link_options(app PRIVATE
  -pie -Wl,-z,relro -Wl,-z,now -Wl,-z,noexecstack)

8.2 关键开关详解

旗标作用判据
-D_FORTIFY_SOURCE=2strcpy/memcpy 的 size 检查（3 需新 glibc）nm 见 __*_chk
-fstack-protector-strong栈金丝雀checksec Canary
-fPIE + -pie映像参与 ASLRfile 显示 pie
-fstack-clash-protection大栈不能跳过 guard极小开销
-fcf-protection=fullCET：IBT + shadow stackx86_64
-ftrivial-auto-var-init=zero未初始化填 0消栈泄漏
-fno-delete-null-pointer-checks别优化掉 NULL 检查内核被坑过
-D_GLIBCXX_ASSERTIONSoperator[] 边界按延迟预算开
-fhardened（GCC 14+）一键开大部分仍要 -Werror

8.3 _FORTIFY_SOURCE 实例

dst 大小已知时，strcpy 编译期告警，运行时走 __strcpy_chk。拦不住算不出的动态 size。

8.4 -ftrivial-auto-var-init=zero —— 自动初始化

未初始化读会泄栈（绕 ASLR 的第一步）。Chrome / 内核已填零。代码里仍应初始化。

8.5 警告开关（一定要开 -Werror）

最低集：-Wall -Wextra -Wformat-security -Wnull-dereference -Wconversion -Werror。警告留下来等于没开。

8.6 Clang 专属：-fsanitize=*

CFI：-fsanitize=cfi -flto -fvisibility=hidden。ASan 用法见 Sanitizers，不要编进生产。

链接期保护 (RELRO / NOW / 等)

Partial vs Full RELRO，readelf 看 BIND_NOW

GOT 必须只读

9.1 RELRO + BIND_NOW

选项作用判据
-Wl,-z,relro启动后把 GOT 可只读部分标只读缺 now 仍是 Partial
-Wl,-z,nowBIND_NOW，GOT 全部只读见下面 readelf -d
-Wl,-z,noexecstack栈 NXchecksec NX enabled
-Wl,-z,separate-code.text 与数据分开，提高 ASLR 熵readelf 段标志
-Wl,--as-needed不链没用到的 .soNEEDED 列表变短
$ readelf -d ./app
 0x0000000000000001 (NEEDED)             Shared library: [libc.so.6]
 0x000000000000001e (FLAGS)              BIND_NOW
 0x000000006ffffffb (FLAGS_1)            Flags: NOW PIE
 0x000000000000001d (RUNPATH)            Library runpath: [$ORIGIN]
 0x0000000000000000 (NULL)               0x0

9.2 检查二进制是否启用了硬化

checksec --file=app 看 RELRO / Canary / NX / PIE。生产要 Full RELRO；缺 BIND_NOW 就是 Partial。

9.3 -static-pie — 静态链接 + ASLR

-static-pie -fPIE：静态二进制也能 ASLR。链接器见 编译指南 §10。

10

运行时缓解

NX + PIE + ASLR 要一起才有用

金丝雀 · seccomp

10.1 ASLR (Address Space Layout Randomization)

每次启动随机化 stack / heap / mmap / 映像。非 PIE 则代码段地址固定。NX、PIE、ASLR 必须一起开。

10.2 Stack Canary（栈金丝雀）

-fstack-protector 只覆盖较长字符数组；-strong 是生产默认；-all 开销大。

10.3 NX / W^X

页不可既写又执行。链接 -Wl,-z,noexecstack。单开 NX 只逼出 ROP，必须配 PIE+ASLR。

10.4 CFI (Control Flow Integrity)

间接调用 / 虚调用只能跳到合法目标。Clang CFI 要 LTO；硬件是 -fcf-protection=full。

10.5 SafeStack / Shadow Stack

返回地址进隔离栈。Clang -fsanitize=safe-stack；CET 用 -mshstk。canary 查线性盖写，shadow stack 查返回地址。

10.6 W^X 的扩展：seccomp / pledge

capability 拆开 root，seccomp 收窄 syscall。见 Linux 安全模型 · capabilities、seccomp；容器对照 操作系统基础 §8。
