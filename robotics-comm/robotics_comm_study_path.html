机器人通信与确定性网络学习路径

P1 确定性网络机制：用 TSN 建立「时间同步 + 门控整形」的地基，再看 DetNet 如何把这套思路搬到 L3 并与 5G 拼接，最后用保障体系把预算分解、抖动定位、尾部测量的方法论串起来 → P2 端内总线与中间件：从 EtherCAT 到共享内存，再到 ROS2/DDS，搞清数据在机器人内部怎么流动 → P3 协议设计与系统架构：自己动手设计一个失效安全的控制协议，把前面所有技术组装成能交付的架构方案，并建立技术前瞻的评估框架。适合有网络或嵌入式背景、要切入机器人 / 工业实时通信方向的工程师。

~32 h8 篇 · 96 道面试题
P1
确定性网络机制（~12 h）
#内容时间关键收获
1TSN 深入5 hgPTP 同步、GCL 设计与 guard band、帧抢占、FRER、taprio 落地
2DetNet 与跨域确定性3 hL3 确定性、CQF 时延界、TSN+DetNet+5G 分层拼接
3确定性网络保障体系4 h预算分解、抖动指纹定位、四类场景、尾部分位测量
✅ 阶段完成标志
  1. 能说清 Qbv 门控为什么必须配 guard band 或帧抢占，并算出 1 Gbps 下的具体数字
  2. 能解释 CQF 的时延界为什么与拓扑无关，以及周期受哪三个约束夹住
  3. 拿到一份「抖动超标」报告，能用四步二分法定位到六类来源中的一类
P2
端内总线与中间件（~8 h）
#内容时间关键收获
4机器人端内总线选型4 hEtherCAT 飞读飞写与 DC、CAN 最坏时延计算、共享内存无锁队列、周期预算
5ROS2 与 DDS / RTPS 深入4 hRTPS 可靠状态机、QoS 兼容性、Executor 实时化、零拷贝、发现风暴
✅ 阶段完成标志
  1. 能解释 EtherCAT 为什么 N 个从站只需一个帧时，以及 DC 为什么不能「收到帧就动」
  2. 能算出一条 CAN 报文的最坏响应时间，并说明 ID 分配为什么是设计动作
  3. 能说清控制流为什么要用 BEST_EFFORT + KEEP_LAST(1) + Lifespan，而不是 RELIABLE
