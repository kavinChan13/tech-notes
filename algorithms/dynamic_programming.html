动态规划

DP 难，不是因为转移方程复杂，而是因为「状态该怎么定」没有机械方法。所以这一篇不堆题目，而是先给一套可复用的五步流程，再用背包、区间、树形、状压、数位五个族把「状态设计」的常见套路走一遍，最后讲四种把 O(n²) 压到 O(n log n) 或 O(n) 的优化——每一种都有明确的适用判据。

01

两个前提，一句本质

DP 不是技巧，是一种「把指数搜索空间折叠成多项式」的手段

DP 适用的两个前提：
  • 最优子结构：问题的最优解可以由子问题的最优解组合出来。（这是能「递推」的前提。）
  • 重叠子问题：同一个子问题在递归展开中会被反复遇到。（这是「记下来」有价值的前提。）
只有最优子结构、没有重叠子问题 → 用分治（归并排序、快速选择）。
两者都有 → 用 DP。
没有最优子结构 → 只能搜索（回溯 + 剪枝），或者换一个有最优子结构的建模。
DP 的本质像爬楼梯时记住每一层的最优走法。

暴力搜索是「从底层出发，穷举每一种上楼路线」——路线数是指数的。DP 说：到第 10 层的最优走法，只取决于「到第 9 层的最优走法」和「到第 8 层的最优走法」，而不取决于我是怎么到第 9 层的。

所以我只需按层从下往上，每层记一个数。指数级的路线空间被「折叠」成了 n 个状态——这就是 DP 全部的魔法。

而「状态设计」就是在回答：要记住哪些信息，才足以让后面的决策不依赖更早的历史？这个「足够的信息」就是状态，多记是浪费（状态数爆炸），少记就错（后面的决策需要它）。
自顶向下（记忆化递归）自底向上（迭代 DP）
思维方式和递归定义一致，好写要先想清计算顺序（拓扑序）
栈深O(递归深度)，可能爆栈0
是否计算无用状态否，只算真正需要的是，全表都填
常数因子函数调用 + 查表开销纯循环，cache 友好
能否压缩空间难（要保留全表）容易（滚动数组）
状态空间稀疏时优势明显（用哈希表存）浪费严重
写 DP 的建议流程：先用记忆化递归写出来（因为它和「状态定义 + 转移」一一对应，最不容易想错），确认对了再改成自底向上（消掉栈深），最后按需压缩空间（滚动数组）。
直接写自底向上容易在「循环顺序」上出错——而循环顺序的错误往往不报错、只给错答案。

1.1 与其他章节的关系

  • 递归与分治 —— 「子问题是否重叠」是分治与 DP 的分界线；记忆化在那里首次出现
  • 单调栈与前缀和 —— §9.2 的单调队列优化、前缀和加速转移
  • 图遍历与拓扑排序 —— DAG 上的 DP 必须按拓扑序转移
  • 最短路与最小生成树 —— Floyd 和 Bellman-Ford 本质都是 DP
  • 贪心与回溯 —— 贪心是「不需要记状态的 DP」；没有最优子结构时退回回溯
  • 前向与反向传播 —— 反向传播本质是计算图上的 DP
02

设计 DP 的五步

把「灵光一闪」变成可执行的流程

2.1 五步方法论

第 ② 步有个通用技巧：站在「最后一步」问「最后这一步有几种选择」。
  • 爬楼梯：最后一步是走 1 级还是 2 级 → 两项转移。
  • 01 背包：最后一个物品选还是不选 → 两项转移。
  • LCS：最后两个字符相等吗 → 相等一种、不等两种。
  • 区间 DP：最后合并的分界点在哪 → 枚举分界点。
这个技巧把「设计转移」变成了「枚举最后一步的可能性」，比凭直觉想方程可靠得多。

2.2 状态设计的三个信号

题目里出现状态里可能需要加DP 族
「前 i 个」「以 i 结尾」一维下标 i线性 DP
「容量 / 预算 / 总和不超过 W」第二维 j = 已用容量背包
「区间 [l, r] 上的操作」「合并相邻」两维 (l, r)区间 DP
「树上的子树」(节点, 该节点的选择)树形 DP
「n ≤ 20」「哪些已被使用」一个位掩码状压 DP
「统计 [L, R] 内满足条件的数」(第几位, 是否贴上界, 附加信息)数位 DP
「最多操作 k 次」「有 k 次机会」加一维 k分层 DP
「持有 / 不持有」「冷却中」加一维状态机状态机 DP（股票买卖）
「n 的范围」是最强的提示（见 复杂度与分析 §3.3）：
  • n ≤ 20 → 状压 DP（2ⁿ 个状态）或回溯。
  • n ≤ 100~500 → O(n³) 可行 → 区间 DP、Floyd。
  • n ≤ 5000 → O(n²) → 线性 DP 的朴素转移、LCS、编辑距离。
  • n ≤ 10⁵ → 必须 O(n log n) 或 O(n) → 需要优化（§9）。
  • 值域很大但位数少（如 ≤ 10¹⁸） → 数位 DP。
看到范围先反推复杂度，再反推状态维数——这比盲想快得多。
03

线性 DP

三个必会的经典，每个代表一种转移形态

3.1 LIS 与它的 O(n log n)

朴素 DP：O(n²)
// dp[i] = 以 a[i] 结尾的最长上升子序列长度
int lis_n2(const std::vector<int>& a) {
    int n = a.size(), best = 0;
    std::vector<int> dp(n, 1);
    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < i; ++j)
            if (a[j] < a[i]) dp[i] = std::max(dp[i], dp[j] + 1);
        best = std::max(best, dp[i]);
    }
    return best;
}
贪心 + 二分：O(n log n)
// tails[k] = 长度为 k+1 的上升子序列的最小可能结尾
int lis_nlogn(const std::vector<int>& a) {
    std::vector<int> tails;
    for (int x : a) {
        // 严格上升用 lower_bound；非严格（允许相等）用 upper_bound
        auto it = std::lower_bound(tails.begin(), tails.end(), x);
        if (it == tails.end()) tails.push_back(x);   // 能接长
        else *it = x;                                  // 替换成更小的结尾
    }
    return (int)tails.size();
}
为什么 tails 一定是递增的、且替换是安全的：
  • tails 递增：如果 tails[k] ≥ tails[k+1]，那长度 k+2 的序列去掉最后一项就得到一个长度 k+1、结尾更小的序列，与 tails[k] 的最小性矛盾。
  • 替换是安全的：把 tails[k] 换成更小的 x，不会让任何已有的长度变短（长度 k+1 仍然可达），但为将来留下了更多接长的可能。
关键警告：tails 数组本身不是某个具体的最长上升子序列——它只是「各长度的最小结尾」的记录。要输出具体序列，需要额外记录每个元素被放到哪个位置以及它的前驱。这是本题最常见的误解。
这个贪心像整理不同高度的积木塔。tails[k] 记的是「搭 k+1 层的塔，最顶上那块最矮能有多矮」。
来了一块新积木 x：如果它比所有塔顶都高，就搭一座更高的新塔；否则找到「第一座塔顶不比 x 矮的塔」，把那个塔顶换成 x——塔还是那么高，但顶更矮了，将来更容易往上接。

所以 tails 记录的是「可能性」而不是「某个具体的塔」，这就是为什么它不能直接当答案序列输出。
严格上升还是非严格决定用 lower_bound 还是 upper_bound：
  • 严格上升（a[i] < a[j]）→ lower_bound（相等时替换掉）。
  • 非严格上升（允许相等）→ upper_bound（相等时可以接长）。
最长不下降 / 下降 / 不上升四种变体，靠「取反数组」和「换 bound」组合即可。写之前先确认题面要哪一种——这个一字之差是本题的高频错误。

3.2 LCS 与编辑距离

// 最长公共子序列：dp[i][j] = s[0..i) 与 t[0..j) 的 LCS 长度
int lcs(const std::string& s, const std::string& t) {
    int m = s.size(), n = t.size();
    std::vector<std::vector<int>> dp(m + 1, std::vector<int>(n + 1, 0));
    for (int i = 1; i <= m; ++i)
        for (int j = 1; j <= n; ++j)
            if (s[i-1] == t[j-1]) dp[i][j] = dp[i-1][j-1] + 1;
            else dp[i][j] = std::max(dp[i-1][j], dp[i][j-1]);
    return dp[m][n];
}

// 编辑距离：三种操作各对应一项转移
int edit_distance(const std::string& s, const std::string& t) {
    int m = s.size(), n = t.size();
    std::vector<std::vector<int>> dp(m + 1, std::vector<int>(n + 1));
    for (int i = 0; i <= m; ++i) dp[i][0] = i;   // 全删
    for (int j = 0; j <= n; ++j) dp[0][j] = j;   // 全插
    for (int i = 1; i <= m; ++i)
        for (int j = 1; j <= n; ++j)
            if (s[i-1] == t[j-1]) dp[i][j] = dp[i-1][j-1];
            else dp[i][j] = 1 + std::min({
                dp[i-1][j-1],   // 替换
                dp[i-1][j],     // 删除 s[i-1]
                dp[i][j-1]      // 插入 t[j-1]
            });
    return dp[m][n];
}
「下标偏移 1」是这类二维 DP 的标准做法：dp 开 (m+1) × (n+1)，dp[i][j] 表示「前 i 个和前 j 个」，字符则用 s[i-1]。
好处是dp[0][*] 和 dp[*][0] 天然表示「空串」这个合法边界，不需要任何特判。这和前缀和取 S[0]=0、二分用半开区间是同一类设计——多留一个哨兵位置，换掉一整类边界判断。

3.3 Kadane：最大子数组和

// 状态：dp[i] = 以 i 结尾的最大子数组和
// 转移：要么接上前面，要么从 i 重新开始
long long max_subarray(const std::vector<int>& a) {
    long long cur = a[0], best = a[0];
    for (size_t i = 1; i < a.size(); ++i) {
        cur = std::max((long long)a[i], cur + a[i]);   // 关键的一行
        best = std::max(best, cur);
    }
    return best;
}
Kadane 是「状态压缩到 O(1)」的最好例子：因为 dp[i] 只依赖 dp[i-1]，所以整个数组退化成一个变量。

另一个视角：最大子数组和 = max(prefix[j] − min(prefix[i]) for i < j)——即「前缀和减去之前的最小前缀和」。这个视角能推广到「长度不超过 k 的最大子数组和」（用单调队列维护窗口内的最小前缀和，见 §9.2）。

一个问题有两种等价表述时，往往能各自推广到不同的变体——这也是为什么值得同时掌握两种视角。
Kadane 的两个高频坑：① 全是负数时答案应该是最大的那个负数（如果题目不允许空子数组）——初始化成 best = 0 就错了，要初始化成 a[0]；② 环形数组的最大子数组和要分两种情况：不跨越首尾（普通 Kadane）和跨越首尾（= 总和 − 最小子数组和），取两者最大，且要处理「全是负数」时后者退化为空的情形。
04

背包全家桶

循环顺序为什么能改变语义

4.1 01 背包与循环顺序

// 二维版：dp[i][j] = 前 i 个物品、容量 j 时的最大价值
for (int i = 1; i <= n; ++i)
    for (int j = 0; j <= W; ++j) {
        dp[i][j] = dp[i-1][j];                       // 不选第 i 个
        if (j >= w[i])
            dp[i][j] = std::max(dp[i][j], dp[i-1][j - w[i]] + v[i]);  // 选
    }

// 一维滚动版：注意 j 必须倒序
std::vector<int> dp(W + 1, 0);
for (int i = 1; i <= n; ++i)
    for (int j = W; j >= w[i]; --j)              // ← 倒序
        dp[j] = std::max(dp[j], dp[j - w[i]] + v[i]);
直接决定了物品能不能重复选 01 背包：j 倒序（W → w[i]） dp[j] = max(dp[j], dp[j − w[i]] + v[i]) 倒序时 dp[j − w[i]] 还没被本轮更新过 ⟹ 它代表「上一轮（不含第 i 个物品）」的值 ⟹ 每个物品最多选 1 次 完全背包：j 正序（w[i] → W） dp[j] = max(dp[j], dp[j − w[i]] + v[i]) 正序时 dp[j − w[i]] 已被本轮更新过 ⟹ 它已经可能含第 i 个物品 ⟹ 同一物品可以重复选 外层物品、内层容量 → 组合数 每种物品只在它自己那一轮被考虑 ⟹ (1,2) 和 (2,1) 视为同一种方案 「有多少种组合凑出金额 W」用这个 外层容量、内层物品 → 排列数 每个容量下都重新考虑所有物品 ⟹ (1,2) 和 (2,1) 算两种方案 「有多少种排列（顺序不同算不同）」用这个
为什么倒序 = 01 背包：一维数组把「上一轮」和「本轮」压在了同一块内存里。
  • 倒序时，dp[j - w[i]]（下标更小）还没被本轮更新 ⟹ 它仍是「上一轮」的值，即「不含第 i 个物品」的最优解 ⟹ 第 i 个物品最多被用一次。
  • 正序时，dp[j - w[i]] 已被本轮更新过 ⟹ 它可能已经含第 i 个物品 ⟹ 该物品可以重复使用。
所以「01 背包倒序、完全背包正序」不是要背的口诀，而是「滚动数组里，下标更小的位置是新值还是旧值」的直接推论。

4.2 完全背包

// 每个物品可选无限次：j 正序
for (int i = 1; i <= n; ++i)
    for (int j = w[i]; j <= W; ++j)              // ← 正序
        dp[j] = std::max(dp[j], dp[j - w[i]] + v[i]);
完全背包的典型伪装：「零钱兑换」（最少硬币数 / 有多少种凑法）、「完全平方数」、「单词拆分」。
识别信号：「每种可以用任意多次」。反之「每种只有一个」是 01 背包，「每种有 k 个」是多重背包。读题时先找这个信号，它决定了循环方向。

4.3 多重背包与二进制拆分

做法复杂度思路
朴素（枚举取几个）O(W · Σkᵢ)对每个物品枚举取 0..k 个
二进制拆分O(W · Σlog kᵢ)把 k 个拆成 1,2,4,…,剩余，转成 01 背包
单调队列优化O(W · n)按余数分组，用单调队列维护窗口最大值
 
// 二进制拆分：把「k 个相同物品」拆成 log k 个「不同物品」
// 因为 1,2,4,...,2^t, 剩余 可以凑出 0..k 的任意个数
std::vector<std::pair<int,int>> items;   // (重量, 价值)
for (int i = 1; i <= n; ++i) {
    int k = cnt[i];
    for (int p = 1; p <= k; p *= 2) {
        items.push_back({p * w[i], p * v[i]});
        k -= p;
    }
    if (k > 0) items.push_back({k * w[i], k * v[i]});   // 剩余部分
}
// 然后对 items 跑标准 01 背包（j 倒序）
为什么二进制拆分是对的：1, 2, 4, …, 2^t, r（其中 r = k − (2^(t+1) − 1)）这组数能且只能凑出 0 到 k 之间的每一个整数。
  • 「能凑出」：1,2,4,…,2^t 可以凑出 0 到 2^(t+1)−1 的任意数（二进制表示）；加上 r 就覆盖到 k。
  • 「只能凑出」：所有数之和恰好是 k，不会超过。
于是「取 0 到 k 个」这个选择被编码成了 log k 个独立的 0/1 选择——这就是把多重背包转成 01 背包的关键。这个「用二进制表示压缩选择空间」的技巧在快速幂、稀疏表、倍增法里也是同一个思想。

4.4 分组背包与「恰好装满」

// 分组背包：每组最多选一个 → 组的循环要在容量循环外面
for (int g = 0; g < groups; ++g)
    for (int j = W; j >= 0; --j)                   // 倒序（每组最多一个，类似 01）
        for (auto& [wi, vi] : group[g])            // ← 物品循环在最内层
            if (j >= wi)
                dp[j] = std::max(dp[j], dp[j - wi] + vi);
分组背包的三层循环顺序不能换：物品循环必须在最内层。如果把它提到容量循环外面，就变成「每组可以选多个」（因为不同物品会在不同轮次被独立考虑），语义就错了。
这又是一个「循环顺序决定语义」的例子——背包这一族里，循环顺序承载的信息量极大。
「恰好装满」vs「不超过容量」：只差初值。
  • 不超过容量（求最大价值）：dp[] = 0（空背包是合法的，价值 0）。
  • 恰好装满（求最大价值）：dp[0] = 0, dp[1..W] = −∞。−∞ 表示「这个容量无法恰好装满」，从而不会被误当成合法解。
  • 恰好装满（求最小代价）：dp[0] = 0, dp[1..W] = +∞。
  • 求方案数：dp[0] = 1（空方案算一种），其余 0。
−∞ 不要用 INT_MIN——dp[j-w] + v 会溢出。用 INT_MIN / 2 或 -1e9。

4.5 组合数 vs 排列数

组合数：外层物品
// 「有多少种组合凑出金额 W」
// (1,2) 和 (2,1) 算同一种
dp[0] = 1;
for (int coin : coins)            // ← 物品在外
    for (int j = coin; j <= W; ++j)
        dp[j] += dp[j - coin];
// 每种硬币只在它自己那一轮被考虑
// → 天然按「硬币种类的顺序」构造，不会重复计数
排列数：外层容量
// 「有多少种排列（顺序不同算不同）」
// (1,2) 和 (2,1) 算两种
dp[0] = 1;
for (int j = 1; j <= W; ++j)       // ← 容量在外
    for (int coin : coins)
        if (j >= coin) dp[j] += dp[j - coin];
// 每个容量下都重新考虑所有硬币
// → 同一组硬币的不同顺序被分别计入
这是背包类计数题最容易搞混也最容易考的一点。判断方法：读题看「[1,2] 和 [2,1] 算一种还是两种」。
  • 「零钱兑换 II」（有多少种组合）→ 外层物品。
  • 「组合总和 IV」（其实求的是排列）→ 外层容量。注意这题名字叫「组合」但要的是排列，是个著名的命名陷阱。
  • 「爬楼梯」（每次走 1 或 2 级，有多少种走法）→ 顺序不同算不同 → 外层容量（就是斐波那契）。
记法：物品在外 = 物品有固定顺序 = 组合；容量在外 = 每步都能重选 = 排列。

区间 DP

按区间长度递增，枚举分界点

状态 dp[l][r] = 处理区间 [l, r] 的最优值 转移 dp[l][r] = min/max{ dp[l][k] + dp[k+1][r] + cost(l, k, r) } k 从 l 到 r−1 循环顺序 按区间长度 len 从小到大（len 是 DP 的阶段！） for (len = 2; len <= n; ++len) for (l = 0; l + len - 1 < n; ++l) { r = l + len - 1; for (k = l; k < r; ++k) ... } 复杂度 O(n³)
// 石子合并：把相邻两堆合并，代价是两堆之和，求最小总代价
int merge_stones(const std::vector<int>& a) {
    int n = a.size();
    std::vector<int> pre(n + 1, 0);
    for (int i = 0; i < n; ++i) pre[i+1] = pre[i] + a[i];   // 前缀和求区间和

    std::vector<std::vector<int>> dp(n, std::vector<int>(n, 0));
    for (int len = 2; len <= n; ++len)              // ← 阶段在最外层
        for (int l = 0; l + len - 1 < n; ++l) {
            int r = l + len - 1;
            dp[l][r] = INT_MAX;
            for (int k = l; k < r; ++k)
                dp[l][r] = std::min(dp[l][r],
                    dp[l][k] + dp[k+1][r] + (pre[r+1] - pre[l]));
        }
    return dp[0][n-1];
}
为什么必须按长度递增：dp[l][r] 依赖 dp[l][k] 和 dp[k+1][r]，它们的区间长度都严格小于 r−l+1。所以「长度」是这个 DP 的阶段维度，必须在最外层——和 Floyd 的 k 完全同理。

另一种等价写法是倒序枚举 l、正序枚举 r（for l = n-1 down to 0; for r = l+1 to n-1），它隐式保证了「更短的区间先算」。两种写法都对，但按长度显式循环更不容易出错。
典型题状态 / 转移的特点
石子合并标准形式；环形版要把数组复制一倍
矩阵链乘法cost 是三个维度的乘积
最长回文子序列dp[l][r] 只依赖 dp[l+1][r-1] 等，转移是 O(1) → 总 O(n²)
戳气球反向思考：枚举「最后一个被戳的」而不是第一个
括号匹配 / 表达式求值需要额外记录「运算符位置」
能否用 k 次操作使区间同色加一维 k
「戳气球」体现了一个重要技巧：反向思考「最后一步」。正向想「先戳哪个」会导致子问题不独立（戳掉一个后左右合并了）；反向想「最后戳哪个」则左右两段完全独立——因为最后戳它时，它两边的边界是固定的原始边界。
区间 DP 卡住时，试试把「第一步」换成「最后一步」，或者把「删除」换成「插入」。

树形 DP

状态是「子树 + 该节点的选择」

状态 dp[u][s] = 以 u 为根的子树、u 处于状态 s 时的最优值 转移 在 DFS 的后序位置，用所有孩子的 dp 值合并出 u 的 dp 值 为什么是后序 子树的信息要「从下往上收」（见「树与平衡树」§2.1 的判据）
// 没有上司的舞会：每个员工有快乐值，不能同时邀请直接上下级
// dp[u][0] = 不选 u 时，u 的子树最大快乐值
// dp[u][1] = 选 u 时
void dfs(int u) {
    dp[u][0] = 0;
    dp[u][1] = happy[u];
    for (int v : children[u]) {
        dfs(v);                                    // 先递归孩子
        dp[u][0] += std::max(dp[v][0], dp[v][1]);   // 不选 u → 孩子随意
        dp[u][1] += dp[v][0];                       // 选 u → 孩子必须不选
    }
}
// 答案：max(dp[root][0], dp[root][1])
类型状态设计典型题
选 / 不选dp[u][0/1]没有上司的舞会、最大独立集、二叉树打家劫舍
树上背包dp[u][j] = 在 u 子树选 j 个的最优值选课、有依赖的背包；合并时是「小背包合并」
换根 DP两遍 DFS：先算子树，再「把根换到每个点」「求每个点作为根时的答案」
树的直径 / 重心后序求「向下最长链」，同时更新全局答案树的直径、重心
虚树 / 点分治处理「路径统计」类问题路径长度为 k 的点对数
换根 DP 是树形 DP 里最有技巧性的一类：需求是「对每个节点 u，求以 u 为根时的答案」，朴素做法是对每个点跑一遍 DFS（O(n²)）。

换根 DP 用两遍 DFS 做到 O(n)：
  1. 第一遍（后序）：算出 down[u] = 只考虑 u 子树内部的答案。
  2. 第二遍（前序）：算出 up[u] = 从父亲那边「传下来」的贡献。关键是 up[v] 可以由 up[parent] 和 down[parent 的其他孩子] 推出。
难点在「排除自己」：算 up[v] 时需要「父亲的所有孩子里除了 v 的部分」，实现上用「前缀 + 后缀」预处理或「总和减去 v 的贡献」（后者要小心 max 不可减的问题）。
树形 DP 的两个实现坑：
  • 递归深度：链状树的 DFS 深度是 n，n = 10⁵ 时可能爆栈。改成迭代 DFS或按 BFS 序倒序处理（先算深的节点）。
  • 树上背包的复杂度容易算错：看起来是 O(n·m²)，但如果合并时按子树大小限制枚举上界（for j in [0, min(size[u], m)]），实际复杂度是 O(n·m) 或 O(n²)——这是一个经典的「看起来更慢但实际更快」的结论，证明用的是「每对点只在它们的 LCA 处被合并一次」。

状压 DP

n ≤ 20 时，把「哪些已选」压成一个整数

识别信号：n ≤ 20（有时 ≤ 22）。此时 2ⁿ ≈ 10⁶，可以把「一个子集」编码成一个整数当状态下标。

状态：dp[mask] 或 dp[mask][i]，其中 mask 的第 k 位表示「第 k 个元素是否已被使用/选中」。
// 旅行商问题（TSP）：dp[mask][i] = 已访问 mask 集合、当前在 i 的最小代价
int tsp(int n, const std::vector<std::vector<int>>& d) {
    const int INF = 0x3f3f3f3f;
    std::vector<std::vector<int>> dp(1 << n, std::vector<int>(n, INF));
    dp[1][0] = 0;                                // 从 0 出发，只访问了 0

    for (int mask = 1; mask < (1 << n); ++mask)   // mask 递增 = 阶段递增
        for (int i = 0; i < n; ++i) {
            if (!(mask >> i & 1) || dp[mask][i] == INF) continue;
            for (int j = 0; j < n; ++j) {
                if (mask >> j & 1) continue;         // j 已访问过
                int& t = dp[mask | (1 << j)][j];
                t = std::min(t, dp[mask][i] + d[i][j]);
            }
        }
    int best = INF;
    for (int i = 1; i < n; ++i)
        best = std::min(best, dp[(1<<n)-1][i] + d[i][0]);   // 回到起点
    return best;   // O(2ⁿ · n²)
}
位运算含义
mask >> i & 1第 i 位是否为 1（元素 i 是否在集合里）
mask | (1 << i)把元素 i 加入集合
mask & ~(1 << i)把元素 i 移出集合
mask & (mask - 1)去掉最低位的 1
mask & -mask只保留最低位的 1（lowbit）
__builtin_popcount(mask)集合大小（1 的个数）
for (int s = mask; s; s = (s-1) & mask)枚举 mask 的所有非空子集（总复杂度 O(3ⁿ)）
最后一行的「枚举子集的子集」值得记住：for (int s = mask; s; s = (s-1) & mask)。
它的总复杂度是 O(3ⁿ) 而不是 O(4ⁿ)——因为对每个元素有三种可能（不在 mask、在 mask 但不在 s、在 s），所以 (mask, s) 的合法配对数是 3ⁿ。
典型用途：「把集合划分成若干组」类问题（如「最少需要几辆车装完所有货物」「集合覆盖」）。
状压 DP 的两个实践限制：
  • n 的上限很硬：n=20 时 2²⁰ ≈ 10⁶ 状态，配上 O(n) 或 O(n²) 的转移是 10⁷–10⁸，勉强可行。n=25 就基本不行了（3×10⁷ 状态 × 转移）。
  • 内存：dp[1<<20][20] 用 int 是 80 MB——常常超限。要么滚动（按 popcount 分层），要么改用 short，要么改记忆化（只算可达状态）。
另外要注意 1 << n 在 n ≥ 31 时溢出，要写 1LL << n。

数位 DP

「统计 [L, R] 内满足条件的数」的标准解法

识别信号：「统计区间 [L, R] 内满足某种数位性质的数的个数」，且 R 可以很大（10¹⁸）。

两个核心技巧：
  1. 差分：ans(L, R) = f(R) − f(L−1)，把区间问题变成「统计 0 到 x」。
  2. 按位构造 + 「是否贴着上界」标记：从高位往低位填数字，用一个 limit 标记「前面的位是否都和 x 相同」——如果是，当前位只能填 0..x[i]；否则可以填 0..9。
// 统计 0..x 中「不含连续相同数字」的数的个数（示意）
std::string s;                        // x 的十进制字符串
int memo[20][11];                   // [位置][上一位数字]，只缓存 limit=false 的状态

int dfs(int pos, int prev, bool limit, bool started) {
    if (pos == (int)s.size()) return started ? 1 : 0;
    // 只有「不贴上界且已开始」的状态才能复用（因为它们与 x 无关）
    if (!limit && started && memo[pos][prev] != -1) return memo[pos][prev];

    int up = limit ? s[pos] - '0' : 9;   // ← limit 决定上界
    int res = 0;
    for (int d = 0; d <= up; ++d) {
        if (started && d == prev) continue;         // 题目约束：不能连续相同
        res += dfs(pos + 1, d,
                   limit && (d == up),                // 仍贴上界？
                   started || d > 0);                // 处理前导零
    }
    if (!limit && started) memo[pos][prev] = res;
    return res;
}
数位 DP 的三个必踩坑：
  • 只能缓存 limit == false 的状态。limit == true 的状态依赖具体的 x（每个 x 只会走一条这样的路径），缓存它们会导致跨查询污染。这是最本质也最容易错的一点。
  • 前导零必须单独处理。「012」和「12」是同一个数，但在按位构造里是不同的路径。用 started（或 lead）标记「是否已经开始填有效数字」——很多题的约束（如「不含连续相同数字」）在前导零阶段不应生效。
  • memo 的维度必须覆盖所有「影响后续决策」的信息。漏一维就会把不同的状态混为一谈。而多一维只是浪费空间，所以不确定时宁可多加。
数位 DP 像按位填写一个不超过给定上限的车牌号。
如果前面几位都和上限完全一样（limit = true），那当前这位就不能超过上限对应的那一位——你被「贴着天花板」了。
但只要有任何一位填得比上限小，后面就彻底自由（limit = false）——可以填 0–9 任意值。

而「彻底自由」的状态才可以缓存复用：因为它们和具体的上限已经无关了，只取决于「还剩几位」和「前面留下的约束信息」。这就是为什么只缓存 limit == false。

优化四件套

每一种都有明确的适用判据

9.1 滚动数组

适用 dp[i][...] 只依赖 dp[i-1][...]（或最近几层） 做法 用 dp[2][...] 交替，或直接压成一维（背包的做法） 收益 空间 O(n·m) → O(m)，时间不变 代价 无法回溯具体方案（旧层被覆盖了）
滚动数组最大的代价是丢掉了方案还原能力。如果题目要求输出具体方案（选了哪些物品、LCS 是什么），就不能滚动——或者要额外记录决策（每个状态记「从哪来」，空间又回到 O(n·m)）。
先确认题目要不要输出方案，再决定是否滚动。

9.2 单调队列优化

适用形式 dp[i] = max/min{ dp[j] + w(i) : i−k ≤ j < i } 候选集是一个随 i 单调右移的窗口，且转移里对 j 求 max/min 关键 候选之间的优劣只依赖 j（与 i 无关） ⟹ 「谁支配谁」是绝对的 ⟹ 可以永久丢弃 收益 O(n·k) → O(n)
// 跳跃游戏 VI：每步最多跳 k 格，求到终点的最大得分
std::deque<int> dq;                     // 存下标，dp 值递减
dp[0] = a[0]; dq.push_back(0);
for (int i = 1; i < n; ++i) {
    if (dq.front() < i - k) dq.pop_front();       // 过期
    dp[i] = dp[dq.front()] + a[i];                // 队首是窗口内 dp 最大者
    while (!dq.empty() && dp[dq.back()] <= dp[i])
        dq.pop_back();                            // 被支配
    dq.push_back(i);
}
除了「窗口最值」，还有两种常见的用数据结构加速转移：
  • 前缀和加速：转移形如 dp[i] = Σ dp[j]（j 在某区间） → 维护 dp 的前缀和，O(1) 查区间和。
  • 树状数组 / 线段树加速：转移形如 dp[i] = max{dp[j] : a[j] < a[i]}（候选集由值而非位置决定）→ 用值域树状数组维护前缀 max，把 LIS 从 O(n²) 降到 O(n log n)。
共同思路：把「对候选集求聚合」交给一个支持增量更新的数据结构。识别信号是「内层循环在做一个可以用数据结构回答的查询」。

9.3 斜率优化

适用形式 dp[i] = min{ dp[j] + (something involving i × j) } 例：dp[i] = min{ dp[j] + (S[i] − S[j])² } 展开 = dp[j] + S[i]² − 2·S[i]·S[j] + S[j]² ↑ i 与 j 的乘积项 关键差别（与单调队列对比） 候选优劣依赖 i ⟹ 不能简单丢弃 ⟹ 要维护一个下凸壳 按斜率查询（i 单调时可以用单调队列维护凸壳）
单调队列优化 vs 斜率优化，一句话判据：
「候选之间的优劣关系是否与 i 无关？」
  • 无关（dp[i] = max{dp[j]} + w(i)）→ 单调队列。丢弃是永久的。
  • 有关（转移里有 i × j 的乘积项）→ 斜率优化 / 凸包技巧。丢弃要看斜率区间。
两者复杂度都是 O(n)，但维护的不变式不同：一个是单调序列，一个是凸壳。这两者常被混为一谈，而判据就是上面那一句。

如果查询的斜率不单调，就要用李超线段树或在凸壳上二分（O(n log n)）。

9.4 决策单调性与分治

适用 最优决策点 opt[i] 关于 i 单调不减 （但转移不是窗口形式，所以单调队列用不上） 做法 分治优化：solve(lo, hi, optL, optR) 取 mid = (lo+hi)/2，在 [optL, optR] 里暴力找 opt[mid] 然后递归 solve(lo, mid-1, optL, opt[mid]) solve(mid+1, hi, opt[mid], optR) 收益 O(n²) → O(n log n)
怎么判断有决策单调性：理论上要验证代价函数满足四边形不等式（w(a,c) + w(b,d) ≤ w(a,d) + w(b,c)，其中 a≤b≤c≤d）。
但实践中（尤其竞赛里）常用打表验证：写朴素 O(n²) 版本，输出每个 i 的最优决策点，肉眼看它是否单调。这不严谨但很有效——而且如果不单调，你立刻就知道这个优化不适用。

四边形不等式还能给出区间 DP 的 O(n²) 优化（把 dp[l][r] 的枚举范围限制在 [opt[l][r-1], opt[l+1][r]]），石子合并就能从 O(n³) 降到 O(n²)。

  1. 基础什么问题适合用 DP？和分治、贪心、回溯怎么区分？

    ① 最优子结构
    最优解可以由子问题的最优解组合出来 —— 这是能「递推」的前提。
    ② 重叠子问题
    同一个子问题在递归展开中被反复遇到 —— 这是「记下来」有价值的前提。
    情形用什么
    有最优子结构 + 无重叠子问题分治（归并排序、快速选择）
    有最优子结构 + 有重叠子问题DP
    局部最优即全局最优（且能证明）贪心——可以看成「不需要记状态的 DP」
    没有最优子结构回溯 + 剪枝，或换一个有最优子结构的建模
    DP 的本质
    「把指数级的搜索空间折叠成多项式个状态」。而状态设计就是在回答：要记住哪些信息，才足以让后面的决策不依赖更早的历史？
    多记浪费（状态数爆炸），少记就错（后面的决策需要它）。
    写 DP 的建议流程
    先用记忆化递归写（和「状态定义 + 转移」一一对应，最不容易想错），确认对了再改自底向上（消栈深），最后按需压缩空间。
    直接写自底向上容易在循环顺序上出错，而循环顺序错不报错、只给错答案。
  2. 基础01 背包的一维写法为什么 j 要倒序？完全背包为什么正序？

    因为一维数组把「上一轮」和「本轮」压在了同一块内存里，j 的方向决定了 dp[j - w[i]] 读到的是旧值还是新值。

    dp[j] = max(dp[j], dp[j - w[i]] + v[i]);
    倒序（j: W → w[i]）= 01 背包
    dp[j - w[i]] 下标更小，还没被本轮更新 ⟹ 它仍是「上一轮」的值，即「不含第 i 个物品」的最优解 ⟹ 第 i 个物品最多被用一次。
    正序（j: w[i] → W）= 完全背包
    dp[j - w[i]] 已被本轮更新过 ⟹ 它可能已经含第 i 个物品 ⟹ 该物品可以重复使用。
    所以这不是要背的口诀
    它是「滚动数组里下标更小的位置是新值还是旧值」的直接推论。理解了这一点，遇到新的背包变体也能自己推出方向。
    还有第二组顺序也决定语义
    「物品在外层 vs 容量在外层」决定组合数还是排列数（求方案数时）：
    · 物品在外 → 每种物品只在自己那一轮被考虑 → (1,2) 和 (2,1) 算同一种 → 组合数
    · 容量在外 → 每个容量下都重新考虑所有物品 → 算两种 → 排列数
    「零钱兑换 II」求组合（物品在外）；「组合总和 IV」名字叫组合但其实求排列（容量在外）——这是个著名的命名陷阱。
  3. 基础LIS 的 O(n log n) 解法是什么？tails 数组是最长上升子序列吗？

    贪心 + 二分。维护 tails[k] = 长度为 k+1 的上升子序列的最小可能结尾。

    for (int x : a) {
    auto it = std::lower_bound(tails.begin(), tails.end(), x);
    if (it == tails.end()) tails.push_back(x);   // 能接长
    else *it = x;                                  // 替换成更小的结尾
}
return tails.size();
    为什么 tails 递增
    若 tails[k] ≥ tails[k+1]，那长度 k+2 的序列去掉最后一项就得到一个长度 k+1、结尾更小的序列，与 tails[k] 的最小性矛盾。
    为什么替换是安全的
    把 tails[k] 换成更小的 x，不会让任何已有长度变短（长度 k+1 仍可达），但为将来留下更多接长的可能。
    tails 不是答案序列（本题最常见的误解）
    它只是「各长度的最小结尾」的记录，不对应任何一个具体的上升子序列。
    要输出具体序列，需额外记录「每个元素被放到哪个位置」以及它的前驱，最后回溯。
    严格 vs 非严格
    严格上升（<）→ lower_bound（相等时替换掉）。
    非严格（允许相等）→ upper_bound（相等时可接长）。
    「最长不下降 / 下降 / 不上升」四种变体靠「取反数组」和「换 bound」组合。写之前先确认题面要哪一种。
  4. 基础「恰好装满」和「不超过容量」的背包差别在哪？

    只差初值。转移方程完全一样。

    问题dp[0]dp[1..W]
    不超过容量，求最大价值00（空背包合法，价值 0）
    恰好装满，求最大价值0−∞
    恰好装满，求最小代价0+∞
    求方案数1（空方案算一种）0
    为什么 −∞ 能表达「恰好」
    −∞ 表示「这个容量无法恰好装满」。因为它极小，任何从它转移来的状态也会是极小值，不会被误当成合法解。
    而初值全 0 意味着「任何容量都可以什么都不装地『装满』」——那就变成了「不超过容量」的语义。
    −∞ 不要用 INT_MIN
    dp[j - w] + v 会有符号溢出（UB），可能变成一个很大的正数从而污染答案。
    用 INT_MIN / 2 或 -1e9（并确保后续加法不会再溢出）。这是个高频且难查的 bug——用 -fsanitize=undefined 能直接抓到。
    最后判断答案时也要小心
    如果 dp[W] 仍是 −∞（或小于某个阈值），要输出「无解」而不是那个负数。

11.2 中级（区分熟练度）

  1. 中级区间 DP 为什么必须按区间长度从小到大循环？

    因为 dp[l][r] 依赖 dp[l][k] 和 dp[k+1][r]，它们的区间长度都严格小于 r−l+1。所以「长度」是这个 DP 的阶段维度，必须在最外层。

    for (len = 2; len <= n; ++len) ← 阶段 for (l = 0; l + len - 1 < n; ++l) { r = l + len - 1; for (k = l; k < r; ++k) ← 枚举分界点 dp[l][r] = min(dp[l][r], dp[l][k] + dp[k+1][r] + cost); } 复杂度 O(n³)
    和 Floyd 完全同理
    Floyd 的 k（允许经过哪些中间点）也是阶段维度，必须最外层。「DP 的阶段必须在最外层」是一条通用规律，同样适用于背包的物品维、状压 DP 的 mask 递增。
    等价的另一种写法
    倒序枚举 l、正序枚举 r（for l = n-1 downto 0; for r = l+1 to n-1），隐式保证了「更短的区间先算」。两种写法都对，但按长度显式循环更不易出错。
    一个重要技巧：反向思考「最后一步」
    「戳气球」正向想「先戳哪个」会导致子问题不独立（戳掉一个后左右合并了）；反向想「最后戳哪个」则左右两段完全独立——因为最后戳它时，两边的边界是固定的原始边界。
    区间 DP 卡住时，试试把「第一步」换成「最后一步」，或把「删除」换成「插入」。
    优化到 O(n²)
    如果代价函数满足四边形不等式，可以用决策单调性把 k 的枚举范围限制在 [opt[l][r-1], opt[l+1][r]]，石子合并就能从 O(n³) 降到 O(n²)。
  2. 中级多重背包的二进制拆分为什么是对的？

    把「k 个相同物品」拆成 1, 2, 4, …, 2^t, r 这几个「不同物品」，然后跑标准 01 背包。复杂度从 O(W·Σkᵢ) 降到 O(W·Σlog kᵢ)。

    int k = cnt[i];
for (int p = 1; p <= k; p *= 2) {
    items.push_back({p * w[i], p * v[i]});
    k -= p;
}
if (k > 0) items.push_back({k * w[i], k * v[i]});   // 剩余
    正确性：这组数「能且只能」凑出 0 到 k
    「能凑出」：1,2,4,…,2^t 能凑出 0 到 2^(t+1)−1 的任意整数（就是二进制表示）；加上剩余 r 就覆盖到 k。
    「只能凑出」：所有数之和恰好是 k，不会超过。
    于是「取 0 到 k 个」这个选择被编码成 log k 个独立的 0/1 选择。
    「用二进制压缩选择空间」是个通用技巧
    同族的还有：快速幂（把 a^n 拆成 log n 次平方）、稀疏表（用 2^k 长度的区间覆盖任意区间）、倍增法（LCA、树上跳 k 步）。
    共同点：把「连续的 0..k 范围」表示成 log k 个二进制位，从而把线性的枚举变成对数的组合。
    还有更优的做法
    单调队列优化可以做到 O(W·n)：按 j mod w[i] 的余数分组，同一组内的转移就变成了「窗口内求最大值」（窗口大小 k），用单调队列 O(1) 摊销。
    代码更长，但复杂度更好。竞赛里 k 很大时用它。
  3. 中级数位 DP 里为什么只能缓存 limit == false 的状态？

    因为 limit == true 的状态依赖具体的上界 x，不能跨查询（甚至不能跨不同的高位选择）复用。

    limit 的含义
    limit == true 表示「前面填的每一位都和上界 x 完全相同」——此时当前位只能填 0..x[pos]。
    limit == false 表示「前面已有某位填得比 x 小」——此时后面彻底自由，可以填 0..9。
    为什么 limit=true 不能缓存
    对每个上界 x，limit == true 的路径只有一条（沿着 x 的各位走下来）。缓存它毫无收益，而且换一个 x 时这个值就错了——因为它算的是「在 x 的约束下」的结果。
    而 limit == false 的状态与 x 无关，只取决于「还剩几位」和「前面留下的约束信息」，所以可以放心缓存和复用。
    if (!limit && started && memo[pos][prev] != -1)
    return memo[pos][prev];
// ... 计算 ...
if (!limit && started) memo[pos][prev] = res;   // 只在这个条件下写缓存
    第二个必踩坑：前导零
    「012」和「12」是同一个数，但按位构造时是不同路径。用 started（或 lead）标记「是否已开始填有效数字」。
    很多题的约束在前导零阶段不应生效——比如「不含连续相同数字」，前导零不算数字。
    第三个坑：memo 维度漏了
    memo 的维度必须覆盖所有影响后续决策的信息。漏一维会把不同状态混为一谈（答案错）；多一维只是浪费空间。不确定时宁可多加。
    整体框架
    差分：ans(L,R) = f(R) − f(L−1)，把区间问题变成「统计 0 到 x」。然后按位构造 + limit 标记 + 记忆化。
  4. 中级单调队列优化和斜率优化怎么区分？

    一句话判据：「候选之间的优劣关系是否与 i 无关？」

    无关 → 单调队列
    转移形如 dp[i] = max{dp[j]} + w(i)，其中 w(i) 只依赖 i。
    此时比较两个候选 j₁、j₂ 只需比 dp[j₁] 和 dp[j₂]——与 i 无关。
    ⟹ 「谁支配谁」是绝对的 ⟹ 被支配者可以永久丢弃 ⟹ 单调队列。
    再加上「候选集是随 i 单调右移的窗口」，就得到 O(n)。
    有关 → 斜率优化 / 凸包技巧
    转移形如 dp[i] = min{dp[j] + (S[i] − S[j])²}，展开后有 −2·S[i]·S[j] 这种 i 与 j 的乘积项。
    此时哪个候选更优取决于 i（相当于取决于查询的斜率）⟹ 不能简单丢弃 ⟹ 要维护一个下凸壳，按斜率查询。
    单调队列斜率优化
    维护的不变式单调序列凸壳
    丢弃是否永久是否（要看斜率区间）
    复杂度O(n)O(n)（斜率单调）/ O(n log n)（不单调）
    斜率不单调时—用李超线段树或凸壳上二分
    还有第三种：决策单调性 + 分治
    如果最优决策点 opt[i] 关于 i 单调不减，但转移不是窗口形式（单调队列用不上），可以用分治优化做到 O(n log n)。
    怎么判断：理论上验证代价函数满足四边形不等式；实践中常用打表验证——写朴素 O(n²) 版，输出每个 i 的最优决策点，看它是否单调。不严谨但有效，而且不单调时你立刻知道这个优化不适用。

11.3 高级（体现深度）

  1. 高级拿到一道你没见过的 DP 题，你的思考流程是什么？

    五步，顺序不能乱。

    ① 先看 n 的范围反推复杂度
    n ≤ 20 → 状压或回溯；n ≤ 500 → O(n³) 区间 DP；n ≤ 5000 → O(n²)；n ≤ 10⁵ → 必须 O(n log n) 或 O(n)，说明需要优化；值域大但位数少 → 数位 DP。
    这一步反推出「状态大概有几维」，比盲想快得多。
    ② 定义状态：问「要记住哪些信息」
    关键问题是「后面的决策还依赖哪些历史信息？」——那些就是状态。
    看题面里的关键词找信号：「容量/预算」→ 加一维；「区间 [l,r]」→ 两维；「子树」→ 树形；「n≤20 + 哪些已用」→ 位掩码；「最多 k 次操作」→ 加一维 k；「持有/不持有」→ 状态机。
    宁可多加一维——多加只是慢，少加是错。
    ③ 写转移：站在「最后一步」
    问「最后这一步有几种选择？」——每种选择对应一项转移。
    爬楼梯：走 1 级还是 2 级；01 背包：最后一个物品选不选；LCS：最后两字符相等吗；区间 DP：最后合并的分界点在哪。
    如果正向想不通，试试反向（「戳气球」枚举最后戳的而不是先戳的）。
    ④ 定初值与循环顺序
    初值：「无解」用 ±∞ 还是 0？「空」是合法状态吗？
    循环顺序：DP 的「阶段」必须在最外层（区间长度、Floyd 的 k、背包的物品）。滚动数组时正序/倒序决定语义。
    ⑤ 最后才优化
    滚动数组 / 单调队列 / 斜率优化 / 决策单调性。不要提前优化——优化会掩盖状态设计的问题，而且没优化的版本正是你对拍的基准。
    还有一条元建议：先写记忆化递归
    它和「状态定义 + 转移」一一对应，最不容易想错，而且不用操心循环顺序。确认对了再改自底向上。
    然后一定要暴力对拍——DP 的两类最难查的 bug（循环顺序错、状态漏维）都不报错、只给错答案，而且常在小数据上碰巧对。暴力版通常十几行，对拍成本极低。
  2. 高级DP 的状态设计怎么判断「维度够不够」？举一个漏维的例子。

    判据：「给定当前状态，后续的最优决策是否完全确定，不再依赖任何更早的历史？」如果还依赖，就说明维度不够。

    漏维例子一 · 股票买卖含冷却期
    「买卖股票，卖出后有 1 天冷却期」。
    只用 dp[i]（第 i 天的最大收益）不够——后续决策还依赖「我现在持有股票吗」和「昨天是否刚卖出」。
    正解：dp[i][0/1/2] = 第 i 天结束时「持有 / 不持有且不在冷却 / 冷却中」的最大收益。这是状态机 DP。
    漏维例子二 · 打家劫舍 III（树上）
    只用 dp[u]（u 子树的最大值）不够——父节点的决策依赖「u 自己有没有被选」。
    正解：dp[u][0/1]。
    漏维例子三 · 「最多交易 k 次」
    只用 dp[i][持有] 不够——还依赖「已经交易了几次」。
    正解：dp[i][j][持有]，j 是已用交易次数。
    自检方法：构造反例
    怀疑维度不够时，构造两个「当前状态相同但历史不同」的输入，看它们的最优后续决策是否相同。
    不同 → 说明有信息没被记进状态 → 需要加维。
    这比盯着方程想更有效，因为它把抽象问题变成了具体检验。
    反过来：维度过多的代价
    多加一维只是空间和时间变差（可能超限），但答案是对的。所以不确定时宁可多加，跑通后再想能不能去掉。
    去掉维度的常见理由：① 那一维的值可以由其他维推出（冗余）；② 那一维只有最后一层有用（可以滚动）；③ 那一维的取值范围极小可以枚举。
  3. 高级树上背包的复杂度为什么是 O(n·m) 而不是 O(n·m²)？

    关键在合并时按子树大小限制枚举上界——这是一个「看起来只是小优化，实际改变了复杂度量级」的经典结论。

    // 树上背包：dp[u][j] = 在 u 子树里选 j 个的最优值
void dfs(int u) {
    size[u] = 1;
    for (int v : children[u]) {
        dfs(v);
        // 合并 v 的子树：枚举上界用 size 而不是 m
        for (int j = std::min(size[u], m); j >= 0; --j)
            for (int k = 0; k <= std::min(size[v], m - j); ++k)
                dp[u][j+k] = std::max(dp[u][j+k], dp[u][j] + dp[v][k]);
        size[u] += size[v];      // ← 合并后才更新 size
    }
}
    证明：每对点只在它们的 LCA 处被合并一次
    内层双重循环的执行次数是 size[u] × size[v]——这恰好是「u 已合并部分的点」与「v 子树的点」的配对数。
    而任意一对点 (x, y)，只会在它们的最近公共祖先那一次合并中被计数一次。
    所以总执行次数 = 点对总数 = O(n²)。
    如果还有容量上限 m，则是 O(n·m)（每个点最多和 m 个「已选数量」配对）。∎
    写成 O(n·m²) 的错法
    for (int j = m; j >= 0; --j)          // ❌ 上界用 m 而不是 size[u]
    for (int k = 0; k <= m - j; ++k)
    这样每个节点都做满 m² 次，总共 O(n·m²)。而且它不会报错，只是慢——所以很多人写出来 TLE 却不知道差在哪。
    还有一个必须注意的顺序
    size[u] += size[v] 必须在合并之后——因为循环上界用的是「已合并部分的大小」。写在前面会让上界偏大，虽然答案还对但复杂度退化。
    这类分析的一般名字
    它属于「启发式合并 / 小到大合并」的复杂度分析家族，同族的还有：DSU on tree（树上启发式合并，O(n log n)）、线段树合并（O(n log n)）、并查集按大小合并（深度 O(log n)）。
    共同的分析套路是「换个角度数总量」——不数「每次操作多少」，而数「某个量总共变化多少」。这和摊销分析的势能法是同一个思想。
  4. 高级一个 O(n²) 的 DP 在 n = 10⁵ 时超时，有哪些优化路径？

    先定位「n² 是从哪来的」——通常是「外层枚举 i，内层枚举所有候选 j」。优化就是把内层的 O(n) 查询变成 O(1) 或 O(log n)。按适用条件排序：

    ① 候选集是滑动窗口 + 求 max/min → 单调队列，O(n)
    转移形如 dp[i] = max{dp[j] : i−k ≤ j < i} + w(i)。
    判据：候选优劣只依赖 j（与 i 无关） ⟹ 被支配者可永久丢弃。
    ② 转移里有 i×j 的乘积项 → 斜率优化，O(n)
    如 dp[i] = min{dp[j] + (S[i]−S[j])²}。
    判据：候选优劣依赖 i ⟹ 不能简单丢弃，要维护下凸壳按斜率查询。斜率不单调时用李超线段树（O(n log n)）。
    ③ 转移是区间求和 → 前缀和，O(n)
    dp[i] = Σ dp[j]（j 在某区间） → 维护 dp 的前缀和，O(1) 查区间和。最简单也最容易被忽略。
    ④ 候选集由「值」而非「位置」界定 → 树状数组 / 线段树，O(n log n)
    dp[i] = max{dp[j] : a[j] < a[i]}（LIS 的形式）→ 用值域树状数组维护前缀 max，先离散化。
    ⑤ 最优决策点单调 → 分治优化，O(n log n)
    opt[i] 关于 i 单调不减，但转移不是窗口形式。怎么判断：验证四边形不等式，或打表看 opt[i] 是否单调（实践中的常用手段）。
    但优化前先问两个问题
    ①「状态设计能不能简化？」——有时 O(n²) 是因为状态多了一维不必要的信息。重新想状态定义可能直接降到 O(n)。
    ②「有没有更好的算法族？」——比如某些 DP 其实可以用贪心（如区间调度）、或者转成图论问题（DAG 最长路）。换算法族的收益通常大于优化转移。
    这五种优化的共同思路
    「把对候选集的聚合查询交给一个支持增量更新的数据结构」。
    识别信号很统一：内层循环在做一个「可以用数据结构回答的查询」（区间最值、区间和、前缀 max、凸壳上的最优线）。
    看到这个形状，就该问「哪个结构能 O(1) 或 O(log n) 回答它」。
