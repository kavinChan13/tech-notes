贪心与回溯

贪心和回溯是搜索策略的两个极端：贪心每步只走一条路，赌它一定对；回溯每步都试所有路，靠剪枝活下来。所以这两个话题的核心都不是模板——贪心的核心是证明（交换论证、拟阵），回溯的核心是剪枝和去重。这一篇把这两件事讲透，并给出「贪心什么时候会失效」的可操作判据。

核心难度 ★★★★☆ 面试出现率 极高 阅读时长 ~38 min 前置 排序 · 递归 · DP
交换论证 拟阵直觉 区间调度与 Huffman 回溯三要素与去重 N 皇后位运算 分支限界
01

两种极端策略

贪心是「不记状态的 DP」，回溯是「没有重叠子问题的 DP」

贪心动态规划回溯
每步的选择只选一个，不回头枚举所有选择，记下最优试所有选择，失败就撤销
需要的性质贪心选择性质 + 最优子结构最优子结构 + 重叠子问题无（但需要可剪枝才实用）
复杂度通常 O(n log n)多项式指数
难点证明它对设计状态剪枝与去重
写错的表现安静地给出次优解安静地给出错误答案超时，或答案重复/遗漏
三者是一条连续谱：
  • 贪心可以看成「不需要记状态的 DP」——因为每步的最优选择不依赖任何历史信息，所以状态维度为 0。
  • DP 在贪心不成立时接手：需要记住一些状态，但子问题重叠，所以能把指数折叠成多项式。
  • 回溯在 DP 也不成立时接手：子问题不重叠（或状态空间太大无法枚举），只能真的搜。
所以拿到一道题的思考顺序应该是：能贪心吗？（最快）→ 能 DP 吗？→ 只能搜吗？
贪心像不带地图爬山，每步都朝最陡的方向走。快，但可能停在半山腰的小山包上（局部最优）。只有当地形保证「一路向上就能到最高峰」时它才对——而证明这一点就是贪心的全部难度。

回溯像系着绳子探洞：每个岔路都进去看看，走不通就顺着绳子退回来换一条。一定能找到出口，但洞穴分支太多时会走到天荒地老。剪枝就是「一眼看出某条路必然走不通，直接不进去」——它不改变最坏复杂度，但在实际数据上往往是几个数量级的差距。

1.1 与其他章节的关系

  • 动态规划 —— 贪心是「不记状态的 DP」；贪心失效时退回 DP
  • 排序全景 —— 绝大多数贪心的第一步是排序；「按什么排」就是贪心策略本身
  • 堆与 Top-K —— Huffman、任务调度类贪心靠堆维护「当前最优候选」
  • 最短路与最小生成树 —— Dijkstra、Kruskal、Prim 都是贪心，正确性靠交换论证
  • 复杂度与分析 —— §7.2 遇到 NP-hard 的五条出路
  • 递归与分治 —— 回溯的 RAII 式状态恢复、深度爆栈
02

贪心的正确性证明

写不出证明就不该用贪心

2.1 交换论证

交换论证（exchange argument）是证明贪心最常用的方法，模板是：
  1. 假设存在一个最优解 OPT，它和贪心解 G 不同。
  2. 找到第一个不同的位置——贪心在这里选了 g，OPT 选了 o。
  3. 证明：把 OPT 里的 o 换成 g（并适当调整后面），得到的新解 不比 OPT 差。
  4. 于是存在一个「和贪心一致得更多」的最优解。反复应用，最终得到「贪心解本身就是最优解」。∎
关键在第 3 步：要说清「换完之后为什么仍然合法，且不变差」。这一步说不清，贪心就是错的。
不少于 OPT 选的那个 ⟹ 把 OPT 的第一个换成贪心选的那个，后面所有区间仍然合法 ⟹ 新解区间数不变（仍是最优）且和贪心多一致一个 ⟹ 反复应用即得贪心最优 ∎

2.2 前缀最优（归纳）

另一种常用证法：用归纳法证明「贪心的每一步前缀都是该规模下的最优解」。
  • 基础：n=1 时显然最优。
  • 归纳步：假设前 k 步的贪心解是「处理前 k 个元素」的最优解，证明加上第 k+1 步的贪心选择后仍最优。
适用场景：贪心是「逐个处理元素」的形态（Kadane、加油站、跳跃游戏）。
而交换论证更适合「先排序、再按序选」的形态（区间调度、Huffman）。
面试里被问「你怎么知道这个贪心是对的」时，不要说「感觉上应该对」或「试了几个例子都对」。至少要给出：
  • 交换论证的第 3 步：「因为贪心选的这个 X，它在 Y 这个维度上不比别的差，所以换过来不会让后面变糟」。
  • 或者一个反例的排除：「如果不这样选，就会出现 Z 这种情况，而它一定不优」。
能说出一句形式化的论证，比多做十道贪心题更能体现水平。

2.3 拟阵与「为什么有的贪心一定对」

拟阵（matroid）是「贪心一定正确」的一个充分条件的抽象。一个拟阵是二元组 (S, I)，其中 I 是 S 的一些子集（称为「独立集」），满足：
  • 遗传性：独立集的任意子集也独立。
  • 交换性：若 A、B 都独立且 |A| < |B|，则 B 中存在元素 x 使 A ∪ {x} 仍独立。
定理：在拟阵上，「按权重降序贪心地加入元素（只要保持独立）」一定得到最大权独立集。

Kruskal 求 MST 正是这个定理的直接应用——「森林」（无环边集）构成一个图拟阵，Kruskal 就是标准的拟阵贪心。
拟阵的两条公理像「组队规则」。
遗传性：一支合法的队伍，去掉几个人后还是合法的（不会因为人少了就违规）。
交换性：如果 A 队人比 B 队少，那 B 队里总能找到一个人加入 A 队而不违规。

满足这两条时，「按能力从高到低挑人，能加就加」就一定能组出最强的队——因为交换性保证了「你不会因为前面挑得不好而卡死」。

这也解释了为什么很多贪心是错的：它们的约束不满足交换性。比如 01 背包——两个都不超重的物品集合，人少的那个未必能从人多的那个里加进任何一件（可能都超重），所以贪心不成立。
实践中很少需要真的验证拟阵公理（那通常比直接做交换论证更难）。它的价值是提供一个直觉判据：
「如果我前面贪心地选了一些，会不会导致后面『无路可走』而其他选法能走通？」
  • 不会（总能继续扩充）→ 结构可能是拟阵，贪心有戏。
  • 会（前面选错就卡死）→ 贪心很可能错，考虑 DP。
这个问法比背拟阵定义实用得多。

经典贪心

四族，每族的「排序依据」就是贪心策略本身

3.1 区间调度

// 最多能安排多少个互不重叠的会议？→ 按结束时间升序贪心
int max_non_overlap(std::vector<std::pair<int,int>> iv) {
    std::sort(iv.begin(), iv.end(),
              [](auto& a, auto& b) { return a.second < b.second; });  // 按结束时间
    int cnt = 0, last_end = INT_MIN;
    for (auto& [s, e] : iv)
        if (s >= last_end) { ++cnt; last_end = e; }
    return cnt;
}
为什么按「结束时间」而不是「开始时间」或「时长」：
贪心选结束最早的那个，是因为它给后面留下的时间最多。交换论证的第 3 步就是这句话——把最优解的第一个换成「结束最早的那个」，后面的区间仍然全部合法（因为可用时间只增不减）。

另外两种排序都是错的：
  • 按开始时间：反例 [0,10], [1,2], [3,4] —— 先选 [0,10] 就只能选 1 个，实际能选 2 个。
  • 按时长：反例 [0,5], [4,6], [5,10] —— 先选最短的 [4,6] 就只能选 1 个，实际能选 2 个（[0,5] 和 [5,10]）。
问题按什么排序 / 策略
最多不重叠区间数结束时间升序
最少删除多少区间使不重叠同上（总数 − 最多不重叠数）
最少需要几个会议室扫描线（不是贪心排序）或最小堆维护「各室的结束时间」
用最少的点覆盖所有区间结束时间升序，每次在当前区间的右端放点
区间合并开始时间升序，然后依次合并
最少区间数覆盖 [0, T]开始时间升序，每步在「能接上的」里选右端最远的
注意表里「按结束排」和「按开始排」各有其题，不能一概而论：
  • 「选最多个」（互斥选择）→ 按结束排，因为要给未来留余地。
  • 「合并 / 覆盖」（连续处理）→ 按开始排，因为要按顺序推进。
读题时先分清是「选择型」还是「推进型」。

3.2 区间覆盖与合并

// 用最少的区间覆盖 [0, T]
int min_cover(std::vector<std::pair<int,int>> iv, int T) {
    std::sort(iv.begin(), iv.end());          // 按开始时间
    int cnt = 0, cur_end = 0, i = 0, n = iv.size();
    while (cur_end < T) {
        int far = cur_end;
        // 在所有「能接上当前位置」的区间里，选右端最远的
        while (i < n && iv[i].first <= cur_end) {
            far = std::max(far, iv[i].second);
            ++i;
        }
        if (far == cur_end) return -1;         // 无法继续覆盖 → 无解
        cur_end = far;
        ++cnt;
    }
    return cnt;
}
这个「在能接上的里面选最远的」模式适用于一大族题：跳跃游戏（最少跳几次）、加油站（最少加几次油）、视频拼接、用最少的箭引爆气球。
识别信号：「用最少的 X 覆盖 / 到达 Y」。
实现要点：用双指针，i 全程只前进（这是 O(n) 而不是 O(n²) 的关键，见 双指针 §2.1 的势能论证）。

3.3 Huffman 编码

// 每次取出两个最小的合并 → 用最小堆
long long huffman_cost(const std::vector<int>& freq) {
    std::priority_queue<long long, std::vector<long long>,
                        std::greater<>> pq(freq.begin(), freq.end());
    long long total = 0;
    while (pq.size() > 1) {
        long long a = pq.top(); pq.pop();
        long long b = pq.top(); pq.pop();
        total += a + b;              // 合并代价
        pq.push(a + b);
    }
    return total;                    // = 加权路径长度 = 编码总长
}
Huffman 的交换论证：设频率最小的两个字符是 x、y。
  • 断言：存在一棵最优编码树，其中 x 和 y 是最深层的一对兄弟。
  • 论证：取任意最优树 T，设它最深层的一对兄弟是 a、b。因为 x、y 频率最小，把 x 与 a 交换、y 与 b 交换后，加权路径长度不会增加（频率小的换到更深处，频率大的换到更浅处）。
  • 所以可以先把 x、y 合并成一个「超级节点」（频率 = 两者之和），问题规模减一，递归应用即得 Huffman 算法。∎
Huffman 的骨架（「反复取两个最小的合并」）适用于一族「合并代价」问题：合并果子、连接绳子的最小费用、最优归并树。
但要注意区分：如果要求只能合并相邻的（如石子合并），那贪心失效——必须用区间 DP。「能否任意合并」是这一族的分界线。

3.4 排序不等式类

问题贪心策略证明要点
最小化平均等待时间（单机调度）按处理时长升序（SJF）交换相邻两个，短的在前总代价更小
两个数组配对求最小/最大内积一升一降配 / 同序配排序不等式
拼接数字使结果最大自定义比较器 a+b > b+a要验证这个比较器满足传递性
带截止时间的任务调度按截止时间排，用堆「反悔」反悔贪心
最少加油次数「先开，油不够了才回头选之前最大的油站」反悔贪心
「反悔贪心」值得单独学：先按某种顺序贪心地全部接受，一旦发现违规就从已接受的里面退掉最差的那个（用堆维护）。 
// 带截止时间的任务调度：最多能完成多少个任务
std::sort(tasks.begin(), tasks.end(), /* 按 deadline 升序 */);
std::priority_queue<int> pq;      // 大顶堆，存已接受任务的耗时
long long t = 0;
for (auto& [dur, ddl] : tasks) {
    t += dur; pq.push(dur);          // 先无条件接受
    if (t > ddl) {                    // 违规了 → 退掉耗时最长的那个
        t -= pq.top(); pq.pop();
    }
}
return pq.size();
为什么这样是对的：退掉耗时最长的那个，既解决了违规，又最大程度地为后面腾出时间，且任务数只减 1（不可能更少）。这是「交换论证」在动态过程中的应用——每次退货都是一次局部交换。

贪心失效时

三个反例 + 一个可操作的判据

4.1 三个反例

❌ 01 背包不能贪心
// 按「价值/重量」比贪心？
容量 W = 10
物品：(w=6, v=7)  比值 1.17
      (w=5, v=5)  比值 1.00
      (w=5, v=5)  比值 1.00

贪心：先拿比值最高的 → 7，剩余容量 4 → 装不下
      结果 = 7
最优：拿后两个 → 10

// 但分数背包（可以切开）贪心是对的！
❌ 零钱兑换不能贪心
// 硬币 [1, 3, 4]，凑 6
贪心（先拿最大）：4 + 1 + 1 = 3 枚
最优：3 + 3 = 2 枚

// 而人民币面额 [1,2,5,10,...] 贪心是对的
// → 「贪心对不对」取决于面额集合，
//   而验证一个面额集合能否贪心本身很难
❌ 只能合并相邻时贪心失效
// 石子合并（只能合并相邻两堆）
堆：[4, 1, 1, 4]

贪心（每次合并最小的相邻两堆）：
  合并中间 1+1=2 → [4,2,4]，代价 2
  合并 4+2=6     → [6,4]，代价 6
  合并 6+4=10    → 代价 10
  总代价 = 18

最优：先合并两端 → 总代价 16

// 「相邻」这个约束破坏了 Huffman 的前提
// → 必须用区间 DP
✅ 对比：可任意合并时贪心正确
// 合并果子（可以任意选两堆）
堆：[4, 1, 1, 4]

Huffman：1+1=2 → 2+4=6 → 6+4=10
总代价 = 18，且这就是最优

// 因为没有位置约束，
// 「两个最小的应该在最深处」的
// 交换论证成立

4.2 失效的判据

贪心可能失效的四个信号（看到任何一个就要警惕）：
  1. 有「容量 / 预算」这类全局资源约束，且物品不可分割 → 01 背包类，用 DP。（可分割则贪心成立——分数背包。）
  2. 选择之间有位置或顺序约束（「只能合并相邻」「必须连续」）→ 区间 DP。
  3. 「恰好」类约束（恰好选 k 个、和恰好为 T）→ 贪心很难满足「恰好」，通常要 DP。
  4. 前面的选择会「堵死」后面（不满足拟阵的交换性）→ DP 或搜索。
而最实用的验证手段是对拍：写一个暴力枚举版本（小数据），随机生成几千组测试比对贪心解和暴力解。贪心的错误往往在「精心构造的小反例」上才暴露，而随机对拍恰好擅长找这类反例。
「试了几个例子都对」是最不可靠的证据。贪心的反例往往需要特定结构（如零钱兑换需要「大面额不是小面额的倍数」），随机测试都可能撞不上——所以既要对拍，也要写下交换论证。

反过来，如果你能想到一个反例，那就立刻放弃贪心，不要试图「修补策略」——修补出来的贪心通常还有别的反例，而且越来越难验证。此时退回 DP 是更快的路。
05

回溯框架

三要素 + 三种模板 + 两种去重

5.1 三要素

// 回溯的通用骨架
void backtrack(State& st) {
    if (is_complete(st)) { record(st); return; }   // ① 终止条件
    for (auto& choice : candidates(st)) {           // ② 候选集合
        if (!valid(st, choice)) continue;             //    剪枝
        make(st, choice);                             // ③ 做选择
        backtrack(st);
        undo(st, choice);                             //    撤销选择 ← 关键
    }
}
三要素：
  1. 路径（已做的选择）——通常是一个 vector，边走边 push/pop。
  2. 候选集合（当前还能做什么选择）——这是三种模板的唯一区别所在（§5.2）。
  3. 终止条件——路径达到目标长度、或候选集合为空、或达到目标状态。
「做选择 → 递归 → 撤销选择」这个三段式必须严格配对。最可靠的写法是只有一个出口（不许 early return），或者用 RAII： 
struct Guard {
    std::vector<int>& p;
    Guard(std::vector<int>& p_, int v) : p(p_) { p.push_back(v); }
    ~Guard() { p.pop_back(); }      // 任何出口（含异常）都会撤销
};
细节见 递归与分治 §3.2。

5.2 子集 / 组合 / 排列的模板差异

候选集合怎么定 子集 / 组合 for (i = start; i < n; ++i) 传 start = i + 1，不回头 ⟹ 每个元素只考虑一次，不产生顺序 排列 for (i = 0; i < n; ++i) 用 used[] 标记，每次从头扫 ⟹ 同一元素在不同位置算不同方案 可重复选（组合总和） for (i = start; i < n; ++i) 递归时传 start = i（不是 i+1） ⟹ 同一元素可以再选 复杂度与状态数 子集：2ⁿ 个　　　组合 C(n,k)：C(n,k) 个　　　排列：n! 个 ⟹ n ≤ 20 时子集可行；n ≤ 10~11 时排列可行（10! ≈ 3.6×10⁶） 看到 n ≤ 20 想子集 / 状压；n ≤ 11 想排列；n 更大就不能穷举，要 DP 或贪心
子集 / 组合：传 start，不回头
void dfs(int start) {
    res.push_back(path);           // 子集：每个节点都记录
    for (int i = start; i < n; ++i) {
        path.push_back(a[i]);
        dfs(i + 1);                 // ← i+1：不回头
        path.pop_back();
    }
}
// 组合 C(n,k)：只在 path.size()==k 时记录
// 可重复选：dfs(i) 而不是 dfs(i+1)
排列：用 used 标记，每次从头扫
void dfs() {
    if ((int)path.size() == n) {
        res.push_back(path); return;
    }
    for (int i = 0; i < n; ++i) {   // ← 每次从 0 开始
        if (used[i]) continue;
        used[i] = true;
        path.push_back(a[i]);
        dfs();
        path.pop_back();
        used[i] = false;
    }
}

5.3 去重的两种场景

输入含重复元素时，需要去重才能保证「不同的方案」只被输出一次。前提是先排序（让相同元素相邻），然后分两种情况：

场景去重条件含义
同一层（组合 / 子集）if (i > start && a[i] == a[i-1]) continue;同一层不能选相同的值两次
同一层（排列）if (i > 0 && a[i] == a[i-1] && !used[i-1]) continue;相同值必须按顺序使用
排列去重的条件是!used[i-1] 而不是 used[i-1]——这个感叹号是本题最难理解也最容易写错的地方：
  • !used[i-1] 意味着「前一个相同的值还没被用」→ 说明我们正在同一层尝试跳过它去选 a[i]，这会产生重复方案 → 跳过。
  • 如果 used[i-1] 为真，说明前一个相同值已经在上层被用了，现在选 a[i] 是合法的「第二个相同值」→ 不能跳。
效果是：相同的值只能按下标从小到大依次使用，从而每组相同值只产生一种相对顺序。
写成 used[i-1] 也能去重，但会把「正确的那一种」也跳掉，导致漏解。
另一种更笨但更稳的去重：用 set 收集结果，或者在同一层用一个局部 unordered_set 记录「本层已选过哪些值」。
代价是常数变大，但不需要预排序，也不容易写错——面试时如果记不清条件，用这个更安全，然后说明「排序 + 条件判断的版本更快」。

剪枝

不改变最坏复杂度，但决定实际能不能跑完

6.1 五种剪枝手段

剪枝做法典型场景
可行性剪枝当前状态已违反约束 → 直接返回N 皇后的冲突检查、数独的行列宫检查
最优性剪枝（限界）当前代价已 ≥ 已知最优 → 返回TSP、装箱问题
上界估计剪枝「剩下全选也达不到目标」→ 返回组合总和、选 k 个的问题
排序 + 提前退出先排序，遇到不可能的就 break 而非 continue组合总和（升序后 sum + a[i] > target 直接 break）
对称性剪枝等价的分支只搜一个N 皇后第一行只搜一半、图着色固定第一个点的颜色
记忆化相同状态不重复搜状态可以编码时（此时其实已经变成 DP）
break 和 continue 的区别在剪枝里很关键：
  • 如果候选已排序且「当前不行意味着后面都不行」→ 用 break，一次剪掉整个尾部。
  • 如果只是当前这个不行、后面可能行 → 用 continue。
例：组合总和里数组升序后，if (sum + a[i] > target) break; ——因为后面的 a[j] ≥ a[i]，也一定超。写成 continue 虽然答案对，但白跑了整个尾部。这一个字的差别在实际数据上常常是几倍到几十倍。
剪枝像找工作时先看硬门槛。不剪枝是「每个岗位都投简历、面完才知道不合适」；剪枝是「看到『要求 10 年经验』就直接跳过」。

而「排序 + break」相当于把岗位按门槛排序——一旦发现某个门槛你达不到，后面所有门槛更高的都不用看了，一次跳过一整批。这就是为什么「先排序」常常是剪枝的前置步骤。

6.2 N 皇后与位运算

朴素版：用三个数组标记
void dfs(int row) {
    if (row == n) { ++cnt; return; }
    for (int c = 0; c < n; ++c) {
        if (col[c] || diag1[row + c] || diag2[row - c + n])
            continue;
        col[c] = diag1[row+c] = diag2[row-c+n] = 1;
        dfs(row + 1);
        col[c] = diag1[row+c] = diag2[row-c+n] = 0;
    }
}
// diag1: 主对角线（row+c 相同）
// diag2: 副对角线（row−c 相同，+n 防负数）
位运算版：快 5–10 倍
// col/d1/d2 用位掩码表示「被占用的列」
void dfs(int row, int col, int d1, int d2) {
    if (row == n) { ++cnt; return; }
    // 可放位置 = 全部 & ~(被三者占用的)
    int avail = ((1 << n) - 1) & ~(col | d1 | d2);
    while (avail) {
        int p = avail & -avail;      // 取最低位的 1（lowbit）
        avail ^= p;                   // 移除该位
        dfs(row + 1, col | p,
            (d1 | p) << 1,           // 对角线随行下移而左移
            (d2 | p) >> 1);
    }
}
// 调用：dfs(0, 0, 0, 0)
位运算版为什么快：
  • avail 一次算出所有可放位置，不需要逐列检查（省掉内层的 n 次判断）。
  • avail & -avail 直接取出最低位的 1——只遍历真正可行的位置，跳过所有被占用的列。
  • 对角线的移位是关键洞察：往下走一行时，主对角线的约束向左移一位（<< 1），副对角线向右移一位（>> 1）。这样就不需要用 row+c / row−c 去索引数组，全部在寄存器里完成。
  • 没有数组访问、没有状态恢复（参数传值天然回溯）→ cache 友好且零撤销开销。
这是「用位运算把状态压进寄存器」的经典案例，同族技巧见 状压 DP。
N 皇后还能加对称性剪枝：第一行只放前 n/2 列，结果乘 2（n 为奇数时中间列单独算）。这能再快近一倍。
但注意：如果题目要求输出所有具体方案而不只是计数，对称性剪枝需要额外镜像还原，代码复杂度上升——要先确认题目要的是「计数」还是「方案」。

分支限界与工程近似

当穷举跑不完，而问题本身就是难的

7.1 分支限界

分支限界（branch and bound）= 回溯 + 上下界估计 + 优先搜索顺序。
  • 下界（对最小化问题）：估算「从当前状态出发，最少还要花多少代价」。如果 已花代价 + 下界 ≥ 已知最优，整个分支剪掉。
  • 搜索顺序：用优先队列先搜「最有希望」的分支（best-first），比 DFS 更早找到好解，从而让限界剪得更狠。
下界必须是「乐观估计」（不能高于真实值），否则会剪掉最优解——这和 A* 的可采纳性是同一个要求。
问题常用下界
TSP剩余点的 MST 权重、或每点最小出边之和
装箱 / 调度⌈总体积 / 箱容量⌉
整数规划LP 松弛（去掉整数约束后的解）
图着色最大团的大小
整数规划的 LP 松弛值得单独说：把「变量必须是整数」这个约束去掉，问题就变成线性规划（多项式可解），它的解一定不差于整数解 → 天然是一个下界。
然后在某个非整数变量上「分支」（x ≤ ⌊v⌋ 或 x ≥ ⌈v⌉），递归求解。这就是所有商业 ILP 求解器（Gurobi、CPLEX、CBC）的核心框架。
工程上遇到组合优化问题，先试求解器往往比自己写搜索快得多，也更容易维护。

7.2 遇到 NP-hard 的出路

策略保证实例
先质疑需求—「真的需要最优解吗？95% 够不够？」这一步收益最大
量真实规模—NP-hard 说的是最坏；n 常年 ≤ 30 时求解器几毫秒就出最优解
近似算法有界近似比顶点覆盖 2-近似、集合覆盖 ln n-近似
限定参数（FPT）k 小时精确O(f(k)·poly(n))，树宽有界的图
精确 + 剪枝最优解，时间不保证分支限界、ILP 求解器、SAT 求解器
启发式无保证模拟退火、遗传算法、贪心 + 局部搜索
松弛改问题不再是原问题整数规划 → LP 松弛后取整
选型判据：问「解差一点的代价是多少」
  • 结果要对外承诺（计费、合规、资源配额）→ 用近似算法，因为你需要一个能写进文档的界。
  • 结果只影响内部效率（缓存预热顺序、任务打包）→ 启发式够用，把精力花在监控实际解质量上。
  • 离线批处理、有几小时窗口→ 直接上 ILP / SAT 求解器，通常能拿到最优或近最优，而且比自己写启发式省事得多。
别掉进的坑：自己从零写启发式（尤其遗传算法这类）往往打不过成熟求解器，还留下无人能维护的代码。先试通用求解器，打不过再自己写。

面试题集（12 道）

按难度分三段，先自测再对照

10.1 基础（必答）

点击每道题展开参考答案（先自测，再对照）。

  1. 基础贪心、DP、回溯三者怎么选？它们的关系是什么？

    三者是一条连续谱，按「需要记多少状态」区分：

    贪心 = 不需要记状态的 DP
    每步的最优选择不依赖任何历史信息，所以状态维度为 0。需要「贪心选择性质」——局部最优能导出全局最优。O(n log n)。
    DP
    贪心不成立时接手：需要记一些状态，但子问题重叠，所以能把指数折叠成多项式。
    回溯
    DP 也不成立时接手：子问题不重叠，或状态空间太大无法枚举 → 只能真的搜，指数复杂度，靠剪枝活下来。
    贪心DP回溯
    难点证明它对设计状态剪枝与去重
    写错的表现安静地给次优解安静地给错答案超时 / 重复 / 遗漏
    思考顺序
    能贪心吗？（最快）→ 能 DP 吗？→ 只能搜吗？
    而 n 的范围通常直接给出答案：n ≤ 11 → 排列穷举；n ≤ 20 → 子集/状压；n ≤ 5000 → O(n²) DP；n ≤ 10⁵ → 贪心或 O(n log n)。
  2. 基础区间调度（最多不重叠区间数）为什么按结束时间排序？

    因为结束最早的区间给后面留下的时间最多。

    std::sort(iv.begin(), iv.end(), [](auto& a, auto& b) {
    return a.second < b.second;    // 按结束时间升序
});
int cnt = 0, last_end = INT_MIN;
for (auto& [s, e] : iv)
    if (s >= last_end) { ++cnt; last_end = e; }
    交换论证
    设最优解 OPT 的第一个区间不是「结束最早的那个 g」。因为 g 结束更早，它给后面留下的可用时间不少于 OPT 选的那个 ⟹ 把 OPT 的第一个换成 g 后，后面所有区间仍然合法 ⟹ 新解区间数不变（仍最优）且与贪心多一致一个。
    反复应用 ⟹ 贪心解本身就是最优解。∎
    另两种排序的反例
    按开始时间：[0,10], [1,2], [3,4] —— 先选 [0,10] 只能选 1 个，实际能选 2 个。
    按时长：[0,5], [4,6], [5,10] —— 先选最短的 [4,6] 只能选 1 个，实际能选 2 个。
    但「按开始排」也有它的题
    「选最多个」（互斥选择）→ 按结束排，因为要给未来留余地。
    「合并 / 覆盖」（连续推进）→ 按开始排，因为要按顺序处理。
    读题时先分清是「选择型」还是「推进型」。
  3. 基础写出回溯的通用框架，说明三要素。 
    void backtrack(State& st) {
    if (is_complete(st)) { record(st); return; }   // ① 终止条件
    for (auto& choice : candidates(st)) {           // ② 候选集合
        if (!valid(st, choice)) continue;             //    剪枝
        make(st, choice);                             // ③ 做选择
        backtrack(st);
        undo(st, choice);                             //    撤销（关键）
    }
}
    三要素
    ① 路径（已做的选择）——通常一个 vector，边走边 push/pop。
    ② 候选集合（当前还能选什么）——这是三种模板的唯一区别所在。
    ③ 终止条件——路径达到目标长度 / 候选为空 / 达到目标状态。
    最常见的两个坑
    ① 忘了撤销，或者 early return 跳过了撤销。
    可靠写法：只留一个出口（不许 early return），或用 RAII：
    struct Guard {
    std::vector<int>& p;
    Guard(std::vector<int>& p_, int v) : p(p_) { p.push_back(v); }
    ~Guard() { p.pop_back(); }   // 任何出口（含异常）都撤销
};
    ② 记录结果时存了引用
    res.push_back(path) 必须是拷贝。存指针或引用会导致所有结果都变成最后一个状态——这个 bug 的症状很迷惑（所有答案都一样），在 C++ 里特别常见。
  4. 基础子集、组合、排列三种回溯模板的区别在哪？

    骨架完全相同，唯一区别是「候选集合怎么定」。

    子集 / 组合：传 start，不回头
    for (int i = start; i < n; ++i) {
    path.push_back(a[i]);
    dfs(i + 1);      // ← i+1
    path.pop_back();
}
    不产生顺序，每元素只考虑一次
    排列：用 used，每次从头扫
    for (int i = 0; i < n; ++i) {  // ← 从 0
    if (used[i]) continue;
    used[i] = true; path.push_back(a[i]);
    dfs();
    path.pop_back(); used[i] = false;
}
    同元素在不同位置算不同方案
    三个变体
    子集：每个递归节点都 record（2ⁿ 个）。
    组合 C(n,k)：只在 path.size() == k 时 record。
    可重复选（组合总和）：递归传 dfs(i) 而不是 dfs(i+1)。
    状态数决定 n 的上限
    子集 2ⁿ → n ≤ 20 可行；排列 n! → n ≤ 10~11 可行（10! ≈ 3.6×10⁶）。
    看到 n ≤ 20 想子集/状压，n ≤ 11 想排列，n 更大就不能穷举——要 DP 或贪心。

10.2 中级（区分熟练度）

  1. 中级什么是交换论证？用它证明一个贪心。

    交换论证是证明贪心最常用的方法，四步模板：

    模板
    ① 假设存在最优解 OPT，它与贪心解 G 不同。
    ② 找到第一个不同的位置——贪心选 g，OPT 选 o。
    ③ 证明：把 OPT 里的 o 换成 g（并适当调整后面），得到的新解不比 OPT 差。
    ④ 于是存在「与贪心一致得更多」的最优解。反复应用 ⟹ 贪心解本身最优。∎
    关键在第 ③ 步
    要说清「换完之后为什么仍然合法，且不变差」。这一步说不清，贪心就是错的。
    区间调度的第 ③ 步就是一句话：「贪心选的区间结束更早 ⟹ 它给后面留下的空间不少于 OPT 选的那个 ⟹ 后面所有区间仍然合法」。
    Huffman 的交换论证
    设频率最小的两个字符是 x、y。断言：存在一棵最优树，x 和 y 是最深层的一对兄弟。
    论证：取任意最优树 T，设它最深层的一对兄弟是 a、b。因 x、y 频率最小，把 x↔a、y↔b 交换后加权路径长度不会增加（频率小的换到更深、频率大的换到更浅）。
    所以可以先把 x、y 合并成一个超级节点，规模减一，递归应用即得 Huffman。∎
    另一种证法：前缀最优（归纳）
    证明「贪心的每一步前缀都是该规模下的最优解」。适合「逐个处理元素」的贪心（Kadane、加油站、跳跃游戏）；而交换论证更适合「先排序再按序选」的形态。
    面试时不要说这两句
    「感觉上应该对」「试了几个例子都对」。至少要给出交换论证的第 ③ 步，或者一个反例的排除。能说出一句形式化的论证，比多做十道贪心题更能体现水平。
  2. 中级为什么 01 背包不能贪心，但分数背包可以？
    01 背包的反例
    容量 W=10，物品 (w=6,v=7) 比值 1.17、(w=5,v=5) 比值 1.00、(w=5,v=5) 比值 1.00。
    按比值贪心：先拿 7，剩余容量 4 装不下 → 结果 7。
    最优：拿后两个 → 10。
    分数背包可以贪心
    物品能切开时，按「价值/重量」比降序装，装满为止。最后一个可以只装一部分——所以容量总能恰好用完，不会出现「剩下 4 但装不下 5」的浪费。
    交换论证：任何最优解里，如果比值高的没装满而比值低的装了，把后者换成前者一定不差。∎
    用拟阵的视角看差别
    拟阵的交换性要求：若 A、B 都是独立集且 |A| < |B|，则 B 中存在元素可以加入 A 而保持独立。
    01 背包不满足：两个都不超重的物品集合，元素少的那个未必能从元素多的那个里加进任何一件（可能都超重）。
    所以「前面选错会堵死后面」——这正是贪心失效的本质。
    可操作的判据
    问自己：「如果我前面贪心地选了一些，会不会导致后面『无路可走』而其他选法能走通？」
    不会（总能继续扩充）→ 贪心有戏。会 → 贪心很可能错，考虑 DP。
    这个问法比背拟阵定义实用得多。
  3. 中级排列去重的条件为什么是 !used[i-1] 而不是 used[i-1]？

    前提：先排序（让相同元素相邻）。然后：

    if (i > 0 && a[i] == a[i-1] && !used[i-1]) continue;
    解释这个感叹号
    !used[i-1] 为真 = 「前一个相同的值还没被用」
    ⟹ 说明我们正在同一层尝试「跳过前一个相同值，直接选 a[i]」
    ⟹ 这和「选前一个相同值」产生的方案完全相同（值一样嘛）→ 重复，跳过。

    反之 used[i-1] 为真 = 前一个相同值已在上层被用了 ⟹ 现在选 a[i] 是合法的「第二个相同值」→ 不能跳。
    效果
    相同的值只能按下标从小到大依次使用，从而每组相同值只产生一种相对顺序。
    写成 used[i-1] 会怎样
    也能「去重」，但会把正确的那一种也跳掉 → 漏解。这是本题最容易犯的错。
    对比：组合/子集的去重条件
    if (i > start && a[i] == a[i-1]) continue;
    用 i > start 而不是 i > 0——因为组合里 start 标记了本层的起点，只需保证「同一层不选相同值两次」，不涉及 used。
    记不清时的稳妥做法
    在同一层用一个局部 unordered_set 记录「本层已选过哪些值」。常数变大，但不需要预排序也不容易写错。
    面试时可以先写这个版本，再说明「排序 + 条件判断更快」。
  4. 中级回溯剪枝有哪些手段？break 和 continue 的区别为什么重要？
    剪枝做法
    可行性已违反约束 → 返回（N 皇后冲突检查、数独行列宫）
    最优性（限界）当前代价 ≥ 已知最优 → 返回
    上界估计「剩下全选也达不到目标」→ 返回
    排序 + 提前退出先排序，遇到不可能的 break
    对称性等价分支只搜一个（N 皇后第一行只搜一半）
    break vs continue
    候选已排序且「当前不行意味着后面都不行」→ 用 break，一次剪掉整个尾部。
    只是当前这个不行、后面可能行 → 用 continue。
    例：组合总和里数组升序后，if (sum + a[i] > target) break;——后面的 a[j] ≥ a[i] 也一定超。
    写成 continue 答案对但白跑整个尾部，实际数据上常常是几倍到几十倍的差距。
    这也解释了「先排序」为什么是剪枝的前置步骤
    排序把「零散的不可行」变成「一个连续的不可行尾部」，从而能一次剪掉一整批。
    类比：找工作时把岗位按门槛排序，一旦发现达不到某个门槛，后面更高的都不用看了。
    剪枝不改变最坏复杂度
    它只影响实际数据上的表现。所以：① 别指望剪枝把指数变成多项式；② 但对真实数据往往是几个数量级的差距，值得花时间做；③ 如果剪枝后还是跑不完，说明问题规模超出了搜索的能力范围，要换近似或求解器。

10.3 高级（体现深度）

  1. 高级怎么判断一个贪心策略是错的？如果发现反例该怎么办？

    四个「贪心可能失效」的信号（看到任何一个就警惕）：

    ① 有全局资源约束且物品不可分割
    「容量 / 预算 / 总和上限」+ 不能切开 → 01 背包类，用 DP。（可切开则贪心成立——分数背包。）
    ② 选择之间有位置或顺序约束
    「只能合并相邻」「必须连续」→ 区间 DP。
    反例：石子合并 [4,1,1,4]，贪心（每次合并最小的相邻两堆）得 18，最优（先合并两端）得 16。「相邻」这个约束破坏了 Huffman 的前提。
    ③ 「恰好」类约束
    恰好选 k 个、和恰好为 T → 贪心很难满足「恰好」，通常要 DP。
    ④ 前面的选择会「堵死」后面
    不满足拟阵的交换性 → DP 或搜索。
    最实用的验证手段：暴力对拍
    写一个 O(指数) 的暴力枚举（小数据），随机生成几千组测试比对贪心解和暴力解。
    贪心的错误往往只在「精心构造的小反例」上暴露，而随机对拍恰好擅长找这类反例。「试了几个例子都对」是最不可靠的证据——零钱兑换需要「大面额不是小面额倍数」这种特定结构，随机测试都可能撞不上。所以既要对拍也要写下交换论证。
    发现反例后：立刻放弃贪心，不要修补
    修补出来的贪心通常还有别的反例，而且越来越难验证。
    此时退回 DP 是更快的路——DP 的正确性只依赖「状态定义 + 转移完备」，比贪心的「全局最优性」容易验证得多。
    工程上也是这个道理：一个需要五条特殊规则才对的贪心，维护成本远高于一个直白的 DP。
  2. 高级N 皇后的位运算优化为什么能快 5–10 倍？ 
    void dfs(int row, int col, int d1, int d2) {
    if (row == n) { ++cnt; return; }
    int avail = ((1 << n) - 1) & ~(col | d1 | d2);
    while (avail) {
        int p = avail & -avail;      // lowbit：取最低位的 1
        avail ^= p;
        dfs(row + 1, col | p, (d1 | p) << 1, (d2 | p) >> 1);
    }
}
    四个原因
    ① avail 一次算出所有可放位置，不需要逐列检查（省掉内层 n 次判断）。
    ② avail & -avail 直接取最低位的 1——只遍历真正可行的位置，跳过所有被占用的列。
    ③ 对角线的移位是关键洞察：往下走一行时，主对角线约束向左移一位（<< 1）、副对角线向右移一位（>> 1）。这样就不需要用 row+c/row−c 去索引数组，全部在寄存器里完成。
    ④ 参数传值天然回溯——没有数组访问、没有显式的状态恢复。
    对角线移位为什么对
    主对角线上的格子满足 row + col 相同。从第 row 行走到第 row+1 行时，同一条主对角线对应的列号减少 1 → 在位掩码里就是左移一位。副对角线（row − col 相同）则列号增加 1 → 右移一位。
    把「二维的对角线约束」编码成「一维掩码的移位」，这是本优化最精妙的地方。
    还能再快近一倍：对称性剪枝
    第一行只放前 n/2 列，结果乘 2（n 为奇数时中间列单独算）。
    但注意：如果要输出所有具体方案而不只是计数，对称性剪枝需要额外镜像还原，代码复杂度上升。先确认题目要「计数」还是「方案」。
    同族技巧
    「用位运算把状态压进寄存器」还出现在：状压 DP、数独求解（每行/列/宫一个掩码）、图的邻接矩阵用 bitset（传递闭包 O(V³/64)）、Swiss Table 的 SIMD 控制字节。
  3. 高级什么是分支限界？它和普通回溯、A* 有什么关系？

    分支限界 = 回溯 + 上下界估计 + 优先搜索顺序。

    下界（对最小化问题）
    估算「从当前状态出发，最少还要花多少代价」。若 已花代价 + 下界 ≥ 已知最优，整个分支剪掉。
    优先搜索顺序
    用优先队列先搜「最有希望」的分支（best-first），比 DFS 更早找到好解，从而让限界剪得更狠。这是一个正反馈：好解越早出现，剪枝越有效。
    和 A* 的关系
    下界必须是「乐观估计」（不能高于真实值），否则会剪掉最优解——这和 A* 要求启发函数「可采纳」（不高估）是完全同一个条件。
    实际上 A* 可以看成分支限界在「最短路」这个特定问题上的实例：f = g + h 里的 h 就是下界。
    问题常用下界
    TSP剩余点的 MST 权重、或每点最小出边之和
    装箱 / 调度⌈总体积 / 箱容量⌉
    整数规划LP 松弛（去掉整数约束后的解）
    图着色最大团的大小
    LP 松弛值得单独说
    把「变量必须是整数」去掉，问题变成线性规划（多项式可解），它的解一定不差于整数解 → 天然是一个下界。
    然后在某个非整数变量上分支（x ≤ ⌊v⌋ 或 x ≥ ⌈v⌉），递归求解。
    这就是所有商业 ILP 求解器（Gurobi、CPLEX、CBC）的核心框架。
    工程上遇到组合优化问题，先试求解器往往比自己写搜索快得多，也更容易维护。
  4. 高级生产上遇到一个需要「最优排班/装箱/路径规划」的需求，怎么落地？

    这类需求几乎都是 NP-hard。但动手写算法之前，有两步收益更大。

    ① 先质疑需求（收益最大的一步）
    很多「最优」是把业务约束抽象过头的结果。「给 1000 个任务排最优班」是 NP-hard，但业务上往往只要「95% 的任务在 SLA 内 + 最坏不超过 2 倍」——那就变成一个贪心能解的问题。
    动手前确认真的需要最优解。
    ② 量真实输入规模
    NP-hard 说的是最坏情形随 n 增长的行为。如果生产数据里 n 常年 ≤ 30，ILP 求解器几毫秒就返回最优解——这个「NP-hard」在工程上根本不是问题。
    先看数据，再谈复杂度类。

    确认必须放弃精确解后，按「保证强度」排序的出路：

    策略保证适合
    近似算法有界近似比结果要对外承诺（计费、合规、配额）
    ILP / SAT 求解器最优解，时间不保证离线批处理，有几小时窗口
    限定参数（FPT）k 小时精确某个参数天然很小
    启发式无保证结果只影响内部效率
    别掉进的坑
    自己从零写启发式（尤其遗传算法这类）往往打不过成熟求解器，还留下无人能维护的代码。
    先试通用求解器（Gurobi / CBC / OR-Tools），打不过再自己写。而且求解器通常还免费给你「当前解距离最优的上界」，这个信息对业务沟通极有价值。
    还要考虑算法之外的三件事
    ① 可解释性：排班结果要给人看，「为什么小王被排了周末」必须能回答。一个复杂启发式的输出常常无法解释，这在实际推行时是致命的。
    ② 稳定性：输入微小变化不应导致排班大幅重排（用户会抗议）。这通常要在目标函数里加「与上一版的差异」惩罚项。
    ③ 可干预：业务方需要能手工锁定某些安排，然后让算法优化其余部分。这三点往往比「解好 2%」更决定项目成败。
