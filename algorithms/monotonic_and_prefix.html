单调栈与前缀和

这四个工具解决的是同一类问题：把「每次查询都重新扫一遍」换成「维护一个可增量更新的状态」。单调栈和单调队列丢掉永远不会成为答案的候选；前缀和与差分把区间操作变成两个端点的加减。它们的共同代价也一样——都需要先证明「被丢掉的东西真的没用」或「这个运算真的可逆」。

核心难度 ★★★★☆ 面试出现率 高 阅读时长 ~35 min 前置 复杂度 · 双指针
单调栈不变式 柱状图最大矩形 单调队列 前缀和 + 哈希表 二维容斥 差分与扫描线
01

本质：只留有用的候选

两条不同的省法，同一个动机

这一篇里的四个工具分成两族，动机相同但手法相反：

族工具手法关键前提
丢候选单调栈（§2）新元素让某些旧元素永远不可能再成为答案 → 直接弹出「被遮挡」关系可判定
单调队列（§3）同上，外加「过期」也要从另一端弹同上 + 窗口按序滑动
预处理前缀和（§4）区间查询 → 两个端点相减运算可逆（有逆元）
差分（§5）区间修改 → 两个端点加减同上，且修改与查询分阶段
合法性就两句：弹出 x 时必须证明——对所有还没处理的位置，x 都不可能是答案。通常理由是新来的 y 在各方面都不比 x 差、且更靠后，于是 x 被 y 完全支配。前缀和则要求运算有逆元才能 S[r]−S[l−1]：加 / 异或 / 非零乘法可以，max / min / gcd 不行——没有逆元就去稀疏表或线段树。这条判据比记模板重要。
单调栈像排队看演出的视线：你站在队尾往前看，只能看到「比前面所有人都高」的人——一旦被更高的挡住，对后面所有人永远不可见，可以从名单里永久删除。栈里剩下的正是「从当前位置往回还能看见的人」，天然递减；每人最多进队一次、出队一次，所以总代价 O(n)。前缀和像累计里程表：第 30 到第 80 公里跑了多远，看两个读数相减即可。前提是只增且可减——记「最高时速」相减毫无意义。

1.1 与其他章节的关系

  • 双指针与滑动窗口 —— 窗口极值必须靠单调队列；窗口对负数失效时改用前缀和
  • 复杂度与分析 —— 「每个元素进出各一次」的 O(n) 论证用的是那里的势能法
  • 堆与 Top-K —— §3.2 讲单调队列与优先队列的分工
  • 并查集与区间结构 —— 一维前缀 / 差分的代码与「改查交错上树」在那边；本篇只留图 + 二维 / 哈希
  • 排序全景 —— 扫描线的第一步永远是按坐标排序
  • SQL 从基础到高级 —— §7.3 的窗口函数就是前缀和的声明式版本
02

单调栈

一个模板，五道经典题

单调栈维护「还没找到答案的候选」。新元素一来，把被它完全支配的旧元素全部结算并永久移出。下面先看栈里为什么必须单调，再看弹出的那一刻为什么就是写答案的时刻。

2.1 不变式与模板

// 每个位置「右边第一个更大」的下标；没有则为 n。存下标。
std::vector<int> next_greater(const std::vector<int>& a) {
    int n = (int)a.size();
    std::vector<int> res(n, n), st;
    for (int i = 0; i < n; ++i) {
        while (!st.empty() && a[st.back()] < a[i]) {
            res[st.back()] = i;      // 弹出时才写答案
            st.pop_back();
        }
        st.push_back(i);
    }
    return res;
}
三条约定：① 存下标不存值（求宽度必须有下标）。② 求「更大」递减栈，「更小」递增栈。③ 答案写在 pop 时，不是 push 时。O(n)：每下标进出各一次，内层 while 总次数 = 总 pop ≤ n，与双指针同一套势能。

2.2 下一个更大元素

四种变体只需改两处——比较符号和遍历方向：
要求遍历方向while 条件栈内单调性
右边第一个更大左 → 右a[st.back()] < a[i]递减
右边第一个更小左 → 右a[st.back()] > a[i]递增
左边第一个更大右 → 左a[st.back()] < a[i]递减
左边第一个更小右 → 左a[st.back()] > a[i]递增
循环数组：下标 i % n 扫 2n 轮，第二轮只弹不压——第一轮已经把「绕一圈能看到的更大元素」写进答案，再压会破坏「每个下标只进一次」。

2.3 接雨水

三种解法代表三种角度。双指针版常被追问「凭什么 O(1) 空间」：矮的那一侧水位已经被对侧更高的墙钉死，不必知道对面的确切高度。单调栈版则按层结算横条。

解法时间 / 空间角度
预处理左右最大值O(n) / O(n)按列：min(左max, 右max) − h[i]
对撞双指针O(n) / O(1)同上，左右 max 边走边维护
单调栈O(n) / O(n)按层：弹出时结算一条横向水条
双指针凭什么 O(1)：lmax < rmax 时，左指针右侧至少有一根 ≥ rmax 的柱，所以左格水位就是 lmax——不必知道右侧最大的精确值。单调栈版弹出 bottom 后若栈空，左边没墙，必须 break，否则访问空栈是 UB。

2.4 柱状图最大矩形

这是单调栈的标志性题目：求柱状图中能勾出的最大矩形。难点不在栈，而在枚举「哪根柱是矩形的高」而不是枚举左右端点。对每根柱，宽度由两侧第一个更矮者决定，而这正是单调栈的标准输出。

// 首尾高度 0：栈永不空 + 全部弹出结算
int largest_rectangle(std::vector<int> h) {
    h.insert(h.begin(), 0);
    h.push_back(0);
    std::vector<int> st;
    int best = 0;
    for (int i = 0; i < (int)h.size(); ++i) {
        while (!st.empty() && h[st.back()] > h[i]) {
            int top = st.back(); st.pop_back();
            best = std::max(best, h[top] * (i - st.back() - 1));
        }
        st.push_back(i);
    }
    return best;
}
哨兵：左 0 保证栈永不空（st.back() 合法）；右 0 把剩余柱子全部弹出结算，省掉循环后再清算。链表哑头、区间 [−∞,+∞]、字符串终止符都是同一手法——循环后还要再处理一遍剩余状态时，先想能不能加哨兵。

2.5 推广到二维

「01 矩阵最大矩形」= 逐行压成柱状图，复用 §2.4，O(m·n)。以第 r 行为地面，往上连续 1 的个数就是柱高；遇 0 清零。这是处理二维问题的通用套路：不去直接想三维，而是对每一层问「如果这一层是地面，往下能挖多深」——二维前缀和、最大子矩阵和（枚举上下界 + 一维 Kadane）、二维差分都是同一降维。

03

单调队列

单调栈 + 一个「过期」出口

单调队列 = 单调栈 + 从另一端弹出「过期」元素。窗口求和能加减是因为加法可逆；求最大值不行——max 没有逆元，移出最大值后次大值丢失。它要求元素按下标顺序进入、按下标顺序过期，这个更强的假设才换来 O(n)。

3.1 滑动窗口最大值

下面用滑动窗口最大值把两个出口走一遍。队尾弹「被支配」、队头弹「过期」，队首恒为当前窗口最大。

// 定长 k 窗口最大值，O(n) 摊销。存下标，值递减。
std::vector<int> max_sliding_window(const std::vector<int>& a, int k) {
    std::deque<int> dq;
    std::vector<int> res;
    for (int i = 0; i < (int)a.size(); ++i) {
        while (!dq.empty() && a[dq.back()] <= a[i]) dq.pop_back();
        dq.push_back(i);
        if (dq.front() <= i - k) dq.pop_front();
        if (i >= k - 1) res.push_back(a[dq.front()]);
    }
    return res;
}
两个出口，两种理由：尾部 pop_back 是被支配（新元素更大且更靠后，旧的永不可能再是最大，永久删）；头部 pop_front 是过期（没被支配，只是滑出窗口）。必须用 deque。不变式：下标递增、值递减，队首 = 窗口最大。求最大值用 <= 弹相等项——旧的更先过期；要统计最大值出现次数才用 <。头部用 if 即可，每轮最多一个过期。

3.2 与优先队列的分工

单调队列堆multiset
窗口最大值O(n) 摊销O(n log n)O(n log k)
删任意元素否需延迟删除能
同时取最大最小要两个队列要两个堆能
前提按序进出无无

单调队列用「按序进出」换 O(n)：被支配者一定比支配者先过期，才能永久丢。堆没有这个前提，必须保留全部（延迟删除还要一张表判断堆顶是否过期）。窗口不是定长滑动时改延迟删除堆；同时要最大和最小用两个单调队列；要中位数见 堆与 Top-K。

3.3 DP 的决策单调优化

dp[i] = max{ dp[j] + w(i) : i − k ≤ j < i } 候选窗口随 i 整体右移 → 就是定长窗口最大值 → 单调队列 O(n)

识别：转移对 j 求 max/min，且候选区间随 i 单调移动。典型题是跳跃游戏 VI：每步最多跳 k 格，dp[i] = max(dp[i-k..i-1]) + a[i]，队首就是窗口内 dp 最大者。权重含 i·j 乘积项（如 (a[i]−a[j])²）则是斜率优化：谁更优取决于 i，不能永久丢，要维护下凸壳。一句话：候选之间的优劣是否与 i 无关——无关则单调队列，有关则凸包。展开见 动态规划。

04

前缀和

把区间查询变成两个端点相减

前缀和把「每次查询都扫一遍」换成预处理。一维模板和差分数组与 并查集与区间结构 §4 重复，本篇只留图，把那边没有的二维容斥和「前缀和 + 哈希表」写清楚。共同前提仍是：运算可逆，且修改与查询不交错。

4.1 一维与 STL 对应

一维前缀和 / 差分的代码与「改查交错上树」见 并查集与区间结构 §4。这里只留图：S[0]=0 长度 n+1，sum(l,r)=S[r+1]−S[l]，让 l=0 不用特判。输出必须 long long——partial_sum 的累加类型由输出容器决定，vector<int> 就会溢出。partial_sum 是 inclusive，公式要 exclusive，C++17 用 exclusive_scan(..., 0LL)。

4.2 前缀和 + 哈希表

含负数时窗口失效（和不单调）。枚举右端，查有多少左端使 S[r]−S[l]=k，即查 S−k 的次数。三处必错：cnt[0]=1（空前缀，否则漏掉从 0 起的子数组）；先查后加（否则 k=0 匹配自己）；存次数不是存「是否出现」。

变体key / value转化
和为 k 的个数前缀和 → 次数查 S−k
和为 k 的最长前缀和 → 最早下标key 不存在才插入
能被 k 整除S mod k → 次数((S%k)+k)%k
0/1 数量相等最长(1 数−0 的数) → 最早下标0 当 −1，化和为 0

真正要学的是转化：把 0 当 −1、数负号奇偶、对 k 取模，本质都是找到一个可累加且可相减的量。自问：能否定义一个前缀量，使「区间满足条件」等价于两个前缀相等或相差 k？

4.3 二维前缀和与容斥

// S 取 (m+1)×(n+1)，首行首列 0。查询原矩阵 [r1..r2][c1..c2]
for (int i = 1; i <= m; ++i)
    for (int j = 1; j <= n; ++j)
        S[i][j] = S[i-1][j] + S[i][j-1] - S[i-1][j-1] + a[i-1][j-1];
long long query2d(int r1, int c1, int r2, int c2) {
    return S[r2+1][c2+1] - S[r1][c2+1] - S[r2+1][c1] + S[r1][c1];
}

k 维容斥 2^k 项：二维好用，三维勉强（查询 8 项），再高换 k-d 树或分块。维度取 (m+1)×(n+1) 且首行首列全 0，与一维 S[0]=0 同理，否则 r1=0 或 c1=0 要写四个分支。代价是下标偏移 1——查原矩阵 [r1..r2][c1..c2] 要用 S 的 [r1..r2+1][c1..c2+1]，这是 off-by-one 高发点。

4.4 前缀异或与其他可逆运算

本质要求是可逆。异或最优雅：逆运算是自己，无溢出无符号；「区间内每个数出现偶数次 ⟺ 区间异或为 0」。max/min/gcd 没有逆元，换稀疏表 / 线段树，见 并查集与区间结构。有趣的对称：求和能前缀和不能稀疏表（重叠会加两次）；max 能稀疏表不能前缀和。

运算逆前缀查询
加 / 异或减 / 自身S[r+1]−S[l] / X[r+1]^X[l]
乘（无 0）/ 模乘除 / 逆元含 0 则乘法失效
max / min / gcd无稀疏表或线段树
05

差分数组

前缀和的对偶：把区间修改变成两点加减

差分和前缀和互为逆运算：a 的差分的前缀和 = a。前缀和擅长区间查、改要重建；差分擅长区间改、查要先还原。两者都要求修改与查询分阶段——交错就上树。

5.1 区间加、单点查

一维差分代码见 并查集与区间结构 §4.2。d[l]+=v; d[r+1]-=v，最后前缀还原。长度必须 n+1（r 可以是 n−1）。「O(1) 改」的前提是所有修改都在查询之前；改查交错则差分套 BIT 或线段树懒标记。

5.2 二维差分

子矩阵加 v：四角 + − − +，全部打完再做二维前缀和。符号与二维查询相同——互为逆运算。记住其中一个就能推出另一个。矩阵同样要多留一行一列，否则 r2+1/c2+1 越界，而且小数据下常常不崩。

5.3 扫描线

值域稀疏时不开全数组，只记变化点，排序后扫。会议室 = 最大重叠：开始 +1、结束 −1。同刻顺序由开闭语义决定：左闭右开 [s,e) 先减后加（pair 字典序 -1<+1 自动做到）；闭区间在端点相交则先加后减。写反只在「刚好相接」上错。

题型事件状态
会议室(开始,+1) (结束,−1)当前重叠 max
天际线(左,−h) (右,+h)高度 multiset
矩形面积并竖边入/出y 覆盖长度（线段树）
二维数点按一维排序另一维树状数组

扫描线 = 排序 + 一个可增量维护的状态。难度全在状态用什么结构：只要计数 → 一个整数（会议室）；要最大值且需删任意元素 → multiset 或延迟删除堆（天际线）；要区间覆盖长度 → 线段树（矩形面积并）；要「有多少已插入值小于 x」→ 树状数组（二维数点 / 逆序对）。识别信号：题目涉及区间 / 线段 / 事件，且答案与某时刻的聚合状态有关。

07

工程里的前缀和

监控、直方图、SQL 里的同一个东西

7.1 单调计数器与 rate

Prometheus 的 counter 就是前缀和：rate = (c(t2)−c(t1))/(t2−t1)。存累计值而不是每秒增量：

为什么存累计说明
抗采样丢失丢点只影响时间精度，下一个点仍能算出正确总量；存增量则那段永远丢了
抗采样间隔变化15s 改 30s 时累计语义不变，增量语义会变
客户端无状态只需原子自增，不用维护上次上报时刻
可任意重采样同一份数据能算 1 分钟或 1 小时的 rate

进程重启会归零，必须用 rate()/increase() 检测 reset，不要手写相减——发版时会出现巨大负尖刺。见 可观测性。

7.2 直方图与分位数

桶计数的前缀和是 CDF，上面二分估 p99，桶内线性插值。Prometheus histogram 直接存累积（le="…"），桶可跨实例相加后再算分位数——累积计数可加，这是它能汇总的原因。代价是精度受桶宽限制：p99 落在很宽的桶里时插值偏差大。要「任意分位数相对误差 ≤ 1%」用 t-digest / DDSketch，用近似换 O(log 值域) 空间。distinct count 同样不可加，要换成 HyperLogLog。

7.3 SQL 窗口函数

SUM() OVER (ORDER BY … ROWS UNBOUNDED PRECEDING) 是前缀和；ROWS 6 PRECEDING 是定长窗口；LAG 是差分。ROWS 按行、RANGE 按值——缺日期时「最近 7 天」必须用 RANGE INTERVAL '6' DAY，否则前 6 条记录可能跨过一周。详见 SQL 从基础到高级。

面试题集（12 道）

按难度分三段，先自测再对照

9.1 基础（必答）

点击每道题展开参考答案（先自测，再对照）。

  1. 基础什么是单调栈？写出「下一个更大元素」的模板，并说明为什么是 O(n)。

    单调栈是一个栈内元素保持单调的栈。它的作用是维护「还没找到答案的候选集」——新元素一来，就把被它完全支配的旧元素全部结算并永久移出。

    std::vector<int> next_greater(const std::vector<int>& a) {
    int n = a.size();
    std::vector<int> res(n, n), st;   // st 存下标
    for (int i = 0; i < n; ++i) {
        // 不变式：栈内值严格递减
        while (!st.empty() && a[st.back()] < a[i]) {
            res[st.back()] = i;      // 弹出时才确定答案
            st.pop_back();
        }
        st.push_back(i);
    }
    return res;
}
    O(n) 的论证
    每个下标最多 push 一次、pop 一次。内层 while 的总执行次数等于总 pop 次数 ≤ n。取势能 Φ = 已 pop 的元素数（单调增、上界 n）——和双指针是同一套论证。
    弹出为什么安全
    弹出 x 时，a[i] > a[x] 且 i > x。对任何 j > i，a[i] 比 a[j] 离 x 更近且已经更大 ⟹ x 的答案必然是 i，不可能是 j ⟹ x 被完全支配，可永久移出。
    三条约定
    ① 栈里存下标不存值（下标能反查值，且求宽度必须有下标）；② 求「更大」用递减栈、求「更小」用递增栈；③ 答案在 pop 时写入，不是 push 时——这是单调栈题的统一节奏。
  2. 基础前缀和怎么做区间和查询？为什么数组长度要取 n+1？
    S[0] = 0, S[i] = a[0] + … + a[i−1] sum(l, r) = S[r+1] − S[l] （闭区间 [l, r]） 预处理 O(n)，此后每次查询 O(1)
    为什么长度取 n+1 且 S[0]=0
    让 l = 0 时不需要特判。否则公式要写成 l == 0 ? S[r] : S[r] - S[l-1]，多一个分支就多一处出错机会。
    这和二分用半开区间是同一类设计：多留一个哨兵位置，换掉一整类边界判断。
    溢出
    S 必须用 long long。10⁵ 个 10⁴ 量级的 int 相加就溢出，而有符号溢出是 UB。
    用 STL 时更隐蔽：std::partial_sum 的累加类型由输出容器的元素类型决定——给 vector<int> 输出就是 int 累加。
    STL 对应
    std::partial_sum 是 inclusive（含当前项）；区间查询公式要的是 exclusive。C++17 起用名字明确的 std::exclusive_scan(first, last, out, 0LL)——顺带还能显式指定累加类型，并支持 std::execution::par 并行。
  3. 基础差分数组解决什么问题？它和前缀和是什么关系？

    差分解决「多次区间加，最后统一查询」：把 O(n) 的区间修改压成 O(1) 的两点加减。

    d[l] += v; d[r+1] -= v; ← 区间 [l, r] 全加 v，O(1) 最后对 d 求一次前缀和，得到最终数组 m 次操作总代价 O(m + n)，而不是朴素的 O(m·n)
    两者互为逆运算
    a 的差分的前缀和 = a。所以它们是同一枚硬币的两面：
    · 前缀和：区间查询 O(1)，但修改要 O(n) 重建
    · 差分：区间修改 O(1)，但查询要先还原 O(n)
    生活类比
    差分像「只在门口记进出的人数」——要让 10 点到 12 点的每个人都算一次，不用给这两小时每分钟都记一笔，只在 10 点记 +1、12 点零一分记 −1。想知道任意时刻屋里多少人，把从开门到那一刻的进出累加（前缀和）即可。
    两个坑
    ① d 的长度必须是 n+1——r 可以等于 n−1，此时要写 d[n]。少留一位就是越界写，而且小数据下常常不崩（写进了容量冗余），非常隐蔽。
    ② 「O(1) 修改」的前提是所有修改都在查询之前。修改与查询交错时差分不适用，要换树状数组或线段树+懒标记。
  4. 基础为什么滑动窗口求「最大值」不能像求「和」那样加一个减一个？

    因为移出的可能正是最大值，而你不知道次大值是谁。求和时「减掉移出的元素」是精确可逆的；求最大值时，移出最大值后你手上没有任何信息能恢复出新的最大值。

    本质原因：max 没有逆元。加法可以减回来，max 不能「max 回去」。这条判据同时解释了为什么区间最值不能用前缀和（见 §4.4）。

    正解：单调队列，O(n) 摊销
    std::deque<int> dq;   // 存下标，对应值递减
for (int i = 0; i < n; ++i) {
    while (!dq.empty() && a[dq.back()] <= a[i])
        dq.pop_back();                  // ① 尾部：被支配
    dq.push_back(i);
    if (dq.front() <= i - k) dq.pop_front();  // ② 头部：过期
    if (i >= k - 1) res.push_back(a[dq.front()]);
}
    两个出口，两个不同理由
    尾部弹出（被支配）：新元素既更大、位置又更靠后 ⟹ 旧元素永远不可能再是最大值 ⟹ 永久删除。
    头部弹出（过期）：下标滑出窗口。它没被支配，只是不再有资格参赛。
    正因为有两个出口，容器必须是双端队列而不是栈。
    替代方案
    multiset（O(n log k)，但能删任意元素、能同时取最大最小）；延迟删除堆（O(n log n)，但当窗口不是定长滑动而是任意区间时反而唯一可行）。

9.2 中级（区分熟练度）

  1. 中级「和恰好为 k 的子数组个数」怎么做（数组可含负数）？有哪些必须注意的细节？

    滑动窗口在含负数时失效（和不随窗口变长单调），正解是前缀和 + 哈希表：枚举右端点 r，查「有多少个左端点 l 使 S[r] − S[l] = k」，即查 S[r] − k 出现过几次。

    int subarray_sum(const std::vector<int>& a, int k) {
    std::unordered_map<long long, int> cnt;
    cnt[0] = 1;                 // ① 空前缀
    long long S = 0; int ans = 0;
    for (int x : a) {
        S += x;
        auto it = cnt.find(S - k);
        if (it != cnt.end()) ans += it->second;   // ② 先查
        ++cnt[S];                                //    后加
    }
    return ans;
}
    ① cnt[0] = 1 是必需的
    它代表「空前缀」，对应「子数组从下标 0 开始」。漏掉它，所有以 0 开头的合法子数组都会被漏算。
    ② 必须先查后加
    如果先 ++cnt[S] 再查 S − k，那么 k = 0 时当前前缀会匹配到自己，多算一个长度为 0 的「子数组」。
    ③ 存次数而非「是否出现」
    含负数时同一个前缀和会反复出现，每次对应一个不同的左端点，必须累加次数。
    变体只需换 key/value 的语义
    · 求最长而非个数 → value 存「最早出现的下标」，且只在 key 不存在时插入（保留最早的）
    · 能被 k 整除的子数组 → key 存 ((S % k) + k) % k（负数取模要修正）
    · 0 和 1 数量相等的最长子数组 → 把 0 当 −1，转化成「和为 0」
    · 乘积为正的最长段 → 数负号个数的奇偶，转化成前缀奇偶性
    这些题的共同点是「找到一个可累加且可相减的量」——这才是前缀和题的真正技巧。
  2. 中级「柱状图中最大矩形」怎么用单调栈解？哨兵技巧解决了什么？

    关键不在单调栈，而在视角转换：不枚举矩形的左右端点（O(n²)），而是枚举「哪根柱子是矩形的高」。

    对每根柱 i：宽度上限由两侧第一个更矮的柱子决定 width = right[i] − left[i] − 1 面积 = h[i] × width 而「两侧第一个更矮」正是单调栈的标准输出 ⟹ O(n)
    int largest_rectangle(std::vector<int> h) {
    h.insert(h.begin(), 0);   // 左哨兵
    h.push_back(0);            // 右哨兵
    std::vector<int> st;         // 递增栈
    int best = 0;
    for (int i = 0; i < (int)h.size(); ++i) {
        while (!st.empty() && h[st.back()] > h[i]) {
            int top = st.back(); st.pop_back();
            best = std::max(best, h[top] * (i - st.back() - 1));
        }
        st.push_back(i);
    }
    return best;
}
    哨兵消掉了两类边界判断
    左哨兵 0：比任何柱子都矮，永不被弹出 ⟹ 栈永不为空 ⟹ st.back() 总是合法，不用判空。
    右哨兵 0：会把栈里剩下的所有柱子都弹出 ⟹ 不需要在循环后再写一段「清算剩余栈」的重复代码。
    哨兵是个通用手法
    链表题的哑头节点、区间题的 [−∞, +∞] 边界、字符串题末尾补终止符，都是同一个东西。
    识别信号：如果你在写「循环后还要再处理一遍剩余状态」，通常加个哨兵就能合并掉。
    二维推广
    「01 矩阵中全 1 的最大矩形」= 逐行把二维压成柱状图（heights[c] = g[r][c]=='1' ? heights[c]+1 : 0），每行调一次上面的函数，O(m·n)。「降维 + 复用已有解法」是二维问题的通用套路。
  3. 中级为什么区间 max 不能用前缀和？该用什么？

    因为前缀和的本质要求是运算可逆（有逆元）——只有能「减掉不要的部分」，才能用 S[r] − S[l] 还原区间。max 没有逆元：知道 max(a[0..r]) 和 max(a[0..l-1])，推不出 max(a[l..r])。

    运算有逆元？能否前缀和
    加法减法能
    异或异或自身能（最优雅，无溢出无符号问题）
    乘法（无 0）除法能，含 0 则失效
    模乘（模质数）乘逆元能
    max / min / gcd无不能
    替代方案（按需求选）
    无修改 + 要 O(1) 查询 → 稀疏表（sparse table）：O(n log n) 预处理，O(1) 查询。它利用 max 的「可重叠合并」性质——两个有重叠的区间取 max 仍正确，所以用两个长度为 2^k 的区间覆盖任意区间即可。
    有修改 → 线段树：O(n) 建、O(log n) 查改，通用但代码长。
    定长窗口滑动 → 单调队列：O(1) 摊销，但要求元素按序进出。
    为什么 gcd 能用稀疏表但不能用前缀和
    稀疏表只要求运算可结合 + 可重叠合并（idempotent），不要求可逆。gcd(gcd(x,y), gcd(y,z)) = gcd(x,y,z) 成立，所以能用。
    而求和不能用稀疏表（重叠部分会被加两次），却能用前缀和。两个结构的适用条件恰好互补——这是区间查询问题里一个很有启发的对称性。
  4. 中级扫描线解「会议室 II」，同一时刻的事件该按什么顺序处理？

    把每个会议拆成两个事件：(开始, +1) 和 (结束, −1)，排序后累加，过程中的最大值就是所需会议室数。

    for (auto& [s, e] : iv) {
    ev.emplace_back(s, +1);
    ev.emplace_back(e, -1);
}
std::sort(ev.begin(), ev.end());   // pair 字典序：同刻时 -1 排在 +1 前
int cur = 0, best = 0;
for (auto& [t, d] : ev) { cur += d; best = std::max(best, cur); }
    顺序由区间开闭语义决定
    左闭右开 [s, e)（会议时间段的常规语义）：[1,3) 与 [3,5) 不冲突 ⟹ 同刻先减后加。上面的代码靠 pair 字典序（-1 < +1）自动实现。
    闭区间 [s, e]（线段覆盖）：[1,3] 与 [3,5] 确实在点 3 相交 ⟹ 同刻先加后减，要反转排序键，或把结束时刻改成 e + 1。
    为什么这个坑难发现
    写反了只在「刚好首尾相接」的用例上错，随机测试很难命中。动手前先在纸上写清「首尾相接算不算重叠」——这是扫描线第一大坑。
    扫描线 = 排序 + 一个可增量维护的状态
    难度全在「状态用什么结构维护」：
    · 只要计数 → 一个整数（会议室）
    · 要最大值且需删任意元素 → multiset 或延迟删除堆（天际线问题）
    · 要区间覆盖长度 → 线段树（矩形面积并）
    · 要「有多少已插入值小于 x」→ 树状数组（二维数点 / 逆序对）
    识别信号：题目涉及区间 / 线段 / 事件，且答案与「某时刻的聚合状态」有关。

9.3 高级（体现深度）

  1. 高级单调队列还能优化 DP，怎么识别这类题？它和斜率优化的区别是什么？

    识别信号：DP 转移的候选区间是一个随 i 单调移动的窗口，且转移里对 j 求 max/min。

    dp[i] = max{ dp[j] + w(i) : i − k ≤ j < i } 朴素：每个 i 扫 k 个候选 → O(n·k) 观察：候选集 {i−k, …, i−1} 随 i 整体右移 ⟹ 就是「定长滑动窗口最大值」 ⟹ 单调队列 → O(n)
    // 跳跃游戏 VI：每步最多跳 k 格，求最大得分
for (int i = 1; i < n; ++i) {
    if (dq.front() < i - k) dq.pop_front();       // 过期
    dp[i] = dp[dq.front()] + a[i];                  // 队首是窗口内 dp 最大者
    while (!dq.empty() && dp[dq.back()] <= dp[i])
        dq.pop_back();                              // 被支配
    dq.push_back(i);
}
    与斜率优化的关键区别
    看转移权重能否拆成「只依赖 j 的部分」：
    单调队列适用：dp[i] = max{dp[j]} + w(i)——候选的比较只依赖 j（比 dp[j] 大小），与 i 无关。所以「谁支配谁」是绝对的，可以永久丢弃。
    斜率优化适用：dp[i] = min{dp[j] + (a[i] − a[j])²}——展开后有 −2·a[i]·a[j] 这种i 与 j 的乘积项，谁更优取决于 i。此时不能简单丢弃，要维护一个下凸壳（convex hull trick），按斜率查询。
    一句话判据
    「候选之间的优劣关系是否与 i 无关」——无关则单调队列（丢弃是永久的），有关则凸包/李超线段树（丢弃要看斜率区间）。
    这两者常被混为一谈，但复杂度都是 O(n)，区别在维护的不变式：一个是单调序列，一个是凸壳。
    还有一类：决策单调性 + 分治
    如果最优决策点 opt[i] 关于 i 单调不减（但转移不是窗口形式），可以用分治优化（divide and conquer optimization）做到 O(n log n)。这三类优化会在批次 4 的动态规划里系统对比。
  2. 高级Prometheus 的 counter 为什么设计成「只增的累计值」而不是「每个周期的增量」？

    因为 counter 就是前缀和，而 rate() 就是区间查询 S[r] − S[l]。这个设计的好处正是前缀和相对于「存增量」的好处。

    ① 抗采样丢失
    存增量时丢一个采样点就永久丢了那段数据；存累计值时丢点只影响时间精度，下一个点仍能算出正确的总量。监控系统的采集必然会偶尔失败，这一条是决定性的。
    ② 抗采样间隔变化
    采集周期从 15s 改成 30s 时，累计值的语义不变；增量的语义会变（「每 15s 多少」变成「每 30s 多少」），历史数据无法直接对比。
    ③ 客户端无状态
    只需一个原子自增，不需要维护「上次上报时刻」和窗口状态。这让客户端库极简，也避免了多线程下的窗口同步问题。
    ④ 可任意重采样
    同一份数据能算 1 分钟、5 分钟、1 小时的 rate；增量存储只能向上聚合，且聚合后无法还原更细粒度。
    代价：counter reset
    进程重启让计数归零，此时 counter(t2) − counter(t1) 变成负数。所以 rate() 的实现必须检测重置——读数下降就假定发生重启，那一段按「从 0 开始」处理。
    这就是为什么应该用 rate()/increase() 而不要手写 a - b：手写版不处理重置，会在每次发版时产生一个巨大的负值尖刺，进而触发误告警。
    同一族设计
    histogram 也存累积形式（每个 bucket 记「≤ 阈值的样本数」），这样桶可以跨实例相加后再算分位数——累积计数是可加的。代价是精度受桶边界限制，histogram_quantile 只能在桶内线性插值。想要更好精度就换 t-digest / DDSketch（用相对误差保证换 O(log 值域) 空间）。
    见 可观测性。
  3. 高级一个「查询任意时间区间内的请求量」的接口，随着数据量增长越来越慢，怎么设计？

    先定位：如果实现是「扫描原始日志表按时间过滤求和」，那复杂度是 O(区间内记录数)——数据量涨，查询必然线性变慢。这是「每次查询都重新扫一遍」的典型症状，也正是前缀和要解决的问题。

    ① 先问清查询模式
    这决定了全部方案：区间端点是否任意（还是只查「最近 N 分钟」）？需要多细的粒度（秒级还是分钟级）？写入是否还在持续（历史数据是否会变）？能接受多大误差？
    ② 历史数据不变 → 预聚合 + 前缀和
    按分钟预聚合成一张表，再对它建累计和（前缀和）。任意区间查询变成两行相减，O(1)。
    数据量从「每请求一行」降到「每分钟一行」——降了几个数量级。这是最划算的一步。
    ③ 写入持续 → 分层聚合（roll-up）
    秒级保留 1 小时、分钟级保留 7 天、小时级保留 1 年。查询时按区间长度自动选层：查最近 10 分钟用秒级，查上个月用小时级。
    这就是时序数据库（Prometheus 的 recording rules、VictoriaMetrics、InfluxDB 的 continuous query）的标准做法——不要自己造，直接用。
    ④ 需要边写边查任意区间 → 树状数组 / 线段树
    前缀和不支持高效修改（要 O(n) 重建）。修改与查询交错时，用树状数组（单点改 + 区间和查，O(log n)，代码最短）。
    「修改和查询是否交错」是这类选型的第一判据：不交错 → 前缀和 O(1)；交错 → 树状数组 O(log n)。
    ⑤ 别忽略基数问题
    如果要按维度（接口、状态码、地域）分别统计，预聚合的行数是各维度基数的乘积。维度里混进了 user_id 或 trace_id 这类高基数字段，预聚合表会比原始数据还大。
    预聚合的前提是维度组合可控——这是实践中最常翻车的地方。
    再往上一层
    如果查询的是「去重用户数」而不是「请求量」，预聚合不成立——去重计数不可加（两个小时各 100 个 UV，合起来不是 200）。此时要用 HyperLogLog：它的 sketch 可以合并，用约 1.5% 的相对误差换 O(1) 空间的可加性。
    「这个指标可加吗」决定了能不能预聚合：sum/count/min/max 可加；avg 要存 sum 和 count 分别聚合；distinct count 和分位数不可加，必须换成可合并的近似结构（HLL、t-digest）。见 Redis 与缓存。
  4. 高级「天际线问题」为什么不能只用一个整数维护当前高度？该用什么？

    因为天际线要的是当前所有活跃建筑高度的最大值，而建筑的结束顺序与开始顺序无关——一个先开始的高楼可能最后才结束。

    为什么整数不够
    会议室问题维护的是「重叠数量」，加减是可逆的，一个整数够了。天际线维护的是「高度最大值」——max 没有逆元，移除一个建筑时你无法从「当前最大值」推出「新的最大值」。
    这和 §9.1 第 4 题（窗口最大值不能加一个减一个）是同一个根因。
    为什么单调队列也不够
    单调队列要求元素按序进入、按序过期。天际线里建筑的结束时刻是任意的——先入的可能后出，所以「被支配就永久丢弃」这个论证不成立。
    方案一 · multiset（最直观）
    事件为 (x, −h) 表示开始、(x, +h) 表示结束。扫描时开始就 insert(h)、结束就 erase(find(h))（注意用 find 只删一个，直接 erase(h) 会删掉所有等于 h 的），取 *rbegin() 为当前高度。O(n log n)。
    事件排序技巧：把开始事件的高度存成负数，这样同一 x 处「先处理开始（负数小，排前面）再处理结束」，且「多个开始时高的先处理」——一次排序解决全部同刻顺序问题。
    方案二 · 延迟删除的大顶堆
    堆不支持删任意元素。做法是只入不删，取堆顶时先循环丢弃「已过期」的堆顶（用一个 unordered_map<高度, 待删次数> 或比较结束时刻判断）。
    优点是常数比 multiset 小（数组连续 vs 红黑树指针追逐）；代价是堆可能膨胀到 O(n)。
    这是「可删除堆」这一类需求
    同类问题还有：滑动窗口中位数、带删除的 Top-K、Dijkstra 的 decrease-key。通用手段有三种——① 换能删任意元素的结构（multiset、平衡树）；② 延迟删除（懒惰堆，最常用）；③ 索引堆（额外维护「元素 → 堆内位置」的映射，支持真正的 O(log n) 任意删除与 decrease-key）。
    三者的取舍见 堆与 Top-K。
