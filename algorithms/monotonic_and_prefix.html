单调栈与前缀和

这四个工具解决的是同一类问题：把「每次查询都重新扫一遍」换成「维护一个可增量更新的状态」。单调栈和单调队列丢掉永远不会成为答案的候选；前缀和与差分把区间操作变成两个端点的加减。它们的共同代价也一样——都需要先证明「被丢掉的东西真的没用」或「这个运算真的可逆」。

01

本质：只留有用的候选

两条不同的省法，同一个动机

这一篇里的四个工具分成两族，动机相同但手法相反：

族工具手法关键前提
丢候选单调栈（§2）新元素让某些旧元素永远不可能再成为答案 → 直接弹出「被遮挡」关系可判定
单调队列（§3）同上，外加「过期」也要从另一端弹同上 + 窗口按序滑动
预处理前缀和（§4）区间查询 → 两个端点相减运算可逆（有逆元）
差分（§5）区间修改 → 两个端点加减同上，且修改与查询分阶段
「丢候选」的合法性论证：单调栈弹出元素 x 时，必须能证明——对于所有还没处理的位置，x 都不可能是它们的答案。通常的理由是「新来的元素 y 在各方面都不比 x 差，而且位置更靠后」，于是 x 被 y 完全支配（dominated）。

「预处理」的合法性论证：前缀和要求运算有逆元，才能用 S[r] − S[l-1] 还原区间。加法、异或、乘法（非零）可以；max / min / gcd 不行——它们没有逆元，区间查询要改用稀疏表或线段树。这条判据比记模板重要得多。
单调栈像排队看演出时的视线遮挡。你站在队尾往前看，只能看到那些「比前面所有人都高」的人——一旦某人被前面更高的人挡住，他对后面所有人来说都是不可见的，可以从「能看到的人」名单里永久删除。

栈里剩下的正是这个「从当前位置往回看能看见的人」的名单，而它天然是单调递减的。每个人最多进队一次、出队一次，所以总代价 O(n)——这就是单调栈为什么是线性的。

前缀和则像累计里程表。想知道「第 30 公里到第 80 公里之间跑了多远」，你不需要重新跑一遍，只要看两个读数相减。前提是里程表只增不减且可相减——如果它记的是「最高时速」，两个读数相减就毫无意义了。

单调栈

一个模板，五道经典题

2.1 不变式与模板

// 求每个位置「右边第一个更大元素」的下标；没有则为 n
std::vector<int> next_greater(const std::vector<int>& a) {
    int n = (int)a.size();
    std::vector<int> res(n, n);
    std::vector<int> st;                // 存下标，不存值
    st.reserve(n);

    for (int i = 0; i < n; ++i) {
        // ┌ 不变式：栈内下标对应的值严格递减（从栈底到栈顶）
        // └ 含义：栈内元素都「还没找到右边更大的」
        while (!st.empty() && a[st.back()] < a[i]) {
            res[st.back()] = i;      // a[i] 就是它的答案
            st.pop_back();            // 已解决 → 永久移出
        }
        st.push_back(i);
    }
    return res;
}
三条要记住的约定：
  1. 栈里存下标，不存值。下标能反查值，反之不行；而且求「宽度 / 距离」类答案时必须有下标。
  2. 不变式写在循环开头：栈内值单调（递增或递减）。方向由题目决定——求「下一个更大」用递减栈，求「下一个更小」用递增栈。
  3. 弹出的那一刻就是答案确定的时刻。所以答案是在 pop 时写入的，不是在 push 时。这是单调栈题的统一节奏。

复杂度 O(n) 的论证：每个下标最多被 push 一次、pop 一次。内层 while 的总执行次数等于总 pop 次数 ≤ n。这和双指针的势能论证是同一套：取 Φ = 已 pop 的元素数，单调增且上界 n。

2.2 下一个更大元素

四种变体只需改两处——比较符号和遍历方向：
要求遍历方向while 条件栈内单调性
右边第一个更大左 → 右a[st.back()] < a[i]递减
右边第一个更小左 → 右a[st.back()] > a[i]递增
左边第一个更大右 → 左a[st.back()] < a[i]递减

循环数组（如「下一个更大元素 II」）的处理：把循环下标写成 i % n 遍历 2n 轮，第二轮只弹不压。

2.3 接雨水

「接雨水」有三种解法，值得都会——因为它们代表三种不同的思考角度。

解法时间空间思考角度
预处理左右最大值O(n)O(n)按列算：每列水量 = min(左max, 右max) − h[i]
对撞双指针O(n)O(1)同上，但左右最大值可以边走边维护
单调栈O(n)O(n)按层算：弹出时结算一个横向的水条
✅ 对撞双指针：O(1) 空间
int trap(const std::vector<int>& h) {
    int l = 0, r = (int)h.size() - 1;
    int lmax = 0, rmax = 0, ans = 0;
    while (l < r) {
        lmax = std::max(lmax, h[l]);
        rmax = std::max(rmax, h[r]);
        // 关键：矮的那侧的水位已被确定
        if (lmax < rmax) ans += lmax - h[l++];
        else             ans += rmax - h[r--];
    }
    return ans;
}
✅ 单调栈：按层结算
int trap(const std::vector<int>& h) {
    std::vector<int> st;   // 递减栈
    int ans = 0;
    for (int i = 0; i < (int)h.size(); ++i) {
        while (!st.empty() && h[st.back()] < h[i]) {
            int bottom = st.back(); st.pop_back();
            if (st.empty()) break;      // 左边没有墙 → 存不住水
            int left = st.back();
            int width  = i - left - 1;
            int height = std::min(h[left], h[i]) - h[bottom];
            ans += width * height;      // 一个横条
        }
        st.push_back(i);
    }
    return ans;
}
双指针版为什么对（这是最常被追问的）：设 lmax < rmax，考察左指针位置 l 的水位。水位 = min(l 左侧最大, l 右侧最大)。我们知道 l 左侧最大就是 lmax；而 l 右侧最大 ≥ rmax > lmax（因为 r 及其左侧至少有 rmax 那么高的柱子在 l 右边）。
所以 min(...) = lmax —— 无需知道右侧最大的确切值，只要知道它比 lmax 大就够了。这就是能 O(1) 空间的原因。∎
单调栈版有个易漏的边界：弹出 bottom 后如果栈空，说明左边没有更高的墙，这个位置存不住水，必须 break（或 continue 到外层）。漏掉这一句会访问空栈的 back()——UB。
另外单调栈版是「按层」累加的：每次弹出结算的是一个横向的水条，而不是一列。理解这一点才知道为什么 height 要减去 h[bottom]。

2.4 柱状图最大矩形

这是单调栈的标志性题目：求柱状图中能勾出的最大矩形面积。

// 哨兵技巧：首尾各加一个高度 0 的虚拟柱，省掉所有边界判断
int largest_rectangle(std::vector<int> h) {
    h.insert(h.begin(), 0);   // 左哨兵：保证栈永不为空
    h.push_back(0);            // 右哨兵：保证所有柱子都被弹出结算

    std::vector<int> st;         // 递增栈
    int best = 0;
    for (int i = 0; i < (int)h.size(); ++i) {
        while (!st.empty() && h[st.back()] > h[i]) {
            int top = st.back(); st.pop_back();
            // 弹出时才知道 top 的右界是 i、左界是新的栈顶
            int width = i - st.back() - 1;
            best = std::max(best, h[top] * width);
        }
        st.push_back(i);
    }
    return best;
}
哨兵（sentinel）技巧值得单独学。它用两个虚拟元素消掉了两类边界判断：
  • 左哨兵 0：它比任何柱子都矮，永远不会被弹出 ⟹ 栈永不为空 ⟹ st.back() 总是合法，不用判空。
  • 右哨兵 0：它会把栈里剩下的所有柱子都弹出 ⟹ 不需要在循环后写一段「清算剩余栈」的重复代码。
这个手法在链表题里对应哑头节点（dummy head）、在区间题里对应 [−∞, +∞] 边界、在字符串题里对应末尾补一个终止符。识别信号：如果你在写「循环后还要再处理一遍剩余状态」，通常加个哨兵就能合并掉。

2.5 推广到二维

「最大矩形」（01 矩阵中全 1 的最大矩形）是柱状图题的二维版，做法是把二维压成 n 个一维问题：

int maximal_rectangle(const std::vector<std::string>& g) {
    if (g.empty()) return 0;
    int m = (int)g.size(), n = (int)g[0].size();
    std::vector<int> heights(n, 0);
    int best = 0;

    for (int r = 0; r < m; ++r) {
        // 把「以第 r 行为底」的柱状图算出来
        for (int c = 0; c < n; ++c)
            heights[c] = (g[r][c] == '1') ? heights[c] + 1 : 0;
        best = std::max(best, largest_rectangle(heights));   // 复用 §2.4
    }
    return best;   // O(m·n)
}
这个「逐行压成柱状图」的手法像给每一层楼拍一张地基图。你不去直接思考三维的建筑，而是对每一层问：「如果这一层是地面，往下能连续挖多深？」——于是三维问题变成 m 个二维问题，每个都用已经会的工具解。

「降维 + 复用已有解法」是处理二维问题的通用套路：二维前缀和（§4.3）、最大子矩阵和（枚举上下边界 + 一维 Kadane）、二维差分（§5.2）都是同一个思路。

单调队列

单调栈 + 一个「过期」出口

3.1 滑动窗口最大值

定长窗口求和很容易（加一个减一个），求最大值却不行——移出的可能正是最大值，而你不知道次大值是谁。单调队列解决的正是这个问题。

// 长度 k 的滑动窗口最大值，O(n) 摊销
std::vector<int> max_sliding_window(const std::vector<int>& a, int k) {
    std::deque<int> dq;             // 存下标，对应值单调递减
    std::vector<int> res;
    res.reserve(a.size() >= (size_t)k ? a.size() - k + 1 : 0);

    for (int i = 0; i < (int)a.size(); ++i) {
        // ① 尾部：弹掉所有 ≤ 新元素的（它们被永久支配）
        while (!dq.empty() && a[dq.back()] <= a[i]) dq.pop_back();
        dq.push_back(i);

        // ② 头部：弹掉已滑出窗口的（过期，不是被支配）
        if (dq.front() <= i - k) dq.pop_front();

        // ③ 窗口满了才输出；队首恒为窗口最大值
        if (i >= k - 1) res.push_back(a[dq.front()]);
    }
    return res;
}
两个出口，两个不同的理由——这是单调队列和单调栈的唯一区别：
  • 尾部弹出（被支配）：新元素 a[i] 既比它大、位置又比它靠后 ⟹ 只要 a[i] 还在窗口里，那个旧元素就永远不可能是最大值 ⟹ 永久删除。
  • 头部弹出（过期）：下标已滑出窗口范围。它没有被支配，只是不再有资格参赛。
正因为有两个出口，容器必须是双端队列而不是栈。

不变式：队列内下标递增、对应值递减，且队列 = 「窗口内所有还可能成为未来某个窗口最大值的候选」。所以队首恒为当前窗口最大值。
尾部弹出的条件用 <= 还是 < 决定了相等元素的处理：
  • 用 <=（弹掉相等的）：队列里不留重复值，更省空间。求最大值时这样写是对的——相等的旧元素比新的先过期，留着没用。
  • 用 <（保留相等的）：队列可能存多个相等值。如果题目需要「最大值的所有出现位置」或要统计个数，就得这样写。
另外 if (dq.front() <= i - k) 用 if 就够（不用 while），因为每轮最多有一个元素过期。

3.2 与优先队列的分工

单调队列优先队列（堆）multiset
窗口最大值O(n) 摊销O(n log n)O(n log k)
能否删任意元素否（只能从两端）否（需索引堆或延迟删除）能，O(log k)
能否同时取最大和最小否（要两个队列）否（要两个堆）能
要求元素按序进出无无
空间O(k)O(n)（含过期元素）O(k)
单调队列的适用前提比堆严格得多：它要求元素严格按下标顺序进入、按下标顺序过期。正是这个「有序进出」的性质让「被支配的元素可以永久丢弃」成立——因为你能断定被支配者一定比支配者先过期。

堆没有这个前提，所以它必须保留所有元素（用「延迟删除」时还要靠一个额外的计数表判断堆顶是否已过期）。换句话说：单调队列是用「更强的输入假设」换来了「更好的复杂度」。
用堆做滑动窗口最大值的延迟删除写法（面试可能追问）：把 (值, 下标) 入堆，取堆顶时先循环丢弃「下标已过期」的堆顶。它的复杂度是 O(n log n)、空间 O(n)——比单调队列差，但当窗口不是定长滑动而是任意区间时反而是唯一可行的做法。
需要同时维护最大和最小（如「绝对差不超过 limit 的最长子数组」）时，两个单调队列并用是标准解法；需要中位数则要对顶堆或 multiset，见 堆与 Top-K。

3.3 DP 的决策单调优化

单调队列最有价值的用途不在刷题，而在把 O(n·k) 的 DP 优化成 O(n)。典型形式是：

dp[i] = max{ dp[j] + w(i) : i − k ≤ j < i } 朴素：对每个 i 扫一遍 k 个候选 j → O(n·k) 观察：候选集合 {i−k, …, i−1} 随 i 增大而整体右移 ⟹ 这就是一个定长滑动窗口的最大值问题 ⟹ 单调队列 → O(n)
// 跳跃游戏 VI：每步最多跳 k 格，求到终点的最大得分
int max_result(const std::vector<int>& a, int k) {
    int n = (int)a.size();
    std::vector<int> dp(n);
    std::deque<int> dq;              // 存下标，dp 值递减
    dp[0] = a[0];
    dq.push_back(0);

    for (int i = 1; i < n; ++i) {
        if (dq.front() < i - k) dq.pop_front();     // 过期
        dp[i] = dp[dq.front()] + a[i];                // 队首是窗口内 dp 最大者
        while (!dq.empty() && dp[dq.back()] <= dp[i])
            dq.pop_back();                            // 被支配
        dq.push_back(i);
    }
    return dp[n - 1];
}
识别这类优化的信号：DP 转移的候选区间是一个随 i 单调移动的窗口，且转移里对 j 求的是 max/min。
如果转移形如 dp[i] = min{dp[j] + (a[i]−a[j])²}（候选权重同时依赖 i 和 j 的乘积项），那就不是单调队列而是斜率优化 / 凸包技巧（convex hull trick）——它维护的是一个下凸壳而不是单调序列。这两者常被混为一谈，区别在于「权重能否拆成只依赖 j 的部分」。斜率优化会在批次 4 的动态规划里展开。

前缀和

把区间查询变成两个端点相减

4.1 一维与 STL 对应

定义 S[0] = 0, S[i] = a[0] + a[1] + … + a[i−1] 区间和 sum(l, r) = S[r+1] − S[l] （闭区间 [l, r]） 预处理 O(n)，此后每次查询 O(1)
S 的长度取 n+1、且 S[0] = 0，这不是可选的风格问题——它让 l = 0 时不需要特判（否则要写 l == 0 ? S[r] : S[r] - S[l-1]）。这和二分用半开区间是同一类设计：多留一个哨兵位置，换掉一整类边界判断。
// 手写
std::vector<long long> S(n + 1, 0);
for (int i = 0; i < n; ++i) S[i + 1] = S[i] + a[i];
auto range_sum = [&](int l, int r) { return S[r + 1] - S[l]; };

// STL：注意 partial_sum 是含当前项的（inclusive）
std::vector<long long> P(n);
std::partial_sum(a.begin(), a.end(), P.begin());     // P[i] = a[0..i]

// C++17 起有明确区分的两个版本 + 并行支持
std::inclusive_scan(a.begin(), a.end(), P.begin());   // P[i] = a[0..i]
std::exclusive_scan(a.begin(), a.end(), P.begin(), 0LL);  // P[i] = a[0..i-1]，即上面的 S
std::inclusive_scan(std::execution::par, ...);          // 并行前缀和
两个必踩的坑：
  • 类型溢出：partial_sum 的累加类型由输出迭代器的 value_type 决定（实际由第一个元素的类型推导）。给 vector<int> 求前缀和时，中间结果就是 int，10⁵ 个 10⁴ 量级的数就溢出。输出容器必须是 long long，或用带初值的 exclusive_scan 显式指定类型。
  • inclusive 与 exclusive 混用：partial_sum 是 inclusive，而区间查询公式要的是 exclusive（带 S[0]=0 的那种）。混用会整体偏移一位。C++17 之后建议直接用名字明确的 exclusive_scan。
并行前缀和（inclusive_scan + par）不是简单的分块相加——它是一个两趟的 scan 算法，这也是为什么标准要求运算可结合但允许非交换。

4.2 前缀和 + 哈希表

这个组合是「和为 K 的子数组」类问题的标准答案，也是滑动窗口对负数失效时的替代方案。

// 和恰好为 k 的子数组个数（可含负数和 0）
int subarray_sum_equals_k(const std::vector<int>& a, int k) {
    std::unordered_map<long long, int> cnt;
    cnt[0] = 1;                    // 空前缀：必须有，否则漏掉从头开始的子数组
    long long S = 0;
    int ans = 0;

    for (int x : a) {
        S += x;
        // 找有多少个左端点 l 使 S − S[l] = k，即 S[l] = S − k
        auto it = cnt.find(S - k);
        if (it != cnt.end()) ans += it->second;
        ++cnt[S];                    // 先查后加：避免 k=0 时自己匹配自己
    }
    return ans;
}
三个必须理解的细节：
  1. cnt[0] = 1 是必需的。它代表「空前缀」，对应「子数组从下标 0 开始」的情形。漏掉它，所有以 0 开头的合法子数组都会被漏算。
  2. 必须「先查后加」。如果先 ++cnt[S] 再查 S − k，那么 k = 0 时当前前缀会匹配到自己，多算一个长度为 0 的「子数组」。
  3. 哈希表存的是「出现次数」而不是「是否出现」。因为同一个前缀和可能出现多次（含负数时很常见），每次都对应一个不同的左端点。
这三点每一点都能让答案错，而且都是「小数据可能测不出」的那种错。
变体哈希表的 key / value技巧
和为 k 的子数组个数前缀和 → 出现次数查 S − k
和为 k 的最长子数组前缀和 → 最早出现的下标只在 key 不存在时插入（保留最早）
能被 k 整除的子数组个数前缀和 mod k → 次数负数取模要 ((S % k) + k) % k
0 和 1 数量相等的最长子数组(1的数−0的数) → 最早下标把 0 当 −1，转化成「和为 0」
连续元素乘积为正的最长段—数负号个数的奇偶，转化成前缀奇偶性
这张表里最值得学的是「转化」这一列：绝大多数看起来不像前缀和的题，都是通过一次巧妙的重新定义变成前缀和的。把 0 当 −1、数负号奇偶、对 k 取模——本质都是找到一个「可累加且可相减」的量。
写题时的自问句：「我能定义一个前缀量，使得『区间满足条件』等价于『两个前缀量相等 / 相差 k』吗？」

4.3 二维前缀和与容斥

// 构建：S 的维度是 (m+1) × (n+1)，首行首列为 0
std::vector<std::vector<long long>> build2d(const Matrix& a, int m, int n) {
    std::vector<std::vector<long long>> S(m + 1, std::vector<long long>(n + 1, 0));
    for (int i = 1; i <= m; ++i)
        for (int j = 1; j <= n; ++j)
            S[i][j] = S[i-1][j] + S[i][j-1] - S[i-1][j-1] + a[i-1][j-1];
    return S;
}

// 查询原矩阵闭区间 [r1..r2][c1..c2] 的和，O(1)
long long query2d(const auto& S, int r1, int c1, int r2, int c2) {
    return S[r2+1][c2+1] - S[r1][c2+1] - S[r2+1][c1] + S[r1][c1];
}
推广到 k 维时，容斥项数是 2^k（每个维度选「取」或「不取」，符号由取的个数的奇偶决定）。三维前缀和查询需要 8 项。
所以二维前缀和好用，三维勉强，四维以上通常改用其他结构（如 k-d 树或直接分块）——2^k 的项数增长是它的天然上限。

4.4 前缀异或与其他可逆运算

前缀和的本质要求是运算可逆（有逆元）。满足这一点的运算都能用同一套思路：

运算逆运算区间查询公式典型题
加法 +减法 −S[r+1] − S[l]区间和
异或 ⊕异或自身X[r+1] ^ X[l]区间异或、找出现奇数次的数
乘法 ×（无 0）除法 ÷P[r+1] / P[l]区间乘积（含 0 则失效）
模乘（模质数）乘逆元P[r+1] × inv(P[l])组合数、区间乘积取模
max / min无逆元不适用要用稀疏表 / 线段树
gcd无逆元不适用稀疏表（gcd 可重叠合并）
异或是最优雅的一个，因为它的逆运算就是它自己（x ^ x = 0）。这让「前缀异或」比前缀和更省心——不用担心溢出，也不用担心符号。
典型应用是「区间内每个数出现偶数次 ⟺ 区间异或为 0」这个等价关系，它把「统计出现次数」这个 O(值域) 的问题压成了一个整数。

而 max/min 没有逆元这件事，解释了整个「区间查询」问题为什么需要更复杂的数据结构：前缀和之所以简单是因为它能「减掉」不要的部分，max 减不掉。所以区间最值要么用稀疏表（O(n log n) 预处理、O(1) 查询、不支持修改），要么用线段树（O(n) 建、O(log n) 查改）。这两个会在批次 3 的并查集与区间结构里展开。

差分数组

前缀和的对偶：把区间修改变成两点加减

5.1 区间加、单点查

前缀和：区间查询 O(1)，但修改 O(n)（要重建） 差分　：区间修改 O(1)，但查询要先还原 O(n) d[l] += v; d[r+1] -= v; ← 区间 [l, r] 全部加 v，O(1) 最后对 d 求一次前缀和，得到最终数组 两者是互逆的：a 的差分的前缀和 = a
// 航班预订统计：m 次「区间 [l, r] 加 v」，最后输出整个数组
std::vector<int> corp_flight_bookings(const std::vector<std::array<int,3>>& ops, int n) {
    std::vector<long long> d(n + 1, 0);   // 多留一位放 r+1
    for (auto& op : ops) {
        int l = op[0], r = op[1], v = op[2];
        d[l] += v;
        d[r + 1] -= v;                       // r+1 可能等于 n，所以 d 要 n+1 长
    }
    std::vector<int> res(n);
    long long cur = 0;
    for (int i = 0; i < n; ++i) { cur += d[i]; res[i] = (int)cur; }
    return res;
}
// O(m + n)，而不是朴素的 O(m·n)
差分像只在门口记进出的人数，而不是每分钟数一遍屋里有多少人。要知道「10 点到 12 点每个人都算一次」，你不用给这两小时里的每一分钟都记一笔——只在 10 点记「+1」、12 点零一分记「−1」。

最后想知道任意时刻屋里有多少人，把从开门到那一刻的所有进出累加一遍就行——这个累加就是前缀和。所以差分和前缀和是同一枚硬币的两面：一个负责「登记变化」，一个负责「还原状态」。
d 的长度必须是 n+1，因为 r 可以等于 n−1，此时 d[r+1] = d[n]。少留一位就是越界写——而且这种越界在小数据下常常不崩（写到了容器的容量冗余里），非常隐蔽。
另外「区间修改 O(1)」的前提是所有修改都在查询之前完成。如果修改和查询交错，差分就不适用了——要改用树状数组（支持单点改 + 区间查，或差分套树状数组做区间改 + 单点查）或线段树 + 懒标记（区间改 + 区间查）。「修改与查询是否分阶段」是选型的第一个判据。

5.2 二维差分

二维差分是「区间加」在矩阵上的版本：给子矩阵 [r1..r2][c1..c2] 全部加 v，O(1)。

// 四个角打标记：和二维前缀和的容斥公式对称
void add_rect(auto& d, int r1, int c1, int r2, int c2, long long v) {
    d[r1     ][c1     ] += v;
    d[r1     ][c2 + 1] -= v;
    d[r2 + 1][c1     ] -= v;
    d[r2 + 1][c2 + 1] += v;    // 被减两次，补回来
}

// 全部操作完成后，对 d 做二维前缀和即得最终矩阵
for (int i = 0; i < m; ++i)
    for (int j = 0; j < n; ++j) {
        if (i) d[i][j] += d[i-1][j];
        if (j) d[i][j] += d[i][j-1];
        if (i && j) d[i][j] -= d[i-1][j-1];
    }
注意 add_rect 的四项符号 + − − + 和二维前缀和查询的 + − − + 完全一致——这不是巧合，而是因为差分和前缀和互为逆运算。记住其中一个，另一个可以推出来。
同样地，k 维差分需要 2^k 个角打标记。

5.3 扫描线

「差分」的思想推广到坐标不连续、值域很大的场景，就是扫描线（sweep line）：不再开一个覆盖整个值域的数组，而是只记录发生变化的那些点，排序后依次处理。

// 会议室 II：最少需要多少间会议室（= 最大同时进行的会议数）
int min_meeting_rooms(const std::vector<std::pair<int,int>>& iv) {
    std::vector<std::pair<int, int>> ev;      // (时刻, 增量)
    ev.reserve(iv.size() * 2);
    for (auto& [s, e] : iv) {
        ev.emplace_back(s, +1);                // 开始 → +1
        ev.emplace_back(e, -1);                // 结束 → -1
    }
    // 同一时刻：先处理结束（-1），再处理开始（+1）
    // 因为 [1,3) 和 [3,5) 不冲突。靠 -1 < +1 自动排在前面
    std::sort(ev.begin(), ev.end());

    int cur = 0, best = 0;
    for (auto& [t, delta] : ev) {
        cur += delta;
        best = std::max(best, cur);
    }
    return best;   // O(n log n)，瓶颈在排序
}
同一时刻的事件顺序是扫描线第一大坑，而且它由题目的区间开闭语义决定：
  • 区间左闭右开 [s, e)（会议室、时间段）：[1,3) 与 [3,5) 不冲突 ⟹ 同一时刻先减后加。上面的代码靠 pair 的字典序（-1 < +1）自动实现。
  • 区间闭区间 [s, e]（线段覆盖、区间交集）：[1,3] 与 [3,5] 确实在点 3 相交 ⟹ 同一时刻先加后减，要把结束事件的键写成 (e, +1) 之类来反转顺序，或者把结束时刻改成 e + 1。
写反了会在「刚好首尾相接」的用例上错，而随机测试很难命中这种边界。动手前先在纸上写清「首尾相接算不算重叠」。
题型事件是什么维护的量
会议室 / 最大重叠数(开始, +1), (结束, −1)当前重叠数的最大值
区间合并按左端排序当前合并区间的右端
天际线问题(左边界, −h), (右边界, +h)当前高度的多重集（要能删任意元素 → multiset）
矩形面积并竖边入 / 出当前 y 方向的覆盖长度（线段树）
逆序对 / 二维数点按一维排序另一维的树状数组
扫描线 = 排序 + 一个可增量维护的状态。它的难度全在「状态该用什么结构维护」：
  • 只要计数 → 一个整数（会议室）
  • 要最大值且要删任意元素 → multiset 或 延迟删除堆（天际线）
  • 要区间覆盖长度 → 线段树（矩形面积并）
  • 要「有多少个已插入的值小于 x」→ 树状数组（二维数点）
识别信号：题目涉及「区间 / 线段 / 事件」，且答案与「某时刻的聚合状态」有关。

监控、直方图、SQL 里的同一个东西

7.1 单调计数器与 rate

Prometheus 这类监控系统的 counter 类型就是前缀和：它只增不减，记录「自进程启动以来的累计次数」。查询时用两个时间点的读数相减得到区间增量。

counter(t) = 累计值（前缀和） rate(t1, t2) = (counter(t2) − counter(t1)) / (t2 − t1) ↑ 这就是 sum(l, r) = S[r] − S[l]
为什么不直接存「每秒的增量」说明
抗采样丢失存增量时丢一个采样点就永久丢了那段数据；存累计值时丢点只影响精度，下一个点仍能算出正确的总量。
抗采样间隔变化采集周期从 15s 改成 30s 时，累计值不受影响；增量的语义会变。
客户端无状态只需一个原子自增，不需要维护「上次上报时刻」和窗口。
可任意重采样同一份数据能算 1 分钟、5 分钟、1 小时的 rate，而增量存储只能向上聚合。
counter 有一个前缀和没有的问题：进程重启会让计数归零，此时 counter(t2) − counter(t1) 变成负数。所以 rate() 的实现必须检测重置（counter reset）——发现读数下降就假定发生了重启，把那一段按「从 0 开始」处理。
这也是为什么 Prometheus 里应该用 rate() / increase() 而不要手写 a - b：手写的版本不处理重置，会在每次发版时产生一个巨大的负值尖刺。相关内容见 可观测性。

7.2 直方图与分位数

直方图（histogram）的桶计数做一次前缀和，就得到累积分布函数（CDF）；在 CDF 上二分就能估算任意分位数。

桶计数 buckets[i] = 落在第 i 个区间的样本数 累积 cdf[i] = buckets[0] + … + buckets[i] ← 前缀和 p99 在 cdf 上找第一个 ≥ 0.99 × total 的桶 ← 二分 然后在桶内线性插值估算具体值
Prometheus 的 histogram 直接存累积形式（le="0.1"、le="0.5"、le="1"… 每个 bucket 记「≤ 该阈值的样本数」），这样：
  • 桶可以跨实例相加——累积计数是可加的，所以多个副本的直方图能直接汇总后再算分位数。
  • 代价是精度受桶边界限制。histogram_quantile 在桶内做线性插值，如果 p99 落在一个很宽的桶里，估计值可能偏差很大。
想要更好的精度又不想开太多桶，就用 t-digest 或 DDSketch——它们用相对误差保证（如「任意分位数的相对误差 ≤ 1%」）换取 O(log(值域)) 的空间。这又是「精确无界 → 近似有界」的那个取舍。

7.3 SQL 窗口函数

SQL 的窗口函数是前缀和 / 滑动窗口的声明式版本，写法一一对应：

-- 前缀和（累计销售额）
SELECT day, amount,
       SUM(amount) OVER (ORDER BY day
                          ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total
FROM sales;

-- 定长滑动窗口（7 日移动平均）
SELECT day, amount,
       AVG(amount) OVER (ORDER BY day
                          ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS ma7
FROM sales;

-- 差分（同比 / 环比）
SELECT day, amount,
       amount - LAG(amount, 1) OVER (ORDER BY day) AS delta
FROM sales;
ROWS 和 RANGE 的区别是这里的高频坑：ROWS 按行数算窗口（前 6 行），RANGE 按值算（ORDER BY 列的值在某个范围内）。日期有缺失时两者结果不同——ROWS 6 PRECEDING 拿的是「前 6 条记录」，如果中间缺了几天，实际跨度会超过 7 天。要严格的「最近 7 天」必须用 RANGE BETWEEN INTERVAL '6' DAY PRECEDING AND CURRENT ROW。
完整的窗口函数用法见 SQL 从基础到高级。

9.1 基础（必答）

点击每道题展开参考答案（先自测，再对照）。

  1. 基础什么是单调栈？写出「下一个更大元素」的模板，并说明为什么是 O(n)。

    单调栈是一个栈内元素保持单调的栈。它的作用是维护「还没找到答案的候选集」——新元素一来，就把被它完全支配的旧元素全部结算并永久移出。

    std::vector<int> next_greater(const std::vector<int>& a) {
    int n = a.size();
    std::vector<int> res(n, n), st;   // st 存下标
    for (int i = 0; i < n; ++i) {
        // 不变式：栈内值严格递减
        while (!st.empty() && a[st.back()] < a[i]) {
            res[st.back()] = i;      // 弹出时才确定答案
            st.pop_back();
        }
        st.push_back(i);
    }
    return res;
}
    O(n) 的论证
    每个下标最多 push 一次、pop 一次。内层 while 的总执行次数等于总 pop 次数 ≤ n。取势能 Φ = 已 pop 的元素数（单调增、上界 n）——和双指针是同一套论证。
    弹出为什么安全
    弹出 x 时，a[i] > a[x] 且 i > x。对任何 j > i，a[i] 比 a[j] 离 x 更近且已经更大 ⟹ x 的答案必然是 i，不可能是 j ⟹ x 被完全支配，可永久移出。
    三条约定
    ① 栈里存下标不存值（下标能反查值，且求宽度必须有下标）；② 求「更大」用递减栈、求「更小」用递增栈；③ 答案在 pop 时写入，不是 push 时——这是单调栈题的统一节奏。
  2. 基础前缀和怎么做区间和查询？为什么数组长度要取 n+1？
    S[0] = 0, S[i] = a[0] + … + a[i−1] sum(l, r) = S[r+1] − S[l] （闭区间 [l, r]） 预处理 O(n)，此后每次查询 O(1)
    为什么长度取 n+1 且 S[0]=0
    让 l = 0 时不需要特判。否则公式要写成 l == 0 ? S[r] : S[r] - S[l-1]，多一个分支就多一处出错机会。
    这和二分用半开区间是同一类设计：多留一个哨兵位置，换掉一整类边界判断。
    溢出
    S 必须用 long long。10⁵ 个 10⁴ 量级的 int 相加就溢出，而有符号溢出是 UB。
    用 STL 时更隐蔽：std::partial_sum 的累加类型由输出容器的元素类型决定——给 vector<int> 输出就是 int 累加。
    STL 对应
    std::partial_sum 是 inclusive（含当前项）；区间查询公式要的是 exclusive。C++17 起用名字明确的 std::exclusive_scan(first, last, out, 0LL)——顺带还能显式指定累加类型，并支持 std::execution::par 并行。
  3. 基础差分数组解决什么问题？它和前缀和是什么关系？

    差分解决「多次区间加，最后统一查询」：把 O(n) 的区间修改压成 O(1) 的两点加减。

    d[l] += v; d[r+1] -= v; ← 区间 [l, r] 全加 v，O(1) 最后对 d 求一次前缀和，得到最终数组 m 次操作总代价 O(m + n)，而不是朴素的 O(m·n)
    两者互为逆运算
    a 的差分的前缀和 = a。所以它们是同一枚硬币的两面：
    · 前缀和：区间查询 O(1)，但修改要 O(n) 重建
    · 差分：区间修改 O(1)，但查询要先还原 O(n)
    生活类比
    差分像「只在门口记进出的人数」——要让 10 点到 12 点的每个人都算一次，不用给这两小时每分钟都记一笔，只在 10 点记 +1、12 点零一分记 −1。想知道任意时刻屋里多少人，把从开门到那一刻的进出累加（前缀和）即可。
    两个坑
    ① d 的长度必须是 n+1——r 可以等于 n−1，此时要写 d[n]。少留一位就是越界写，而且小数据下常常不崩（写进了容量冗余），非常隐蔽。
    ② 「O(1) 修改」的前提是所有修改都在查询之前。修改与查询交错时差分不适用，要换树状数组或线段树+懒标记。
  4. 基础为什么滑动窗口求「最大值」不能像求「和」那样加一个减一个？

    因为移出的可能正是最大值，而你不知道次大值是谁。求和时「减掉移出的元素」是精确可逆的；求最大值时，移出最大值后你手上没有任何信息能恢复出新的最大值。

    本质原因：max 没有逆元。加法可以减回来，max 不能「max 回去」。这条判据同时解释了为什么区间最值不能用前缀和（见 §4.4）。

    正解：单调队列，O(n) 摊销
    std::deque<int> dq;   // 存下标，对应值递减
for (int i = 0; i < n; ++i) {
    while (!dq.empty() && a[dq.back()] <= a[i])
        dq.pop_back();                  // ① 尾部：被支配
    dq.push_back(i);
    if (dq.front() <= i - k) dq.pop_front();  // ② 头部：过期
    if (i >= k - 1) res.push_back(a[dq.front()]);
}
    两个出口，两个不同理由
    尾部弹出（被支配）：新元素既更大、位置又更靠后 ⟹ 旧元素永远不可能再是最大值 ⟹ 永久删除。
    头部弹出（过期）：下标滑出窗口。它没被支配，只是不再有资格参赛。
    正因为有两个出口，容器必须是双端队列而不是栈。
    替代方案
    multiset（O(n log k)，但能删任意元素、能同时取最大最小）；延迟删除堆（O(n log n)，但当窗口不是定长滑动而是任意区间时反而唯一可行）。

9.2 中级（区分熟练度）

  1. 中级「和恰好为 k 的子数组个数」怎么做（数组可含负数）？有哪些必须注意的细节？

    滑动窗口在含负数时失效（和不随窗口变长单调），正解是前缀和 + 哈希表：枚举右端点 r，查「有多少个左端点 l 使 S[r] − S[l] = k」，即查 S[r] − k 出现过几次。

    int subarray_sum(const std::vector<int>& a, int k) {
    std::unordered_map<long long, int> cnt;
    cnt[0] = 1;                 // ① 空前缀
    long long S = 0; int ans = 0;
    for (int x : a) {
        S += x;
        auto it = cnt.find(S - k);
        if (it != cnt.end()) ans += it->second;   // ② 先查
        ++cnt[S];                                //    后加
    }
    return ans;
}
    ① cnt[0] = 1 是必需的
    它代表「空前缀」，对应「子数组从下标 0 开始」。漏掉它，所有以 0 开头的合法子数组都会被漏算。
    ② 必须先查后加
    如果先 ++cnt[S] 再查 S − k，那么 k = 0 时当前前缀会匹配到自己，多算一个长度为 0 的「子数组」。
    ③ 存次数而非「是否出现」
    含负数时同一个前缀和会反复出现，每次对应一个不同的左端点，必须累加次数。
    变体只需换 key/value 的语义
    · 求最长而非个数 → value 存「最早出现的下标」，且只在 key 不存在时插入（保留最早的）
    · 能被 k 整除的子数组 → key 存 ((S % k) + k) % k（负数取模要修正）
    · 0 和 1 数量相等的最长子数组 → 把 0 当 −1，转化成「和为 0」
    · 乘积为正的最长段 → 数负号个数的奇偶，转化成前缀奇偶性
    这些题的共同点是「找到一个可累加且可相减的量」——这才是前缀和题的真正技巧。
  2. 中级「柱状图中最大矩形」怎么用单调栈解？哨兵技巧解决了什么？

    关键不在单调栈，而在视角转换：不枚举矩形的左右端点（O(n²)），而是枚举「哪根柱子是矩形的高」。

    对每根柱 i：宽度上限由两侧第一个更矮的柱子决定 width = right[i] − left[i] − 1 面积 = h[i] × width 而「两侧第一个更矮」正是单调栈的标准输出 ⟹ O(n)
    int largest_rectangle(std::vector<int> h) {
    h.insert(h.begin(), 0);   // 左哨兵
    h.push_back(0);            // 右哨兵
    std::vector<int> st;         // 递增栈
    int best = 0;
    for (int i = 0; i < (int)h.size(); ++i) {
        while (!st.empty() && h[st.back()] > h[i]) {
            int top = st.back(); st.pop_back();
            best = std::max(best, h[top] * (i - st.back() - 1));
        }
        st.push_back(i);
    }
    return best;
}
    哨兵消掉了两类边界判断
    左哨兵 0：比任何柱子都矮，永不被弹出 ⟹ 栈永不为空 ⟹ st.back() 总是合法，不用判空。
    右哨兵 0：会把栈里剩下的所有柱子都弹出 ⟹ 不需要在循环后再写一段「清算剩余栈」的重复代码。
    哨兵是个通用手法
    链表题的哑头节点、区间题的 [−∞, +∞] 边界、字符串题末尾补终止符，都是同一个东西。
    识别信号：如果你在写「循环后还要再处理一遍剩余状态」，通常加个哨兵就能合并掉。
    二维推广
    「01 矩阵中全 1 的最大矩形」= 逐行把二维压成柱状图（heights[c] = g[r][c]=='1' ? heights[c]+1 : 0），每行调一次上面的函数，O(m·n)。「降维 + 复用已有解法」是二维问题的通用套路。
  3. 中级为什么区间 max 不能用前缀和？该用什么？

    因为前缀和的本质要求是运算可逆（有逆元）——只有能「减掉不要的部分」，才能用 S[r] − S[l] 还原区间。max 没有逆元：知道 max(a[0..r]) 和 max(a[0..l-1])，推不出 max(a[l..r])。

    运算有逆元？能否前缀和
    加法减法能
    异或异或自身能（最优雅，无溢出无符号问题）
    乘法（无 0）除法能，含 0 则失效
    模乘（模质数）乘逆元能
    max / min / gcd无不能
    替代方案（按需求选）
    无修改 + 要 O(1) 查询 → 稀疏表（sparse table）：O(n log n) 预处理，O(1) 查询。它利用 max 的「可重叠合并」性质——两个有重叠的区间取 max 仍正确，所以用两个长度为 2^k 的区间覆盖任意区间即可。
    有修改 → 线段树：O(n) 建、O(log n) 查改，通用但代码长。
    定长窗口滑动 → 单调队列：O(1) 摊销，但要求元素按序进出。
    为什么 gcd 能用稀疏表但不能用前缀和
    稀疏表只要求运算可结合 + 可重叠合并（idempotent），不要求可逆。gcd(gcd(x,y), gcd(y,z)) = gcd(x,y,z) 成立，所以能用。
    而求和不能用稀疏表（重叠部分会被加两次），却能用前缀和。两个结构的适用条件恰好互补——这是区间查询问题里一个很有启发的对称性。
  4. 中级扫描线解「会议室 II」，同一时刻的事件该按什么顺序处理？

    把每个会议拆成两个事件：(开始, +1) 和 (结束, −1)，排序后累加，过程中的最大值就是所需会议室数。

    for (auto& [s, e] : iv) {
    ev.emplace_back(s, +1);
    ev.emplace_back(e, -1);
}
std::sort(ev.begin(), ev.end());   // pair 字典序：同刻时 -1 排在 +1 前
int cur = 0, best = 0;
for (auto& [t, d] : ev) { cur += d; best = std::max(best, cur); }
    顺序由区间开闭语义决定
    左闭右开 [s, e)（会议时间段的常规语义）：[1,3) 与 [3,5) 不冲突 ⟹ 同刻先减后加。上面的代码靠 pair 字典序（-1 < +1）自动实现。
    闭区间 [s, e]（线段覆盖）：[1,3] 与 [3,5] 确实在点 3 相交 ⟹ 同刻先加后减，要反转排序键，或把结束时刻改成 e + 1。
    为什么这个坑难发现
    写反了只在「刚好首尾相接」的用例上错，随机测试很难命中。动手前先在纸上写清「首尾相接算不算重叠」——这是扫描线第一大坑。
    扫描线 = 排序 + 一个可增量维护的状态
    难度全在「状态用什么结构维护」：
    · 只要计数 → 一个整数（会议室）
    · 要最大值且需删任意元素 → multiset 或延迟删除堆（天际线问题）
    · 要区间覆盖长度 → 线段树（矩形面积并）
    · 要「有多少已插入值小于 x」→ 树状数组（二维数点 / 逆序对）
    识别信号：题目涉及区间 / 线段 / 事件，且答案与「某时刻的聚合状态」有关。

9.3 高级（体现深度）

  1. 高级单调队列还能优化 DP，怎么识别这类题？它和斜率优化的区别是什么？

    识别信号：DP 转移的候选区间是一个随 i 单调移动的窗口，且转移里对 j 求 max/min。

    dp[i] = max{ dp[j] + w(i) : i − k ≤ j < i } 朴素：每个 i 扫 k 个候选 → O(n·k) 观察：候选集 {i−k, …, i−1} 随 i 整体右移 ⟹ 就是「定长滑动窗口最大值」 ⟹ 单调队列 → O(n)
    // 跳跃游戏 VI：每步最多跳 k 格，求最大得分
for (int i = 1; i < n; ++i) {
    if (dq.front() < i - k) dq.pop_front();       // 过期
    dp[i] = dp[dq.front()] + a[i];                  // 队首是窗口内 dp 最大者
    while (!dq.empty() && dp[dq.back()] <= dp[i])
        dq.pop_back();                              // 被支配
    dq.push_back(i);
}
    与斜率优化的关键区别
    看转移权重能否拆成「只依赖 j 的部分」：
    单调队列适用：dp[i] = max{dp[j]} + w(i)——候选的比较只依赖 j（比 dp[j] 大小），与 i 无关。所以「谁支配谁」是绝对的，可以永久丢弃。
    斜率优化适用：dp[i] = min{dp[j] + (a[i] − a[j])²}——展开后有 −2·a[i]·a[j] 这种i 与 j 的乘积项，谁更优取决于 i。此时不能简单丢弃，要维护一个下凸壳（convex hull trick），按斜率查询。
    一句话判据
    「候选之间的优劣关系是否与 i 无关」——无关则单调队列（丢弃是永久的），有关则凸包/李超线段树（丢弃要看斜率区间）。
    这两者常被混为一谈，但复杂度都是 O(n)，区别在维护的不变式：一个是单调序列，一个是凸壳。
    还有一类：决策单调性 + 分治
    如果最优决策点 opt[i] 关于 i 单调不减（但转移不是窗口形式），可以用分治优化（divide and conquer optimization）做到 O(n log n)。这三类优化会在批次 4 的动态规划里系统对比。
  2. 高级Prometheus 的 counter 为什么设计成「只增的累计值」而不是「每个周期的增量」？

    因为 counter 就是前缀和，而 rate() 就是区间查询 S[r] − S[l]。这个设计的好处正是前缀和相对于「存增量」的好处。

    ① 抗采样丢失
    存增量时丢一个采样点就永久丢了那段数据；存累计值时丢点只影响时间精度，下一个点仍能算出正确的总量。监控系统的采集必然会偶尔失败，这一条是决定性的。
    ② 抗采样间隔变化
    采集周期从 15s 改成 30s 时，累计值的语义不变；增量的语义会变（「每 15s 多少」变成「每 30s 多少」），历史数据无法直接对比。
    ③ 客户端无状态
    只需一个原子自增，不需要维护「上次上报时刻」和窗口状态。这让客户端库极简，也避免了多线程下的窗口同步问题。
    ④ 可任意重采样
    同一份数据能算 1 分钟、5 分钟、1 小时的 rate；增量存储只能向上聚合，且聚合后无法还原更细粒度。
    代价：counter reset
    进程重启让计数归零，此时 counter(t2) − counter(t1) 变成负数。所以 rate() 的实现必须检测重置——读数下降就假定发生重启，那一段按「从 0 开始」处理。
    这就是为什么应该用 rate()/increase() 而不要手写 a - b：手写版不处理重置，会在每次发版时产生一个巨大的负值尖刺，进而触发误告警。
    同一族设计
    histogram 也存累积形式（每个 bucket 记「≤ 阈值的样本数」），这样桶可以跨实例相加后再算分位数——累积计数是可加的。代价是精度受桶边界限制，histogram_quantile 只能在桶内线性插值。想要更好精度就换 t-digest / DDSketch（用相对误差保证换 O(log 值域) 空间）。
    见 可观测性。
  3. 高级一个「查询任意时间区间内的请求量」的接口，随着数据量增长越来越慢，怎么设计？

    先定位：如果实现是「扫描原始日志表按时间过滤求和」，那复杂度是 O(区间内记录数)——数据量涨，查询必然线性变慢。这是「每次查询都重新扫一遍」的典型症状，也正是前缀和要解决的问题。

    ① 先问清查询模式
    这决定了全部方案：区间端点是否任意（还是只查「最近 N 分钟」）？需要多细的粒度（秒级还是分钟级）？写入是否还在持续（历史数据是否会变）？能接受多大误差？
    ② 历史数据不变 → 预聚合 + 前缀和
    按分钟预聚合成一张表，再对它建累计和（前缀和）。任意区间查询变成两行相减，O(1)。
    数据量从「每请求一行」降到「每分钟一行」——降了几个数量级。这是最划算的一步。
    ③ 写入持续 → 分层聚合（roll-up）
    秒级保留 1 小时、分钟级保留 7 天、小时级保留 1 年。查询时按区间长度自动选层：查最近 10 分钟用秒级，查上个月用小时级。
    这就是时序数据库（Prometheus 的 recording rules、VictoriaMetrics、InfluxDB 的 continuous query）的标准做法——不要自己造，直接用。
    ④ 需要边写边查任意区间 → 树状数组 / 线段树
    前缀和不支持高效修改（要 O(n) 重建）。修改与查询交错时，用树状数组（单点改 + 区间和查，O(log n)，代码最短）。
    「修改和查询是否交错」是这类选型的第一判据：不交错 → 前缀和 O(1)；交错 → 树状数组 O(log n)。
    ⑤ 别忽略基数问题
    如果要按维度（接口、状态码、地域）分别统计，预聚合的行数是各维度基数的乘积。维度里混进了 user_id 或 trace_id 这类高基数字段，预聚合表会比原始数据还大。
    预聚合的前提是维度组合可控——这是实践中最常翻车的地方。
    再往上一层
    如果查询的是「去重用户数」而不是「请求量」，预聚合不成立——去重计数不可加（两个小时各 100 个 UV，合起来不是 200）。此时要用 HyperLogLog：它的 sketch 可以合并，用约 1.5% 的相对误差换 O(1) 空间的可加性。
    「这个指标可加吗」决定了能不能预聚合：sum/count/min/max 可加；avg 要存 sum 和 count 分别聚合；distinct count 和分位数不可加，必须换成可合并的近似结构（HLL、t-digest）。见 Redis 与缓存。
  4. 高级「天际线问题」为什么不能只用一个整数维护当前高度？该用什么？

    因为天际线要的是当前所有活跃建筑高度的最大值，而建筑的结束顺序与开始顺序无关——一个先开始的高楼可能最后才结束。

    为什么整数不够
    会议室问题维护的是「重叠数量」，加减是可逆的，一个整数够了。天际线维护的是「高度最大值」——max 没有逆元，移除一个建筑时你无法从「当前最大值」推出「新的最大值」。
    这和 §9.1 第 4 题（窗口最大值不能加一个减一个）是同一个根因。
    为什么单调队列也不够
    单调队列要求元素按序进入、按序过期。天际线里建筑的结束时刻是任意的——先入的可能后出，所以「被支配就永久丢弃」这个论证不成立。
    方案一 · multiset（最直观）
    事件为 (x, −h) 表示开始、(x, +h) 表示结束。扫描时开始就 insert(h)、结束就 erase(find(h))（注意用 find 只删一个，直接 erase(h) 会删掉所有等于 h 的），取 *rbegin() 为当前高度。O(n log n)。
    事件排序技巧：把开始事件的高度存成负数，这样同一 x 处「先处理开始（负数小，排前面）再处理结束」，且「多个开始时高的先处理」——一次排序解决全部同刻顺序问题。
    方案二 · 延迟删除的大顶堆
    堆不支持删任意元素。做法是只入不删，取堆顶时先循环丢弃「已过期」的堆顶（用一个 unordered_map<高度, 待删次数> 或比较结束时刻判断）。
    优点是常数比 multiset 小（数组连续 vs 红黑树指针追逐）；代价是堆可能膨胀到 O(n)。
    这是「可删除堆」这一类需求
    同类问题还有：滑动窗口中位数、带删除的 Top-K、Dijkstra 的 decrease-key。通用手段有三种——① 换能删任意元素的结构（multiset、平衡树）；② 延迟删除（懒惰堆，最常用）；③ 索引堆（额外维护「元素 → 堆内位置」的映射，支持真正的 O(log n) 任意删除与 decrease-key）。
    三者的取舍见 堆与 Top-K。
