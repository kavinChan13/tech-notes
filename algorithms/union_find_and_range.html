并查集与区间结构

这一篇讲四个「为特定查询定制的结构」：并查集回答「这两个东西连通吗」，树状数组和线段树回答「这段区间的聚合值是多少」，稀疏表回答「这段区间的最值是多少」。它们的复杂度都漂亮到不像话（α(n)、log n、O(1)），而每一个漂亮背后都有一个明确的前提——搞清前提，选型就不用猜。

01

两类问题，一个动机

动机都是「别每次都重新扫一遍」

结构回答什么问题关键前提复杂度
并查集（§2）「a 和 b 在同一集合吗」
「把 a 和 b 的集合合并」		只合并、不分裂α(n)，实际 ≤ 4
树状数组（§4）「单点改 + 区间聚合查」运算可逆（有逆元）O(log n)
线段树（§5）「区间改 + 区间聚合查」运算可结合O(log n)
稀疏表（§6）「区间最值查」，不支持修改运算可重叠合并O(1) 查，O(n log n) 建
「关键前提」这一列是本篇最重要的东西。它决定了一个结构能不能用，而这比记模板重要得多：
  • 并查集只能合并不能分裂——因为路径压缩把树压平了，分裂时无法恢复原来的父子关系。要「删边」就必须离线逆向处理（§3.4）。
  • 树状数组要求可逆——它靠「前缀和相减」得到区间，所以 max/min 不能用（详见 前缀和 §4.4 的同一条判据）。
  • 线段树只要求可结合——所以它能处理 max/min/gcd，这是它比树状数组通用的地方。
  • 稀疏表要求可重叠合并（idempotent）——max(max(a,b), max(b,c)) = max(a,b,c) 成立，所以能用两个有重叠的区间覆盖任意区间；但求和不行（重叠部分会加两次）。
四个结构像四种不同的「档案索引」。

并查集像户籍合并：只记「你归哪个户口本」，两家合并就把一本的户主指向另一本。查「是不是一家人」只需比较户主。但户籍法只允许合并不允许分家——这就是它的前提。
树状数组像分层的账本汇总：底层记每日流水，上层记每周、每月小计。改一天的数只需更新它所在的几层小计。
线段树像把整个仓库切成嵌套的分区，每个分区记一个汇总值。要改「整个 3 号区」时不逐个改，而是在 3 号区门口挂一张便条（懒标记），等真有人要往里查再往下传。
稀疏表像预先算好所有「2 的幂长度」的区间最值。查任意区间时用两个可能重叠的预算结果一比——因为求最值不怕重复算。

1.1 与其他章节的关系

  • 单调栈与前缀和 —— 「可逆 / 可结合 / 可重叠」这三个判据在那里首次出现
  • 树与平衡树 —— 线段树是「为区间查询而设计的树」，不需要平衡（结构固定）
  • 复杂度与分析 —— α(n) 的证明用的是势能法
  • 最短路与最小生成树 —— Kruskal 完全建立在并查集上
  • 图遍历与拓扑排序 —— 无向图连通性可以用并查集也可以用 DFS，两者的分工
02

并查集

二十行代码，近乎常数的复杂度

2.1 朴素实现与它的问题

// 朴素版：每个集合是一棵树，根代表整个集合
std::vector<int> parent;

int find(int x) {                 // 一路往上找根
    while (parent[x] != x) x = parent[x];
    return x;
}
void unite(int a, int b) {
    parent[find(a)] = find(b);      // 一个根挂到另一个根下
}
// ❌ 问题：树可能退化成链
// unite(1,2), unite(2,3), unite(3,4), ... → 链长 n → find 是 O(n)

两个优化各自独立有效，合起来给出近乎常数的复杂度。

2.2 路径压缩

所有节点直接挂到根下 压缩前 1 2 3 5 find(5) 要走 3 步 压缩 压缩后 1 2 3 5 之后任何 find 都只需 1 步 两种写法 递归：简洁，但深度大 　　　时可能爆栈 迭代（两趟）：先找根， 再回头改指针 生产用迭代版
递归版（简洁）
int find(int x) {
    if (parent[x] != x)
        parent[x] = find(parent[x]);  // 回溯时改父指针
    return parent[x];
}
// 优雅，但递归深度 = 压缩前的路径长
// 极端情况（未按秩合并时）可能爆栈
迭代版（生产用）
int find(int x) {
    int root = x;
    while (parent[root] != root) root = parent[root];
    while (parent[x] != root) {          // 第二趟改指针
        int next = parent[x];
        parent[x] = root;
        x = next;
    }
    return root;
}
// 无递归，栈深 O(1)
还有一种路径分裂 / 路径减半的写法：parent[x] = parent[parent[x]]，一趟完成，每次把节点挂到祖父而不是根。它的渐进复杂度和完全压缩相同（仍是 α(n)），而且只需一趟、代码更短： 
int find(int x) {
    while (parent[x] != x) {
        parent[x] = parent[parent[x]];   // 路径减半
        x = parent[x];
    }
    return x;
}
竞赛里常用这个版本。三种写法渐进相同，选哪个看代码风格。

2.3 按秩合并

// 按秩（近似树高）或按大小合并：总是把小的挂到大的下面
std::vector<int> parent, sz;

bool unite(int a, int b) {
    a = find(a); b = find(b);
    if (a == b) return false;      // 已在同一集合
    if (sz[a] < sz[b]) std::swap(a, b);
    parent[b] = a;                    // 小的挂到大的下面
    sz[a] += sz[b];
    return true;                     // 返回「本次是否真的合并了」很有用
}
为什么「小挂大」能限制树高：一个节点的深度只在它所在的树被挂到别人下面时才增加 1。而按大小合并保证：树的大小每次至少翻倍才会让深度加 1。所以深度 ≤ log₂n。

unite 返回 bool 是个实用细节——「本次是否真的合并了」可以直接用来：数连通块数量（每次成功合并就减一）、判断加入这条边是否成环（Kruskal 的核心判断）、检测重复边。

2.4 α(n) 是什么

只用路径压缩： 摊销 O(log n) 只用按秩合并： 最坏 O(log n) 两者同时用： 摊销 O(α(n)) α 是反 Ackermann 函数，增长极慢： α(n) ≤ 4 对所有 n < 2^2^2^2^16 （远超宇宙原子数） ⟹ 工程上直接当常数用
α(n) 的证明用势能法（Tarjan 1975）：给每个节点定义一个势能，与它的秩和它到根的距离有关；证明每次 find 的实际代价加上势能变化不超过 O(α(n))。
这是摊销分析里势能法最著名的应用——也是「聚合法做不到、必须用势能法」的典型（操作交错、模式不规整）。

而且这个界是紧的：Fredman 和 Saks 证明了任何基于指针的并查集实现都不可能做到 O(1) 摊销。所以 α(n) 不是「还没优化到常数」，而是这个问题的真实下界。
实践中的一个常见问题：只用路径压缩、不用按秩合并，行不行？
  • 渐进上：摊销 O(log n)，比 α(n) 差但仍可接受。
  • 实践上：绝大多数情况完全够用，而且代码少一半（不用维护 sz 数组）。竞赛和面试里这样写很常见。
  • 但递归版 find 在初期（还没压缩过）可能有很深的路径 → 有爆栈风险。所以如果只用路径压缩，建议用迭代版或路径减半版。
反过来只用按秩合并不用路径压缩就没什么理由了——路径压缩几乎是免费的（find 本来就要走这条路）。

并查集的四种变形

同一个骨架，换一下「存什么」就能解不同的题

3.1 带权并查集

在 parent 之外再存一个到父节点的「权值」，路径压缩时把权值累加起来。这样就能回答「a 相对于 b 的差值/比例是多少」。

// 例：除法求值 —— 已知 a/b=2, b/c=3，问 a/c = ?
std::vector<int> parent;
std::vector<double> w;      // w[x] = x / parent[x]

int find(int x) {
    if (parent[x] == x) return x;
    int root = find(parent[x]);
    w[x] *= w[parent[x]];        // ← 关键：压缩时把权值沿路径累乘
    parent[x] = root;
    return root;
}

void unite(int a, int b, double val) {   // a / b = val
    int ra = find(a), rb = find(b);
    if (ra == rb) return;
    parent[ra] = rb;
    w[ra] = val * w[b] / w[a];   // 推导：让 a/b 仍等于 val
}
带权并查集的权值更新公式必须自己推，不能背。推导方法：写出「压缩/合并后，各个已知关系仍然成立」这个等式，解出待求的 w。
比如上面的 w[ra] = val * w[b] / w[a]：合并后 a/b 应该等于 val，而 a/b = (a/ra · ra/rb) / (b/rb) = (w[a] · w[ra]) / w[b]，令它等于 val 即得。
加法版本（差值）就把乘除换成加减。这类题的难点全在这个式子上，写错了不会崩、只会给错答案。

3.2 扩展域

并查集只能表达「同类」关系。要表达「敌对」关系（a 和 b 一定不在同一组），办法是把每个元素拆成两个「域」：

扩展域（开点两倍）：为元素 x 建立两个节点——x（表示「x 在集合 A」）和 x + n（表示「x 在集合 B」）。
  • 「a 和 b 同组」→ unite(a, b) 且 unite(a+n, b+n)。
  • 「a 和 b 敌对」→ unite(a, b+n) 且 unite(a+n, b)。
  • 矛盾检测：若 find(x) == find(x+n)，说明推出了「x 既在 A 又在 B」→ 矛盾。
典型题：判断二分图（染色）、「关押罪犯」、食物链（三个域）、「等式方程的可满足性」。
扩展域和「DFS 染色」是判二分图的两种解法，各有适用场景：
  • 并查集：只能回答「有没有矛盾」，不能直接给出染色方案。但它支持在线（边一条条来，随时能判断），且代码更短。
  • DFS/BFS 染色：能给出具体染色方案，也能处理「输出一个奇环」这类需求。但需要先建好整张图（离线）。
「在线 vs 离线」是这类问题的第一个分岔口——题目说「依次处理 m 个操作，每次都要输出答案」就得用并查集。

3.3 可撤销与可持久化

路径压缩和「撤销」是不兼容的。压缩把路径上所有节点直接挂到根，原来的父子关系永久丢失——没法回滚。

所以可撤销并查集必须放弃路径压缩，只用按秩合并（最坏 O(log n)），并用一个栈记录每次 unite 改了哪些位置： 
// 可撤销：只按秩合并，不压缩
std::vector<std::pair<int, int>> history;   // (被改的节点, 旧值)

bool unite(int a, int b) {
    a = find(a); b = find(b);          // find 里不做压缩
    if (a == b) { history.push_back({-1, -1}); return false; }
    if (sz[a] < sz[b]) std::swap(a, b);
    history.push_back({b, sz[a]});       // 记下要恢复什么
    parent[b] = a; sz[a] += sz[b];
    return true;
}
void rollback() {
    auto [b, old_sz] = history.back(); history.pop_back();
    if (b == -1) return;
    sz[parent[b]] = old_sz;
    parent[b] = b;
}
用途：线段树分治（把「边在某段时间存在」的问题转成一棵时间线段树，DFS 时加边、回溯时撤销）、动态图连通性的离线算法。

3.4 离线与逆向处理

并查集不支持删除（分裂集合）。经典的绕法是把时间倒过来：

逆向处理：题目要求「依次删除节点/边，每次输出连通块数量」。删除是并查集做不到的，但把操作序列反转后，删除就变成了添加。

做法：先把所有删除操作读完（离线），得到最终状态；从最终状态开始，逆序把删掉的东西加回去，每次用并查集合并；最后把答案数组反转输出。

典型题：「打砖块」（Bricks Falling When Hit）、「移除最多的同行同列石头」、离线的动态连通性。
这个技巧像倒放拆迁录像。你想知道「每拆一栋楼后还剩几个连通的小区」——拆楼是分裂，很难算。但把录像倒着放，拆楼就变成了盖楼，盖楼就是合并，并查集立刻能算。

算完所有帧的答案，再把答案序列反转回来，就是正放时每一帧的答案。前提是你能先看完整段录像（离线）——这也是这个技巧的唯一限制。

4.2 单点改 + 区间查

struct BIT {
    std::vector<long long> t;
    int n;
    BIT(int n) : t(n + 1, 0), n(n) {}      // 1-based，下标 0 不用

    void add(int i, long long v) {           // a[i] += v
        for (; i <= n; i += i & -i) t[i] += v;
    }
    long long prefix(int i) const {         // a[1..i] 的和
        long long s = 0;
        for (; i > 0; i -= i & -i) s += t[i];
        return s;
    }
    long long range(int l, int r) const {    // a[l..r] 的和
        return prefix(r) - prefix(l - 1);   // ← 依赖可逆性
    }
};
// 建树也可以 O(n)：先直接填 t[i]=a[i]，再 for i: t[i+lowbit(i)] += t[i]
树状数组必须 1-based，因为 lowbit(0) = 0 会让循环死掉。用 0-based 下标传进来时记得 +1。这是最高频的实现 bug。

另外注意 range(l, r) 用了 prefix(r) - prefix(l-1)——这依赖运算可逆。所以：
  • 加法、异或 → 可以
  • max / min → 不行（虽然有「BIT 求前缀 max」的变体，但它只支持前缀查询和「值只增大」的更新，不支持任意区间和任意更新）
要区间最值就用线段树或稀疏表。这是「可逆」这个判据的直接后果。

这个「两个 BIT」的技巧值得记住，因为它让树状数组能覆盖线段树的绝大多数常见用途，而代码量只有线段树的四分之一。
树状数组 vs 线段树的实际选型：
  • 只做和（或其他可逆运算）的区间操作 → 树状数组，代码短、常数小（约快 2–3 倍）。
  • 需要 max/min/gcd、或需要复杂的懒标记（区间赋值、区间乘）、或需要「线段树上二分」→ 线段树。
竞赛里的经验：能用 BIT 就用 BIT。

4.4 值域 BIT 与二维

把 BIT 的下标从「位置」换成「值」，它就能回答「已插入的元素中有多少个 ≤ x」——这是求逆序对、动态第 k 小的标准手段。

// 求逆序对：从右往左扫，每次查「已插入的比当前小的个数」
long long count_inversions(std::vector<int> a) {
    // ① 离散化：把值映射到 1..m（BIT 大小受值域限制，必须先压缩）
    std::vector<int> s = a;
    std::sort(s.begin(), s.end());
    s.erase(std::unique(s.begin(), s.end()), s.end());
    for (int& x : a)
        x = (int)(std::lower_bound(s.begin(), s.end(), x) - s.begin()) + 1;

    BIT bit((int)s.size());
    long long ans = 0;
    for (int i = (int)a.size() - 1; i >= 0; --i) {
        ans += bit.prefix(a[i] - 1);   // 右边有多少个严格小于 a[i]
        bit.add(a[i], 1);
    }
    return ans;
}
这和归并排序求逆序对是同一问题的两种解法：归并版不需要离散化、常数更小；BIT 版需要离散化，但更容易扩展成「在线查询」「三元逆序对」「二维数点」。
离散化是值域 BIT 的必备前置步骤——BIT 的大小等于值域，值域是 10⁹ 时必须先压缩到 O(n)。忘记离散化是这类题的第一大坑。
05

线段树

通用但代码长；懒标记是它的灵魂

5.1 建树与查询

线段树是一棵「区间的二叉树」：根管 [1, n]，每个节点把自己的区间对半分给两个孩子，叶子管单个元素。每个节点存它所管区间的聚合值。

它只要求运算可结合（merge(merge(a,b), c) = merge(a, merge(b,c))），不要求可逆——所以能处理 max、min、gcd、区间赋值等树状数组做不到的操作。

用数组存（下标 1 开始，左孩子 2i、右孩子 2i+1）时，数组要开 4n——因为 n 不是 2 的幂时最底层可能错开，2n 不够。这是最常见的 RE 原因。
struct SegTree {
    int n;
    std::vector<long long> t;

    SegTree(const std::vector<long long>& a)
        : n((int)a.size()), t(4 * a.size()) {   // ← 4n，不是 2n
        build(1, 0, n - 1, a);
    }
    void build(int p, int l, int r, const std::vector<long long>& a) {
        if (l == r) { t[p] = a[l]; return; }
        int m = l + (r - l) / 2;
        build(2*p, l, m, a);
        build(2*p+1, m+1, r, a);
        t[p] = t[2*p] + t[2*p+1];         // pull up
    }
    long long query(int p, int l, int r, int ql, int qr) {
        if (qr < l || r < ql) return 0;        // 完全不相交
        if (ql <= l && r <= qr) return t[p];    // 完全被包含 → 直接用
        int m = l + (r - l) / 2;
        return query(2*p, l, m, ql, qr)
             + query(2*p+1, m+1, r, ql, qr);
    }
};
为什么查询是 O(log n)：任意查询区间 [ql, qr] 在线段树上最多被拆成 O(log n) 个「完全被包含」的节点。
证明要点：在每一层上，最多有 2 个节点是「部分相交」的（左边界所在的和右边界所在的）；部分相交的节点才需要继续往下递归。所以每层最多递归 2 个节点，共 log n 层 → O(log n)。

5.2 懒标记

区间修改如果真的去改每个叶子，就是 O(n)。懒标记（lazy propagation）的思路是：改到「完全被包含」的节点就停下，在那里挂一张便条，等真有人要往下查再传下去。

停在完全被覆盖的节点，打标记 [0,7] sum+=12 [0,3] sum+=6 [4,7] sum+=6 [0,1] [2,3] lazy=3 [4,5] lazy=3 [6,7] ↓ 孩子不动 ↓ 孩子不动 节点自己的 sum 立刻更新（因为查询可能直接命中它）；孩子只记一张便条（lazy）。 下次要递归进这个节点时先 push_down：把 lazy 应用到两个孩子、清空自己的 lazy。修改与查询都变 O(log n)。 
// 区间加 + 区间求和（带懒标记）
std::vector<long long> t, lazy;

void apply(int p, int l, int r, long long v) {
    t[p]    += v * (r - l + 1);   // 区间和：要乘区间长度
    lazy[p] += v;
}
void push_down(int p, int l, int r) {
    if (lazy[p] == 0) return;
    int m = l + (r - l) / 2;
    apply(2*p, l, m, lazy[p]);
    apply(2*p+1, m+1, r, lazy[p]);
    lazy[p] = 0;                   // 清空
}
void update(int p, int l, int r, int ql, int qr, long long v) {
    if (qr < l || r < ql) return;
    if (ql <= l && r <= qr) { apply(p, l, r, v); return; }  // 停在这里
    push_down(p, l, r);                                     // 要往下走 → 先结清
    int m = l + (r - l) / 2;
    update(2*p, l, m, ql, qr, v);
    update(2*p+1, m+1, r, ql, qr, v);
    t[p] = t[2*p] + t[2*p+1];
}
懒标记的四个高频坑：
  • 忘记在 query 里也 push_down。查询要往下递归时同样必须先结清欠账，否则读到过期的值。
  • apply 里忘了乘区间长度。区间加 v 对「区间和」的影响是 v × 长度，不是 v。（对「区间最值」则是 +v，不乘。）
  • 多种标记共存时顺序错。同时有「区间赋值」和「区间加」时，赋值会覆盖之前的加——apply 里必须先处理赋值标记再处理加标记，且打赋值标记时要清掉已有的加标记。这是线段树最容易写错的地方。
  • 标记不满足「可合并」。懒标记要求「两次修改可以合成一个标记」。区间加可以（v1+v2）；「区间开平方」不行——这类操作要用势能线段树（暴力递归到叶子，靠「每个元素最多被开几次」来保证总复杂度）。

5.4 线段树上二分

这是线段树能做而树状数组不能的一类操作：在 O(log n) 内找到「满足某条件的第一个位置」，而不是 O(log²n)（二分 + 每次查询）。

// 找第一个前缀和 ≥ target 的位置（要求元素非负）
int find_first(int p, int l, int r, long long target) {
    if (t[p] < target) return -1;      // 整个子树都不够
    if (l == r) return l;
    push_down(p, l, r);
    int m = l + (r - l) / 2;
    // 关键：先看左子树够不够，够就只进左边（不需要两边都走）
    if (t[2*p] >= target) return find_first(2*p, l, m, target);
    return find_first(2*p+1, m+1, r, target - t[2*p]);
}
// O(log n) 而不是 O(log²n)：只走一条路径
为什么这比「二分 + 区间查询」快一个 log：朴素做法是在外面二分位置，每次调一次 O(log n) 的 query → O(log²n)。
而「线段树上二分」把二分的决策直接放进树的下降过程里——每到一个节点，用左孩子的聚合值一次比较就决定往哪边走，全程只走一条根到叶的路径。

「把外层的二分融进结构自身的下降过程」是个通用技巧，同样适用于树状数组（用 lowbit 从高位往低位试）、可持久化线段树（求区间第 k 小）、以及平衡树（求排名）。

稀疏表

O(1) 查区间最值，代价是不支持修改

6.1 可重叠合并

// st[k][i] = 区间 [i, i + 2^k − 1] 的最大值
int st[LOG][N], lg[N];

void build(const std::vector<int>& a) {
    int n = (int)a.size();
    lg[1] = 0;
    for (int i = 2; i <= n; ++i) lg[i] = lg[i / 2] + 1;
    for (int i = 0; i < n; ++i) st[0][i] = a[i];
    for (int k = 1; (1 << k) <= n; ++k)
        for (int i = 0; i + (1 << k) <= n; ++i)
            st[k][i] = std::max(st[k-1][i], st[k-1][i + (1 << (k-1))]);
}

int query(int l, int r) {          // O(1)
    int k = lg[r - l + 1];
    // 用两个长度为 2^k 的区间覆盖 [l,r]，它们可能重叠
    return std::max(st[k][l], st[k][r - (1 << k) + 1]);
}
「可重叠合并」（idempotent）是稀疏表的唯一前提：max(max(a,b), max(b,c)) = max(a,b,c) —— 重复计算 b 不影响结果。

所以查询时可以偷懒：不精确拆分区间，而是用两个长度都是 2^k 的区间去「盖住」[l, r]，允许它们在中间重叠。这样只需两次查表，O(1)。

而求和不满足这个性质——重叠部分会被加两次。所以稀疏表不能求区间和。
运算可重叠合并？能用稀疏表？
max / min是能
gcd / lcm是能
按位与 / 按位或是能
加法 / 求和否（重叠会加两次）不能
异或否（重叠会抵消）不能

6.2 三者适用条件的对称性

不支持修改 线段树 要求：仅需可结合 ✓ 上面全部都行 因为它精确拆分区间， 既不减也不重叠 O(log n) 查改，支持懒标记 代价：代码最长、常数最大
这三个结构像三种不同的「盘点方式」。
前缀和是累计台账：想知道某段的总额，用两个时间点的余额相减。前提是账目能相减。
稀疏表是预先按 2、4、8、16 天为单位记好每段的最高气温。想知道任意一段的最高温，找两段能盖住它的即可——重复统计几天不影响「最高」。
线段树是把整年切成嵌套的区间树，精确拆分不重叠。所以它什么都能算，代价是每次要走 log n 层。

有意思的是：前缀和能算的（求和）稀疏表算不了，稀疏表能算的（最值）前缀和算不了——两者的适用范围恰好互补，而线段树覆盖两者。

  1. 基础写一个并查集，说明两个优化各自解决什么问题。 
    struct DSU {
    std::vector<int> p, sz;
    DSU(int n) : p(n), sz(n, 1) { for (int i = 0; i < n; ++i) p[i] = i; }

    int find(int x) {                    // 路径减半（一趟，无递归）
        while (p[x] != x) { p[x] = p[p[x]]; x = p[x]; }
        return x;
    }
    bool unite(int a, int b) {           // 按大小合并
        a = find(a); b = find(b);
        if (a == b) return false;
        if (sz[a] < sz[b]) std::swap(a, b);
        p[b] = a; sz[a] += sz[b];
        return true;                        // 「本次是否真的合并了」
    }
};
    朴素版的问题
    unite(1,2), unite(2,3), unite(3,4)… 会把树变成一条链 → find 退化到 O(n)。
    路径压缩
    find 时顺便把路径上的节点直接挂到根下。它的妙处是查询本身在优化数据结构——下次查同一条路径只需 1 步。单独用可得摊销 O(log n)。
    按秩 / 按大小合并
    总是把小的挂到大的下面。一个节点的深度只在它所在的树被挂到别人下面时才 +1，而按大小合并保证「树大小至少翻倍才会让深度 +1」⟹ 深度 ≤ log₂n。单独用可得最坏 O(log n)。
    两者同时用 → α(n)
    α 是反 Ackermann 函数，对所有现实的 n（哪怕 2^2^2^2^16）都 ≤ 4，工程上直接当常数。
    证明用势能法（Tarjan 1975），而且这个界是紧的——Fredman 和 Saks 证明了任何基于指针的实现都不可能做到 O(1) 摊销。所以 α(n) 不是「还没优化到常数」，而是真实下界。
    实践建议
    只用路径压缩、不用按秩合并，绝大多数情况完全够用（摊销 O(log n)），而且代码少一半。但这时 find 要用迭代版或路径减半版——递归版在还没压缩过的深路径上有爆栈风险。
  2. 基础树状数组的 lowbit 是什么？为什么两个操作都是 O(log n)？
    lowbit(i) = i & (−i) 取出 i 的二进制最低位的 1 6 = 0110 → lowbit = 0010 = 2 8 = 1000 → lowbit = 1000 = 8 结构 tree[i] 管辖 a[i − lowbit(i) + 1 .. i]，共 lowbit(i) 个元素
    void add(int i, long long v) { for (; i <= n; i += i & -i) t[i] += v; }
long long prefix(int i) { long long s=0; for (; i>0; i -= i & -i) s += t[i]; return s; }
    为什么是 O(log n)
    查询：i -= lowbit(i) 每次消掉 i 的一个二进制 1，而 i 最多有 log n 个 1 → 最多 log n 步（7→6→4→0）。
    更新：i += lowbit(i) 每次让最低位的 1 向高位进位，最多 log n 步就超出 n（3→4→8→16）。
    必须 1-based
    lowbit(0) = 0 ⟹ 用 0-based 会死循环。外部传 0-based 下标时记得 +1。这是最高频的实现 bug。
    依赖运算可逆
    range(l,r) = prefix(r) − prefix(l−1) 要求运算有逆元。加法、异或可以；max/min 不行（虽有「BIT 求前缀 max」的变体，但它只支持前缀查询且更新只能让值增大）。要区间最值就换线段树或稀疏表。
    建树也能 O(n)
    不必调 n 次 add（那是 O(n log n)）。先直接 t[i] = a[i]，再 for i: if (i + lowbit(i) <= n) t[i + lowbit(i)] += t[i]。
  3. 基础线段树和树状数组该怎么选？

    两个问题就能定：

    ① 修改和查询是否交错？
    不交错（先全改再全查，或根本不改）→ 用前缀和 / 差分 / 稀疏表，O(1)，代码 3 行。这一步经常被跳过，直接上线段树是过度设计。
    交错 → 树状数组或线段树，O(log n)。
    ② 运算有什么性质？
    可逆（加法、异或）→ 树状数组：代码 10 行、常数快 2–3 倍。
    只可结合（max / min / gcd / 区间赋值 / 区间乘）→ 线段树。
    「能用 BIT 就用 BIT」
    配上差分技巧，树状数组能覆盖八成常见需求：
    · 单点改 + 区间和 → 1 个 BIT
    · 区间改 + 单点查 → 1 个 BIT 维护差分数组
    · 区间改 + 区间查 → 2 个 BIT（一个存 d[j]，一个存 j·d[j]）
    而代码量只有线段树的四分之一。
    线段树独有的能力
    ① max/min/gcd 等不可逆运算；② 复杂懒标记（区间赋值 + 区间加共存）；③ 线段树上二分——O(log n) 找「第一个满足条件的位置」，而不是 O(log²n)；④ 动态开点、可持久化、线段树合并等高级变体。
    线段树的两个必踩坑
    数组要开 4n（不是 2n，n 非 2 的幂时会越界）；query 里也要 push_down（凡是往下递归就要先结清懒标记）。
  4. 基础为什么区间 max 不能用前缀和，但可以用稀疏表？

    因为两个结构要求的性质不同，而且恰好互补。

    前缀和要求「可逆」
    它靠 S[r] − S[l−1] 得到区间值，也就是「减掉不要的部分」。max 没有逆元——知道 max(a[0..r]) 和 max(a[0..l−1])，推不出 max(a[l..r])。
    稀疏表要求「可重叠合并」
    max(max(a,b), max(b,c)) = max(a,b,c) —— 重复计算 b 不影响结果。
    所以查询时可以偷懒：用两个长度都是 2^k 的区间去「盖住」 [l,r]，允许中间重叠，只需两次查表 → O(1)。
    int k = lg[r - l + 1];
return std::max(st[k][l], st[k][r - (1 << k) + 1]);
    反过来：稀疏表不能求和
    重叠部分会被加两次。异或也不行（重叠会抵消）。
    三者构成一个漂亮的对称
    要求能力
    前缀和 / BIT可逆加、异或、乘
    稀疏表可重叠合并max、min、gcd、与、或
    线段树仅需可结合以上全部
    要求依次放宽，能力依次增强，代价（代码量、常数）也依次增大。
    前缀和能算的稀疏表算不了，稀疏表能算的前缀和算不了——两者恰好互补，而线段树覆盖两者。
    但稀疏表不支持修改
    O(n log n) 预处理、O(1) 查询，但任何修改都要整体重建。要修改就只能线段树。

9.2 中级（区分熟练度）

  1. 中级什么是懒标记？它有哪些必须注意的地方？

    区间修改如果真去改每个叶子就是 O(n)。懒标记的思路是：改到「完全被查询区间覆盖」的节点就停下，在那里挂一张便条，等真有人要往下走再传下去。

    核心不变式
    节点自己的聚合值立刻正确（因为查询可能直接命中它），孩子的值「欠着」——等被访问时才结清。
    void apply(int p, int l, int r, long long v) {
    t[p] += v * (r - l + 1);   // 区间和要乘长度；最值则不乘
    lazy[p] += v;
}
void push_down(int p, int l, int r) {
    if (!lazy[p]) return;
    int m = l + (r-l)/2;
    apply(2*p, l, m, lazy[p]);
    apply(2*p+1, m+1, r, lazy[p]);
    lazy[p] = 0;
}

    四个高频坑：

    ① query 里也要 push_down
    查询要往下递归时同样必须先结清欠账，否则读到过期值。只在 update 里 push_down 是最常见的错。
    ② apply 忘乘区间长度
    区间加 v 对「区间和」的影响是 v × 长度；对「区间最值」是 +v（不乘）。改聚合类型时容易忘改这里。
    ③ 多种标记共存时顺序错
    同时有「区间赋值」和「区间加」时，赋值会覆盖之前的加。apply 里必须先处理赋值再处理加，且打赋值标记时要清掉已有的加标记。这是线段树最容易写错的地方。
    ④ 标记必须「可合并」
    懒标记要求「两次修改能合成一个标记」。区间加可以（v1+v2）；「区间开平方」不行——这类操作要用势能线段树：暴力递归到叶子，靠「每个元素最多被开 log log 次就变成 1」来保证总复杂度。
  2. 中级怎么用树状数组求逆序对？和归并排序的做法比有什么区别？

    把 BIT 的下标从「位置」换成「值」，它就能回答「已插入的元素中有多少个 ≤ x」。

    // ① 离散化（必须！BIT 大小 = 值域）
std::vector<int> s = a;
std::sort(s.begin(), s.end());
s.erase(std::unique(s.begin(), s.end()), s.end());
for (int& x : a)
    x = lower_bound(s.begin(), s.end(), x) - s.begin() + 1;

// ② 从右往左扫，查「右边有多少个严格小于当前值」
BIT bit(s.size());
long long ans = 0;
for (int i = n - 1; i >= 0; --i) {
    ans += bit.prefix(a[i] - 1);
    bit.add(a[i], 1);
}
    离散化是必备前置
    BIT 的大小等于值域。值域 10⁹ 时不离散化直接 MLE。忘记离散化是这类题的第一大坑。
    归并排序版BIT 版
    复杂度O(n log n)O(n log n)
    需要离散化否是
    常数更小稍大
    支持在线查询否是
    扩展性三元逆序对较难易扩展（二维数点、动态第 k 小）
    为什么 BIT 版更好扩展
    它把问题变成了「维护一个可查询的值域计数结构」，而这个抽象很容易叠加维度：
    · 二维数点：按一维排序（扫描线），另一维用 BIT
    · 动态第 k 小：在权值 BIT 上做「BIT 上二分」（从高位往低位试 lowbit）
    · 区间第 k 小：换成可持久化线段树（主席树）
    归并版是「一次性算完」的，加不了这些。
  3. 中级并查集能删边吗？如果题目要求「依次删除边，每次输出连通块数」怎么做？

    不能。路径压缩把路径上所有节点直接挂到根，原来的父子关系永久丢失——没法分裂。而且即使不压缩，「从一个集合里拆出一部分」本身就不是并查集能表达的操作。

    标准绕法：离线 + 逆向处理
    把时间倒过来——删除就变成了添加。
    ① 先读完所有删除操作（离线），得到最终状态的图；
    ② 从最终状态开始，逆序把删掉的边加回去，每次用并查集合并并记录答案；
    ③ 把答案数组反转输出。
    类比
    像倒放拆迁录像：拆楼是分裂（难算），倒着放就变成盖楼（合并，并查集擅长）。算完所有帧再把答案序列反转回来。
    唯一限制是必须能先看完整段录像（离线）。
    典型题
    「打砖块」（Bricks Falling When Hit）、「移除最多的同行同列石头」、各种离线动态连通性。
    必须在线怎么办
    ① 可撤销并查集 + 线段树分治：把「边在时间段 [l,r] 内存在」挂到一棵时间线段树上，DFS 时加边、回溯时撤销。注意可撤销版必须放弃路径压缩（只按秩合并，O(log n)），因为压缩不可逆。
    ② LCT（Link-Cut Tree）：真正支持在线加删边的动态树，O(log n) 摊销。但代码 200+ 行且极易写错——面试里能说出它的名字和适用范围就够了，不必现场写。
    ③ 如果只需判断连通性而非计数，有基于欧拉回路树（ET-tree）的方案。
  4. 中级什么是扩展域并查集？用它判二分图和 DFS 染色各有什么优劣？

    并查集只能表达「同类」关系。要表达「敌对」（a 和 b 一定不在同一组），做法是把每个元素拆成两个域。

    扩展域（开两倍点）
    为元素 x 建两个节点：x（「x 在集合 A」）和 x+n（「x 在集合 B」）。
    · 「a 与 b 同组」→ unite(a, b) 且 unite(a+n, b+n)
    · 「a 与 b 敌对」→ unite(a, b+n) 且 unite(a+n, b)
    · 矛盾检测：若 find(x) == find(x+n)，说明推出「x 既在 A 又在 B」→ 矛盾

    典型题：判二分图、关押罪犯、食物链（三个域）、等式方程的可满足性。

    扩展域并查集DFS / BFS 染色
    能否给出染色方案否（只答有无矛盾）能
    能否输出一个奇环否能
    在线处理支持（边一条条来，随时可判）需要先建好整图
    代码量更短中等
    「在线 vs 离线」是这类问题的第一个分岔口
    题目说「依次处理 m 个操作，每次都要输出答案」→ 必须并查集。
    题目说「给定一张图，判断/输出方案」→ DFS 染色更合适。
    读题时先找这个信号，比纠结「哪个算法更好」有用。
    相关变形：带权并查集
    「敌对」是二元关系，如果关系是「a 比 b 大 3」这类数值关系，就用带权并查集：额外存「到父节点的权值」，路径压缩时沿路径累加。
    权值更新公式必须自己推（写出「压缩后已知关系仍成立」的等式解出来），不能背——写错不会崩，只会给错答案。

9.3 高级（体现深度）

  1. 高级什么是「线段树上二分」？为什么它比「二分 + 区间查询」快一个 log？

    需求：找「第一个使某条件成立的位置」，比如「第一个前缀和 ≥ target 的下标」。

    朴素做法：O(log²n)
    在外面二分位置，每次调一次 O(log n) 的 query 验证 → log n × log n。
    线段树上二分：O(log n)
    把二分的决策直接放进树的下降过程里：
    int find_first(int p, int l, int r, long long target) {
    if (t[p] < target) return -1;   // 整个子树都不够
    if (l == r) return l;
    push_down(p, l, r);
    int m = l + (r-l)/2;
    // 用左子树的聚合值一次比较就决定往哪边走
    if (t[2*p] >= target) return find_first(2*p, l, m, target);
    return find_first(2*p+1, m+1, r, target - t[2*p]);
}
    全程只走一条根到叶的路径——每层只做一次比较、只递归一个孩子。
    这是个通用技巧
    「把外层的二分融进结构自身的下降过程」，同样适用于：
    · 树状数组上二分：从最高位的 lowbit 往低位试，O(log n) 求「第 k 小」
    · 可持久化线段树：求「区间第 k 小」（比较两个版本的左子树计数差）
    · 平衡树：维护子树大小后求排名 / 第 k 大
    · Trie：求「与 x 异或最大的数」（每层贪心选相反位）

    共同特征是：结构的每个节点都存着足够的聚合信息，让你一次比较就能排除一半。识别出这个模式，很多 O(log²n) 的解法都能降一个 log。
    前提
    要求「聚合值关于位置单调」或至少「能从左子树的聚合值判断答案在哪边」。前缀和要求元素非负；求第 k 小要求权值线段树的计数天然非负。前提不满足时这个技巧不适用。
  2. 高级为什么可撤销并查集必须放弃路径压缩？有什么替代方案？

    路径压缩和撤销在本质上不兼容：压缩把路径上所有节点直接挂到根，原来的父子关系永久丢失。要撤销就得记下「改了哪些节点的父指针以及原值」——而一次 find 可能改 O(log n) 甚至更多个节点，且这些修改和后续的 unite 交织在一起，无法干净地按操作回滚。

    可撤销版的做法：只按秩合并
    放弃压缩 ⟹ 最坏 O(log n)（而非 α(n)）。用一个栈记录每次 unite 改了什么：
    bool unite(int a, int b) {
    a = find(a); b = find(b);   // find 里不压缩
    if (a == b) { history.push_back({-1,-1}); return false; }
    if (sz[a] < sz[b]) std::swap(a, b);
    history.push_back({b, sz[a]});   // 记下要恢复什么
    p[b] = a; sz[a] += sz[b];
    return true;
}
void rollback() {
    auto [b, old] = history.back(); history.pop_back();
    if (b == -1) return;
    sz[p[b]] = old; p[b] = b;
}
    注意即使 unite 什么都没做（已在同一集合）也要压一条空记录，否则 rollback 次数会对不上。
    主要用途：线段树分治
    处理「边只在时间段 [l,r] 内存在」的问题：把每条边挂到时间线段树对应的 O(log T) 个节点上，然后 DFS 整棵时间树——进入节点时加边，回溯时撤销。每条边最多被加/撤 O(log T) 次，总复杂度 O(m log T log n)。
    这解决了一大类「动态图连通性」的离线问题。
    其他方案
    LCT（Link-Cut Tree）：真正在线支持加删边，O(log n) 摊销。但代码 200+ 行、极易写错。
    离线逆向处理：如果操作只有删除（没有交错的加删），直接倒过来处理，删除变添加，可以用完整的压缩 + 按秩合并（α(n)）。这是最优先考虑的方案——先看能不能离线。
    一般化的教训
    「优化」和「可回滚」常常冲突，因为优化往往通过丢弃冗余信息换性能，而回滚需要那些信息。
    同类现象：数据库的就地更新 vs MVCC（保留旧版本才能回滚/快照）、压缩存储 vs 随机访问、路径压缩 vs 可撤销。设计时如果知道将来要回滚，就得在一开始留出信息，而不是事后补。
  3. 高级一个「实时统计任意时间区间内的指标聚合」的服务，用什么结构？

    先问三个问题，它们决定全部方案：指标可加吗？修改和查询是否交错？区间端点任意还是只查最近 N 分钟？

    ① 历史数据不变 → 预聚合 + 前缀和
    按分钟预聚合，再对它建累计和。任意区间查询变成两行相减，O(1)。数据量从「每请求一行」降到「每分钟一行」，降几个数量级。
    这一步收益最大，而且是时序数据库（Prometheus recording rules、VictoriaMetrics）的标准做法——不要自己造。
    ② 边写边查任意区间 → 树状数组
    前缀和不支持高效修改（要 O(n) 重建）。修改与查询交错时用 BIT：单点改 + 区间和查，O(log n)，代码 10 行。
    如果还要「区间批量修改」（如补数据、修正历史），用两个 BIT（差分套 BIT）。
    ③ 但先确认指标可加
    sum / count / min / max 可加 → 能预聚合、能用 BIT/线段树。
    avg 要拆 → 分别聚合 sum 和 count，查询时再除。
    distinct count 和分位数不可加 → 必须换成可合并的近似结构：HyperLogLog（去重计数，~1.5% 相对误差）、t-digest / DDSketch（分位数）。
    「这个指标可加吗」决定整个方案的形态，应该在第一步就问。
    ④ 别忽略维度基数
    要按维度（接口、状态码、地域）分别统计时，预聚合的行数是各维度基数的乘积。混进 user_id / trace_id 这类高基数字段，预聚合表会比原始数据还大。
    预聚合的前提是维度组合可控——这是实践中最常翻车的地方。
    ⑤ 分层聚合是工程上的标准答案
    秒级保留 1 小时、分钟级保留 7 天、小时级保留 1 年；查询时按区间长度自动选层。
    这比「用一个精巧的数据结构」更重要——存储分层解决的是数据量问题，数据结构解决的是单次查询效率问题，前者的收益通常大一个数量级。面试时先说分层再说 BIT，顺序反了会显得只看到局部。
  4. 高级你要实现一个区间结构，怎么保证它是对的？

    区间结构（尤其是带懒标记的线段树）是典型的「能跑但安静地错」的代码——一半的 bug 不会崩，只会给出错误结果。所以正确性保障必须是主动的。

    ① 暴力对拍（最有效，不是可选项）
    写一个 O(n) 的暴力实现（直接循环改/查数组），然后：
    for (int test = 0; test < 10000; ++test) {
    int n = rand() % 20 + 1;        // 小数据才能暴力
    // 随机 100 次操作，每次都比对两边结果
}
    小 n 是关键——边界 bug（4n 越界、push_down 漏掉、区间端点）在 n=1,2,3 时最容易暴露，而大数据反而掩盖问题。
    ② 写下前提并断言
    本篇有三类「前提不满足却硬用」的错误，代码能跑但结果错：稀疏表求和、BIT 求 max、压缩后想撤销。
    动手前明确写出：这个运算可逆吗？可重叠合并吗？修改与查询交错吗？把答案写成注释放在结构定义旁边。
    ③ 不变式检查函数（debug 构建）
    写一个 verify()：递归检查每个节点的聚合值是否等于两个孩子的合并、懒标记是否与实际值一致。在每次操作后调用（只在 #ifndef NDEBUG 下）。
    这能把「哪一步开始出错」定位到具体操作，而对拍只能告诉你「结果不对」。
    ④ 覆盖这些具体边界
    n=1；查询单点（l==r）；查询整个区间；查询空区间；区间左端=右端；操作序列里连续多次修改同一区间；先改后查同一区间（专门测 push_down）；懒标记叠加多次后再查。
    ⑤ 工程上还要考虑
    溢出：聚合值一律 long long，并用 -fsanitize=undefined 抓有符号溢出。
    越界：-fsanitize=address 能直接抓到「线段树只开 2n」这类问题。
    把对拍挂进 CI：区间结构的正确性依赖大量边界组合，一次性测过不代表以后改动还对。
    见 Sanitizers 实战。
