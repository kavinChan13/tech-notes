复杂度与分析

渐进复杂度是一门把实现细节和硬件差异全部抹掉的语言，它让「哪个算法更好」变成一个可以在纸上回答的问题。但它抹掉的东西不是不存在——同样是 O(n) 的遍历，链表能比数组慢一个数量级。这一篇既要把定义、摊销、主定理讲到能证明的程度，也要讲清楚渐进符号沉默的地方藏着什么。

核心难度 ★★★☆☆ 面试出现率 极高 阅读时长 ~30 min 前置 无

01

为什么需要渐进分析

从「跑得快」到「可比较」

「这个算法快不快」取决于 CPU、编译器、输入和 cache，没法拿实测数字比较算法本身。渐进分析只问输入翻倍时工作量怎么变：丢掉常数和低阶项，换来跨机器都成立的结论。这个取舍贯穿全章——§2–§6 用它在纸上比较算法，§7 再把被抹掉的常数和 cache 捡回来。同一份 O(n) 遍历，链表能比数组慢一个数量级，那不是渐进分析错了，是它根本没声称自己管这件事。

像搬家按箱数报价，不写「哪个师傅快 15%」。O(n) 是按箱线性计费，O(n²) 是每箱都要和其他箱对一遍清单——1000 箱时后者必炸。§7 的常数因子则是报价单没写的那句：有没有电梯，同样箱数差十倍。

1.1 与其他章节的关系

  • 递归与分治 —— 本章 §5 的主定理正是分治复杂度的求解工具
  • 排序全景 —— 比较排序的 Ω(n log n) 下界要用到本章 §2 的 Ω 记号
  • 二分查找 —— O(log n) 的典型来源，也是主定理情形二的例子
  • STL 容器深度剖析 —— 各容器的复杂度承诺与迭代器失效
  • 性能优化指南 —— §7 的常数因子问题在这里有完整的测量方法论
02

五个记号的严格定义

O 是上界，不是「就是」

2.1 定义与直觉

五个记号描述的是 n→∞ 时两个函数的相对增长速度。前缀「∃ c, n₀」就是「忽略常数、只看足够大的 n」。工程习惯写 f = O(g)，但等号是单向的：3n+7 = O(n²) 成立，反过来说就不成立——O(n²) 是一个函数集合。

O(g) 上界（≤） ∃ c>0, n₀, ∀ n≥n₀: f(n) ≤ c·g(n) Ω(g) 下界（≥） ∃ c>0, n₀, ∀ n≥n₀: f(n) ≥ c·g(n) Θ(g) 确界（=） f ∈ O(g) 且 f ∈ Ω(g) o(g) 严格上界（<） ∀ c>0 最终都 f < c·g ω(g) 严格下界（>） ∀ c>0 最终都 f > c·g

O 只要存在一个 c；o 要求任意小的 c 都最终成立。故 n² ∈ O(n²) 但 n² ∉ o(n²)；n ∈ o(n²)。O(n²) 是集合：可写 3n+7 = O(n²)，不能反过来说。

O 像体检「血压不超过 140」——实际 110 也成立。答「快排是 O(n²)」是真话但没信息。要听的是平均 Θ(n log n)、最坏 Θ(n²)。

2.2 四种常见误用

错对
「快排是 O(n log n)」缺口径。平均 Θ(n log n)，最坏 Θ(n²)；随机 pivot 后最坏很难被构造
「O(2n) 比 O(n) 慢」同一集合。想说「常数大一倍」就说常数因子，不要用 O
「哈希 O(1) 一定快过树的 O(log n)」n=64 时 log n=6；hash 还要扫 key + 可能 miss，红黑树上层常驻 cache
「最坏 O(n²) 就不能用」先问最坏输入能否被攻击者构造。能 → 安全问题；不能 → 通常可接受
第 4 条最贵。2011 Hash-DoS：构造大量冲突 key，把哈希 O(1) 拖成 O(n)，几十 KB 的 POST 就能打满一个核。修复不是换数据结构，而是给哈希加随机种子（SipHash），让攻击者算不出最坏输入。工程含义：最坏情形的价值，取决于谁能决定输入。

2.3 大 O 光谱

纵轴每一格 10 倍。n log n 与 n 的缝远小于 n² 与 n log n：n=10⁹ 时 log n≈30，几乎是常数。「把 O(n log n) 抠成 O(n)」收益通常有限，「干掉 O(n²)」几乎总值得。优化精力按这个顺序分配，不要在已经线性对数的热路径上死磕常数，却放着一层嵌套循环不管。

2.4 比较排序下界

任意只靠「比较两个元素」的排序，最坏至少 Ω(n log n)。决策树有 n! 片叶子（每种排列一条路径），二叉树高 ≥ log₂(n!)，Stirling 给出 log(n!) = Θ(n log n)。归并和堆排的 Θ(n log n) 因此是最优的，不是凑巧。要打破下界必须动用元素值本身：计数 / 基数 / 桶排序的模型已经不是「只比较」。平均情形在「所有排列等概率」下同样是 Ω(n log n)——信息论对期望高度也给同样的界。

03

怎么把代码数成复杂度

三条法则，以及循环层数骗人的地方

3.1 三条运算法则

法则形式说明
加法O(f)+O(g)=O(max)排序再遍历 = O(n log n)
乘法O(f)×O(g)=O(f·g)外 n 次、内 log n = O(n log n)
常数吸收O(c·f)=O(f)O(2ⁿ⁺¹)=O(2ⁿ)，但 O(2²ⁿ)≠O(2ⁿ)
常数在指数外面可吸收；在里面是改增长率。O(2ⁿ⁺¹)=O(2ⁿ)，但 O(2²ⁿ)=O(4ⁿ)≠O(2ⁿ)。O(log n²)=O(log n)，O((log n)²) 不能化简。加法法则也是「只优化瓶颈」的依据：O(n²)+O(n) 的流水线，把线性那段抠到极致也没用。

3.2 循环不能只看层数

数的是循环体总执行次数。外层翻倍、内层 n → n log n；双指针 j 只进不退 → O(n)。下面只留一组最刺眼的对照。

❌ O(n²)：内层每次完整扫
for (int i = 0; i < n; ++i)
    for (int j = 0; j < n; ++j)
        work(i, j);
// n · n 次
✅ O(n)：j 全程只前进
int j = 0;
for (int i = 0; i < n; ++i)
    while (j < n && ok(i, j)) ++j;
// j 最多 +n → ≤ 2n
同类平方还藏在运算符里：循环里 s = s + x 每次拷整串、对 vector insert(begin(), x)、反复 substr。数复杂度时把每次调用换成它的代价再加。调和级数也常被漏：for i=1..n for j=i; j<=n; j+=i 的总次数是 n(1+1/2+…+1/n)≈ n ln n，埃氏筛就长这样——两层循环却是 O(n log n)。

3.3 复杂度速查

复杂度n=10⁶典型来源

04

摊销分析三法

为什么 push_back 是 O(1)，尽管它有时要搬走整个数组

vector::push_back 多数时候写一格（O(1)），满了要搬走全部（O(n)）。摊销分析把「偶尔很贵」摊到整段序列上：任意 m 次操作总代价 ≤ m·T(n)，则单次摊销为 T(n)。这是确定性上界，不依赖概率——和「平均」的区别见 §8。

4.1 聚合法：vector 扩容

容量从 1 翻倍。n 次 push 的搬移发生在 1、2、4、…、2ᵏ（2ᵏ<n），总量 2ᵏ⁺¹−1 < 2n。写入 n 次 + 搬移 < 2n → 总 < 3n，摊销 O(1)。关键就是等比求和：公比大于 1 时，和由最后一项主导，是末项的常数倍，所以「所有历史扩容」不超过「最后一次扩容」的两倍。增长必须是乘性的——每次容量 +1，搬移变成 1+2+…+n = Θ(n²)，摊销 O(n)，vector 就没法当动态数组用了。

换更大的房子：等塞满再搬到两倍处，一辈子搬家总量不超过最后一次的两倍，摊到每件家具头上只是常数次搬运。每次只加一间房，每添一件家具都要搬家，总代价变成三角形。增长因子的工程选择见 4.4：渐进相同，碎片和搬移次数不同。

哈希表 rehash 是同一张图：装载因子超阈值 → 容量翻倍、全部键重映射，单次 O(n)，序列摊销 O(1)。拉链在 α=1 时平均链长才 1，还可以继续涨；开放寻址的探测随 α→1 发散，所以 Swiss Table 用 0.875 而不是 1。和 vector 的差别：rehash 会让迭代器失效，低延迟要么 reserve(峰值)，要么像 Redis 那样每次操作搬一个桶，把尖峰切碎。

4.2 记账法

每次操作预收一笔固定费用，便宜的把余款存起来，贵的用存款付。账户永不透支，预收款就是合法摊销上界。vector 每次 push 收 3：

用途费用说明
写入自己1立刻花掉
预付自己将来被搬一次1存起来
帮一个老元素搬一次1存起来

容量 c→2c 要搬 c 个。后一半 c/2 个是上次扩容之后新来的，各存了 2，合计正好 c。第三笔看起来像「凭空多收」，其实是在给前一半老元素付搬家费。

4.3 势能法

Φ 度量结构有多「紧」。摊销 = 实际 + ΔΦ。若 Φ(初)=0 且始终 Φ≥0，则 Σ摊销 = Σ实际 + Φ(末) ≥ Σ实际，摊销之和是合法上界。聚合法要写出整段序列的闭式；势能法是局部的——对每种操作各验证一个不等式，所以能处理并查集、斐波那契堆、splay 这类操作交错的结构。难点全在找对 Φ。

vector 取 Φ = 2·size − capacity：刚翻倍时 size=cap/2，Φ=0；写满时 Φ=cap。不扩容：实际 1、Φ 增 2，摊销 3。扩容（size=cap=c）：实际 c+1，新 Φ=2，旧 Φ=c，ΔΦ=2−c，摊销仍是 3。

4.4 1.5× 还是 2×

2×（libstdc++）1.5×（MSVC / folly）
每元素搬移~1 次~2 次
浪费上限50%33%
复用旧块历史和永远差 1终会超过下一块

两者都是摊销 O(1)，差别在常数和碎片。2× 时历史块之和 1+2+…+2^{k−1}=2^k−1，永远差 1 放不下下一块，分配器很难原地拼回去，堆往高地址涨。1.5× 时历史和终会超过下一块，有机会复用。这个差异只在「单一大 vector 反复增长」时明显；堆上夹杂别的分配时会被稀释。reserve 把摊销变成真 O(1)；超出预留后仍按因子从当前值增长，不会退回按需精确分配。shrink_to_fit 是非绑定请求。

4.5 摊销 ≠ 平均

摊销平均
概率假设不需要依赖输入分布
保证任意操作序列只对「典型输入」
能否被攻击不能能（构造最坏输入）
例子push_back、并查集快排 Θ(n log n)、均匀哈希

不存在让 n 次 push 超过 O(n) 的「运气差」序列。快排的平均则是对排列求期望——具体输入可以退化成 Θ(n²)。摊销 O(1) 也不等于每次都快：那次 O(n) 扩容落在哪个请求上，哪个就是 p99。低延迟场景启动时 reserve 到峰值。详见 低延迟编程。

05

递归树与主定理

分治算法复杂度的通用解法

分治是 T(n)=a·T(n/b)+f(n)。归并 2T(n/2)+Θ(n)，二分 T(n/2)+Θ(1)。工具：递归树看谁主导，主定理给闭式。

5.1 递归树：把递归摊平

每层代价加总。问三件事：每层多少、树多高（log_b n）、叶子多少（n^{log_b a}）。然后看代价集中在哪：根（每层递减）、均匀（每层相同）、叶子（每层递增）——正好对应主定理三情形。递归树不需要记公式，而且能看见是谁在主导，猜错量级时也知道该往哪边改。

5.2 主定理三情形

对 T(n)=a T(n/b)+f(n)，临界指数 c*=log_b a（叶子数的指数）。把 f(n)（根的合并代价）和 n^{c*}（叶子总代价）比大小：谁大听谁的，一样大就多乘 log n。情形一 f = O(n^{c*−ε}) → Θ(n^{c*})；情形二 f = Θ(n^{c*} log^k n) → Θ(n^{c*} log^{k+1} n)；情形三 f = Ω(n^{c*+ε}) 且满足正规性 a·f(n/b)≤c f(n)（某个 c<1）→ Θ(f(n))。正规性保证各层按几何级数递减；多项式的 f 几乎都满足，反例是 n² sin² n 这种震荡——面试极少考，但知道它存在说明你不是死背公式。

情形条件（直观）递归树T(n)
一 叶子主导f 比 n^{c*} 低一截越往下越贵Θ(n^{c*})
二 势均力敌f ~ n^{c*} log^k n每层一样Θ(n^{c*} log^{k+1} n)
三 根主导f 比 n^{c*} 高一截，且正规根最贵、几何递减Θ(f(n))

5.3 典型算法归位

算法递推c*情形结果
二分T(n/2)+10二Θ(log n)
归并2T(n/2)+n1二Θ(n log n)
快速选择（理想）T(n/2)+n0三Θ(n)
朴素矩阵乘8T(n/2)+n²3一Θ(n³)
Strassen7T(n/2)+n²≈2.81一Θ(n^{log₂7})
Karatsuba3T(n/2)+n≈1.58一Θ(n^{log₂3})
朴素大数乘4T(n/2)+n2一Θ(n²)（没减 a）

Strassen / Karatsuba 都是减 a：8→7、4→3。情形一像层层转包——总包自己干的活（f）再努力也改不了大局，成本在最底层无数小工队（叶子）上，唯一有效的是减少每级分包数。情形三反过来：协调工作已经贵过所有叶子，优化 f 才有意义。

5.4 主定理不适用时

主定理要求子问题规模相等。不等分如 T(n/3)+T(2n/3)+n（快排某些划分）：最短路径 log₃n、最长 log_{3/2}n，每层代价 ≤ n，得 O(n log n)；精确解用 Akra–Bazzi。减法如 T(n−1)+n：展开成三角形 Θ(n²)。子问题个数随 n 变则换元或展开。

兜底是代入法：猜 T(n)≤c n log n，假设对所有更小规模成立，代进递推看能否推出 n 也成立。猜错了归纳会卡，卡在哪通常就提示了正确量级。
06

空间复杂度与递归栈

递归深度是会崩溃的那一维

额外空间不含输入：显式结构和递归栈。Linux 默认线程栈 8 MB，深度大约 10⁴～10⁵ 就爆；O(log n) 的递归（n=10⁹ 才 30 层）安全，n=10⁶ 的链表递归必崩。

算法额外空间备注
归并（数组 / 链表）O(n) / O(log n)数组要缓冲；链表改指针
快排（朴素 / 先小后大）O(n) / O(log n)只递归短边，栈深无条件 log n
堆排 / BFS / DFSO(1) / O(V) / O(V)深链 DFS 会爆栈

「只递归较短一半、长的改循环」把栈深从 O(n) 压到 O(log n)，与 pivot 质量无关：较短的那半必然 ≤ n/2。这是无条件保证，和随机化 pivot（只降概率）互补。libstdc++ 的 std::sort 还叠了 introsort：递归深度超限就转堆排，把时间最坏也拉回 O(n log n)。代码见面试题；栈帧布局见 递归与分治。

07

渐进之外：常数因子

渐进符号沉默的地方，藏着 10 倍的性能差

前面在用渐进分析。这里讲它什么时候会骗你：RAM 模型假设每次访问同价，今天 L1 ~1 ns、主存 ~100 ns，被算作 O(1) 的一次读内部差 100 倍。

7.1 内存墙与 cache line

CPU 按 64B cache line 整块读。空间局部性：读 a[0]，同 line 的 a[1..15]（4 字节 int）已在 cache，顺序遍历每 16 个元素才 1 次 miss。硬件预取检测到顺序模式会提前取下一行，只对可预测访问生效——指针追逐完全无效。

层级延迟~3 GHz 周期
L1 / L2 / L3~1 / 4 / 15 ns4 / 12 / 45
主存 DRAM~80–100 ns~300
NVMe SSD~50–100 µs~300 000
去图书馆一次借一整格 16 本。数组按序摆，搬一次够读 16 本，管理员还会预取下一格。链表每本写着下一本在哪栋楼——每本跑一趟。渐进分析说两者都是 O(n)。

7.2 list 的 O(1) 输给 vector 的 O(n)

教科书：中间插入 list O(1)、vector O(n)。几万元素规模下 vector 常快 5–10 倍。list 的 O(1) 前提是已持有迭代器；先找位置就是最慢那种 O(n)（每个节点一次 miss，预取失效）。vector 的 memmove 是连续内存上的 SIMD 批量搬，带宽约 10 GB/s；list 每次插入还要一次 malloc，节点 24–32 字节 vs int 的 4 字节。

先用渐进排除 O(n²)，再用测量优化常数。跳过第一步是在给错误算法抛光。std::list 真正值钱的是：已持有迭代器 且 插删后迭代器/引用仍有效 且 用得上 splice。典型是 LRU：哈希表存 key→list 迭代器，移到表头是真 O(1)。

7.3 常数 vs 复杂度（交互）

常数大的低阶算法，在什么 n 被常数小的高阶反超——这就是 std::sort 小区间切插入排序的依据。插入排序的常数极小（顺序写、零分配、分支可预测），归并要缓冲和两路交错访问；交叉点通常在几十到一两百，所以 introsort 在 ≤16 就停递归，最后再扫一遍插入排序。这个 16 比理论交叉点更小，因为小区间能整块留在 L1。

最坏 / 平均 / 期望 / 摊销

四种口径，以及为什么线上只看 p99

8.1 四种口径的区别

口径对什么取极值假设例子
最坏所有输入里最差的无归并 / 堆排 Θ(n log n)
平均对输入分布求期望输入分布快排在等概率排列下
期望对算法内部随机数随机源可靠随机化快排、跳表、随机哈希
摊销对操作序列求平均无push_back、并查集

随机化不改善最坏（仍 Θ(n²)），但让最坏从「攻击者可控」变成「不可控」——这是安全性质，不是性能性质。跳表用随机层高代替红黑树旋转、哈希用随机种子抵御 Hash-DoS，都是同一思路。归并/堆排没有这条担忧：它们的最坏就是 Θ(n log n)，口径只有一种。

8.2 为什么线上看 p99

扇出放大尾延迟：一个用户请求并行调 n 个下游并等全部返回，可见延迟 = max(所有调用)。单次 p99=L 时，P(至少一次超过 L)=1−0.99^n；n=100 已经约 63%。算法课看均值，生产看尾部——摊销 O(1) 的 push_back 均值完美，那次 O(n) 扩容落在谁头上谁就是 p99。

  • 预分配：启动时 reserve 到峰值，摊销 O(1) 变成最坏 O(1)。
  • 宁要稳定的 O(log n)：实时系统常用平衡树而不是哈希——树每次都是 log n，哈希 rehash 会抖。
  • 把贵操作切碎：Redis 增量 rehash、分代 GC，一次长停顿变成多次短停顿。
  • 运行期零 malloc：对象池 / arena / 固定环形缓冲。malloc 自身的尾延迟就不受控。

P、NP 与工程含义

当问题本身就是难的，该怎么办

前面问「算法多快」。复杂度类问「问题有没有快算法」。NP-hard 是止损信号：别再找精确多项式解，改近似或启发式。

类直觉例子
P能高效解出来排序、最短路、最大流
NP能高效验算SAT、TSP 判定版
NP-完全NP 里最难、彼此可归约3-SAT、团、顶点覆盖
NP-hard至少一样难，不必属于 NPTSP 优化版、停机问题
填好的数独几分钟能验（NP）；空盘广义 n×n 数独有没有快算法未知。NP-完全再加一层：这些问题可以互相「翻译」——攻破 SAT 等于攻破全部 NP，所以它是实用的止损信号：几十年里没人拿下其中任何一个，你手上这个大概也不会例外。证明 NP-hard 的标准姿势是归约：把已知难题 X 的实例多项式变换成你的问题 Y 的实例，于是「Y 能快解 ⇒ X 也能快解」。方向反了只说明 Y 不比 X 难，是另一回事。

策略做法代价实例

面试题集（12 道）

按难度分三段，先自测再对照

10.1 基础（必答）

点击每道题展开参考答案（先自测，再对照）。

  1. 基础O、Θ、Ω 有什么区别？为什么说「快排是 O(n log n)」不算完整回答？

    O 是上界（f 增长不快于 g），Ω 是下界，Θ 是两者同时成立即确界。三者都带「存在常数 c 和阈值 n₀」的前缀，用来忽略常数因子和小规模行为。

    「快排是 O(n log n)」有两个问题：

    缺口径
    没说是最坏、平均还是期望。快排的最坏是 Θ(n²)（例如已排序输入 + 取端点为 pivot），平均才是 Θ(n log n)。不说口径等于隐瞒了退化风险。
    用 O 而非 Θ
    O 只给上界，所以「快排是 O(n²)」也是真话——但没信息量。要表达「就是这个量级」应该用 Θ。

    完整答法：平均/期望 Θ(n log n)，最坏 Θ(n²)；随机化 pivot 或 median-of-medians 后最坏可控。

  2. 基础下面两段代码的复杂度分别是多少？为什么？ 
    // A
for (int i = 1; i <= n; i *= 2)
    for (int j = 0; j < n; ++j) work();

// B
int j = 0;
for (int i = 0; i < n; ++i)
    while (j < n && ok(i, j)) ++j;

    A 是 Θ(n log n)：外层 i 每次翻倍，只有 ⌊log₂n⌋+1 层，每层内层跑 n 次。

    B 是 Θ(n)：虽然是两层，但 j 在整个过程中只增不减，最多前进 n 次。外层 n 次 + 内层总共 n 次 = 2n。

    通用方法
    不要数循环层数，数循环体的总执行次数。B 用的是「势能/记账」思路：找一个单调变化的量（这里是 j），它的总变化量就是内层的总代价上界。双指针、滑动窗口、单调栈的 O(n) 都靠这个论证。
  3. 基础为什么 std::vector::push_back 是 O(1)，尽管它有时要搬走整个数组？

    因为它是摊销 O(1)。容量每次翻倍，所以做 n 次 push_back，扩容发生在第 1、2、4、…、2^k 次，搬移总量是等比数列：

    1 + 2 + 4 + ... + 2^k = 2^(k+1) − 1 < 2n

    总代价 < n（写入）+ 2n（搬移）= 3n，除以 n 次操作得摊销 O(1)。

    关键
    公比 > 1 的等比数列，其和是最后一项的常数倍。所以「所有历史扩容之和」不超过「最后一次扩容」的两倍。
    反例
    如果每次容量 +1（加性增长），搬移总量变成 1+2+…+n = Θ(n²)，摊销就是 O(n)。增长必须是乘性的。

    要注意摊销 O(1) 不代表每次都快——单次仍可能 O(n)，这是尾延迟来源，低延迟场景要 reserve 规避。

  4. 基础n = 10⁵ 和 n = 5000 分别提示你用什么复杂度的算法？

    基准：现代 CPU 单线程每秒约 10⁸～10⁹ 次简单操作，常见时限 1 秒。

    n可行复杂度常见算法
    10⁸～10⁹O(n)单遍扫描、双指针、计数排序
    10⁵～10⁶O(n log n)排序、堆、平衡树、线段树
    5000O(n²)双层循环 DP、Floyd 的一层、朴素最近对
    300O(n³)Floyd 全源最短路、区间 DP
    20～25O(2ⁿ)状压 DP、子集枚举
    ≤ 11O(n!)全排列枚举
    反向使用
    数据范围就是出题人给的复杂度暗示。看到 n≤20 基本是状压/回溯；看到 n≤10⁵ 但要求多次查询，大概率要预处理成 O(1)/O(log n) 查询。面试时把这个推理说出来，比直接报答案更能体现思路。

10.2 中级（区分熟练度）

  1. 中级「摊销复杂度」和「平均复杂度」的本质区别是什么？举例说明。

    摊销不依赖任何概率假设，平均依赖输入分布假设。

    摊销
    对任意长度为 m 的操作序列，总代价 ≤ m·T(n)。这是确定性上界——不存在「运气不好」的序列让 n 次 push_back 超过 O(n)。
    平均
    对输入分布求期望。快排的 Θ(n log n) 假设「所有排列等概率」；存在具体输入让它退化成 Θ(n²)，只是在假设的分布下概率很低。
    工程后果
    平均复杂度可被攻击。2011 年的 Hash-DoS 就是构造大量哈希冲突的 key，把哈希表的 O(1) 拖成 O(n)，几十 KB 请求打满一个核。修复不是换数据结构，而是给哈希函数加随机种子（SipHash），让攻击者算不出最坏输入。
    还有第三种：期望
    随机化算法的「期望 O(n log n)」把不确定性放在算法自己的随机源上，而不是输入上。所以对任意固定输入都有好的期望性能——这是安全性质。随机化快排、跳表都属于这一类。
  2. 中级用主定理分析 T(n)=2T(n/2)+n、T(n)=T(n/2)+1、T(n)=7T(n/2)+n²。

    对 T(n)=a·T(n/b)+f(n)，先算临界指数 c* = log_b a，再把 f(n) 和 n^c* 比大小。

    递推式c* = log_b af(n) vs n^c*情形结果
    2T(n/2)+nlog₂2 = 1n = n¹，相等二（k=0）Θ(n log n)
    T(n/2)+1log₂1 = 01 = n⁰，相等二（k=0）Θ(log n)
    7T(n/2)+n²log₂7 ≈ 2.807n² < n^2.807一Θ(n^log₂7) ≈ Θ(n^2.807)

    三者分别是归并排序、二分查找、Strassen 矩阵乘法。

    直觉记法
    n^c* 是叶子的总代价，f(n) 是根的代价。谁大听谁的（情形一 / 三），一样大就多乘一个 log n（情形二）。Strassen 落在情形一说明它的收益全部来自「把 8 次子乘降到 7 次」（降 a），而不是优化合并。
    情形三别忘正规性条件
    还要满足 a·f(n/b) ≤ c·f(n)（某个 c<1），保证各层代价按几何级数递减。多项式形式的 f 基本都满足。
  3. 中级递归实现的快排，为什么最坏栈深是 O(n)？怎么无条件压到 O(log n)？

    最坏 O(n) 的来源：pivot 每次都取到极值（如已排序数组取末位），划分变成「1 个元素 + n−1 个元素」，递归链长 n。Linux 默认线程栈 8 MB，n 到 10⁵ 量级就 SIGSEGV。

    修复不是「选更好的 pivot」——那只降低概率，不给保证。正确做法是两个技巧叠加：

    只递归小半边
    比较两侧长度，对较短的那半递归，较长的那半通过修改 lo/hi 转成循环（手工尾递归消除）。递归的那半必然 ≤ n/2，所以栈深 ≤ log₂n。
    while (lo < hi) {
    int p = partition(a, lo, hi);
    if (p - lo < hi - p) { qsort(a, lo, p-1); lo = p+1; }
    else                 { qsort(a, p+1, hi); hi = p-1; }
}
    为什么这是无条件保证
    它不依赖 pivot 质量。哪怕每次划分都极度不均，「较短的一半」也一定不超过一半，log 上界照样成立。这是确定性的，和随机化 pivot（概率性的）互补——工程上两个都要。

    libstdc++ 的 std::sort 同时用了这个模式和「深度超限转堆排」（introsort），后者把时间最坏也拉回 O(n log n)。

  4. 中级vector 的增长因子选 2× 还是 1.5×？各自的理由是什么？

    两者都给出摊销 O(1)（只要是乘性增长），差别在常数与内存行为。libstdc++ 用 2×，MSVC STL 和 folly::fbvector 用 1.5×。

    维度2×1.5×
    每元素摊销搬移次数约 1 次约 2 次
    内存浪费上限50%33%
    扩容次数（到 n）log₂n≈1.7 log₂n
    能否复用已释放空间不能可以
    1.5× 最有意思的理由
    用 2× 时历史块之和 1+2+4+…+2^(k−1) = 2^k − 1，永远差 1 个单位不够放下一块，所以分配器没法把前面释放的空间拼起来复用，堆持续向高地址增长。1.5× 时历史块之和最终会超过下一块所需，有机会原地复用，长期碎片更少。
    实践要点
    reserve 之后超出预留量，容量仍按增长因子从当前值翻倍，不会退回按需精确分配。shrink_to_fit 是非绑定请求，标准只要求「不增加容量」。

10.3 高级（体现深度）

  1. 高级教科书说链表中间插入是 O(1)、vector 是 O(n)，为什么实测常常 vector 快 5–10 倍？

    因为渐进分析基于 RAM 模型，假设每次内存访问代价相同。真实机器上 L1 命中约 1 ns、主存约 100 ns，差两个数量级——「访问一个内存单元」这个被算作 O(1) 的操作内部有 100 倍浮动。

    ① O(1) 的前提没成立
    list 的 O(1) 插入前提是你已经持有那个位置的迭代器。若需先找位置，那 O(n) 的指针追逐不但没省掉，还是最慢的一种 O(n)：每个节点一次 cache miss，且硬件预取完全失效（读完当前节点才知道下一个地址在哪）。
    ② 两个 O(n) 的常数差 16 倍以上
    vector 顺序访问每 64 字节 cache line 覆盖 16 个 int，miss 率 1/16，且预取器几乎全命中。list 每个节点一次 miss，miss 率约 1/1。
    ③ memmove 极快
    vector 的 O(n) 搬移是连续内存上的 SIMD 批量拷贝，带宽约 10 GB/s；而 list 每次插入还要一次 malloc，节点开销 24–32 字节 vs int 的 4 字节。
    list 真正的适用场景
    已持有迭代器 且 需要迭代器/引用在插删后保持有效 且 用得上 splice 常数时间拼接。典型是 LRU 缓存：哈希表存「key → list 迭代器」，移动到表头是真 O(1) 且不失效其他迭代器。
    正确的结论
    不是「渐进分析没用」，而是渐进分析决定 n 大时的量级（不可违抗），常数因子决定同量级内的胜负（可优化 10 倍）。先用渐进排除 O(n²)，再用测量优化常数。跳过第一步去调常数，是在给错误的算法抛光。
  2. 高级什么是势能法？用它证明 vector::push_back 的摊销 O(1)。它比聚合法强在哪？

    势能法定义一个函数 Φ 度量数据结构的「紧张程度」，把摊销代价定义为实际代价 + 势能变化：

    摊销代价 = 实际代价 + Φ(after) − Φ(before) 若 Φ(初始)=0 且 Φ(任何时刻) ≥ 0，则 Σ摊销 = Σ实际 + Φ(末) − Φ(初) ≥ Σ实际 → 合法上界

    对 vector 取 Φ = 2·size − capacity（刚扩容后 size=capacity/2 时 Φ=0，写满时 Φ=capacity）：

    不扩容
    实际代价 1；size+1 使 Φ 增加 2 → 摊销 = 1+2 = 3。
    触发扩容
    size=capacity=c。实际代价 = c 次搬移 + 1 次写入 = c+1。扩容后 capacity=2c、size=c+1，新 Φ = 2(c+1)−2c = 2；旧 Φ = 2c−c = c。ΔΦ = 2−c。摊销 = (c+1)+(2−c) = 3。

    两种情况都是常数，故摊销 O(1)。Φ 的作用是把贵操作的代价提前存起来，贵操作发生时释放势能正好抵消。

    比聚合法强在哪
    聚合法要求你能算出整个序列的总代价闭式解，只适用于操作模式规整的情况。势能法是局部论证——只需对每种操作单独验证一个不等式，不必知道操作序列长什么样。所以它能处理操作交错、类型多样的结构：并查集的 α(n)、斐波那契堆的 O(1) 摊销 decrease-key、splay 树的 O(log n) 摊销，都只能用势能法证。代价是找到合适的 Φ 是全部难点，没有机械方法。
  3. 高级为什么线上系统看 p99 而不是均值？这对算法与数据结构选型有什么具体影响？

    因为请求扇出会放大尾延迟。一个用户请求并行调用 n 个下游并等全部返回时，用户可见延迟 = max(所有调用延迟)：

    P(至少一次超过 p99 阈值) = 1 − 0.99^n n=10 → 9.6% n=100 → 63.4% n=1000 → 99.996%

    也就是说，扇出 100 次时，大多数用户请求都会撞上至少一个 p99 慢响应。均值再漂亮也没用。

    对选型的四条具体影响：

    预分配
    启动时 reserve 到峰值，把摊销 O(1) 变成最坏 O(1)。摊销 O(1) 在均值上完美，但那次 O(n) 扩容落在哪个请求上，那个请求就是 p99。
    宁要稳定 O(log n)
    很多实时系统用平衡树而非哈希表：红黑树每次查找都是稳定的 log n，哈希表 rehash 时会突然长停顿。可预测性有时比平均速度更值钱。
    分摊贵操作
    把一次长停顿切成很多次短停顿：Redis 的增量式 rehash（每次操作搬几个 bucket）、分代 GC、分批 compaction。
    消除不可预测的分配
    对象池 / arena / 固定容量环形缓冲区，让运行期零 malloc。malloc 本身的尾延迟就不受控。
    再往上一层
    算法层面压不下去时，靠架构：对冲请求（hedged request，等到 p95 还没回就向副本再发一份，取先到的）能把扇出场景的 p99 显著拉低，代价是约 5% 的额外负载。这是「用吞吐换延迟」的典型交易。
  4. 高级你负责的服务里有个需求被判定为 NP-hard，接下来怎么做？

    NP-hard 的工程价值是止损信号：停止寻找精确多项式算法。但在换算法之前，先做一件更重要的事。

    ① 先质疑需求
    很多 NP-hard 是把业务约束抽象过头的结果。「给 1000 个任务排最优调度」是 NP-hard，但业务上往往只要「95% 任务在 SLA 内 + 最坏不超过 2 倍」——那就变成一个贪心能解的问题。动手找算法之前，先确认真的需要最优解。
    ② 量一量真实输入规模
    NP-hard 说的是最坏情形随 n 增长的行为。如果生产数据里 n 常年 ≤ 30，分支限界或 ILP 求解器几毫秒就返回最优解，那这个「NP-hard」在工程上根本不是问题。先看数据，再谈复杂度类。

    确认必须放弃精确解后，按「保证强度」排序的五条出路：

    策略保证实例
    近似算法有界近似比顶点覆盖 2-近似、集合覆盖 ln n-近似
    限定参数（FPT）k 小时精确O(f(k)·poly(n))，树宽有界的图
    精确 + 剪枝最优解，时间不保证分支限界、ILP（Gurobi/CBC）、SAT 求解器
    启发式无保证模拟退火、遗传算法、贪心 + 局部搜索
    松弛改问题不再是原问题整数规划 → LP 松弛后取整
    选型的判断标准
    问「解差一点的代价是多少」。结果要对外承诺（计费、合规、资源配额）→ 用近似算法，因为你需要一个能写进文档的界。结果只影响内部效率（缓存预热顺序、任务打包）→ 启发式够用，把精力花在监控实际解质量上。离线批处理、有几小时窗口→ 直接上 ILP 求解器，通常能拿到最优或近最优，而且比自己写启发式省事得多。
    别掉进的坑
    自己从零写启发式（尤其是遗传算法这类）往往打不过成熟求解器，还留下无人能维护的代码。先试通用求解器，打不过再自己写。
