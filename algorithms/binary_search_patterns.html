二分查找

二分是最简单的算法，也是最多人写不对的算法。原因是大家把它记成了「在有序数组里找一个数」这个特例，于是每换一种边界要求就得重新猜一遍 < 还是 <=。这一篇换一个视角：二分的本质是在单调谓词上找分界点；理解这一点后，一个模板就能覆盖全部边界，而且每次都能证明它对。

核心难度 ★★★☆☆ 面试出现率 极高 阅读时长 ~30 min 前置 复杂度与分析
循环不变式证明 四种边界统一模板 lower_bound 实现 二分答案 旋转数组 cache 友好布局
01

本质不是「找数」

而是在单调谓词上找那条分界线

教科书把二分定义成「在有序数组中查找目标值」。太窄：那只是 P(i) = (a[i] >= target) 的特例。工作里直接用 std::lower_bound；面试里常遇到没有数组的二分答案。前提只有一句——能证明谓词单调。

一般形式：区间 [lo, hi) 上有单调布尔谓词 P（存在分界点，之前全假、之后全真），O(log n) 次求值找到第一个真。数组不必存在，答案不必是下标。

写二分时只问两句：我的 P 是什么？它真的单调吗？有序数组找目标只是 P(i)=a[i]≥target。git bisect、二分答案、山峰数组都没有「排好序的目标值」，但各自构造出了单调 P。

二分像 git bisect：500 个提交里定位引入 bug 的那一次，谓词是「这个提交上 bug 还在吗」——一旦引入就一直为真，约 9 次测试即可。没有有序数组，也没有目标值。若测试时好时坏（flaky），谓词不单调，bisect 不报错，只安静地骗你。

1.1 与其他章节的关系

  • 复杂度与分析 —— O(log n) 的来源，以及为什么 log n 在工程规模内是小常数
  • 排序全景 —— 二分的前置条件由排序提供；决策树论证也给出了二分的下界
  • 递归与分治 —— 二分是「只有一个子问题」的退化分治
  • STL 算法库 —— lower_bound / upper_bound / equal_range / binary_search
  • 存储与数据架构 —— B+ 树、跳表、LSM 里二分的真实用途
02

为什么大家都写错

三行代码里有四个能出错的地方

循环条件、mid 取整方向、lo/hi 赋值、区间开闭——任意一对拧了，轻则漏解，重则死循环或越界。下面两个陷阱（溢出、少一次循环）加上「区间没缩小」几乎覆盖全部现场事故。

2.1 mid 溢出

2006 年 Joshua Bloch 披露：JDK 的 Arrays.binarySearch 带着 (lo + hi) / 2 这个 bug 活了九年，源头是《Programming Pearls》。有符号加法溢出是 UB，迭代器则根本不能相加。

对指针和迭代器，lo + (hi - lo) / 2 不是防御性编程而是必须：ptr1 + ptr2 在 C++ 里不合法。这也是 STL 实现长这样的原因。

2.2 死循环与少一次循环

死循环几乎总是「这一轮区间没缩小」。少一次循环则是区间约定和 while 条件拧在一起，退出时还剩一个没看过的元素。

写法为什么坏何时爆
while (lo < hi) + lo = midmid 偏左，hi == lo+1 时 mid==lo，lo 不动剩 2 个元素
while (lo <= hi) + hi = mid同理，hi 可能不动剩 1–2 个
半开初始化 + 闭区间循环hi = n 却写 lo <= hi → 读 a[n]目标大于全部
mid 向下取整时：hi = mid 安全（mid < hi），lo = mid 不安全，必须 lo = mid + 1。若逻辑真要 lo = mid，改成向上取整 lo + (hi - lo + 1) / 2。取整方向和赋值必须配对。
03

用不变式一次写对

不靠试错，靠证明

写二分最稳的办法不是跑几个用例猜 < 还是 <=，而是先写下循环不变式，让每一次收缩都保持它。半开区间让「空」只有一种表示，终止条件、没找到、长度计算都从同一套符号推出来。

3.1 半开区间 + 不变式

下面这一块是全文唯一需要记住的循环。不变式写在注释里：所有边界都从它推出来，不必猜 < 还是 <=。

// [0, n) 上找第一个使 P 为真的下标；全假则返回 n
// 不变式：∀ i < lo, ¬P(i)；∀ i ≥ hi, P(i)（若 i < n）→ 答案 ∈ [lo, hi]
int lo = 0, hi = n;
while (lo < hi) {
    int mid = lo + (hi - lo) / 2; // 避免溢出；mid 偏左，lo ≤ mid < hi
    if (P(mid)) hi = mid;          // 答案 ≤ mid
    else         lo = mid + 1;      // 答案 > mid
}
return lo;                          // lo == hi，区间空
① 初始 lo=0, hi=n。∀ i<0 假、∀ i≥n 真，都是空真。 ② 保持 mid 满足 lo ≤ mid < hi。 P(mid) 真 → 单调性给出 ∀ i≥mid 皆真 → hi=mid。 P(mid) 假 → ∀ i≤mid 皆假 → lo=mid+1。 ③ 退出 lo==hi，不变式变成「i<lo 全假、i≥lo 全真」→ lo 就是第一个真。 ④ 终止 两分支都严格缩短区间 → 至多 ⌈log₂ n⌉ 轮。

3.2 左闭右开 vs 闭区间

不变式像装修封条：「外面已经验收」。房子分成已确认全假、待查、已确认全真三块，每次只拆中间一间再把封条往里挪。待查区变空时，两道封条之间就是答案——不必回头复查任何一间。
04

左 / 右边界

只写一个 lower_bound，别写三份几乎一样的循环

4.1 一块写完 lower_bound

左边界 = 第一个 ≥ x，右边界 = 第一个 > x。两者夹出的 [L, R) 就是全部等于 x 的元素。「最后一个满足 Q」=「第一个满足 ¬Q」减一，不要另写一套 hi = mid - 1 的循环。

要找什么谓词 P(i)返回
第一个 ≥ x（lower_bound）a[i] >= x下标或 n
第一个 > x（upper_bound）a[i] > x下标或 n
最后一个 < xa[i] >= x返回值 − 1（可能 −1）
最后一个 ≤ xa[i] > x返回值 − 1（可能 −1）
 
// 同一套 §3 模板，只换谓词
int L = lower_bound_by(n, [&](int i){ return a[i] >= x; }); // 左 = 第一个 ≥ x
int R = lower_bound_by(n, [&](int i){ return a[i] >  x; }); // 右 = 第一个 > x
// 出现次数 = R - L；存在 ⟺ L < n && a[L] == x
// 最后一个 < x = L-1；最后一个 ≤ x = R-1（先判 > −1）
「最后一个」在全体 ≥ x 时得到 −1。忘了检查就是 a[-1]。不是逻辑更难，只是多了一个失败返回值。

4.2 四种边界互相表达

这四个位置不是四套算法：lower_bound / upper_bound 是「第一个」，各减一得到「最后一个」。

一句话：[lower_bound, upper_bound) = 全部等于 x。插入点在 L（前插，保持相对顺序时用 R 后插）。出现次数就是 R−L；L==R 表示不存在。

4.3 变体对照

每种变体只记「问什么 → 不变量 → 收缩哪边」。循环形状与 §3 相同，不要为每道题再写一份。

问什么不变量收缩哪边
第一个 ≥ x / > x答案 ∈ [lo, hi]；i < lo 皆不满足 PP(mid) → hi=mid，否则 lo=mid+1
最后一个 < x / ≤ x等于「第一个 ¬Q」− 1先套上一行，再减一（检查 −1）
最小化最大值值域 [lo, hi)；feasible 单调可行 → hi=mid，否则 lo=mid+1
最大化最小值可行在「更大」一侧P 取反，或 mid 上取整配 lo=mid
旋转点（无重复）P(i)= a[i] ≤ a[n−1] 单调同 §3 模板
峰值P(i)= a[i] > a[i+1]（已下降）已下降 → hi=mid，否则 lo=mid+1
第 k 小count(≤ x) 关于 x 递增在值域上二分 x
整体有序矩阵摊平一维 [0, mn)同 lower_bound
行列有序（非整体）不该硬套二分右上角走，O(m+n) 排除整行/列
浮点最优固定 100 轮，不靠 eps可行 → hi=mid，否则 lo=mid
set 查找要用成员函数算法版 advance 是 O(n)

05

STL 与复杂度陷阱

保证的是比较次数，不是运行时间

5.1 比较次数 ≠ 运行时间

std::lower_bound 保证的是 O(log n) 次比较，不是 O(log n) 运行时间。它维护 len 而不是 last，用 advance(mid, half) 前进——对 ForwardIterator 也能编译。随机访问上这是真 O(log n)；list / set 的迭代器上 advance 沿中序一步步走，总推进 O(n)，比线性扫描还慢（同样 O(n) 移动，外加 log n 次比较和更差的访问模式）。

迭代器比较推进总时间
RandomAccess（vector）O(log n)O(log n)O(log n)
Bidirectional（set / list）O(log n)O(n)O(n)
容器提供了同名成员函数就用成员：s.lower_bound(x) 沿红黑树从根往下，才是真 O(log n)。算法版只能通过迭代器接口，拿不到树形结构。同类差异：set::find vs std::find、string::find vs std::search。

5.2 全家桶对照

接口返回用途
lower_bound第一个 ≥ x插入点、左边界
upper_bound第一个 > x右边界、稳定插入
equal_range两者一起等于 x 的区间
binary_search只给 bool先它再 lower_bound = 二分两次；直接 lower_bound 一次再检查
partition_point第一个使 P 为假谓词已划分时的二分，最接近 §3
partition_point 找第一个使 P 为假的位置，要求区间已按 P 划分——就是「谓词单调」的另一种说法。按派生字段或外部条件二分时，用它比硬凑 comparator 干净。binary_search 只给 bool：先它再 lower_bound 是二分了两次，直接 lower_bound 一次再检查即可。
06

二分答案

把「求最优值」变成「判定可行性」

6.1 求最优 → 判定可行

直接求最优 x* 往往很难；给定候选判断「行不行」通常只要贪心扫一遍。若 feasible(x) 单调，就在值域上套 §3 模板。代价 O(log(值域) × 一次判定)。

像试衣服：不测 37 个围度，直接问「这一号能不能穿」。M 能穿则 L、XL 一定能——这就是单调。尺码乱标则二分会给错号。
题型二分对象判定单调方向
分割数组最大值最小每段和上限贪心分段，数段数上限越大越可行
船运载重 / 珂珂吃香蕉载重 / 速度贪心装货或 Σ⌈pile/speed⌉越大越可行
木材切割每段长度Σ ⌊len_i / L⌋长度越小越可行
第 k 小的距离对距离 d双指针数 ≤ d 的对数距离越大越可行

6.2 最短判定函数

分割数组：分成 k 段，使各段和的最大值最小。判定「上限 limit 能否 ≤ k 段」——贪心，塞不下就开新段。

// 最小值最大化 / 最大值最小化：判定尽量短
bool feasible(long long limit, int k) {
    int segs = 1; long long cur = 0;
    for (int x : a) {
        if (x > limit) return false;
        if (cur + x > limit) { ++segs; cur = x; } else cur += x;
    }
    return segs <= k;                    // 值域 [max, sum]，套 §3
}
三个识别信号都命中就基本确定用二分答案：① 最小化最大值或最大化最小值；② 答案是数值且值域已知或易估；③ 验证一个候选比找到它容易。判定几乎总是「贪心扫一遍 + 计数」，比直接 DP 的 O(n²k) 好一个数量级。

07

找回单调性

数组不全局有序时，二分还能用吗

7.1 旋转有序数组

[4,5,6,7,0,1,2] 不全局有序，但任意划分后至少一半有序。更干净的做法：构造单调谓词，套 §3。

不要为每种变体重新设计二分：P(i) = (a[i] <= a[n-1]) 在旋转数组上恰好是前段大值（假）、后段小值（真），模板一字不改。找到旋转点后再在对应有序段做标准二分。
// 找旋转点 = 第一个 a[i] ≤ a[n-1]；P 在旋转数组上单调
int lo = 0, hi = n - 1;
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (a[mid] <= a[hi]) hi = mid; else lo = mid + 1;
}                                   // lo = 最小值下标，再在有序段做标准二分
有重复时 [1,1,1,0,1] 无法判断哪半有序，只能 ++lo，最坏 O(n)——那是信息论下界（0 可在任意位置），不是实现不够好。

7.2 山峰数组

数组本身先增后减，不单调；导出量 a[i] > a[i+1]（已开始下降）单调。循环形状同 §3，hi 取 n−1 以保证 mid+1 合法。细节见 §4.3 表。

导出量含义用来解
a[i] > a[i+1]是否已开始下降山峰、局部极值
a[i] ≤ a[n-1]是否已过旋转点旋转数组最小值
a[i] − i是否已出现空洞缺失的数、第 k 个缺失
count(≤ x)不超过 x 的个数，关于 x 递增第 k 小、有序矩阵第 k 小
行列都有序但不是「下一行首 > 上一行尾」时，不要对每行二分。从右上角走：比目标大就弃整列，小就弃整行，O(m+n)，信息利用率高于 O(m log n)。能二分不等于该二分——先问每步能排除多少候选。整体有序的矩阵才摊平当一维 lower_bound。
08

浮点二分

为什么固定迭代次数比 eps 更稳

浮点上「相邻两个可表示数」的间距随数量级变大。用绝对 eps 当终止条件，等于把算法和题目精度、数值大小绑死：1e18 上 1e-9 永远达不到，小数上又可能过早停。固定 100 轮把循环次数变成与数值无关的常数；能乘 10^k 做成整数二分就不要走浮点。

坑症状修法
hi - lo > eps 且数值巨大死循环固定迭代次数
浮点 while (lo < hi)几乎必然死循环不要用严格不等判终止
绝对 eps 判相等大数判不出、小数过早判相对误差 eps * max(1, |a|)
输出默认 6 位算对被判错printf("%.10f")
上下界估错答案卡在边界、偶发才暴露宁可放宽
09

工程里的二分

从 git bisect 到 cache 友好的内存布局

工程里二分的「一次判定」往往比比较两个整数贵几个数量级：一次编译、一次磁盘页、一次 cache miss。所以真正要优化的是判定次数和每次判定碰到的硬件层次，而不是再把比较次数从 30 降到 28。

9.1 git bisect

日常里最贵的「一次判定」：编译 + 测试。500 个提交约 9 次。谓词是「这个提交上 bug 还在」——前提是 bug 一旦引入就一直在。

要素在 git bisect 里
区间good 到 bad 之间的提交
谓词这个提交上 bug 存在吗
单调性引入后一直存在
失效flaky、中间编不过（该 skip）、修了又引入（FTFT）
单调性坏了不会报错，只安静给错答案。判定必须是纯函数、处处有定义、真单调。

9.2 B+ 树页内二分

数据库和文件系统的 B+ 树里，二分出现在两个层次上：

层次次数单次代价优化目标
树高（跨页）log_B(n)一次磁盘 I/O ≈ 100 µs把 B 做大，树尽量矮
页内二分log₂B ≈ 8–10内存访问 ≈ 100 ns次要（差一千倍）

两层代价差 1000 倍。节点做成页（B ≈ 数百），log_B(10⁹) ≈ 3~4；二叉搜索树要 ~30 次 I/O。用页内廉价二分换掉跨页跳转。展开见 存储与数据架构。LSM 块内二分、跳表、列存 min/max 剪枝是同一套路。

9.3 cache 友好的布局

大数组上标准二分前几步跳 n/2、n/4……每步一次 cache miss，而且下一步依赖比较结果，预取器完全失效。4 GB 的 int 约 30 步里前 20 步都在等主存。只读热点才值得换布局。

手段思路前提
分支消除cmov 代替 50% 误预测的分支先做这个
eytzinger层序存放，前几层同一 cache line只读索引
cache 层 B 树一行多个 key，SIMD 一次比 8–16 个实现重
插值查找均匀时 O(log log n)不均则退化 O(n)
这些优化只在「数组远超 L3 + 查询极频繁 + 只读」时值得做：数据库只读索引、倒排表、游戏静态资源表。绝大多数业务代码里 std::lower_bound 已经够——先看 profile 里这段是否超过 5%。点查且不需要范围扫描时，哈希表的 O(1) 比任何二分优化都强。测量见 性能优化指南。

面试题集（12 道）

按难度分三段，先自测再对照

10.1 基础（必答）

点击每道题展开参考答案（先自测，再对照）。

  1. 基础手写一个二分查找，并说明 mid 为什么不能写 (lo + hi) / 2。 
    // 找第一个 >= target 的下标；没有则返回 n
int lower_bound(const int* a, int n, int target) {
    int lo = 0, hi = n;                  // 半开区间 [lo, hi)
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;   // lo ≤ mid < hi
        if (a[mid] >= target) hi = mid;
        else                  lo = mid + 1;
    }
    return lo;
}
    溢出问题
    lo + hi 在两者都接近 INT_MAX/2 以上时会有符号整数溢出——这是 UB，实际常得到负数，然后 a[负数] 越界读。
    这个 bug 在 JDK 的 Arrays.binarySearch 里活了九年（2006 年 Joshua Bloch 披露），而它照抄自《Programming Pearls》——那本书里错了二十年。
    正确写法
    lo + (hi - lo) / 2（最通用）或 (int)(((unsigned)lo + hi) >> 1)。
    对指针和迭代器来说前者是唯一写法——ptr1 + ptr2 在 C++ 里根本不合法。这也是 STL 实现长这样的原因。
    为什么用半开区间
    「空区间」有唯一表示（lo == hi），区间长度就是 hi - lo，hi = n 天然表示「没找到」，而且和 STL 的 [first, last) 一致。它能消掉一整类 off-by-one 错误，不是审美偏好。
  2. 基础二分的死循环通常怎么产生？怎么从结构上避免？

    根因只有一个：某轮循环后区间没有严格缩小。

    最常见的一种
    mid 向下取整时，如果区间只剩 2 个元素（hi == lo+1），那么 mid == lo。此时写 lo = mid 等于没变 → 永远循环。
    记住这条配对规则
    mid 向下取整时（lo + (hi-lo)/2）：hi = mid 安全（mid < hi 恒成立），lo = mid 不安全，必须写 lo = mid + 1。
    如果逻辑确实需要 lo = mid，就把 mid 改成向上取整：lo + (hi - lo + 1) / 2，此时 mid > lo 恒成立，lo = mid 变安全而 hi = mid 变不安全。取整方向和赋值方式必须配对。
    另一类：区间约定混用
    初始 hi = n（半开）但循环条件写 lo <= hi（闭区间的写法）→ 会访问 a[n] 越界。一份代码里只用一种区间约定。
    结构上的根治
    写一个循环不变式并保证每轮都成立，终止性就是自动的推论：hi = mid 时新长度 mid - lo < hi - lo；lo = mid+1 时新长度 hi - mid - 1 < hi - lo。两个分支都严格缩短 ⟹ 至多 ⌈log₂n⌉ 轮必然退出。
  3. 基础lower_bound 和 upper_bound 的区别是什么？怎么用它们数出 x 出现了几次？
    返回谓词
    lower_bound(x)第一个 不小于 x（≥ x）的位置a[i] >= x
    upper_bound(x)第一个 大于 x（> x）的位置a[i] > x

    对 [1,3,5,5,5,7,9] 查 x=5：lower_bound=2、upper_bound=5。

    一句话记牢
    两者夹出的 [lo, up) 就是所有等于 x 的元素。所以：
    · 出现次数 = up - lo（等于 0 就是不存在）
    · 最后一个 < x 的位置 = lo - 1
    · 最后一个 ≤ x 的位置 = up - 1
    · equal_range 一次同时返回两者
    auto [lo, up] = std::equal_range(v.begin(), v.end(), x);
int count = up - lo;
bool exists = (lo != up);
    「最后一个」要检查 −1
    当所有元素都 ≥ x 时 lower_bound 返回 0，减一得 −1 → 表示不存在。忘了检查就是 a[-1] 越界。这是「找最后一个」比「找第一个」更易错的唯一原因——不是逻辑更难，而是多了一个要显式处理的失败返回值。
    别二分两次
    binary_search 只返回 bool，拿不到位置。「先 binary_search 判存在再 lower_bound 取位置」是二分了两次。直接 lower_bound 一次，然后查 it != last && *it == x。
  4. 基础二分查找的前提是什么？「数组必须有序」这个说法准确吗？

    不准确，它太窄了。真正的前提是：存在一个在区间上单调的布尔谓词——即存在某个分界点，之前全假、之后全真。

    「有序数组找目标值」只是取 P(i) = (a[i] >= target) 的特例。只要能构造出单调谓词，二分就适用——数组不必存在，答案也不必是下标。

    三个「不是有序数组」但能二分的例子：

    git bisect
    提交历史不是排好序的数字，找的也不是某个值，而是「状态从好翻转到坏」的位置。谓词是「这个提交上 bug 存在吗」，单调性来自「bug 一旦引入就一直存在」。
    二分答案
    「最小的能在 D 天内运完的船载重」——根本没有数组，二分的是答案的值域。谓词是 feasible(cap)。
    山峰数组
    数组本身不单调（先增后减），但导出量 a[i] > a[i+1]（「是否已开始下降」）单调。
    这也说明了失效条件
    谓词不单调时，二分不会报错，只会安静地给出错误答案。所以每次用二分都要先确认单调性，而不是假设它成立。git bisect 遇到 flaky test 就是这么被带偏的。

10.2 中级（区分熟练度）

  1. 中级写出二分的循环不变式，并用它证明算法的正确性与终止性。

    对 [lo, hi) 半开区间模板：

    不变式 答案 ∈ [lo, hi]，即 ∀ i < lo: P(i) 为假 ∀ i ≥ hi: P(i) 为真

    三步走：

    ① 初始化
    lo=0, hi=n。「∀ i < 0 假」和「∀ i ≥ n 真」都是空真（vacuously true）。✓
    ② 保持
    由 mid = lo + (hi-lo)/2 得 lo ≤ mid < hi。
    · P(mid) 真 → 由单调性 ∀ i ≥ mid 皆真 → 答案 ≤ mid → 置 hi = mid，不变式保持。
    · P(mid) 假 → 由单调性 ∀ i ≤ mid 皆假 → 答案 > mid → 置 lo = mid+1，不变式保持。✓
    ③ 终止时给出答案
    退出时 lo == hi，不变式给出「∀ i < lo 假、∀ i ≥ lo 真」⟹ lo 就是第一个使 P 为真的下标。∎
    ④ 必然终止
    hi = mid 时新长度 mid − lo < hi − lo（因 mid < hi）；lo = mid+1 时新长度 hi − mid − 1 < hi − lo。两分支都严格缩短 ⟹ 至多 ⌈log₂n⌉ 轮。∎
    这个方法的价值
    写二分时不靠试错试出 < 还是 <=，而是先写下不变式，让边界从不变式里推出来。这样每次都能证明它对，而不是「跑几个用例看着没错」。
    循环不变式是验证任何循环的通用工具，不只用于二分——它也是 Dijkstra、并查集、Floyd 等算法正确性证明的骨架。
  2. 中级什么是「二分答案」？举一道题说明怎么把「求最优」变成「判定可行」。

    直接求最优值 x* 往往很难；但给定一个候选值判断它可行不可行，常常容易得多。如果 feasible(x) 关于 x 单调，就在答案的值域上二分找分界点。

    代价：O(log(值域) × 一次判定的代价) 收益：判定通常只要贪心扫一遍，而求最优可能要 DP 甚至枚举

    例 · 分割数组的最大值最小化：把数组分成 k 个连续子数组，使各段和的最大值最小。

    // 判定：以 limit 为「每段和上限」，能否分成 ≤ k 段？→ 贪心 O(n)
bool feasible(const std::vector<int>& a, long long limit, int k) {
    int segs = 1; long long cur = 0;
    for (int x : a) {
        if (x > limit) return false;
        if (cur + x > limit) { ++segs; cur = x; } else cur += x;
    }
    return segs <= k;
}
// 值域：[max(a), sum(a)]，套 §3 模板一字不改 → O(n log(sum))
// 对比直接 DP 的 O(n²k)
    三个识别信号
    ① 题目说「最小化最大值」或「最大化最小值」；② 答案是数值且值域已知/易估；③ 验证一个候选答案比找到它容易。三个都命中就基本确定。
    同类题
    船运载重（D 天运完）、木材切割（得 k 段长 ≥ L）、爱吃香蕉的珂珂（H 小时吃完）、第 k 小的距离对、最小化最大等待时间。判定函数几乎总是「贪心扫一遍 + 计数」。
    还有一类：二分「有多少个 ≤ x」
    「有多少个元素 ≤ x」关于 x 天然单调递增，所以任何「第 k 小」问题都可以试着二分答案 + 数个数。这在「有序矩阵第 k 小」「第 k 小的距离对」里是标准解法。
  3. 中级在旋转有序数组里查找一个数怎么做？有重复元素时会怎样？

    数组不全局有序，但任意一次划分后至少有一半是有序的——这就是可二分的依据。

    解法一 · 判断哪半有序：比较 a[lo] 与 a[mid]，然后在有序的那半里判断 target 是否落在其中。

    if (a[lo] <= a[mid]) {                     // 左半有序
    if (a[lo] <= target && target < a[mid]) hi = mid - 1;
    else                                    lo = mid + 1;
} else {                                    // 右半有序
    if (a[mid] < target && target <= a[hi]) lo = mid + 1;
    else                                    hi = mid - 1;
}
    解法二（更推荐）· 先找旋转点
    把它变成一个标准的谓词二分：谓词 P(i) = (a[i] <= a[n-1]) 在旋转数组上恰好单调（前段是旋转前的大值 → 假，后段是小值 → 真）。
    while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (a[mid] <= a[hi]) hi = mid; else lo = mid + 1;
}   // lo = 最小值下标
    找到旋转点后在对应的有序段做标准二分。好处是模板一字不改——这正是「构造单调谓词而不是重新设计二分」的做法。
    有重复元素时退化 O(n)
    [1,1,1,0,1,1,1] 找 0：a[lo] == a[mid] == 1，无法判断哪半有序，只能 ++lo 逐个收缩。
    而且这个 O(n) 不可改善
    考虑 [1,1,...,1,0,1,...,1]——那个 0 可能在任何位置，且任何比较都无法排除超过常数个候选。所以 O(n) 是信息论下界，不是实现不够好。面试时能指出这一点是加分项。
  4. 中级为什么在 std::set 上不该用 std::lower_bound？std::partition_point 又是什么？

    因为 std::lower_bound 保证的是 O(log n) 次比较，而不是 O(log n) 的运行时间。

    // 实现里维护 len 而不是 last，用 advance 推进
auto half = len >> 1;
It mid = first;
std::advance(mid, half);      // ← 关键
    迭代器类别比较推进总复杂度
    RandomAccess（vector）O(log n)O(log n)O(log n)
    Bidirectional（set / list）O(log n)O(n)O(n)

    在 set 上，advance 要沿红黑树中序一步步走。所以 std::lower_bound(s.begin(), s.end(), x) 能编译、结果对，但 O(n)——甚至比线性扫描更慢（同样 O(n) 移动，外加 log n 次比较）。

    正确做法
    用成员函数 s.lower_bound(x)——它直接沿红黑树从根往下走，真正 O(log n)。
    通用规则：容器提供了同名成员函数时一律用成员函数，因为它能利用内部结构而算法版只能通过迭代器接口。同类差异还有 set::find vs std::find、string::find vs std::search。
    partition_point（被低估的一个）
    C++11 的 std::partition_point(first, last, P) 返回第一个使谓词 P 为假的位置，要求区间已按 P 划分（也就是「谓词单调」的另一种说法）。
    它就是本文 §3 的谓词版模板。凡是「有序但不是按元素值排序」的二分——按某个派生字段、按外部条件——用它比硬凑一个 comparator 干净得多。

10.3 高级（体现深度）

  1. 高级你用二分答案解了一道题，但线上偶尔给出错误结果。可能是什么原因？

    二分答案最危险的性质是：单调性不成立时它不会报错，只会安静地给出错误答案。「偶尔错」这个描述指向三类问题。

    ① 谓词根本不单调
    典型是带「恰好」「正好等于」的约束。比如「选恰好 k 个元素使和等于 v」——feasible 序列可能是 F T F T，二分会随机落到某个可行点。
    放宽资源反而可能让「恰好」失效，这是单调性被破坏的最常见来源。这类题的正解通常是 DP，不是二分。
    ② 判定函数不确定（有随机性/依赖外部状态）
    如果 feasible 读了缓存、依赖当前时间、或用了浮点累加导致同一输入两次结果不同——那就是 git bisect 遇到 flaky test 的情形：一次误判会把整个二分带偏，而且表现为「偶发」。
    判定函数必须是纯函数。
    ③ 值域上下界估错
    下界比真实答案大、或上界比真实答案小，二分会返回边界值。这类错误只在数据接近极端时暴露，所以也表现为「偶尔」。上下界宁可放宽——多几轮迭代的代价可以忽略。

    怎么定位和根治：

    对拍验证单调性
    小数据下把值域全部枚举一遍，打印 feasible 序列，肉眼确认它是 FFF...FTTT...T 而不是交替的。这是最直接的验证，应该作为写二分答案的标准步骤。
    写下形式化的蕴含式
    明确写出 feasible(x) ⟹ feasible(x')（x' 是更宽松那侧）并给出一句话理由。最常用的理由是「原方案在放宽约束后仍然合法」——如果你说不出这句话，单调性很可能不成立。
    断言 + 暴力对拍进 CI
    把「小规模下二分答案 == 暴力枚举」写成一个属性测试挂进 CI。二分答案的正确性依赖一个数学性质而不是代码逻辑，所以它需要的是性质测试而不是几个用例。
  2. 高级B+ 树里二分出现在哪几个层次？为什么 B+ 树要设计成「又矮又胖」？

    两个层次，而它们的代价单位完全不同——这正是 B+ 树设计的全部动机。

    层次次数单次代价优化目标
    树高（跨页导航）log_B(n)一次磁盘/SSD I/O ≈ 100 µs把 B 做大 → 树高尽量低
    页内二分log₂B ≈ 8–10一次内存访问 ≈ 100 ns次要（差 1000 倍）
    为什么又矮又胖
    把节点做成一个磁盘页大小（4–16 KB），每页能放几百个 key，于是 B ≈ 数百：
    log_B(10⁹) ≈ 3~4 ← 十亿行只需 3~4 次 I/O log₂(10⁹) ≈ 30 ← 二叉搜索树要 30 次 I/O
    B+ 树的全部智慧就是「用页内的廉价二分（100 ns）换掉昂贵的跨页跳转（100 µs）」。
    B+ 而不是 B 的额外理由
    B+ 树把数据只放叶子、内部节点只放 key。这让内部节点能塞更多 key（B 更大 → 树更矮），而且叶子按序链成链表，范围扫描（WHERE x BETWEEN a AND b、ORDER BY）变成顺序 I/O 而不是回树遍历。
    同一思路的其他化身
    跳表：用多层链表模拟二分，每层跳过约一半——本质是「链表上的二分」，而且靠随机层高避免了红黑树的旋转（Redis ZSet 用它）。
    LSM-Tree 的 SSTable：块索引 + 块内二分，外加 Bloom 过滤器先挡掉不存在的 key。
    Parquet/ORC 列存：先用块级 min/max 统计剪枝，再在块内二分。
    cache 层的 B 树：把同一思路下移一层——一个 cache line 放多个 key，用 SIMD 一次比较 8–16 个，把「内存访问」当成新的「磁盘 I/O」来省。
    展开见 存储与数据架构。
  3. 高级一个 4 GB 的只读有序索引，二分查询是热点。怎么优化？

    标准二分在超出 cache 的大数组上渐进最优但常数很差：前几步跳跃距离是 n/2、n/4、n/8……每步一次 cache miss，而且预取器完全失效（下一步位置依赖当前比较结果，不可预测）。4 GB 数据 ≈ 10⁹ 个 int，log₂n ≈ 30 步，前约 20 步全是主存访问 → 单次查询约 2 µs 里绝大部分在等内存。

    ① 分支消除（最容易，先做这个）
    用条件移动代替分支：lo += cond ? half+1 : 0。二分的分支本质不可预测（约 50% 误预测率），每次误预测约 15–20 周期。写成 cmov 形式后能省掉这部分。
    ② eytzinger 布局（收益最大）
    把二叉搜索树按层序（BFS）压平存放：root 在下标 1，子节点在 2i / 2i+1。
    好处：前几层挤在同一条 cache line 里，头几步几乎零 miss；下标计算是纯乘法，无分支。
    代价：只适合只读索引——布局要预先构建，不支持随时插入。
    ③ B 树式扁平索引（终极方案）
    把 B+ 树的思路下移到 cache 层：一个 cache line（64 B）放 16 个 int32 key，用 SIMD 一次比较 16 个，一次 cache miss 换 4 位信息（而标准二分一次 miss 只换 1 位）。树高从 30 降到约 8。这是现代内存索引（如 ART、Masstree、FAST）的核心手段。
    ④ 插值查找（看分布）
    数据近似均匀时按值估算位置，期望 O(log log n)。但分布不均时退化到 O(n)，所以生产上要做成「插值探测几步，不收敛就退回二分」的混合形式。
    ⑤ 预取
    __builtin_prefetch 提前取两个可能的下一步。用一半带宽换延迟——只在带宽有余量时划算。
    但先问两个问题
    ① 这段二分在 profile 里真的超过 5% 了吗？如果没有，以上全是过早优化。② 能不能换掉二分？如果查询是点查且不需要范围扫描，一个哈希表就是 O(1)——比任何二分优化都强。如果查询有局部性（相邻查询的 key 接近），加一层缓存或改成从上次位置开始的指数搜索（galloping）可能比优化二分更有效。
    算法层面的选择永远排在常数优化之前。测量方法见 性能优化指南。
  4. 高级浮点二分为什么建议固定迭代次数而不是用 eps 判终止？有哪些别的坑？
    用 eps 的两个问题
    ① 大数值时死循环：while (hi - lo > 1e-9) 在 lo, hi ≈ 1e18 时，相邻 double 的间隔已远大于 1e-9 → 条件永远为真 → 挂死。
    ② eps 难定：取大了精度不够，取小了白跑（甚至不收敛）。而且它耦合了「算法」和「题目精度要求」两件事。
    固定迭代次数
    for (int it = 0; it < 100; ++it) {
    double mid = lo + (hi - lo) / 2;
    if (ok(mid)) hi = mid; else lo = mid;
}
    double 有 53 位有效位 → 相对精度上限约 2⁻⁵³ ≈ 1.1e-16，约 60 轮就已到极限（再多轮 lo/hi 会变成相邻浮点数，区间无法再缩）。100 轮是保守余量，开销可忽略。
    关键是把循环次数变成与数值大小无关的常数。

    其他坑：

    用 lo < hi 判终止
    浮点上这几乎必然死循环——mid 会变成等于 lo 或 hi，区间不再缩小但 lo != hi。浮点二分不能用严格不等式判终止。
    用绝对 eps 判「相等」
    fabs(a-b) < 1e-9 在大数上判不出、在小数上过早判定。要用相对误差：fabs(a-b) <= eps * max(1.0, fabs(a))。
    输出精度
    算对了但 cout 默认只输出 6 位有效数字。要 printf("%.10f") 或 setprecision(10)。
    最好的办法：整数化
    很多「浮点二分」的题可以乘以 10^k 变成整数二分（要求保留 4 位小数就在 [0, ans_max*10⁴] 上做整数二分）。这样既避开全部浮点陷阱，又精确控制精度。
    能整数化就整数化——和「金额用『分』而不是浮点『元』」是同一个原则。
