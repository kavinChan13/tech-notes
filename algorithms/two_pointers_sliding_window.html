双指针与滑动窗口

这一类技巧的共同点只有一句：让某个指针全程只往一个方向走，绝不回退。回退是 O(n²) 的来源，不回退就是 O(n)。所以真正要练的不是模板，而是「凭什么可以不回退」——每道题都要能说出那个让你敢丢掉一半候选的性质。本篇把这个论证讲清，再把三类指针和窗口的四步骨架收成一套可迁移的写法。

核心难度 ★★★☆☆ 面试出现率 极高 阅读时长 ~36 min 前置 复杂度与分析
势能法证 O(n) Floyd 判圈 窗口四步骨架 恰好 K 的拆解 限流与 TCP 窗口
01

本质：单调推进

不回退，所以线性

「双指针」这个名字有误导性——它描述的是形式（有两个下标变量），而不是机制。真正让复杂度从 O(n²) 掉到 O(n) 的机制是：

单调推进（monotone advancement）：算法维护若干个下标，每个下标在整个执行过程中只沿一个方向移动，总移动量 O(n)。于是即便代码写成嵌套循环，循环体的总执行次数仍是 O(n)。

这要求一个前提：每次移动指针时，你必须能确定性地排除掉一批候选解，且被排除的候选永远不必再看。这个「凭什么能排除」的论证，是双指针题的全部难点——模板谁都会背，论证才决定你写的对不对。
对撞指针像两个人从走廊两端相向找门牌号。你在左端看到号码太小，就确定左边这一间以及它左边所有间都不可能是答案——因为号码是递增的。于是你安心右移一步，永远不回头。

关键不在「有两个人」，而在走廊上号码递增这个性质。如果号码乱排（无序数组），你左移右移都排除不了任何东西，两个人来回走也还是要试遍所有组合。所以「数组有序」不是解法的装饰，它就是解法本身。

本篇按「指针怎么动」分四类，每类都先给出排除性论证，再给模板：

类型指针怎么动靠什么性质排除候选典型题
对撞（§3）两端向中间有序性 / 单调的目标函数两数之和、三数之和、盛水容器
快慢（§4）同向不同速相对位移的周期性环检测、找中点、倒数第 k 个
同向读写（§5）同向同速，读快于写写指针左侧已是最终结果原地去重、移除、分区
滑动窗口（§6）右扩左缩，都不回退约束关于窗口长度单调最长无重复子串、最小覆盖子串

  • 复杂度与分析 —— §2 的 O(n) 论证用的正是那里的势能法

02

为什么两层循环是 O(n)

这个论证要能随手写出来

2.1 势能视角的证明

先看这段代码——它是两层循环，但复杂度是 O(n) 而不是 O(n²)：

int j = 0;
for (int i = 0; i < n; ++i) {
    while (j < n && ok(i, j)) ++j;   // j 在整个函数里只增不减
    use(i, j);
}
错误的数法 外层 n 次 × 内层最坏 n 次 = O(n²) ——这个上界成立，但太松，没抓住关键。 正确的数法 分开数两件事： · 外层循环体执行次数：恰好 n 次 · 内层 ++j 的总执行次数：j 从 0 单调增到至多 n ⟹ 无论分布在哪几轮外层里，总量 ≤ n 总代价 = n（外层）+ n（内层总量）= O(n) ∎

这就是摊销分析里的势能法：取势能 Φ = j（一个单调不减、上界为 n 的量）。内层每执行一次就让 Φ 增加 1，而 Φ 总增量不超过 n，所以内层总次数 ≤ n。

写双指针题时的自检问题：我能指出一个单调变化且有界的量吗？
  • 对撞指针：Φ = right − left（区间长度），每轮至少减 1，初值 n ⟹ 至多 n 轮。
  • 滑动窗口：Φ = left + right，两者都只增、各至多 n ⟹ 总移动 ≤ 2n。
  • 同向读写：Φ = 读指针位置，只增 ⟹ n 次。
指不出这个量，就说明你的解法可能不是 O(n)。

2.2 论证何时失效

把「双指针」当成万能模板套上去是常见错误。下面两个例子形式上像双指针，实际不是 O(n)：

❌ 内层指针会回退 → O(n²)
for (int i = 0; i < n; ++i) {
    int j = i;                  // ← 每轮重置！
    while (j < n && ok(i, j)) ++j;
}
// j 的总移动量是 O(n²)，不是 O(n)
// 这只是「两个变量」，不是双指针
❌ 约束不单调 → 窗口不能只缩不扩
// 「子数组乘积 < K」，但数组含负数
// 乘积不随窗口变长而单调变化：
//   [2, -3, 2] 乘积 = -12 < K
//   [2, -3]    乘积 = -6
//   [2]        乘积 = 2
// → 缩小窗口不保证「更容易满足」
// → 滑动窗口不适用，要用前缀积 + 分类讨论
右边这个失效条件极其重要，也是面试高频追问：滑动窗口要求「约束关于窗口的伸缩单调」——即「窗口合法」这个性质满足：如果 [l, r] 合法，那么它的任意子区间也合法（或反向单调）。

数组全为正数时和/积随窗口变长单调递增，所以窗口可用。一旦出现负数或 0，这个单调性就断了，必须换成前缀和 + 哈希表（见 前缀和）或前缀积 + 分类讨论。「数组元素是否全为正」是滑动窗口题的隐藏前提，读题时要主动去找。
03

对撞指针

两端向中间，每步排除一整行或一整列

3.1 有序两数之和

有序数组里找两个数使和为 target。朴素双层循环 O(n²)，对撞指针 O(n)。

std::pair<int, int> two_sum_sorted(const std::vector<int>& a, int target) {
    int l = 0, r = (int)a.size() - 1;
    while (l < r) {
        int s = a[l] + a[r];
        if (s == target) return {l, r};
        if (s < target) ++l;   // 和太小 → 必须换更大的左端
        else            --r;   // 和太大 → 必须换更小的右端
    }
    return {-1, -1};
}

正确性的关键是排除性论证，必须能说清：

论证：设当前 a[l] + a[r] < target。因为数组有序，a[r] 是剩余候选里最大的右端。既然 a[l] 配上最大的右端都还不够，那 a[l] 配任何剩余右端都不够 ⟹ 包含下标 l 的所有候选对都可以丢弃，于是 ++l 不会漏解。对称地，和太大时 --r 也不漏解。∎
无序数组的两数之和不能用对撞指针（没有可排除的性质），标准解法是哈希表一遍扫（O(n) 时间 O(n) 空间）。
反过来，如果题目要求返回原始下标而数组无序，排序会破坏下标——此时要么排 (值, 原下标) 的 pair，要么直接用哈希表。「要不要保留原下标」决定了该排序还是该用哈希表。

3.2 三数之和与去重

三数之和 = 固定一个 + 对撞找另两个，O(n²)。难点全在去重。

std::vector<std::vector<int>> three_sum(std::vector<int> a) {
    std::sort(a.begin(), a.end());
    std::vector<std::vector<int>> res;
    int n = (int)a.size();

    for (int i = 0; i < n - 2; ++i) {
        if (a[i] > 0) break;                       // 剪枝：最小的已 > 0
        if (i > 0 && a[i] == a[i - 1]) continue;   // 去重①：跳过重复的第一个数

        int l = i + 1, r = n - 1;
        while (l < r) {
            int s = a[i] + a[l] + a[r];
            if (s < 0) ++l;
            else if (s > 0) --r;
            else {
                res.push_back({a[i], a[l], a[r]});
                ++l; --r;
                // 去重②：跳过与刚用过的相同的值
                while (l < r && a[l] == a[l - 1]) ++l;
                while (l < r && a[r] == a[r + 1]) --r;
            }
        }
    }
    return res;
}
去重必须在两个位置都做，而且写法有讲究：
  • 去重①用 a[i] == a[i-1] 而不是 a[i] == a[i+1]。用后者会把「三个相同数刚好构成解」（如 [0,0,0]）也跳掉。规则：去重时总是和「已处理过的前一个」比，不和「还没处理的后一个」比。
  • 去重②要在 ++l; --r; 之后做，比较对象是 a[l-1] / a[r+1]（刚用过的那个值）。
另一种更省心的写法是先收集再 sort + unique，代价是多一次 O(m log m)。面试里手写去重更能体现细节把控，但要说清上面两条。

3.3 盛水容器：贪心正确性

「盛最多水的容器」：给定高度数组，选两条线与 x 轴构成容器，求最大蓄水量 min(h[l], h[r]) × (r − l)。这题的对撞指针写法只有五行，但正确性论证是本节最值得学的一处。

int max_area(const std::vector<int>& h) {
    int l = 0, r = (int)h.size() - 1, best = 0;
    while (l < r) {
        best = std::max(best, std::min(h[l], h[r]) * (r - l));
        // 移动较矮的那一侧
        if (h[l] < h[r]) ++l; else --r;
    }
    return best;
}
为什么必须移动较矮的一侧（反证）：设 h[l] < h[r]，考虑所有以 l 为左端的候选 (l, r')，其中 r' < r。
  • 宽度：r' − l < r − l，严格变小。
  • 高度：min(h[l], h[r']) ≤ h[l] = min(h[l], h[r])，不会变大（因为已被 h[l] 卡住）。
两个因子都不增，所以这些候选全都不优于当前的 (l, r) ⟹ 包含 l 的候选可以整行丢弃 ⟹ ++l 不漏最优解。∎

反之若移动较高的一侧（--r），高度仍被 h[l] 卡住、宽度还变小，但你丢掉的那一列里可能藏着更优解（那个更高的 h[r] 配上别的左端），所以会错。
这个论证像木桶原理决定该换哪块板。桶能装多少水由最短的那块板决定。现在桶变窄一定是损失，所以唯一可能赚回来的办法是换掉最短的板——换长板毫无意义，因为短板还在那儿卡着，你只是让桶变窄了。

面试时把这句话说出来，比背代码有用得多：「宽度必然减小，所以只有可能提升高度上限的动作才值得做，而高度上限由短板决定。」
04

快慢指针

同向不同速，用相对位移做检测

4.1 Floyd 判圈

判断链表是否有环。哈希表记录访问过的节点是 O(n) 时间 O(n) 空间；Floyd 判圈（龟兔赛跑）做到 O(n) 时间 O(1) 空间。

bool has_cycle(Node* head) {
    Node* slow = head;
    Node* fast = head;
    while (fast && fast->next) {
        slow = slow->next;          // 每次 1 步
        fast = fast->next->next;    // 每次 2 步
        if (slow == fast) return true;
    }
    return false;   // fast 走到 nullptr → 无环
}
为什么一定会相遇（有环时）：一旦两者都进入环，考察它们的相对位移——快指针每轮比慢指针多走 1 步，所以两者的环内距离每轮恰好减少 1。距离是环长内的非负整数，每轮减 1，所以最多 环长 轮后必然变成 0，即相遇。∎

为什么步长必须是 1 和 2：若快指针每次走 3 步，相对位移每轮减 2——当环长为偶数而初始距离为奇数时，距离会在奇数间跳变，永远跨过 0 而不等于 0。步长差为 1 才保证「距离逐个递减、不可能跳过 0」。这是本题最常被追问的一点。

4.2 找环入口的证明

相遇之后，把一个指针放回头部，两者同速前进，再次相遇处就是环入口。这个结论的推导值得完整看一遍：

Node* cycle_entry(Node* head) {
    Node *slow = head, *fast = head;
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) {              // 相遇
            Node* p = head;
            while (p != slow) {          // 同速前进
                p = p->next;
                slow = slow->next;
            }
            return p;                    // 环入口
        }
    }
    return nullptr;
}
同一套数学还能解「寻找重复数」（把数组 a[i] 看成「i → a[i]」的隐式链表，重复数就是环入口）和「快乐数」（数字变换的循环检测）。
识别信号：题目里有一个「确定性的后继函数 f(x)」且状态空间有限——那么从任意起点出发必然进入循环，Floyd 就适用，而且空间 O(1)。

4.3 中点与倒数第 k 个

找中点（一遍扫）
Node* middle(Node* head) {
    Node *slow = head, *fast = head;
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
    }
    return slow;
}
// 偶数个节点时返回后中点
// 想要前中点：while (fast->next && fast->next->next)
倒数第 k 个（固定间距）
Node* kth_from_end(Node* head, int k) {
    Node* fast = head;
    for (int i = 0; i < k; ++i) {
        if (!fast) return nullptr;   // k > 长度
        fast = fast->next;
    }
    Node* slow = head;
    while (fast) { fast = fast->next; slow = slow->next; }
    return slow;
}
// 关键：先让 fast 领先 k 步，然后同速走到底
「偶数个节点返回前中点还是后中点」是链表题最容易踩的边界。判断方法：手推 n=2 的情形。while(fast && fast->next) 在 n=2 时执行一轮，slow 落到第 2 个 → 后中点。这类题一律用 n=0,1,2 手推，比记规则可靠。
另外，删除节点类的题（如「删除倒数第 k 个」）要用哑头节点（dummy head），否则删除头节点要单独写一个分支。

同向读写指针

STL 的 remove / unique 就是这个模式

5.1 std::remove 的真相

这个模式最好的教材就是 STL 自己。std::remove 是很多人误用的算法：

// libstdc++ 的 remove（简化）
template<typename It, typename T>
It remove(It first, It last, const T& value) {
    first = std::find(first, last, value);      // 跳到第一个要删的
    if (first == last) return first;
    It write = first;                            // 写指针
    for (It read = ++first; read != last; ++read) // 读指针
        if (!(*read == value))
            *write++ = std::move(*read);         // 保留的往前搬
    return write;                                // 新的逻辑末尾
}
std::remove 不会真的删除元素，也不改变容器大小。它只是把「保留的元素」搬到前面，返回新的逻辑末尾；后面那段是未指定的值（被 move 走的空壳）。所以必须配 erase： 
// ❌ 什么都没删掉，size 不变
std::remove(v.begin(), v.end(), 3);

// ✅ erase-remove 惯用法
v.erase(std::remove(v.begin(), v.end(), 3), v.end());

// ✅ C++20 起直接一行（推荐）
std::erase(v, 3);
std::erase_if(v, [](int x){ return x % 2; });
为什么标准要这么设计？因为算法只拿到迭代器，拿不到容器——它无法调用 erase 改变大小。这是 STL「算法与容器解耦」的代价，也是 C++20 补上 std::erase 的原因。

5.2 原地去重与分区

任务不变式（写指针左侧的性质）STL 对应
移除等于 v 的元素[0, write) 都不等于 vstd::remove
去除相邻重复[0, write) 无相邻重复std::unique
按谓词分区[0, write) 全满足谓词std::partition
移动零到末尾[0, write) 全非零且保持原序—（手写）
 
// 有序数组去重，每个值最多保留 k 个（通用版）
int dedup_at_most_k(std::vector<int>& a, int k) {
    int write = 0;
    for (int x : a) {
        // 不变式：a[0..write) 已合法。只要「往前数第 k 个」不等于 x，就还能放
        if (write < k || a[write - k] != x)
            a[write++] = x;
    }
    return write;   // 新长度
}
// k=1 → 完全去重；k=2 → 每个值最多两个。一份代码覆盖两道经典题
这个 a[write - k] != x 的写法值得记住：它把「已写入部分」当成状态来查询，而不是另外维护计数器。因为数组有序，往前数第 k 个若不等于 x，就说明当前已写入的 x 少于 k 个。
能这样写的前提是输入有序——无序输入要退回哈希表计数。又一次说明：先看清题目给的性质，再选工具。
std::unique 只去除相邻重复，所以要先排序才能全局去重（sort + unique + erase）。这也是它和「哈希去重」的分工点：sort+unique 是 O(n log n) 时间 O(1) 空间且结果有序；哈希去重是 O(n) 时间 O(n) 空间且不保序（或用 unordered_set + 保序遍历）。

滑动窗口统一模板

四步骨架，覆盖绝大多数窗口题

6.1 定长窗口

定长窗口最简单：右进一个、左出一个，维护窗口内的聚合量。

// 长度为 k 的子数组的最大和
long long max_sum_k(const std::vector<int>& a, int k) {
    long long sum = 0, best = LLONG_MIN;
    for (int r = 0; r < (int)a.size(); ++r) {
        sum += a[r];                        // ① 右端进入
        if (r >= k) sum -= a[r - k];        // ② 左端离开（超长才减）
        if (r >= k - 1) best = std::max(best, sum);  // ③ 窗口满了才统计
    }
    return best;
}
两个 off-by-one 高发点：if (r >= k) 用于「移出」（此时窗口长度是 k+1，需要缩回 k），而 if (r >= k-1) 用于「统计」（此时窗口长度正好 k）。两个条件差 1，写混了就会漏掉第一个窗口或多算一个。
可靠的做法是明确写出「循环体开头 sum 代表 a[r-k+1..r] 的和」这个不变式，再逐行核对。

6.2 变长窗口的四步骨架

变长窗口是真正需要模板的地方。骨架永远是这四步：

求最长：统计在 while 之后
// 最长无重复字符子串
int longest_unique(const std::string& s) {
    int cnt[128] = {}, l = 0, best = 0;
    for (int r = 0; r < (int)s.size(); ++r) {
        ++cnt[(unsigned char)s[r]];              // ①
        while (cnt[(unsigned char)s[r]] > 1)      // ② 不合法就缩
            --cnt[(unsigned char)s[l++]];
        best = std::max(best, r - l + 1);       // ③ 缩完才统计
    }
    return best;
}
求最短：统计在 while 之内
// 和 ≥ target 的最短子数组（全正数）
int min_len_ge(const std::vector<int>& a, int target) {
    long long sum = 0;
    int l = 0, best = INT_MAX;
    for (int r = 0; r < (int)a.size(); ++r) {
        sum += a[r];                            // ①
        while (sum >= target) {                 // ② 已合法就缩
            best = std::min(best, r - l + 1);   // ③ 缩之前统计
            sum -= a[l++];
        }
    }
    return best == INT_MAX ? 0 : best;
}

6.3 「恰好 K」的拆解

滑动窗口天然处理「至多 K」（约束单调），但直接处理「恰好 K」会失效——因为「恰好 K 个不同元素」不满足「子区间也合法」。标准解法是做差：

恰好 K = 至多 K − 至多 (K−1) 写成代码： exactly(K) = atMost(K) - atMost(K - 1) 其中 atMost(m) 用标准变长窗口，统计「以每个 r 结尾的合法子数组个数」： ans += r - l + 1
// 恰好 K 个不同整数的子数组个数
long long at_most(const std::vector<int>& a, int m) {
    if (m < 0) return 0;
    std::unordered_map<int, int> cnt;
    long long ans = 0;
    int l = 0;
    for (int r = 0; r < (int)a.size(); ++r) {
        ++cnt[a[r]];
        while ((int)cnt.size() > m)
            if (--cnt[a[l++]] == 0) cnt.erase(a[l - 1]);
        ans += r - l + 1;      // 以 r 结尾的合法子数组有 r-l+1 个
    }
    return ans;
}

long long exactly_k(const std::vector<int>& a, int k) {
    return at_most(a, k) - at_most(a, k - 1);
}
为什么 ans += r - l + 1 是「个数」而不是「长度」：收缩完成后，[l, r] 是以 r 结尾的最长合法子数组。由于「至多 m」满足子区间也合法，那么 [l, r], [l+1, r], …, [r, r] 全都合法，共 r − l + 1 个。
把每个 r 的贡献加起来就是总个数——「枚举右端点，统计以它结尾的合法区间数」是所有「求子数组个数」题的通用框架，不只用于窗口。
同一个「做差」技巧的其他形态：「恰好 K 个奇数」「恰好 K 个不同字符」「和恰好为 K」（前缀和版）。识别信号是：题目要「恰好」，而你的工具只会「至多 / 至少」——那就做差。
注意 at_most(k-1) 在 k=0 时参数为负，要显式返回 0（代码里第一行那个守卫）。

窗口的三种约束类型

状态用什么维护，取决于约束长什么样

7.1 计数型

约束是「窗口内某类元素的个数」：不同字符数 ≤ K、重复字符数 = 0、奇数个数 ≤ K。状态用计数数组或哈希表维护。

字符集状态容器理由
ASCII 小写字母int cnt[26]最快，无分配、cache 友好
完整 ASCIIint cnt[128]同上；注意用 unsigned char 索引
任意整数 / 宽字符unordered_map值域太大，只能哈希
只关心「有没有」uint32_t 位掩码26 个字母用一个 int 的 26 位，判重是一次位运算
用 char 直接做数组下标是经典 UB 来源：char 在多数平台上是有符号的，遇到非 ASCII 字节（如 UTF-8 中文的高位字节）会得到负数下标。
// ❌ 中文输入直接越界
++cnt[s[r]];

// ✅
++cnt[(unsigned char)s[r]];
更彻底的做法：处理可能含多字节字符的输入时，不要按字节开窗口——UTF-8 的一个字符占 1–4 字节，按字节滑动会切断字符。要么先解码成码点序列，要么改用哈希表以字符串切片为键。

7.2 覆盖型

约束是「窗口包含了目标集合的全部元素（含重数）」。经典题是最小覆盖子串。难点在于怎么 O(1) 判断「已覆盖」。

// 最小覆盖子串：s 中包含 t 所有字符（含重数）的最短子串
std::string min_window(const std::string& s, const std::string& t) {
    int need[128] = {}, have[128] = {};
    for (unsigned char c : t) ++need[c];

    int required = 0;                       // t 中不同字符的种数
    for (int c = 0; c < 128; ++c) required += (need[c] > 0);

    int formed = 0;                         // 已「满额」的字符种数 ← 关键
    int l = 0, bl = 0, blen = INT_MAX;

    for (int r = 0; r < (int)s.size(); ++r) {
        unsigned char c = s[r];
        ++have[c];
        if (need[c] > 0 && have[c] == need[c]) ++formed;   // 恰好满额时 +1

        while (formed == required) {          // 已合法 → 一边缩一边统计
            if (r - l + 1 < blen) { blen = r - l + 1; bl = l; }
            unsigned char d = s[l++];
            if (need[d] > 0 && have[d] == need[d]) --formed;  // 掉出满额时 -1
            --have[d];
        }
    }
    return blen == INT_MAX ? "" : s.substr(bl, blen);
}
formed 这个技巧是本题的全部精华：不要每次都遍历 128 个计数去检查「是否全部覆盖」（那样是 O(128n)），而是维护「已经满额的字符种数」，让判断变成一次整数比较。

维护它的两条规则要写对：① 加入字符后，只在 have[c] == need[c]（恰好相等）时 ++formed——超额再加不能重复计数；② 移出字符时，先在 have[d] == need[d] 时 --formed，再 递减 have[d]。顺序反了就会漏判。

这个「把一个需要 O(k) 检查的条件，压缩成一个可增量维护的计数器」的手法，在窗口题里反复出现。

7.3 和 / 积型与负数陷阱

题型数组约束能用滑动窗口？正确工具
和 ≥ target 的最短子数组全正数能变长窗口（求最短）
和 ≤ target 的最长子数组全正数能变长窗口（求最长）
乘积 < K 的子数组个数全正数能变长窗口 + ans += r-l+1
和恰好为 K 的子数组个数可含负数不能前缀和 + 哈希表
和 ≥ target 的最短子数组可含负数不能前缀和 + 单调队列
最大子数组和可含负数不能Kadane（DP）或前缀和最小值
表里的分界线只有一条：数组是否全为正。全正时「和」随窗口变长严格递增，收缩窗口一定让和变小——这个单调性是窗口能工作的唯一依据。

含 0 时要小心「乘积」类题目（乘积会变 0 又变回来，且除法会除零）；含负数时和与积都不再单调。面试里如果题面没说「正整数」，一定要主动问一句——这既能避免写错，也能体现你知道前提在哪。

工程里的滑动窗口

限流、TCP、流式聚合都是同一个词的不同含义

8.1 限流四算法

「滑动窗口限流」和刷题里的滑动窗口是同一个思想（维护一段时间内的计数），但工程上关注的是内存开销和边界突刺。

// 令牌桶：O(1) 空间，惰性补充（不需要后台定时器）
class TokenBucket {
    double rate_;        // 每秒产生多少令牌
    double burst_;       // 桶容量（允许的突发量）
    double tokens_;
    double last_;         // 上次补充的时间（单调时钟）
public:
    bool allow(double now, double need = 1.0) {
        // 惰性补充：只在被调用时按经过的时间算出该补多少
        tokens_ = std::min(burst_, tokens_ + (now - last_) * rate_);
        last_ = now;
        if (tokens_ >= need) { tokens_ -= need; return true; }
        return false;
    }
};
三个实现要点：① 时间必须用单调时钟（steady_clock / CLOCK_MONOTONIC），用墙上时钟会被 NTP 调整或闰秒搞乱；② 惰性补充比后台定时器好——它不需要额外线程，而且限流器数量可以随 key 动态增长；③ 分布式限流要把状态放 Redis 并保证原子性（Lua 脚本或 INCR + EXPIRE），单机限流器在多副本下会把总配额放大到副本数倍。
完整的生产讨论见 限流 · 熔断 · 降级 · 隔离。

8.2 TCP 滑动窗口

TCP 的「滑动窗口」和算法题的窗口共享同一个结构（左右边界都只前进），但它解决的是流量控制：接收方通过窗口大小告诉发送方「我还能收多少」。

概念算法题的窗口TCP 的窗口
右边界前进读入新元素发送新数据（受 cwnd 与 rwnd 双重限制）
左边界前进移出旧元素收到 ACK，确认数据已被接收
窗口大小由约束决定min(拥塞窗口 cwnd, 接收窗口 rwnd)
不变式窗口内合法窗口内是「已发送未确认」的数据
TCP 窗口有两个算法题里没有的问题：① 零窗口——接收方缓冲满时通告窗口为 0，发送方必须靠 持续计时器（persist timer） 定期探测，否则死锁；② 糊涂窗口症候群（silly window syndrome）——接收方每腾出一点空间就通告，导致大量小包，靠 Nagle 算法（发送侧）与延迟 ACK（接收侧）缓解，而这两者组合又会引入额外延迟。
细节见 网络编程。

8.3 流式聚合与乱序

流处理系统里的「窗口」是同一族概念，但多了一个算法题完全不涉及的维度：数据会乱序到达。

窗口类型语义典型用途
滚动窗口（tumbling）不重叠的定长窗口每分钟 PV
滑动窗口（sliding/hopping）定长 + 定步长，可重叠近 5 分钟错误率，每 10s 更新
会话窗口（session）按「空闲超时」自动切分用户会话时长
全局窗口 + 触发器自定义复杂业务聚合
算法题的窗口有一个隐含前提：数据按顺序到达、且不会迟到。流处理里这个前提不成立——网络抖动、分区不均、客户端时钟偏差都会让事件乱序。于是引入两个概念：
  • 水位线（watermark）：系统对「事件时间已推进到哪里」的估计。窗口在水位线越过其结束时间后才触发计算。
  • 允许迟到（allowed lateness）：水位线过去后仍保留窗口状态一段时间，迟到数据到达就增量更新已发出的结果；再迟就进侧输出流（side output）或丢弃。
这本质上是「左边界什么时候可以安全前进」的问题——算法题里左边界前进是无条件安全的，流处理里它是一个正确性与延迟的权衡：水位线放得越宽，结果越准但延迟越高。相关展开见 Spark 内核。

陷阱症状修法
内层指针被重置看着是双指针，实际 O(n²)确认能指出一个单调有界的势能量（§2.1）
约束不单调却用窗口结果错，且小数据可能测不出问「数组是否全正」；不满足就换前缀和 + 哈希表

定长窗口 off-by-one漏第一个窗口或多算一个写清不变式；移出用 r >= k，统计用 r >= k-1
char 直接做下标非 ASCII 输入越界（UB）强转 (unsigned char)；多字节输入不要按字节开窗
三数之和去重方向错[0,0,0] 这类解被跳掉去重和「已处理的前一个」比，不和「后一个」比
Floyd 步长取 1 和 3特定环长下永不相遇步长差必须为 1，保证相对距离逐个递减

面试题集（12 道）

按难度分三段，先自测再对照

10.1 基础（必答）

点击每道题展开参考答案（先自测，再对照）。

  1. 基础下面这段代码是两层循环，为什么复杂度是 O(n) 而不是 O(n²)？ 
    int j = 0;
for (int i = 0; i < n; ++i) {
    while (j < n && ok(i, j)) ++j;
    use(i, j);
}

    因为 j 声明在循环外，全程只增不减。不能用「外层 n 次 × 内层最坏 n 次」来数——那个上界成立但太松。

    正确数法：分开数两件事 · 外层循环体：恰好 n 次 · 内层 ++j 的总次数：j 从 0 单调增到至多 n ⟹ 总量 ≤ n 总代价 = n + n = O(n)
    这就是势能法
    取势能 Φ = j（单调不减、上界 n）。内层每执行一次让 Φ 增加 1，而 Φ 总增量 ≤ n，所以内层总次数 ≤ n。
    对照：什么时候不成立
    如果写成 int j = i;（每轮重置），j 的总移动量就变回 O(n²)。那只是「两个变量」，不是双指针。
    自检问题
    写完双指针解法，问自己：我能指出一个单调变化且有界的量吗？对撞指针是 r − l（每轮至少减 1）；滑动窗口是 l + r（都只增、各至多 n）。指不出来，就说明解法可能不是 O(n)。
  2. 基础有序数组的两数之和用对撞指针，为什么移动指针不会漏掉解？无序数组呢？

    靠排除性论证：设当前 a[l] + a[r] < target。因为数组有序，a[r] 是剩余候选里最大的右端。

    推理
    既然 a[l] 配上最大的右端都还不够，那 a[l] 配任何剩余右端都不够 ⟹ 包含下标 l 的所有候选对都可丢弃 ⟹ ++l 不漏解。和太大时 --r 对称成立。∎
    几何直观
    候选空间是 n² 个 (l, r) 对。每步排除一整行或一整列，所以至多 2n 步就能覆盖完——这才是 O(n) 的来源，而不是「试遍所有对但试得快」。
    无序数组不能用
    没有可排除的性质：a[l] 配别的右端完全可能更大。此时标准解法是哈希表一遍扫（O(n) 时间 O(n) 空间）：遍历时查 target - a[i] 是否已出现过。
    一个易忽略的分岔
    如果题目要求返回原始下标而数组无序，排序会破坏下标。要么排 (值, 原下标) 的 pair，要么直接用哈希表。「要不要保留原下标」决定了该排序还是该用哈希表。
  3. 基础写出变长滑动窗口的模板。「求最长」和「求最短」的写法差别在哪？

    骨架四步：① 右扩 → ② while 收缩 → ③ 统计 → ④ r 继续前进，l 永不回退。差别全在②和③的关系。

    求最长：统计在 while 之后
    for (r...) {
    add(a[r]);
    while (不合法()) remove(a[l++]);
    best = max(best, r - l + 1);
}
    求最短：统计在 while 之内
    for (r...) {
    add(a[r]);
    while (已合法()) {
        best = min(best, r - l + 1);
        remove(a[l++]);
    }
}
    收缩条件正好相反
    求最长时收缩条件是「不合法」——缩到刚好合法再统计。求最短时收缩条件是「已合法」——一边缩一边统计，缩到不合法为止。写错位置是变长窗口第一大 bug 来源，落笔前先确定要的是最长还是最短。
    收缩必须用 while 而不是 if
    一次右扩可能需要多次收缩（例如加入一个字符后窗口里出现了多处违规）。用 if 只缩一次，窗口会残留非法状态。
    求「个数」时的统计式
    ans += r - l + 1。因为收缩完成后 [l,r] 是以 r 结尾的最长合法区间，而约束满足「子区间也合法」，所以 [l,r], [l+1,r], …, [r,r] 全合法，共 r−l+1 个。
  4. 基础Floyd 判圈（快慢指针）怎么工作？为什么步长要取 1 和 2？

    慢指针每次 1 步、快指针每次 2 步。无环时快指针先走到 nullptr；有环时两者必然相遇。O(n) 时间、O(1) 空间（对比哈希表法的 O(n) 空间）。

    为什么一定相遇
    两者都进入环后，考察相对位移：快指针每轮比慢指针多走 1 步，所以两者的环内距离每轮恰好减少 1。距离是环长内的非负整数，每轮减 1 ⟹ 最多「环长」轮后必然变成 0，即相遇。∎
    为什么不能取 1 和 3
    步长差为 2 时，相对距离每轮减 2。当环长为偶数而初始距离为奇数时，距离只在奇数间跳变，永远跨过 0 而不等于 0 → 永不相遇。
    步长差必须为 1，才保证「距离逐个递减、不可能跳过 0」。
    找环入口
    相遇后把一个指针放回头部，两者同速前进，再次相遇处就是入口。推导：设头到入口 a、入口到相遇点 b、相遇点回到入口 c，则相遇时 slow 走 a+b、fast 走 a+b+k(b+c)，且 fast 恰是 slow 的两倍：
    2(a+b) = a+b+k(b+c) ⟹ a = (k−1)(b+c) + c
    所以「从头走 a 步」和「从相遇点走 c 步（+整圈）」落在同一点。
    识别信号
    题目里有一个确定性的后继函数 f(x) 且状态空间有限 → 从任意起点必然进入循环，Floyd 就适用。同一套数学解「寻找重复数」（把 i → a[i] 看成隐式链表）和「快乐数」。

10.2 中级（区分熟练度）

  1. 中级「盛最多水的容器」为什么要移动较矮的那一侧？给出证明。

    蓄水量 = min(h[l], h[r]) × (r − l)。设 h[l] < h[r]，考虑所有以 l 为左端、右端在 r 内侧的候选 (l, r')（r' < r）：

    宽度
    r' − l < r − l，严格变小。
    高度
    min(h[l], h[r']) ≤ h[l] = min(h[l], h[r])，不会变大——因为已经被较矮的 h[l] 卡住了。

    两个因子都不增 ⟹ 这些候选全都不优于当前的 (l, r) ⟹ 包含 l 的候选可以整行丢弃 ⟹ ++l 不漏最优解。∎

    为什么不能移动较高的一侧
    移动 r 时：高度仍被 h[l] 卡着（不会变大）、宽度还变小，但你丢掉的那一列里可能藏着更优解——那个较高的 h[r] 配上别的左端可能更好。所以会错。
    一句话版本（面试时说这句）
    「宽度必然减小，所以唯一可能赚回来的是提升高度上限；而高度上限由短板决定，换长板毫无意义。」这就是木桶原理——桶能装多少由最短的板决定，桶变窄是纯损失，只有换掉短板才有机会。
  2. 中级「恰好 K 个不同整数的子数组个数」怎么做？为什么不能直接开窗口？

    不能直接开窗口，因为「恰好 K 个不同元素」不满足「子区间也合法」——把窗口缩小，不同元素数会掉到 K 以下。滑动窗口只能处理「至多 K」这类关于伸缩单调的约束。

    恰好 K = 至多 K − 至多 (K−1) exactly(K) = atMost(K) − atMost(K−1)

    atMost(m) 用标准变长窗口，统计「以每个 r 结尾的合法子数组个数」：

    long long at_most(const std::vector<int>& a, int m) {
    if (m < 0) return 0;              // k=0 时 m=-1，必须守卫
    std::unordered_map<int,int> cnt;
    long long ans = 0; int l = 0;
    for (int r = 0; r < (int)a.size(); ++r) {
        ++cnt[a[r]];
        while ((int)cnt.size() > m)
            if (--cnt[a[l++]] == 0) cnt.erase(a[l-1]);
        ans += r - l + 1;
    }
    return ans;
}
    为什么 ans += r−l+1
    收缩完成后 [l,r] 是以 r 结尾的最长合法子数组。「至多 m」满足子区间也合法 ⟹ [l,r], [l+1,r], …, [r,r] 全合法，共 r−l+1 个。
    通用框架
    「枚举右端点，统计以它结尾的合法区间数」是所有「求子数组个数」题的共同框架，不只用于窗口——前缀和 + 哈希表也是这个框架（枚举右端点，查有多少个合法左端点）。
    而「做差」技巧适用于任何「工具只会至多/至少，题目要恰好」的场合：恰好 K 个奇数、恰好 K 个不同字符、和恰好为 K。
  3. 中级什么情况下滑动窗口不能用？举两个具体例子。

    滑动窗口要求约束关于窗口的伸缩单调——即「如果 [l,r] 合法，那么它的任意子区间也合法」（或反向单调）。不满足就不能用。

    例一 · 数组含负数的「和」类题
    「和恰好为 K 的子数组个数」，数组可含负数。和不随窗口变长单调递增：[2,-3,2] 的和是 1，去掉末尾变成 −1，再去掉变成 2——缩小窗口不保证和变小。
    正解：前缀和 + 哈希表。枚举右端点 r，查 prefix[r] − K 出现过几次，O(n)。
    例二 · 含负数的「乘积」类题
    「乘积 < K 的子数组个数」在全正数时可以开窗口（乘积随窗口变长单调递增）。一旦含负数，乘积的符号会翻转，单调性完全断裂；含 0 时还有除零问题。
    正解：按 0 切段 + 前缀积/符号分类讨论。
    隐藏前提
    「数组是否全为正」是滑动窗口题的隐藏前提。表面上题目只是给了一堆数，但和/积的单调性完全依赖这一点。
    面试里如果题面没说「正整数」，一定要主动问一句——既避免写错，也体现你知道前提在哪。
    另一类失效：约束是「恰好」
    「恰好 K 个不同元素」也不满足子区间性质，要用「至多 K − 至多 K−1」做差（见上一题）。
    替代工具速查
    约束不单调时按题型换工具：求个数且和恰好 → 前缀和+哈希表；求最短且含负数 → 前缀和+单调队列；求最大子数组和 → Kadane（DP）；求窗口极值 → 单调队列。
  4. 中级「最小覆盖子串」里怎么 O(1) 判断「已覆盖目标集合」？

    不要每次都遍历计数数组检查（那是 O(128n) 或 O(nk)），而是维护一个整数 formed = 已经「满额」的字符种数，判断变成一次比较 formed == required。

    int need[128]={}, have[128]={};
for (unsigned char c : t) ++need[c];
int required = 0;   // t 中不同字符的种数
for (int c=0;c<128;++c) required += (need[c] > 0);

int formed = 0;
// 加入：
++have[c];
if (need[c] > 0 && have[c] == need[c]) ++formed;   // 恰好相等才 +1
// 移出：
if (need[d] > 0 && have[d] == need[d]) --formed;   // 先判再减！
--have[d];
    两条维护规则必须写对
    ① 加入后只在 have[c] == need[c]（恰好相等）时 ++formed——超额再加不能重复计数；② 移出时先在 have[d] == need[d] 时 --formed，再递减 have[d]。顺序反了就会漏判。
    这题是「求最短」
    所以收缩条件是「已合法」，统计放在 while 之内（缩之前先记录当前长度）。
    可迁移的手法
    「把一个需要 O(k) 检查的条件，压缩成一个可增量维护的计数器」——这个手法在窗口题里反复出现：判「窗口内无重复」维护重复字符数、判「已覆盖」维护满额种数、判「所有条件达标」维护达标项数。
    它的本质是把「检查」变成「在状态变更点做 O(1) 的差分更新」，和差分数组、Fenwick 树的思路同源。
    别忘了 unsigned char
    char 在多数平台有符号，非 ASCII 字节会得到负数下标（UB）。必须写 (unsigned char)s[r]。含多字节字符（UTF-8 中文）时更不能按字节开窗——一个字符占 1–4 字节，按字节滑动会切断字符。

10.3 高级（体现深度）

  1. 高级设计一个限流器。固定窗口、滑动窗口、漏桶、令牌桶各有什么取舍？

    四种算法复杂度都是 O(1)，差别在边界突刺、内存开销、是否允许突发。

    算法边界突刺内存允许突发
    固定窗口有，可达 2 倍限额O(1)不受控
    滑动日志无O(QPS)不受控
    滑动计数（分格）近似无O(格数)不受控
    漏桶无O(1)不允许
    令牌桶无O(1)受控（burst 参数）
    固定窗口的突刺
    限额 100/秒。攻击者在 0.9s 打满 100，1.1s 窗口重置后再打 100 → 0.2s 内通过 200。这是它不能用于严格限流的原因。
    工程默认选令牌桶
    状态只需 (上次时间, 当前令牌数) 两个字段，惰性补充（被调用时按经过时间算该补多少），不需要后台定时器，而且能表达「允许合理突发」这个真实业务需求（用户批量操作、重试风暴后的恢复）。
    bool allow(double now, double need = 1) {
    tokens_ = std::min(burst_, tokens_ + (now - last_) * rate_);
    last_ = now;
    if (tokens_ >= need) { tokens_ -= need; return true; }
    return false;
}
    三个实现要点
    ① 必须用单调时钟（steady_clock），墙上时钟会被 NTP 调整或闰秒搞乱；② 惰性补充优于定时器——不需额外线程，限流器可按 key 动态增长；③ 分布式限流要把状态放 Redis 并保证原子性（Lua 脚本），否则 N 个副本各自限流会把总配额放大 N 倍。
    再往上一层
    限流只是「过载保护」的一环，单独用它会把问题推给上游。生产上要配排队 + 超时（被限流的请求是立即拒绝还是排队？排多久？）、优先级（限流时先丢哪类流量）、自适应限流（按实测延迟动态调整配额，而不是拍一个固定值）。见 限流 · 熔断 · 降级 · 隔离。
  2. 高级算法题的「滑动窗口」和流处理系统的「窗口」有什么本质区别？

    算法题的窗口有一个隐含前提：数据按顺序到达、且不会迟到。所以左边界前进是无条件安全的。流处理里这个前提不成立——这就是全部区别的来源。

    乱序从哪来
    网络抖动、分区消费速度不均、客户端时钟偏差、上游重试。事件的产生时间（event time）和到达时间（processing time）不一致，且没有上界。
    水位线（watermark）
    系统对「事件时间已推进到哪里」的估计。窗口在水位线越过其结束时间后才触发计算。它把「左边界何时可以安全前进」从一个无条件动作变成了一个估计。
    允许迟到（allowed lateness）
    水位线过去后仍保留窗口状态一段时间，迟到数据到达就增量更新已发出的结果；再迟则进侧输出流或丢弃。
    这是一个正确性与延迟的权衡
    水位线放得越宽 → 结果越准，但延迟越高、状态占用越久。算法题里没有这个权衡（数据是完整且有序的），工程里它是核心设计决策。
    而且它还牵出幂等性要求：迟到数据会导致同一个窗口的结果被多次发出，下游必须能处理「同一 key 的结果更新」而不是简单累加。
    窗口类型也更丰富
    滚动（不重叠定长）、滑动/跳跃（定长+定步长，可重叠）、会话窗口（按空闲超时自动切分，长度不定）、全局窗口+自定义触发器。会话窗口在算法题里根本没有对应物——它的边界由数据本身的间隙决定。
    还有一个：状态要能容错
    算法题的窗口状态在内存里，进程挂了重跑就行。流处理的窗口状态可能有几十 GB 且必须可 checkpoint、可恢复、且恢复后语义一致（exactly-once）。这是 Flink 状态后端和 Spark 结构化流的主要复杂度来源。见 Spark 内核。
  3. 高级为什么 std::remove 不删除元素？这个设计说明了 STL 的什么原则？

    因为算法只拿到迭代器，拿不到容器——迭代器无法改变容器大小。std::remove 能做的只有「把要保留的元素搬到前面，返回新的逻辑末尾」。

    It remove(It first, It last, const T& value) {
    first = std::find(first, last, value);
    if (first == last) return first;
    It write = first;                              // 写指针
    for (It read = ++first; read != last; ++read)   // 读指针
        if (!(*read == value)) *write++ = std::move(*read);
    return write;                                  // 新逻辑末尾
}
    后果
    size() 不变，返回值之后那段是未指定的值（被 move 走的空壳）。所以单独调用 std::remove(v.begin(), v.end(), 3) 什么都没删掉。
    正确写法
    // erase-remove 惯用法
v.erase(std::remove(v.begin(), v.end(), 3), v.end());
// C++20 起（推荐）
std::erase(v, 3);
std::erase_if(v, [](int x){ return x % 2; });
    体现的 STL 原则：算法与容器解耦
    算法只依赖迭代器概念，所以一份 remove 能作用于 vector、deque、array、裸数组、甚至自定义容器。代价就是它只能做「重排」不能做「增删」。
    同一原则的其他体现：std::unique 也不删除、std::partition 只重排、std::sort 要求随机访问迭代器所以对 list 不可用（list 自带 sort 成员）。
    C++20 补上短板的方式
    std::erase / std::erase_if 是针对容器的自由函数重载（每个容器一份特化），而不是泛型算法——正是因为「改变大小」必须知道容器类型。这也印证了原来的设计不是疏忽，而是概念边界的必然结果。
    相关的 STL 接口取舍见 STL 算法库。
  4. 高级线上一个「统计近 5 分钟错误率」的接口在流量高峰时内存暴涨，怎么排查和重构？

    「近 5 分钟」+ 「内存随流量增长」几乎可以直接定位：实现用的是滑动日志——把每个请求的时间戳（甚至完整记录）存进一个队列，查询时扫一遍算 5 分钟内的数量。

    ① 确认内存去向
    看 RSS 增长是否与 QPS 线性相关；用 heap profiler（jemalloc/tcmalloc 的 profile、或 massif）看是不是那个容器占主导。滑动日志的内存是 O(QPS × 窗口秒数)——QPS 从 1k 涨到 50k，5 分钟窗口就从 30 万条变成 1500 万条。
    ② 顺带会发现第二个问题
    滑动日志的查询通常是 O(窗口内条数)。内存涨的同时查询延迟也在涨，两个症状同源。如果清理是「查询时惰性清理」，那高峰期第一次查询会一次性删掉几百万条 → 一个长停顿尖刺。

    重构：把「精确日志」换成「有界的近似聚合」。

    方案一 · 分格滑动计数（推荐）
    把 5 分钟切成 30 个 10 秒的格子，每格只存一个计数（成功数 + 失败数）。查询时把 30 个格子加起来。内存从 O(QPS×300) 降到 O(30)，查询 O(30)。
    代价是边界精度损失最多一格（10 秒）——对「错误率」这类监控指标完全可接受。格数就是精度与内存的旋钮。
    方案二 · 指数衰减（EWMA）
    只存一个数：rate = α·新样本 + (1−α)·rate。内存 O(1)、更新 O(1)。适合做告警和自适应限流，但它不是「严格的 5 分钟窗口」，而是一个加权平均——如果需求真的是「精确 5 分钟」（比如 SLA 计算），就不能用。
    选型的判据是「这个数字给谁看」
    驱动自动决策（熔断、限流、扩缩容）→ EWMA 或分格计数都行，平滑性反而是优点。对外承诺 / 计费 / SLA → 需要可解释、可复算的定义，用分格计数并把格粒度写进文档。事后排查 → 不要在进程内保留，直接打点到时序数据库（Prometheus / VictoriaMetrics），让专门的系统去做降采样和长期存储。
    这是一类通用的取舍
    「精确但无界」换成「近似但有界」是流式统计的通用手段：计数 → 分格计数 / EWMA；去重计数 → HyperLogLog；Top-K → Count-Min Sketch；分位数 → t-digest / DDSketch。
    共同点是：用一个可控的误差上界，换 O(1) 或 O(log n) 的空间。反过来说，动手前必须先问清「误差多少可以接受」——没有这个数字，就没法选。
