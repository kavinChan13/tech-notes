图遍历与拓扑排序

门槛不在十行 DFS/BFS，而在「这是不是图问题」和「图怎么存」。表示选错，复杂度从 O(V+E) 变成 O(V²)。下面用图把遍历、拓扑、连通性和缩点讲清，正文只留几份骨架代码，其余题型收进表。

核心难度 ★★★★☆ 面试出现率 极高 阅读时长 ~30 min 前置 递归 · 并查集

01

图的表示决定一切

选错表示，复杂度直接差一个量级

1.1 三种表示的取舍

邻接矩阵邻接表（vector 套 vector）链式前向星（CSR）
空间Θ(V²)Θ(V + E) + 每个 vector 的开销Θ(V + E)，两个扁平数组
遍历某点的所有边Θ(V)（要扫整行）Θ(deg)Θ(deg)，连续内存
判断 (u,v) 是否有边Θ(1)Θ(deg)Θ(deg)
cache 友好度好（连续）但数据量大差（每个 vector 独立分配）最好
适合稠密图、Floyd、V ≤ 几千通用，代码最短竞赛/高性能，V、E 很大
默认邻接表。E 落在 [0, V²]：稀疏（E = O(V)）走 O(V+E)；稠密（E ≈ V²）走矩阵，此时 Floyd / 朴素 Dijkstra 的 O(V²) 反而更省堆常数。V = 10⁵ 绝不能开矩阵。
三种表示像三种记通话记录的方式。矩阵是一张 V×V 大表：查「A 打过 B 吗」一眼看到，但列出 A 的通话对象要扫整行——一万人就要一亿格。邻接表是每人一本小册子，只记真实通话；CSR 把所有册子订成一本连续的书，再加「从第几页开始」的索引，内容一样，cache 更好。

1.2 与其他章节的关系

  • 递归与分治 —— DFS 是递归；深图爆栈改迭代或 BFS
  • 并查集与区间结构 —— 无向连通性的在线路线，分工见 §5.1
  • 最短路与最小生成树 —— BFS = 无权最短路；0-1 BFS 是 Dijkstra 特例
  • 动态规划 —— DAG 上 DP 必须按拓扑序转移
  • 堆与 Top-K —— Dijkstra 的优先队列
  • 多工具并行执行 —— 拓扑排序在 Agent 调度里的应用
02

DFS

十行代码，但时间戳理论能解一整类问题

2.1 模板与三色标记

// 三色：有向环检测必须用。WHITE 未访 / GRAY 在栈 / BLACK 已完成
enum { WHITE, GRAY, BLACK };
std::vector<int> color;

bool dfs(int u) {                  // 返回是否发现环
    color[u] = GRAY;
    for (int v : g[u]) {
        if (color[v] == GRAY) return true;   // 回边
        if (color[v] == WHITE && dfs(v)) return true;
    }
    color[u] = BLACK;
    return false;
}
为什么必须三色：visited == true 盖住两种完全不同的状态——还在当前递归栈里（GRAY，走过去就是环）和已经整棵子树处理完（BLACK，只是跨边或前向边）。连通分量、桥、SCC 都建立在「栈上 vs 已完成」这个区分上；深图递归深度 = 最长路径，Linux 默认栈约 8 MB，链状 10⁶ 必崩，能换 BFS 就换，必须 DFS 就改显式栈并加深度上限。

2.2 时间戳与四种边

进入时间 tin、离开时间 tout 把边分成四类，是桥 / 割点 / SCC 的共同语言。分类只看访问 v 时它是什么颜色：WHITE 是树边，GRAY 是回边（有环），BLACK 再比 tin 分前向边和跨边。

树边和回边两种（没有前向/跨边）
括号定理：任意两点的 [tin, tout] 要么完全嵌套（一个是另一个的后代），要么完全不相交——不可能部分重叠。v 是 u 的后代 ⟺ tin[u] < tin[v] && tout[v] < tout[u]。这把「是不是祖先」变成 O(1)，把子树问题变成区间问题，再用线段树处理（见 区间结构）。无向图没有前向边和跨边，只剩树边与回边。

2.3 环检测

图类型判据陷阱
有向走到 GRAY；或 Kahn 出队数 < nvisited 把跨边当环
无向vis[v] 且 v 不是来路用父节点跳会漏掉平行边环
无向 + 重边传边 id：if (eid == in_edge) continue两条平行边本身就是环

读题先问清有没有自环和重边——它同时影响环检测、桥判定和最短路。生产里发现环还要把环上的节点打出来（沿 GRAY 栈回溯），光返回 false 不够诊断。

03

BFS 与它的四个变体

队列一换，能力就变

3.1 无权图最短路

// BFS 天然给出无权图的单源最短路
std::vector<int> bfs(int s, int n) {
    std::vector<int> dist(n, -1);
    std::queue<int> q;
    dist[s] = 0; q.push(s);
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int v : g[u])
            if (dist[v] == -1) {        // ← 入队时就设 dist
                dist[v] = dist[u] + 1;
                q.push(v);
            }
    }
    return dist;
}
必须在入队时标记并写 dist，不是出队时。出队才标会让同一节点反复入队：稠密图上队列胀到 O(E)，症状是「答案对但超时」或 dist 偏大。边权不同时「层数少」不等于「距离短」，改 Dijkstra 或 0-1 BFS。

3.2 多源 BFS

「到最近一个 1 的距离」：全部 1 先入队，再跑标准 BFS，仍是 O(V+E)，不是 O(k(V+E))。正确性：所有源点连到一个权 0 的虚拟超级源，问题变回单源。「任意一个 / 至少一个 / 多汇」都是同一招——网络流里的源汇也是这么造出来的。

格子题本质是隐式图：节点 = 格子，边 = 相邻可走。不要真的建 vector<vector<int>>，在 BFS 里用方向数组生成邻居即可。多源场景（01 矩阵到最近的 1、多入口迷宫）仍然是「源格子先入队」。

3.3 双向 BFS

三个前提：已知确切终点、能反向遍历（有向图建反图）、边权相同。「总是扩较小一侧」让两边前沿平衡，避免一边爆炸。典型题：单词接龙、最小基因变化、八数码。

3.4 0-1 BFS

边权只有 0/1 时用双端队列：权 0 压队首、权 1 压队尾，O(V+E)，不必上堆。识别信号是「某些移动免费、某些花 1」：打通格子、最少翻边（正向 0 反向 1）、转弯有代价直走免费。

// 权 0 压队首（同层），权 1 压队尾（下一层）
std::vector<int> bfs01(int s, int n) {
    std::vector<int> dist(n, INT_MAX);
    std::deque<int> dq;
    dist[s] = 0; dq.push_back(s);
    while (!dq.empty()) {
        int u = dq.front(); dq.pop_front();
        for (auto [v, w] : g[u]) {
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                if (w == 0) dq.push_front(v);
                else          dq.push_back(v);
            }
        }
    }
    return dist;
}
为什么对：deque 里任意时刻最多两个距离值（d 和 d+1），队首总是最小——这就是 Dijkstra 的选取规则，只是不用堆。权 0 不增加距离，仍属当前层 → 队首；权 1 是下一层 → 队尾。复杂度从 O((V+E) log V) 降到 O(V+E)。边权是小范围整数时用桶队列 / Dial：每个距离一个桶，O(V + E + C·V)。
04

拓扑排序

两种写法，各有独门本事

4.1 Kahn：按入度剥离

// Kahn：反复取出入度为 0 的节点
std::vector<int> topo_kahn(int n) {
    std::vector<int> indeg(n, 0), order;
    for (int u = 0; u < n; ++u)
        for (int v : g[u]) ++indeg[v];
    std::queue<int> q;
    for (int u = 0; u < n; ++u)
        if (indeg[u] == 0) q.push(u);
    while (!q.empty()) {
        int u = q.front(); q.pop();
        order.push_back(u);
        for (int v : g[u])
            if (--indeg[v] == 0) q.push(v);
    }
    if ((int)order.size() != n) return {};   // 有环
    return order;
}
Kahn 的层就是 DAG 的最长路：同层节点互无依赖，可以并行；层数是「再多机器也不能更快」的下界。实际调度往往不卡死在层上，而是谁的入度先归零谁就跑（工作队列 + 计数器），并行度更高。环的报错必须可诊断：对剩余节点跑三色 DFS，沿栈打印整个环。

4.2 DFS 逆后序

后序位置 push，最后 reverse，就是拓扑序。任意边 u→v：v 是 WHITE 则先递归完 v；BLACK 则已完成；GRAY 则有环。故所有边上 tout[v] < tout[u]，按 tout 降序即「u 在 v 前」。默认仍用 Kahn：不爆栈、能分层、能换堆求字典序。DFS 逆后序只在两处必要——Kosaraju 第一遍，或你同时需要时间戳。

KahnDFS 逆后序
环检测order.size() < n发现 GRAY
字典序最小队列换堆不能
分层 / 关键路径按层剥离不直接
栈深无深图爆栈
Kosaraju 第一遍不适用必须

4.3 字典序最小

Kahn 的队列换成最小堆，O(V log V + E)。必须在过程中每步贪心选最小，不能先随便排出一个拓扑序再调整。「字典序最小拓扑序」和「让某点尽量靠前」是两道题：后者通常要反向拓扑再反向贪心。题面这两个词出现时要分清。

4.4 工程用途

构建 / 包管理 / Airflow / Excel 重算 / 死锁等待图：节点是任务或事务，边是先后或等待。环 = 不可调度或死锁。拓扑的工程价值有三面：顺序（按什么执行）、环检测（配置有没有问题，很多系统里这才是主用途）、层数 = DAG 最长路 = 理论最短完成时间。场景对照见 §7，Agent 调度见 多工具并行执行。

05

连通性

从「连通分量」到「割点、桥、SCC」

5.1 无向图：连通分量

选型只问一句：边是一次给全还是陆续到来？一次给全且还要路径/割点 → DFS/BFS。陆续到、只问是否连通 → 并查集（不用建图，见 并查集）。要删边：并查集离线逆向，或 LCT。
DFS / BFS并查集
复杂度O(V+E)O(E·α(V))
建图要不要
在线加边否是
分量节点列表遍历时直接得到要再收集
顺带能求路径、桥、SCC只有连通

5.2 割点与桥

求桥必须用边 id 跳来路：父节点会把平行边误判成桥。回边更新是 min(low[u], tin[v]) 不是 low[v]——回边只能跳到 v，不能接着用 v 的 low。根的割点要另判：树边孩子 ≥ 2。

5.3 有向图：SCC

强连通分量：集合内任意两点互相可达。Kosaraju 两遍 DFS：原图求逆后序，再在反图上按该顺序 DFS，每棵树一个 SCC——好讲，但要建反图。Tarjan 一遍完成：栈里是「还没确定归属」的节点，low[u]==tin[u] 时弹出一个 SCC。关键是 else if (on_stack[v])：v 已弹出说明它属于已经确定的另一个 SCC，那条跨边绝不能拉低当前 low，否则多个分量会被错误合并。面试讲 Kosaraju 更清楚，生产更常用 Tarjan。

5.4 缩点成 DAG

缩点像把「互相都能到」的城市合成都市圈。圈内部有环，谈不上先后；圈与圈之间一定单向——否则它们本就是同一个圈。Tarjan 给出的编号恰好是缩点后 DAG 的逆拓扑序，可以直接拿来做 DP，不必再跑一遍 Kahn。
06

二分图

一个判定，一个匹配

6.1 判定

二分图：节点能分成两组，所有边跨组。等价于没有奇环。染色能给出方案也能输出一个奇环；扩展域并查集（每个点拆成 x 与 x+n）支持边陆续到来，但拿不到方案。在线操作选并查集，给定整图要方案就染色。

6.2 最大匹配

匈牙利靠增广路：每次给一个左部点找一条「未匹配边与已匹配边交替」的路，找到就翻转，匹配数 +1。每轮必须重置 used，否则匹配数偏小。数据大换 Hopcroft-Karp（O(E√V)）。

算法 / 定理要点
匈牙利增广路O(V·E)；每轮重置 used；右部 match[v]=左部
Hopcroft-KarpO(E√V)，数据大时换它
König二分图最小点覆盖 = 最大匹配
最大独立集V − 最大匹配（仅二分图）
DAG 最小路径覆盖拆点建二分图，答案 = V − 最大匹配
带权匹配KM 或最小费用最大流

看到「最少点覆盖所有边 / 最多互不相邻 / DAG 最少路径覆盖」，第一反应是二分图匹配。König：最小点覆盖 = 最大匹配。带权用 KM 或最小费用最大流，后者更好写。网络流建模见 最短路与最小生成树。

工程场景

「这是个图问题」往往是最难的一步

场景节点 / 边算法
构建系统 / Airflow / Excel目标 → 依赖Kahn；环 = 循环依赖；层数 = 关键路径
数据库死锁事务 → 等待的锁有向环；沿栈取出环再选牺牲者
微服务发布服务 → 调用SCC 找循环依赖；拓扑定顺序
网络可靠性路由器 → 链路桥 / 割点 = 单点故障
Agent 工具编排调用 → 参数依赖拓扑 + 按层并行
状态空间（八数码 / 接龙）整个状态 → 合法一步不显式建图；双向 BFS / A*

识别信号三条：出现「依赖 / 先后 / 前置」→ 有向图 + 拓扑；「连通 / 可达 / 分组」→ 无向用遍历或并查集，有向用 SCC；「最少步数」→ BFS / 0-1 BFS / Dijkstra。最容易错的是节点是什么——不一定是题面里的对象：八数码的节点是整盘状态，且图不显式建出来；点容量或路径覆盖要拆点；「最多免费坐 k 次车」把节点变成 (位置, 已用次数)。边的方向也取决于你要什么：求执行顺序是「被依赖的指向依赖者」，求影响范围则反过来。

面试题集（12 道）

按难度分三段，先自测再对照

9.1 基础（必答）

点击每道题展开参考答案（先自测，再对照）。

  1. 基础邻接矩阵和邻接表怎么选？复杂度差别在哪？
    邻接矩阵邻接表
    空间Θ(V²)Θ(V+E)
    遍历某点所有边Θ(V)（扫整行）Θ(deg)
    判 (u,v) 是否有边Θ(1)Θ(deg)
    判据：稀疏还是稠密
    E 的范围是 [0, V²]。
    稀疏图（E = O(V)：道路网、社交网络、依赖图）→ 邻接表，O(V+E) 远优于 O(V²)。
    稠密图（E ≈ V²：完全图、距离矩阵）→ 邻接矩阵，而且此时 O(V²) 的算法（朴素 Dijkstra、Floyd）反而更好，省掉堆的常数。
    真实世界的图绝大多数是稀疏的，所以默认邻接表。
    高性能场景还有第三选择：CSR / 链式前向星
    两个扁平数组（start[] 存每点边的起始位置，to[] 存所有边的终点），空间 Θ(V+E) 且完全连续。
    对比 vector<vector<int>>：后者每个内层 vector 独立分配，遍历时指针追逐、cache 不友好。CSR 是顺序访问，预取友好。V、E 到百万量级时差别明显。
    读题信号
    看给定的 V、E 范围：V ≤ 500 且要求全源最短路 → 直接邻接矩阵 + Floyd。V = 10⁵ → 必须邻接表（矩阵要 10¹⁰ 格，MLE）。
  2. 基础有向图环检测为什么需要三种颜色？只用 visited 会怎样？

    visited == true 只说明「访问过」，但这有两种截然不同的情况：

    GRAY：还在当前递归栈里
    从 u 走到 v 意味着从 v 能回到 v → 有环。
    BLACK：已经完全处理完了
    只是一条跨边或前向边，不是环。
    只用 visited 的反例
    1→2, 1→3, 2→3。从 1 出发：DFS 到 2，2 到 3（3 变 visited 并完成），回到 1，1 再看 3 —— 若只看 visited 就误报有环。而这是个 DAG。
    enum { WHITE, GRAY, BLACK };
bool dfs(int u) {
    color[u] = GRAY;                          // 进栈
    for (int v : g[u]) {
        if (color[v] == GRAY) return true;   // 回边 → 环
        if (color[v] == WHITE && dfs(v)) return true;
    }
    color[u] = BLACK;                         // 出栈
    return false;
}
    另一条路：Kahn 拓扑排序
    如果最终出队节点数 < n，说明剩下的节点入度永远降不到 0 → 有环。一次遍历同时得到「有没有环」和「如果没有，顺序是什么」，比单独跑环检测更实用。
    无向图不一样
    无向图只有树边和回边（没有前向/跨边），所以只需 visited + 跳过来路。但要用边 id 而非父节点跳——否则有重边时会漏判（两条平行边本身构成环）。
  3. 基础为什么 BFS 能给出无权图的最短路？BFS 有什么实现坑？

    因为 BFS 按层扩展——先访问所有距离 1 的，再距离 2 的……所以一个节点第一次被访问时，走的必然是最短路径。

    这个论证依赖「每条边权重相同」
    边权不同时「层数少」不等于「距离短」，BFS 失效 → 要用 Dijkstra。
    而 0-1 BFS 是两者之间的折中：边权只有 0/1 时用双端队列，O(V+E)。
    最高频的实现坑：出队时才标记
    必须在「入队时」标记并设 dist：
    for (int v : g[u])
    if (dist[v] == -1) {          // 检查
        dist[v] = dist[u] + 1;     // 入队时就设
        q.push(v);
    }
    出队时标记会让同一节点多次入队——稠密图上队列膨胀到 O(E)，而且 dist 可能被写成非最短值。症状是「答案对但超时」或「答案偏大」。
    第二个坑：只从节点 0 开始
    图可能不连通。要计数连通分量、或确保全覆盖时，必须外层从每个未访问节点各起一次。
    这个坑在所有图遍历题里都存在（连通分量、SCC、二分图染色、拓扑排序的多个起点）。
    多源 BFS
    「从任意一个起点出发的最短距离」不需要跑 k 次——把所有起点一起放进初始队列，复杂度仍是 O(V+E)。
    正确性：等价于「加一个虚拟超级源点，连所有起点，边权 0」。看到「任意一个 / 至少一个」就该想到加虚拟节点。
  4. 基础写出拓扑排序，并说明怎么顺带检测环。

    Kahn 算法：反复取出入度为 0 的节点。

    std::vector<int> topo(int n) {
    std::vector<int> indeg(n, 0), order;
    for (int u = 0; u < n; ++u)
        for (int v : g[u]) ++indeg[v];

    std::queue<int> q;
    for (int u = 0; u < n; ++u) if (!indeg[u]) q.push(u);

    while (!q.empty()) {
        int u = q.front(); q.pop();
        order.push_back(u);
        for (int v : g[u]) if (--indeg[v] == 0) q.push(v);
    }
    if ((int)order.size() != n) return {};   // ← 环检测
    return order;
}
    环检测
    如果最终 order.size() < n，说明剩下的节点入度永远降不到 0——它们互相依赖，构成环。必须检查这一行，否则有环时会静默返回错误的部分序。
    另一种写法：DFS 逆后序
    DFS 后序的逆序就是拓扑序。证明：对任意边 u→v，若 v 是 WHITE 则先递归完 v（tout[v] < tout[u]）；若 v 是 BLACK 则显然 tout[v] < tout[u]；若 v 是 GRAY 则有环。所以按 tout 降序排列满足所有边的约束。
    KahnDFS 逆后序
    求字典序最小能（队列换最小堆）不能
    求「最少几轮完成」能（按层剥离）不直接
    栈深风险无深图爆栈
    用于 Kosaraju 求 SCC不适用必须用它
    默认用 Kahn
    更直观、无爆栈、能扩展到字典序最小和分层。只在做 Kosaraju 或需要时间戳时用 DFS 逆后序。

9.2 中级（区分熟练度）

  1. 中级什么是 0-1 BFS？为什么它能用双端队列代替堆？

    当边权只有 0 和 1 两种时，不需要 Dijkstra 的堆——用双端队列即可，复杂度从 O((V+E) log V) 降到 O(V+E)。

    for (auto [v, w] : g[u]) {            // w ∈ {0, 1}
    if (dist[u] + w < dist[v]) {
        dist[v] = dist[u] + w;
        if (w == 0) dq.push_front(v);   // 同层 → 队首
        else          dq.push_back(v);    // 下一层 → 队尾
    }
}
    为什么对
    双端队列在任意时刻最多包含两个不同的距离值（d 和 d+1），且队首的距离总是最小的——这正好复现了 Dijkstra「每次取距离最小的点」的性质，而不需要堆来维护。
    权 0 的边不增加距离 → 新节点属于「当前层」→ 压队首；权 1 → 「下一层」→ 压队尾。
    本质是 Dijkstra 的特例：「取最小」这个操作被队列结构免费提供了。
    识别信号
    「某些移动免费、某些移动花费 1」：
    · 网格最短路，某些格子可以「打通」（打通花 1，直接走花 0）
    · 「最少翻转多少条边使 s 能到 t」→ 正向边权 0、反向边权 1
    · 迷宫中「转弯花代价、直走免费」
    更一般的情形
    边权只有 {0, w} 两种也可以（把 w 当 1，最后乘回去）。
    边权是小范围整数 [0, C] 时用桶队列 / dial's algorithm：每个距离一个桶，O(V + E + C·V)。
    这一族方法的共同思路是：用「结构」代替「堆」来提供有序性——只要距离值的取值范围足够小或足够规整。
  2. 中级怎么求无向图的桥和割点？两者的判据差别在哪？

    都用 Tarjan 的 low 值：low[u] = 从 u 的子树（含 u）通过至多一条回边能到达的最小 tin。

    桥 树边 (u,v)：low[v] > tin[u] （v 的子树无法绕过这条边回到 u 或更早） 割点 树边 (u,v)：low[v] ≥ tin[u] 且 u 不是根 u 是根时：u 有 ≥ 2 个树边孩子
    为什么一个是 > 一个是 ≥
    桥关心的是「这条边能不能被绕过」——如果 v 的子树能回到 u 本身（low[v] == tin[u]），那说明有另一条路径连接 u 和 v，这条边不是桥。
    割点关心的是「删掉这个点后 v 的子树是否失联」——如果 v 的子树最多只能回到 u（而回不到 u 的祖先），那删掉 u 就会让 v 的子树孤立，所以 low[v] == tin[u] 时 u 就是割点。
    三个实现坑
    ① 求桥必须用边 id 跳过来路，不能用父节点——否则有重边时会把平行边误判成桥（平行边永远不是桥）。求割点用父节点是安全的。
    ② 回边更新必须是 low[u] = min(low[u], tin[v])，不是 low[v]——回边只能「跳到」v，不能继续用 v 的 low。混用这两个是最常见的错。
    ③ 根节点的割点判据不同（要数树边孩子个数），忘了特判会误判根。
    工程意义
    桥和割点就是单点故障：网络拓扑里的桥是「断了就分区的链路」，割点是「宕了就分区的路由器」。
    进一步：边双连通分量（去掉桥后的连通块）内部任意两点有至少两条边不重复的路径 → 冗余区域。这是网络可靠性分析的基础。
  3. 中级Tarjan 求 SCC 里的 on_stack 检查为什么必不可少？

    因为它区分了两种「v 已被访问」的情况，而它们对 low[u] 的影响完全不同。

    for (int v : g[u]) {
    if (!tin[v]) {                          // 树边
        tarjan(v);
        low[u] = std::min(low[u], low[v]);
    } else if (on_stack[v]) {              // ← 关键
        low[u] = std::min(low[u], tin[v]);
    }
    // v 已访问但不在栈上 → 指向已完成的 SCC，不能更新 low
}
    在栈上 vs 不在栈上
    在栈上：v 属于「当前正在探索、还没确定归属」的节点集合 → u 和 v 可能在同一个 SCC → 应该更新 low。
    不在栈上：v 所属的 SCC 已经确定并弹出了 → u 和 v 一定不在同一个 SCC（否则 v 的 SCC 不会先被确定）→ 这条跨边不应影响 u 的 low。
    去掉检查会怎样
    对所有已访问的 v 都更新 low，会让 u 的 low 被无关的、已完成的 SCC 拉低 → low[u] == tin[u] 的判定失效 → SCC 划分错误（通常是把多个 SCC 错误地合并）。
    对比 Kosaraju
    Kosaraju 两遍 DFS：① 原图求逆后序；② 反图上按该顺序 DFS，每棵树就是一个 SCC。
    易理解易写，但要建反图（内存双份）。Tarjan 一遍完成、不需反图，代价是逻辑更绕。面试里 Kosaraju 更容易讲清，生产里 Tarjan 更常用。
    Tarjan 的一个额外好处
    它给出的 SCC 编号顺序恰好是缩点后 DAG 的逆拓扑序——可以直接用来做 DP，不必再跑一遍拓扑排序。
    而缩点的意义是「消除环，恢复偏序」：把每个 SCC 缩成一个点后必然是 DAG（否则那些 SCC 会合并），于是拓扑排序和 DAG 上的 DP 就都能用了。
  4. 中级判断二分图有哪两种方法？各自的适用场景？

    二分图 ⟺ 不存在奇环。这个等价性是两种算法的共同依据。

    方法一 · BFS/DFS 染色
    相邻节点染不同色，冲突则有奇环。
    for (int s = 0; s < n; ++s) {      // 必须遍历所有分量
    if (col[s] != -1) continue;
    // BFS 染色，col[v] = col[u] ^ 1
    // if (col[v] == col[u]) return false;
}
    能给出染色方案，也能输出一个奇环。
    方法二 · 扩展域并查集
    每个点拆成 x 和 x+n 两个域。对每条边 (u,v)：先查 find(u) == find(v)（已被推断为同组 → 矛盾），否则 unite(u, v+n) 且 unite(u+n, v)。
    支持在线——边可以陆续到来，随时能回答。
    染色扩展域并查集
    给出染色方案能否
    输出奇环能否
    在线处理需先建全图支持
    代码量中等更短
    「在线 vs 离线」是第一个分岔口
    题面说「依次处理 m 个操作，每次输出答案」→ 必须并查集。说「给定一张图，判断/输出方案」→ 染色更合适。
    染色法的高频遗漏
    必须遍历所有连通分量。图可能不连通，只从节点 0 开始会漏掉其他分量。这个坑在所有图遍历题里都存在。

9.3 高级（体现深度）

  1. 高级设计一个构建系统的依赖调度器，怎么做？循环依赖怎么报错？

    模型：节点 = 构建目标，边 = 依赖关系（A 依赖 B ⟹ 边 B→A，表示 B 必须先完成）。核心是拓扑排序。

    ① 用 Kahn 而不是 DFS
    三个理由：无爆栈风险（依赖链可能很长）；顺带环检测；最重要的是——按层剥离天然给出并行度。
    ② 按层并行执行
    Kahn 的每一「层」（同时入度为 0 的节点）内部互无依赖，可以并行。
    层数 = DAG 的最长路径长度 = 关键路径，它决定了理论最短完成时间——再多机器也不能更快。这是评估「加机器有没有用」的关键指标。
    实际实现通常不严格按层，而是「谁的依赖先满足谁就开跑」（用一个工作队列 + 计数器），并行度更高。
    ③ 循环依赖的报错必须可诊断
    光说「检测到循环依赖」没用——用户需要知道是哪几个目标构成的环。
    做法：Kahn 结束后若 order.size() < n，对剩下的节点跑一次 DFS 三色标记，遇到 GRAY 时沿递归栈回溯打印整个环。
    这是「工程实现」和「刷题实现」的关键差别：刷题只要返回 false，生产必须给出可操作的错误信息。
    ④ 还要处理的现实问题
    增量构建：只重建「变了的目标 + 它的所有下游」→ 从变更点做正向可达性搜索（BFS/DFS）。
    缓存命中：用「输入内容哈希 + 命令哈希」做 key（bazel 的做法），能跨机器复用。
    失败处理：一个目标失败后，它的所有下游都要标记为「跳过」而不是「失败」——同样是正向可达性。
    动态依赖：某些依赖只有构建后才知道（如 C 的 #include）→ 需要边构建边扩展图。
    ⑤ 这个模型的其他化身
    Airflow / DAG 工作流引擎、Excel 公式重算、编译器的类型推导顺序、Agent 工具调用编排、包管理器依赖解析（但版本约束求解本质是 SAT，比拓扑排序难）。
    共同点：都要同时解决「顺序」和「环检测」两件事，而且环检测的错误信息质量往往比算法效率更重要。
  2. 高级数据库怎么检测死锁？检测到之后怎么办？

    建等待图（wait-for graph）：节点 = 事务，边 T1 → T2 表示「T1 在等 T2 持有的锁」。死锁 ⟺ 等待图中有环。

    ① 检测：有向图环检测
    用 DFS 三色标记（GRAY = 在当前递归栈中）。发现回边时沿栈回溯得到整个环——这一步是必要的，因为要从环里选牺牲者。
    触发时机有两种：周期性检测（每隔几百毫秒扫一遍，MySQL 早期）或等待时立即检测（每次一个事务开始等待就从它出发找环，InnoDB 的做法，更及时）。
    ② 选牺牲者的策略
    不能随便选——要让代价最小且避免活锁（同一个事务反复被选中回滚，永远无法完成）：
    · 回滚代价最小：已修改的行数最少、持有的锁最少、已执行时间最短（InnoDB 用「undo log 长度」近似）
    · 避免活锁：把「已被回滚次数」计入权重，或按事务开始时间给老事务优先权
    · 不选系统关键事务
    ③ 另一条路：预防而非检测
    超时（innodb_lock_wait_timeout）：最简单，但会误杀只是慢的事务，且超时值难调（太短误杀、太长死锁持续久）。
    按固定顺序加锁：从根上避免环（比如「总是按主键升序加锁」）。这是应用层最有效的手段，但要求所有代码都遵守。
    Wait-Die / Wound-Wait：按事务时间戳决定「等待还是回滚」，无环可证，但回滚率高于检测法。
    ④ 分布式场景更难
    单机的等待图在一个进程内，扫一遍就行。分布式下等待关系跨节点，要么用集中式死锁检测器（收集各节点的局部等待图拼成全局图，有单点和延迟问题），要么用边追逐（edge chasing）算法传递探测消息。
    而且网络延迟会导致「假死锁」——检测到环时它可能已经解开了。所以分布式系统更倾向用超时 + 重试这种简单粗暴但鲁棒的方案。这是「理论最优」在分布式下让位于「可运维」的又一个例子。
  3. 高级一个 DFS 在生产数据上爆栈了，有哪些解法？各自的取舍？

    DFS 递归深度 = 图的最长路径，而 Linux 默认栈 8 MB、每帧几十到上百字节 → 安全深度约 10⁴–10⁵。V = 10⁶ 的链状图必崩。

    ① 换 BFS（最简单，优先考虑）
    队列在堆上，天然不爆栈。
    但要确认问题是否允许：求最短路、连通分量、拓扑排序（Kahn）、二分图判定都可以换。不能换的是依赖「后序」的问题——求 SCC、桥、割点、子树聚合、时间戳，这些必须 DFS。
    ② 显式栈改写 DFS
    把递归改成「栈里存 (节点, 已处理到第几个邻居)」，模拟递归的执行状态。
    能保留 DFS 的全部性质（包括后序和时间戳），代价是代码可读性明显下降，而且容易写错（尤其是后序位置）。
    这就是递归转迭代里的「状态机」方法——栈里存的那个「已处理到第几个」就是程序计数器。
    ③ 加大栈（临时止血，不是根治）
    ulimit -s unlimited、pthread_attr_setstacksize、或在 Windows 上用链接器选项。
    缺点：只是把上限推高，深度再翻倍还是会崩；而且在容器/受限环境里可能改不了；多线程时每个线程都要这么大栈，内存浪费。可以作为应急，但要同时安排根治。
    ④ 深度断言 + 拒绝（安全视角）
    如果图来自不可信输入（用户上传的依赖文件、外部 API 返回的关系），这不只是性能问题而是 DoS 漏洞——攻击者构造深链就能打崩服务。
    必须加显式深度上限并优雅拒绝，而不只是改大栈。这和递归下降解析器的爆栈是同一类问题。
    ⑤ 决策顺序
    问题允许换 BFS 吗？→ 换（最省事）。
    必须 DFS 但图可信？→ 显式栈（一次性成本，之后不用再管）。
    必须 DFS 且图不可信？→ 显式栈 + 深度上限（安全要求）。
    只是临时救火？→ 加大栈 + 记一个技术债。
    另外用 -fsanitize=address 能把爆栈报成明确的 stack-overflow 而不是裸 SIGSEGV，定位快得多。
  4. 高级怎么把一个实际问题识别成图问题？建模时最容易错在哪？

    三个识别信号：

    ① 「依赖 / 先后 / 前置」
    → 有向图 + 拓扑排序。构建系统、任务调度、类型推导、Excel 重算。
    ② 「连通 / 可达 / 分组」
    → 连通分量。无向图用并查集（在线）或 DFS（要更多信息）；有向图用 SCC。
    ③ 「最少步数 / 最短」
    → BFS（无权）、0-1 BFS（权只有 0/1）、Dijkstra（正权）、Bellman-Ford（有负权）。
    最容易错的是「节点是什么」
    节点不一定是题面里显式给的对象：
    · 状态空间搜索：节点是整个状态（八数码里是整个棋盘、单词接龙里是整个单词）。这类图不显式建出来——邻居是「按规则生成的」，图可能是无穷大的。
    · 拆点：一个对象拆成「入点」和「出点」。用于点容量限制（网络流）、DAG 最小路径覆盖（二分图匹配）。
    · 分层图：节点是 (位置, 附加状态)。「最多可以免费坐 k 次车的最短路」→ 节点变成 (城市, 已用免费次数)，图规模乘以 k+1。
    · 边变节点：某些问题里边才是主体（如「边的着色」）。
    第二个易错点：边的方向和权重
    「A 依赖 B」建成 A→B 还是 B→A？取决于你要什么——求「执行顺序」要 B→A（B 先完成），求「影响范围」要 A→B（改了 B 影响谁）。两个方向的图都建出来往往更方便。
    「最少翻转多少边」这类题里，边权是你构造出来的（正向 0、反向 1），不是题面给的。
    建模比套算法难，也更值得练
    算法就那几个（DFS/BFS/拓扑/Dijkstra/并查集），而建模的变化是无穷的。
    练法：拿到题先问三句——「节点是什么？边是什么？我要的答案对应图上的什么？」把这三句用自然语言写清楚，算法通常就自明了。反过来，如果这三句说不清，直接开始写代码一定会绕弯路。
