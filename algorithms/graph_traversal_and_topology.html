图遍历与拓扑排序

图算法的入门门槛不在算法本身——DFS 和 BFS 各只有十行——而在「这个问题是不是图问题」和「图该怎么存」。这一篇先把三种表示的取舍讲清（它直接决定复杂度是 O(V+E) 还是 O(V²)），再把 DFS 的时间戳理论、BFS 的四个变体、拓扑排序的两种写法和 Tarjan 缩点讲透，最后落到构建系统、死锁检测这些真实场景。

图的表示决定一切

选错表示，复杂度直接差一个量级

1.1 三种表示的取舍

邻接矩阵邻接表（vector 套 vector）链式前向星（CSR）
空间Θ(V²)Θ(V + E) + 每个 vector 的开销Θ(V + E)，两个扁平数组
遍历某点的所有边Θ(V)（要扫整行）Θ(deg)Θ(deg)，连续内存
判断 (u,v) 是否有边Θ(1)Θ(deg)Θ(deg)
cache 友好度好（连续）但数据量大差（每个 vector 独立分配）最好
适合稠密图、Floyd、V ≤ 几千通用，代码最短竞赛/高性能，V、E 很大
 
// ① 邻接表：最常用，代码最短
std::vector<std::vector<int>> g(n);
g[u].push_back(v);

// ② 链式前向星 / CSR：两个扁平数组，cache 最友好
//    先统计每点的度，求前缀和得到每点边的起始位置，再填充
std::vector<int> start(n + 1, 0), to(m);
for (auto& [u, v] : edges) ++start[u + 1];
for (int i = 0; i < n; ++i) start[i + 1] += start[i];   // 前缀和
{
    std::vector<int> pos = start;
    for (auto& [u, v] : edges) to[pos[u]++] = v;
}
// 遍历 u 的邻居：for (int i = start[u]; i < start[u+1]; ++i) { int v = to[i]; }
// 全部在两个连续数组里 → 顺序访问，预取友好
稀疏 vs 稠密的分界：图论算法的复杂度通常写成 O(V + E) 或 O(V²)，而 E 的范围是 [0, V²]。
  • 稀疏图（E = O(V)，如道路网、社交网络、依赖图）→ 邻接表/CSR，O(V+E) 远优于 O(V²)。
  • 稠密图（E ≈ V²，如完全图、距离矩阵）→ 邻接矩阵，且此时 O(V²) 的算法（如朴素 Dijkstra、Floyd）反而更好，因为省掉了堆的常数。
真实世界的图绝大多数是稀疏的——所以默认用邻接表。但读题时要看 V 和 E 的给定范围：V ≤ 500 且要求全源最短路 → 直接上邻接矩阵 + Floyd。
三种表示像三种记录「谁和谁通话」的方式。
邻接矩阵是一张 V×V 的大表格，每格填 0/1。查「A 和 B 通过话吗」一眼就看到（O(1)），但要列出「A 和谁通过话」得把 A 那一整行扫完——哪怕 A 只打过一个电话。而且一万人就要一亿格。
邻接表是每人一本小册子，只记自己打过的电话。列举很快，但查「A 和 B 通过话吗」要翻遍 A 的册子。
CSR是把所有册子按人名顺序装订成一本大书，再加一个「每人从第几页开始」的索引。内容完全一样，但因为是一整本连续的书，翻起来（cache）快得多。

1.2 与其他章节的关系

  • 递归与分治 —— DFS 是递归；深图会爆栈，要改迭代或用 BFS
  • 并查集与区间结构 —— 无向图连通性的另一条路，两者的分工在 §5.1
  • 最短路与最小生成树 —— BFS 是无权图的最短路；0-1 BFS 是 Dijkstra 的特例
  • 堆与 Top-K —— Dijkstra 的优先队列与 decrease-key
  • 动态规划 —— DAG 上的 DP 必须按拓扑序转移
  • 多工具并行执行 —— 拓扑排序在 Agent 工具调度里的应用
02

DFS

十行代码，但时间戳理论能解一整类问题

2.1 模板与三色标记

// 最简版：只需 visited
std::vector<bool> vis;
void dfs(int u) {
    vis[u] = true;
    for (int v : g[u])
        if (!vis[v]) dfs(v);
}

// 三色标记版：有向图环检测必须用这个
enum { WHITE, GRAY, BLACK };   // 未访问 / 在栈中 / 已完成
std::vector<int> color;

bool dfs(int u) {                  // 返回是否发现环
    color[u] = GRAY;                  // 进入递归栈
    for (int v : g[u]) {
        if (color[v] == GRAY) return true;   // ← 回边：找到环
        if (color[v] == WHITE && dfs(v)) return true;
    }
    color[u] = BLACK;                 // 离开递归栈
    return false;
}
为什么有向图环检测需要三种颜色而不是两种：vis[v] == true 只说明「v 被访问过」，但这有两种情况——
  • v 还在当前递归栈里（GRAY）→ 从 u 走到 v 形成了环。
  • v 已经完全处理完了（BLACK）→ 只是一条跨边或前向边，不是环。
只用 visited 会把第二种误判成环。典型反例：1→2, 1→3, 2→3，从 1 出发 DFS 到 3（BLACK），回来走 2→3 时若只看 visited 就会误报有环。

2.2 时间戳与四种边

给 DFS 加上「进入时间 tin」和「离开时间 tout」，就能把图的所有边分成四类——这是很多高级图算法的基础。

树边和回边两种（没有前向/跨边）
括号定理（parenthesis theorem）：对任意两个节点 u、v，它们的时间区间 [tin, tout] 要么完全嵌套（一个是另一个的后代），要么完全不相交（互不为后代）——不可能部分重叠。

由此得到一个极其有用的判据：v 是 u 的后代 ⟺ tin[u] < tin[v] && tout[v] < tout[u]。
这让「u 是不是 v 的祖先」变成 O(1) 判断，是DFS 序 / 欧拉序技巧的基础——把树上的子树问题转化成区间问题，再用线段树/树状数组处理（见 区间结构）。

2.3 环检测

有向图：三色标记
// GRAY 表示「在当前递归栈中」
if (color[v] == GRAY) return true;   // 回边 → 有环

// 或用 Kahn 拓扑排序：
// 如果最终出队的节点数 < n，说明有环
无向图：跳过父边
bool dfs(int u, int parent) {
    vis[u] = true;
    for (int v : g[u]) {
        if (v == parent) continue;   // ← 关键：跳过来路
        if (vis[v]) return true;      // 回边 → 有环
        if (dfs(v, u)) return true;
    }
    return false;
}
// 或用并查集：加边时两端已连通 → 有环
无向图跳过父边有个陷阱：如果图里有重边（u 和 v 之间有两条边），v == parent 会把第二条也跳过，导致漏判环（而两条平行边本身就构成一个环）。
正确做法是按「边的编号」而不是「父节点」来跳过： 
bool dfs(int u, int in_edge) {   // 传进来的是边的 id
    vis[u] = true;
    for (auto [v, eid] : g[u]) {
        if (eid == in_edge) continue;   // 只跳过同一条边
        if (vis[v]) return true;
        if (dfs(v, eid)) return true;
    }
    return false;
}
「有没有重边和自环」是图论题必须问清的前置条件——它影响环检测、桥的判定、最短路的实现。
03

BFS 与它的四个变体

队列一换，能力就变

3.1 无权图最短路

// BFS 天然给出无权图的单源最短路
std::vector<int> bfs(int s, int n) {
    std::vector<int> dist(n, -1);
    std::queue<int> q;
    dist[s] = 0; q.push(s);
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int v : g[u])
            if (dist[v] == -1) {        // ← 入队时就设 dist 并标记
                dist[v] = dist[u] + 1;
                q.push(v);
            }
    }
    return dist;
}
必须在「入队时」标记已访问，而不是「出队时」。出队时标记会让同一个节点被多次入队——在稠密图上队列可能膨胀到 O(E)，而且 dist 也可能被写成非最短值。
这是 BFS 最高频的实现 bug，症状是「答案对但超时」或「答案偏大」。
BFS 为什么给出最短路：BFS 按层扩展——先访问所有距离 1 的，再距离 2 的……所以一个节点第一次被访问时，走的必然是最短路径。

这个论证依赖每条边权重相同。边权不同时，「层数少」不等于「距离短」，BFS 就失效了——这时要用 Dijkstra（见 最短路）。而 0-1 BFS（§3.4）是这两者之间的一个漂亮折中。

3.2 多源 BFS

「从任意一个起点出发的最短距离」——不需要跑 k 次 BFS，把所有起点一起放进初始队列就行。

// 例：01 矩阵，求每个 0 到最近的 1 的距离
std::queue<std::pair<int,int>> q;
for (int i = 0; i < m; ++i)
    for (int j = 0; j < n; ++j)
        if (a[i][j] == 1) { dist[i][j] = 0; q.push({i, j}); }   // 全部入队
// 然后就是标准 BFS —— 复杂度仍是 O(V+E)，不是 O(k(V+E))
多源 BFS 的正确性来自一个简单的观察：把所有源点看成连到一个「虚拟超级源点」的距离为 0 的边，问题就变成单源 BFS。
这个「加虚拟节点」的技巧在图论里反复出现：多源最短路加超级源、多汇加超级汇、「选一个起点」加虚拟起点连所有候选、网络流建模里的源汇点。看到「任意一个 / 至少一个」就该想到它。

3.3 双向 BFS

单向 BFS 的搜索量 ≈ b^d （b = 分支因子，d = 距离） 双向 BFS 的搜索量 ≈ 2·b^(d/2) ← 两边各搜一半 b=10, d=6 时：10⁶ → 2×10³，快 500 倍
// 从起点和终点同时扩展，相遇即得答案
int bidirectional_bfs(int s, int t) {
    if (s == t) return 0;
    std::unordered_set<int> fs{s}, bs{t}, vis_f{s}, vis_b{t};
    int step = 0;
    while (!fs.empty() && !bs.empty()) {
        // 关键优化：总是扩展较小的那一侧
        if (fs.size() > bs.size()) { std::swap(fs, bs); std::swap(vis_f, vis_b); }
        std::unordered_set<int> next;
        ++step;
        for (int u : fs)
            for (int v : g[u]) {
                if (vis_b.count(v)) return step;   // 相遇
                if (!vis_f.count(v)) { vis_f.insert(v); next.insert(v); }
            }
        fs = std::move(next);
    }
    return -1;
}
双向 BFS 的三个前提：① 必须知道确切的终点（不能是「任意满足条件的终点」）；② 图必须能反向遍历（无向图天然可以，有向图需要建反图）；③ 边权相同。
「总是扩展较小的一侧」是关键优化——它让两边的搜索前沿保持平衡，避免一边爆炸。
典型题：单词接龙（Word Ladder）、最小基因变化、八数码。

3.4 0-1 BFS

当边权只有 0 和 1两种时，不需要 Dijkstra 的堆——用双端队列就够，复杂度 O(V+E)。

// 边权只有 0/1：权 0 的边压队首，权 1 的边压队尾
std::vector<int> bfs01(int s, int n) {
    std::vector<int> dist(n, INT_MAX);
    std::deque<int> dq;
    dist[s] = 0; dq.push_back(s);
    while (!dq.empty()) {
        int u = dq.front(); dq.pop_front();
        for (auto [v, w] : g[u]) {          // w ∈ {0, 1}
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                if (w == 0) dq.push_front(v);  // 同层 → 队首
                else          dq.push_back(v);   // 下一层 → 队尾
            }
        }
    }
    return dist;
}
为什么这样是对的：双端队列在任意时刻最多包含两个不同的距离值（d 和 d+1），且队首的距离总是最小的——这正好复现了 Dijkstra「每次取距离最小的点」的性质，而不需要堆。
权 0 的边不增加距离，所以新节点属于「当前层」→ 压队首；权 1 的边属于「下一层」→ 压队尾。

它本质是 Dijkstra 的特例：把 O((V+E) log V) 降到 O(V+E)，因为「取最小」这个操作被队列的结构免费提供了。
识别 0-1 BFS 的信号：「某些移动免费、某些移动花费 1」。典型题：
  • 网格中的最短路径，某些格子可以「打通」（打通花 1，直接走花 0）。
  • 「最少翻转多少条边使 s 能到 t」——正向边权 0，反向边权 1。
  • 迷宫中「转弯要花代价，直走免费」。
更一般的情形：边权只有 {0, w} 两种值时也可以（把 w 当 1 处理，最后乘回去）；边权是小范围整数时用桶队列 / dial's algorithm（每个距离一个桶），也能做到 O(V + E + maxW·V)。
04

拓扑排序

两种写法，各有独门本事

4.1 Kahn：按入度剥离

// Kahn：反复取出「入度为 0」的节点
std::vector<int> topo_kahn(int n) {
    std::vector<int> indeg(n, 0), order;
    for (int u = 0; u < n; ++u)
        for (int v : g[u]) ++indeg[v];

    std::queue<int> q;
    for (int u = 0; u < n; ++u)
        if (indeg[u] == 0) q.push(u);

    while (!q.empty()) {
        int u = q.front(); q.pop();
        order.push_back(u);
        for (int v : g[u])
            if (--indeg[v] == 0) q.push(v);
    }
    // 环检测：如果 order.size() < n，说明剩下的节点构成环
    if ((int)order.size() != n) return {};   // 有环，无拓扑序
    return order;
}
Kahn 顺带解决环检测：如果最终排出的节点数少于 n，说明剩下的节点入度永远降不到 0——它们互相依赖，构成了环。
这比单独跑一遍 DFS 环检测更实用，因为一次遍历同时得到「有没有环」和「如果没有，顺序是什么」。

4.2 DFS 逆后序

// DFS 后序的逆序就是拓扑序
std::vector<int> order;
std::vector<int> color;

bool dfs(int u) {
    color[u] = GRAY;
    for (int v : g[u]) {
        if (color[v] == GRAY) return false;      // 有环
        if (color[v] == WHITE && !dfs(v)) return false;
    }
    color[u] = BLACK;
    order.push_back(u);          // ← 后序位置
    return true;
}
// 最后 std::reverse(order) 即得拓扑序
为什么逆后序是拓扑序：考虑任意一条边 u → v。
  • 若 v 是 WHITE（未访问）→ DFS 会先递归完 v，所以 tout[v] < tout[u]。
  • 若 v 是 BLACK（已完成）→ 显然 tout[v] < tout[u]。
  • 若 v 是 GRAY → 存在环，无拓扑序（已排除）。
所以对所有边都有 tout[v] < tout[u] ⟹ 按 tout 降序排列（即后序的逆序）就满足「u 排在 v 前面」。∎
Kahn（BFS 式）DFS 逆后序
环检测顺带完成（order.size() < n）顺带完成（发现 GRAY）
能否求字典序最小能（把队列换成优先队列）不能
能否求「每层」信息能（按层剥离 → 最长路径层数）不直接
栈深风险无（队列在堆上）深图会爆栈
用于 SCC（Kosaraju）不适用必须用它（第一遍求逆后序）
代码直观度更直观（「先做没有前置的」）需要理解逆后序
默认用 Kahn：更直观、无爆栈风险、顺带环检测、能扩展到字典序最小和分层。
只在两种情况用 DFS 逆后序：① 做 Kosaraju 求 SCC（第一遍必须是 DFS 逆后序）；② 需要同时拿到 DFS 的时间戳信息。

而且要注意区分两个不同的问题：

  • 「使某个节点尽量靠前」→ 这是不同的问题，通常要反向拓扑 + 反向贪心，或者用其他建模。
题面里「字典序最小」和「让 x 尽可能早」是两回事，读题时要分清。

4.4 工程用途

场景节点 / 边是什么环意味着什么
构建系统（make / bazel / cargo）节点=目标，边=依赖循环依赖 → 报错
包管理器依赖解析节点=包，边=依赖循环依赖 → 需要特殊处理或报错
任务调度 / 工作流（Airflow、DAG 引擎）节点=任务，边=先后约束不可调度
数据库死锁检测节点=事务，边=「等待谁的锁」死锁 → 选一个牺牲者回滚
编译器的指令调度 / 类型推导顺序节点=指令/类型，边=依赖循环类型定义 → 报错
Agent 工具调用编排节点=工具调用，边=参数依赖无法并行执行
课程安排 / 技能树节点=课程，边=先修无法完成
Excel 公式重算顺序节点=单元格，边=引用循环引用 → 报错
拓扑排序的工程价值有两面：
  • 「顺序」——告诉你按什么次序执行（构建、调度、重算）。
  • 「环检测」——告诉你配置有问题（循环依赖、死锁）。在很多系统里后者才是主要用途：构建工具和包管理器绝大多数时候是在报「循环依赖」这个错。
而「按层剥离」还给出第三个东西：Kahn 的层数 = DAG 的最长路径长度 = 「最少需要几轮才能全部完成」。这在并行调度里是关键指标（关键路径长度决定了理论最短完成时间），也是 Agent 并行工具调用 的调度依据。

5.2 割点与桥

割点（cut vertex / articulation point）：删掉它会让连通分量数增加的节点。
桥（bridge）：删掉它会让连通分量数增加的边。

两者都用 Tarjan 的 low 值求：low[u] = 从 u 的子树（含 u）通过至多一条回边能到达的最小 tin。
桥的判据 树边 (u, v)，v 是 u 的孩子： low[v] > tin[u] （v 的子树无法绕过这条边回到 u 或更早） 割点的判据 树边 (u, v)： low[v] ≥ tin[u] 且 u 不是根 u 是根时：u 有 ≥ 2 个树边孩子 注意：桥用 >，割点用 ≥ —— 一个符号之差
// 求桥（无向图）；注意用边 id 而非父节点来避免重边问题
std::vector<int> tin, low;
int timer = 0;
std::vector<std::pair<int,int>> bridges;

void dfs(int u, int in_edge) {
    tin[u] = low[u] = ++timer;
    for (auto [v, eid] : g[u]) {
        if (eid == in_edge) continue;        // 跳过来时那条边（不是「父节点」）
        if (tin[v]) {                          // 已访问 → 回边
            low[u] = std::min(low[u], tin[v]);
        } else {
            dfs(v, eid);
            low[u] = std::min(low[u], low[v]);
            if (low[v] > tin[u]) bridges.push_back({u, v});   // 桥
        }
    }
}
求桥时必须用边 id 跳过来路，不能用父节点——否则有重边时会把平行边误判成桥（实际上平行边永远不是桥）。求割点时用父节点是安全的（重边不影响割点判定）。
另外 low[u] = min(low[u], tin[v]) 这里用的是 tin[v] 而不是 low[v]——回边只能「跳到」v，不能继续用 v 的 low。混用这两个是最常见的错。

5.3 有向图：SCC

强连通分量（SCC）：有向图中的极大节点集合，使得集合内任意两点可以互相到达。

两种主流算法：
  • Kosaraju（两遍 DFS）：① 在原图上 DFS 求逆后序；② 在反图上按这个顺序 DFS，每棵树就是一个 SCC。易理解、易写，但要建反图（内存双份）。
  • Tarjan（一遍 DFS）：用一个栈维护「当前可能属于同一 SCC 的节点」，当 low[u] == tin[u] 时弹出栈顶到 u 的所有节点作为一个 SCC。一遍完成、不需反图，但逻辑更绕。
// Tarjan SCC：一遍 DFS
std::vector<int> tin, low, comp, stk;
std::vector<bool> on_stack;
int timer = 0, ncomp = 0;

void tarjan(int u) {
    tin[u] = low[u] = ++timer;
    stk.push_back(u); on_stack[u] = true;
    for (int v : g[u]) {
        if (!tin[v]) {                          // 树边
            tarjan(v);
            low[u] = std::min(low[u], low[v]);
        } else if (on_stack[v]) {              // ← 关键：只有在栈上才更新
            low[u] = std::min(low[u], tin[v]);
        }
        // v 已访问但不在栈上 → 跨边，指向已完成的 SCC，不能更新 low
    }
    if (low[u] == tin[u]) {                    // u 是这个 SCC 的根
        while (true) {
            int w = stk.back(); stk.pop_back();
            on_stack[w] = false;
            comp[w] = ncomp;
            if (w == u) break;
        }
        ++ncomp;
    }
}
else if (on_stack[v]) 这个条件是 Tarjan SCC 的核心，也是最容易写错的地方。如果去掉 on_stack 检查，改成对所有已访问的 v 都更新 low，算法就错了——因为指向已经确定的 SCC 的跨边不应该影响当前节点的 low 值（那个 SCC 已经弹出栈了，和当前 SCC 无关）。
这个条件的作用是区分「回边/指向同一 SCC 的边」和「指向已完成 SCC 的跨边」。

5.4 缩点成 DAG

把每个 SCC 缩成一个点，有向图就变成了 DAG（不可能有环，否则那些 SCC 会合并成一个更大的 SCC）。

这个变换的价值在于：DAG 上可以做拓扑排序和 DP，而一般有向图不行。所以「有向图上的最长路径 / 最大权路径」这类在有环图上无解的问题，缩点后就能解。

而且 Tarjan 有个额外好处：它给出的 SCC 编号顺序恰好是缩点后 DAG 的逆拓扑序——可以直接用来做 DP，不必再跑一遍拓扑排序。
问题缩点后怎么解
有向图最长路径 / 最大点权和缩点 → DAG 上按拓扑序 DP
「至少加几条边使全图强连通」缩点 → 答案 = max(入度为 0 的点数, 出度为 0 的点数)
2-SAT建蕴含图 → Tarjan SCC → 若 x 与 ¬x 同 SCC 则无解
「有多少点能被所有点到达」缩点 → 找出度为 0 的 SCC（若唯一则它的大小就是答案）
找必经点 / 必经边缩点 + 支配树
缩点像把「互相都能到」的城市合并成一个都市圈。原来的交通图可能有很多环（A 能到 B，B 也能到 A），难以定义「先后顺序」。
但一旦把每个都市圈看成一个整体，圈与圈之间就一定是单向的——如果 X 圈能到 Y 圈、Y 圈也能到 X 圈，那它们本来就该是同一个圈。

所以缩点的本质是「消除环，从而恢复偏序」——恢复偏序之后，拓扑排序和 DP 这些只能在 DAG 上工作的工具就都能用了。

6.1 判定

二分图：节点能分成两组，使所有边都跨组（组内无边）。
等价刻画：图中不存在奇环。这个等价性是判定算法的依据——染色时冲突意味着找到了奇环。
BFS / DFS 染色（能给出方案）
bool is_bipartite(int n) {
    std::vector<int> col(n, -1);
    for (int s = 0; s < n; ++s) {   // ← 要遍历所有分量
        if (col[s] != -1) continue;
        col[s] = 0;
        std::queue<int> q; q.push(s);
        while (!q.empty()) {
            int u = q.front(); q.pop();
            for (int v : g[u]) {
                if (col[v] == -1) { col[v] = col[u] ^ 1; q.push(v); }
                else if (col[v] == col[u]) return false;   // 奇环
            }
        }
    }
    return true;
}
扩展域并查集（支持在线）
// 每个点拆成 x 和 x+n 两个域
DSU d(2 * n);
for (auto [u, v] : edges) {
    if (d.find(u) == d.find(v)) return false;  // 已被推断为同组 → 矛盾
    d.unite(u, v + n);
    d.unite(u + n, v);
}
return true;
// 优点：边可以陆续到来，随时能回答
// 缺点：拿不到染色方案，也拿不到奇环
染色法有个高频遗漏：必须遍历所有连通分量（外层的 for s 循环）。图可能不连通，只从节点 0 开始 DFS 会漏掉其他分量。
这个坑在所有「图遍历类」题目里都存在——连通分量计数、SCC、拓扑排序（多个入度 0 的起点）都要记得从每个未访问节点各起一次。

6.2 最大匹配

// 匈牙利算法（增广路）：O(V·E)
std::vector<int> match;      // 右部点匹配了哪个左部点，-1 表示未匹配

bool try_augment(int u, std::vector<bool>& used) {
    for (int v : g[u]) {              // u 是左部点
        if (used[v]) continue;
        used[v] = true;
        // v 没被匹配，或 v 的现任能让出来（递归找增广路）
        if (match[v] == -1 || try_augment(match[v], used)) {
            match[v] = u;
            return true;
        }
    }
    return false;
}

int max_matching(int nl) {
    int res = 0;
    for (int u = 0; u < nl; ++u) {
        std::vector<bool> used(match.size(), false);   // 每轮都要重置
        if (try_augment(u, used)) ++res;
    }
    return res;
}
三个必须记住的定理（它们让很多看似无关的问题变成二分图匹配）：
  • König 定理：二分图中，最小点覆盖 = 最大匹配。
  • 最大独立集 = V − 最大匹配（二分图）。
  • 最小路径覆盖（DAG）= V − 最大匹配（把每个点拆成出点和入点建二分图）。
所以看到「最少选多少个点覆盖所有边」「最多选多少个互不相邻的点」「最少用多少条路径覆盖 DAG」，第一反应应该是二分图匹配。
匈牙利算法是 O(V·E)，数据大时用 Hopcroft-Karp（O(E√V)）。而带权二分图匹配（每条边有代价，求最小/最大权完美匹配）要用 KM 算法或转成最小费用最大流——后者更通用且更容易写对。
网络流的建模见 最短路与最小生成树 §8。

  1. 基础邻接矩阵和邻接表怎么选？复杂度差别在哪？
    邻接矩阵邻接表
    空间Θ(V²)Θ(V+E)
    遍历某点所有边Θ(V)（扫整行）Θ(deg)
    判 (u,v) 是否有边Θ(1)Θ(deg)
    判据：稀疏还是稠密
    E 的范围是 [0, V²]。
    稀疏图（E = O(V)：道路网、社交网络、依赖图）→ 邻接表，O(V+E) 远优于 O(V²)。
    稠密图（E ≈ V²：完全图、距离矩阵）→ 邻接矩阵，而且此时 O(V²) 的算法（朴素 Dijkstra、Floyd）反而更好，省掉堆的常数。
    真实世界的图绝大多数是稀疏的，所以默认邻接表。
    高性能场景还有第三选择：CSR / 链式前向星
    两个扁平数组（start[] 存每点边的起始位置，to[] 存所有边的终点），空间 Θ(V+E) 且完全连续。
    对比 vector<vector<int>>：后者每个内层 vector 独立分配，遍历时指针追逐、cache 不友好。CSR 是顺序访问，预取友好。V、E 到百万量级时差别明显。
    读题信号
    看给定的 V、E 范围：V ≤ 500 且要求全源最短路 → 直接邻接矩阵 + Floyd。V = 10⁵ → 必须邻接表（矩阵要 10¹⁰ 格，MLE）。
  2. 基础有向图环检测为什么需要三种颜色？只用 visited 会怎样？

    visited == true 只说明「访问过」，但这有两种截然不同的情况：

    GRAY：还在当前递归栈里
    从 u 走到 v 意味着从 v 能回到 v → 有环。
    BLACK：已经完全处理完了
    只是一条跨边或前向边，不是环。
    只用 visited 的反例
    1→2, 1→3, 2→3。从 1 出发：DFS 到 2，2 到 3（3 变 visited 并完成），回到 1，1 再看 3 —— 若只看 visited 就误报有环。而这是个 DAG。
    enum { WHITE, GRAY, BLACK };
bool dfs(int u) {
    color[u] = GRAY;                          // 进栈
    for (int v : g[u]) {
        if (color[v] == GRAY) return true;   // 回边 → 环
        if (color[v] == WHITE && dfs(v)) return true;
    }
    color[u] = BLACK;                         // 出栈
    return false;
}
    另一条路：Kahn 拓扑排序
    如果最终出队节点数 < n，说明剩下的节点入度永远降不到 0 → 有环。一次遍历同时得到「有没有环」和「如果没有，顺序是什么」，比单独跑环检测更实用。
    无向图不一样
    无向图只有树边和回边（没有前向/跨边），所以只需 visited + 跳过来路。但要用边 id 而非父节点跳——否则有重边时会漏判（两条平行边本身构成环）。
  3. 基础为什么 BFS 能给出无权图的最短路？BFS 有什么实现坑？

    因为 BFS 按层扩展——先访问所有距离 1 的，再距离 2 的……所以一个节点第一次被访问时，走的必然是最短路径。

    这个论证依赖「每条边权重相同」
    边权不同时「层数少」不等于「距离短」，BFS 失效 → 要用 Dijkstra。
    而 0-1 BFS 是两者之间的折中：边权只有 0/1 时用双端队列，O(V+E)。
    最高频的实现坑：出队时才标记
    必须在「入队时」标记并设 dist：
    for (int v : g[u])
    if (dist[v] == -1) {          // 检查
        dist[v] = dist[u] + 1;     // 入队时就设
        q.push(v);
    }
    出队时标记会让同一节点多次入队——稠密图上队列膨胀到 O(E)，而且 dist 可能被写成非最短值。症状是「答案对但超时」或「答案偏大」。
    第二个坑：只从节点 0 开始
    图可能不连通。要计数连通分量、或确保全覆盖时，必须外层从每个未访问节点各起一次。
    这个坑在所有图遍历题里都存在（连通分量、SCC、二分图染色、拓扑排序的多个起点）。
    多源 BFS
    「从任意一个起点出发的最短距离」不需要跑 k 次——把所有起点一起放进初始队列，复杂度仍是 O(V+E)。
    正确性：等价于「加一个虚拟超级源点，连所有起点，边权 0」。看到「任意一个 / 至少一个」就该想到加虚拟节点。
  4. 基础写出拓扑排序，并说明怎么顺带检测环。

    Kahn 算法：反复取出入度为 0 的节点。

    std::vector<int> topo(int n) {
    std::vector<int> indeg(n, 0), order;
    for (int u = 0; u < n; ++u)
        for (int v : g[u]) ++indeg[v];

    std::queue<int> q;
    for (int u = 0; u < n; ++u) if (!indeg[u]) q.push(u);

    while (!q.empty()) {
        int u = q.front(); q.pop();
        order.push_back(u);
        for (int v : g[u]) if (--indeg[v] == 0) q.push(v);
    }
    if ((int)order.size() != n) return {};   // ← 环检测
    return order;
}
    环检测
    如果最终 order.size() < n，说明剩下的节点入度永远降不到 0——它们互相依赖，构成环。必须检查这一行，否则有环时会静默返回错误的部分序。
    另一种写法：DFS 逆后序
    DFS 后序的逆序就是拓扑序。证明：对任意边 u→v，若 v 是 WHITE 则先递归完 v（tout[v] < tout[u]）；若 v 是 BLACK 则显然 tout[v] < tout[u]；若 v 是 GRAY 则有环。所以按 tout 降序排列满足所有边的约束。
    KahnDFS 逆后序
    求字典序最小能（队列换最小堆）不能
    求「最少几轮完成」能（按层剥离）不直接
    栈深风险无深图爆栈
    用于 Kosaraju 求 SCC不适用必须用它
    默认用 Kahn
    更直观、无爆栈、能扩展到字典序最小和分层。只在做 Kosaraju 或需要时间戳时用 DFS 逆后序。

9.2 中级（区分熟练度）

  1. 中级什么是 0-1 BFS？为什么它能用双端队列代替堆？

    当边权只有 0 和 1 两种时，不需要 Dijkstra 的堆——用双端队列即可，复杂度从 O((V+E) log V) 降到 O(V+E)。

    for (auto [v, w] : g[u]) {            // w ∈ {0, 1}
    if (dist[u] + w < dist[v]) {
        dist[v] = dist[u] + w;
        if (w == 0) dq.push_front(v);   // 同层 → 队首
        else          dq.push_back(v);    // 下一层 → 队尾
    }
}
    为什么对
    双端队列在任意时刻最多包含两个不同的距离值（d 和 d+1），且队首的距离总是最小的——这正好复现了 Dijkstra「每次取距离最小的点」的性质，而不需要堆来维护。
    权 0 的边不增加距离 → 新节点属于「当前层」→ 压队首；权 1 → 「下一层」→ 压队尾。
    本质是 Dijkstra 的特例：「取最小」这个操作被队列结构免费提供了。
    识别信号
    「某些移动免费、某些移动花费 1」：
    · 网格最短路，某些格子可以「打通」（打通花 1，直接走花 0）
    · 「最少翻转多少条边使 s 能到 t」→ 正向边权 0、反向边权 1
    · 迷宫中「转弯花代价、直走免费」
    更一般的情形
    边权只有 {0, w} 两种也可以（把 w 当 1，最后乘回去）。
    边权是小范围整数 [0, C] 时用桶队列 / dial's algorithm：每个距离一个桶，O(V + E + C·V)。
    这一族方法的共同思路是：用「结构」代替「堆」来提供有序性——只要距离值的取值范围足够小或足够规整。
  2. 中级怎么求无向图的桥和割点？两者的判据差别在哪？

    都用 Tarjan 的 low 值：low[u] = 从 u 的子树（含 u）通过至多一条回边能到达的最小 tin。

    桥 树边 (u,v)：low[v] > tin[u] （v 的子树无法绕过这条边回到 u 或更早） 割点 树边 (u,v)：low[v] ≥ tin[u] 且 u 不是根 u 是根时：u 有 ≥ 2 个树边孩子
    为什么一个是 > 一个是 ≥
    桥关心的是「这条边能不能被绕过」——如果 v 的子树能回到 u 本身（low[v] == tin[u]），那说明有另一条路径连接 u 和 v，这条边不是桥。
    割点关心的是「删掉这个点后 v 的子树是否失联」——如果 v 的子树最多只能回到 u（而回不到 u 的祖先），那删掉 u 就会让 v 的子树孤立，所以 low[v] == tin[u] 时 u 就是割点。
    三个实现坑
    ① 求桥必须用边 id 跳过来路，不能用父节点——否则有重边时会把平行边误判成桥（平行边永远不是桥）。求割点用父节点是安全的。
    ② 回边更新必须是 low[u] = min(low[u], tin[v])，不是 low[v]——回边只能「跳到」v，不能继续用 v 的 low。混用这两个是最常见的错。
    ③ 根节点的割点判据不同（要数树边孩子个数），忘了特判会误判根。
    工程意义
    桥和割点就是单点故障：网络拓扑里的桥是「断了就分区的链路」，割点是「宕了就分区的路由器」。
    进一步：边双连通分量（去掉桥后的连通块）内部任意两点有至少两条边不重复的路径 → 冗余区域。这是网络可靠性分析的基础。
  3. 中级Tarjan 求 SCC 里的 on_stack 检查为什么必不可少？

    因为它区分了两种「v 已被访问」的情况，而它们对 low[u] 的影响完全不同。

    for (int v : g[u]) {
    if (!tin[v]) {                          // 树边
        tarjan(v);
        low[u] = std::min(low[u], low[v]);
    } else if (on_stack[v]) {              // ← 关键
        low[u] = std::min(low[u], tin[v]);
    }
    // v 已访问但不在栈上 → 指向已完成的 SCC，不能更新 low
}
    在栈上 vs 不在栈上
    在栈上：v 属于「当前正在探索、还没确定归属」的节点集合 → u 和 v 可能在同一个 SCC → 应该更新 low。
    不在栈上：v 所属的 SCC 已经确定并弹出了 → u 和 v 一定不在同一个 SCC（否则 v 的 SCC 不会先被确定）→ 这条跨边不应影响 u 的 low。
    去掉检查会怎样
    对所有已访问的 v 都更新 low，会让 u 的 low 被无关的、已完成的 SCC 拉低 → low[u] == tin[u] 的判定失效 → SCC 划分错误（通常是把多个 SCC 错误地合并）。
    对比 Kosaraju
    Kosaraju 两遍 DFS：① 原图求逆后序；② 反图上按该顺序 DFS，每棵树就是一个 SCC。
    易理解易写，但要建反图（内存双份）。Tarjan 一遍完成、不需反图，代价是逻辑更绕。面试里 Kosaraju 更容易讲清，生产里 Tarjan 更常用。
    Tarjan 的一个额外好处
    它给出的 SCC 编号顺序恰好是缩点后 DAG 的逆拓扑序——可以直接用来做 DP，不必再跑一遍拓扑排序。
    而缩点的意义是「消除环，恢复偏序」：把每个 SCC 缩成一个点后必然是 DAG（否则那些 SCC 会合并），于是拓扑排序和 DAG 上的 DP 就都能用了。
  4. 中级判断二分图有哪两种方法？各自的适用场景？

    二分图 ⟺ 不存在奇环。这个等价性是两种算法的共同依据。

    方法一 · BFS/DFS 染色
    相邻节点染不同色，冲突则有奇环。
    for (int s = 0; s < n; ++s) {      // 必须遍历所有分量
    if (col[s] != -1) continue;
    // BFS 染色，col[v] = col[u] ^ 1
    // if (col[v] == col[u]) return false;
}
    能给出染色方案，也能输出一个奇环。
    方法二 · 扩展域并查集
    每个点拆成 x 和 x+n 两个域。对每条边 (u,v)：先查 find(u) == find(v)（已被推断为同组 → 矛盾），否则 unite(u, v+n) 且 unite(u+n, v)。
    支持在线——边可以陆续到来，随时能回答。
    染色扩展域并查集
    给出染色方案能否
    输出奇环能否
    在线处理需先建全图支持
    代码量中等更短
    「在线 vs 离线」是第一个分岔口
    题面说「依次处理 m 个操作，每次输出答案」→ 必须并查集。说「给定一张图，判断/输出方案」→ 染色更合适。
    染色法的高频遗漏
    必须遍历所有连通分量。图可能不连通，只从节点 0 开始会漏掉其他分量。这个坑在所有图遍历题里都存在。

9.3 高级（体现深度）

  1. 高级设计一个构建系统的依赖调度器，怎么做？循环依赖怎么报错？

    模型：节点 = 构建目标，边 = 依赖关系（A 依赖 B ⟹ 边 B→A，表示 B 必须先完成）。核心是拓扑排序。

    ① 用 Kahn 而不是 DFS
    三个理由：无爆栈风险（依赖链可能很长）；顺带环检测；最重要的是——按层剥离天然给出并行度。
    ② 按层并行执行
    Kahn 的每一「层」（同时入度为 0 的节点）内部互无依赖，可以并行。
    层数 = DAG 的最长路径长度 = 关键路径，它决定了理论最短完成时间——再多机器也不能更快。这是评估「加机器有没有用」的关键指标。
    实际实现通常不严格按层，而是「谁的依赖先满足谁就开跑」（用一个工作队列 + 计数器），并行度更高。
    ③ 循环依赖的报错必须可诊断
    光说「检测到循环依赖」没用——用户需要知道是哪几个目标构成的环。
    做法：Kahn 结束后若 order.size() < n，对剩下的节点跑一次 DFS 三色标记，遇到 GRAY 时沿递归栈回溯打印整个环。
    这是「工程实现」和「刷题实现」的关键差别：刷题只要返回 false，生产必须给出可操作的错误信息。
    ④ 还要处理的现实问题
    增量构建：只重建「变了的目标 + 它的所有下游」→ 从变更点做正向可达性搜索（BFS/DFS）。
    缓存命中：用「输入内容哈希 + 命令哈希」做 key（bazel 的做法），能跨机器复用。
    失败处理：一个目标失败后，它的所有下游都要标记为「跳过」而不是「失败」——同样是正向可达性。
    动态依赖：某些依赖只有构建后才知道（如 C 的 #include）→ 需要边构建边扩展图。
    ⑤ 这个模型的其他化身
    Airflow / DAG 工作流引擎、Excel 公式重算、编译器的类型推导顺序、Agent 工具调用编排、包管理器依赖解析（但版本约束求解本质是 SAT，比拓扑排序难）。
    共同点：都要同时解决「顺序」和「环检测」两件事，而且环检测的错误信息质量往往比算法效率更重要。
  2. 高级数据库怎么检测死锁？检测到之后怎么办？

    建等待图（wait-for graph）：节点 = 事务，边 T1 → T2 表示「T1 在等 T2 持有的锁」。死锁 ⟺ 等待图中有环。

    ① 检测：有向图环检测
    用 DFS 三色标记（GRAY = 在当前递归栈中）。发现回边时沿栈回溯得到整个环——这一步是必要的，因为要从环里选牺牲者。
    触发时机有两种：周期性检测（每隔几百毫秒扫一遍，MySQL 早期）或等待时立即检测（每次一个事务开始等待就从它出发找环，InnoDB 的做法，更及时）。
    ② 选牺牲者的策略
    不能随便选——要让代价最小且避免活锁（同一个事务反复被选中回滚，永远无法完成）：
    · 回滚代价最小：已修改的行数最少、持有的锁最少、已执行时间最短（InnoDB 用「undo log 长度」近似）
    · 避免活锁：把「已被回滚次数」计入权重，或按事务开始时间给老事务优先权
    · 不选系统关键事务
    ③ 另一条路：预防而非检测
    超时（innodb_lock_wait_timeout）：最简单，但会误杀只是慢的事务，且超时值难调（太短误杀、太长死锁持续久）。
    按固定顺序加锁：从根上避免环（比如「总是按主键升序加锁」）。这是应用层最有效的手段，但要求所有代码都遵守。
    Wait-Die / Wound-Wait：按事务时间戳决定「等待还是回滚」，无环可证，但回滚率高于检测法。
    ④ 分布式场景更难
    单机的等待图在一个进程内，扫一遍就行。分布式下等待关系跨节点，要么用集中式死锁检测器（收集各节点的局部等待图拼成全局图，有单点和延迟问题），要么用边追逐（edge chasing）算法传递探测消息。
    而且网络延迟会导致「假死锁」——检测到环时它可能已经解开了。所以分布式系统更倾向用超时 + 重试这种简单粗暴但鲁棒的方案。这是「理论最优」在分布式下让位于「可运维」的又一个例子。
  3. 高级一个 DFS 在生产数据上爆栈了，有哪些解法？各自的取舍？

    DFS 递归深度 = 图的最长路径，而 Linux 默认栈 8 MB、每帧几十到上百字节 → 安全深度约 10⁴–10⁵。V = 10⁶ 的链状图必崩。

    ① 换 BFS（最简单，优先考虑）
    队列在堆上，天然不爆栈。
    但要确认问题是否允许：求最短路、连通分量、拓扑排序（Kahn）、二分图判定都可以换。不能换的是依赖「后序」的问题——求 SCC、桥、割点、子树聚合、时间戳，这些必须 DFS。
    ② 显式栈改写 DFS
    把递归改成「栈里存 (节点, 已处理到第几个邻居)」，模拟递归的执行状态。
    能保留 DFS 的全部性质（包括后序和时间戳），代价是代码可读性明显下降，而且容易写错（尤其是后序位置）。
    这就是递归转迭代里的「状态机」方法——栈里存的那个「已处理到第几个」就是程序计数器。
    ③ 加大栈（临时止血，不是根治）
    ulimit -s unlimited、pthread_attr_setstacksize、或在 Windows 上用链接器选项。
    缺点：只是把上限推高，深度再翻倍还是会崩；而且在容器/受限环境里可能改不了；多线程时每个线程都要这么大栈，内存浪费。可以作为应急，但要同时安排根治。
    ④ 深度断言 + 拒绝（安全视角）
    如果图来自不可信输入（用户上传的依赖文件、外部 API 返回的关系），这不只是性能问题而是 DoS 漏洞——攻击者构造深链就能打崩服务。
    必须加显式深度上限并优雅拒绝，而不只是改大栈。这和递归下降解析器的爆栈是同一类问题。
    ⑤ 决策顺序
    问题允许换 BFS 吗？→ 换（最省事）。
    必须 DFS 但图可信？→ 显式栈（一次性成本，之后不用再管）。
    必须 DFS 且图不可信？→ 显式栈 + 深度上限（安全要求）。
    只是临时救火？→ 加大栈 + 记一个技术债。
    另外用 -fsanitize=address 能把爆栈报成明确的 stack-overflow 而不是裸 SIGSEGV，定位快得多。
  4. 高级怎么把一个实际问题识别成图问题？建模时最容易错在哪？

    三个识别信号：

    ① 「依赖 / 先后 / 前置」
    → 有向图 + 拓扑排序。构建系统、任务调度、类型推导、Excel 重算。
    ② 「连通 / 可达 / 分组」
    → 连通分量。无向图用并查集（在线）或 DFS（要更多信息）；有向图用 SCC。
    ③ 「最少步数 / 最短」
    → BFS（无权）、0-1 BFS（权只有 0/1）、Dijkstra（正权）、Bellman-Ford（有负权）。
    最容易错的是「节点是什么」
    节点不一定是题面里显式给的对象：
    · 状态空间搜索：节点是整个状态（八数码里是整个棋盘、单词接龙里是整个单词）。这类图不显式建出来——邻居是「按规则生成的」，图可能是无穷大的。
    · 拆点：一个对象拆成「入点」和「出点」。用于点容量限制（网络流）、DAG 最小路径覆盖（二分图匹配）。
    · 分层图：节点是 (位置, 附加状态)。「最多可以免费坐 k 次车的最短路」→ 节点变成 (城市, 已用免费次数)，图规模乘以 k+1。
    · 边变节点：某些问题里边才是主体（如「边的着色」）。
    第二个易错点：边的方向和权重
    「A 依赖 B」建成 A→B 还是 B→A？取决于你要什么——求「执行顺序」要 B→A（B 先完成），求「影响范围」要 A→B（改了 B 影响谁）。两个方向的图都建出来往往更方便。
    「最少翻转多少边」这类题里，边权是你构造出来的（正向 0、反向 1），不是题面给的。
    建模比套算法难，也更值得练
    算法就那几个（DFS/BFS/拓扑/Dijkstra/并查集），而建模的变化是无穷的。
    练法：拿到题先问三句——「节点是什么？边是什么？我要的答案对应图上的什么？」把这三句用自然语言写清楚，算法通常就自明了。反过来，如果这三句说不清，直接开始写代码一定会绕弯路。
