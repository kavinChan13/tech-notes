最短路与最小生成树

最短路的四个算法（Dijkstra / Bellman-Ford / Floyd / A*）共用同一个原子操作——松弛；它们的差别只在「按什么顺序松弛」和「松弛几轮」。MST 的两个算法（Kruskal / Prim）也共用同一个定理——割性质。理解这两个共同基础，六个算法就从「六个模板」变成「两个思想的四种和两种实现」。

01

松弛：所有最短路算法的原子操作

四个算法的差别只在「按什么顺序松弛」

松弛（relax） 对边 (u, v, w)： if (dist[u] + w < dist[v]) dist[v] = dist[u] + w; 含义：「经过 u 到 v」比「当前已知的到 v 的路径」更短，那就更新
算法松弛顺序松弛几轮复杂度能处理负权
BFS按层每边一次O(V+E)不适用（边权必须相同）
Dijkstra按当前 dist 最小的点每点出队一次O((V+E) log V)否
Bellman-Ford任意顺序，全部边n−1 轮O(V·E)是，且能检测负环
SPFA只松弛「dist 变小过」的点的出边不定平均好，最坏 O(V·E)是
Floyd按「允许经过的中间点集合」V 轮O(V³)是（无负环）
A*按 dist + 启发值最小每点出队一次取决于启发函数否
为什么「松弛顺序」决定了一切：最短路问题的解满足最优子结构（最短路的任意前缀也是最短路），所以只要「松弛的顺序保证了在松弛边 (u,v) 时 dist[u] 已经是最终值」，一次松弛就够。
  • Dijkstra 用「每次取 dist 最小的点」来保证这一点——但这个保证依赖非负权（§2.3）。
  • Bellman-Ford 不做任何保证，用「重复 n−1 轮」来暴力覆盖所有可能的顺序。
  • Floyd 换了个维度：按「允许经过哪些中间点」递增地松弛。
所以这四个算法不是四个独立的技巧，而是「松弛顺序」这一个设计空间里的四个点。
松弛像不断更新「到某地的最优报价」。你手上有一张各城市的报价表（初始都是 ∞），有人告诉你「从 A 到 B 只要 50」，你就检查「我到 A 的报价 + 50」是否比「我到 B 的现有报价」更便宜，便宜就更新。

Dijkstra 是精明的采购：每次先确认最便宜的那个城市（它的报价不可能再降了），再用它去更新邻居。
Bellman-Ford 是笨但稳的采购：不管顺序，把所有报价单反复过 n−1 遍，保证不漏。
Floyd 是会计式的做法：逐个考虑「如果允许中转 1 号城市呢？允许中转 1、2 号呢？」

而负权就像「某条路走过去还倒给你钱」——精明的采购会失效，因为「已经确认最便宜」这个前提被打破了。

1.1 与其他章节的关系

  • 图遍历与拓扑排序 —— BFS 是无权最短路；DAG 上按拓扑序松弛一遍即可
  • 堆与 Top-K —— Dijkstra 的优先队列、延迟删除与索引堆
  • 并查集与区间结构 —— Kruskal 完全建立在并查集上
  • 动态规划 —— Floyd 和 Bellman-Ford 本质都是 DP

02

Dijkstra

最常用，也最容易在负权上翻车

2.1 算法与实现

// 堆优化 Dijkstra + 延迟删除（最常用的写法）
std::vector<long long> dijkstra(int s, int n) {
    const long long INF = LLONG_MAX / 4;
    std::vector<long long> dist(n, INF);
    // (距离, 节点)，小顶堆
    std::priority_queue<std::pair<long long, int>,
                        std::vector<std::pair<long long, int>>,
                        std::greater<>> pq;
    dist[s] = 0;
    pq.push({0, s});

    while (!pq.empty()) {
        auto [d, u] = pq.top(); pq.pop();
        if (d > dist[u]) continue;      // ← 延迟删除：这是个过期条目
        for (auto [v, w] : g[u]) {
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.push({dist[v], v});   // 不改旧条目，直接压新的
            }
        }
    }
    return dist;
}
三个必须注意的实现点：
  • if (d > dist[u]) continue; 不能省。延迟删除会让同一个节点被多次入堆，这一行跳过已经被更好的路径更新过的过期条目。省掉它虽然不影响正确性（后面的松弛都不会成功），但会白做大量无用的邻居遍历。
  • INF 不要用 LLONG_MAX。dist[u] + w 会溢出。用 LLONG_MAX / 4 或先判 dist[u] == INF 再加。
  • 邻接表存 (邻居, 权重)，不要用邻接矩阵（除非是稠密图，此时反而该用 O(V²) 的朴素 Dijkstra，省掉堆的常数）。

2.2 正确性证明

不变式：每次从堆里取出的节点 u，它的 dist[u] 就是最终的最短距离（之后不会再变小）。

证明（反证）：假设取出 u 时 dist[u] 不是最短。那么存在一条更短的路径 s → … → x → … → u，其中 x 是这条路上第一个还没被取出的节点。
因为 x 在这条更短路径上，且所有边权非负，所以：
真实最短距离(x) ≤ 真实最短距离(u) < dist[u] ↑ 这一步用到「x 到 u 的那段路径长度 ≥ 0」
而 x 之前的节点都已取出（dist 已确定），所以 x 已经被松弛过 ⟹ dist[x] = 真实最短距离(x) < dist[u]。
但堆是按 dist 取最小的，dist[x] < dist[u] 意味着 x 应该比 u 先被取出——与「x 还没被取出」矛盾。∎
这个证明的关键一步是「x 到 u 的那段路径长度 ≥ 0」——它完全依赖非负权。这就是为什么负权会让 Dijkstra 失效：那一步不成立，整个论证链断掉。
面试时能指出「证明的哪一步用到了非负性」，比只说「Dijkstra 不能处理负权」深一层。

2.3 负权为何失效

三个常见的错误认知：
  • 「给所有边权加一个大常数变成正数就行了」——错。加常数会让边数多的路径被额外惩罚：原本 3 条边共 5 的路径变成 5+3C，2 条边共 6 的路径变成 6+2C，C 够大时后者反而更短。只有「所有路径边数相同」时才成立。
  • 「负权但无负环，Dijkstra 就能用」——错。上面的反例就没有负环。
  • 「加个 visited 数组不重复访问就行」——错。问题不在重复访问，而在「过早确定」。
正确做法：有负权就用 Bellman-Ford / SPFA；如果需要多次查询且负权固定，用 Johnson 算法（先用 Bellman-Ford 算出一组「势能」重新赋权成非负，再对每个源跑 Dijkstra）。

2.4 堆优化与延迟删除

实现方式复杂度适用
朴素（每轮线性扫最小）O(V²)稠密图（E ≈ V²）反而最优，无堆开销
二叉堆 + 延迟删除O(E log E)默认选择，代码最简单
索引堆（真 decrease-key）O(E log V)堆大小恒为 V，稠密图上更省内存
d-ary 堆（d=4）O(E log₄ V)decrease-key 密集时更快（cache 友好）
斐波那契堆O(E + V log V)理论最优但实测很差
桶队列 / dial'sO(E + maxW·V)边权是小范围整数时
延迟删除是实践中的默认选择，尽管它的堆可能膨胀到 O(E)：
  • 不需要维护「节点 → 堆内位置」的映射，代码短一半。
  • 常数更小：索引堆的每次元素移动都要额外写一次映射表。
  • 堆膨胀到 O(E) 在稀疏图上无所谓（E = O(V)）。
只在稠密图 + 内存紧张时才值得上索引堆。斐波那契堆的理论优势（稠密图上 O(E + V log V)）在实测里被它的指针追逐和 consolidate 开销吃掉，实践中用配对堆或 d-ary 堆更好（见 堆与 Top-K §7）。

Bellman-Ford 与 SPFA

能处理负权，代价是不再贪心

3.1 为什么是 n−1 轮

std::vector<long long> bellman_ford(int s, int n,
                                    const std::vector<Edge>& edges) {
    const long long INF = LLONG_MAX / 4;
    std::vector<long long> dist(n, INF);
    dist[s] = 0;

    for (int round = 0; round < n - 1; ++round) {
        bool changed = false;
        for (auto& [u, v, w] : edges)
            if (dist[u] != INF && dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                changed = true;
            }
        if (!changed) break;      // 提前收敛（实践中很常见）
    }
    // 再跑一轮：如果还能松弛，说明有负环
    for (auto& [u, v, w] : edges)
        if (dist[u] != INF && dist[u] + w < dist[v])
            return {};              // 存在负环，最短路无定义
    return dist;
}
为什么 n−1 轮足够：无负环时，任意最短路最多有 n−1 条边（否则会重复访问节点，形成环；而非负环可以去掉，负环则无最短路）。

用归纳法：第 k 轮结束后，所有「最多 k 条边的最短路」都已被正确算出。
· k=1：直接从 s 出发的边，第一轮必然被松弛。
· k→k+1：设最短路 s → … → u → v 有 k+1 条边，则 s → … → u 有 k 条边，由归纳假设 dist[u] 在第 k 轮后已正确。第 k+1 轮松弛边 (u,v) 时就会得到正确的 dist[v]。∎

所以 n−1 轮覆盖了「最多 n−1 条边」的所有最短路。
if (!changed) break; 这一行在实践中极重要：真实图上通常几轮就收敛，很少跑满 n−1 轮。加上它，Bellman-Ford 在很多实际数据上比理论 O(V·E) 快得多。
另外注意松弛的边顺序会影响收敛速度（但不影响正确性）——按 BFS 序松弛通常比随机顺序快，这也是 SPFA 的动机。

3.2 负环检测

方法做法注意
Bellman-Ford 第 n 轮跑完 n−1 轮后再跑一轮，若还能松弛 → 有负环只能检测从 s 可达的负环
检测任意负环把所有 dist 初始化为 0（等价于加超级源连所有点）这样能查全图的负环
SPFA 入队计数某点入队次数 ≥ n → 有负环常用，但最坏仍 O(V·E)
SPFA + DFS 版DFS 中如果回到栈上的点 → 负环检测负环更快，但求最短路不如 BFS 版
Floydd[i][i] < 0 → 经过 i 有负环O(V³)，但能定位是哪个点
「有负环」和「有负权」是完全不同的两件事：
  • 负权但无负环 → 最短路存在且有定义，用 Bellman-Ford / SPFA 求。
  • 有负环且从 s 可达该环 → 最短路无定义（可以绕环无限次让距离趋于 −∞），必须报错而不是返回某个值。
  • 有负环但从 s 不可达 → 不影响 s 的最短路，正常返回。
题目说「求最短路」时如果可能有负环，必须先明确「有负环时应该输出什么」——这是读题要问的。

3.3 SPFA 与它的最坏

// SPFA = 队列优化的 Bellman-Ford
// 只有「dist 变小过」的点才需要用来松弛它的出边
std::vector<long long> spfa(int s, int n) {
    const long long INF = LLONG_MAX / 4;
    std::vector<long long> dist(n, INF);
    std::vector<bool> in_queue(n, false);
    std::vector<int> cnt(n, 0);        // 入队次数，用于负环检测
    std::queue<int> q;

    dist[s] = 0; q.push(s); in_queue[s] = true;
    while (!q.empty()) {
        int u = q.front(); q.pop(); in_queue[u] = false;
        for (auto [v, w] : g[u])
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                if (!in_queue[v]) {
                    if (++cnt[v] >= n) return {};   // 负环
                    q.push(v); in_queue[v] = true;
                }
            }
    }
    return dist;
}
SPFA 的最坏复杂度仍是 O(V·E)，而且这个最坏是可以被构造出来的。竞赛界有句话「关于 SPFA，它死了」——指的就是出题人会专门造反例卡掉 SPFA 的选手。

所以选型原则很清晰：
  • 非负权 → 一律用 Dijkstra（有确定性的 O(E log V) 保证）。不要因为「SPFA 平均更快」就用它。
  • 有负权 → 用 SPFA 或 Bellman-Ford。此时没得选，但要意识到最坏是 O(V·E)。
  • 需要更好的保证 → Johnson 算法（一次 Bellman-Ford 重赋权 + V 次 Dijkstra）或 Bellman-Ford + SLF/LLL 优化（启发式，仍无保证）。
04

Floyd-Warshall

五行代码解全源最短路，但循环顺序不能错

4.1 DP 视角与循环顺序

// 全源最短路，O(V³)。d 初始化为邻接矩阵（无边为 INF，d[i][i]=0）
for (int k = 0; k < n; ++k)          // ← k 必须在最外层
    for (int i = 0; i < n; ++i)
        for (int j = 0; j < n; ++j)
            if (d[i][k] + d[k][j] < d[i][j])
                d[i][j] = d[i][k] + d[k][j];
Floyd 的 DP 状态定义：d[k][i][j] = 从 i 到 j、只允许经过编号 < k 的中间节点的最短距离。

d[k+1][i][j] = min( d[k][i][j], // 不经过 k d[k][i][k] + d[k][k][j] ) // 经过 k
而 k 这一维可以省掉（滚动数组）——因为 d[k][i][k] == d[k+1][i][k]（到 k 的路径不会因为「允许经过 k」而变短），所以原地更新是安全的。

这就是为什么 k 必须在最外层：它是 DP 的「阶段」维度，而 i、j 是状态维度。把 k 放到内层，就变成了「对每个 (i,j) 试所有中转点」——那只考虑了一次中转，得不到正确答案。
循环顺序写错是 Floyd 最经典的 bug，而且它在小图上可能碰巧对： 
// ❌ 错的：k 在内层
for (i) for (j) for (k)
    d[i][j] = min(d[i][j], d[i][k] + d[k][j]);
// 这只做了「一次中转」的松弛，路径需要两次以上中转时就错
记法：k 是「阶段」（允许用哪些中转点），i, j 是「状态」。DP 的阶段必须在最外层。这条规律对所有类似的 DP 都成立（背包的物品维、区间 DP 的长度维）。

4.2 传递闭包与最小环

变体改什么用途
传递闭包把 min/+ 换成 或/与：d[i][j] |= d[i][k] & d[k][j]「i 能否到达 j」；用 bitset 可优化到 O(V³/64)
最小环在 k 循环内、更新前统计 d[i][k] + d[k][j] + w(j,i)求经过至少 3 个点的最小环
负环检测跑完后看 d[i][i] < 0能定位是哪个点在负环上
路径还原额外存 nxt[i][j]，更新时 nxt[i][j] = nxt[i][k]输出具体路径
恰好 k 条边的最短路邻接矩阵的 (min,+) 快速幂O(V³ log k)
最大瓶颈路把 min(a, b+c) 换成 max(a, min(b,c))「路径上最小边权最大」
最后两行体现了一个通用视角：Floyd 的骨架适用于任何「(⊕, ⊗) 半环」上的路径问题。
  • (min, +) → 最短路
  • (max, min) → 最大瓶颈路（路径上最小边权最大）
  • (or, and) → 可达性（传递闭包）
  • (+, ×) → 路径计数 / 概率
识别出这个抽象，一份 Floyd 代码就能解四类问题。同样的抽象也适用于矩阵快速幂求「恰好 k 步」的各类问题。
Floyd 的 O(V³) 看着慢，但它的常数极小（三层纯循环，无堆无队列，cache 友好），而且能用 SIMD/OpenMP 轻松并行。
实践中的判据：V ≤ 400~500 时 Floyd 往往比「跑 V 次 Dijkstra」更快（后者是 O(V·E log V)，稠密图上 E ≈ V² 就变成 O(V³ log V)）。而且代码只有五行，不容易写错。
05

A* 与启发式

用「对未来的估计」引导搜索方向

5.1 可采纳与一致性

Dijkstra：按 g(n) 排序 g = 从起点到 n 的已知距离 A* ：按 f(n) = g(n) + h(n) 排序 h = 从 n 到终点的估计距离 h ≡ 0 → 退化成 Dijkstra h 越准 → 搜索范围越小 h = 真实距离 → 直接沿最优路径走，不扩展任何多余节点
两个性质决定 A* 的行为：
  • 可采纳性（admissible）：h(n) ≤ 真实距离(n → 目标)，即永不高估。
    ⟹ 保证找到最优解。
  • 一致性 / 单调性（consistent）：对任意边 (u,v,w)，h(u) ≤ w + h(v)（类似三角不等式）。
    ⟹ 保证每个节点只需扩展一次（不需要重新打开已关闭的节点）。
    一致 ⟹ 可采纳（反之不成立）。
实践含义：只用「可采纳」的 h 时，A* 仍能找到最优解，但可能需要重新打开已关闭的节点（reopening），实现更复杂。用「一致」的 h 就能像 Dijkstra 那样「出队即确定」。
常见的几何启发（曼哈顿距离、欧氏距离）在对应的移动规则下都是一致的。
场景启发函数 h是否一致
网格四连通曼哈顿距离 |dx| + |dy|是
网格八连通对角距离 max(|dx|, |dy|)是
任意方向移动欧氏距离是
八数码错位数 / 曼哈顿距离之和是（后者更准）
道路网（真实地图）直线距离 / 最大限速是（除以最大速度保证不高估时间）
—用错的 h（如乘个系数 > 1）不可采纳 → 可能不是最优解
最后一行是实践中的常见权衡：把 h 乘上一个 ε > 1 的系数（weighted A*）会让搜索快得多，但只保证「解不超过最优解的 ε 倍」。
游戏寻路、地图导航里这是可接受的（用户感知不到 5% 的路径差异，但等待时间从 200ms 降到 20ms 很明显）。但要明确知道自己放弃了最优性——不能一边用 weighted A* 一边宣称结果最优。

5.2 双向与分层预处理

技术核心思路适用
双向 Dijkstra / A*从起点和终点同时搜，相遇即停搜索量从 b^d 降到 2b^(d/2)；终止条件比单向复杂
ALT（A* + Landmarks + 三角不等式）预选若干地标，预计算所有点到地标的距离，用三角不等式得到更强的 h道路网；预处理换查询速度
Contraction Hierarchies按「重要性」逐个收缩节点，加入捷径边现代地图导航的主流；全国路网查询能到微秒级
Hub Labeling每点预存一组「枢纽 + 距离」，查询时求交集查询最快，但预处理和存储开销大
分层图高速路一层、国道一层、市内一层直观，工业界早期做法
双向搜索的终止条件是最容易错的地方：不是「两边相遇就得到最优解」。
正确条件是：当两边已扩展节点的最小 dist 之和 ≥ 当前找到的最优路径长度时才能停。因为相遇点不一定在最优路径上——可能存在一条经过其他节点的更短路径还没被发现。

标准做法是：相遇后不立刻返回，而是继续搜索并维护一个「当前最优」，直到上述条件满足。无权图的双向 BFS 没这个问题（层数单调），所以很多人从 BFS 迁移到 Dijkstra 时会踩这个坑。
A* 像开车时既看里程表也看导航的剩余距离。Dijkstra 只看「已经开了多少」——所以它向四面八方均匀扩散，像水波纹。A* 同时看「还剩多少」，于是优先探索朝着目标的方向。

「可采纳」就是「导航不能低报剩余距离」——如果导航说还剩 1 公里但实际有 10 公里，你会误以为快到了而放弃探索其他更好的路线。低报（h 高估）会导致错过最优解；而保守估计（h ≤ 真实）虽然会多探索一些，但保证不错过。

最小生成树

两个算法，一个定理

7.1 割性质：两个算法的共同基础

最小边一定属于某棵 MST 割 A B C 集合 S D E F 集合 V∖S 2 ← 最小 7 5 横跨割的边：A-D(7), B-D(5), B-F(2) → 权 2 的边必在某棵 MST 里
割性质：把节点集分成任意两个非空部分 S 和 V∖S，则横跨这个割的所有边中，权重最小的那条一定属于某棵最小生成树。

证明（交换论证）：设 e 是横跨割的最小边，假设某棵 MST T 不含 e。把 e 加入 T 会形成一个环，而这个环必然至少还有另一条边 f 也横跨这个割（因为环要从 S 出去还要回来）。由 e 的最小性，w(e) ≤ w(f)。用 e 换掉 f 得到 T'，它仍是生成树且 w(T') ≤ w(T) ⟹ T' 也是 MST 且含 e。∎

两个算法都在做同一件事——找横跨某个割的最小边：
  • Prim：割是「已选节点集 vs 其余」，每次选横跨它的最小边。
  • Kruskal：按权排序扫边，当前边如果连接两个不同连通块，那它就是横跨「这两个块之间的某个割」的最小边（因为更小的边都已被处理过）。

7.2 Kruskal

// 按边权排序 + 并查集判环，O(E log E)
long long kruskal(int n, std::vector<Edge> edges) {
    std::sort(edges.begin(), edges.end(),
              [](const Edge& a, const Edge& b) { return a.w < b.w; });
    DSU dsu(n);
    long long total = 0;
    int used = 0;
    for (auto& [u, v, w] : edges) {
        if (dsu.unite(u, v)) {        // 返回 true 说明本次真的合并了（无环）
            total += w;
            if (++used == n - 1) break;   // 已选够 n−1 条边
        }
    }
    return used == n - 1 ? total : -1;   // 不连通则无 MST
}
dsu.unite() 返回「本次是否真的合并了」正是 Kruskal 需要的判断（见 并查集 §2.3）——返回 false 说明两端已连通，加这条边会成环。
别忘了检查连通性：如果最终选到的边少于 n−1 条，说明图不连通，不存在生成树（此时要返回「最小生成森林」还是报错，取决于题目）。

7.3 Prim

// 堆优化 Prim，O(E log V)。形式上和 Dijkstra 几乎一样
long long prim(int n) {
    std::vector<bool> in_mst(n, false);
    std::priority_queue<std::pair<long long, int>,
                        std::vector<std::pair<long long, int>>,
                        std::greater<>> pq;
    long long total = 0;
    int cnt = 0;
    pq.push({0, 0});
    while (!pq.empty()) {
        auto [w, u] = pq.top(); pq.pop();
        if (in_mst[u]) continue;        // 延迟删除
        in_mst[u] = true; total += w; ++cnt;
        for (auto [v, w2] : g[u])
            if (!in_mst[v]) pq.push({w2, v});   // ← 注意：压的是边权，不是累计距离
    }
    return cnt == n ? total : -1;
}
Prim 和 Dijkstra 代码极像，但有一处关键区别： 
Dijkstra：pq.push({dist[u] + w, v});   // 累计距离
Prim　　：pq.push({w, v});               // 单条边的权重
因为 Dijkstra 求「从源点到 v 的路径总长」，而 Prim 求「把 v 接入已选集合的那一条边的代价」。写混了会得到完全错误的结果，而且两者代码相似度极高，很容易在改写时出错。
面试里能主动指出这一处差别，比背两份模板有说服力。

网络流入门

建模比算法难

8.1 最大流最小割

最大流最小割定理：网络的最大流量等于最小割容量（把源和汇分开所需删除的最小边容量之和）。

直觉：流量必须全部通过每一个割，所以最大流 ≤ 任意割的容量；而定理说这个上界是可达的。

工程含义：「最多能传多少」和「最脆弱的瓶颈在哪」是同一个问题的两面。求出最大流后，残量网络中从源点可达的点集就给出了最小割——这让「找瓶颈」变成一次可执行的计算。
算法复杂度特点
Ford-Fulkerson（任意增广路）不保证终止（无理数容量）只有理论意义
Edmonds-Karp（BFS 找最短增广路）O(V·E²)易实现，小数据够用
Dinic（分层 + 多路增广）O(V²·E)；单位容量图 O(E√E)实践首选，实测远好于理论界
ISAPO(V²·E)常数略优于 Dinic
HLPP（最高标号预流推进）O(V²√E)理论最好，代码长
最小费用最大流（SPFA/Dijkstra 增广）依赖实现带权匹配、调度问题

8.2 Dinic

Dinic 的两个核心优化（相比 Edmonds-Karp）：
  1. 分层（level graph）：先 BFS 给每个点标一个「到源点的层数」，只允许沿「层数 +1」的边增广。这保证每次增广的都是最短路，且同一层次图上可以增广多次。
  2. 当前弧优化（current arc）：DFS 时记住每个点「已经试到第几条出边」，下次从那里继续——避免反复尝试已经饱和的边。这个优化不是可选的，去掉后复杂度会退化。
加上这两条，Dinic 在实践中的表现远好于理论界 O(V²E)；单位容量图（如二分图匹配）上是 O(E√E)，这也是它能替代匈牙利算法的原因。
网络流实现的三个高频坑：
  • 反向边必须成对存储。用 e ^ 1 取配对边（边从 0 开始成对加入），这样残量更新 cap[e] -= f; cap[e^1] += f; 才对。无向边的处理不同——两个方向都给满容量，而不是一个 0。
  • 层数数组每轮 BFS 都要重置，且 BFS 无法到达汇点时算法结束。
  • 当前弧不能在 DFS 内部重置——它必须在整个「同一层次图的多路增广」过程中持续有效。这是最容易写错也最容易导致 TLE 的地方。

  1. 基础写出堆优化的 Dijkstra，并说明「延迟删除」那一行的作用。 
    std::vector<long long> dijkstra(int s, int n) {
    const long long INF = LLONG_MAX / 4;   // ← 不用 LLONG_MAX，防溢出
    std::vector<long long> dist(n, INF);
    std::priority_queue<std::pair<long long,int>,
        std::vector<std::pair<long long,int>>, std::greater<>> pq;
    dist[s] = 0; pq.push({0, s});
    while (!pq.empty()) {
        auto [d, u] = pq.top(); pq.pop();
        if (d > dist[u]) continue;              // ← 延迟删除
        for (auto [v, w] : g[u])
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.push({dist[v], v});
            }
    }
    return dist;
}
    延迟删除是什么
    堆不支持修改已有元素的优先级（decrease-key）。所以不改旧条目，直接压入新的 (更小距离, v)——同一节点可能在堆里有多个条目。
    if (d > dist[u]) continue; 跳过那些已经被更好路径更新过的过期条目。
    省掉这一行会怎样
    不影响正确性（后续松弛都不会成功），但会白做大量无用的邻居遍历——稠密图上明显变慢。
    INF 的选择
    不能用 LLONG_MAX——dist[u] + w 会有符号溢出（UB）。用 LLONG_MAX / 4，或在松弛前先判 dist[u] == INF。
    为什么延迟删除是实践首选
    对比索引堆（真 decrease-key）：延迟删除不需要维护「节点→堆内位置」映射，代码短一半、常数更小（索引堆每次元素移动都要额外写映射表）。
    堆可能膨胀到 O(E)，但稀疏图上 E = O(V)，无所谓。只在稠密图 + 内存紧张时才值得上索引堆。
  2. 基础Dijkstra 为什么不能处理负权边？给一个反例。

    因为它的不变式「每次从堆取出的节点，其 dist 已是最终值」依赖非负权。

    最小反例
    S →(1) A
S →(4) B
B →(−4) A
    Dijkstra：取出 S → dist[A]=1, dist[B]=4；取出 A（dist=1 最小）→ 认定已确定；取出 B，松弛 B→A 得 4−4=0 < 1——但 A 已经出队，不会再被处理。
    真实 dist[A] = 0，Dijkstra 给出 1。注意这个图没有负环。
    证明的哪一步用到了非负性
    反证时需要「x 到 u 的那段路径长度 ≥ 0」，从而推出 真实距离(x) ≤ 真实距离(u)。负权让这一步不成立，整个论证链断掉。
    能指出这一点比只说「不能处理负权」深一层。
    三个常见的错误补救
    ①「所有边权加一个大常数」——错。这会额外惩罚边数多的路径：3 条边共 5 变成 5+3C，2 条边共 6 变成 6+2C，C 大时后者反而更短。只有「所有路径边数相同」才成立。
    ②「无负环就能用」——错，上面反例就没负环。
    ③「加 visited 不重复访问」——错，问题不在重复访问而在过早确定。
    正确做法
    单源 → Bellman-Ford / SPFA（O(V·E)）。
    需要全源且负权固定 → Johnson 算法：先用一次 Bellman-Ford 算出一组「势能」把边权重新赋成非负，再对每个源跑 Dijkstra。
  3. 基础Bellman-Ford 为什么松弛 n−1 轮？怎么检测负环？

    因为无负环时任意最短路最多 n−1 条边（否则会重复访问节点形成环；非负环可去掉，负环则无最短路）。

    归纳证明
    第 k 轮结束后，所有「最多 k 条边的最短路」都已正确算出。
    · k=1：从 s 直接出发的边，第一轮必被松弛。
    · k→k+1：最短路 s→…→u→v 有 k+1 条边 ⟹ s→…→u 有 k 条边，归纳假设 dist[u] 已正确 ⟹ 第 k+1 轮松弛 (u,v) 得到正确的 dist[v]。∎
    负环检测：跑第 n 轮
    n−1 轮后再跑一轮，如果还能松弛成功 → 存在负环（因为无负环时 n−1 轮已收敛）。
    for (auto& [u,v,w] : edges)
    if (dist[u] != INF && dist[u] + w < dist[v])
        return {};   // 有负环
    「有负环」和「有负权」是两件事
    负权但无负环 → 最短路存在，正常求。
    有负环且从 s 可达 → 最短路无定义（绕环可趋于 −∞），必须报错而不是返回值。
    有负环但 s 不可达 → 不影响，正常返回。
    题目可能有负环时，必须先问清「有负环时输出什么」。
    两个实用细节
    ① 加 if (!changed) break;——真实图通常几轮就收敛，很少跑满 n−1 轮。
    ② 要检测任意负环（不只是 s 可达的），把所有 dist 初始化为 0（等价于加超级源连所有点）。
  4. 基础Floyd 的三层循环为什么 k 必须在最外层？

    因为 k 是 DP 的「阶段」维度，而 i、j 是状态维度。

    状态定义 d[k][i][j] = 从 i 到 j、只允许经过编号 < k 的中间点的最短距离 转移 d[k+1][i][j] = min( d[k][i][j], // 不经过 k d[k][i][k] + d[k][k][j] ) // 经过 k

    k 这一维可以滚动省掉（因为 d[k][i][k] == d[k+1][i][k]，原地更新安全），于是变成熟悉的三层循环：

    for (int k = 0; k < n; ++k)        // ← 阶段，必须最外层
    for (int i = 0; i < n; ++i)
        for (int j = 0; j < n; ++j)
            d[i][j] = min(d[i][j], d[i][k] + d[k][j]);
    k 放内层会怎样
    for(i) for(j) for(k)   // ❌
    这变成「对每个 (i,j) 试所有中转点」，只考虑了一次中转。需要两次以上中转的路径就算错。
    而且它在小图上可能碰巧对——这让 bug 特别难查。
    记法
    「DP 的阶段必须在最外层」。这条规律对所有类似 DP 都成立：背包的物品维、区间 DP 的长度维、状压 DP 的状态维。
    Floyd 骨架的推广
    它适用于任何「(⊕, ⊗) 半环」上的路径问题——只需换掉 min 和 +：
    · (min, +) → 最短路
    · (max, min) → 最大瓶颈路（路径上最小边权最大）
    · (or, and) → 可达性（传递闭包，可用 bitset 优化到 O(V³/64)）
    · (+, ×) → 路径计数 / 概率
    一份代码解四类问题。
    什么时候该用 Floyd
    它的 O(V³) 常数极小（三层纯循环、cache 友好、易并行），而且代码只五行。
    V ≤ 400~500 时 Floyd 往往比「跑 V 次 Dijkstra」更快——后者在稠密图上是 O(V³ log V)。

10.2 中级（区分熟练度）

  1. 中级Kruskal 和 Prim 的共同正确性基础是什么？两者怎么选？

    共同基础是割性质（cut property）：把节点集分成任意两个非空部分 S 和 V∖S，则横跨这个割的最小边一定属于某棵 MST。

    证明（交换论证）
    设 e 是横跨割的最小边，假设某棵 MST T 不含 e。把 e 加入 T 形成一个环，这个环必然至少还有另一条边 f 也横跨这个割（要出去还要回来）。由 e 的最小性 w(e) ≤ w(f)，用 e 换 f 得到 T'，仍是生成树且 w(T') ≤ w(T) ⟹ T' 也是 MST 且含 e。∎
    两个算法都在找「横跨某个割的最小边」
    Prim：割是「已选节点集 vs 其余」，每次选横跨它的最小边。
    Kruskal：按权排序扫边，当前边若连接两个不同连通块，它就是横跨「这两块之间某个割」的最小边（更小的边都已处理过）。
    KruskalPrim（堆）Prim（朴素）
    复杂度O(E log E)O(E log V)O(V²)
    适合稀疏图稀疏图稠密图
    不连通图自然得到最小生成森林要对每个分量各跑同
    边已排序O(E·α)，极快无优势无优势
    Prim 和 Dijkstra 的关键区别
    代码极像，但压入堆的东西不同：
    Dijkstra：pq.push({dist[u] + w, v});   // 累计距离
Prim　　：pq.push({w, v});               // 单条边权
    因为 Dijkstra 求「源到 v 的路径总长」，Prim 求「把 v 接入已选集合的那条边的代价」。写混了结果完全错，而两份代码相似度极高。
    别忘检查连通性
    选中边数 < n−1 说明图不连通，不存在生成树。
  2. 中级A* 的启发函数需要满足什么条件？「可采纳」和「一致」有什么区别？
    Dijkstra：按 g(n) 排序 g = 起点到 n 的已知距离 A* ：按 f(n) = g(n) + h(n) h = n 到终点的估计距离 h ≡ 0 → 退化成 Dijkstra；h 越准 → 搜索范围越小
    可采纳（admissible）
    h(n) ≤ 真实距离(n → 目标)，即永不高估。
    ⟹ 保证找到最优解。
    一致 / 单调（consistent）
    对任意边 (u,v,w)：h(u) ≤ w + h(v)（类似三角不等式）。
    ⟹ 保证每个节点只需扩展一次（不需重新打开已关闭的节点）。
    一致 ⟹ 可采纳（反之不成立）。
    实践含义
    只有「可采纳」时 A* 仍找到最优解，但可能需要重新打开已关闭节点（reopening），实现更复杂。
    「一致」时就能像 Dijkstra 那样「出队即确定」。常见的几何启发（曼哈顿、欧氏、对角距离）在对应移动规则下都是一致的，所以实践中很少需要考虑 reopening。
    weighted A*：主动放弃最优性
    把 h 乘上 ε > 1，搜索快得多，但只保证「解 ≤ ε × 最优解」。
    游戏寻路和地图导航常这么做（用户感知不到 5% 的路径差，但 200ms → 20ms 很明显）。但必须明确知道自己放弃了最优性——不能一边用 weighted A* 一边宣称最优。
    双向 A*/Dijkstra 的终止条件坑
    不是「两边相遇就得到最优解」。正确条件是「两边已扩展节点的最小 dist 之和 ≥ 当前找到的最优路径长度」。
    相遇点不一定在最优路径上——可能有一条经过别处的更短路还没被发现。标准做法是相遇后继续搜索并维护当前最优，直到条件满足。
    无权图的双向 BFS 没这个问题（层数单调），所以从 BFS 迁移到 Dijkstra 时容易踩。
  3. 中级什么情况下不需要 Dijkstra 就能求最短路？

    四种情况，按「被忽略的频率」排序：

    ① 图是 DAG（最容易被忽略）
    按拓扑序松弛一遍即可，O(V+E)，而且天然支持负权（没有环，「绕环变小」不可能发生）。
    很多问题的图其实是 DAG：任务依赖、状态转移、时间推进、分层图。此时用 Dijkstra 是多余的，用 Bellman-Ford 更是浪费。
    ② 边权全相同（无权图）
    BFS，O(V+E)。BFS 按层扩展，节点第一次被访问时走的必然是最短路。
    ③ 边权只有 0 和 1
    0-1 BFS：双端队列，权 0 压队首、权 1 压队尾，O(V+E)。
    双端队列在任意时刻最多含两个距离值（d 和 d+1）且队首最小——正好复现 Dijkstra 的性质而不需要堆。
    识别信号：「某些移动免费、某些花费 1」。
    ④ 边权是小范围整数
    桶队列 / dial's algorithm：每个距离一个桶，O(V + E + maxW·V)。
    共同思路
    这四种都是用「结构」代替「堆」来提供有序性——只要距离值的取值范围足够小或足够规整，就不需要通用的优先队列。
    而 DAG 那一条更本质：它用「问题本身的偏序」代替了「按距离排序」。拿到最短路问题的第一个动作应该是问「这图是 DAG 吗」。
  4. 中级最大流最小割定理说了什么？它有什么工程价值？

    网络的最大流量 = 最小割容量（把源和汇分开所需删除的最小边容量之和）。

    直觉
    流量必须全部通过每一个割 ⟹ 最大流 ≤ 任意割的容量。定理说这个上界是可达的。
    工程价值：「能传多少」和「瓶颈在哪」是同一个问题
    求出最大流后，残量网络中从源点可达的点集就给出了最小割——这让「找瓶颈」从直觉判断变成一次可执行的计算。
    应用：网络容量规划（哪条链路要扩容）、供应链瓶颈分析、图像分割（graph cut）。
    它统一了一批看似无关的问题
    König 定理（二分图最小点覆盖 = 最大匹配）是它在二分图上的特例。
    最大独立集 = V − 最大匹配（二分图）。
    最小路径覆盖（DAG）= V − 最大匹配。
    看到「最少选多少个覆盖」「最多选多少个互不冲突的」就该想到这一族。
    算法选择
    实践首选 Dinic（分层 + 多路增广 + 当前弧优化），实测远好于理论界 O(V²E)；单位容量图上是 O(E√E)，这是它能替代匈牙利算法做二分图匹配的原因。
    当前弧优化不是可选的——去掉后复杂度会退化，而且它不能在 DFS 内部重置。
    难点在建模不在算法
    算法几十行可以背，难的是「怎么把题目翻译成管道图」。三个套路：
    超级源汇：多源多汇 → 单源单汇。
    拆点：v_in → v_out，中间边容量 = 点容量（用于「每个中转站最多过 k 个」）。
    最小割 = 二选一代价：把「选 A 还是 B」建成割（最大权闭合子图、项目选择）。

10.3 高级（体现深度）

  1. 高级要给一个全国路网做导航，直接跑 Dijkstra 行吗？工业界怎么做？

    不行。全国路网约 10⁷ 量级的节点，一次 Dijkstra 要扫遍大半张图——单次查询几百毫秒到秒级，而导航服务的 QPS 可能上万。

    ① 先算清瓶颈
    Dijkstra 的问题不是复杂度不对（O(E log V) 已经很好），而是常数太大且无法复用：每次查询都从零开始扫。
    关键观察：路网是静态的（几周才更新一次），而查询是海量的 ⟹ 应该用预处理换查询速度。
    ② 主流方案：Contraction Hierarchies（CH）
    按「重要性」逐个收缩节点：删掉一个节点时，如果它的邻居之间的最短路必须经过它，就加一条捷径边（shortcut）补上。
    查询时做双向 Dijkstra，且只往「重要性更高」的方向走——搜索范围极小。
    效果：全国路网单次查询能到微秒级，预处理几分钟到几十分钟。这是 OSRM 等开源导航引擎的核心。
    ③ 其他方案
    ALT（A* + Landmarks + 三角不等式）：预选若干地标，预计算所有点到地标的距离，用三角不等式得到比直线距离强得多的 h。实现简单，加速 10–100 倍。
    Hub Labeling：每点预存一组「枢纽 + 距离」，查询时求交集——查询最快（几乎 O(1)），但存储开销大（每点几十到几百个标签）。
    分层图（高速/国道/市内分层）：工业界早期做法，直观但加速比不如 CH。
    ④ 但真实导航还有 CH 处理不了的东西
    实时路况：边权动态变化 → CH 的捷径边失效。解法是「Customizable CH」（把预处理分成「拓扑相关」和「权重相关」两阶段，后者可以几秒内重算）。
    转向限制（不能左转、单行道）→ 要在边而不是点上建图，或用「拆点」表达。
    多目标（最快 vs 最短 vs 最少收费）→ 每个目标一套预处理，或用多目标 Pareto 最短路。
    路线偏好、避开拥堵、途经点→ 都会破坏纯粹的最短路模型。
    ⑤ 可迁移的判断
    「图是静态的 + 查询是海量的」→ 预处理换查询速度。这个判断适用于所有类似场景：搜索引擎的倒排索引、数据库的索引、编译期计算。
    反过来，如果图会频繁变化，重预处理的成本可能超过收益——此时要么增量更新预处理结果，要么退回在线算法。动手前先量「更新频率 vs 查询频率」。
  2. 高级「有负权但要多次查询全源最短路」怎么做？

    朴素做法有两条，各有问题：跑 V 次 Bellman-Ford 是 O(V²E)；用 Floyd 是 O(V³)——V 大时都不行。

    Johnson 算法：重赋权 + V 次 Dijkstra
    核心思想是把负权图变成等价的非负权图，从而能用 Dijkstra。
    步骤：
    ① 加一个虚拟源点 q，向所有点连权 0 的边；
    ② 用 Bellman-Ford 从 q 求出 h[v]（顺带检测负环——有负环则无解）；
    ③ 重赋权：w'(u,v) = w(u,v) + h[u] − h[v]；
    ④ 对每个源跑 Dijkstra（在 w' 上）；
    ⑤ 还原：真实距离(u,v) = dist'(u,v) − h[u] + h[v]。
    为什么 w' 非负
    Bellman-Ford 的结果满足三角不等式 h[v] ≤ h[u] + w(u,v)（否则还能继续松弛），移项即得 w(u,v) + h[u] − h[v] ≥ 0。∎
    为什么最短路的「相对顺序」不变
    对任意路径 p: v₀ → v₁ → … → v_k：
    w'(p) = Σ [w(vᵢ,vᵢ₊₁) + h[vᵢ] − h[vᵢ₊₁]] = w(p) + h[v₀] − h[v_k] ← 中间项全部抵消
    同一对 (起点, 终点) 的所有路径，w' 长度都比 w 长度多出同一个常数 h[v₀] − h[v_k] ⟹ 最短路不变。这就是「势能法重赋权」的精髓。
    复杂度
    O(V·E log V)（一次 Bellman-Ford + V 次 Dijkstra），稀疏图上远优于 Floyd 的 O(V³)。
    稠密图（E ≈ V²）上则和 Floyd 相当甚至更差，此时直接用 Floyd（代码五行、常数小）。
    「势能重赋权」是个通用技巧
    同样的思路用在最小费用最大流里：每轮增广后费用可能变负，用势能重赋权后就能用 Dijkstra 代替 SPFA 找增广路（Primal-Dual 方法），复杂度更好。
    核心是「加一个只依赖节点的项，让所有路径同步偏移，从而不改变相对优劣」——这个想法也出现在 A* 的启发函数（一致性条件本质就是重赋权后非负）里。
  3. 高级一个「最少加多少条网线让所有机房连通，且成本最低」的需求，怎么建模？

    看起来是 MST，但读题要确认四件事——它们决定了这到底是不是 MST 问题。

    ① 已有部分连接吗？
    如果某些机房之间已经连通，把这些边先并入并查集（代价 0），然后对剩余候选边跑 Kruskal。这是「必选边」的标准处理。
    ② 要连通「所有」还是「指定的一部分」？
    所有点 → MST。只需连通指定的 k 个点、可以借道其他点 → 那是 Steiner 树，NP-hard（k 小时用状压 DP）。
    这一字之差决定了问题的复杂度类，必须问清。
    ③ 图是无向的吗？
    无向 → Kruskal/Prim。有向（比如「单向光纤」）→ 那是最小树形图，要用朱刘算法（Edmonds），Kruskal/Prim 完全不适用。
    ④ 目标是「总成本最小」还是「最贵的那条最便宜」？
    总成本最小 → MST。「最贵的那条最便宜」→ 最小瓶颈生成树——好消息是 MST 恰好也是最小瓶颈生成树（MST 上任意两点路径的最大边权最小），所以同一个算法。
    建模确认后：Kruskal + 并查集
    // 已有连接先并入
for (auto& [u,v] : existing) dsu.unite(u, v);
// 候选边按成本排序后扫
for (auto& [u,v,w] : sorted_candidates)
    if (dsu.unite(u, v)) { total += w; ++used; }
// 检查连通性：used + existing_merges == n-1
    为什么选 Kruskal 而非 Prim：能自然处理「已有边」和「图可能不连通」，而且候选边通常是稀疏的（不是所有机房两两之间都能拉线）。
    工程上还要考虑的（MST 模型覆盖不到的）
    可靠性：MST 是树 → 任何一条边断了就分区。真实网络要求冗余，实际是「求一个 2-边连通的最小子图」（更难的问题），或者在 MST 基础上加环。
    容量：网线有带宽上限 → 变成网络流或多商品流问题。
    施工约束：某些路径不能施工、成本随时间变化。
    面试时指出「MST 得到的是树，没有任何冗余」这一点，比只写出 Kruskal 更有价值。
  4. 高级为什么说网络流「建模比算法难」？举一个建模的例子。

    因为算法（Dinic）是固定的几十行，可以背；而建模是把一道自然语言描述的问题翻译成管道图，变化无穷且没有机械方法。

    三个基本套路
    超级源汇：多源多汇 → 加虚拟 S 连所有起点、虚拟 T 连所有终点。
    拆点：点有容量限制时，把 v 拆成 v_in → v_out，中间边容量 = 点容量。
    最小割 = 二选一：「选 A 还是选 B，各有代价」建成一个割，割掉哪边就是选哪边。
    建模例子：项目选择 / 最大权闭合子图
    题：有若干项目（有收益）和若干设备（有成本），每个项目需要若干设备，设备可共用。选一些项目使「总收益 − 总成本」最大。
    建模：
    · S → 每个项目，容量 = 该项目的收益
    · 每个设备 → T，容量 = 该设备的成本
    · 项目 → 它需要的设备，容量 = ∞
    答案 = 总收益 − 最小割。
    为什么对：容量 ∞ 的边不可能被割，所以任何有限割要么割掉「S→项目」（= 放弃该项目的收益），要么割掉「设备→T」（= 支付该设备的成本）。最小割就是「最小的放弃+支付」，于是总收益减去它就是最大净收益。
    这个例子体现的建模思路
    把「二选一的代价」编码成边容量，把「必须同时选」编码成 ∞ 边。然后「最优决策」就变成「最小割」。
    同族问题：图像分割（前景/背景二选一，相邻像素倾向同类 → ∞ 或大权边）、文理分科、最大密度子图。
    为什么这类题的难度分布极不均
    想到建模 → 剩下是套模板（10 分钟）；想不到 → 完全无从下手。没有中间状态。
    所以练法不是刷更多题，而是积累「建模模式库」：看到「点有容量」想拆点，看到「二选一有代价」想最小割，看到「一对一分配」想二分图匹配，看到「每人做几件事有上限」想容量限制。
    面试里网络流出现频率不高（建模难、代码长），但知道「最大流最小割定理」和「二分图匹配 = 最大流」很有价值——因为 König 定理这类结论会以「最少选多少个点覆盖所有边」的形式出现。
