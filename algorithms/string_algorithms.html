字符串匹配

字符串算法的共同主题是「不要浪费已经比较过的信息」。朴素匹配失配后从头再来，KMP 用 border 记住「已匹配的前缀里有多少能复用」，Z 函数记住「之前算出的匹配段」，滚动哈希把「重新比一遍」变成一次加减乘。理解这个主线，六个算法就从六个模板变成一个思想的六种实现。

核心难度 ★★★★☆ 面试出现率 中高 阅读时长 ~35 min 前置 哈希 · Trie · BFS
border 理论 Z 函数 双哈希 Manacher AC 自动机 ReDoS
01

本质：复用已比较的信息

六个算法，一条主线

算法复用什么信息复杂度解决什么
朴素匹配什么都不复用O(nm)基准
KMP模式串的 border（前缀=后缀的最长长度）O(n+m)单模式匹配 + 周期性问题
Z 函数之前算出的匹配段 [l, r]O(n)「每个位置能和开头匹配多长」
Rabin-Karp上一个窗口的哈希值O(n+m) 期望多次比较、二维匹配、去重指纹
Manacher已知回文的对称性O(n)所有回文子串
AC 自动机Trie + 失配指针（KMP 的多串版）O(n + Σm + 命中数)多模式同时匹配
后缀数组 / SAM所有后缀的有序关系 / 等价类O(n log n) / O(n)任意子串的复杂查询
朴素匹配像核对身份证号时每次错了就从第一位重新念。

KMP 说：等等——我已经知道前面对了 7 位，而这 7 位里「前 3 位和后 3 位一样」；所以我不用退到最开头，退到第 3 位继续就行。这个「前缀和后缀重合多少」就是 border，也是 KMP 的全部内容。

滚动哈希则是另一条路：不逐位比，而是给每个 7 位窗口算一个「指纹」。窗口右移一位时，指纹只需减掉最左那位的贡献、加上最右那位——一次加减乘，而不是重新算 7 位。

1.1 与其他章节的关系

  • 哈希表内核 —— 滚动哈希的碰撞概率、双哈希、以及「输入可信吗」这个判据
  • 树与平衡树 —— AC 自动机建在 Trie 上；后缀树是压缩 Trie
  • 图遍历与拓扑排序 —— AC 自动机的失配指针用 BFS 构造
  • 动态规划 —— 编辑距离、最长公共子串都是 DP；AC 自动机上还能做 DP
  • 递归与分治 —— 正则回溯的爆栈与 ReDoS
  • 搜索引擎基础 —— 倒排索引与全文检索的完整讨论
02

朴素匹配与它的浪费

先看清浪费在哪，才知道 KMP 省了什么

// 朴素匹配：O(n·m)
int naive(const std::string& s, const std::string& p) {
    int n = s.size(), m = p.size();
    for (int i = 0; i + m <= n; ++i) {
        int j = 0;
        while (j < m && s[i + j] == p[j]) ++j;
        if (j == m) return i;
        // 失配 → i 前进 1，j 归零 —— 刚才比对的 j 位信息全部丢弃
    }
    return -1;
}
重新比了一遍。KMP 的洞察： 这些信息本来就在手里
关键洞察：失配时我们已经知道 s[i..i+j-1] == p[0..j-1]。所以「文本串接下来长什么样」的信息，其实完全等价于「模式串的前 j 个字符长什么样」——而后者是可以预处理的，与文本串无关。

这就是 KMP 的设计：把「失配后该退到哪」这个问题，预先在模式串上算好。所以 KMP 分两个阶段——先 O(m) 预处理模式串，再 O(n) 扫文本串。
03

KMP 与 border 理论

理解 border，KMP 就不用背了

3.1 border 是什么

border（也叫「失配函数」「前缀函数」「next 数组」）：
字符串 t 的 border 是指既是 t 的真前缀、又是 t 的真后缀的字符串。next[i] 定义为 p[0..i] 的最长 border 的长度。

例：p = "ababa"
  • "a" 的最长 border = 0（next[0] = 0）
  • "ab" = 0
  • "aba" → "a" 既是前缀又是后缀 → 1
  • "abab" → "ab" → 2
  • "ababa" → "aba" → 3
所以 next = [0, 0, 1, 2, 3]。

3.2 next 数组的构造

// 构造 next 数组：本质是「用 p 匹配自己」
std::vector<int> build_next(const std::string& p) {
    int m = p.size();
    std::vector<int> nxt(m, 0);
    for (int i = 1, len = 0; i < m; ++i) {
        // len = 当前已匹配的 border 长度；失配则沿 next 链回退
        while (len > 0 && p[i] != p[len]) len = nxt[len - 1];
        if (p[i] == p[len]) ++len;
        nxt[i] = len;
    }
    return nxt;
}
为什么构造过程是 O(m)：用势能法——取势能 Φ = len。
  • 外层循环每轮 len 最多增加 1（那个 ++len）。
  • 内层 while 每执行一次让 len 严格减小（因为 nxt[len-1] < len）。
  • len ≥ 0，且总增量 ≤ m ⟹ 总减量也 ≤ m ⟹ 内层总执行次数 ≤ m。∎
这和双指针「两层循环仍是 O(n)」是完全同一套论证。

3.3 匹配过程

// 匹配：和构造几乎一样的代码
std::vector<int> kmp_search(const std::string& s, const std::string& p) {
    auto nxt = build_next(p);
    std::vector<int> hits;
    int m = p.size();
    for (int i = 0, j = 0; i < (int)s.size(); ++i) {
        while (j > 0 && s[i] != p[j]) j = nxt[j - 1];   // 失配回退
        if (s[i] == p[j]) ++j;
        if (j == m) {
            hits.push_back(i - m + 1);
            j = nxt[j - 1];                          // 找下一个（允许重叠）
        }
    }
    return hits;
}
三个实现细节：
  • i 全程只前进，从不回退——这是 O(n) 的关键，也是 KMP 相对朴素匹配的本质区别。
  • 找到一个匹配后 j = nxt[j-1]（而不是 j = 0），这样能找到重叠的匹配（如在 "aaaa" 里找 "aa" 应得 3 个）。如果题目要求不重叠，才写 j = 0。
  • 常见的另一种 next 定义（下标偏移 1、next[0] = -1）也很流行。两种都对，但不要混用——混用会导致下标错乱。

3.4 border 的其他用途

问题用 border 怎么解
最小周期n − next[n-1]。若 n % (n − next[n-1]) == 0 则该串由这个周期整数次重复而成
所有 border沿 next 链：next[n-1], next[next[n-1]-1], …（border 的传递性）
「重复的子字符串」判断 n % (n − next[n-1]) == 0 && next[n-1] > 0
最短「回文添加」对 s + '#' + reverse(s) 求 next，next[末尾] 就是最长回文前缀长度
两串的最长公共前后缀对 a + '#' + b 求 next，末尾值即答案（分隔符必须是两串都没有的字符）
字符串的最小表示 / 循环同构判定在 s + s 里找 t
「最小周期 = n − next[n-1]」这个结论值得单独理解，因为它是 KMP 用得最多的副产品。
直觉：如果 p[0..n-1] 有长度 k 的 border，说明「前 k 个 = 后 k 个」⟹ 把整个串右移 n−k 位后，重叠部分完全吻合 ⟹ n−k 是一个「周期」（允许最后一段不完整）。
而当 n 能被 n−k 整除时，最后一段刚好完整 ⟹ 整个串是这个周期的整数次重复。

拼接技巧（a + '#' + b）也很通用：把「两个串的关系」转化成「一个串的自身结构」，从而复用 next / Z 函数。分隔符必须是两串都不含的字符，否则会产生跨界的假匹配。
04

Z 函数（扩展 KMP）

比 KMP 更直观，很多题更好用

Z 函数：z[i] = s[i..] 与 s 本身的最长公共前缀长度。（约定 z[0] = n 或不定义。）

例：s = "aabxaab" → z = [7, 1, 0, 0, 3, 1, 0]
（z[4] = 3 因为 s[4..] = "aab" 与 s 的前 3 个字符 "aab" 相同。）
// Z 函数：O(n)。维护一个已知匹配段 [l, r]（称为 Z-box）
std::vector<int> z_function(const std::string& s) {
    int n = s.size();
    std::vector<int> z(n, 0);
    z[0] = n;
    for (int i = 1, l = 0, r = 0; i < n; ++i) {
        // 若 i 在已知匹配段内，可以先复用对称位置的结果
        if (i < r) z[i] = std::min(r - i, z[i - l]);
        // 然后暴力往后扩展
        while (i + z[i] < n && s[z[i]] == s[i + z[i]]) ++z[i];
        // 更新匹配段（只在能扩得更远时）
        if (i + z[i] > r) { l = i; r = i + z[i]; }
    }
    return z;
}
为什么是 O(n)：同样用势能法——取势能 Φ = r。
  • 内层 while 每成功执行一次，都会让最终的 i + z[i] 更大；而只有 i + z[i] > r 时才更新 r。
  • 关键观察：内层 while 的每次成功都会使 r 严格增大（因为初始 z[i] 已经保证了 i + z[i] ≥ min(r, ...)）。
  • r 单调不减且 ≤ n ⟹ 内层总执行次数 ≤ n。∎
三个字符串算法（KMP 构造、Z 函数、Manacher）用的都是同一套「维护一个已知区间 + 势能法证 O(n)」的框架。
Z 函数做字符串匹配：对 p + '#' + s 求 Z 函数，凡是 z[i] == m 的位置就是一个匹配（# 是两串都不含的分隔符）。

Z 函数 vs KMP，什么时候用哪个：
  • 纯匹配：两者等价，KMP 省一点空间（不用拼接）。
  • 「每个位置与开头匹配多长」类问题 → Z 函数更直接（这就是它的定义）。
  • 周期性 / border 相关 → KMP 的 next 更直接。
  • 代码好写程度：Z 函数的逻辑更直观（「复用对称位置 + 暴力扩展」），很多人觉得比 KMP 的 next 链回退更容易理解和记住。
05

Rabin-Karp 与滚动哈希

它的价值不在单模式匹配

5.1 滚动哈希

多项式哈希 H(s[0..m-1]) = s[0]·B^(m-1) + s[1]·B^(m-2) + … + s[m-1] (mod M) 滚动（窗口右移一位） H_new = (H_old − s[i]·B^(m-1)) · B + s[i+m] (mod M) ↑ 减掉最左位的贡献 ↑ 整体左移 ↑ 加上最右位 O(1) 完成，而不是重新算 m 位
// 前缀哈希：预处理后 O(1) 求任意子串哈希（比滚动更通用）
const unsigned long long B = 131;
std::vector<unsigned long long> h, pw;

void build(const std::string& s) {
    int n = s.size();
    h.assign(n + 1, 0); pw.assign(n + 1, 1);
    for (int i = 0; i < n; ++i) {
        h[i+1] = h[i] * B + (unsigned char)s[i];   // 自然溢出当 mod 2^64
        pw[i+1] = pw[i] * B;
    }
}
// 子串 s[l..r] 的哈希（0-based，闭区间）
unsigned long long sub(int l, int r) {
    return h[r+1] - h[l] * pw[r - l + 1];
}
前缀哈希比滚动哈希更常用，因为它能 O(1) 取任意子串的哈希（不限于固定长度的滑动窗口）。这让「比较任意两个子串是否相等」变成 O(1)，从而能配合二分解「最长公共子串」「最长重复子串」等问题。
注意 (unsigned char) 强转——char 有符号时非 ASCII 字节会变负数（见 双指针 §7.1 的同一个坑）。

5.2 碰撞与双哈希

用「自然溢出」（mod 2^64）有一个已知的攻击：可以构造出「Thue-Morse 串」使任意基数 B 下的自然溢出哈希碰撞。竞赛里这被用来卡掉单哈希选手。

三种防御，按强度排序：
  • 随机基数：B 在运行时从一个范围随机取（而非固定 131 / 13331）。挡住「离线构造反例」这一类攻击。
  • 大质数模数：用 mod = 1e9+7 或更大的质数，配合随机 B。需要 __int128 或注意乘法溢出。
  • 双哈希：用两组不同的 (B, M)，两者都相等才认为字符串相等。碰撞概率降到两者之积的量级。
碰撞概率的量级：单哈希 mod 1e9+7、比较 n 对字符串时，由生日悖论碰撞概率约 n²/(2M)——n = 10⁵ 时约 0.5%，不算低。双哈希后降到可忽略。
什么时候必须用「真正的比较」而不能只信哈希：
  • 输入不可信（用户上传的内容、外部 API）→ 攻击者可以构造碰撞。此时要么用带随机密钥的哈希（SipHash），要么哈希相等后再做一次真实比较。
  • 结果用于安全决策（去重、鉴权、内容寻址）→ 必须用密码学哈希（SHA-256、BLAKE3）或真实比较。
  • 竞赛 / 内部工具，输入可信 → 双哈希 + 随机基数够用。
这和 哈希表 §7 的 Hash-DoS 是同一个原理：「平均情形可被攻击」。

5.3 它真正的价值

场景为什么哈希比 KMP 更合适
比较任意两个子串是否相等前缀哈希 O(1)；KMP 做不到（它只回答「模式串在哪」）
二分 + 判定（最长公共子串、最长重复子串）需要「任意长度的子串比较」，哈希天然支持
二维匹配先对每行哈希，再对「行哈希序列」做一维匹配
多模式匹配（模式串等长）把所有模式串的哈希放进 unordered_set，扫一遍文本
去重指纹 / 相似检测MinHash、SimHash 都基于哈希（但那是相似度而非精确匹配）
树哈希（判子树同构）把子树结构编码成哈希值
所以「Rabin-Karp 做单模式匹配」其实是它最不重要的用法——那件事 KMP 做得更好（确定性、无碰撞风险、无需处理模数）。

哈希的真正价值是「把字符串比较变成 O(1) 的整数比较」，从而让字符串问题能用上所有处理整数的工具：set 去重、二分、DP 状态、图的节点标识。这个视角比记住 Rabin-Karp 的匹配流程有用得多。
06

Manacher：线性求回文

复用「已知回文的对称性」

// Manacher：O(n) 求以每个位置为中心的最长回文半径
// 技巧：先在字符间插入分隔符，把奇偶长度统一成奇数
std::vector<int> manacher(const std::string& raw) {
    std::string s = "^";                        // 首哨兵
    for (char c : raw) { s += '#'; s += c; }
    s += "#$";                                 // 尾哨兵（防越界）

    int n = s.size();
    std::vector<int> p(n, 0);                  // p[i] = 以 i 为中心的回文半径
    int c = 0, r = 0;                          // 当前最右回文的中心与右边界
    for (int i = 1; i < n - 1; ++i) {
        // 复用对称位置的结果（i 关于 c 的镜像是 2c − i）
        if (i < r) p[i] = std::min(r - i, p[2 * c - i]);
        // 暴力扩展（哨兵保证不越界）
        while (s[i + p[i] + 1] == s[i - p[i] - 1]) ++p[i];
        // 更新最右回文
        if (i + p[i] > r) { c = i; r = i + p[i]; }
    }
    return p;   // p[i] 就是原串中对应回文的长度
}
两个技巧值得单独学：
  1. 插入分隔符统一奇偶：原串 "abba" 变成 "^#a#b#b#a#$"。这样所有回文都变成奇数长度，只需处理一种情况。而且插入后 p[i] 的值恰好等于原串中回文的长度——这不是巧合，是分隔符数量刚好补齐的结果。
  2. 首尾哨兵（^ 和 $，且互不相同）：让 while 的扩展自动在边界停下，不需要任何越界判断。这和柱状图最大矩形的哨兵技巧是同一个思路。
Manacher 复用信息的方式像照镜子。你已经知道「以 c 为中心、右边界到 r」这一段是回文。现在要算位置 i（在 c 右边）的回文半径——
因为大回文内部是对称的，i 在镜子里的对应位置是 2c − i，而那个位置的回文半径已经算过了。所以可以直接把它拿来当起点，只需从那里继续往外扩。

唯一的限制是「镜像的结论只在大回文内部有效」——所以要取 min(r − i, p[2c−i])，不能超出边界。这个「先复用、再扩展」的结构和 Z 函数一模一样。
如果只需要「最长回文子串」而不是所有回文，还有两个更简单的选择：
  • 中心扩展法：O(n²) 但代码五行，n ≤ 1000 时完全够用，而且不容易写错。
  • 二分 + 哈希：O(n log n)，思路直接（二分长度，用前缀哈希判「是否存在该长度的回文」）。
Manacher 的 O(n) 只在 n 很大（10⁶ 量级）或需要「所有位置的回文半径」时才必要。面试时能说出「有 O(n) 的 Manacher，但这题 O(n²) 够用」比硬写 Manacher 更稳。
07

AC 自动机：多模式匹配

Trie + KMP 的失配指针

问题：给定 k 个模式串和一个文本串，一次扫描找出所有模式串的所有出现位置。
朴素做法：对每个模式串跑一次 KMP → O(k·n)。
AC 自动机：O(n + Σmᵢ + 命中数)——文本只扫一遍。
struct ACAutomaton {
    static const int C = 26;
    std::vector<std::array<int, C>> ch{1};   // 节点 0 = 根
    std::vector<int> fail{0}, cnt{0};

    void insert(const std::string& w) {
        int u = 0;
        for (char c : w) {
            int k = c - 'a';
            if (!ch[u][k]) {
                ch[u][k] = ch.size();
                ch.push_back({}); fail.push_back(0); cnt.push_back(0);
            }
            u = ch[u][k];
        }
        ++cnt[u];
    }

    // 用 BFS 构造 fail 指针，并把 Trie「补全」成自动机
    void build() {
        std::queue<int> q;
        for (int k = 0; k < C; ++k)
            if (ch[0][k]) q.push(ch[0][k]);
        while (!q.empty()) {
            int u = q.front(); q.pop();
            for (int k = 0; k < C; ++k) {
                int& v = ch[u][k];
                if (v) {
                    fail[v] = ch[fail[u]][k];   // fail 指向「最长的、是自己后缀的前缀」
                    q.push(v);
                } else {
                    v = ch[fail[u]][k];         // ← 补全：空边直接指向 fail 的对应边
                }
            }
        }
    }

    // 查询：文本只扫一遍，i 全程只前进
    long long query(const std::string& s) {
        long long total = 0;
        int u = 0;
        for (char c : s) {
            u = ch[u][c - 'a'];               // 因为已补全，不需要 while 回退
            // 沿 fail 链累加所有以此结尾的模式串
            for (int t = u; t; t = fail[t]) total += cnt[t];
        }
        return total;
    }
};
两个关键设计：
  1. fail 指针 = KMP 的 next 的多串版：fail[v] 指向「是 v 所代表字符串的后缀 且 是某个模式串的前缀」的最长节点。作用完全等同于 KMP 失配后的回退。
  2. 「补全」Trie（v = ch[fail[u]][k]）：把不存在的边直接指向「沿 fail 走一步后的对应边」。这样查询时不需要 while 循环回退——每个字符恰好一次状态转移，代码更短且更快。这一步把「Trie + fail 指针」真正变成了一个「自动机」。
为什么用 BFS 构造：fail[v] 依赖 fail[u]（u 是 v 的父节点），所以必须按深度从小到大处理——这正是 BFS 的顺序。
查询的复杂度陷阱：for (int t = u; t; t = fail[t]) 这个内层循环在最坏情况下是 O(节点数)。如果模式串有大量嵌套后缀关系（如 a, aa, aaa, …），总复杂度会退化。
两种优化：
  • 只需统计总数时：把 cnt 沿 fail 树预先向上累加（sum[v] = cnt[v] + sum[fail[v]]，按 BFS 序），查询就只需 O(1)。
  • 需要知道每个模式串命中几次时：查询时只在节点上打标记，最后在 fail 树上做一次自底向上的累加（拓扑序或 DFS 后序）。
「fail 指针构成一棵树」是 AC 自动机的重要性质——很多进阶应用（fail 树上的 DP、子树求和）都基于它。
应用说明
敏感词过滤最经典的用途；一遍扫出所有命中，可同时替换
入侵检测 / WAF 规则匹配成千上万条规则同时匹配
生物序列的多模式搜索DNA 片段库
AC 自动机上的 DP「构造长度 n 的串使不含任何模式串」→ 在自动机的状态上做 DP
输入法 / 分词的词库匹配常用双数组 Trie + AC 的变体

后缀结构简介

从「找一个模式」到「任意子串的任意查询」

8.1 后缀数组

后缀数组（SA）：把字符串的所有 n 个后缀按字典序排序，sa[i] = 排名第 i 的后缀的起始位置。
height 数组（LCP）：height[i] = 排名相邻的两个后缀 sa[i-1] 和 sa[i] 的最长公共前缀长度。

构造：倍增法 O(n log n)（好写、常用）、DC3 / SA-IS O(n)（复杂）。
height 数组用 Kasai 算法 O(n) 求出。
问题用 SA + height 怎么解
模式串是否出现在 SA 上二分，O(m log n)
最长重复子串max(height[i])
不同子串的个数n(n+1)/2 − Σ height[i]
两串的最长公共子串拼接 a + '#' + b，求 max(height[i]) 且 sa[i-1] 与 sa[i] 来自不同串
至少出现 k 次的最长子串height 上的滑动窗口最小值
任意两后缀的 LCPheight 上的区间最小值（稀疏表 O(1) 查询）
最后一行是 SA 最强大的性质：「任意两个后缀的 LCP = height 数组上的区间最小值」。配上稀疏表就能 O(1) 回答「任意两个位置往后能匹配多长」——这让一大批子串问题变成区间查询问题。
而「两串最长公共子串」那一行的「来自不同串」这个条件很容易漏——漏了会得到「同一个串内部的重复」，答案偏大。

8.2 后缀自动机与后缀树

结构本质构造优势
后缀数组所有后缀的有序排列O(n log n) 倍增代码最短、常数小、易理解
后缀树所有后缀构成的压缩 TrieO(n) Ukkonen理论优雅，但代码极长
后缀自动机（SAM）识别所有子串的最小 DFAO(n) 在线增量能处理「子串出现次数」等 SA 难做的问题
广义 SAM多串的 SAMO(Σn)多串子串问题
SAM 的核心概念是 endpos 等价类：把「出现位置集合相同」的子串归为一类，每个类对应 SAM 的一个状态。由此得到两个关键性质：
  • 状态数 ≤ 2n − 1，转移数 ≤ 3n − 4（线性！这是 SAM 能 O(n) 构造的原因）。
  • link 指针构成一棵树（parent tree / link tree），在这棵树上做 DP 能算「每个子串出现多少次」「不同子串个数」等。
实践建议：SAM 的构造代码约 40 行且非常精妙（涉及「克隆节点」的分类讨论），初学时建议先掌握后缀数组——它能解 80% 的题，且更容易调试。SAM 是「必须要它才能做」的时候再学。
面试里后缀结构几乎不会要求手写（代码太长、易错）。有价值的是知道：
  • 「有这类工具」以及它们能解什么——比如被问「怎么求最长重复子串」时，能说出「后缀数组 + height 数组，答案是 max(height)」，或者「二分 + 哈希，O(n log n)」。
  • 后者往往是更好的面试答案：二分 + 哈希思路直接、代码短、能当场写出来。而后缀数组适合作为「如果需要更多子串查询，可以预处理 SA」的补充说明。

工程场景

正则、grep、检索、diff

9.1 正则与 ReDoS

两种正则引擎，性质完全不同：
  • 回溯型（backtracking / NFA 模拟）：PCRE、Java、Python re、JavaScript、.NET。
    支持反向引用、前后查找等强大特性，但最坏是指数时间。
  • 自动机型（DFA / Thompson NFA）：RE2（Go、部分 C++ 项目）、Rust 的 regex。
    保证 O(n·m) 线性，但不支持反向引用（因为那超出了正则语言的表达能力）。
ReDoS（正则拒绝服务）：回溯型引擎在某些模式 + 输入组合下会指数爆炸。 
// 典型的「灾难性回溯」模式
/^(a+)+$/      配 "aaaaaaaaaaaaaaaaaaaaaaaaX"
/(a|aa)+$/     配 "aaaa…a!"
/^(\s*\w+)*$/  配一长串空格加非法字符
共同特征：嵌套的量词（(x+)+、(x*)*）+ 有多种方式匹配同一段输入 + 最后失配。引擎必须尝试所有拆分方式，数量是指数级的。

25 个字符的输入就能让 CPU 跑几秒——如果正则或输入来自用户，这就是一个 DoS 漏洞。2019 年 Cloudflare 的全球宕机就是一条 WAF 正则引发的 ReDoS。
防御做法代价
换 RE2 / Rust regex自动机型引擎，线性保证失去反向引用等特性
超时 + 熔断给正则匹配设时限需要能中断（很多引擎不支持）
限制输入长度纵深防御，应该同时做可能拒绝合法长输入
静态检查正则用工具（如 safe-regex、recheck）扫描危险模式有假阳性/假阴性
不让用户提供正则改成受限的查询语法功能受限，但最安全
避免嵌套量词code review 规则靠人，不可靠
ReDoS 和本站讲过的其他漏洞是同一个原理：
「某个资源维度没有上界，而它由攻击者控制」——
  • Hash-DoS：碰撞把 O(1) 拖成 O(n)。
  • 递归解析爆栈：深度嵌套的 JSON。
  • 快排复杂度攻击：构造锯齿输入。
  • zip bomb：解压比无上限。
共同的防御思路：对每个资源维度问「上界在哪，谁保证」。

9.2 grep / 全文检索 / diff

系统用什么算法
GNU grepBoyer-Moore（从模式串尾部开始比，失配可跳过多个字符 → 平均 亚线性）+ Commentz-Walter（多模式）
ripgrepRust regex（自动机型）+ SIMD 加速的字面量搜索（memchr）
全文检索（ES / Lucene）倒排索引——不做字符串匹配，而是预先把文档切词建索引
数据库 LIKE '%x%'通常无法用索引（前缀通配符），退化成全表扫；解法是全文索引或 trigram 索引
git diffMyers 差分算法（本质是「编辑距离的 DP」在编辑图上的 BFS 优化）
拼写纠错编辑距离 DP + Trie 剪枝，或 BK-tree、SymSpell
近似去重MinHash / SimHash（相似度而非精确匹配）
三个值得记住的工程洞察：
  1. Boyer-Moore 的「亚线性」是 grep 快的关键：它从模式串尾部开始比较，失配时能一次跳过多个字符（跳的距离由「坏字符」和「好后缀」规则决定）。模式串越长、字符集越大，跳得越远——这和 KMP 的「一次前进一格」是不同的哲学。
  2. 全文检索根本不做字符串匹配：它把「在文档里找词」变成「在倒排索引里查词，得到文档列表」。预处理换查询速度——这和 Contraction Hierarchies 是同一个思路。
  3. LIKE '%x%' 用不了 B+ 树索引，因为 B+ 树只支持前缀比较。要支持中间匹配得用全文索引（倒排）或 trigram 索引（把字符串切成三字组建索引）。这是数据库慢查询的常见根因。

10.1 基础（必答）

点击每道题展开参考答案（先自测，再对照）。

  1. 基础KMP 的 next 数组是什么含义？手写它的构造。

    next[i] = p[0..i] 的最长 border 的长度。而 border 是「既是真前缀、又是真后缀」的字符串。

    例：p = "ababa" → next = [0, 0, 1, 2, 3]（"ababa" 的最长 border 是 "aba"，长度 3）。

    std::vector<int> build_next(const std::string& p) {
    int m = p.size();
    std::vector<int> nxt(m, 0);
    for (int i = 1, len = 0; i < m; ++i) {
        while (len > 0 && p[i] != p[len]) len = nxt[len - 1];
        if (p[i] == p[len]) ++len;
        nxt[i] = len;
    }
    return nxt;
}
    next 有什么用（这才是重点）
    失配时我们已经知道 s[i-j..i-1] == p[0..j-1]。而 p[0..j-1] 的后缀 = 它的前缀（长度 next[j-1]）⟹ s 的最近这几位已经匹配上了 p 的开头几位 ⟹ 可以直接从 j = next[j-1] 继续，不必退到 0。
    构造为什么是 O(m)
    势能法：取 Φ = len。外层每轮 len 最多 +1（总增量 ≤ m）；内层 while 每次让 len 严格减小；len ≥ 0 ⟹ 总减量 ≤ 总增量 ≤ m ⟹ 内层总次数 ≤ m。∎
    和双指针「两层循环仍是 O(n)」是同一套论证。
    两种 next 定义不要混用
    还有一种流行定义是下标偏移 1、next[0] = -1。两种都对，但混用会导致下标错乱。选一种记牢。
  2. 基础KMP 的匹配过程为什么是 O(n)？

    因为i（文本串指针）全程只前进，从不回退——这是它相对朴素匹配的本质区别。

    for (int i = 0, j = 0; i < n; ++i) {     // i 只增
    while (j > 0 && s[i] != p[j]) j = nxt[j-1];   // j 回退
    if (s[i] == p[j]) ++j;
    if (j == m) { record(i - m + 1); j = nxt[j-1]; }
}
    势能论证
    取 Φ = j。外层每轮 j 最多 +1 ⟹ 总增量 ≤ n。内层 while 每次让 j 严格减小，且 j ≥ 0 ⟹ 内层总执行次数 ≤ n。
    总代价 = n（外层）+ n（内层总量）= O(n)。∎
    对比朴素匹配的浪费
    朴素匹配失配后 i 前进 1、j 归零——刚才比对的 j 位信息全部丢弃。
    s = "AAAAAB", p = "AAAB"：i=0 时已知 s[1..3] = "AAA"，但 i=1 时又把这三个 A 重新比了一遍。而这些信息本来就在手里。
    两个实现细节
    ① 找到匹配后写 j = nxt[j-1]（不是 j = 0），才能找到重叠的匹配（在 "aaaa" 里找 "aa" 应得 3 个）。题目要求不重叠才写 j = 0。
    ② KMP 分两阶段：O(m) 预处理模式串 + O(n) 扫文本串。预处理只依赖模式串，所以同一个模式串匹配多个文本时可以复用 next 数组。
  3. 基础什么是滚动哈希？它有什么风险？
    多项式哈希 H(s[0..m-1]) = s[0]·B^(m-1) + … + s[m-1] (mod M) 滚动（窗口右移一位） H_new = (H_old − s[i]·B^(m-1)) · B + s[i+m] (mod M) ↑ 减掉最左位 ↑ 左移 ↑ 加最右位 O(1) 完成，而不是重算 m 位
    前缀哈希比滚动更常用
    预处理 h[] 和 pw[] 后，任意子串的哈希是 h[r+1] − h[l]·pw[r-l+1]，O(1)。
    这让「比较任意两个子串是否相等」变成 O(1)，从而能配合二分解「最长公共子串」「最长重复子串」。
    风险一：碰撞
    单哈希 mod 1e9+7、比较 n 对字符串时，由生日悖论碰撞概率约 n²/(2M)——n = 10⁵ 时约 0.5%，不算低。
    风险二：可被构造攻击
    用「自然溢出」（mod 2^64）时，可以构造 Thue-Morse 串使任意基数下都碰撞。竞赛里这被用来卡单哈希选手。
    三种防御
    ① 随机基数（运行时随机取 B，而非固定 131）——挡住离线构造反例；② 大质数模数 + 随机 B；③ 双哈希（两组不同的 (B, M)，都相等才认为相等）。
    什么时候不能只信哈希
    输入不可信（用户上传、外部 API）→ 用带随机密钥的哈希，或哈希相等后再做真实比较。
    用于安全决策（去重、鉴权、内容寻址）→ 必须用密码学哈希或真实比较。
    这和 Hash-DoS 是同一个原理：平均情形可被攻击。
    另外别忘 (unsigned char) 强转——char 有符号时非 ASCII 字节会变负数。
  4. 基础求「最长回文子串」有哪几种方法？分别什么复杂度？
    方法复杂度代码量适用
    中心扩展O(n²)五行n ≤ 1000，面试首选
    DP dp[i][j]O(n²) 时间 O(n²) 空间中等需要判断所有子串是否回文时
    二分 + 哈希O(n log n)中等思路直接，能当场写
    ManacherO(n)较长n 很大，或需所有位置的回文半径
    中心扩展的要点
    枚举中心（2n−1 个：n 个字符中心 + n−1 个间隙中心），向两边扩展。
    「间隙中心」是处理偶数长度回文的关键，漏掉它会错过 "abba" 这类。
    Manacher 的两个技巧
    ① 插入分隔符统一奇偶："abba" → "^#a#b#b#a#$"，所有回文变成奇数长度，只需处理一种情况。而且插入后 p[i] 恰好等于原串中回文的长度。
    ② 首尾哨兵（^ 和 $，互不相同）：让扩展自动在边界停下，不需要越界判断。和柱状图最大矩形的哨兵是同一思路。
    Manacher 复用什么信息
    已知「以 c 为中心、右边界到 r」是回文。要算 i（在 c 右边）时，因为大回文内部对称，i 的镜像位置 2c−i 的结果已经算过，可以直接拿来当起点。
    限制是镜像结论只在大回文内部有效 → 取 min(r−i, p[2c−i])。这个「先复用、再扩展」的结构和 Z 函数一模一样。
    面试策略
    先写中心扩展（五行、不易错），然后说「有 O(n) 的 Manacher，思路是复用已知回文的对称性」。这比硬写 Manacher 更稳——现场写 Manacher 很容易在哨兵和下标上出错。

10.2 中级（区分熟练度）

  1. 中级怎么用 KMP 的 next 数组求字符串的最小周期？
    最小周期 = n − next[n−1] 若 n % (n − next[n−1]) == 0 且 next[n−1] > 0 ⟹ 整个串由这个周期整数次重复而成
    直觉
    如果 p[0..n-1] 有长度 k 的 border，说明「前 k 个 = 后 k 个」
    ⟹ 把整个串右移 n−k 位后，重叠部分完全吻合
    ⟹ n−k 是一个「周期」（允许最后一段不完整）。
    而当 n 能被 n−k 整除时，最后一段刚好完整 ⟹ 整个串是这个周期的整数次重复。
    例子
    "abcabcabc"，n=9，next[8] = 6（border 是 "abcabc"）→ 最小周期 = 9−6 = 3，且 9 % 3 == 0 ⟹ 由 "abc" 重复 3 次。
    "abcabca"，n=7，next[6] = 4 → 周期 3，但 7 % 3 ≠ 0 ⟹ 不是整数次重复（最后一段不完整）。
    border 的传递性（同样重要）
    next[i] 对应的 border 的 border 也是 p[0..i] 的 border ⟹ 沿 next 链 i → next[i]−1 → … 能枚举出所有 border。
    这用于「求所有周期」「统计每个前缀出现次数」等问题。
    拼接技巧：把两串关系转成一串的自身结构
    对 a + '#' + b 求 next，末尾值 = a 的后缀与 b 的前缀的最长匹配。
    同理可解：最短回文添加（对 s + '#' + reverse(s) 求 next）、循环同构判定（在 s+s 里找 t）。
    分隔符必须是两串都不含的字符，否则会产生跨界的假匹配。
  2. 中级Z 函数是什么？它和 KMP 怎么选？

    z[i] = s[i..] 与 s 本身的最长公共前缀长度。
    例：s = "aabxaab" → z = [7, 1, 0, 0, 3, 1, 0]。

    for (int i = 1, l = 0, r = 0; i < n; ++i) {
    if (i < r) z[i] = std::min(r - i, z[i - l]);   // 复用对称位置
    while (i + z[i] < n && s[z[i]] == s[i + z[i]]) ++z[i];   // 暴力扩展
    if (i + z[i] > r) { l = i; r = i + z[i]; }        // 更新 Z-box
}
    它复用什么信息
    维护一个已知匹配段 [l, r]（Z-box）——这段等于 s 的一个前缀。若 i 落在这段内，它对应的信息在 z[i-l] 里已经算过，可以直接拿来当起点。
    O(n) 的证明：势能 Φ = r，内层 while 每次成功都让 r 严格增大，r ≤ n。∎
    用 Z 函数做匹配
    对 p + '#' + s 求 Z 函数，凡 z[i] == m 的位置就是一个匹配。
    情形选谁
    纯匹配等价；KMP 省一点空间（不用拼接）
    「每个位置与开头匹配多长」Z 函数（这就是它的定义）
    周期性 / border 相关KMP 的 next
    好写好记Z 函数（「复用对称位置 + 暴力扩展」比 next 链回退直观）
    三个算法共用一套框架
    KMP 构造、Z 函数、Manacher 都是「维护一个已知区间 + 在区间内复用 + 区间外暴力扩展 + 势能法证 O(n)」。
    认出这个框架，三个算法就变成了一个模式的三种实例。
  3. 中级AC 自动机怎么工作？fail 指针和 KMP 的 next 什么关系？

    AC 自动机 = Trie + fail 指针，解决「k 个模式串同时匹配一个文本串」，复杂度 O(n + Σmᵢ + 命中数)——文本只扫一遍（对比「对每个模式串跑一次 KMP」的 O(k·n)）。

    fail 指针 = KMP 的 next 的多串版
    fail[v] 指向「是 v 所代表字符串的后缀，且是某个模式串的前缀」的最长节点。
    作用完全等同于 KMP 失配后的回退——只不过 KMP 在一个串上回退，AC 自动机在整棵 Trie 上回退。
    用 BFS 构造 + 「补全」Trie
    if (v) { fail[v] = ch[fail[u]][k]; q.push(v); }
else   { v = ch[fail[u]][k]; }        // ← 补全：空边指向 fail 的对应边
    为什么用 BFS：fail[v] 依赖 fail[父节点]，所以必须按深度从小到大处理。
    「补全」的价值：查询时不需要 while 回退——每个字符恰好一次状态转移。这一步把「Trie + fail」真正变成了「自动机」。
    查询的复杂度陷阱
    for (int t = u; t; t = fail[t]) total += cnt[t]; 这个内层循环最坏是 O(节点数)。模式串有大量嵌套后缀（a, aa, aaa, …）时会退化。
    优化：只需总数时，把 cnt 沿 fail 树预先向上累加（sum[v] = cnt[v] + sum[fail[v]]，按 BFS 序），查询变 O(1)；需要每个模式串的次数时，查询只打标记，最后在 fail 树上做一次自底向上累加。
    「fail 指针构成一棵树」是重要性质
    很多进阶应用基于它：fail 树上的 DP、子树求和、AC 自动机上的 DP（「构造长度 n 的串使不含任何模式串」→ 在自动机状态上做 DP）。
    典型应用：敏感词过滤、WAF 规则匹配、生物序列多模式搜索、输入法词库。
  4. 中级怎么求「两个字符串的最长公共子串」？（注意是子串不是子序列）

    先区分清楚：子串（substring）必须连续；子序列（subsequence）可以不连续。这两个问题的解法完全不同。

    方法复杂度要点
    DP dp[i][j]O(nm)dp[i][j] = 以 a[i]、b[j] 结尾的公共子串长度；不等时置 0（不是取 max！）
    二分 + 哈希O((n+m) log)二分长度 L，把 a 的所有长 L 子串哈希放 set，查 b 的
    后缀数组O(n log n)拼接后求 max(height[i])，且 sa[i-1]、sa[i] 来自不同串
    后缀自动机O(n)对 a 建 SAM，用 b 在上面跑
    DP 版最常见的错
    字符不相等时必须置 0（dp[i][j] = 0），而不是像 LCS（最长公共子序列）那样取 max(dp[i-1][j], dp[i][j-1])。
    因为子串要求连续——一旦断开就得重新开始。这一行的差别就是「子串 vs 子序列」的全部区别。
    二分 + 哈希是面试的最佳答案
    思路直接（「存在长度 L 的公共子串」关于 L 单调 → 可以二分），代码短，能当场写出来。
    但要说明单调性：如果存在长度 L 的公共子串，那它的任意子串（长度 < L）也是公共子串 ⟹ 单调成立。
    后缀数组版的易漏条件
    拼接 a + '#' + b 后求 max(height[i])，必须同时要求 sa[i-1] 和 sa[i] 来自不同的原串。
    漏掉这个条件会得到「同一个串内部的重复」，答案偏大。

10.3 高级（体现深度）

  1. 高级什么是 ReDoS？线上有一条用户可配置的正则，怎么防？

    ReDoS（正则拒绝服务）：回溯型正则引擎在某些模式 + 输入组合下会指数爆炸。

    // 典型的「灾难性回溯」
/^(a+)+$/      配 "aaaaaaaaaaaaaaaaaaaaaaaaX"
/(a|aa)+$/     配 "aaaa…a!"
/^(\s*\w+)*$/  配一长串空格加非法字符
    共同特征
    嵌套的量词（(x+)+、(x*)*）+ 有多种方式匹配同一段输入 + 最后失配。
    引擎必须尝试所有拆分方式，数量指数级。25 个字符就能让 CPU 跑几秒。
    2019 年 Cloudflare 的全球宕机就是一条 WAF 正则引发的 ReDoS。
    两种引擎的本质差别
    回溯型（PCRE、Java、Python re、JS、.NET）：支持反向引用等强特性，但最坏指数。
    自动机型（RE2、Rust regex）：保证 O(n·m) 线性，但不支持反向引用（那超出了正则语言的表达能力）。

    防御，按优先级：

    ① 换自动机型引擎（根治）
    RE2 / Rust regex。代价是失去反向引用、前后查找等特性——但如果正则来自用户，这些特性本来就不该开放。
    ② 不让用户提供正则（更根治）
    改成受限的查询语法（如只支持前缀/后缀/包含），后端翻译成安全的匹配。功能受限但最安全。
    「用户可配置正则」本身就是一个值得质疑的需求。
    ③ 纵深防御（应该同时做）
    超时 + 熔断（但很多引擎不支持中断，可能要放到独立进程/线程里跑）；限制输入长度；静态扫描危险模式（safe-regex、recheck 等工具，有假阳性但能挡住明显的）。
    这和其他几类漏洞是同一个原理
    「某个资源维度没有上界，而它由攻击者控制」：
    · Hash-DoS（碰撞把 O(1) 拖成 O(n)）
    · 递归解析爆栈（深度嵌套 JSON）
    · 快排复杂度攻击（构造锯齿输入）
    · zip bomb（解压比无上限）
    共同防御思路：对每个资源维度问「上界在哪，谁保证」。
  2. 高级为什么 GNU grep 用 Boyer-Moore 而不是 KMP？

    因为 Boyer-Moore 的平均复杂度是「亚线性」的——它可以跳过文本中的字符而不检查，而 KMP 必须逐个字符看过去。

    核心差别：从尾部开始比
    BM 从模式串的尾部开始比较。失配时用两条规则决定跳多远：
    坏字符规则：文本里那个不匹配的字符，如果在模式串里根本不存在 → 直接跳过整个模式串长度。
    好后缀规则：已匹配的后缀在模式串里还出现在别处 → 对齐到那个位置。
    模式串越长、字符集越大，跳得越远 —— 平均可以做到 O(n/m)。
    对比 KMP 的哲学
    KMP：「一次前进一格，但绝不回退」——O(n) 有确定性保证，且预处理只依赖模式串。
    BM：「尽可能一次跳很远」——平均亚线性，但最坏仍是 O(nm)（除非用 Galil 规则改进）。
    grep 面对的是「在大文件里找短模式」，此时「跳过大段文本」的收益远大于「最坏保证」。
    现代实现走得更远
    ripgrep：Rust regex（自动机型，线性保证）+ SIMD 加速的字面量搜索（memchr 一次比较 16–32 字节）。
    对「查找一个固定字符串」这个最常见的情形，SIMD 暴力扫描往往打败所有精巧算法——因为它把「每字符一次比较」变成「每 32 字节一条指令」。
    这又是「渐进相同、常数决定胜负」的例子。
    更高层的洞察：全文检索根本不做字符串匹配
    ES / Lucene 把「在文档里找词」变成「在倒排索引里查词，得到文档列表」——预处理换查询速度，和 Contraction Hierarchies 是同一思路。
    而 LIKE '%x%' 用不了 B+ 树索引（B+ 树只支持前缀比较）→ 要用全文索引（倒排）或 trigram 索引（把字符串切成三字组）。这是数据库慢查询的常见根因。
  3. 高级要做一个敏感词过滤系统，怎么设计？

    核心算法是 AC 自动机（Trie + fail 指针），一遍扫描找出所有命中。但真实系统的难点几乎都不在算法上。

    ① 算法层：AC 自动机 + 预累加
    建 Trie → BFS 构造 fail 并补全 → 文本扫一遍。
    关键优化：把 cnt 沿 fail 树预先向上累加，查询时 O(1) 而不是沿 fail 链走。否则词库里有 a, aa, aaa 这类嵌套后缀时会退化。
    词库几万到几十万条时，内存是主要约束 → 用双数组 Trie或按字符集压缩节点。
    ② 真正的难点是「变体绕过」
    攻击者会用：拼音替换、形近字（O↔0、l↔1）、插入无意义字符（「敏*感*词」）、全角/半角、繁简转换、零宽字符、emoji 分隔。
    解法是「归一化预处理」：统一转小写、全角转半角、繁转简、删除零宽字符和标点、可选地转拼音。把归一化做好比优化算法重要十倍。
    ③ 第二个难点是「误杀」
    「三个代表」「毛主席」这类词在正常语境里合法。纯字符串匹配无法区分语境。
    解法：白名单（精确短语豁免）、上下文窗口（周围出现某些词则放行）、分级（高危直接拦、中危送人审、低危只记录）。
    「宁可漏一个也不能误杀一片」还是反过来，是业务决策不是技术决策——必须先问清。
    ④ 工程要求
    热更新词库：不能重启服务 → 构建新自动机后原子指针切换（旧的等引用归零再释放）。
    性能：AC 自动机是 O(n)，但归一化和多套索引（原文/拼音/形近）会乘上常数。要压测最坏输入（超长文本、大量命中）。
    可观测性：记录命中了哪些词、误杀申诉率——这些数据是调优词库的唯一依据。
    ⑤ 什么时候该换方案
    如果绕过手段持续升级，字符串匹配会陷入「打补丁」的军备竞赛。此时应该补一层语义模型（文本分类 / embedding 相似度），用「字符串匹配挡明显的、模型挡变体的」两层结构。
    但字符串匹配层不能去掉——它快、确定、可解释、可审计，这些是模型给不了的。「用确定性方法挡住已知的，用模型兜住未知的」是内容安全的通用架构。
  4. 高级面试被问「最长重复子串」，你会怎么答？

    先问清定义：「重复」是指出现至少两次吗？允许重叠吗？要返回长度还是具体串？——这些会影响解法。

    最佳面试答案：二分 + 哈希，O(n log n)
    思路：二分答案长度 L，判定「是否存在长度 L 的子串出现两次」——用前缀哈希把所有长 L 子串的哈希放进 unordered_set，出现重复就说明可行。
    单调性论证（必须说）：若存在长度 L 的重复子串，则它的任意长度 < L 的子串也重复出现 ⟹ 可行性关于 L 单调 ⟹ 可以二分。
    优势：思路直接、代码二十行、能当场写完、能讲清正确性。
    补充：后缀数组，O(n log n)
    求出 SA 和 height 数组后，答案就是 max(height[i])——因为排名相邻的两个后缀有最长的公共前缀。
    要「至少出现 k 次的最长子串」→ height 数组上的滑动窗口最小值（窗口大小 k−1）。
    说出这个能体现知识广度，但不要主动提议现场手写 SA。
    如果不允许重叠
    二分 + 哈希时要额外记录每个哈希值最早出现的位置，要求两次出现的位置差 ≥ L。
    后缀数组版则需要在 height 上滑窗时同时维护 max(sa) 和 min(sa)，要求差 ≥ L。这个条件很容易漏。
    哈希方案要说明碰撞风险
    单哈希 mod 1e9+7、n = 10⁵ 时碰撞概率约 0.5%（生日悖论）。要提一句「用双哈希或随机基数降低碰撞」，或者「哈希相等后再做一次真实比较」。
    主动提出这一点比等面试官问更好——它说明你知道哈希方案的风险边界。
    面试策略总结
    ① 先问清定义（重叠？次数？返回什么）；② 给出能当场写的方案（二分+哈希）并说明单调性；③ 主动提碰撞风险和缓解；④ 补充「如果需要更多子串查询，可以预处理后缀数组，答案是 max(height)」。
    这个结构（问清 → 可实现方案 → 风险 → 更优方案的存在性）适用于绝大多数算法面试题。
