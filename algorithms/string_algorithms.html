字符串匹配

共同主题是「不要浪费已经比较过的信息」。失配后朴素匹配从头再来；KMP 用 border 决定回退到哪；Z 函数复用已知匹配段；滚动哈希用一次加减乘更新指纹。六个算法是同一思想的六种实现。

核心难度 ★★★★☆ 面试出现率 中高 阅读时长 ~30 min 前置 哈希 · Trie · BFS
border 理论 Z 函数 双哈希 Manacher AC 自动机 ReDoS
01

本质：复用已比较的信息

六个算法，一条主线

算法复用什么信息复杂度解决什么
朴素匹配什么都不复用O(nm)基准
KMP模式串的 border（前缀=后缀的最长长度）O(n+m)单模式匹配 + 周期性问题
Z 函数之前算出的匹配段 [l, r]O(n)「每个位置能和开头匹配多长」
Rabin-Karp上一个窗口的哈希值O(n+m) 期望多次比较、二维匹配、去重指纹
Manacher已知回文的对称性O(n)所有回文子串
AC 自动机Trie + 失配指针（KMP 的多串版）O(n + Σm + 命中数)多模式同时匹配
后缀数组 / SAM所有后缀的有序关系 / 等价类O(n log n) / O(n)任意子串的复杂查询
读这张表时抓住一条：已经比过的信息，能不能变成下一次比较的起点。KMP / Z / Manacher 把答案存在「已知区间」里；滚动哈希把窗口收成一个整数；AC 和后缀结构把多串、全后缀预建成可转移的状态。选型先问「要复用什么」，再问复杂度。
核对长号码时，错了一位就从第一位重新念——这是朴素匹配。KMP 说：已经对了 7 位，而这 7 位的前 3 = 后 3，所以退到第 3 位继续。「前缀和后缀重合多少」就是 border，也是 KMP 的全部内容。滚动哈希走另一条路：不逐位比，给窗口算指纹；右移时减最左、加最右，一次加减乘而不是重算 7 位。Z 函数 / Manacher 则记住「已经算出的一段」，新位置先抄对称处的答案再往外扩。

1.1 与其他章节的关系

  • 哈希表内核 —— 滚动哈希的碰撞概率、双哈希、以及「输入可信吗」这个判据
  • 树与平衡树 —— AC 自动机建在 Trie 上；后缀树是压缩 Trie
  • 图遍历与拓扑排序 —— AC 自动机的失配指针用 BFS 构造

  • 搜索引擎基础 —— 倒排索引与全文检索的完整讨论
02

朴素匹配与它的浪费

先看清浪费在哪，才知道 KMP 省了什么

朴素匹配失配后 i 前进 1、j 归零——刚才比对过的信息全部丢掉。最坏 AAAAAB 配 AAAB：每个窗口都要把已经确认的 AAA 再比一遍。复杂度 O(nm)，在「模式几乎全是同一个字符」时打满。

重新比了一遍。KMP 的洞察： 这些信息本来就在手里
关键洞察：失配时已经知道 s[i..i+j-1] == p[0..j-1]。文本接下来长什么样，完全等价于模式前 j 个字符的结构——后者可以预处理，与文本无关。KMP 就是把「失配后该退到哪」预先在模式串上算好：O(m) 预处理 + O(n) 扫描。预处理只依赖模式，同一个 p 扫多份文本时 next 可以复用。
03

KMP 与 border 理论

理解 border，KMP 就不用背了

3.1 border 是什么

border（失配函数 / 前缀函数 / next）：既是 t 的真前缀又是真后缀的串。next[i] = p[0..i] 的最长 border 长度。
例：p = "ababa" → next = [0, 0, 1, 2, 3]（整串的最长 border 是 "aba"）。

3.2 next 数组的构造

构造就是「用 p 匹配自己」；匹配是同一套回退。势能 Φ = len（或匹配中的 j）：外层每轮最多 +1（总增量 ≤ n），内层 while 每次让它严格减小且 ≥ 0，所以总减量也 ≤ n，两层循环仍是 O(m) / O(n)。和双指针、「维护已知区间」的 Z / Manacher 是同一套论证。

// next 构造 + 匹配：同一套回退。i / 外层下标只增不减
std::vector<int> build_next(const std::string& p) {
    int m = p.size();
    std::vector<int> nxt(m, 0);
    for (int i = 1, len = 0; i < m; ++i) {
        while (len > 0 && p[i] != p[len]) len = nxt[len - 1];
        if (p[i] == p[len]) ++len;
        nxt[i] = len;
    }
    return nxt;
}
std::vector<int> kmp_search(const std::string& s, const std::string& p) {
    auto nxt = build_next(p);
    std::vector<int> hits; int m = p.size();
    for (int i = 0, j = 0; i < (int)s.size(); ++i) {
        while (j > 0 && s[i] != p[j]) j = nxt[j - 1];
        if (s[i] == p[j]) ++j;
        if (j == m) { hits.push_back(i - m + 1); j = nxt[j - 1]; }
    }
    return hits;
}

3.3 匹配过程

把「已匹配长度」看成自动机状态：匹配就沿绿边 +1；失配沿红虚线 fail（即 next[j-1]）回退，i 不动。到达终态即命中，再沿 fail 找重叠匹配。这和真正的 DFA 一样：每个字符一次转移；区别是失配边在实现里往往用 while 沿 next 走，而不是把 256 条边都补全——AC 自动机的「补全」才把 while 消掉。

i 只前进是 O(n) 的本质。命中后 j = nxt[j-1] 才能找重叠（"aaaa" 里找 "aa" 应得 3 个）；题目要求不重叠才归零。另一种 next（next[0]=-1、下标偏 1）也对，不要混用。

3.4 border 的其他用途

有长 k 的 border ⟹ 整串右移 n−k 后重叠部分吻合 ⟹ n−k 是周期；若还能整除，就是整数次重复。拼接 a + '#' + b 把「两串关系」收成「一串的自身结构」（分隔符必须两串都不含）。

问题用 border 怎么解
最小周期n − next[n-1]；能整除则是整数次重复
所有 border沿 next 链枚举（border 的传递性）
重复的子字符串n % (n − next[n-1]) == 0 且 next[n-1] > 0
最短回文添加s + '#' + reverse(s) 的 next 末项 = 最长回文前缀
最长公共前后缀a + '#' + b 的 next 末项
循环同构在 s+s 里找 t
04

Z 函数（扩展 KMP）

比 KMP 更直观，很多题更好用

Z 函数：z[i] = s[i..] 与 s 本身的最长公共前缀长度（z[0] 常取 n）。例：s = "aabxaab" → z = [7, 1, 0, 0, 3, 1, 0]。
// Z 函数：维护已知匹配段 [l, r)（Z-box）
std::vector<int> z_function(const std::string& s) {
    int n = s.size();
    std::vector<int> z(n); z[0] = n;
    for (int i = 1, l = 0, r = 0; i < n; ++i) {
        if (i < r) z[i] = std::min(r - i, z[i - l]);
        while (i + z[i] < n && s[z[i]] == s[i + z[i]]) ++z[i];
        if (i + z[i] > r) { l = i; r = i + z[i]; }
    }
    return z;
}

势能 Φ = r：while 每次成功都让 r 增大，r ≤ n 故 O(n)。对 p + '#' + s 求 Z，凡 z[i] == m 就是一次匹配。

情形选谁
纯匹配等价；KMP 不用拼接，省一点空间
每个位置与开头匹配多长Z 函数（这就是定义）
周期性 / borderKMP 的 next
好写好记Z：「复用对称位置 + 暴力扩展」比 next 链直观
05

Rabin-Karp 与滚动哈希

它的价值不在单模式匹配

5.1 滚动哈希

多项式哈希 H(s[0..m-1]) = s[0]·B^(m-1) + … + s[m-1] (mod M) 滚动 H_new = (H_old − s[i]·B^(m-1)) · B + s[i+m] (mod M) 前缀 sub(l, r) = h[r+1] − h[l]·pw[r−l+1]　　任意子串 O(1)

5.2 碰撞与双哈希

自然溢出（mod 2⁶⁴）可被 Thue-Morse 串打穿任意基数，竞赛里专门卡单哈希。防御按强度：运行时随机基数（挡住离线构造）→ 大质数模 + 随机 B（注意乘法溢出 / __int128）→ 双哈希（两组 (B,M) 都相等才认）。生日悖论：mod 1e9+7 比较 10⁵ 对时碰撞约 0.5%，双哈希后才可忽略。
不能只信哈希的时候：输入不可信（用户上传、外部 API）→ SipHash 或哈希命中后再真比较；用于去重 / 鉴权 / 内容寻址 → SHA-256、BLAKE3。竞赛或内部工具、输入可信 → 双哈希 + 随机基数够用。这和 哈希表 的 Hash-DoS 同一原理：平均情形可被攻击。

5.3 它真正的价值

单模式匹配请用 KMP（确定、无碰撞、不用模数）。哈希的价值是把字符串比较变成 O(1) 整数比较，从而能用 set、二分、DP 状态、图节点标识。前缀哈希比定长滚动更常用：预处理 h[]、pw[] 后任意子串 O(1)，这才是最长公共 / 重复子串里「二分 + 判定」能成立的原因。字节必须转 unsigned char，否则有符号 char 会把非 ASCII 变成负数。

场景为何哈希比 KMP 合适
任意两子串是否相等前缀哈希 O(1)；KMP 只回答「模式在哪」
二分 + 判定任意长度子串比较：最长公共 / 重复子串
二维匹配每行先哈希，再对行哈希序列做一维匹配
等长多模式模式哈希进 unordered_set，扫一遍文本
树哈希 / 指纹结构编码成整数；SimHash 是相似不是精确
06

Manacher：线性求回文

复用「已知回文的对称性」

最长回文子串：中心扩展 O(n²)（2n−1 个中心：n 个字符 + n−1 个间隙）代码五行，n ≤ 1000 面试首选；二分 + 哈希 O(n log n) 能当场写。Manacher 的 O(n) 只在 n 到 10⁶、或需要每个位置的半径时才必要。插 # 把奇偶统一成奇数，首尾哨兵 ^ ≠ $ 让扩展自动停——和柱状图最大矩形的哨兵同一思路。面试策略：先写中心扩展，再口述「有 O(n) 的 Manacher，复用已知回文的对称性」。

07

AC 自动机：多模式匹配

Trie + KMP 的失配指针

k 个模式同时扫一段文本：朴素是 k 次 KMP；AC 自动机是 Trie + fail，O(n + Σm + 命中数)，文本只走一遍。fail[v] 指向「是 v 的后缀、又是某模式前缀」的最长节点——KMP next 的多串版。空边补成 ch[fail[u]][k] 后，查询每个字符恰好一次转移。fail 依赖父节点，必须 BFS 按深度建。

// Trie：最短 insert / search（节点 0 为根）
void insert(const std::string& w) {
    int u = 0;
    for (char c : w) {
        int k = c - 'a';
        if (!ch[u][k]) { ch[u][k] = ch.size(); ch.push_back({}); }
        u = ch[u][k];
    }
    ++cnt[u];
}
bool search(const std::string& w) {
    int u = 0;
    for (char c : w) { u = ch[u][c - 'a']; if (!u) return false; }
    return cnt[u] > 0;
}
查询若沿 fail 链累加 cnt，模式有 a, aa, aaa… 这类嵌套后缀时会退化成 O(节点数)。只要总数：按 BFS 序预累加 sum[v] = cnt[v] + sum[fail[v]]，查询 O(1)。要每条模式的次数：查询只打标记，最后在 fail 树上自底向上加。fail 指针构成一棵树，AC 上的 DP 也走这棵树。
应用要点
敏感词 / WAF / 序列搜索一遍扫出全部命中，可同时替换
AC 上的 DP「长 n 且不含任何模式」：自动机状态当 DP 下标
词库 / 输入法双数组 Trie 等压空间变体；内存往往比时间更紧
热更新词库新建自动机后原子切换指针，旧对象引用归零再释放
08

后缀结构简介

从「找一个模式」到「任意子串的任意查询」

8.1 后缀数组

sa[i] = 排名第 i 的后缀起点；height[i] = 相邻两后缀的 LCP。倍增 O(n log n) 好写，DC3 / SA-IS 是 O(n) 但复杂；height 用 Kasai O(n)。任意两后缀的 LCP = height 上这两名次之间的区间最小值，配稀疏表就是 O(1)。两串最长公共子串要拼 a+'#'+b 再取 max(height)，且两端来自不同串——漏了这个条件会得到串内重复，答案偏大。

问题SA + height
模式是否出现SA 上二分，O(m log n)
最长重复子串max(height[i])
不同子串个数n(n+1)/2 − Σ height
两串最长公共子串拼接后取 max(height)，且两端来自不同串（漏了会算成串内重复）
至少出现 k 次height 上滑窗最小值
任意两后缀 LCPheight 的 RMQ（稀疏表 O(1)）

8.2 后缀自动机与后缀树

结构本质何时用
后缀数组后缀有序 + LCP首选：好写、常数小
后缀树压缩后缀 Trie理论漂亮，代码极长
SAM识别全部子串的最小 DFA出现次数等 SA 别扭的查询；状态 ≤ 2n−1

SAM 按 endpos 等价类建状态（出现位置集合相同的子串归一类），状态数 ≤ 2n−1、转移 ≤ 3n−4，所以能线性构造。link（parent tree）上做 DP 能算出现次数、不同子串个数。构造约 40 行且有「克隆节点」分支，初学先 SA——能解八成题，也好调。SAM 是「必须要它」时再学。面试几乎不手写：先给二分+哈希，再补一句「更多子串查询可预处理 SA」。

工程场景

正则、grep、检索、diff

9.1 正则与 ReDoS

回溯型（PCRE / Java / Python re / JS / .NET）：反向引用、前后查找都支持，最坏指数。自动机型（RE2、Rust regex）：保证 O(n·m) 线性，但反向引用超出了正则语言，做不了。用户可配置正则时，这些强特性本来就不该开放。

// 典型灾难性回溯
/^(a+)+$/      配一长串 a 再加 X
/(a|aa)+$/     配 aaaa…a!
/^(\s*\w+)*$/  配长空白加非法字符
防御代价
换 RE2 / Rust regex线性保证；失去反向引用
不让用户提供正则改成受限查询语法，最安全
超时熔断 + 限长纵深；许多引擎不能中断，可能要丢独立进程
静态扫描危险模式safe-regex / recheck，有假阳假阴

9.2 grep / 全文检索 / diff

系统算法
GNU grepBoyer-Moore：从模式尾部比，失配可跳多格，平均亚线性
ripgrep自动机型 regex + SIMD memchr
ES / Lucene倒排索引，查询阶段不做字符串扫描
LIKE '%x%'B+ 树用不上，要全文索引或 trigram
git diffMyers：编辑图上的 BFS 优化
拼写纠错编辑距离 + Trie 剪枝，或 BK-tree / SymSpell
近似去重MinHash / SimHash，相似不是精确匹配

BM 和 KMP 哲学相反：KMP「一次一格、绝不回退」有最坏保证；BM 从模式尾部比，坏字符 / 好后缀一次可跳多格，模式越长、字符集越大跳得越远，平均亚线性，最坏仍可能 O(nm)（除非 Galil）。grep 面对的是大文件里找短模式，「跳过大段」比「最坏保证」更值钱。ripgrep 对字面量直接 SIMD 扫，常数往往赢过精巧算法。全文检索把「在文档里找词」变成「在倒排里查词」——预处理换查询，和 Contraction Hierarchies 同一思路。LIKE '%x%' 的 % 在前，B+ 树前缀比较用不上，这是数据库慢查询的常见根因。

10.1 基础（必答）

点击每道题展开参考答案（先自测，再对照）。

  1. 基础KMP 的 next 数组是什么含义？手写它的构造。

    next[i] = p[0..i] 的最长 border 的长度。而 border 是「既是真前缀、又是真后缀」的字符串。

    例：p = "ababa" → next = [0, 0, 1, 2, 3]（"ababa" 的最长 border 是 "aba"，长度 3）。

    std::vector<int> build_next(const std::string& p) {
    int m = p.size();
    std::vector<int> nxt(m, 0);
    for (int i = 1, len = 0; i < m; ++i) {
        while (len > 0 && p[i] != p[len]) len = nxt[len - 1];
        if (p[i] == p[len]) ++len;
        nxt[i] = len;
    }
    return nxt;
}
    next 有什么用（这才是重点）
    失配时我们已经知道 s[i-j..i-1] == p[0..j-1]。而 p[0..j-1] 的后缀 = 它的前缀（长度 next[j-1]）⟹ s 的最近这几位已经匹配上了 p 的开头几位 ⟹ 可以直接从 j = next[j-1] 继续，不必退到 0。
    构造为什么是 O(m)
    势能法：取 Φ = len。外层每轮 len 最多 +1（总增量 ≤ m）；内层 while 每次让 len 严格减小；len ≥ 0 ⟹ 总减量 ≤ 总增量 ≤ m ⟹ 内层总次数 ≤ m。∎
    和双指针「两层循环仍是 O(n)」是同一套论证。
    两种 next 定义不要混用
    还有一种流行定义是下标偏移 1、next[0] = -1。两种都对，但混用会导致下标错乱。选一种记牢。
  2. 基础KMP 的匹配过程为什么是 O(n)？

    因为i（文本串指针）全程只前进，从不回退——这是它相对朴素匹配的本质区别。

    for (int i = 0, j = 0; i < n; ++i) {     // i 只增
    while (j > 0 && s[i] != p[j]) j = nxt[j-1];   // j 回退
    if (s[i] == p[j]) ++j;
    if (j == m) { record(i - m + 1); j = nxt[j-1]; }
}
    势能论证
    取 Φ = j。外层每轮 j 最多 +1 ⟹ 总增量 ≤ n。内层 while 每次让 j 严格减小，且 j ≥ 0 ⟹ 内层总执行次数 ≤ n。
    总代价 = n（外层）+ n（内层总量）= O(n)。∎
    对比朴素匹配的浪费
    朴素匹配失配后 i 前进 1、j 归零——刚才比对的 j 位信息全部丢弃。
    s = "AAAAAB", p = "AAAB"：i=0 时已知 s[1..3] = "AAA"，但 i=1 时又把这三个 A 重新比了一遍。而这些信息本来就在手里。
    两个实现细节
    ① 找到匹配后写 j = nxt[j-1]（不是 j = 0），才能找到重叠的匹配（在 "aaaa" 里找 "aa" 应得 3 个）。题目要求不重叠才写 j = 0。
    ② KMP 分两阶段：O(m) 预处理模式串 + O(n) 扫文本串。预处理只依赖模式串，所以同一个模式串匹配多个文本时可以复用 next 数组。
  3. 基础什么是滚动哈希？它有什么风险？
    多项式哈希 H(s[0..m-1]) = s[0]·B^(m-1) + … + s[m-1] (mod M) 滚动（窗口右移一位） H_new = (H_old − s[i]·B^(m-1)) · B + s[i+m] (mod M) ↑ 减掉最左位 ↑ 左移 ↑ 加最右位 O(1) 完成，而不是重算 m 位
    前缀哈希比滚动更常用
    预处理 h[] 和 pw[] 后，任意子串的哈希是 h[r+1] − h[l]·pw[r-l+1]，O(1)。
    这让「比较任意两个子串是否相等」变成 O(1)，从而能配合二分解「最长公共子串」「最长重复子串」。
    风险一：碰撞
    单哈希 mod 1e9+7、比较 n 对字符串时，由生日悖论碰撞概率约 n²/(2M)——n = 10⁵ 时约 0.5%，不算低。
    风险二：可被构造攻击
    用「自然溢出」（mod 2^64）时，可以构造 Thue-Morse 串使任意基数下都碰撞。竞赛里这被用来卡单哈希选手。
    三种防御
    ① 随机基数（运行时随机取 B，而非固定 131）——挡住离线构造反例；② 大质数模数 + 随机 B；③ 双哈希（两组不同的 (B, M)，都相等才认为相等）。
    什么时候不能只信哈希
    输入不可信（用户上传、外部 API）→ 用带随机密钥的哈希，或哈希相等后再做真实比较。
    用于安全决策（去重、鉴权、内容寻址）→ 必须用密码学哈希或真实比较。
    这和 Hash-DoS 是同一个原理：平均情形可被攻击。
    另外别忘 (unsigned char) 强转——char 有符号时非 ASCII 字节会变负数。
  4. 基础求「最长回文子串」有哪几种方法？分别什么复杂度？
    方法复杂度代码量适用
    中心扩展O(n²)五行n ≤ 1000，面试首选
    DP dp[i][j]O(n²) 时间 O(n²) 空间中等需要判断所有子串是否回文时
    二分 + 哈希O(n log n)中等思路直接，能当场写
    ManacherO(n)较长n 很大，或需所有位置的回文半径
    中心扩展的要点
    枚举中心（2n−1 个：n 个字符中心 + n−1 个间隙中心），向两边扩展。
    「间隙中心」是处理偶数长度回文的关键，漏掉它会错过 "abba" 这类。
    Manacher 的两个技巧
    ① 插入分隔符统一奇偶："abba" → "^#a#b#b#a#$"，所有回文变成奇数长度，只需处理一种情况。而且插入后 p[i] 恰好等于原串中回文的长度。
    ② 首尾哨兵（^ 和 $，互不相同）：让扩展自动在边界停下，不需要越界判断。和柱状图最大矩形的哨兵是同一思路。
    Manacher 复用什么信息
    已知「以 c 为中心、右边界到 r」是回文。要算 i（在 c 右边）时，因为大回文内部对称，i 的镜像位置 2c−i 的结果已经算过，可以直接拿来当起点。
    限制是镜像结论只在大回文内部有效 → 取 min(r−i, p[2c−i])。这个「先复用、再扩展」的结构和 Z 函数一模一样。
    面试策略
    先写中心扩展（五行、不易错），然后说「有 O(n) 的 Manacher，思路是复用已知回文的对称性」。这比硬写 Manacher 更稳——现场写 Manacher 很容易在哨兵和下标上出错。

10.2 中级（区分熟练度）

  1. 中级怎么用 KMP 的 next 数组求字符串的最小周期？
    最小周期 = n − next[n−1] 若 n % (n − next[n−1]) == 0 且 next[n−1] > 0 ⟹ 整个串由这个周期整数次重复而成
    直觉
    如果 p[0..n-1] 有长度 k 的 border，说明「前 k 个 = 后 k 个」
    ⟹ 把整个串右移 n−k 位后，重叠部分完全吻合
    ⟹ n−k 是一个「周期」（允许最后一段不完整）。
    而当 n 能被 n−k 整除时，最后一段刚好完整 ⟹ 整个串是这个周期的整数次重复。
    例子
    "abcabcabc"，n=9，next[8] = 6（border 是 "abcabc"）→ 最小周期 = 9−6 = 3，且 9 % 3 == 0 ⟹ 由 "abc" 重复 3 次。
    "abcabca"，n=7，next[6] = 4 → 周期 3，但 7 % 3 ≠ 0 ⟹ 不是整数次重复（最后一段不完整）。
    border 的传递性（同样重要）
    next[i] 对应的 border 的 border 也是 p[0..i] 的 border ⟹ 沿 next 链 i → next[i]−1 → … 能枚举出所有 border。
    这用于「求所有周期」「统计每个前缀出现次数」等问题。
    拼接技巧：把两串关系转成一串的自身结构
    对 a + '#' + b 求 next，末尾值 = a 的后缀与 b 的前缀的最长匹配。
    同理可解：最短回文添加（对 s + '#' + reverse(s) 求 next）、循环同构判定（在 s+s 里找 t）。
    分隔符必须是两串都不含的字符，否则会产生跨界的假匹配。
  2. 中级Z 函数是什么？它和 KMP 怎么选？

    z[i] = s[i..] 与 s 本身的最长公共前缀长度。
    例：s = "aabxaab" → z = [7, 1, 0, 0, 3, 1, 0]。

    for (int i = 1, l = 0, r = 0; i < n; ++i) {
    if (i < r) z[i] = std::min(r - i, z[i - l]);   // 复用对称位置
    while (i + z[i] < n && s[z[i]] == s[i + z[i]]) ++z[i];   // 暴力扩展
    if (i + z[i] > r) { l = i; r = i + z[i]; }        // 更新 Z-box
}
    它复用什么信息
    维护一个已知匹配段 [l, r]（Z-box）——这段等于 s 的一个前缀。若 i 落在这段内，它对应的信息在 z[i-l] 里已经算过，可以直接拿来当起点。
    O(n) 的证明：势能 Φ = r，内层 while 每次成功都让 r 严格增大，r ≤ n。∎
    用 Z 函数做匹配
    对 p + '#' + s 求 Z 函数，凡 z[i] == m 的位置就是一个匹配。
    情形选谁
    纯匹配等价；KMP 省一点空间（不用拼接）
    「每个位置与开头匹配多长」Z 函数（这就是它的定义）
    周期性 / border 相关KMP 的 next
    好写好记Z 函数（「复用对称位置 + 暴力扩展」比 next 链回退直观）
    三个算法共用一套框架
    KMP 构造、Z 函数、Manacher 都是「维护一个已知区间 + 在区间内复用 + 区间外暴力扩展 + 势能法证 O(n)」。
    认出这个框架，三个算法就变成了一个模式的三种实例。
  3. 中级AC 自动机怎么工作？fail 指针和 KMP 的 next 什么关系？

    AC 自动机 = Trie + fail 指针，解决「k 个模式串同时匹配一个文本串」，复杂度 O(n + Σmᵢ + 命中数)——文本只扫一遍（对比「对每个模式串跑一次 KMP」的 O(k·n)）。

    fail 指针 = KMP 的 next 的多串版
    fail[v] 指向「是 v 所代表字符串的后缀，且是某个模式串的前缀」的最长节点。
    作用完全等同于 KMP 失配后的回退——只不过 KMP 在一个串上回退，AC 自动机在整棵 Trie 上回退。
    用 BFS 构造 + 「补全」Trie
    if (v) { fail[v] = ch[fail[u]][k]; q.push(v); }
else   { v = ch[fail[u]][k]; }        // ← 补全：空边指向 fail 的对应边
    为什么用 BFS：fail[v] 依赖 fail[父节点]，所以必须按深度从小到大处理。
    「补全」的价值：查询时不需要 while 回退——每个字符恰好一次状态转移。这一步把「Trie + fail」真正变成了「自动机」。
    查询的复杂度陷阱
    for (int t = u; t; t = fail[t]) total += cnt[t]; 这个内层循环最坏是 O(节点数)。模式串有大量嵌套后缀（a, aa, aaa, …）时会退化。
    优化：只需总数时，把 cnt 沿 fail 树预先向上累加（sum[v] = cnt[v] + sum[fail[v]]，按 BFS 序），查询变 O(1)；需要每个模式串的次数时，查询只打标记，最后在 fail 树上做一次自底向上累加。
    「fail 指针构成一棵树」是重要性质
    很多进阶应用基于它：fail 树上的 DP、子树求和、AC 自动机上的 DP（「构造长度 n 的串使不含任何模式串」→ 在自动机状态上做 DP）。
    典型应用：敏感词过滤、WAF 规则匹配、生物序列多模式搜索、输入法词库。
  4. 中级怎么求「两个字符串的最长公共子串」？（注意是子串不是子序列）

    先区分清楚：子串（substring）必须连续；子序列（subsequence）可以不连续。这两个问题的解法完全不同。

    方法复杂度要点
    DP dp[i][j]O(nm)dp[i][j] = 以 a[i]、b[j] 结尾的公共子串长度；不等时置 0（不是取 max！）
    二分 + 哈希O((n+m) log)二分长度 L，把 a 的所有长 L 子串哈希放 set，查 b 的
    后缀数组O(n log n)拼接后求 max(height[i])，且 sa[i-1]、sa[i] 来自不同串
    后缀自动机O(n)对 a 建 SAM，用 b 在上面跑
    DP 版最常见的错
    字符不相等时必须置 0（dp[i][j] = 0），而不是像 LCS（最长公共子序列）那样取 max(dp[i-1][j], dp[i][j-1])。
    因为子串要求连续——一旦断开就得重新开始。这一行的差别就是「子串 vs 子序列」的全部区别。
    二分 + 哈希是面试的最佳答案
    思路直接（「存在长度 L 的公共子串」关于 L 单调 → 可以二分），代码短，能当场写出来。
    但要说明单调性：如果存在长度 L 的公共子串，那它的任意子串（长度 < L）也是公共子串 ⟹ 单调成立。
    后缀数组版的易漏条件
    拼接 a + '#' + b 后求 max(height[i])，必须同时要求 sa[i-1] 和 sa[i] 来自不同的原串。
    漏掉这个条件会得到「同一个串内部的重复」，答案偏大。

10.3 高级（体现深度）

  1. 高级什么是 ReDoS？线上有一条用户可配置的正则，怎么防？

    ReDoS（正则拒绝服务）：回溯型正则引擎在某些模式 + 输入组合下会指数爆炸。

    // 典型的「灾难性回溯」
/^(a+)+$/      配 "aaaaaaaaaaaaaaaaaaaaaaaaX"
/(a|aa)+$/     配 "aaaa…a!"
/^(\s*\w+)*$/  配一长串空格加非法字符
    共同特征
    嵌套的量词（(x+)+、(x*)*）+ 有多种方式匹配同一段输入 + 最后失配。
    引擎必须尝试所有拆分方式，数量指数级。25 个字符就能让 CPU 跑几秒。
    2019 年 Cloudflare 的全球宕机就是一条 WAF 正则引发的 ReDoS。
    两种引擎的本质差别
    回溯型（PCRE、Java、Python re、JS、.NET）：支持反向引用等强特性，但最坏指数。
    自动机型（RE2、Rust regex）：保证 O(n·m) 线性，但不支持反向引用（那超出了正则语言的表达能力）。

    防御，按优先级：

    ① 换自动机型引擎（根治）
    RE2 / Rust regex。代价是失去反向引用、前后查找等特性——但如果正则来自用户，这些特性本来就不该开放。
    ② 不让用户提供正则（更根治）
    改成受限的查询语法（如只支持前缀/后缀/包含），后端翻译成安全的匹配。功能受限但最安全。
    「用户可配置正则」本身就是一个值得质疑的需求。
    ③ 纵深防御（应该同时做）
    超时 + 熔断（但很多引擎不支持中断，可能要放到独立进程/线程里跑）；限制输入长度；静态扫描危险模式（safe-regex、recheck 等工具，有假阳性但能挡住明显的）。
    这和其他几类漏洞是同一个原理
    「某个资源维度没有上界，而它由攻击者控制」：
    · Hash-DoS（碰撞把 O(1) 拖成 O(n)）
    · 递归解析爆栈（深度嵌套 JSON）
    · 快排复杂度攻击（构造锯齿输入）
    · zip bomb（解压比无上限）
    共同防御思路：对每个资源维度问「上界在哪，谁保证」。
  2. 高级为什么 GNU grep 用 Boyer-Moore 而不是 KMP？

    因为 Boyer-Moore 的平均复杂度是「亚线性」的——它可以跳过文本中的字符而不检查，而 KMP 必须逐个字符看过去。

    核心差别：从尾部开始比
    BM 从模式串的尾部开始比较。失配时用两条规则决定跳多远：
    坏字符规则：文本里那个不匹配的字符，如果在模式串里根本不存在 → 直接跳过整个模式串长度。
    好后缀规则：已匹配的后缀在模式串里还出现在别处 → 对齐到那个位置。
    模式串越长、字符集越大，跳得越远 —— 平均可以做到 O(n/m)。
    对比 KMP 的哲学
    KMP：「一次前进一格，但绝不回退」——O(n) 有确定性保证，且预处理只依赖模式串。
    BM：「尽可能一次跳很远」——平均亚线性，但最坏仍是 O(nm)（除非用 Galil 规则改进）。
    grep 面对的是「在大文件里找短模式」，此时「跳过大段文本」的收益远大于「最坏保证」。
    现代实现走得更远
    ripgrep：Rust regex（自动机型，线性保证）+ SIMD 加速的字面量搜索（memchr 一次比较 16–32 字节）。
    对「查找一个固定字符串」这个最常见的情形，SIMD 暴力扫描往往打败所有精巧算法——因为它把「每字符一次比较」变成「每 32 字节一条指令」。
    这又是「渐进相同、常数决定胜负」的例子。
    更高层的洞察：全文检索根本不做字符串匹配
    ES / Lucene 把「在文档里找词」变成「在倒排索引里查词，得到文档列表」——预处理换查询速度，和 Contraction Hierarchies 是同一思路。
    而 LIKE '%x%' 用不了 B+ 树索引（B+ 树只支持前缀比较）→ 要用全文索引（倒排）或 trigram 索引（把字符串切成三字组）。这是数据库慢查询的常见根因。
  3. 高级要做一个敏感词过滤系统，怎么设计？

    核心算法是 AC 自动机（Trie + fail 指针），一遍扫描找出所有命中。但真实系统的难点几乎都不在算法上。

    ① 算法层：AC 自动机 + 预累加
    建 Trie → BFS 构造 fail 并补全 → 文本扫一遍。
    关键优化：把 cnt 沿 fail 树预先向上累加，查询时 O(1) 而不是沿 fail 链走。否则词库里有 a, aa, aaa 这类嵌套后缀时会退化。
    词库几万到几十万条时，内存是主要约束 → 用双数组 Trie或按字符集压缩节点。
    ② 真正的难点是「变体绕过」
    攻击者会用：拼音替换、形近字（O↔0、l↔1）、插入无意义字符（「敏*感*词」）、全角/半角、繁简转换、零宽字符、emoji 分隔。
    解法是「归一化预处理」：统一转小写、全角转半角、繁转简、删除零宽字符和标点、可选地转拼音。把归一化做好比优化算法重要十倍。
    ③ 第二个难点是「误杀」
    「三个代表」「毛主席」这类词在正常语境里合法。纯字符串匹配无法区分语境。
    解法：白名单（精确短语豁免）、上下文窗口（周围出现某些词则放行）、分级（高危直接拦、中危送人审、低危只记录）。
    「宁可漏一个也不能误杀一片」还是反过来，是业务决策不是技术决策——必须先问清。
    ④ 工程要求
    热更新词库：不能重启服务 → 构建新自动机后原子指针切换（旧的等引用归零再释放）。
    性能：AC 自动机是 O(n)，但归一化和多套索引（原文/拼音/形近）会乘上常数。要压测最坏输入（超长文本、大量命中）。
    可观测性：记录命中了哪些词、误杀申诉率——这些数据是调优词库的唯一依据。
    ⑤ 什么时候该换方案
    如果绕过手段持续升级，字符串匹配会陷入「打补丁」的军备竞赛。此时应该补一层语义模型（文本分类 / embedding 相似度），用「字符串匹配挡明显的、模型挡变体的」两层结构。
    但字符串匹配层不能去掉——它快、确定、可解释、可审计，这些是模型给不了的。「用确定性方法挡住已知的，用模型兜住未知的」是内容安全的通用架构。
  4. 高级面试被问「最长重复子串」，你会怎么答？

    先问清定义：「重复」是指出现至少两次吗？允许重叠吗？要返回长度还是具体串？——这些会影响解法。

    最佳面试答案：二分 + 哈希，O(n log n)
    思路：二分答案长度 L，判定「是否存在长度 L 的子串出现两次」——用前缀哈希把所有长 L 子串的哈希放进 unordered_set，出现重复就说明可行。
    单调性论证（必须说）：若存在长度 L 的重复子串，则它的任意长度 < L 的子串也重复出现 ⟹ 可行性关于 L 单调 ⟹ 可以二分。
    优势：思路直接、代码二十行、能当场写完、能讲清正确性。
    补充：后缀数组，O(n log n)
    求出 SA 和 height 数组后，答案就是 max(height[i])——因为排名相邻的两个后缀有最长的公共前缀。
    要「至少出现 k 次的最长子串」→ height 数组上的滑动窗口最小值（窗口大小 k−1）。
    说出这个能体现知识广度，但不要主动提议现场手写 SA。
    如果不允许重叠
    二分 + 哈希时要额外记录每个哈希值最早出现的位置，要求两次出现的位置差 ≥ L。
    后缀数组版则需要在 height 上滑窗时同时维护 max(sa) 和 min(sa)，要求差 ≥ L。这个条件很容易漏。
    哈希方案要说明碰撞风险
    单哈希 mod 1e9+7、n = 10⁵ 时碰撞概率约 0.5%（生日悖论）。要提一句「用双哈希或随机基数降低碰撞」，或者「哈希相等后再做一次真实比较」。
    主动提出这一点比等面试官问更好——它说明你知道哈希方案的风险边界。
    面试策略总结
    ① 先问清定义（重叠？次数？返回什么）；② 给出能当场写的方案（二分+哈希）并说明单调性；③ 主动提碰撞风险和缓解；④ 补充「如果需要更多子串查询，可以预处理后缀数组，答案是 max(height)」。
    这个结构（问清 → 可实现方案 → 风险 → 更优方案的存在性）适用于绝大多数算法面试题。
