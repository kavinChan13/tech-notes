核心问题：三大主流 Agent 记忆系统各有千秋。选型不是"哪个最好"，而是"哪个最适合你的场景"。就像选车：市区通勤选轿车（Claude Code），越野旅行选 SUV（OpenViking），长途货运选卡车（Hermes Agent）。没有最好，只有最适合。

三种系统代表了三种不同的设计哲学：Claude Code 追求简单可靠（文件式，一个 Markdown 搞定）；OpenViking 追求知识组织（层级虚拟文件系统，目录递归检索）；Hermes 追求自我进化（KEPA 闭环，从失败中学习）。

2.1 Claude Code — 记忆提取流水线

Claude Code 的记忆提取由后台子 Agent 完成，整个流水线遵循四个核心原则：权限锁死、两轮对话、互斥检查、游标追踪。

2.2 OpenViking — 层级虚拟文件系统

OpenViking 将记忆组织为三级虚拟目录（resources/、user/、agent/），每个文件有 L0/L1/L2 三个加载层级，支持目录递归检索——从根目录开始逐层缩小范围，避免全量搜索的 Token 浪费。

2.3 Hermes Agent — KEPA 闭环详解

Hermes Agent 的 KEPA（Knowledge Experience Practice Assessment）是一个持续运行的自我进化闭环。它不只是"记住"失败，而是从失败中提炼可迁移的规则，并通过复盘验证规则的有效性。

选型核心原则：不要追求"最强"记忆系统，而是根据你的核心痛点选择——编码场景选简单直接的 Claude Code，知识管理选层级化的 OpenViking，稳定性优先选自我进化的 Hermes Agent。

混合选型决策树

  1. 你的核心需求是编码辅助吗？ → 是 → Claude Code（文件式 + Prompt Cache）
  2. 你有超过 1 万份文档需要管理？ → 是 → OpenViking（层级虚拟 FS + 三层分级）
  3. 你的 Agent 需要 7×24 长期稳定运行？ → 是 → Hermes Agent（KEPA + 五层防御）
  4. 以上都不是？ → 混合方案：Claude Code 的简单记忆 + OpenViking 的知识层级 + Hermes 的经验沉淀

  • 根据核心痛点选型，不追求"最强"
  • 编码场景优先 Prompt Cache 优化（省 67% 成本）
  • 知识库场景用三层分级加载（减 83%+ Token）
  • 稳定性场景启用 KEPA 闭环 + 字符硬上限
  • 文档量超过 1 万份时考虑迁移到层级化方案
  • 不要无脑选"功能最多"的系统
  • 不要在编码场景用层级化记忆（过度工程化）
  • 不要在知识库场景用纯文件式记忆（检索效率低）
  • 不要忽视遗忘机制（长期运行后记忆堆积）
  • 不要在稳定性场景跳过安全防御
迁移决策信号：当你的 Claude Code MEMORY.md 超过 50KB、检索召回率低于 70%、或月 Token 成本超过 $300 时，就是考虑迁移到层级化记忆系统（如 OpenViking）的信号。反之，如果文档量始终在 5000 份以下，Claude Code 的文件式记忆完全够用，不需要引入额外的复杂度。

渐进式记忆系统升级路径

大多数团队不需要一步到位选择最复杂的方案。推荐采用渐进式升级策略，根据业务增长和痛点变化逐步引入更高级的记忆机制：

阶段记忆方案触发条件预计工期关键动作
Phase 1Claude Code 文件式项目启动 / 文档 < 5000 份1-2 天创建 MEMORY.md，配置 Prompt Cache
Phase 2+ OpenViking 层级 FS文档 > 1 万份 / 召回率 < 70%2-4 周设计目录树，生成 L0/L1 摘要索引
Phase 3+ Hermes KEPA 闭环7×24 运行 / 错误率 > 3%4-8 周部署 KEPA 流水线，配置字符硬上限
Phase 4全混合 + 自动化多 Agent 协作 / 跨项目复用8-12 周统一记忆总线，自动路由 & 冲突解决
升级决策信号：
  • Phase 1 → Phase 2：MEMORY.md 超过 50KB，或月 Token 成本超过 $300，或检索召回率低于 70%
  • Phase 2 → Phase 3：Agent 错误率连续两周 > 3%，或同类错误反复出现（说明缺乏经验沉淀）
  • Phase 3 → Phase 4：多个 Agent 实例需要共享记忆，或跨项目知识复用需求明确

常见踩坑点

  • 从 Claude Code 起步，验证记忆价值后再升级
  • 迁移时保留旧系统的记忆快照作为回退方案
  • L0/L1 摘要生成用 LLM 自动化，人工抽检 10%
  • KEPA 闭环初期用"宽松模式"（高容错），稳定后切换"严格模式"
  • 不要一开始就上全混合方案（复杂度过高，团队消化不良）
  • 不要在 Phase 1 阶段就为 Phase 3 做预留设计（过度工程化）
  • 不要忽略 L0/L1 摘要质量——垃圾摘要比没有摘要更危险
  • 不要跳过 Phase 2 直接到 Phase 3（没有知识层级，KEPA 无处沉淀）
三大记忆系统的选型原则：编码场景用文件式记忆（简单确定），对话场景用层级化记忆（结构化 + 向量化），知识库场景用图谱式记忆（关系推理）。没有银弹，只有场景匹配。

Q&A

Claude Code ：文件式记忆 + 后台自动提取 + Prompt Cache 优化…
Q1：三大记忆系统的核心差异是什么？

Claude Code：文件式记忆 + 后台自动提取 + Prompt Cache 优化，简单直接适合编码。OpenViking：层级虚拟文件系统 + 三层分级加载 + 目录递归检索，适合知识库密集场景。Hermes Agent：KEPA 自我进化闭环 + 三层知识架构 + 五层防御 + 字符硬上限遗忘，适合稳定性要求高的场景。核心区别：Claude Code 追求"快"，OpenViking 追求"全"，Hermes 追求"稳"。

Q2：为什么 Hermes Agent 的字符硬上限是个好设计？

字符硬上限强制模型进行"主动选择性遗忘"——当记忆超过上限时，模型必须自己决定哪些信息值得保留。结果是保留的都是真正有价值的信息，记忆质量显著提升（评分从 3.1/5 提升至 4.6/5）。Claude Code 和 OpenViking 都没有显式遗忘机制，长期运行后记忆可能堆积导致检索质量下降。本质：遗忘不是缺陷，而是信息质量的保障。

Q3：如何为不同场景选择记忆系统？

根据核心痛点选择：① 编码助手→ Claude Code（文件式记忆简单直接，Prompt Cache 省 67% 成本）。② 知识库密集→ OpenViking（层级检索，检索延迟 -85%，Token -83~96%）。③ 稳定性优先→ Hermes Agent（KEPA 自我进化，错误率从 8% 降至 1.2%）。④ 通用场景→ 混合方案（取各家之长）。

Q4：OpenViking 的三层分级加载（L0/L1/L2）是怎么工作的？为什么能省 83-96% Token？

三层分级：L0 = 一句话摘要（~50 tokens），L1 = 段落概述（~200 tokens），L2 = 完整文档（可能数千 tokens）。Agent 检索时先加载 L0（快速判断相关性），需要时再加载 L1（了解概要），只有确认需要细节时才加载 L2（完整内容）。90% 的检索只需要 L0/L1，避免了全文加载的 Token 浪费。生产数据：10 万+ 文档场景，平均检索延迟从 800ms 降至 120ms，因为 L0 层可以直接在内存中完成匹配，不需要全量向量搜索。

Q5：KEPA 闭环的自我进化机制是什么？为什么它能让 Agent 越用越聪明？

KEPA = Knowledge Experience Practice Assessment 闭环：(1) 失败 → Agent 执行任务出错；(2) 反思 → 分析失败原因（是知识不足、经验不足还是策略错误）；(3) 提炼 → 从失败中总结出可迁移的经验规则；(4) 复盘 → 用提炼的经验重新处理类似任务，验证有效性。闭环持续运行，Agent 的经验库不断丰富且经过验证。生产数据：金融运维场景 3 个月后，错误率从 8% 降至 1.2%，且下降趋势仍在持续。关键：不是"记住所有失败"，而是"从失败中提炼可复用经验"。

Q6：能否组合使用多个记忆系统的特性？有哪些可行的混合方案？

可以，且在生产环境中越来越常见。三种典型的混合方案：

① Claude Code + OpenViking 混合：用 Claude Code 的文件式记忆管理编码偏好和项目约定（简单确定），同时用 OpenViking 的层级虚拟 FS 管理大规模知识库文档（结构化检索）。实测效果：编码效率保持 Claude Code 水平（Prompt Cache 命中 90%+），知识库检索达到 OpenViking 水平（延迟 <130ms），月度 Token 成本约 $95（介于两者之间）。

② OpenViking + Hermes 混合：用 OpenViking 的目录结构存储知识，用 Hermes 的 KEPA 闭环自动沉淀经验到 agent/ 目录。适合"知识库 + 长期运维"场景。关键改造：将 KEPA 提炼的经验规则自动写入 agent/lessons-learned.md，并利用 OpenViking 的 L0/L1 机制进行高效检索。

③ 三者全混合：Claude Code 的 Prompt Cache（编码加速）+ OpenViking 的层级 FS（知识管理）+ Hermes 的 KEPA（经验进化）。实现复杂度最高，但效果最好。建议分阶段实施：先上 Claude Code → 文档量增大后引入 OpenViking → 需要长期稳定性时叠加 Hermes KEPA。

核心原则：混合方案不是"功能堆砌"，而是让每个系统负责其最擅长的部分——Claude Code 管编码记忆、OpenViking 管知识检索、Hermes 管经验进化。
