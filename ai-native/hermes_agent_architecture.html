核心定位与设计哲学

Hermes Agent 是 Nous Research 推出的自主式 AI Agent 系…

Hermes Agent 是 Nous Research 推出的自主式 AI Agent 系统，核心目标是让 Agent 从"被动工具"进化为"自主数字同事"。

维度设计选择为什么
运行模式独立进程，7×24 后台运行用户离线时仍可执行任务
记忆三层持久记忆跨会话积累经验，不会"失忆"
自进化KEPA 闭环 + Skill 系统从错误中学习，能力随时间增长
平台20+ 平台适配器跨平台统一接入
安全五层纵深防御金融级安全可控
Harness 的本质：Hermes 不只是调用一个模型，而是一整套围绕模型的工程约束系统——上下文管理、工具编排、权限控制、执行恢复、经验沉淀。这套系统就是 Harness，它让 Agent 在真实生产环境中稳定运行。

Agent 核心循环

Hermes 的主循环遵循经典 Agent 模式，但有几个关键设计差异：

Hermes 的主循环遵循经典 Agent 模式，但有几个关键设计差异：

阶段动作设计要点
1. Prompt 组装系统提示 + 冻结记忆 + 历史 + 用户消息10 层提示词体系，冻结快照确保一致性
2. Provider 选择根据配置选择 API 模式三种模式统一抽象不同 LLM
3. 模型调用调用 LLM 获取响应支持流式/非流式
4. 工具调度解析 tool_calls → 并发执行线程池并发，有依赖的调用串行
5. 历史管理追加本轮对话超过阈值触发压缩
6. 持久化保存会话状态到磁盘支持断点恢复

三种 API 模式

模式Provider特点
chat_completionsOpenAI / OpenRouter / Ollama标准 Chat API，兼容性最广
codex_responsesOpenAI Codex专为代码任务优化
anthropic_messagesAnthropic ClaudeMessages API，支持长上下文
核心循环设计哲学：模型调用只是循环体内的一步，而非全部。Agent 的真正价值在于 prompt 组装、工具调度、历史压缩和持久化——这些工程能力决定了 Agent 的可用性。

提示词组装体系

Hermes 采用 10 层提示词组装机制，确保每次模型调用都有一致且完整的上下文

Hermes 采用 10 层提示词组装机制，确保每次模型调用都有一致且完整的上下文。

10 层提示词结构

层级内容来源
L1系统身份与核心指令硬编码
L2工具定义与约束ToolRegistry 自动生成
L3用户偏好 (USER.md)冻结快照
L4经验教训 (MEMORY.md)冻结快照
L5激活的 Skill 内容动态加载
L6相关记忆检索结果FTS5 / Honcho
L7历史对话摘要压缩后的历史
L8当前会话消息实时
L9环境上下文（时间、平台）Gateway 注入
L10安全约束与输出格式硬编码
为什么是"冻结快照"？USER.md 和 MEMORY.md 在会话开始时被冻结，整个会话期间引用的是同一版本。这避免了"会话中途修改记忆导致上下文不一致"的问题——如果允许实时更新，模型可能基于过时记忆做出错误决策。

四层记忆架构

Hermes 的记忆系统分为四层，从瞬时到持久，从精确到语义，形成完整的"AI 大脑"

Hermes 的记忆系统分为四层，从瞬时到持久，从精确到语义，形成完整的"AI 大脑"。

层级存储容量用途访问延迟
Tier 0: 工作记忆内存 (Python dict)当前会话实时对话上下文<1ms
Tier 1: 文件记忆USER.md + MEMORY.md1375 / 2200 chars用户偏好 + 核心经验~5ms
Tier 2: 结构化存储SQLite FTS5无硬上限跨会话全文搜索~8ms
Tier 3: 外部服务Honcho / mem0 / 向量DB取决于服务语义搜索 + 高级管理~45ms

Tier 1: 文件记忆设计

文件字符上限内容写入时机
USER.md1375用户偏好、编码风格、时区用户主动设置 / 首次交互提取
MEMORY.md2200关键经验教训、项目模式任务完成后后台整理
字符上限的深意：硬上限强制模型自主决策——当记忆超限时，模型必须自己决定保留什么、遗忘什么。这迫使信息质量提升，而非无限制堆积。

上下文压缩与父子链

当会话历史过长时，Hermes 不直接覆盖，而是：

  1. 压缩旧历史为摘要
  2. 创建新会话（子会话）
  3. 记录父子关系（Session Lineage）

这确保了任务链路可追溯，且不会因压缩丢失关键决策上下文。

工具系统

Hermes 提供 70+ 内置工具，通过自注册机制和组合式推送实现灵活扩展。

ToolEntry: 工具的"厚数据模型"

字段类型说明
namestr工具唯一标识
descriptionstrLLM 可见的描述（影响是否被调用）
parametersJSON Schema参数定义（SSOT 单一数据源）
toolsetstr所属工具集（用于批量启用/禁用）
handlerasync fn实际执行函数
enabledbool运行时是否启用
visible_to_llmbool是否暴露给 LLM
requires_approvalbool执行前是否需要人工确认
timeoutint执行超时（秒）
retry_policydict失败重试策略
side_effectslist声明的副作用（文件/网络/数据库）
Schema SSOT 原则：参数定义只在一处（ToolEntry.parameters），运行时自动转换为 OpenAI/Anthropic/Ollama 各自的 function calling schema。切换 Provider 无需改代码。

AST 静态扫描安全校验

工具注册时自动分析代码：

  • 检测危险操作（直接文件删除、网络外传）
  • 检查未声明的副作用
  • 验证参数类型与使用一致性

组合式按需推送

工具不是一次性全部暴露给 LLM，而是根据上下文动态组合：

层级触发条件推送工具
基线层所有会话文件读写、终端执行、记忆管理
任务层检测到代码任务+ git 操作、代码分析、测试工具
平台层来自 Discord/Slack+ 消息发送、表情反应、线程操作
用户层根据用户偏好+ 用户常用工具

Skill vs RAG

维度SkillRAG
数据质量已验证的解决方案原始文档片段
结构标准格式（场景/步骤/陷阱）非结构化 chunk
演进有 success_count 追踪通常静态
本质程序性记忆（知道怎么做）陈述性记忆（知道什么）
Skill 是 Agent 的"程序性记忆"：类似人类骑自行车的技能 vs 读骑车手册。RAG 提供的是"读过什么"，Skill 提供的是"做过什么且成功了"。

DM 配对授权

防止未授权用户通过公共频道滥用 Agent：

  1. 用户首次 DM Agent → 生成配对码
  2. 管理员确认配对码

KEPA 自我进化闭环

KEPA = Knowledge Extraction → Evaluation → Pur…

KEPA = Knowledge Extraction → Evaluation → Purification → Application。让 Agent 从错误中持续学习。

失败 →

复盘验证 →

四阶段详解

阶段动作产出
Extraction分析失败日志，提取根因失败模式识别
Evaluation评估经验价值（≥3 次同类失败才生成规则）候选经验
Purification生成 IF-THEN 规则，影子模式验证 1 周验证通过的经验
Application正式启用，写入 MEMORY.md 或 Skill可复用知识

生产验证数据

指标初始值3 个月后改善
错误率8%1.2%↓85%
经验规则数0450+覆盖 95% 常见场景
选择性遗忘触发—23 次质量评分 3.1→4.6/5
KEPA 的核心洞见：价值不在于"记住所有失败"，而在于"从失败中提炼可复用经验"。字符硬上限强制执行选择性遗忘，反而提升了记忆质量。

五层纵深防御体系

金融级安全保障：输入过滤 → 权限控制 → 沙箱执行 → 输出审查 → 人工审批

金融级安全保障：输入过滤 → 权限控制 → 沙箱执行 → 输出审查 → 人工审批。

层级防御机制
L1输入过滤恶意 Prompt 拦截（正则 + 语义检测）
L2权限控制工具调用鉴权（基于用户角色）
L3沙箱执行隔离环境运行（Docker/SSH/Singularity）
L4输出审查敏感信息过滤（PII/密钥/内部路径）
L5人工审批高风险操作默认需要确认

级联中断与心跳机制

当 Agent 执行长时间任务时：

  • 心跳：定期向 Gateway 报告存活状态
  • 级联中断：用户可随时中断，中断信号从 Gateway → Agent 主循环 → 当前工具执行
  • 优雅退出：保存当前进度到断点，下次可恢复
五层防御的生产效果：上线 3 个月拦截 1200+ 次异常操作，89 次 Prompt Injection 尝试成功率 100%。

Hermes vs OpenClaw

维度Hermes AgentOpenClaw

Do / Don't

  • 让 Agent 经历沉淀为经验（KEPA 闭环）
  • 字符硬上限强制选择性遗忘
  • 冻结快照确保会话期间记忆一致性
  • 组合式工具推送避免 LLM 注意力稀释
  • 五层纵深防御确保金融级安全
  • Skill 需 ≥3 次成功验证才正式启用
  • DM Pairing 确保多平台身份安全
  • 把 Agent 当一次性工具（忽视经验沉淀）
  • 让 Agent 无限积累不遗忘（质量下降）
  • 允许会话中途修改记忆（上下文不一致）
  • 一次性暴露所有工具（稀释注意力）
  • 高风险操作无人工审批
  • 小样本就生成经验规则（≥3 次才可靠）
  • 忽视 Token 预算管理（成本可失控）

Q&A

三个本质区别：① 运行模式 ：Copilot 嵌入编辑器随用户会话启停，Hermes 是独立…
Q1: Hermes Agent 与 IDE Copilot 的核心区别是什么？

三个本质区别：①运行模式：Copilot 嵌入编辑器随用户会话启停，Hermes 是独立进程 7×24 后台运行；②记忆持久性：Copilot 仅有当前会话上下文，Hermes 拥有四层持久记忆可跨会话积累；③自进化：Copilot 不会学习，Hermes 通过 KEPA 闭环持续进化。本质上 Copilot 是"被动工具"，Hermes 是"自主 Agent"。

Q2: 为什么记忆要分层设计？不用统一向量数据库？

四层各有分工：Tier 0（内存）保证实时对话零延迟；Tier 1（文件）控制 token 成本；Tier 2（FTS5）对结构化经验关键词匹配比语义更可靠；Tier 3（向量 DB）留给复杂语义场景。分层平衡了成本、精度和能力。

Q3: KEPA 闭环如何避免提炼出错误经验？

三重保障：①样本量：需 ≥3 次同类失败才生成规则（避免小样本偏差）；②影子模式：新规则上线前只记录不执行，观察 1 周确认无误；③定期审计：每月检查规则触发效果，错误率 >5% 的规则自动下线。

Q4: 字符硬上限为什么能提升记忆质量？

超限时模型必须自主决策保留什么、遗忘什么。这迫使"主动选择性遗忘"，而非无限制堆积。结果是保留的信息都是真正有价值的，生产数据显示遗忘后质量评分从 3.1→4.6/5。

Q5: 工具系统的 Schema SSOT 是什么？

参数定义只在 ToolEntry.parameters 一处维护，运行时自动转换为 OpenAI/Anthropic/Ollama 各自的 function calling schema。切换 Provider 无需改代码，避免多处定义导致的不一致。

Q6: 什么是 Harness？

Harness 不只是"调用模型"，而是围绕模型的一整套工程约束系统——上下文管理、工具编排、权限控制、执行恢复、经验沉淀。它让 Agent 在真实生产环境中稳定运行，而非仅仅是一个 LLM wrapper。
