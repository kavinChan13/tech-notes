01

概率引擎本质：训练目标从未包含"事实性"

要理解幻觉为什么不可消除，必须先理解 自回归生成 的本质
大模型的训练目标只有一个——预测下一个 token。它从未学习过"事实"与"虚构"的区分标准。输出的每一句话，本质上都是权重空间中概率分布的采样结果。

要理解幻觉为什么不可消除，必须先理解自回归生成的本质。GPT 类模型在每一步做的事情是：根据前文所有 token，计算下一个 token 的概率分布，然后从中采样。这个过程不包含任何"事实校验"环节。

大模型生成过程（单步视角）
用户输入: "爱因斯坦获得诺贝尔奖的年份是"
数十亿参数协同计算
输出 token 概率分布: · "1921" → 34% · "1922" → 18% · "1905" → 12% · "1925" → 8% ← 看起来合理 · ... · 无"事实校验"层
采样输出: "1921年" (正确) 或 "1925年" (幻觉)
模型自己无法区分两者

知识存储方式：分布式参数，非结构化数据库

大模型的知识以分布式参数方式存储——数十亿个参数协同编码信息，没有任何参数专门负责"存储"某个特定事实。这意味着无法像查询数据库那样精确定位和验证某条知识。

维度数据库查询大模型生成
知识存储结构化记录，精确索引分布式参数，模糊编码
检索方式精确匹配 / SQL 查询概率采样，无确定性保证
错误类型查不到返回空查不到则"编造"流畅替代
一致性ACID 事务保证同一问题多次回答可能不同
更新机制UPDATE / DELETE 语句需重新训练或微调

暴露偏差：训练与推理的系统性错配

Teacher Forcing 训练策略是幻觉的另一个隐性来源。在训练阶段，模型每一步看到的都是"正确答案"的前缀；但在推理时，模型需要基于自己之前生成的（可能错误的）token 继续预测。一旦早期某个 token 出错，后续生成就会基于错误前提继续偏移——这种训练-推理错配被称为暴露偏差（Exposure Bias），它使错误像滚雪球一样在长文本生成中不断放大。

阶段输入来源错误传播影响范围
训练（Teacher Forcing）真实标签的前缀每步独立，不传播单步
推理（自回归）模型自身生成的前缀一步错→步步偏移累积到末尾

这就是为什么模型在长文本生成中越到后面越容易"跑题"——不是因为后面更难，而是因为累积的错误越来越多。暴露偏差与注意力散光叠加，使长上下文成为幻觉的高发区。

理论证明（arXiv:2401.11817）：在有限容量的模型上，幻觉不可能被完全消除。任何可计算枚举的模型集合都无法在所有可计算查询上做到零幻觉。这不是工程能力问题，而是信息论层面的根本限制。但概率可以被持续降低——改进算法、改进数据、改进系统架构，都能将幻觉率压缩到更低水平。
02

六大根因深度拆解

幻觉不是单一原因造成的，它贯穿模型的训练数据、架构设计、对齐流程、推理过程的全生命周期

幻觉不是单一原因造成的，它贯穿模型的训练数据、架构设计、对齐流程、推理过程的全生命周期。以下六大根因从不同角度解释了"为什么大模型会编造事实"。

根因① 训练目标错位——无事实性监督

交叉熵损失只度量模型预测的 token 与训练数据中实际 token 的概率差距，不度量预测内容的"事实正确性"。模型在训练时学到的是"什么样的文本分布最像训练数据"，而不是"什么样的回答最符合事实"。当面对训练数据中低频或未覆盖的事实时，模型会基于概率外推——这就是幻觉的起点。

根因② 分布式知识存储——无法精准定位

知识分布在整个模型的参数矩阵中，没有"知识卡片"式的独立存储单元。当模型需要回忆"张三的电话号码"时，它不是在查表，而是在做一次概率推断。对于低频事实（只有少量训练样本提及的信息），参数中的编码信号极弱，模型极易给出错误但流畅的回答。

根因③ 无元认知能力——不知道自己不知道

人类具备元认知（Metacognition）能力：能判断自己是否真的知道某件事。大模型不具备这种能力。它对"确定知道"和"完全不知道"的问题，可能给出同样自信的回答。在 2025 年的多项评测中，主流前沿模型在"不知道答案时主动承认不知道"的能力上，得分普遍低于 40%。

根因④ 注意力散光——长文本碎片拼凑

注意力机制在长文本场景下出现"散光"效应：模型无法集中注意力于关键片段，而是分散地关注多个不相关位置。结果是把不同段落的信息碎片拼凑在一起，形成一个"逻辑通顺但事实错误"的回答。这是长上下文幻觉的核心机制。

根因⑤ 知识压缩极限——低频细节被舍弃

有限参数需要压缩海量知识。就像一个只有 100 页笔记本的学生要记住 1000 本教科书，高频出现的核心知识被精确记住，低频的细枝末节（具体数字、罕见人名、小众 API 参数）则在压缩中被"模糊化"或"替换"。

根因⑥ 对齐训练偏差——RLHF 惩罚"我不知道"

RLHF（基于人类反馈的强化学习）在对齐阶段会惩罚"拒绝回答"的行为——人类标注者倾向于给"有回答"更高的分数。这导致模型在对齐后学会了"宁可编造也不拒答"的策略。研究显示，经过 RLHF 后模型拒答率下降约 60%，但幻觉率反而上升了 15-25%。

根因阶段核心矛盾严重程度
训练目标错位预训练损失函数不含事实性监督根本性
分布式知识存储预训练知识编码模糊，无法精确定位结构性
无元认知能力推理无法判断自身知识的边界架构性
注意力散光推理长文本注意力权重过度分散场景性

六大根因之间的关系并非并列，而是层级递进的：训练目标错位是"根因之根因"——正因为损失函数不包含事实性，分布式存储才成为问题（如果有精确索引就不怕模糊编码），知识压缩才成为问题（如果有外部存储就不需要压缩）。对齐偏差则是"雪上加霜"——在本就不可靠的概率引擎上，还惩罚了诚实拒答行为。
六大根因横跨模型的全生命周期：预训练阶段（训练目标、知识存储、压缩极限）、对齐阶段（RLHF 偏差）、推理阶段（元认知缺失、注意力散光）。防御策略也必须对应分层设计，任何单点方案都只能解决部分问题。理解这一点，就能理解为什么"只加 RAG"或"只加 CoT"永远不够——每一层防御只能缓解部分根因，只有纵深防御才能系统性控制幻觉率。

三层工程防御体系：RAG + CoT + 置信度校验

防御幻觉的核心思路不是"让模型更聪明"，而是通过系统设计来约束概率引擎的输出边界

防御幻觉的核心思路不是"让模型更聪明"，而是通过系统设计来约束概率引擎的输出边界。三层防御分别对应：输入层（给模型正确的知识）、生成层（约束推理过程）、输出层（拦截不可信结果）。

第一层：RAG 切断虚构补全链

RAG（检索增强生成）的核心防御逻辑是：在模型生成前，先从外挂知识库检索相关事实并注入上下文，让模型的回答有据可依。关键不在于"接入了知识库"，而在于"检索到的文档是否真正相关、是否覆盖关键事实、是否时效正确"。

生产数据：配备良好 RAG 的系统可将幻觉率降低约 50%。但法律 AI 工具即使使用 RAG，幻觉率仍有 17-33%（2025 年评测数据），说明 RAG 是必要非充分条件。

第二层：CoT 截断误差累积

CoT（思维链）强制模型将复杂问题拆解为多个子步骤，每步基于上一步结论和检索证据进行推理。核心作用是将"一步到位的概率跳跃"变为"分步的概率传递"，使误差在单步内可检测、可截断，而非跨步骤不可控地累积。

第三层：置信度校验

通过监控模型输出的置信度（confidence score）来拦截不可信结果。核心技术包括：

  • Token 级熵值监控：当模型在关键 token 上的概率分布过于平坦（高熵），说明模型不确定，应触发外部搜索或拒答
  • 期望校准误差（ECE）：度量模型"自认为对的概率"与"实际正确率"的差距。ECE 越小说明模型越"诚实"
  • NLI 一致性校验：用自然语言推理模型判断回答与检索证据之间是否存在矛盾

置信度校验与系统闭环

期望校准误差 （Expected Calibration Error, ECE）是衡量模型"…
信任转移的核心：从"信任模型能力"转向"信任系统设计"。不是期望模型永远不犯错，而是设计一个系统，在模型犯错时能够检测、拦截、纠正。

核心原则：承认概率引擎的局限性。幻觉不可能被消除，但可以被管理。工程团队需要建立的不是"零幻觉"的幻想，而是一个"幻觉可控、错误可追溯、修复可闭环"的系统。

ECE 校准与拒答策略的联动

期望校准误差（Expected Calibration Error, ECE）是衡量模型"自信程度"与"实际正确率"匹配度的关键指标。一个完美校准的模型，当它说"80% 确定"时，应该确实有 80% 的概率正确。主流模型在未经校准时 ECE 可达 0.15-0.30，经过温度缩放或 Platt Scaling 后可降至 0.03-0.08。

拒答策略的设计本质是找到最优阈值：阈值过低会导致过多正确回答被拦截（伤害可用性），阈值过高会让错误回答泄漏（伤害可靠性）。生产系统的典型做法是按业务风险分级设置不同阈值——金融场景阈值设为 0.85，一般问答设为 0.65。

多信号融合：单一校验手段的局限

生产系统通常不依赖单一校验信号，而是融合多个信号做综合判断。例如：Token 概率低 + 语义熵高 + NLI 矛盾 = 高幻觉风险（强拦截）；Token 概率低但语义熵低 + NLI 一致 = 低风险（允许输出但标记抽检）。多信号融合可以显著降低误拦截率——单信号系统的误拦截率通常在 15-25%，融合后可降至 5-8%。

生产案例与防御实战

背景： 某银行智能客服用于回答信用卡费率、还款规则、申请条件等问题

案例一：金融客服系统的幻觉防御改造

背景：某银行智能客服用于回答信用卡费率、还款规则、申请条件等问题。知识来源是多个部门维护的产品文档和制度文件。

问题：上线初期只有简单 RAG（向量检索 Top-5），模型在回答"信用卡分期利率"时，将不同产品的利率混在一起生成"平均值"。抽检发现高风险事实错误率 8.3%，其中 60% 来自检索到了过期文档。

改造方案：

  • RAG 层：增加文档版本号与生效时间过滤，检索结果按时间倒序取最新
  • 生成层：CoT 强制要求模型先引用产品编号和费率表，再基于引用回答
  • 校验层：金额和百分比字段增加正则校验，NLI 模型检测回答与检索文档的蕴含关系
  • 运营层：高风险问题（涉及金额、期限、资格条件）自动转人工复核

效果：高风险错误率从 8.3% 降至 0.6%，引用覆盖率从 35% 提升至 94%，人工接管率从 5% 提高到 11%（可接受范围内）。

各层防御对不同幻觉类型的覆盖

幻觉类型RAG 层CoT 层置信度校验层综合效果
事实性幻觉强（提供事实锚点）中（分步验证）强（拦截低置信输出）降低 ~70%
忠实性幻觉中（提供上下文）强（强制引用绑定）强（NLI 比对）降低 ~65%
逻辑性幻觉弱强（分步可审计）中（自一致性）降低 ~50%
引用性幻觉强（引用验证）中中（规则校验）降低 ~60%
内部矛盾弱中（步骤间一致性）强（自一致性检测）降低 ~55%

没有任何单层防御能覆盖所有幻觉类型。三层联合部署时，各层互为补充：RAG 提供事实锚点，CoT 约束推理结构，置信度校验做最后拦截。这种纵深防御（Defense-in-Depth）策略是生产系统的基本范式。

2024 年 arXiv（2401
为什么幻觉从理论上不可能被完全消除？

2024 年 arXiv（2401.11817）的形式化证明指出：任何有限容量的模型在面对不可压缩或长尾事实时，必然产生不可约的错误。大模型的知识以分布式参数存储，无法像数据库那样精确定位和验证每条事实。概率采样的本质决定了模型永远在"基于统计模式猜测"而非"基于事实查询回答"。工程能做的不是消灭幻觉，而是将其控制在业务可接受的阈值内。

RAG 为什么不能单独解决幻觉问题？

RAG 只解决了"知识缺失"这一种幻觉来源。但幻觉还可能来自：检索到不相关的文档（检索质量问题）、检索到过期文档（时效问题）、模型忽视检索到的上下文（忠实性问题）、总结时曲解原文（摘要偏差）。实测数据：法律 AI 工具即使使用 RAG，幻觉率仍有 17-33%。RAG 是必要基础，但非充分方案。

CoT 思维链如何截断幻觉的误差累积？

CoT 将复杂推理拆解为多个子步骤，每步只做一个小推断。如果某一步出错，错误只影响后续步骤，不会像"一步到位"那样让错误渗透到整个推理链。更关键的是，CoT 的每步输出是可检查的——系统可以在每步之后验证中间结论是否与检索证据一致，发现不一致时截断并重新推理。这本质上是把"黑盒一步输出"变成了"白盒分步可审计"。

置信度校验中 ECE 指标为什么比单纯的准确率更重要？

准确率只告诉你"模型答对了多少"，而 ECE（期望校准误差）告诉你"模型是否知道自己什么时候会答错"。一个准确率 85% 但 ECE 很高（如 0.25）的模型，意味着它对答对和答错的题目给出了相似的置信度——你无法通过置信度来区分对错。而一个 ECE 很低（如 0.05）的模型，当它说"我很确定"时确实大概率正确，说"我不确定"时确实大概率错误，你可以据此设计拒答策略。

RLHF 对齐训练为什么会加剧幻觉？

RLHF 阶段的人类标注者天然偏好"有回答"而非"拒答"。当模型说"我不知道"时，标注者倾向给低分；当模型给出一个流畅自信的回答时（即使是编造的），标注者可能给高分。这导致模型在对齐后学会了"宁可编造也不承认不知道"的策略。研究数据显示，RLHF 后模型拒答率下降约 60%，但幻觉率上升 15-25%。缓解方式是在 RLHF 训练中明确奖励"诚实拒答"行为。

生产系统中幻觉防御的分层阈值应该怎么设置？

按业务风险分三档：高风险场景（金融费率、医疗建议、法律条款）置信度阈值设为 0.85 以上，低于阈值一律拒答转人工；中风险场景（一般知识问答、文档摘要）阈值设为 0.65-0.85，低于阈值触发二次检索后重新生成；低风险场景（闲聊、创意写作）阈值设为 0.45-0.65，允许更积极的回答。同时需要持续监控各档位的幻觉率和拒答率，动态调整阈值以平衡可用性和可靠性。

语义熵检测与 Token 级熵值监控有什么区别？

Token 级熵值监控关注单个 token 的概率分布——如果模型在生成某个词时概率分布过于平坦（高熵），说明它在"猜"。但这种方法对"高置信度幻觉"无效——模型有时对错误答案也非常确定。语义熵检测则从更高层面入手：对同一问题生成多个回答，然后判断这些回答在语义上是否一致。如果多次生成的回答表达了不同的意思（语义变异大），说明模型在这类问题上不稳定。两者互补使用效果最佳。
