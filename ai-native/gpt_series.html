① GPT-1 — 无监督预训练 + 有监督微调

2018 · OpenAI 117M 参数

2018 · OpenAI117M 参数

核心思想

GPT-1 首次证明了 "无监督预训练 → 有监督微调" 这一两阶段范式（Pretrain-then-Finetune）的有效性。在大量无标注文本上做语言建模预训练，再在下游任务上做少量标注微调，即可取得 SOTA 结果。

架构与训练

  • 12 层 Transformer Decoder（单向自注意力），768 维隐藏层，12 个注意力头
  • 训练数据：BooksCorpus（约 7000 本书，~5GB 文本）
  • 预训练目标：标准的自回归语言建模（Causal LM），最大化 P(wₜ | w₁…wₜ₋₁)
  • 微调时在输入前后加特殊 token，把分类 / NLI / 相似度等任务统一为序列形式

关键贡献

  • 验证了 Transformer 在 NLP 预训练中的潜力（此前主流是 LSTM）
  • 奠定了后续 GPT 系列"先预训练再微调"的基本路线
  • 在 9/12 个 NLP 基准上超越专门设计的模型

💡 知识要点

  • GPT-1 = Transformer Decoder + 两阶段范式；与 BERT 同年但思路不同
  • 为什么选 Decoder-Only？自回归更天然适合文本生成，且预训练目标与下游生成任务一致
  • BooksCorpus 的局限：数据量小、领域单一，限制了模型泛化能力

② GPT-2 — Zero-Shot 多任务学习

2019 · OpenAI 1

2019 · OpenAI1.5B 参数

核心论文

"Language Models are Unsupervised Multitask Learners" — 核心洞见：足够大的语言模型本身就是一个隐式的多任务学习器，无需微调即可 Zero-Shot 完成翻译、摘要、问答等任务。

关键升级

  • 参数量从 117M 扩展到 1.5B（约 12.8× 增长）
  • 训练数据：WebText（Reddit 高赞链接爬取，~40GB），数据质量远超 BooksCorpus
  • 48 层 Transformer Decoder，1600 维隐藏层
  • 使用 BPE（Byte Pair Encoding）分词，词表 50257

重要发现

  • Zero-Shot 能力：不做任何微调，纯靠 Prompt 就能完成多种任务
  • Scaling 初现端倪：更大模型 + 更多数据 = 更强的泛化能力
  • 引发"AI 安全"讨论，OpenAI 曾因担忧滥用而延迟发布完整模型

💡 知识要点

  • GPT-2 的核心贡献是证明了 Zero-Shot 的可行性，而非模型架构创新
  • 从 GPT-1 到 GPT-2 的变化：取消微调 → 用 Prompt 驱动任务
  • WebText 数据策略：用 Reddit karma 做隐式质量过滤

③ GPT-3 — In-Context Learning 与 Prompt 范式

2020 · OpenAI 175B 参数

2020 · OpenAI175B 参数

规模跃迁

  • 参数量达到 175B（GPT-2 的 ~117 倍），96 层，12288 维隐藏层
  • 训练数据：混合语料（Common Crawl 过滤 + WebText2 + Books + Wikipedia），约 300B tokens
  • 训练成本估计：数百万美元级别

In-Context Learning（ICL）

GPT-3 最重要的贡献 — 不更新模型权重，仅通过在 Prompt 中提供少量示例，模型即可"学会"新任务：

  • Zero-Shot：仅给任务描述
  • One-Shot：给一个示例
  • Few-Shot：给 2~数十个示例
Task Description + [Example₁, Example₂, …] + Query → Model Output

涌现能力（Emergent Abilities）

  • 模型规模超过某一阈值后突然出现的能力：算术推理、代码生成、多步逻辑等
  • 该现象在后续 Scaling Laws 研究中被深入讨论

Prompt 范式的开端

GPT-3 标志着 NLP 从"Pre-train + Fine-tune"范式转向"Pre-train + Prompt"范式，开启了 Prompt Engineering 时代。

💡 知识要点

  • ICL 的本质：不更新参数，利用注意力机制在推理时动态"学习"示例中的模式
  • ICL 为什么有效？假说包括：隐式贝叶斯推断、任务向量形成、注意力头的 induction head 机制
  • 涌现能力的争议：是真正的"涌现"还是评估指标造成的假象？
  • GPT-3 的局限：容易胡说八道（hallucination）、无法遵循复杂指令、安全性差

④ InstructGPT — RLHF 与人类对齐

2022 · OpenAI 基于 GPT-3 (1

2022 · OpenAI基于 GPT-3 (1.3B/6B/175B)

核心动机

GPT-3 虽然能力强大，但经常生成不符合用户意图的内容（有害、不真实、不相关）。InstructGPT 的目标是让模型遵循指令并与人类偏好对齐。

RLHF 三阶段训练

  1. SFT（Supervised Fine-Tuning）：收集人类标注者编写的高质量 Prompt-Response 对，对 GPT-3 进行有监督微调
  2. RM（Reward Model）训练：对同一 Prompt 的多个模型输出，让标注者排序；用排序数据训练一个奖励模型来预测人类偏好
  3. PPO（Proximal Policy Optimization）：用 RM 作为奖励信号，通过 PPO 算法优化语言模型策略，同时用 KL 散度约束防止模型偏离太远
SFT Model → RM(ranking data) → PPO(policy = SFT model, reward = RM, KL penalty)

关键成果

  • 1.3B 的 InstructGPT 在人类评估中优于 175B 的 GPT-3
  • "对齐税"（Alignment Tax）很小：对齐后模型在标准 NLP 基准上性能损失有限
  • 直接奠定了 ChatGPT 的技术基础

💡 知识要点

  • RLHF 三阶段必须能完整描述：SFT → RM → PPO，每一步的输入输出是什么
  • RM 训练用的是 pairwise ranking loss（Bradley-Terry 模型），不是直接的回归
  • PPO 中的 KL 约束作用：防止 reward hacking，保持模型语言能力
  • RLHF 的替代方案：DPO（Direct Preference Optimization）直接用偏好数据优化策略，跳过 RM

⑤ GPT-4 — 多模态与更强推理

2023 · OpenAI 参数量未公开（传闻 MoE ~1

2023 · OpenAI参数量未公开（传闻 MoE ~1.8T）

核心能力升级

  • 多模态输入：支持图像 + 文本输入（GPT-4V），能理解图表、照片、手绘草图等
  • 更强推理：在 SAT、GRE、律师资格考试等专业考试中表现接近或超过人类
  • 上下文长度扩展：8K → 32K → 128K tokens
  • 更好的指令遵循和安全对齐

MoE 架构传闻

  • 传闻 GPT-4 使用 Mixture of Experts（MoE） 架构：~16 个专家，每次推理激活 ~2 个
  • 总参数 ~1.8T，但每次推理实际使用 ~220B 参数
  • MoE 的优势：以更低的推理成本获得更大模型的能力

安全对齐改进

  • 引入 RBRM（Rule-Based Reward Model） 辅助安全评估
  • 更严格的 Red Teaming 流程
  • System Prompt 层面的行为控制（System Message 优先级更高）

💡 知识要点

  • MoE 原理：每个 token 由 Router 选择 Top-K 个专家处理，稀疏激活降低计算量
  • MoE 训练挑战：负载均衡（Load Balancing Loss）、专家坍缩、通信开销
  • 多模态实现：Visual Encoder（如 ViT）编码图像 → 映射到 LLM 的 token 空间
  • GPT-4 vs GPT-3.5：推理能力质变、幻觉率降低、指令遵循更精准

⑥ o1 / o3 推理模型 — 思考再回答

2024-2025 · OpenAI 推理时计算范式

2024-2025 · OpenAI推理时计算范式

核心理念

传统 LLM 是"快思考"（System 1）：一次前向传播直接输出。o1/o3 系列引入"慢思考"（System 2）：在回答前进行内部的 Chain-of-Thought 推理，花更多推理时间换取更高准确率。

Chain-of-Thought 内化

  • 不再依赖用户在 Prompt 中写"Let's think step by step"
  • 模型内部自动生成推理链（hidden chain-of-thought），然后给出最终答案
  • 通过 RL 训练让模型学会"何时思考"以及"如何思考"

Test-time Compute Scaling

传统 Scaling Laws 关注训练时计算量（模型更大、数据更多）。o1/o3 开辟了新维度：

  • Test-time Scaling：推理时投入更多计算 → 更好的结果
  • 具体方式：更长的思考链、多次采样后投票（Best-of-N）、树搜索
  • 与 AlphaGo 的 MCTS 思路类似：推理时搜索 + 评估

推理模型 vs 生成模型

  • 生成模型（GPT-4）：擅长创意写作、对话、翻译等流畅生成任务
  • 推理模型（o1/o3）：擅长数学证明、代码竞赛、科学推理等需要多步逻辑的任务
  • 未来趋势：两种能力融合，按需动态分配推理预算

💡 知识要点

  • Test-time Compute Scaling 的本质：用推理时的额外计算换取准确性
  • 与传统 CoT Prompting 的区别：o1 的推理链是训练出来的内在能力，而非外部提示
  • 训练方法：大规模 RL（据传使用改进的 PPO/GRPO），奖励来自可验证任务的正确性
  • 局限：推理成本高、延迟大、对简单任务"过度思考"反而浪费资源

⑦ Decoder-Only 架构为什么胜出？

三种 Transformer 架构对比

维度Encoder-Only (BERT)Encoder-Decoder (T5)Decoder-Only (GPT)
注意力双向（Bidirectional）编码器双向 + 解码器单向单向（Causal）
预训练目标MLM（掩码语言模型）Span Corruption自回归 LM（Next Token Prediction）
代表模型BERT, RoBERTaT5, BARTGPT 系列, LLaMA, Claude
擅长任务理解（分类、NER）Seq2Seq（翻译、摘要）生成 + 理解（通用）
Scaling 表现增益递减中等持续提升

Decoder-Only 胜出的原因

  1. 自回归天然适合生成：Next Token Prediction 目标与实际使用场景（对话、写作、代码）一致
  2. Scaling 优势：Chinchilla / Kaplan Scaling Laws 表明，Decoder-Only 在相同 FLOPs 下持续受益于参数增长
  3. 训练效率高：每个 token 都参与损失计算（BERT 的 MLM 只用 15% 的 token）
  4. 架构简洁：只有一个统一的 Decoder 栈，工程实现和分布式训练更简单
  5. 统一范式：所有任务都可以表述为"给定前缀，生成续写"，无需针对不同任务设计不同的输入格式
  6. ICL 天然适配：自回归的序列处理方式让 Few-Shot / In-Context Learning 自然落地

BERT 为什么"输"了？

  • MLM 目标与生成不匹配：BERT 学的是"填空"，不是"续写"
  • 双向注意力无法直接做自回归生成
  • 在理解任务上 BERT 仍然优秀，但 LLM 时代生成能力更受重视
  • BERT 在工业界的嵌入（Embedding）和分类场景仍广泛使用

💡 知识要点

  • Causal LM vs MLM：训练目标如何影响模型能力
  • 为什么 Encoder-Decoder 没有胜出？多了一倍参数但 Scaling 性价比不如纯 Decoder
  • prefix LM（如 GLM）是一种折中，同一 Decoder 中部分 token 做双向注意力
  • Scaling Laws（Kaplan 2020 / Chinchilla 2022）的核心结论：计算最优时参数量与数据量应同步增长

Q1：GPT-1 与 BERT 的核心区别是什么？

架构方向：GPT-1 使用单向 Transformer Decoder（Causal Attention），BERT 使用双向 Transformer Encoder（Full Attention）。

预训练目标：GPT-1 做自回归语言建模（预测下一个 token），BERT 做掩码语言建模（MLM，预测被遮盖的 token）。

适用场景：GPT 更适合生成任务，BERT 更适合理解/分类任务。两者发布时间接近（2018年），但后续发展证明 Decoder-Only 在大规模 Scaling 下更有优势。

Q2：GPT-3 的 In-Context Learning 为什么有效？

目前有几种解释假说：

1. 隐式贝叶斯推断：模型在预训练中见过大量"示例→答案"模式，ICL 本质上是在做后验推断，用 Prompt 中的示例来"定位"预训练中学到的合适的潜在概念。

2. Induction Heads 机制（Olsson et al., 2022）：Transformer 中特定的注意力头可以做"模式匹配与复制"，即识别上文中的 [A][B]…[A] 模式，预测下一个 token 为 [B]。

3. 任务向量形成：示例在模型内部形成了一个隐式的"任务表示"，引导后续的生成方向。

关键点：ICL 不更新权重，所有"学习"发生在前向传播的注意力计算中。

Q3：RLHF 中的 Reward Model 是怎么训练的？

数据收集：给定同一个 Prompt，让 SFT 模型生成 K 个不同回答（通常 K=4~9），人类标注者对这些回答进行偏好排序。

损失函数：使用 Bradley-Terry 模型，将排序转化为 pairwise 比较。对于一对 (chosen, rejected)：

Loss = -log(σ(r(chosen) - r(rejected)))

其中 r(·) 是 RM 输出的标量分数，σ 是 sigmoid 函数。一组 K 个回答的排序可以产生 C(K,2) 个训练对。

RM 架构：通常是去掉最后一层的 LLM + 一个线性投影层，输出标量分数。

Q4：PPO 在 RLHF 中具体怎么用的？

角色分配：

  • Policy（策略）= 当前要优化的 LLM
  • Reference Model = 冻结的 SFT 模型（用于 KL 约束）
  • Reward Model = 训练好的 RM（提供奖励信号）
  • Value Model = 估计状态价值（用于计算 Advantage）

优化目标：最大化 RM 给出的奖励，同时最小化与 Reference Model 的 KL 散度。

Objective = E[R(x,y)] - β·KL(π_θ || π_ref)

PPO 的 clip 机制限制每次更新幅度，保证训练稳定性。β 控制 KL 惩罚强度。

Q5：DPO 与 RLHF 有什么区别？

RLHF：先训练一个 Reward Model，再用 RL（PPO）优化策略模型。两阶段流程，训练复杂。

DPO（Direct Preference Optimization）：数学上证明可以将 RM + RL 的优化目标改写为直接基于偏好数据的损失函数，跳过 RM 训练步骤：

L_DPO = -log σ(β · (log π(y_w|x)/π_ref(y_w|x) - log π(y_l|x)/π_ref(y_l|x)))

DPO 优势：实现简单、训练稳定、无需 RL 的超参调优。
DPO 劣势：对偏好数据分布敏感、可能存在过拟合风险、缺少显式 RM 做持续评估。

Q6：为什么 Decoder-Only 在 Scaling 上比 Encoder-Only 更有优势？

1. 训练效率：自回归 LM 中每个 token 都参与损失计算，而 BERT 的 MLM 每次只计算 15% 被掩码的 token，等效训练效率低。

2. Scaling Laws 验证：Kaplan et al. (2020) 的实验表明 Decoder-Only 模型在跨多个数量级的参数范围内表现出稳定的幂律关系，性能持续提升且无明显拐点。

3. 统一的任务接口：所有下游任务都可以表述为续写问题，Scaling 带来的通用能力可以无缝迁移到各类任务。而 Encoder-Only 的双向注意力在生成任务上有先天限制。

4. KV Cache 友好：Causal Attention 支持高效的 KV Cache，推理时逐 token 生成只需计算新增 token 的注意力，大幅降低推理成本。

Q7：GPT-4 传闻中的 MoE 架构有什么优势和挑战？

优势：

  • 总参数量大（知识容量高），但每次推理只激活一小部分专家（计算成本低）
  • 不同专家可以专精不同领域/技能，形成隐式的"分工"
  • 在相同的推理 FLOPs 下能达到更高的模型质量

挑战：

  • 负载均衡：如果 Router 总是选同几个专家，其他专家浪费 → 需要 Auxiliary Load Balancing Loss
  • 专家坍缩：多个专家学到相同的东西，失去多样性
  • 通信开销：MoE 层需要 All-to-All 通信，分布式训练中带宽要求高
  • 显存占用：虽然推理时只用部分专家，但所有专家的权重都需要加载到内存中
Q8：o1 的 Test-time Compute Scaling 具体是怎么实现的？

Test-time Compute Scaling 的核心思路是在推理阶段投入更多计算来换取更好的结果。具体实现包括：

  • 内化的 Chain-of-Thought：模型在输出最终答案前，生成（可能隐藏的）推理链，相当于在推理时做更多"计算"
  • Best-of-N 采样：生成多个候选答案，用 RM 或 Verifier 选出最好的
  • 树搜索/Beam Search 变体：在推理链的中间步骤进行分支和评估
  • 自我验证/反思：模型检查自己的推理过程，发现错误后回溯修正

训练上，o1 据报道使用了大规模 RL，在数学、代码等有客观答案的任务上，利用结果正确性作为奖励信号来强化模型的推理能力。

Q9：Scaling Laws 的核心结论是什么？

Kaplan et al. (2020)：模型性能（Loss）与参数量 N、数据量 D、计算量 C 之间存在幂律关系。在固定计算预算下，应优先增加模型参数量。

Chinchilla (Hoffmann et al., 2022)：修正了 Kaplan 的结论 — 参数量和数据量应同步等比增长。即：

最优配比 ≈ 20 tokens / parameter

这意味着许多模型（如 GPT-3, LLaMA-1）训练时数据量不足（under-trained）。后续的 LLaMA-2/3 等模型大幅增加了训练 token 数，印证了 Chinchilla 的结论。

实际影响：Chinchilla Scaling 推动了"小模型 + 更多数据"的趋势（如 LLaMA-7B 用 1T tokens），在推理效率和性能之间取得更好平衡。

Q10：GPT 系列未来的发展方向有哪些？

1. 推理能力深化：从 o1/o3 开始的 Test-time Scaling 路线将继续发展，模型将具备更强的多步推理、规划和自我纠错能力。

2. 原生多模态：GPT-4o 开启了真正的原生多模态（文本/图像/音频/视频统一处理），未来模型将具备更自然的跨模态理解和生成能力。

3. Agent 化：从被动问答到主动执行 — 模型将能调用工具、浏览网页、写代码并运行，成为真正的 AI Agent。

4. 更高效的对齐：从 RLHF 到 DPO 到 RLAIF（AI 反馈的 RL），对齐方法将更高效、更可扩展。

5. 长上下文与记忆：上下文窗口持续扩展（百万级 tokens），结合外部记忆机制实现"无限上下文"。

6. 开源 vs 闭源竞争：Meta LLaMA、Mistral 等开源模型持续追赶，推动整个生态发展。
