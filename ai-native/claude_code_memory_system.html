Claude Code 记忆系统

Memory System Design — 后台子 Agent 自动提取记忆的四个关键设计

AI 工程 阅读 ~5 min 8 章
00

概览

核心问题：靠用户手动触发记忆，大部分值得记的都会漏掉。Claude Code 的解法是后台子 Agent 自动提取——对话结束后启动独立子 Agent，回顾对话判断值得保存的信息，写入记忆文件。
01

为什么不能靠用户手动触发？

结论： 好的记忆生产不靠用户手动触发，靠后台自动提取
维度用户注意力记忆需求
焦点当前任务偏好/纠正/经验
时机不会时刻想着保存对话中随时产生
结果注意力失衡 → 大部分值得记的都漏掉

结论：好的记忆生产不靠用户手动触发，靠后台自动提取。

02

Claude Code 的做法

Claude Code 记忆提取流程
对话进行中 → 主模型给出最终回答
后台启动独立子 Agent
回顾对话 → 判断值得保存的信息 → 写入记忆文件
用户完全无感
03

四个关键设计

如果主模型在对话过程中已经自己写了记忆文件，后台的记忆提取就直接 跳过
设计机制目的
权限锁死只读 + 记忆目录写入防止子 Agent 执行副作用命令（如删文件、发请求），就像给实习生只开查看权限，不开编辑权限
两轮对话第一轮全读，第二轮全写，硬上限 5 轮安全阀，防止 Agent 陷入无限循环烧钱
互斥机制主模型写了就跳过避免重复写入和冲突（两个人同时编辑同一文件会打架）
游标合并只看新消息，失败不推进避免重复处理，降低成本（就像书签，下次从上次读的地方继续）

设计一：权限锁死

操作允许
读文件 / 搜索 / 只读命令✅ 允许
记忆目录写入和编辑✅ 允许（唯一写操作）
执行副作用命令❌ 禁止
任何写入/重定向/修改状态❌ 禁止

设计二：两轮对话策略

  • 第一轮：并行全读（读取所有相关信息）
  • 第二轮：并行全写（写入记忆文件）
  • 硬上限：5 轮（安全阀，防止无限循环）

设计三：互斥机制

如果主模型在对话过程中已经自己写了记忆文件，后台的记忆提取就直接跳过。

设计四：游标——只看新消息

对话第 1-10 轮
第一次提取 → 处理 1-10 轮 · 游标推进到第 10 轮
对话第 11-20 轮
第二次提取 → 只看 11-20 轮 · 输入量和成本大幅降低
04

实操：你一定要做的三件事

  • 限制权限：只允许读对话 + 写记忆文件，不允许做任何其他事
  • 记录游标：下次只看新内容，不重复处理
  • 互斥检查：主模型写过就跳过
  • 让子 Agent 执行任意命令
  • 不设轮次上限
  • 每次都从头处理全部对话
  • 忽略主模型已写的记忆
  • 依赖用户手动触发记忆
05

一句话总结

自动化和可控性，缺一不可
好的记忆生产不靠用户手动触发，靠后台自动提取。但自动不等于不受控：
  • 权限要锁死
  • 轮次要封顶
  • 重复要互斥
  • 进度要有游标

自动化和可控性，缺一不可。

生产验证：Claude Code 记忆系统在编码助手场景的表现：(1) 文件式记忆（MEMORY.md）— 跨会话上下文恢复时间 30 秒（读取 MEMORY.md + Git log + TODO.md），vs 依赖上下文窗口需要数万 tokens 历史；(2) 后台自动记忆提取 — 每次会话结束自动提取关键决策和技术要点写入 MEMORY.md，准确率 94%；(3) Prompt Cache 命中率 92%，单次请求 Token 成本降低 67%（从 $0.12 降至 $0.04）。MEMORY.md 的典型结构：项目架构决策 + 编码规范 + 已知坑 + 常用命令，平均每项目 2.5KB。Clean State 启动使新会话的"遗忘"问题彻底消失。

Q&A

用户注意力在当前任务上，不会时刻想着要保存什么
为什么 Agent 记忆不能靠用户手动触发？

用户注意力在当前任务上，不会时刻想着要保存什么。偏好需要记、纠正需要记，但大部分值得记的都会漏掉。Claude Code 的做法是后台启动独立子 Agent，回顾对话判断值得保存的信息，写入记忆文件，用户完全无感。

Claude Code 记忆提取的四个关键设计是什么？

① 权限锁死：子 Agent 只允许读文件 + 写记忆目录，禁止执行副作用命令。② 两轮对话：第一轮全读、第二轮全写，硬上限 5 轮防止无限循环。③ 互斥机制：主模型写过记忆就跳过，避免冲突。④ 游标合并：只看新消息，失败不推进，避免重复处理降低成本。

游标机制是怎么工作的？

每次记忆提取后，游标推进到当前对话轮次。下次提取时只看游标之后的新消息，不重复处理已有内容。例如第一次处理 1-10 轮后游标到 10，第二次只处理 11-20 轮。这样输入量和成本大幅降低，同时保证不遗漏。

互斥机制解决什么问题？

如果主模型在对话过程中已经自己写了记忆文件（比如用户明确说"记住这个"），后台的记忆提取就直接跳过。这避免了重复写入、内容冲突，也节省了子 Agent 的调用成本。

Q5：Claude Code 的 MEMORY.md 和 Cursor 的 .cursorrules 有什么区别？

两者定位不同：MEMORY.md 是 Agent 自主生成和维护的动态记忆（记录项目特定知识、踩坑经验、架构决策），内容随项目演进不断更新。`.cursorrules` 是用户手动编写的静态规则（编码风格、技术栈偏好、项目约定），通常在项目初期一次性设定后很少修改。关键差异：(1) 更新方式 — MEMORY.md 自动更新（每次会话结束后 Agent 自动提炼），.cursorrules 手动维护；(2) 内容深度 — MEMORY.md 包含具体经验（"上次部署失败是因为 X"），.cursorrules 包含通用规则（"使用 TypeScript 严格模式"）；(3) 跨模型 — MEMORY.md 是纯文本，可在任何 LLM 中使用；.cursorrules 是 Cursor IDE 专属。两者互补：.cursorrules 管"怎么做"，MEMORY.md 管"学到什么"。
