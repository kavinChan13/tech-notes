概览

人类大脑有两种长期记忆： 情景记忆 记住"上次发生了什么"， 程序性记忆 记住"怎么做一件事…

人类大脑有两种长期记忆：情景记忆记住"上次发生了什么"，程序性记忆记住"怎么做一件事"。过去两年 AI Agent 的记忆系统只做了一半——情景记忆（存储历史轨迹），而另一半更重要的程序性记忆（可执行的技能脚本）完全空白。SkillPro（ICML 2026 Spotlight）首次填补了这个缺口，让 Agent 从"每次从头推理"进化为"积累并复用技能"。

01

问题背景：为什么情景记忆远远不够

当前 Agent 经验复用的主流方案（RAG、Expel、A-MEM）本质上都是"存储历史…

当前 Agent 经验复用的主流方案（RAG、Expel、A-MEM）本质上都是"存储历史 + 检索参考"——它们存储的是叙事（narrative），而不是程序（program）。Agent 每次遇到相似场景时，仍然需要检索历史、重新推理、重新生成行动计划。这就像每次做菜前都要翻看上次做菜的日记，而不是直接按照已经熟练的食谱操作。

1.1 情景记忆的三大致命缺陷

当前 Agent 经验复用的主流方案——RAG（Retrieval-Augmented Generation）、Expel（经验抽取）、A-MEM（增强记忆）——本质上都是"存储历史 + 检索参考"。它们存储的是叙事文本（"上次我做了什么、发生了什么、学到了什么"），而不是可执行的程序（"遇到这类情况应该按这些步骤操作"）。这个根本性的存储格式差异导致了三个致命的效率问题。

缺陷一：存储膨胀。传统方案将完整的交互轨迹存入向量库。一个 Agent 在 100 次任务中产生的轨迹文本可达数十万 tokens。Expel 系统存储 294,447 tokens，AWM 存储 391,706 tokens——相当于每次决策都要翻阅一本数百页的"历史回忆录"。

缺陷二：检索噪声。情景记忆的检索基于语义相似度，但"语义最相似的历史"未必是"当前最优的行动指南"。一条语义接近但策略错误的历史轨迹被检索出来后，反而会误导 Agent 的决策。更隐蔽的问题是：当历史轨迹中包含多个互相矛盾的策略（有些成功、有些失败），Agent 无法自动区分哪些经验值得参考、哪些应该忽略。

缺陷三：推理冗余。检索到历史后，Agent 仍需要 LLM 重新推理——将历史信息与当前状态结合，生成新的行动计划。这个"重新推理"过程既消耗大量 tokens，又引入不稳定性。每次重新推理都可能产生不同的结果（尤其是 temperature > 0 时），导致 Agent 在相似场景下的行为不一致——同一个问题问两次，可能得到两个不同的行动方案。

02

Skill-MDP：将技能形式化为可执行三元组

SkillPro 的第一个核心贡献是 Skill-MDP ——将经典马尔可夫决策过程扩展为包…

SkillPro 的第一个核心贡献是Skill-MDP——将经典马尔可夫决策过程扩展为包含技能层的层次化架构。每个技能 ω 被形式化为三元组 ⟨Iω, πω, βω⟩，分别对应激活条件、执行程序、终止条件。这让"模糊的经验"变成了"精确的可执行程序"。

2.1 技能三要素详解

激活条件（Activation Condition, Iω）：用自然语言描述"什么情况下应该使用这个技能"。例如："当目标刚刚启动，尚无环境反馈信息时"。Agent 在每个决策步通过语义匹配选择最合适的技能。

执行程序（Execution Process, πω）：用自然语言描述的有序步骤序列。例如："步骤1：构建假设空间… 步骤2：提出最大信息量猜测… 步骤3：根据反馈更新假设…"。这是技能的核心——将推理固化为可重复执行的脚本。

终止条件（Termination Condition, βω）：定义"什么时候这个技能完成了"。例如："当假设空间缩小到单一候选，或连续三次反馈一致时"。终止条件确保技能不会无限执行。

2.2 层次化策略分解

Skill-MDP 的核心思想是将 Agent 的决策分解为两个层次。上层技能选择策略 μ 负责从技能池 Ω 中选择最合适的技能 ωt。下层冻结的 LLM πLLM 以选中的技能为指导，生成具体的原子动作。这种分解将"推理开销"从运行时转移到了技能学习阶段——一旦技能被学好，运行时只需"匹配 + 执行"，不再需要从头推理。

层次化策略的数学表达为：πΩ(ωt, at | st) = μ(ωt | st, Ω) · πLLM(at | st, ωt)。其中 μ 是技能选择概率（基于语义相似度），πLLM 是条件动作生成概率（以技能为指导）。这种分解的关键优势是：技能学习阶段的计算开销是一次性的（分摊到训练中），而推理阶段的开销极低（仅需语义匹配 + 条件生成）。

层次化策略的直觉理解：就像一个经验丰富的木匠不需要每次做椅子都从头思考"先锯哪块木头"——他的大脑在"椅子制作"这个技能的激活条件满足时（看到木材和工具），自动调用已经内化的操作序列。Skill-MDP 做的就是把这种"内化操作序列"用自然语言显式编码，让 LLM Agent 也能享受同样的效率提升。

组件功能实现方式类比

执行程序 πω指导 LLM 执行原子动作有序步骤序列 (prompt)小脑协调的运动序列

Skill-MDP 的精妙之处在于：它不需要修改 LLM 的任何参数。所有"学习"都发生在技能文本的增删改上——新增技能、修改步骤、删除低效技能。这使得整个系统可以在不触碰模型权重的前提下持续进化，避免了灾难性遗忘的风险。

03

非参数化 PPO：三阶段技能进化引擎

SkillPro 的第二个核心贡献是 非参数化 PPO （Non-Parametric PP…

SkillPro 的第二个核心贡献是非参数化 PPO（Non-Parametric PPO）——将经典 PPO 强化学习范式从"参数更新空间"映射到"自然语言文本空间"。参数更新 → 技能文本更新，梯度 → 语义梯度，重要性比率裁剪 → PPO 门控验证。这让技能可以在不修改 LLM 参数的前提下持续优化。

3.1 阶段一：语义梯度——用自然语言描述改进方向

经典 PPO 通过反向传播计算参数梯度来更新模型。SkillPro 的语义梯度（Semantic Gradient）用自然语言替代数值梯度——对每条使用技能 ω 的轨迹 τi，让 LLM 进行"事后归因"（hindsight attribution），输出结构化的修改建议 gi = (gi(I), gi(π), gi(β))。然后在一批轨迹上聚合这些建议为 ḡω，通过 LLM 操作符 ⊕ 生成候选技能 ω' = ω ⊕ ḡω。

语义梯度聚合与技能更新流程:
  对每条轨迹 τ_i 调用技能 ω:
    g_i = LLM.hindsight_attribution(τ_i, ω)  # 自然语言修改建议
  ḡ_ω = aggregate(g_1, g_2, ..., g_n)        # 批量聚合
  ω' = LLM.apply_edit(ω, ḡ_ω)                # 生成候选技能
  # ω' 是修改后的技能文本，未经过验证

3.2 阶段二：PPO 门控——信任域验证

语义梯度有"幻觉风险"——LLM 可能提出看似合理但实际有害的修改建议。PPO 门控（PPO Gate）借鉴了经典 PPO 的裁剪机制，在历史轨迹上计算候选技能的 clipped surrogate 分数，只有"最佳且正分"的候选才替换旧技能。

3.3 阶段三：在线打分——进化压力下的技能池维护

技能池需要维持"进化压力"。SkillPro 为每个技能维护一个在线优势分数：累积优势除以调用次数。随着训练推进，基线 R̄ 逐步上升——曾经"有用"的技能在新基线下可能变为负分，被自动淘汰。这确保了技能池始终保持高质量和紧凑。实测中，单个技能平均迭代 12 个版本，最终版本的错误率比初始版本降低 83%。

在线打分机制还有一个重要的"遗忘效应"：当某个技能长期未被调用时，其累积优势停止增长，而基线持续上升——导致该技能的分数逐渐降低，最终被新技能取代。这确保了技能池中不会积累"僵尸技能"——每个保留下来的技能都是近期活跃且有正向贡献的。

3.4 三阶段协同的工程实现

非参数化 PPO 的三阶段在工程实现上采用"周期性批处理"模式：每执行 N 次任务（典型值 N=50-100），触发一次进化循环——从缓冲区采样批次轨迹，计算语义梯度，生成候选，PPO 门控验证，更新技能池，执行在线打分淘汰。这种设计将进化开销分摊到多次任务执行之间，不影响单次任务的响应速度。

PPO 门控的消融实验结果令人印象深刻：去掉 PPO 门控后，"幻觉技能"（看似改进但实际有害的技能修改）会进入技能池，导致性能不稳定甚至退化。这证明了语义梯度虽然能发现改进方向，但不能保证每次修改都是安全的——信任域验证是不可或缺的"安全阀"。

4.3 关键数字解读

Token 消耗降 99%：RAG 需要 116,527 tokens 存储经验，SkillPro 仅需 816 tokens——压缩比达 142:1。这是因为程序性记忆存储的是"压缩后的可执行脚本"而非"完整的原始轨迹"。

函数调用超越纯推理基准 37%：在需要工具调用的任务中，SkillPro 的技能脚本可以直接编码函数调用序列，比纯推理方案（每次从零推理调用什么函数）高出 37% 的成功率。

跨模型泛化提升 2.1 倍：SkillPro 在 Gemma-3 4B 上学到的技能，直接迁移到 Qwen3 32B 后复用率达 0.875（原始方法仅 0.146-0.270）。这证明自然语言技能是一种"协议级"的跨模型可迁移表示。

最反直觉的发现是"816 tokens 达到 0.925 复用率"——将经验转化为可执行程序而非叙事文本，使信息密度提升了两个数量级。这意味着 Agent 的"程序性记忆库"可以压缩到不足 1KB 的文本中，却足以指导数百次任务的高效执行。

5.2 PPO 门控：不可或缺的安全阀

消融实验中最关键的发现是PPO 门控的不可替代性。没有门控验证时，语义梯度产生的候选技能中约有 30-40% 是"看起来更好但实际更差"的幻觉修改。这些幻觉技能一旦进入技能池，会在后续任务中持续产生负面影响，且随着技能池膨胀，错误会被放大。

5.3 在线打分的进化压力机制

在线打分机制的精妙之处在于"基线上升效应"。随着训练推进，技能池整体质量提升，基线 R̄ 随之上升。曾经"还不错"的技能在新的高基线下可能变为负分——这就像进化论中的"红皇后效应"，技能必须不断进步才能留在池中。这种持续的进化压力确保了技能池的长期高质量。

6.3 SkillPro 的局限性

程序性记忆不是万能的。SkillPro 有三个核心局限：第一，技能是显式文本占用上下文窗口——当技能池过大时会挤占任务推理空间；第二，技能质量受限于基座 LLM 能力——语义梯度无法产出超越基座模型能力的改进；第三，技能选择策略 μ 目前仅用简单语义匹配——在大规模技能池中可能需要更复杂的检索器。

6.4 技能演化的收敛性分析

SkillPro 论文中一个有价值的发现是技能版本迭代的收敛模式。在 Mastermind 任务中，单个技能平均经历 12 个版本的迭代后趋于稳定。前 3 个版本通常是"大改"（步骤序列的结构性调整），中间 4-8 版本是"微调"（条件判断的细化），最后 9-12 版本是"打磨"（边界情况的处理）。这种"粗调 → 微调 → 收敛"的模式与参数化 PPO 的训练曲线高度一致，验证了非参数化 PPO 确实复现了经典 RL 的学习动态。

6.5 与 PolySkill 和 SkillRevise 的关系

SkillPro 并非 2026 年唯一的程序性记忆工作。ICLR 2026 的 PolySkill 提出了"多态抽象"——同一个技能在不同场景下有不同实例化形式，解决了技能泛化的粒度问题。SkillRevise（2026）则专注于技能的迭代修正——在冷启动场景下，通过执行轨迹追溯来改进初始技能质量，将基础 Agent 成功率从 36% 提升到 62%。三者共同构成了程序性记忆研究的完整生态：SkillPro 提供进化机制，PolySkill 提供泛化框架，SkillRevise 提供冷启动方案。

最理想的 Agent 记忆系统是三层协同：工作记忆处理当前任务状态，情景记忆提供历史参考（特别是长尾新颖场景），程序性记忆执行高频重复任务。SkillPro 填补了程序性记忆的空白，但并没有取代情景记忆——两者是互补关系，不是替代关系。当遇到技能池中不匹配的新颖任务时，Agent 回退到情景记忆检索 + 从头推理，成功后将新经验沉淀为新技能。

跨模型泛化与产业影响

SkillPro 最令人兴奋的特性是 跨模型泛化 ——在 Gemma-3 4B 上学到的技能…

SkillPro 最令人兴奋的特性是跨模型泛化——在 Gemma-3 4B 上学到的技能可以直接被 Llama-3.3 70B 使用，且复用率从原始方法的 0.146-0.270 跃升至 0.875。这意味着自然语言技能是一种"模型无关"的协议层表示——任何 LLM 都能读懂并执行。

7.1 为什么自然语言技能是"协议级"表示

传统模型压缩（蒸馏、量化）迁移的是模型内部的参数或表示——不同架构之间的迁移极其困难。但 SkillPro 的技能是自然语言文本——这是一种所有 LLM 都能理解的"通用协议"。就像一个 Python 脚本可以在任何安装了 Python 解释器的机器上运行，一段自然语言技能可以在任何足够强大的 LLM 上被解读和执行。

7.2 产业应用前景

跨模型泛化能力意味着企业可以在一个低成本小模型上积累技能，然后直接迁移到生产环境的大模型上——无需重新学习。这对多模型混合部署、模型升级迁移、跨团队协作三个场景具有巨大价值。

SkillPro 的跨模型实验数据堪称惊艳：Gemma-3 4B 学到的技能在 Qwen3 32B 上的复用率 0.875，在 Llama-3.3 70B 上 0.647。相比之下，所有情景记忆基线（RAG 0.146、Expel 0.270、A-MEM 0.018）在跨模型场景下几乎失效。这从根本上改变了 Agent 经验积累的经济学——技能积累不再绑定特定模型，而是成为可跨模型复用的"通用资产"。

场景一：多模型混合部署。在客服系统中，简单查询用小模型（如 Qwen-7B），复杂问题转给大模型（如 GPT-4）。SkillPro 允许小模型在日常交互中自主积累技能，当需要升级到大模型时，技能库直接传递——大模型立刻继承小模型积累的所有操作经验，无需冷启动。

场景二：模型升级迁移。当企业从 Llama-3 升级到 Llama-4 时，传统方案需要在 Llama-4 上重新进行经验积累。SkillPro 的技能库是模型无关的自然语言——直接传递给 Llama-4 即可使用，实现"零迁移成本"的模型升级。

场景三：跨团队协作。团队 A 在金融风控场景积累的技能，可以直接共享给团队 B 的欺诈检测 Agent——只要两个场景有足够的共性。这建立了一个"技能市场"的可能性：高质量技能作为可交易的 Agent 资产。

SkillPro 揭示了一个范式转变：Agent 的核心资产不是模型权重，而是积累的程序性记忆。模型可以更换（从 GPT-4 换到 Claude，或从 Llama 换到 Qwen），但技能库可以直接复用。这将 Agent 的"经验资产"从绑定特定模型变成了模型无关的可迁移知识。

7.3 与 Claude Agent Skills 的对比

Anthropic 在 Claude 中推出的 Agent Skills 是人工编写的技能模板。SkillPro 提供了算法化的路径——让 Agent 从交互经验中自主学习这些模板。两者的互补关系是：人类编写种子技能 → SkillPro 从使用中自主进化 → 人类审查最终技能库。这构成了"人机协作的技能工程"完整闭环。

从 SkillPro 论文到 Claude Agent Skills 的实践，Agent 技能系统正在从"学术研究"走向"生产标配"。2026 年的趋势是：每个成熟的 Agent 产品都将拥有自己的技能库——部分是人工编写的种子技能，部分是算法自主学习和进化的技能。技能库的质量（而非模型参数的大小）将成为 Agent 产品的核心竞争力。

7.4 技能治理的未来方向

随着技能库规模的扩大，技能治理将成为重要课题。2026 年的 SkillsVote 框架提出了技能的全生命周期管理——从收集、推荐、归因到进化。核心挑战包括：技能的版本控制（如何回滚到旧版本？）、技能的权限管理（哪些 Agent 可以使用哪些技能？）、以及技能的质量认证（如何确保一个技能在多种场景下都是安全的？）。

Q & A

程序性记忆和情景记忆是替代关系还是互补关系？
互补关系。程序性记忆处理"反复出现的已知任务"——技能匹配后直接执行，速度快、token 少。情景记忆处理"新颖的未知任务"——当技能池中没有匹配的技能时，Agent 回退到情景记忆检索 + 从头推理。最佳实践是：高频重复任务沉淀为程序性记忆，长尾新颖任务保留在情景记忆中。SkillPro 的 0.925 复用率意味着约 7.5% 的任务仍然需要情景记忆来处理。
语义梯度如何避免"幻觉修改"——LLM 提出的改进建议本身可能是错的？
这正是 PPO 门控存在的理由。语义梯度只是"提议"——它产生 Nc 个候选技能修改。PPO 门控在历史轨迹上回测每个候选：计算冻结 LLM 在新旧技能下的概率比率 ρ，然后用 PPO 的裁剪目标函数 L_CLIP 评估。只有"回测证明更好"的候选才会替换旧技能。消融实验证明，去掉门控后约 30-40% 的语义梯度修改是有害的——这就是为什么两道防线（发现 + 验证）缺一不可。
技能池的容量 K 应该设多大？太小会不会丢失有用技能？
SkillPro 的实验显示，紧凑的技能池（K=10-50 个技能，总存储 <1000 tokens）反而优于大池子。原因是：技能池越大，检索时的噪声越多，匹配到"语义接近但策略错误"的技能的概率越高。在线打分机制会自动淘汰低分技能——当容量满时，最低分技能被移除。实践中 K 应该根据任务域的多样性设定：单一领域 K=10-20，多领域 K=30-50。
跨模型泛化时，不同 LLM 对同一段技能文本的理解会不会有差异？
会有差异，但影响有限。实验数据说明了一切：Gemma-3 4B 上学的技能在 Qwen3 32B 上复用率 0.875，在 Llama-3.3 70B 上 0.647。Qwen3 复用率更高可能是因为架构更接近 Gemma，而 Llama 的 tokenizer 和训练分布差异更大。但 0.647 仍然远超所有基线方法。核心原因是：自然语言技能描述的是"做什么"（步骤序列），而非"怎么在特定模型内部实现"——任何足够强的 LLM 都能理解"步骤1：构建假设空间"这样的指令。
SkillPro 能否处理需要多个技能组合的复杂任务？
SkillPro 的层次化架构天然支持技能组合。在每个决策步 t，技能选择策略 μ 可以选择不同的技能——Agent 可以在任务前半段使用"信息收集"技能，后半段切换到"决策执行"技能。终止条件 β 确保前一个技能在合适的时间点交出控制权。但目前的限制是技能之间缺乏显式的"组合协议"——未来的工作方向是引入技能间的依赖关系图。
SkillPro 的局限是什么？什么场景下它不适用？
三个主要局限。第一，技能是显式文本，占用上下文窗口——当技能池过大时会挤占任务推理的空间。第二，技能质量受限于基座 LLM 的能力——如果 LLM 本身在某类任务上就表现差，语义梯度也无法产生有效的改进建议。第三，技能选择策略 μ 目前仅用简单语义匹配——在大规模技能池中可能需要更复杂的检索策略。不适用的场景：每次任务都完全不同的纯创造性工作（没有可复用的模式），或需要亚秒级响应的实时系统（技能匹配有延迟）。
SkillPro 与传统 Prompt Engineering 的关系是什么？
SkillPro 可以被视为"自动化的 Prompt Engineering"。传统 PE 是人类手动编写提示词模板来指导 LLM 行为，SkillPro 的技能本质上也是自然语言的执行指令——但它不是人类编写的，而是 Agent 从经验中自主学习并通过非参数化 PPO 持续优化的。两者的关系是：人类编写的 PE 模板可以作为 SkillPro 的种子技能（初始技能池），然后 SkillPro 在实际使用中自主进化这些模板，逐步超越人类初始设计。
非参数化 PPO 的"非参数化"具体是什么意思？和参数化 PPO 有什么本质区别？
"非参数化"指的是优化过程中不更新 LLM 的任何权重参数。参数化 PPO 通过反向传播更新模型参数 θ，每轮训练需要大量 GPU 计算。非参数化 PPO 的"参数"是技能文本——更新操作是修改自然语言字符串（添加、删除、替换步骤），而非数值梯度下降。本质区别在于：参数化更新改变模型的"内在能力"，有灾难性遗忘风险；非参数化更新改变"外部知识库"，LLM 本身保持不变，零遗忘风险。代价是受限于 LLM 原有能力上限。
SkillPro 的技能选择策略 μ 目前用简单语义匹配，这在大规模技能池中够用吗？
在 SkillPro 的实验规模（10-50 个技能）下，语义匹配足够有效。但论文作者也指出，当技能池扩展到数百甚至数千个时，简单语义匹配会遇到"语义碰撞"问题——多个技能的激活条件在语义上高度相似，导致选择不够精确。论文建议的改进方向包括：引入 RL-based 检索器、使用技能的历史成功率作为辅助信号、以及为技能增加更细粒度的标签体系。
SkillPro 能处理需要实时响应的场景吗？技能匹配会不会引入延迟？
技能匹配的延迟极低——语义相似度计算（embedding 比较）通常只需 1-5ms，远低于 LLM 推理的 30-500ms。实际上，SkillPro 通过"匹配 + 直接执行"替代了传统方案的"检索 + 重新推理"，总体延迟反而更低。但需要注意，如果技能的执行步骤很长（10+ 步），LLM 按步骤执行的总时间可能超过直接端到端推理——此时技能的优势在于成功率更高，而非速度更快。
如何将 SkillPro 集成到现有的 Agent 框架中（如 LangChain、AutoGen）？
SkillPro 的集成相对简单，因为它的核心组件都是"提示层"的修改。具体步骤：1) 在 Agent 的 System Prompt 中添加技能池（816 tokens 的技能文本）；2) 在每步决策前，通过 embedding 匹配选择最相关技能；3) 将选中技能作为 System Prompt 的一部分注入 LLM 调用；4) 定期（每 50-100 次任务）运行非参数化 PPO 进化循环更新技能池。整个流程不需要修改 LLM 权重，可以在任何支持 Prompt 注入的框架中实现。
程序性记忆的概念可以扩展到代码生成 Agent 吗？比如让编程 Agent 积累"代码重构技能"？
完全可以，而且这是最有前景的应用方向之一。编程 Agent 可以学习的程序性技能包括：代码重构模式（"当遇到 God Class 时，按 SRP 原则拆分"）、测试策略（"对纯函数用单元测试，对 API 用集成测试"）、Debug 流程（"先检查最近 3 次提交的 diff，再检查日志"）。这些技能的共同特点是：高频出现、步骤固定、一旦学会就无需重新推理。Claude Code 的 Agent Skills 机制已经在实践这种模式，只是目前依赖人工编写——SkillPro 提供了自动化学习的算法路径。
