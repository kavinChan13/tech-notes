02

LCEL：链式表达式语言

用管道符 | 把 AI 组件像乐高一样拼在一起——输入流过每个组件，逐步被加工成输出

用管道符 | 把 AI 组件像乐高一样拼在一起——输入流过每个组件，逐步被加工成输出。

LCEL 的核心思想：所有组件都实现 Runnable 接口（invoke / stream / batch），通过管道符串联成 Chain。

RAG Chain 数据流

LCEL RAG Chain 数据流
用户问题
Retriever 向量检索 → Top-K 文档片段
Prompt Template 文档 + 问题 → 填充到模板
LLM Prompt → 生成回答
Output Parser 原始文本 → 结构化输出

LCEL 三大优势

优势说明
原生流式链中任何组件都支持 streaming，Token 级流式输出自动传播
自动批处理batch() 方法自动并行处理多个输入，无需手写并发逻辑
自动重试内置重试和降级机制，LLM 调用失败时自动重试
LCEL 适用边界：适合线性管道（DAG 结构）——输入 → 处理 → 输出，没有循环。如果任务需要循环（如 ReAct Agent）、条件分支、或持久化状态，应该使用 LangGraph。
03

Agent 与 Tool Calling

LangChain 的 Agent = LLM + Tools + 决策循环——LLM 决定…

LangChain 的 Agent = LLM + Tools + 决策循环——LLM 决定用什么工具，工具返回结果，LLM 再决定下一步。

创建 Agent 的核心要素

要素说明
Tool包含名称、描述和执行函数。描述质量直接影响工具选择准确率
bind_tools把 Tool 列表绑定到 LLM，让模型知道有哪些工具可用
create_react_agent创建 ReAct 模式 Agent：思考 → 选工具 → 执行 → 观察 → 继续
Tool 描述的重要性：Tool 的描述就是给 LLM 看的"说明书"。模糊的描述（"搜索一些东西"）会导致 LLM 误选工具。好的描述应该明确说明：这个工具做什么、输入什么、返回什么、什么时候该用。类似于写好函数的 docstring。

LangGraph：有状态 Agent 编排

当 LCEL 的线性管道不够用时——LangGraph 用状态图让你构建循环、分支、可恢复的…

当 LCEL 的线性管道不够用时——LangGraph 用状态图让你构建循环、分支、可恢复的复杂 Agent。

核心抽象：StateGraph

概念说明
State整个图的共享状态（TypedDict），所有节点读写同一个状态对象
Node处理节点，接收 State 并返回更新
Edge节点间的连接，支持条件路由（根据状态动态决定下一个节点）
Checkpointer持久化引擎，每次节点执行后自动保存快照。支持断点续跑和 Time Travel

Memory 系统

LangGraph 的记忆系统从简单的消息列表进化到三层记忆架构——短期、长期、语义

LangGraph 的记忆系统从简单的消息列表进化到三层记忆架构——短期、长期、语义。

三层记忆模型

记忆层存储内容生命周期典型用途
短期记忆（Checkpoint）当前会话完整状态单次会话中断恢复、Time Travel
长期记忆（Store）跨会话持久化信息永久用户偏好、学习成果
语义记忆长期记忆的向量索引永久语义检索"上次类似问题"

上下文管理策略

策略方式适用场景
滑动窗口保留最近 N 条消息简单对话（N=20）
Token 限制按 Token 数裁剪长对话
摘要压缩LLM 将旧消息压缩为摘要超长对话
实际生产系统通常组合使用多种策略：短期用滑动窗口，跨会话用长期记忆 Store，复杂检索用语义记忆。
06

LangSmith：可观测性与评估

LangSmith 是 LLM 应用的"调试器 + 质量仪表盘"——看到每一步的输入输出，知…

LangSmith 是 LLM 应用的"调试器 + 质量仪表盘"——看到每一步的输入输出，知道哪里出了错。

LangSmith 解决 LLM 应用的核心痛点：不透明。一个 Agent 执行了 5 次工具调用，最终给了错误答案——是哪一步出了问题？没有 LangSmith，你只能猜测。

核心功能

功能说明
Trace完整记录每次调用全链路——LLM 输入/输出、工具调用、耗时、Token 消耗
Evaluation对 Trace 结果运行评估器（准确性、相关性、毒性等），生成质量报告
Prompt HubPrompt 版本管理，像 Git 管理代码一样管理 Prompt，支持 A/B 测试和回滚
Online Evaluation生产环境持续评估，对线上流量自动采样，质量退化时报警
实际价值：不只是"看看日志"——LangSmith 让你能复现任意一次线上调用（Trace → 测试用例）、对比不同 Prompt 版本效果、发现生产 bad case 并定向修复。是 LLM 应用从 demo 到 production 的关键基础设施。

LangServe：一键部署

把 LangChain/LangGraph 应用变成 API——一行配置，自动获得 REST…

把 LangChain/LangGraph 应用变成 API——一行配置，自动获得 REST 接口 + Playground。

LangServe 将任何实现了 Runnable 接口的组件自动暴露为 REST API，附带：

流式输出（SSE）、输入验证（Pydantic Schema）、内置 Playground、LangSmith 自动集成。

LangGraph Platform 是 LangServe 的升级版，专门用于部署 LangGraph 应用。提供 Cron 任务（定时执行 Agent）、Webhook（事件触发 Agent）、持久化存储等生产级功能。

LangChain 生态使用准则

按需使用

不要安装整个 langchain 包。按需引入 langchain-core、langgraph、具体集成包。

尽早接入 LangSmith

从开发第一天就开启 Trace。早期数据能帮你快速定位 Prompt 和工具定义的问题。

强行用 LCEL 做 Agent

LCEL 适合线性管道。需要循环和状态 → LangGraph。不要强行用 Chain 实现复杂逻辑。

过度依赖抽象层

理解底层 API（OpenAI SDK、向量库原生接口）后再用 LangChain 包装，出了问题能更快定位。

核心要点：LangChain 生态的核心价值是标准化接口（Runnable）和全链路覆盖（从编排到部署到观测）。选择组件时按复杂度分层：简单管道用 LCEL，Agent 用 LangGraph，观测用 LangSmith。同时保持对底层 API 的理解，避免被抽象层"黑箱"困住。
