01

从 RNN 到 Transformer：为什么需要新架构

Transformer 的诞生只为一件事：让每个 token 不再排队等待，而是直接与任意位…

Transformer 的诞生只为一件事：让每个 token 不再排队等待，而是直接与任意位置的 token 对话。

2017 年之前，处理序列数据的主力是 RNN（循环神经网络）。RNN 像一条单行道——信息只能从第 1 个词依次流向最后一个词。这带来两个致命缺陷：

RNN 的两大硬伤

问题表现根因量化影响
无法并行100 个 token 必须依次计算 100 步第 t 步依赖第 t-1 步的输出训练速度比 Transformer 慢 10~50 倍
长距离依赖弱第 1 词的信息传到第 800 词时几乎丢失反复乘以权重矩阵导致梯度消失/爆炸超过 200 token 的依赖关系几乎无法捕获

LSTM 和 GRU 通过门控机制部分缓解了长距离依赖问题，但没有从根本上解决——因为它们仍然被困在"串行"这条单行道上。信息传递路径长度 = 序列长度，这是结构性瓶颈。

RNN · 串行传递

T1→ T2→ T3→ … → T6
  • T1→T6 距离5 步（O(N)）
  • 信息衰减严重
  • 训练并行度1（逐步串行）

Transformer · 全连接

T1T2T3任意两点直连
  • T1→T6 距离1 步（O(1)）
  • 信息衰减几乎无
  • 训练并行度N（全部 token 同时）

2017 年，Google 团队发表了 《Attention Is All You Need》，提出了 Transformer 架构。核心突破只有一个：Self-Attention——让每个 token 直接关联任意位置的 token，信息传递距离从 O(N) 降到 O(1)。

如果说 RNN 是一条单行道（车只能依次通过），那 Transformer 就是一个立交桥系统——任意两辆车都可以直接交换位置信息，不需要经过中间车辆传递。

02

Self-Attention 核心：Q·K·V 机制深度解剖

Self-Attention 的本质就是一场"信息投票"：每个 token 发出查询（Q）…

Self-Attention 的本质就是一场"信息投票"：每个 token 发出查询（Q），每个 token 也展示自己的身份（K），投票结果决定了该从哪些 token 那里获取信息（V）。

为什么需要 Q·K·V 三个投影？

直觉上你可能会问：为什么不直接让输入向量互相点积？为什么要把同一个输入 X 投影成三份 Q、K、V？

三个投影矩阵各自承担不同角色：

矩阵全称作用维度
WQQuery 投影把输入投影到"提问空间"——这个 token 在关注什么[d_model, d_k]
WKKey 投影把输入投影到"被查询空间"——这个 token 能提供什么[d_model, d_k]
WVValue 投影把输入投影到"信息空间"——被选中后要传递的内容[d_model, d_v]
Self-Attention 完整公式：
Attention(Q, K, V) = Softmax(Q · KT / √dk) · V

其中：Q = X · WQ，K = X · WK，V = X · WV
X: [seq_len, d_model] | Q,K: [seq_len, d_k] | V: [seq_len, d_v]

逐步拆解计算过程

第 1 步：计算相关性分数

Q · KT 得到 [seq_len, seq_len] 的矩阵——每个 token 与其他所有 token 的"匹配分数"。第 i 行第 j 列表示：token i 的 Query 与 token j 的 Key 的点积相似度。

第 2 步：缩放（Scaling）

为什么要除以 √dk？当 dk 很大时（如 64 或 128），点积结果的方差会随维度线性增长。假设 Q 和 K 的每个元素都是独立的均值为 0 的随机变量，那么点积 q·k = Σqiki 的方差 = dk。不缩放会导致 Softmax 输出极度尖锐（几乎所有概率集中在最大项），梯度接近 0，训练无法推进。

第 3 步：Softmax 归一化

把每行的分数转换为概率分布（和为 1）——这决定了每个 token "看"其他 token 的权重分配。

第 4 步：加权聚合 Value

用 Softmax 概率对 V 进行加权求和——"关注度高的 token 贡献更多信息，关注度低的被抑制。"

Self-Attention 完整数据流（示例 [8, 512]：8 个 token，每个 512 维）
输入 X · [8, 512]
经 W_Q / W_K / W_V 投影 → Q「找什么」/ K「能提供什么」/ V「传递的内容」各 [8, 64]
匹配分数 [8, 8]
每对 token 的相似度
Softmax [8, 8]
归一化为注意力权重
输出 [8, 64]
加权聚合后的新表示

Self-Attention 的计算复杂度是 O(N² · d)，其中 N 是序列长度。这就是为什么长文本处理（128K token）如此昂贵——注意力矩阵大小是 128K × 128K ≈ 163 亿个浮点数。FlashAttention 等优化技术正是为解决这一问题而生。

因果掩码（Causal Mask）

在 Decoder-Only 架构中，每个 token 只能"看到"自己和它前面的 token，不能偷看未来。实现方式是在注意力矩阵的上三角部分填入 −∞，经过 Softmax 后这些位置的权重变为 0。

位置能看到的范围掩码矩阵应用场景
Encoder所有 token（双向）无掩码，全 0 矩阵BERT / 双向理解
Decoder仅自己和之前的 token上三角填 −∞GPT / 自回归生成
Cross-Attention整个 Encoder 输出无掩码T5 / 翻译生成阶段
03

多头注意力：并行捕获多种语义关系

单头注意力只能关注一种关系模式

单头注意力只能关注一种关系模式。多头注意力像是派出多个侦察兵，每个头专注于发现不同类型的语义关联——主谓关系、动宾关系、指代关系、修饰关系等。

Self-Attention 的一个天然限制是：一次注意力计算只能捕获一种"关注模式"。但语言中的关系是多维的——"他"可能同时指代前面的"张三"（指代关系），又修饰后面的动词（语法关系），还与句子开头的主语形成呼应（语篇关系）。

多头机制如何工作

把 d_model（如 512）拆分为 h 个头（如 8 个头，每个头 d_k = 64）。每个头独立执行 Self-Attention 计算，最后把所有头的输出拼接起来，再乘以一个投影矩阵 WO 混合信息。

多头注意力数据流（8 heads, d_model=512, 每头 d_k=64）
输入 X · [seq_len, 512]
每个头独立算 Q/K/V → Attention，各输出 [seq_len, 64]
Head 1Attn₁
Head 2Attn₂
Head 3Attn₃
Head 4Attn₄
Head 5Attn₅
Head 6Attn₆
Head 7Attn₇
Head 8Attn₈
输出 [seq_len, 512]
注意力头典型捕获的关系例子激活模式
Head 1主谓一致"猫" → "在睡觉" (主语找到谓语)相邻位置高权重
Head 2指代消解"他" → "张三" (代词指向实体)长距离跳跃连接
Head 3动宾搭配"吃" → "苹果" (动词找到宾语)局部聚集
Head 4句法结构从句边界检测周期性模式
Head 5~8语义相似/冗余备份不同粒度的语义关联多样化

GQA：分组查询注意力

2026 年主流模型（LLaMA 3、Qwen 2.5、Mistral）普遍采用 GQA（Grouped-Query Attention）。标准 MHA 中每个头有独立的 Q/K/V，但 GQA 让多个 Query 头共享同一组 K/V：

方案K/V 头数显存节省代表模型
MHA（标准多头）= Q 头数（如 32）基线GPT-3, 早期 BERT
MQA（Multi-Query）1 个 K/V 头~95%PaLM
GQA（分组查询）Q 头数 / G（如 32/8=4）~87%LLaMA 3, Qwen 2.5

GQA 在推理时极大减少 KV Cache 的显存占用。LLaMA 3-70B 使用 GQA（32 个 Q 头共享 8 组 K/V），在 128K 上下文时 KV Cache 从 38GB 降至 ~10GB，几乎不影响模型质量。

GQA 的直觉：不是每个侦察兵都需要独立的地图和望远镜——可以几个人共享一套装备，各自从不同角度观察，既省钱又不耽误任务。

位置编码：让 Transformer "感知"词序

位置编码的本质：给每个 token 的位置赋予一个独特的"身份签名"，让模型区分同一词汇在不…

位置编码的本质：给每个 token 的位置赋予一个独特的"身份签名"，让模型区分同一词汇在不同位置的语义差异。

三种主流位置编码方案

方案核心思想公式 / 机制优势劣势代表模型
绝对位置编码每个位置分配固定的 sin/cos 向量PE(pos, 2i) = sin(pos / 100002i/d)
PE(pos, 2i+1) = cos(pos / 100002i/d)		实现简单，理论优雅无法外推到训练时未见的长度原始 Transformer, BERT
可学习位置编码把位置编码当作可训练参数随机初始化 → 训练学习灵活适应数据分布固定长度，无法外推GPT-2, BERT
RoPE（旋转位置编码）通过旋转矩阵注入相对位置信息对 Q/K 施加与位置相关的旋转角度支持长度外推，相对位置建模精准实现略复杂LLaMA 3, Qwen, Mistral

RoPE 的精妙之处

RoPE（Rotary Position Embedding） 的核心洞察：不直接"加"位置信息到 token 表示上，而是对 Q 和 K 向量施加一个与位置相关的旋转。两个位置的 Q 和 K 做点积时，结果自动编码了它们之间的相对距离。

这意味着 RoPE 天然支持相对位置编码——模型关注的是"token A 在 token B 前面第 3 个位置"，而非"token A 在绝对位置 7"。这让模型在推理时能处理比训练更长的序列（长度外推能力）。

RoPE 旋转公式 (2D 简化):
q(pos) = [q₁·cos(pos·θ) - q₂·sin(pos·θ), q₁·sin(pos·θ) + q₂·cos(pos·θ)]

其中 θ 是不同维度使用的不同频率。点积 q(pos₁)·k(pos₂) 只依赖 (pos₁ - pos₂)，即相对距离。

2026 年的标准配置：几乎所有主流 LLM 都采用 RoPE。配合 NTK-aware Scaling 等技术，可以让 8K 训练长度的模型外推到 128K+ 上下文，这是原始 sin/cos 编码完全无法做到的。

FFN 层：Transformer 的"知识仓库"

Attention 负责"信息交流"（token 之间互相看），FFN 负责"独立思考"（每…

Attention 负责"信息交流"（token 之间互相看），FFN 负责"独立思考"（每个 token 独自做深度加工）。研究表明，FFN 层的参数存储了模型的大部分事实性知识。

FFN 的结构

FFN（Feed-Forward Network） 是一个两层全连接网络，中间夹一个激活函数。它对每个 token 独立执行相同的变换——token 之间不交流，各自"独立思考"。

# FFN 标准结构 (d_model=512, d_ff=2048, 即4倍扩展)
x → Linear(512, 2048) → Activation → Linear(2048, 512) → output
#    扩展维度            非线性变换     压缩回原维度

为什么 FFN 能存储知识？

FFN 的本质是一个超大的查找表。中间的扩展维度（通常是 d_model 的 4 倍）形成了大量"神经元槽位"。每个槽位可以被训练为响应特定的输入模式——当输入匹配某个模式时，对应的神经元被激活，向输出注入相关信息。研究通过"知识神经元定位"实验发现：

知识类型存储位置验证方法删除后效果
事实性知识（"法国首都是巴黎"）中间层 FFN消融特定 FFN 神经元事实回答准确率下降 30~60%
语法/语法规则早期层 Attention探针分类器语法判断能力下降
推理能力晚期层 FFN + AttentionChain-of-Thought 分析多步推理失败率上升

SwiGLU：现代 FFN 激活函数

原始 Transformer 使用 ReLU 作为 FFN 激活函数，但 2026 年的标准配置已全面转向 SwiGLU。SwiGLU 结合了 Swish 激活函数和 Gated Linear Unit（GLU），通过门控机制让信息更可控地流动。

激活函数公式时代代表模型
ReLUmax(0, x)2017~2020原始 Transformer, BERT
GELUx · Φ(x) (高斯累积分布)2019~2023GPT-2, GPT-3
SwiGLUSwish(xW₁) ⊙ (xW₂)2023~2026LLaMA, Qwen, Mistral, DeepSeek

SwiGLU 引入了一个"门"：信息需要通过两道关卡（Swish 激活 + 门控乘法）才能输出。这提供了更细粒度的信息控制，实验表明比 GELU 提升约 0.3~0.5% 的下游任务准确率，且训练稳定性更好。

SwiGLU 使用 3 个权重矩阵 (W₁, W₂, W₃)，隐藏层维度需要调整为 8/3 · d_model 以保持与标准 FFN 相同的参数量

LLaMA 3 用 d_ff = 8/3 · d_model 配合 SwiGLU

不要把 SwiGLU 的隐藏层维度设为 4·d_model——这会导致参数量比标准 FFN 多 50%，破坏计算预算平衡

不要在已有模型中直接替换激活函数而不重新训练——激活函数的变化需要从头预训练

三种架构流派：Encoder-only / Decoder-only / Encoder-Decoder

Transformer 的三大分支并非三种不同的机器，而是同一台机器的三种"接线方式"——差…

Transformer 的三大分支并非三种不同的机器，而是同一台机器的三种"接线方式"——差异仅在于注意力掩码的方向。

2017 年的原始 Transformer 是完整的 Encoder-Decoder 架构。但后续研究者发现，拆掉一半反而做出了更好的模型。这催生了三条技术路线：

Encoder-Only（BERT 路线）

Encoder ×N
  • 注意力双向，看全部输入
  • 预训练Masked LM（填空 15%）
  • ✅ 理解任务极强❌ 不能生成

Decoder-Only（GPT 路线）

Decoder ×N
  • 注意力因果，只看过去
  • 预训练Next Token（预测下一个）
  • ✅ 生成 + 理解✅ 涌现推理能力

Encoder-Decoder（T5 路线）

Encoder ×N+ Decoder ×N
  • 注意力Encoder 双向 + Decoder 因果 + Cross-Attn
  • 预训练Span Corruption
  • ✅ 翻译/摘要专用

三大架构全面对比

维度Encoder-Only (BERT)Decoder-Only (GPT)Encoder-Decoder (T5)
注意力方向双向（看全部输入）因果（只看过去 token）Encoder 双向 + Decoder 因果 + Cross-Attn
预训练目标Masked LM（随机 mask 15% token 并预测）Next Token Prediction（预测下一个 token）Span Corruption（随机遮盖连续 span）
数据利用率~15%（只有被 mask 的 token 参与损失）100%（每个 token 都参与损失计算）~50%（被遮盖的 span 参与损失）
生成能力无（只能理解，不能生成）强（天然自回归生成）有（通过 Decoder 生成）
训练数据需求需要大量标注数据或特定格式海量无标注文本即可需要对齐的输入-输出对
典型规模110M~340M (BERT/RoBERTa)1.5B~1.8T (GPT-3~GPT-4)220M~11B (T5/mT5)
2026 年地位Embedding / 分类任务专用统治地位，所有新模型首选几乎淘汰，仅存量系统
代表模型BERT, RoBERTa, DeBERTaGPT-4, Claude, LLaMA 3, Qwen 2.5T5, BART, mBART

Decoder-Only 的四大碾压优势

优势一：目标统一

所有任务都化为"预测下一个 token"。翻译？"翻译成法语：你好 → Bonjour"。摘要？"总结以下文章：……"。问答？"问题：…… 答案："。统一的目标让模型可以用同一种训练范式处理所有任务。

优势二：数据利用最大化

BERT 每轮训练只有 15% 的 token 参与损失计算——85% 的数据是"白看"。Decoder-Only 的每个 token 都贡献梯度信号，等效于用 6~7 倍的数据效率训练。GPT-3 在 300B token 上训练，如果换成 BERT 的 MLM，等效有效数据量仅 45B。

优势三：规模效应与涌现

当 Decoder-Only 模型规模超过临界点（约 100B 参数），会自发涌现三种小模型不具备的能力：

涌现能力触发规模表现生产验证
In-Context Learning>10B 参数给 2~3 个示例即可学会新任务，无需微调GPT-3 (175B) 首次在训练中观察到
Chain-of-Thought>100B 参数能进行多步骤逻辑推理，输出中间推理过程GPT-4、Claude 3.5 在数学推理中验证
指令跟随>30B 参数理解自然语言指令并按要求执行ChatGPT / Claude 日常使用验证

优势四：工程友好

单层 block 堆叠的设计让分布式训练、显存优化、推理加速都只需针对一种组件。所有前沿优化——KV Cache、Speculative Decoding、Flash Attention——都是为 Decoder-Only 量身设计的。

Decoder-Only 的胜利不是因为它"更好"，而是因为它"更简单且更通用"——在足够大的规模下，简单的 next-token prediction 约束反而迫使模型自发发展出理解能力。"理解"成了"生成"的副产品。

Encoder-Decoder 在 2026 年还有用吗？

虽然 Decoder-Only 在通用大模型领域一统天下，但 Encoder-Decoder 并未完全消亡。在以下场景中它仍有独特价值：

  • 跨模态任务：输入是图像/音频/视频、输出是文本时（如 Whisper 语音识别），Encoder 处理输入模态 + Decoder 生成文本是自然设计
  • 一输入多输出：同一份长文档翻译为 10 种语言——编码一次、解码多次，比 Decoder-Only 重复编码 10 次高效
  • 小模型精调：在翻译/摘要等任务上，精调后的 T5/BART 仍能以 1~3B 参数量达到与 10B+ Decoder-Only 模型相当的效果

但在通用智能领域，结论非常清晰：2026 年所有新发布的旗舰模型——GPT-5、Claude 4、Gemini 2、LLaMA 4、Qwen 3——无一例外都是 Decoder-Only。

深度问答

为什么 Transformer 要用 Q·K·V 三个矩阵，直接 X·XT 不行吗？
直接用 X·XT 有两个根本问题。第一，角色耦合——同一个向量既当"提问者"又当"被查询者"，表达能力受限。比如"猫"在 Query 角色时需要找到谓语"睡觉"，但在 Key 角色时需要被形容词"慵懒的"找到。两个方向的需求完全不同，必须用不同投影来解耦。第二，没有 Value 投影的话，被关注到的信息就是原始输入 X 本身，无法对"传递什么内容"做独立控制。三个投影矩阵让模型分别学习"关注什么"、"提供什么"和"传递什么"，极大增强了表达能力。实验表明，移除任一投影矩阵，模型性能下降 15~30%。
Self-Attention 的 O(N²) 复杂度到底有多严重？实际数字是什么？
以 GPT-4 的 128K 上下文为例：注意力矩阵大小 = 128K × 128K = 16,384 × 16,384 ≈ 2.68 亿个浮点数，仅一个头的注意力矩阵就需要 ~1GB 显存。LLaMA 3 有 64 个注意力头，完整的注意力矩阵需要 64GB+。这就是为什么 FlashAttention（通过分块计算避免物化完整矩阵）和 Sliding Window Attention（只关注局部窗口）成为长文本处理的必备技术。当序列从 8K 扩展到 128K 时，计算量增长 256 倍（平方关系），这也是 128K 以上上下文仍然困难的核心原因。
BERT 的 15% mask 策略为什么效率低？能不能提高 mask 比例？
BERT 的 Masked LM 每轮只 mask 15% 的 token——意味着每轮训练中 85% 的前向计算是"浪费"的（这些 token 虽然参与了注意力计算，但不贡献梯度）。如果提高到 40~50%，模型会因上下文被破坏过多而难以学习连贯语义；如果降到 5%，训练信号太弱需要更多轮次。Google 的 Wettig et al. (2023) 实验发现最优 mask 比例约 40%，但此时需要调整训练策略。相比之下，Decoder-Only 的 Next Token Prediction 天然让 100% 的 token 参与损失——在相同的训练 token 数下，有效学习信号是 BERT 的 6~7 倍。
多头注意力的"头数"越多越好吗？如何选择最优头数？
不是越多越好。每个头的维度 d_k = d_model / h，头数增多意味着每个头的维度变小，捕获复杂关系的能力减弱。实证研究表明：d_k = 64 是一个甜点值，头数 = d_model / 64 即可。GPT-3 (d_model=12288) 用 96 头，LLaMA 3-70B (d_model=8192) 用 64 头。更重要的是，研究发现部分注意力头是"冗余"的——LLaMA 2-70B 的 64 个头中，约有 8~10 个头的注意力模式高度相似，可以合并。这正是 MQA/GQA 的理论基础：不需要每个 Query 头都有独立的 K/V，多组 Query 共享一套 K/V 几乎不损失性能。
为什么 FFN 被称为"知识仓库"？Attention 层不也存储知识吗？
关键区别在于知识的类型。Attention 层学习的是"token 之间如何关联"——是关系型知识（语法结构、指代关系、句法模式）。FFN 层学习的是"token 本身蕴含什么信息"——是事实型知识（"巴黎是法国首都"、"Python 是一种编程语言"）。Meng et al. (2022) 的 "Locating and Editing Factual Associations" 实验直接证明：修改中间层 FFN 的特定神经元权重，可以精准修改模型的事实知识（如让模型"认为"法国首都是里昂），而不影响其语法和推理能力。反过来，修改 Attention 层则影响句法结构处理，不影响事实记忆。这种功能分离是 Transformer 架构的一个重要涌现特性。
2026 年 Encoder-Decoder 架构完全没落了吗？还有什么场景必须用它？
在通用大模型领域确实几乎消亡——2024 年后没有新的旗舰级 Encoder-Decoder 模型发布。但在三类场景中它仍有不可替代的价值：(1) 跨模态理解——Whisper 用 Encoder 处理音频频谱、Decoder 生成文本，这种输入输出模态不同的任务天然适合两阶段架构；(2) 一输入多输出的高效推理——同一篇文档翻译为 20 种语言，Encoder 只需执行 1 次，Decoder 执行 20 次，比 Decoder-Only 完整推理 20 次节省约 40% 计算；(3) 小模型精调场景——Google 的 RedLLM (2025) 实验证明，在精调后 Encoder-Decoder 在翻译任务上以相同参数量达到比 Decoder-Only 高 2~3% 的 BLEU 分数。但这些场景都是"专用工具"，不再是通用智能的基础架构。
RoPE 如何实现长度外推？训练 8K 能推理 128K 的原理是什么？
RoPE 的核心是对 Q 和 K 向量施加位置相关的旋转角度。旋转角度 θ 与位置 pos 的关系是 θ = pos × base_freq。当推理序列超过训练长度时，新的位置只是对应了"更大角度的旋转"——旋转操作本身不会失效。但问题是：超出训练范围的旋转角度组合是模型训练中从未见过的，可能导致注意力分布异常。NTK-aware Scaling 通过将位置索引按比例缩小（如 128K/8K = 16 倍），同时调整 base_freq 来补偿，让模型在"等效训练范围内的位置"上工作。YaRN 进一步引入温度缩放和注意力衰减，将 LLaMA 2 的 4K 上下文扩展到 128K 时困惑度仅增加 0.8。这不是完美外推，但是工程上足够好的折中方案。
DeepSeek-V3 的 MLA（Multi-Latent Attention）和 GQA 有什么区别？
GQA 让多组 Query 共享同一组 K/V 头来减少 KV Cache，但 K/V 仍然是完整的向量。MLA 更进一步——它将 K 和 V 联合压缩为一个低维"潜向量"（latent vector），推理时只需缓存这个压缩后的潜向量。具体数字：DeepSeek-V3 的 d_model=7168，GQA 方案下每层 KV Cache 需要 2 × 7168 = 14336 个浮点数/token，而 MLA 的潜向量维度仅为 512+64 = 576，KV Cache 压缩了约 25 倍。在 128K 上下文时，这意味着 KV Cache 从 ~30GB 降至 ~1.2GB。代价是引入了额外的上投影计算，但 MLA 通过精心设计的低秩分解将这部分开销降至最低。
