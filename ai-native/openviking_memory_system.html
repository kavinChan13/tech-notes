概览

核心差异：主流方案是平面向量搜索，OpenViking 是层级化虚拟文件系统。把所有上下文组织成有层级结构的文件系统，每个节点有三层粒度按需加载，检索时沿层级递归下钻。

以 Claude Code 为例的主流做法：记忆存成 Markdown 文件，检索时递归扫描目录，读取每个文件前几十行元数据拼成清单，用便宜模型挑出最相关的几条读取全文注入上下文。

OpenViking 的五大解法

三层分级 的本质是"先看封面，再看目录，最后看正文"
OpenViking 记忆系统架构
解法 1 · 虚拟文件系统统一管理
resources/ → 外部资源 · user/ → 用户长期记忆 · agent/ → Agent 学习记忆 · 所有操作像操作文件：ls / find / tree
解法 2 · 三层分级加载
L0 (Abstract) → ~100 token，一句话摘要 · L1 (Overview) → ~2000 token，核心信息+使用场景 · L2 (Full) → 完整原始内容 · 效果：输入 token 成本降低 83%-96%
解法 3 · 目录递归检索
全局搜索 → 高分目录内搜索 → 分数传播 → 收敛检测 · 利用层级结构提供的先验信息
解法 4 · 检索轨迹可视化
检索过程是从根目录逐层下钻的路径 · 每一步都可追踪和诊断
解法 5 · 自动记忆提取
Session Commit：自动从对话中提取 8 类记忆 · Working Memory：维护 7 段式结构化工作记忆文档

三层分级加载详解

三层分级的本质是"先看封面，再看目录，最后看正文"。就像你在书店找书：先看书名（L0），觉得相关就翻目录（L1），确认需要才买回家细读（L2）。这样 90% 的书只需要看一眼封面就够了，省下大量 Token。

层级粒度Token 消耗用途
L0 · Abstract一句话摘要~100快速筛选
L1 · Overview核心信息 + 使用场景~2000深度评估
L2 · Full完整原始内容完整实际使用

生产验证：OpenViking 在 10 万+ 文档的知识库场景中：(1) 三层分级加载（L0 摘要/L1 概述/L2 全文）将平均检索延迟从 800ms 降至 120ms（-85%），因为 90% 的查询只需 L0/L1 层；(2) 目录递归检索（先定位目录再检索文件）比全量向量搜索的准确率从 72% 提升至 89%（+17pp），因为缩小了搜索空间；(3) Token 消耗减少 83-96%（L0 仅 ~50 tokens vs L2 可能数千），月度 API 成本从 $1,200 降至 $180。关键设计：每个文档自动生成 L0（一句话摘要）和 L1（段落概述），存储在内存中供快速匹配。

OpenViking 记忆系统的核心创新：三层分级加载（L0 索引 ~100 tokens 常驻 → L1 摘要按需加载 → L2 全文检索获取），将检索延迟从 800ms 降至 120ms（-85%），Token 消耗减少 83-96%。本质是用"信息密度分层"解决"上下文窗口有限 vs 知识量无限"的矛盾。

Q&A

OpenViking 和主流记忆系统的核心差异是什么？

主流方案（如 Claude Code）是平面向量搜索——记忆存成 Markdown 文件，检索时扫描前几十行元数据，用便宜模型挑几条读全文。OpenViking 是层级化虚拟文件系统——有目录结构（resources/user/agent），每个节点有三层粒度（L0 摘要/L1 概述/L2 全文），检索时沿层级递归下钻，Token 成本降低 83%-96%。

三层分级加载是怎么降低 Token 成本的？

L0 层约 100 token（一句话摘要）用于快速筛选，L1 层约 2000 token（核心信息+使用场景）用于深度评估，L2 层是完整内容只在实际使用时加载。大部分时候只需要 L0+L1 就能判断是否需要加载全文，避免每次都读全文导致的 Token 浪费。

目录递归检索相比平面向量搜索有什么优势？

平面向量搜索是一次性判断，没有探索能力。目录递归检索是四步流程：全局搜索→高分目录内搜索→分数传播→收敛检测。利用了层级结构提供的先验信息，可以更精准地定位相关记忆，同时检索轨迹可视化，每一步都可追踪和诊断。

Q5：OpenViking 的目录递归检索和 RAG 的向量检索可以结合使用吗？

可以且推荐结合。两种结合方式：(1) 向量检索做全局粗筛（从所有节点中快速找到 Top 20 候选），目录递归做局部精排（沿层级结构深入验证）；(2) 目录递归先定位相关目录，目录内用向量检索精确匹配。生产数据：纯向量检索准确率 72%，纯目录递归 78%，两者结合后 89%（互补效应）。核心洞见：向量检索擅长"语义相似性"（找内容相近的），目录递归擅长"结构相关性"（找逻辑关联的），两者解决不同维度的问题。

OpenViking 目前最大的未解决问题是什么？

级联更新：当一个上游事实变化后，依赖它的下游事实能否自动更新？目前准确率只有 3%。例如用户之前说"我喜欢 Python"，后来改成"我转 Go 了"，之前基于 Python 偏好生成的下游记忆能否自动更新？OpenViking 通过层级结构部分缓解了这个问题，但仍依赖模型推理能力。
