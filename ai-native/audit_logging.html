  • LLM 审计日志的驱动因素：合规（法规强制）、安全（事件追溯）、优化（质量分析）、成本（费用归因）
  • 与传统日志最大不同：内容非结构化、不确定性高、敏感信息密度大
  • 日志本身也是敏感数据——日志的访问控制和加密同样重要

全量记录实现

import hashlib, json, time
from dataclasses import dataclass, field

@dataclass
class AuditRecord:
    event_id: str
    timestamp: float
    request_hash: str
    request_body: dict
    response_body: dict
    usage: dict
    context: dict
    integrity_hash: str = field(init=False)

    def __post_init__(self):
        self.integrity_hash = self._compute_hash()

    def _compute_hash(self):
        payload = json.dumps({
            "event_id": self.event_id,
            "timestamp": self.timestamp,
            "request_hash": self.request_hash,
            "response_body": self.response_body
        }, sort_keys=True)
        return hashlib.sha256(payload.encode()).hexdigest()

class LLMAuditLogger:
    def __init__(self, storage_backend, pii_detector):
        self.storage = storage_backend
        self.pii = pii_detector

    def log_completion(self, request, response, context):
        pii_result = self.pii.scan(request, response)

        record = AuditRecord(
            event_id=generate_uuid(),
            timestamp=time.time(),
            request_hash=hashlib.sha256(
                json.dumps(request).encode()
            ).hexdigest(),
            request_body=self._redact_if_needed(request, pii_result),
            response_body=self._redact_if_needed(response, pii_result),
            usage=response.get("usage", {}),
            context=context
        )

        self.storage.write(record)
        return record

    def _redact_if_needed(self, content, pii_result):
        if pii_result.has_pii:
            return self.pii.redact(content, pii_result.entities)
        return content

防篡改日志设计

防篡改技术方案

方案原理优点缺点
哈希链每条日志包含前一条的哈希值简单高效，篡改即断链单点写入瓶颈
Merkle Tree日志组织为 Merkle 树高效验证、支持批量实现复杂
WORM 存储Write Once Read Many硬件级防篡改成本高、不灵活
数字签名可信时间戳 + 签名法律效力强密钥管理复杂
区块链锚定哈希定期写入公链第三方可验证延迟高、费用

哈希链实现

import hashlib, json

class TamperProofLog:
    def __init__(self):
        self.chain = []
        self.prev_hash = "0" * 64  # 创世哈希

    def append(self, record: dict) -> dict:
        entry = {
            "sequence": len(self.chain),
            "timestamp": time.time(),
            "data": record,
            "prev_hash": self.prev_hash,
        }

        entry["hash"] = hashlib.sha256(
            json.dumps(entry, sort_keys=True).encode()
        ).hexdigest()

        self.chain.append(entry)
        self.prev_hash = entry["hash"]
        return entry

    def verify_integrity(self) -> bool:
        for i in range(1, len(self.chain)):
            current = self.chain[i]
            previous = self.chain[i - 1]

            if current["prev_hash"] != previous["hash"]:
                return False

            expected_hash = hashlib.sha256(
                json.dumps({
                    "sequence": current["sequence"],
                    "timestamp": current["timestamp"],
                    "data": current["data"],
                    "prev_hash": current["prev_hash"]
                }, sort_keys=True).encode()
            ).hexdigest()

            if current["hash"] != expected_hash:
                return False

        return True

class SIEMIntegration:
    def __init__(self, siem_endpoint, api_key):
        self.endpoint = siem_endpoint
        self.api_key = api_key

    def forward_security_events(self, event):
        """将安全相关事件转发到 SIEM 系统"""
        siem_event = {
            "source": "llm-application",
            "event_type": self.map_event_type(event),
            "severity": self.calculate_severity(event),
            "timestamp": event["timestamp"],
            "details": {
                "user": event.get("user_id"),
                "action": event.get("action"),
                "outcome": event.get("outcome"),
                "risk_indicators": self.extract_risk_indicators(event)
            }
        }

        # 转发到 Splunk / Sentinel / QRadar
        self.send_to_siem(siem_event)

    def extract_risk_indicators(self, event):
        indicators = []
        if event.get("pii_detected"):
            indicators.append("pii_in_prompt")
        if event.get("content_filtered"):
            indicators.append("content_safety_triggered")
        if event.get("unusual_token_usage"):
            indicators.append("abnormal_usage_pattern")
        return indicators

class RetentionManager:
    def __init__(self):
        self.policies = {
            "audit_events": {
                "min_retention": "7y",
                "storage_tier_transitions": [
                    {"after": "30d", "to": "warm"},
                    {"after": "1y", "to": "cold"}
                ],
                "deletion": "crypto_shred + deletion_certificate"
            },
            "llm_completions": {
                "min_retention": "6m",
                "storage_tier_transitions": [
                    {"after": "7d", "to": "warm"},
                    {"after": "6m", "to": "cold_or_delete"}
                ],
                "deletion": "secure_delete"
            },
            "user_sessions": {
                "min_retention": "90d",
                "storage_tier_transitions": [
                    {"after": "30d", "to": "warm"}
                ],
                "deletion": "standard_delete"
            }
        }

    def execute_retention(self):
        for data_type, policy in self.policies.items():
            expired = self.find_expired(data_type, policy)
            for batch in expired:
                self.transition_or_delete(batch, policy)
                self.generate_deletion_certificate(batch)

    def handle_deletion_request(self, user_id):
        """处理用户数据删除请求（GDPR 被遗忘权）"""
        user_data = self.find_user_data(user_id)
        for record in user_data:
            if self.is_under_legal_hold(record):
                self.anonymize(record)
            else:
                self.secure_delete(record)
        return DeletionCertificate(user_id=user_id)

LLM 审计日志与传统应用日志有什么本质区别？

五个核心区别：①体量——传统日志每条 KB 级，LLM 日志每条 KB~MB 级（包含完整 prompt 和 response）；②确定性——传统应用相同输入产生相同输出，LLM 由于 temperature 等参数相同 prompt 可产生不同回答，必须记录每次实际输出；③敏感性——LLM 日志高概率包含用户发送的 PII 和业务敏感信息，日志本身就是需要保护的数据；④关联性——传统日志是独立的请求-响应对，LLM 日志需要关联多轮对话链和工具调用链，一个会话可能涉及数十条关联记录；⑤不可预测性——LLM 可能产生幻觉或有害内容，日志需要记录内容安全检测结果用于事后审计。

如何设计防篡改的审计日志系统？

多层防篡改方案：①写入层——使用 WORM（Write Once Read Many）存储，从物理层面阻止修改和删除；②数据层——哈希链技术，每条日志包含前一条的 SHA-256 哈希，形成不可篡改的链式结构，任何修改都会导致后续所有哈希失效；③验证层——定期执行完整性验证，遍历哈希链检查一致性，发现断链立即告警；④外部锚定——定期将 Merkle Root 写入外部系统（如公共区块链或第三方时间戳服务），提供独立的第三方验证能力；⑤访问控制——日志系统与业务系统权限隔离，即使业务管理员也无法修改审计日志。在实践中，通常组合使用"哈希链 + WORM 存储 + 独立验证"三重保护。

如何实现 LLM 应用的 Token 使用量归因和成本分摊？

Token 归因需要在日志中记录多维度上下文：①每次 API 请求记录 prompt_tokens、completion_tokens、total_tokens 和 estimated_cost；②关联上下文信息包括 user_id（用户维度）、team_id（团队维度）、application（应用维度）、model（模型维度）、environment（环境维度）；③聚合计算按日/周/月汇总各维度的 token 消耗和费用；④成本分摊模型可选直接归因（按实际使用量）、共享分摊（公共模型按比例）、预算制（按团队配额）。实现关键点：使用时序数据库（如 ClickHouse、InfluxDB）存储 token 指标，用 Grafana 构建可视化仪表盘，设置 per-team 和 per-user 的阈值告警防止滥用。

LLM 审计日志如何与企业 SIEM 系统集成？

集成方案包括：①事件映射——将 LLM 特有事件（content_filter_triggered、abnormal_token_usage、pii_detected）映射为 SIEM 可识别的安全事件格式（如 CEF/LEEF）；②转发通道——使用 Syslog/Kafka/Webhook 将安全相关事件实时转发到 SIEM（Splunk/Sentinel/QRadar）；③告警规则——在 SIEM 中配置 LLM 特有的告警规则，如"单用户 1 小时内触发内容过滤 > 10 次"、"Token 消耗超过日均 3 倍"、"频繁数据导出"；④关联分析——将 LLM 事件与其他安全数据源（网络、终端、身份）关联，发现更复杂的攻击模式（如先窃取凭据再利用 LLM 提取数据）；⑤不是所有日志都转发到 SIEM——只转发安全相关事件，避免 SIEM 被海量 INFO 日志淹没。

日志保留策略如何应对多法规冲突（如 GDPR 删除权 vs 合规保留要求）？

这是审计日志设计中的经典冲突——GDPR 要求尊重用户删除请求，但合规法规（如 SOX 7 年保留）要求保存记录。解决方案：①匿名化而非删除——对处于合规保留期内的日志，将用户身份信息不可逆匿名化（如替换为 hash），保留事件内容但无法关联到具体用户，既满足"被遗忘"又满足"保留"；②分类处理——将日志数据分为"必须保留"（法定审计事件）和"可删除"（非法定要求的详细日志），删除请求只影响可删除部分；③Legal Hold 机制——正在调查或诉讼中的记录暂不处理删除请求，直到 hold 解除；④删除证书——对确实执行删除的数据生成带时间戳的删除证书，证明合规执行了删除操作。核心原则：在所有适用法规中取最严格的要求，当要求冲突时优先满足强制性保留，用匿名化调和隐私删除需求。
