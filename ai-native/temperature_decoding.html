概览

Temperature 的本质：控制 softmax 分布的'尖锐程度'

Temperature 的本质：控制 softmax 分布的'尖锐程度'。T→0 变成 argmax（只选最大概率），T→∞ 变成均匀分布（完全随机）。

02

Temperature 参数的数学原理

LLM 的最终输出层（LM Head）将隐藏状态投影为词汇表上的 logits，然后通过带温…

2.1 Softmax 与 Temperature

LM Head 把隐藏状态投影成词汇表上的 logits，再由带温度的 Softmax 转成概率：

P(tokeni) = exp(logiti / T) / Σj exp(logitj / T)

T 只出现在指数里的分母上，所以它只拉伸 logit 之间的间距，不改变大小顺序——这条性质是后面所有结论的前提。

2.2 Temperature 对概率分布的影响

Temperature效果概率分布生成行为适用场景
T → 0概率坍缩到最大 logit接近 one-hot确定性输出（Greedy）代码生成、数学推理
T = 0.1~0.3高度集中但保留微小概率极锐利几乎确定，偶有变化翻译、摘要
T = 0.7~1.0保持原始分布平滑平衡质量与多样性通用对话
T = 1.2~1.5分布更平坦更均匀高多样性，可能有噪声创意写作、头脑风暴
T → ∞完全均匀分布均匀完全随机无实用价值

2.3 数值示例：同一 logits 在不同 T 下的概率

import numpy as np

def softmax_with_temp(logits, T):
    if T == 0.0:                       # T→0 的极限：one_hot(argmax)
        out = np.zeros_like(logits); out[logits.argmax()] = 1.0; return out
    z = logits / T                     # 唯一的作用：缩放 logit 间距
    z = np.exp(z - z.max())            # 减最大值 = 数值稳定，不改结果
    return z / z.sum()                 # T→∞ 时 z 全趋近 0，退化为均匀分布

2.4 T=0 的数学极限

把 T 往 0 推，最大的那个 logit 与其余的差距被除以 T 无限放大，指数一压，概率就全部集中到它身上——这就是 lim(T→0) softmax(logits/T) = one_hot(argmax(logits))。纯数学假设下，相同输入必然给出完全相同的输出。后面三章要讲的，正是这个假设在真实硬件上为什么不成立。

根因分析：GPU 浮点精度与"数值蝴蝶效应"

现代 GPU 使用 IEEE 754 标准的浮点数格式进行计算

3.1 IEEE 754 浮点数标准

决定 logit 能分辨多小差距的，不是位宽，而是尾数位：

3.2 浮点数加法不满足结合律

这是 T=0 输出不唯一的根本原因。数学上 (A+B)+C = A+(B+C)，浮点数不然——每一步加完都要舍入一次，先加谁决定了舍掉什么：

>>> import numpy as np
>>> a, b, c = np.float16(1.0), np.float16(4e-4), np.float16(4e-4)
>>> (a + b) + c        # 1.0+0.0004 已无法表示 → 舍回 1.0，再加一次还是 1.0
1.0
>>> a + (b + c)        # 先把两个小数攒成 0.0008，超过间隔 → 留下来了
1.0008
# 判据：FP16 在 1.0 附近的最小间隔是 2^-10 ≈ 0.00098。
# 小于间隔的增量单独加会被整个吃掉，攒在一起加就不会——顺序即结果。

3.3 GPU 并行计算触发非确定性

GPU 把矩阵乘拆成数千个线程并行归约，而它们完成的先后顺序每次都不一样。于是上面那条「顺序即结果」直接生效：

3.4 "数值蝴蝶效应"

当 top-1 和 top-2 的 logit 差距小于该精度能分辨的间隔时，这点末位误差就足以让两者排名反转。而贪心解码只看第一名：

要点是误差本身没有变大，变大的是它的后果：自回归把一次二选一的抖动，放大成整条路径的分叉。

计算场景结果差异影响程度
FP32 矩阵乘法~1e-7 级别通常可忽略
FP16 矩阵乘法~1e-3 级别可导致 logit 排名反转
BF16 矩阵乘法~1e-2 级别影响更大

工业界解决方案

# 方案 1: 检测到 T=0 时直接跳过 softmax，执行 argmax def sa…

四个方案不是四选一，而是作用在链路的不同位置——先看清各自堵的是哪个缺口，再决定组合：

4.1 代码短路：T=0 直接 argmax

argmax 是比较而非累加，只要最大值唯一，末位误差不影响谁最大；同时它绕过 softmax 与随机数，反而更快。这是全部四个方案里唯一「白拿」的：

def sample_token(logits, temperature, top_k=0, top_p=1.0):
    if temperature == 0.0:
        return torch.argmax(logits, dim=-1)     # 确定 + 更快，且忽略 top_k/top_p/seed
    logits = logits / temperature
    logits = apply_top_k_top_p(logits, top_k, top_p)
    return torch.multinomial(torch.softmax(logits, dim=-1), 1)

4.2 锁死随机种子

把 random / numpy / torch（含 cuda.manual_seed_all，多卡要用 all）四处种子一起固定，并关掉 cudnn.benchmark（它会按当次实测速度挑算法，等于引入一个隐藏变量）。局限：它锁的是显式随机源，cuBLAS 内部的归约顺序它管不着。

4.3 提升计算精度

主干保持 BF16，只把 LM Head 的输入转成 FP32 再算 logits。计算量占比不到 5%，却把可分辨间隔从 ~1e-3 推到 ~1e-7——要靠误差翻盘，两个候选得挤进千万分之一以内。llama.cpp 的 --logits-all、vLLM 的 dtype=float32 都是这条路。

4.4 开启 GPU 确定性模式

torch.use_deterministic_algorithms(True) 配上 CUBLAS_WORKSPACE_CONFIG=:4096:8，强制 cuBLAS 走固定归约顺序。这是唯一从根上消除的办法，代价是禁用了一批按运行时状态择优的并行算法，吞吐掉 10–30%。（CUDA_LAUNCH_BLOCKING=1 只用于调试，慢到不能上线。）

策略原理参数效果

5.3 Top-P 与 min-p：让分布自己决定留几个

def apply_top_k_top_p(logits, k=0, p=1.0):
    if k > 0:                                   # top-k：留几个由你定死
        kth = torch.topk(logits, k).values[..., -1, None]
        logits = logits.masked_fill(logits < kth, float("-inf"))
    if p < 1.0:                                 # top-p：留几个由分布自己决定
        s, idx = torch.sort(logits, descending=True)
        probs = s.softmax(-1)
        drop  = torch.cumsum(probs, -1) - probs > p   # 减自身 => 第一名永远留下
        logits = logits.masked_fill(drop.scatter(-1, idx, drop), float("-inf"))
    return logits
# 顺序固定：先 k 后 p。反过来先算的核会被 k 再砍一刀，p 就白设了。

实战代码：完整的带 Temperature 采样器

把前面几章拼起来就是一个可用的采样器。三种惩罚的形状不同，先看清它们各自把 logit 往下压多少：

class Sampler:
    """一次调用走完：惩罚 → 温度 → 截断 → 采样"""
    def __call__(self, logits, history):
        for tid, n in Counter(history).items():          # ① 加减式惩罚
            logits[tid] -= self.presence + self.frequency * n
        for tid in set(history):                         # ② 乘除式惩罚
            r = self.rep if logits[tid] > 0 else 1 / self.rep
            logits[tid] /= r
        if self.T == 0.0:
            return int(logits.argmax())                  # ③ 短路：以下全部跳过
        logits = apply_top_k_top_p(logits / self.T, self.top_k, self.top_p)
        return int(torch.multinomial(logits.softmax(-1), 1))

Q&A

数学上 T=0 等价于 argmax，相同输入必然得到相同输出
Temperature=0 时输出为什么还不唯一？

数学上 T=0 等价于 argmax，相同输入必然得到相同输出。但工程实现中：①GPU 并行计算时线程执行顺序不确定；②浮点数加法不满足结合律——不同累加顺序导致不同舍入误差；③FP16/BF16 精度有限（~3-4 位有效数字），极接近的 logit（如差距 < 1e-4）可能被舍入为相同值；④当 top-1 和 top-2 的 logit 差距小于精度时，GPU 误差可能导致排名反转；⑤贪心解码只选第一名，一旦选错后续路径完全分叉——"数值蝴蝶效应"。工业界解决方案：argmax 短路（绕过 softmax）、FP32 logits（提升精度）、GPU 确定性模式（固定计算顺序）。

Temperature 参数对 LLM 输出有什么影响？

Temperature 控制 Softmax 输出概率分布的"锐利度"。公式：P(i) = exp(logit_i / T) / Σ exp(logit_j / T)。T→0 时概率坍缩到 argmax（确定性输出，适合代码/数学）；T=0.7~1.0 保持原始分布（平衡质量与多样性，适合通用对话）；T>1.2 分布更平坦（高多样性，适合创意写作）；T→∞ 趋向均匀分布（完全随机，无实用价值）。本质上 T 是一个"随机性旋钮"——调高增加多样性但可能引入噪声，调低增加确定性但可能降低创造性。

什么是浮点数的"数值蝴蝶效应"？

数值蝴蝶效应指：极小的浮点计算误差通过自回归生成的逐步放大，导致完全不同的输出文本。具体过程：①两个候选 token 的 logit 值极接近（如差距 1e-5）；②FP16 精度有限（~3-4 位有效数字），将两者舍入为相同值；③GPU 两次运行的浮点误差方向不同，导致排名反转（A 胜出 vs B 胜出）；④贪心解码只关心第一名，一旦首个 token 选错，后续所有生成路径完全分叉；⑤最终输出完全不同的文本。类比混沌理论中的蝴蝶效应——初始条件的微小差异导致结果的巨大差异。工业界通过 argmax 短路和 FP32 logits 来消除这个效应。

Top-K 和 Top-P (Nucleus Sampling) 有什么区别？

Top-K：固定保留概率最高的 K 个 token（如 K=50），其余概率设为 0。优点是简单可控，缺点是 K 是固定的——当概率分布很集中时 K 可能太大（包含低质量 token），当分布很平坦时 K 可能太小（丢失好的候选）。Top-P (Nucleus Sampling)：动态保留累积概率 ≥ P 的最小 token 集合（如 P=0.9）。优点是自适应——分布集中时候选少，分布平坦时候选多，更灵活。实际使用中通常两者组合：先 Top-K 截断（如 K=50），再 Top-P 过滤（如 P=0.9），最后按概率采样。这种组合既有 Top-K 的安全上限，又有 Top-P 的自适应能力。

如何在生产环境中保证 LLM 输出的确定性？

分层保障：①argmax 短路——T=0 时直接执行 argmax 跳过 softmax 和采样，完全确定性，vLLM/TensorRT-LLM 标配；②FP32 logits——LM Head 输出用 FP32 计算，精度从 ~3 位提升到 ~7 位有效数字，代价仅 ~2%；③锁死随机种子——锁定 Python/NumPy/PyTorch 的显式随机源，确保 dropout、采样等可复现；④GPU 确定性模式——torch.use_deterministic_algorithms(True) 强制固定并行计算顺序，但性能下降 10-30%。生产环境推荐组合：argmax 短路 + FP32 logits（性价比最高）。合规审计场景可额外开启 GPU 确定性模式。核心权衡：推理效率 vs 结果一致性。
