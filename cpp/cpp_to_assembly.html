从 C++ 到汇编：亲手观察函数调用

前四篇讲清了「机制」，这一篇动手验证。用 g++ -S 和 objdump 把同一个 add 分别在 -O0 和 -O2 下变成汇编，亲眼看到：优化后栈帧如何缩水、局部变量如何进寄存器、函数如何被内联、call 如何彻底消失。这是把前面所有抽象概念「落地」的一篇。

01

动手准备：g++ -S 与 objdump

两种把 C++ 变成汇编的方式，各有用处

把下面代码存为 demo.cpp：

int add(int a, int b) {
    int c = a + b;
    return c;
}

int main() {
    int result = add(10, 20);
    return result;
}
方式命令看到的是
编译期汇编g++ -S -O0 demo.cpp -o demo.s编译器生成的 .s 文本，带标签/注释，最易读
反汇编目标文件g++ -c demo.cpp && objdump -d demo.o已汇编成机器码后再反汇编，接近最终二进制
更易读的语法g++ -S -masm=intel ...Intel 语法（本文采用，目的操作数在前）
在线工具Compiler Explorer (godbolt.org)源码与汇编并排高亮，改选项实时更新

本文汇编用 Intel 语法（mov dst, src）。GCC 默认输出 AT&T 语法（mov src, dst，寄存器带 %）。两者只是写法不同，指令相同。加 -masm=intel 切到 Intel 风格。不同编译器/版本的具体输出会有差异，属正常。

02

-O0 下的 add：教科书式栈帧

未优化，忠实还原前几篇讲的一切

# g++ -S -O0 -masm=intel demo.cpp
add(int, int):
    push    rbp                # 序言：保存旧帧基址
    mov     rbp, rsp           # 建立本帧锚点
    mov     DWORD PTR [rbp-20], edi   # 参数 a（EDI）落栈
    mov     DWORD PTR [rbp-24], esi   # 参数 b（ESI）落栈
    mov     edx, DWORD PTR [rbp-20]
    mov     eax, DWORD PTR [rbp-24]
    add     eax, edx           # a + b
    mov     DWORD PTR [rbp-4], eax    # c = a + b（局部变量在 [rbp-4]）
    mov     eax, DWORD PTR [rbp-4]    # 返回值放 EAX
    pop     rbp                # 结语：恢复旧帧基址
    ret

对照前面各篇，全部要素都在：序言/结语（02 篇）、参数走 EDI/ESI（04 篇）、返回值走 EAX（04 篇）、局部变量 c 在 [rbp-4]（02 篇）。-O0 就像慢动作回放，把机制一帧不落地演出来。

03

-O2 下的 add：栈帧几乎消失

同一份代码，优化后判若两人

# g++ -S -O2 -masm=intel demo.cpp
add(int, int):
    lea     eax, [rdi + rsi]   # 一条指令算完 a+b 放 EAX
    ret                        # 直接返回

发生了什么？编译器看穿了这个函数的本质：

  • 局部变量 c 消失了 —— 它只是 a+b 的中转，没必要给它内存或寄存器；
  • 没有 push rbp / sub rsp —— add 是叶子函数，不需要栈帧；
  • 参数没落栈 —— 直接从 RDI/RSI 用 lea 相加。

这正是 02 篇与 01 篇反复强调的：「局部变量不一定在栈上」「函数调用不一定有栈帧」—— 这里就是活生生的证据。

lea 为什么能做加法？

lea（Load Effective Address）本用于算地址，但地址计算本身就是「基址 + 变址」的加法。编译器借它一条指令完成加法且不影响标志位，是常见的优化技巧。

04

逐条读懂关键指令

看汇编时最常遇到的这几条，记住即可

指令含义与函数调用的关系
mov dst, src数据搬运装载参数、存取局部变量
lea dst, [..]算地址（也用来做加法）取变量地址、快速算术
push / pop压栈 / 弹栈（RSP ∓ 8）保存/恢复寄存器、建帧
sub rsp, N / add rsp, N开辟 / 释放栈空间为局部变量分配、回收
call f压返回地址 + 跳转进入被调函数（03 篇）
ret弹返回地址 + 跳回返回调用者（03 篇）
leave= mov rsp,rbp; pop rbp拆栈帧（结语）

看 main 的 -O0 调用点，能清楚看到 04 篇讲的传参与 call：

main:
    push    rbp
    mov     rbp, rsp
    sub     rsp, 16
    mov     esi, 20            # 第二个参数 b = 20 → ESI
    mov     edi, 10            # 第一个参数 a = 10 → EDI
    call    add(int, int)      # 调用（压返回地址、跳转）
    mov     DWORD PTR [rbp-4], eax   # result = 返回值(EAX)
    ...
05

-O0 vs -O2 逐行对照

同一段 C++，两种世界

-O0（11 条指令）

push rbp
mov  rbp, rsp
mov  [rbp-20], edi
mov  [rbp-24], esi
mov  edx, [rbp-20]
mov  eax, [rbp-24]
add  eax, edx
mov  [rbp-4], eax
mov  eax, [rbp-4]
pop  rbp
ret

-O2（2 条指令）

lea eax, [rdi + rsi]
ret
方面-O0-O2
栈帧建立完整栈帧无栈帧（叶子函数）
局部变量 c在 [rbp-4]被优化掉
参数先落栈再取全程在寄存器
指令数112
可调试性好（每个变量可见）差（变量常在寄存器/被消除）

这解释了为什么 Release（-O2）版调试时 GDB 常显示 <optimized out> —— 变量根本不在内存里，甚至不存在。所以生产排障常用 -O2 -g（优化 + 保留调试信息）折中。

06

inline 与自动内联：call 直接消失

优化后连「函数调用」这件事本身都可能不存在

把 main 和 add 一起在 -O2 编译，add(10,20) 会被内联并常量折叠：

# g++ -S -O2 -masm=intel demo.cpp （main 部分）
main:
    mov     eax, 30            # add(10,20) 被内联并直接算成 30！
    ret                        # 没有 call add，没有传参

编译器发现 add(10,20) 参数是常量、函数体极短，于是：① 把 add 的代码嵌进 main（inline），省掉 call/ret 与传参；② 进一步在编译期算出 10+20=30（常量折叠）。最终二进制里既没有 add 这个函数、也没有对它的调用。

概念说明
inline 关键字主要是链接语义（允许多个 TU 有定义），是否真内联由编译器决定
自动内联即使不写 inline，-O2 也会内联它认为划算的小函数
不内联的情况函数太大、递归、取了函数地址、跨 TU 且无 LTO、显式 __attribute__((noinline))

想强制看到 call，可用 __attribute__((noinline)) 标注 add，或分文件编译（不开 LTO）。这也提醒我们：「有几次函数调用」是编译期的产物，源码里的调用次数不等于运行时的调用次数。

07

别把某份汇编当成绝对规则

影响输出的因素太多

同一段 C++ 生成的汇编，会随以下任意一项改变：

变量举例
编译器与版本GCC 11 vs GCC 13 vs Clang 17
优化级别-O0 / -O1 / -O2 / -O3 / -Os
目标架构 / ABIx86-64 System V vs Windows x64 vs ARM64
指令集扩展-march=native 会用 AVX 等新指令
其它开关-fomit-frame-pointer、-flto、-fno-inline

所以正确的态度是：把汇编当作「在特定条件下的一个观测结果」，用它去验证机制，而不是背诵某一份固定输出。掌握「怎么生成、怎么读」，比记住某条指令序列重要得多。

08

核心结论

  • g++ -S 看编译器汇编，objdump -d 看反汇编，godbolt 最直观。
  • -O0 忠实呈现栈帧/传参/返回值；-O2 下栈帧可能消失、局部变量入寄存器或被删除。
  • inline 与自动内联能让 call 彻底消失，配合常量折叠函数可被算成一个常量。
  • 「源码里的函数调用」≠「运行时的函数调用」—— 后者是编译优化后的结果。
  • 任何一份汇编都依赖编译器/优化/架构/ABI，只能作为验证机制的样本。
09

常见误区

❌ -O2 只是让代码执行得更快。 它会内联、删变量、消栈帧、常量折叠，从根本上改变代码结构与可调试性。

❌ 源码写了 call，二进制里就有 call。 内联后可能完全没有 call。

❌ inline 一定不会产生函数调用。 inline 只是建议 + 链接语义，是否内联由编译器定；反之不写 inline 也可能被内联。

❌ 某本书里的汇编就是标准答案。 换编译器/优化/架构，输出就变。

❌ 局部变量在汇编里一定看得到。 -O2 下常被优化进寄存器或消除，GDB 显示 <optimized out>。

10

面试问题

基础如何查看一段 C++ 对应的汇编？

g++ -S 生成 .s；或 g++ -c 后 objdump -d 反汇编；或用 Compiler Explorer 在线并排查看。加 -masm=intel 用 Intel 语法。

原理为什么 -O2 后有时候看不到函数调用？

编译器把小函数内联进调用点，省去 call/ret 和传参；若参数是常量还会常量折叠，最终二进制里没有该调用。

原理为什么 -O2 下 add 没有栈帧？

它是叶子函数、局部变量可被消除，编译器判断无需栈帧，直接用寄存器计算并 ret。

汇编lea 为什么能做加法？

lea 计算「基址+变址」地址表达式，本质就是加法，且不改标志位，编译器常借它做快速算术。

汇编inline 一定不会产生函数调用吗？

不一定。inline 主要是链接语义与内联建议；能否内联由编译器决定，递归/过大/取地址等情况仍会真调用。

实战为什么 Release 版 GDB 里变量常显示 optimized out？

优化把变量放进寄存器甚至完全消除，内存里没有对应位置，调试器无法取值。可用 -O2 -g 折中或降优化定位。

实战如何强制让编译器保留某次函数调用以便观察？

给被调函数加 __attribute__((noinline))，或分文件编译且不开 LTO，或降到 -O0。
