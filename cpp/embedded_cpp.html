01

又爱又怕：零成本抽象的边界

哪些抽象真零成本，哪些偷偷收费

"嵌入式只能写 C" 过时了。模板、constexpr、RAII、std::array 真正零运行时开销；异常表、RTTI、隐式 new 则存在即收费。几十 KB Flash 上，这几项固定开销会直接压垮固件。用好 C++ 就是分清免费与收费，把收费项按需关掉或替换。

生活类比：自助餐 vs 单点

桌面 C++ 是自助餐：异常、RTTI、堆、STL 全摆着。MCU 是看钱包单点——模板 / constexpr / RAII 免费；异常表、RTTI、隐式 new 要划掉。划掉之后照样有类型安全和表达力。

映射：钱包=Flash/RAM · 免费菜=模板/constexpr/RAII · 贵菜=异常/RTTI/堆

1.1 特性成本速查

特性运行时成本Flash / RAM 成本MCU 上建议
模板 / constexpr / RAII / enum class零模板可能膨胀大力用，控实例化
虚函数一次间接跳转vtable + 每对象 vptr热路径改 CRTP
异常正常路径近零，抛出很贵大：.eh_frame + unwinder-fno-exceptions
RTTI查表每多态类 type_info-fno-rtti
new / string / vector不确定拖入 malloc静态 / 池
"零成本抽象"完整说法：不用的不付钱；用的手写也不会更省。异常/RTTI 的存在本身就要付表空间——必须显式关掉才真不付钱。
02

-fno-exceptions / -fno-rtti / freestanding

关掉之后能用什么、不能用什么

2.1 三个关键开关

arm-none-eabi-g++ \
  -fno-exceptions \      # 禁异常：throw 变 abort，去掉展开表
  -fno-rtti \            # 禁 RTTI：无 dynamic_cast / typeid 元数据
  -ffreestanding \       # 独立环境：不假设有完整 hosted 标准库/main 约定
  -fno-threadsafe-statics \ # 局部 static 初始化不加锁（单核/自己保证）
  -fno-use-cxa-atexit \  # 不注册全局析构（MCU 通常不会正常退出）
  -Os -ffunction-sections -fdata-sections \
  -Wl,--gc-sections ...

hosted 有 OS、完整标准库、从 main 正常退出。freestanding 只保证不依赖运行时的头（<cstddef> / <array> / <atomic> / <type_traits> / <bit>），启动与退出由你写。MCU 固件就是后者：没有 libc 的 printf 假设，也没有「进程退出再析构」。

2.2 每个禁用特性一份对照

开关关掉什么仍可用必须替代
-fno-exceptionsthrow/catch、.eh_frame虚函数、RAIIexpected / 错误码
-fno-rttidynamic_cast、typeid、type_info虚调用、模板tag / variant / CRTP
-ffreestandinghosted libc 假设上述头文件自己启动；无堆则不必 _sbrk
-fno-threadsafe-statics局部 static 守卫锁单核、构造不进 ISR别在中断里首次构造
-fno-use-cxa-atexit全局析构注册MCU 本来不退出不依赖 atexit
关异常后，本应 throw 的路径走 std::terminate（最终 abort）。vector::at() 越界不再抛而是直接挂——要么彻底不用会抛的 API，要么接受「错误即 fault」并靠看门狗复位。虚函数不受 -fno-rtti 影响：RTTI 只关 dynamic_cast/typeid，多态照常走 vptr→vtable。

2.3 异常与 RTTI 贵在空间

异常正常路径不花周期，但启用就要携带整套展开表和 unwinder——这是空间成本。抛出延迟也不确定，硬实时通常直接 -fno-exceptions。机制见 异常机制。

03

不用异常，错误怎么传

expected / status code / Result 模式

关掉异常后错误随返回值走，控制流可静态分析、可覆盖率统计（这也是 MISRA/AUTOSAR 禁异常、ISO 26262 要确定性的原因）。异常的隐藏跳转和不确定延迟难以论证。

3.1 std::expected（C++23）/ tl::expected

// 值或错误，二选一；调用者被类型系统强制处理
enum class SensorErr { Timeout, CrcFail, NotReady };

std::expected<uint16_t, SensorErr> read_adc(uint8_t ch) {
    if (!adc_ready()) return std::unexpected(SensorErr::NotReady);
    uint16_t raw = adc_convert(ch);
    if (!crc_ok(raw)) return std::unexpected(SensorErr::CrcFail);
    return raw;
}
auto r = read_adc(3);
if (r) use(*r);
else switch (r.error()) { /* 分类处理 */ }

C++23 未齐时用 header-only 的 tl::expected 或小型 union Result。它零堆、可平凡拷贝、无异常；[[nodiscard]] 让漏处理变成编译期可见，比 C 的 errno 安全。

范式优点注意
bool + 出参最省易忽略返回值
enum class Status可穷举、[[nodiscard]]值与错误分开传
expected<T,E>一体、可链式E 别太大
04

无堆编程：静态分配与对象池

禁 new 之后如何组织内存

禁堆：反复 malloc/free 会把空闲区切成不连续小块——总空闲够，也申请不到连续大块（碎片）；分配时间不确定，违背硬实时；失败路径还难写。内存在编译期按最坏情况钉死，比「跑着再找空间」可靠。

有初值的全局在 Flash 里放一份 LMA 副本，启动时拷到 RAM 的 VMA；.bss 只在 RAM 清零，不占 Flash。堆画成虚线：一开就要实现 _sbrk，碎片和不确定延迟立刻回来。

4.1 placement new：静态缓冲里就地构造

// 编译期定容量，全部落在 .bss / 栈，零堆
template <class T, size_t N>
class StaticVec {
    alignas(T) unsigned char buf_[N * sizeof(T)];  // 未构造的原始存储
    size_t n_ = 0;
public:
    bool push_back(const T& v) {
        if (n_ >= N) return false;              // 满 → 返回错误，不抛不扩容
        new (&buf_[n_ * sizeof(T)]) T(v);  // placement new
        ++n_;
        return true;
    }
    // operator[] / size / 析构里逐个 ~T()
};

工程用 ETL 的 etl::vector<T,N> / etl::string<N>；标准库 array / span / optional / bitset 也零堆。需要运行时申请/释放（消息、连接）时用固定大小对象池：N 槽 + 空闲链表，分配释放 O(1)、不碎片——与 低延迟 的 arena 同手段，动机是实时而不是吞吐。

栈从 RAM 顶向下长，和 .bss 抢同一块物理空间；嵌套 ISR 与深递归都吃同一条 MSP（除非用 PSP 拆任务栈）。溢出通常不报错，而是静默踩全局变量。链接脚本里的 _Min_Stack_Size 只是占位警告，真正余量要靠最坏调用深度 + 嵌套 IRQ 算出来。

05

编译期换运行时

constexpr 把工作从 MCU 挪到编译机

MCU 周期贵、编译机随便算：能在编译期确定的就别留运行时。查找表、位掩码、状态机跳转表、协议帧长——结果进 Flash 的 .rodata，运行时一次访存。

做法落点要点
constexpr 生成 sin/CRC 表.rodata（Flash）可在运行时求值；不保险
consteval 算波特率分频编译常量必须编译期；函数中间 throw 会让常量求值失败＝编译报错，即使全局 -fno-exceptions 也不生成运行时抛出。比 static_assert 更能卡在复杂计算中间
位掩码 / 帧长校验Flash非法配置编译不过，不上电才炸

代码体积治理

模板膨胀、vtable、.map 分析

Flash 最紧。C++ 用不好会代码膨胀，尤其模板。治理：度量 → 定位 → 削减。

6.1 度量

命令看什么
arm-none-eabi-size -A firmware.elf.text=Flash 代码，.rodata=常量，.data/.bss=RAM
nm --print-size --size-sort --radix=d最大符号
-Wl,-Map=firmware.map,--cref谁把谁拖进来

6.2 模板膨胀

写法结果
每个 T 一份完整 Ring三种类型 = 三份下标逻辑
非模板 RingBase + 薄模板（thin template / fat base）advance 只编一次；模板只存取 T
用 std::span<T> 传缓冲避免按长度再实例化一份

把模板里不依赖类型参数的逻辑下沉到非模板基类（thin template / fat base），每个实例化就只剩存取 T 的薄壳。std::span<T> 传缓冲，避免按长度再实例化一份；头文件里少做大批显式实例化。

6.3 削减开关

手段作用
-Os / -Oz为体积优化
-ffunction-sections -fdata-sections + --gc-sections丢掉未引用函数/数据
LTO跨 TU 去死代码
-fno-exceptions -fno-rtti去掉展开表与 type_info
newlib-nano；别拖 <iostream>砍 printf / locale

vtable 进 Flash、每对象一个 vptr（通常 4B RAM）。少量多态没问题；给每个小对象都上虚函数会累积。热路径改 CRTP 静态多态，见 设计模式 / 对象模型。

07

MCU 上的并发原语

volatile、atomic 与关中断临界区

MCU 并发主要是中断打断主循环。最常见的错：把 volatile 当原子。

7.1 volatile 对 MMIO vs 错当成原子

// ✅ MMIO：每次访问都必须打到总线
volatile uint32_t* const GPIOA_ODR =
    reinterpret_cast<volatile uint32_t*>(0x4001080C);
*GPIOA_ODR |= (1u << 5);     // 不能被优化掉 / 合并

// ❌ 把 volatile 当原子：++ 是读-改-写三步，ISR 插进来就丢更新
volatile int counter;
void isr() { ++counter; }

// ✅ 标量共享用 atomic；复合状态用极短关中断 RAII
std::atomic<int> counter{0};
保证不保证
volatile每次真的访存（MMIO / 标志）原子性、内存序
std::atomic单标量原子 + happens-before一组变量的一致更新
关中断 RAII复合状态一致临界区一长，中断延迟就上去

counter++ 是读-改-写三步：主循环读到一半被 ISR 改完再写回去，更新就丢。volatile 只保证每步都访存，不保证三步不可分割。单核上 std::atomic 通常无锁、极廉价；一组变量要一起改，用极短的关中断 RAII——和 Linux 驱动 spin_lock_irqsave 同构。内存序见 内存模型。

与 C 驱动 / HAL 互操作

extern "C"、ISR、启动代码里的 C++

厂商 HAL 是 C。对接三件事：启动顺序、向量表 C 名字、指定段。

步骤漏了会怎样
设 SP（向量表第 0 项）立刻 HardFault
复制 .data有初值的全局全错
清 .bss未初始化全局是垃圾
__libc_init_arrayC++ 全局对象没构造

8.1 把对象钉进指定段

// 链接脚本把 .ccmram 钉到 CPU 紧耦合 RAM
[[gnu::section(".ccmram")]] static uint8_t pool[4096];

/* MEMORY { FLASH(rx): ORIGIN=0x08000000, LENGTH=256K
            RAM(rwx):  ORIGIN=0x20000000, LENGTH=64K
            CCM(rwx):  ORIGIN=0x10000000, LENGTH=64K }
   SECTIONS { .ccmram (NOLOAD) : { *(.ccmram) } > CCM } */

C++ 会把参数类型编进符号名（name mangling），C 不会。向量表、HAL 回调、链接脚本都按 C 名字找符号，ISR 必须 extern "C"，否则链接到一个不存在的修饰名。头文件用 #ifdef __cplusplus extern "C" { 包一层即可 C/C++ 共用。

链接脚本的 MEMORY 声明 Flash / RAM / CCM 窗口；SECTIONS 把输入段钉进去。[[gnu::section(".ccmram")]] 只是给对象贴标签，真正落点仍由脚本决定。DMA 缓冲、高速对象池常要钉到紧耦合 RAM，别让链接器随便丢进主 SRAM。

跨 TU 全局构造顺序未定义；少用带副作用的全局，改显式 init()。启动务必跑 __libc_init_array。ISR 只置标志，活丢回主循环或 RTOS 任务。

收串口行并解析string += + stoi（堆、会抛）调用方 span + from_chars + expected

动态性能压到编译期就压：已知集合用 tuple/数组、有限类型用 variant（无堆多态）、必须真多态才上虚函数或 CRTP。堆和异常是最后手段，不是默认选项。

10

高频面试题

嵌入式 C++ 岗常考

点击每道题展开参考答案（先自测，再对照）。

  1. 中级嵌入式为什么常关异常？关了之后错误怎么传？

    异常的空间成本是关键：启用它就要携带展开表（.eh_frame/.gcc_except_table）和 unwinder 代码常驻 Flash，几十 KB 固件里往往不可接受；且抛出延迟不确定，不满足硬实时确定性。关掉（-fno-exceptions）后用显式返回值传播错误：std::expected<T,E>（值/错误一体、类型安全、零堆）、enum class 错误码 + [[nodiscard]]，或 bool+出参。功能安全语境还要求控制流可静态分析，这也是禁异常的理由。

  2. 基础volatile 能保证原子性和线程/中断安全吗？

    不能。volatile 只保证"每次访问真的读写内存、不被编译器优化掉/缓存到寄存器"，用于 MMIO 寄存器和被 ISR 改的标志。它不保证原子性（counter++ 是读-改-写三步，会丢更新），也不建立内存序。要原子性/同步用 std::atomic，或关中断的 RAII 临界区来保护复合操作。

  3. 中级-fno-rtti 会影响虚函数吗？RTTI 关掉后什么不能用？

    不影响虚函数——虚调用只需 vptr→vtable 的间接跳转，与 RTTI 无关。-fno-rtti 去掉的是每个多态类的 type_info 元数据，因此 dynamic_cast（向下/交叉转换）和 typeid 不能用。需要"运行时区分类型"时改用带 tag 的基类、std::variant + visit，或 CRTP 静态多态。

  4. 基础MCU 上为什么禁堆？不用 new 怎么管理内存？

    堆有三宗罪：碎片化（长跑后大块申请失败）、分配时间不确定（违背实时）、失败处理复杂。替代方案：编译期固定容量容器（std::array、ETL 的 etl::vector<T,N>）、栈/.bss 静态分配、对象池（预分配 N 槽 + 空闲链表，O(1) 且不碎片）、placement new 就地构造。核心是把内存在编译期/启动期按最坏情况定好。

  5. 高级怎么减小 C++ 固件的代码体积？模板膨胀怎么治？

    先度量（size -A、nm --size-sort、链接 .map）定位大符号。开关：-Os/-Oz、-ffunction-sections -fdata-sections+--gc-sections、LTO、-fno-exceptions -fno-rtti、newlib-nano、别拖 <iostream>。模板膨胀用"thin template / fat base"——把不依赖类型参数的逻辑下沉到非模板基类只编一次；用 std::span 替代按长度模板；控制显式实例化数量。多态开销大时用 CRTP 去掉 vtable/vptr。

  6. 基础extern "C" 干什么用？ISR 为什么要它？

    C++ 有 name mangling（把参数类型编进符号名以支持重载），C 没有。中断向量表、HAL 回调、链接脚本引用的符号都按 C 名字查找，若 ISR 用 C++ 修饰名，向量表就链接不到正确符号。extern "C" 关掉修饰，让符号名和 C 一致。头文件里用 #ifdef __cplusplus extern "C" { 包住供 C/C++ 共用。

11

checklist 与小结

把现代 C++ 安全落到 MCU 的自检清单

  • 编译开关：-fno-exceptions -fno-rtti -ffreestanding -Os -ffunction-sections -fdata-sections -Wl,--gc-sections。
  • 错误传播用 expected<T,E> / enum class 错误码 + [[nodiscard]]，不靠异常。
  • 禁堆：固定容量容器（std::array / ETL）、对象池、placement new；禁 vector/string/make_unique。
  • 能编译期算的绝不留运行时：constexpr/consteval 查找表、位掩码、编译期配置校验。
  • 共享数据：单标量 std::atomic；复合操作用关中断 RAII 临界区（极短）；volatile 只给 MMIO/标志，不当同步用。
  • 多态按需：热路径/大量小对象用 CRTP 静态多态；真多态才上虚函数；无堆多态用 std::variant。
  • 与 C/HAL 对接：ISR 和向量表符号用 extern "C"；ISR 里只置标志、活丢回主循环/任务。
  • 启动代码确认调用 __libc_init_array（否则全局对象不构造）；少用带副作用的全局对象。
  • 持续度量体积：size / nm / .map 纳入 CI，防止 Flash 悄悄超标。
一句话总结：现代 C++ 完全能上 MCU——把异常/RTTI/堆这几样"收费项"关掉或替换，把计算尽量前移到编译期，用类型系统和 RAII 换来安全，你就得到"和手写 C 一样省，却更安全、更表达"的固件。
