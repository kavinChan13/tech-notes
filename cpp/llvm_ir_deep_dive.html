LLVM IR 深入

LLVM IR 是类汇编 + 强类型 + SSA 的编译器中枢：Clang 编进来，opt 在上面跑 Pass，后端降到机器码。这篇用图讲清 SSA / phi / alloca / LTO，再用最短 IR 把指令语义钉死——面向静态分析、插桩、自定义优化。

核心难度 ★★★★☆ 面试出现率 中 阅读时长 ~5 min 前置 编译流程基础

01

为什么是 LLVM IR

跨语言 / 跨平台的中枢 · 三种形态等价

LLVM IR 夹在源码和机器码之间：类汇编、强类型、SSA。C / Rust / Swift 编到同一 IR；x86 / ARM / RISC-V / WASM / GPU 后端吃同一 IR；AOT、JIT、静态分析、sanitizer 插桩也在这一层做。和 GCC GIMPLE 不同，外部工具能直接 emit / parse / transform。

形态扩展名用途
Textual IR.ll人读 · godbolt · 调试
Bitcode.bc紧凑；LTO 时塞进 .o
In-memory—llvm::Module，跑 pass 时
02

IR 解剖学

最短函数 · 指令表 · alloca / load-store · O0 vs O2 · CFG

嵌套四层：Module（一个翻译单元）⊃ Function ⊃ BasicBlock（直通指令序列，只能末尾跳转）⊃ Instruction。

最短函数：alloca / store / load / ret

O0 把局部变量放栈上。吐 IR：clang -S -emit-llvm -O0 inc.c -o inc.ll。

; int inc(int a) { int x = a; x = x + 1; return x; }
define i32 @inc(i32 %a) {
entry:
  %x = alloca i32, align 4     ; 栈槽；放 entry 才能 mem2reg
  store i32 %a, ptr %x         ; 写入
  %0 = load i32, ptr %x        ; 读出
  %1 = add i32 %0, 1
  store i32 %1, ptr %x
  %2 = load i32, ptr %x
  ret i32 %2
}
指令语义
alloca开栈槽，返回 ptr；仅 entry 且不逃逸可 mem2reg
store / load类型写在指令上，不在指针上
ret / br返回 / 跳转（带 i1 则条件）
icmp / fcmp比较 → i1
add / mul / …新 SSA 名，从不改旧名
phi / select按前驱选值 / 无跳转二选一
call / getelementptr按 calling conv 传参 / 只算地址
🧬 交互式演示：max(a,b) 从 C++ 一路降到汇编
点阶段或「下一步」：同一函数从 C++ 降到 IR、SSA、select、x86。口述 → 提纲 → 一句话 → 对方母语。

03

SSA 与 Phi 节点

只赋值一次 · phi 在块顶

SSA：每个名字只赋值一次。def-use 变成一张图上的唯一边，GVN / LICM / DCE 都靠这个前提。源码里「同一个 x 写两次」，IR 里必须换成 %1、%2。
SSA 像快递单号——每个包裹只贴一次。phi 是分拣口：看货从哪条传送带来，就取那条边上的值。
; 源码：x = 1;  x = x + 1;   —— 两次赋值，SSA 禁止改旧名
%1 = add i32 0, 1      ; 第一次赋值 → %1
%2 = add i32 %1, 1     ; 再写 x 必须换 %2；%1 永远不变
ret i32 %2

汇合点：phi

两条前驱都给 x 赋值时，merge 块顶用 phi：按进来的那条边选值。phi 只能出现在块顶。

entry:
  br i1 %cond, label %T, label %F
T:
  br label %M
F:
  br label %M
M:
  %x = phi i32 [ 1, %T ], [ 2, %F ]
  ret i32 %x

SSA 只管函数内的寄存器值。逃逸对象、global、heap 仍是内存；跨函数要 IPA / LTO。

04

类型系统

强类型 · opaque ptr · poison · inbounds GEP

每个 value 都有类型，对不上就是非法 IR。整数无符号性不在类型上，而在 add vs add nsw / udiv vs sdiv 这些算子上。

类型含义
i1 … i128 / iN定宽整数；符号由指令决定
half / float / double浮点
ptrLLVM 16+ 唯一指针类型（opaque）
{i32, double} / [10 x i32] / <4 x float>结构 / 数组 / SIMD 向量
i32 (i32, ptr)函数类型
label / token / void块标签 · 协程/异常令牌 · 无返回

LLVM 16+ 指针一律 ptr，pointee 类型写在 load / store / GEP 上。写 pass 不能再问「这个指针指向什么」，要看 use site。

05

Metadata + Attribute

TBAA · function attributes · calling conv

指令旁边可以挂 metadata；函数/参数/返回值可以挂 attribute。两者都是给优化器的保证，写错等于撒谎，会生成错码。

06

Pass 流水线深入

NewPM 嵌套 · LTO · 常用命令

每个 pass 只干一件事。-O2 大约 150 个，-O3 再多二三十。Transform 改 IR，Analysis 只产信息（DominatorTree / LoopInfo / AA）；LICM 这类 transform 靠后面那批分析。

LLVM 13+ 默认 NewPM（CRTP，比 legacy 虚调用快一截，支持嵌套管线）。自己写 pass 就继承 PassInfoMixin<T> 实现 run()。

命令用途
clang -S -emit-llvm -O0 a.c -o a.ll吐 textual IR
clang -c -emit-llvm a.c -o a.bc吐 bitcode（LTO 进 .o）
opt -passes='mem2reg,instcombine' -S a.ll跑指定 pass
opt -passes='default<O2>' -print-pipeline-passes列出 -O2 管线
opt -O2 -print-after=gvn看某 pass 之后的 IR
opt -O2 -opt-bisect-limit=N二分定位引入 bug 的 pass
opt -time-passes哪个 pass 慢
opt -load-pass-plugin=… -passes=call-counter跑自己的插件
07

7 个关键优化 Pass 内部

Inliner · mem2reg · GVN · LICM · SROA · Vectorize · InstCombine

真正拉开 -O0 和 -O2 的是这七个；其余上百个多半是清理工。

Pass干什么卡点
Inliner函数体替换 call小函数 / 常量实参；后续优化前提
mem2regentry 不逃逸 alloca → SSA没它 GVN/LICM 空转；见 §3
GVN等价表达式同一编号MemorySSA + AA 还能消 load
LICM循环不变量外提AA 说重叠就停
SROA聚合拆 scalar 再 mem2reg没它小对象全走栈
LoopVectorize无依赖循环 → SIMD要 noalias、可数迭代
InstCombine局部 peephole每个 transform 后都跑

7.1 Inliner — 函数体替代 call

自底向上，先 inline 叶子，才能把常量实参送进被调函数的 IR。

7.2 mem2reg — 栈槽提升到 SSA

只提升 entry 块、不逃逸、完整 load/store 的槽。图见 §2 / §3。

7.3 GVN — 等价表达式编号

GVN 前 · 算了两遍
%a = add i32 %x, %y
%b = add i32 %x, %y
%c = mul i32 %a, %b
GVN 后 · 公共子表达式删掉
%a = add i32 %x, %y
%c = mul i32 %a, %a      ; %b 消失

同一地址、中间无 clobber 的 load 也能消。

7.4 LICM — 循环不变量外提

提到 preheader；AA 含糊就停。

7.5 SROA — 聚合拆标量

C++ 小对象和返回值槽靠它进寄存器。

7.6 Loop Vectorizer

打成 <8 x float>，后端再变成 AVX/NEON。

7.7 InstCombine

x+x→shl、x-x→0。自己几乎不加速，给 GVN 提供干净 IR。

08

写自己的 Pass

NewPM 插件 · IRBuilder 插桩

最快的理解路径：写一个 NewPM 插件。分析 pass 返回 PreservedAnalyses::all()；改 IR 的返回 none()，逼着 PM 重算分析。

API作用
PassInfoMixin<T>NewPM 插件基类（CRTP）
run(Function&, FAM&)每个函数调一次；循环两层 BB → Instruction
isa<CallInst> / dyn_cast识别 / 转型指令
llvmGetPassPluginInfo动态库入口，用 -passes=名字 挂上
IRBuilder<>在某条指令前插入新 IR
Module::getOrInsertFunction声明运行时钩子（__asan_report 那一类）

Sanitizer、coverage、profiler 的核心就是最后两行：在 call 前 IRBuilder 再插一个 call @__my_log。编译：opt -load-pass-plugin=libMyPass.so -passes=call-counter。细节见 Sanitizer 内部。

09

调试 Pass

print-after · opt-bisect · FileCheck

命令已收进 §6 那张表。这里只补判据：

  • -print-after=gvn 看某一个 pass 之后的 IR；-print-after-all 会炸日志。
  • -opt-bisect-limit=N：bug 还在就降 N，没了就升 N，锁定那个引入回归的 pass。
  • 单测用 llvm-lit + FileCheck：; RUN: opt -passes=instcombine -S %s | FileCheck %s，然后 ; CHECK-NEXT: 钉住改写后的 IR。测的是「(x+x)+(x+x) 变成 x*4」这类局部契约。
10

Contribute LLVM

Build · 第一份 patch · 社区

LLVM 约千万行 C++。入门路径：good-first-issue → 带 FileCheck 的 .ll 测试 → ninja check-llvm → PR。3–5 个 merged PR 可申请 commit access，仍要 review。

步骤要点
构建cmake -S llvm -B build -G Ninja -DLLVM_ENABLE_PROJECTS="clang;lld" -DLLVM_TARGETS_TO_BUILD="X86;AArch64"，首次 30–60 min
测试llvm/test/ 下加 .ll + FileCheck；跑 ninja check-llvm
社区Discord / Discourse RFC / 每年 Dev Meeting / Kaleidoscope tutorial
关键 take-aways
  • IR 是中枢；LTO 把链接也放在这一层。
  • SSA 一名字一赋值，汇合用 phi；mem2reg 只提升 entry 里不逃逸的 alloca。
  • !tbaa / noalias 是契约，写错会生成错码。插桩 = IRBuilder 再插 call。
