GDB 调试 C++ · 系列 04 / 06

Memory / Register / Assembly：深入程序底层

当变量层面看不出问题（栈损坏、优化后变量消失、崩在库函数里没有源码），就必须下探到内存、寄存器、汇编这一层。这一篇把 x、info registers、disassemble 三件底层利器讲清楚，并建立 C++ 代码 ↔ 汇编 ↔ 寄存器 ↔ 内存 的对应关系 —— 把前面「函数调用、栈帧、ABI」的知识，用 GDB 亲眼验证一遍。

适用条件先说清楚

本篇几乎所有寄存器名（RIP/RSP/RBP/RDI…）与汇编示例都基于 x86-64 + Linux System V ABI。换到 ARM64（x0–x30 / sp / pc / lr）或 Windows x64，寄存器名与调用约定不同，但「代码 ↔ 汇编 ↔ 寄存器 ↔ 内存」的分析思路完全通用。寄存器分配还受编译器与优化级别影响。底层约定详见 Calling Convention / ABI。

01

为什么要下探到内存与寄存器

源码级调试失效时，机器级真相还在

大部分时间你在「变量层面」调试就够了。但有几种情况，变量层面会失灵：

  • 栈被破坏：越界写、栈溢出把返回地址覆盖了，bt 显示乱码 —— 只能去看内存里的栈到底被写成了什么；
  • 优化后变量消失（<optimized out>）：源码里看不到，但值其实就在某个寄存器里；
  • 崩在没有源码的库函数里：只能看汇编和寄存器判断当时在干什么；
  • 怀疑是 ABI / 传参 / 对齐问题：必须核对寄存器和栈的实际内容。
一句话

源码是「程序应该怎么跑」，内存和寄存器是「程序此刻真的怎么跑」。当两者对不上，真相永远在后者。这一层是 C++、嵌入式、系统软件工程师的必修 —— 也是把前面栈帧/ABI 知识落地的地方。

沿用最小例子（g++ -g -O0 addmem.cpp -o addmem）：

int add(int a, int b) { return a + b; }
int main() { int r = add(10, 20); return r; }
02

x 命令：查看内存的瑞士军刀

examine —— 把任意地址的字节按你要的格式解释出来

x（examine）是「读内存」的通用命令。它的语法核心是 x/NFU 地址：

N — 数量
要显示几个单位，如 10、16
F — 格式
x 十六进制 / d 十进制 / i 指令 / s 字符串 / c 字符 / u 无符号 / f 浮点 / a 地址
U — 单位
b 字节(1) / h 半字(2) / w 字(4) / g 巨字(8)
(gdb) x/10x &arr      # 从 arr 起，10 个单位，十六进制
(gdb) x/10d &arr      # 同上，但十进制显示
(gdb) x/10i $pc       # 从当前指令起，反汇编 10 条指令
(gdb) x/s msg         # 把 msg 当 C 字符串打印
(gdb) x/16gx $rsp     # 从栈顶起，16 个 8 字节，十六进制（看栈常用）
x 与 print 的分工

p 面向「有类型的变量/表达式」（它知道 user 是个 User）；x 面向「一段裸地址的原始字节」（它不管那里是什么，按你给的格式硬解释）。排查栈损坏、看原始内存布局、反汇编时用 x；看具体变量值用 p。GDB 会记住上次的 N/F/U，直接敲 x 可继续往后看下一段。

03

x/16gx $rsp：观察当前栈

把这条命令拆开，你就理解了「看栈」

(gdb) x/16gx $rsp
片段含义
xexamine，查看内存
16数量：看 16 个单位
g单位：giant word = 8 字节（64 位一个「格」）
x格式：十六进制
$rsp起始地址：栈顶（栈指针寄存器）

合起来就是：从栈顶开始，以 8 字节为单位，用十六进制打印 16 个格 —— 也就是「把当前栈顶往下的 128 字节，按 64 位对齐排出来看」。这是查看栈布局、找返回地址、诊断栈溢出的标准动作。

(gdb) x/16gx $rsp
0x7fffffffe0a0: 0x0000000000000014  0x00007ffff7...   # 局部/保存值
0x7fffffffe0b0: 0x00007fffffffe0d0  0x0000555555555169 # 旧RBP、返回地址
...
看到栈内容之后怎么分析

栈里最值得关注的是返回地址（第 06 篇实战会用到）。正常情况下它应指向调用者代码段的合理地址；如果这里变成 0x4141414141414141（ASCII 的 AAAA…）或其他被写乱的值，几乎可以断定栈缓冲区溢出覆盖了返回地址 —— 这类问题 bt 会直接崩溃或乱码，只有看内存才看得清。g（8 字节）是 64 位下看栈的正确单位；用 w（4 字节）会把地址切成两半，读起来会错乱。

04

寄存器：info registers 与关键寄存器

CPU 内部的高速工作台

(gdb) info registers      # i r —— 打印所有通用寄存器
rax  0x1e  30
rbx  0x0   0
...
rip  0x555555555159  0x555555555159 <add+16>
(gdb) info registers rax   # 只看某几个
(gdb) p $rax               # 也能用 p 读寄存器（$ 前缀）
(gdb) p $rsp               # 栈顶
(gdb) p/x $rbp             # 帧基址，十六进制
寄存器典型用途（System V ABI）
RAX返回值；部分指令的累加器
RBXcallee-saved 通用寄存器
RCX / RDX第 4 / 第 3 个整型参数；部分指令专用
RDI / RSI第 1 / 第 2 个整型参数
R8 / R9第 5 / 第 6 个整型参数
RSP栈指针（指向栈顶）
RBP帧基址指针（指向当前栈帧基准）
RIP指令指针（下一条要执行的指令地址）
p $rax 与 info registers

info registers 一次看全貌；p $reg 精确取某个、还能参与表达式（p $rsp - $rbp 算当前帧大小、x/i $rip 反汇编当前指令）。寄存器名前的 $ 是 GDB 约定，别漏写。

05

RIP / RSP / RBP 各代表什么

这三个是调试底层时最该盯的寄存器

RIP（Instruction Pointer）—— 「现在执行到哪」
指向下一条即将执行的指令。程序崩溃时，RIP 就是「出事那一刻 CPU 想执行的地址」。若 RIP 指向一个非法/不可执行地址（如 0x0），通常意味着跳转目标被破坏 —— 比如通过野函数指针调用、或返回地址被覆盖后 ret 跳飞。

RSP（Stack Pointer）—— 「栈顶在哪」
始终指向当前栈顶。push 让它减小、pop 让它增大（x86-64 栈向低地址增长）。call 会把返回地址压入、RSP 自动 −8。想看当前栈就 x/…gx $rsp。

RBP（Base Pointer / Frame Pointer）—— 「当前帧的锚点」
指向当前栈帧的基准位置，函数序言里 push rbp; mov rbp, rsp 建立，局部变量和参数常以 RBP 为基准用固定偏移访问（如 [rbp-4]）。它还串起「上一帧的 RBP」，让 bt 能逐帧回溯。注意：-O2 或 -fomit-frame-pointer 下 RBP 可能被省去当普通寄存器用，此时 GDB 靠 DWARF CFI 信息回溯栈，而非靠 RBP 链 —— 详见 栈帧深入。

RIP → 下一条指令地址（执行到哪）
RSP → 栈顶（栈长到哪）
RBP → 当前帧基准（局部变量的锚）
06

Assembly：disassemble / layout asm

把当前函数还原成 CPU 真正执行的指令

(gdb) disassemble         # 反汇编当前函数，→ 标出当前 RIP 所在指令
Dump of assembler code for function add(int, int):
   0x...49 <+0>:   push   %rbp
   0x...4a <+1>:   mov    %rsp,%rbp
   0x...4d <+4>:   mov    %edi,-0x4(%rbp)   # a 存栈
   0x...50 <+7>:   mov    %esi,-0x8(%rbp)   # b 存栈
=> 0x...53 <+10>:  mov    -0x4(%rbp),%edx   # => 当前执行位置
   0x...56 <+13>:  mov    -0x8(%rbp),%eax
   0x...59 <+16>:  add    %edx,%eax        # a + b
   0x...5b <+18>:  pop    %rbp
   0x...5c <+19>:  ret

(gdb) disassemble /m       # 源码行与汇编交错显示（/s 是新版更佳选项）
(gdb) x/i $rip             # 只看当前这一条指令
(gdb) layout asm            # TUI：开一个汇编窗口，单步时高亮跟随
(gdb) layout regs           # TUI：同时看寄存器窗口
看汇编的正确姿势

不需要读懂每一条指令。抓三件事：①函数序言/结语（push rbp / ret 标出边界）；②内存读写（mov 与 [rbp-x] 对应局部变量）；③控制流（call / jmp / je 决定走向）。配合 stepi/nexti 逐指令走、layout asm 高亮跟随，能看清「这一行 C++ 到底编译成了哪几条指令」。

07

串起来：add(a,b) 的参数→寄存器→call→ret

用 GDB 把整套函数调用底层机制走一遍

把前面几篇的原理，用 GDB 在 add(10,20) 上验证成一条闭环：

参数：main 把 10→EDI、20→ESI（info registers 可见）
call add：返回地址压栈，RSP−8，RIP 跳到 add
序言：push rbp; mov rbp,rsp 建栈帧（disassemble 可见）
执行：add %edx,%eax，结果进 EAX
返回值：RAX=30（p $rax 验证）
ret：从栈弹出返回地址→RIP，RSP 复原，回到 main
# 一次完整观察脚本
(gdb) break add
(gdb) run
(gdb) info registers rdi rsi   # 看传进来的参数（低 32 位 edi/esi = 10/20）
(gdb) x/gx $rsp                 # 栈顶就是刚压入的返回地址
(gdb) disassemble               # 看 add 的指令，找到 ret
(gdb) finish                    # 执行完，观察返回值
Run till exit from #0 add (a=10, b=20)
Value returned is $1 = 30           # 就是 RAX 里的值
(gdb) p $rax
$2 = 30
这就是把知识「串起来」

到这里，函数调用发生了什么、栈帧、CALL/RET、ABI 四篇讲的抽象机制，都能在 GDB 里被你亲手观测出来：参数确实在 RDI/RSI，返回地址确实在栈顶，返回值确实在 RAX。调试底层的终极价值，就是把「书上说的」变成「我看到的」。

08

核心结论 + 常见误区

  • x/NFU 地址：N 数量、F 格式、U 单位；看裸内存用 x，看有类型变量用 p。
  • x/16gx $rsp = 从栈顶起、16 个 8 字节、十六进制，看栈的标准动作。
  • 三个关键寄存器：RIP 执行到哪、RSP 栈顶、RBP 帧基准。
  • disassemble + stepi + layout asm 看清一行 C++ 对应的指令。
  • 能用 GDB 验证：参数在 RDI/RSI、返回地址在栈顶、返回值在 RAX。

❌ 看栈用 x/16wx（4 字节单位）。 64 位下地址是 8 字节，应该用 g；用 w 会把每个地址劈成两半，读起来全错。

❌ RBP 一定指向帧基址。 -O2 / -fomit-frame-pointer 下 RBP 可能被当普通寄存器用，此时靠 DWARF CFI 回溯栈。

❌ RIP 就是「当前正在执行的指令」。 严格说它指向下一条将执行的指令。

❌ 寄存器名不用加 $。 GDB 里必须写 $rax / $rsp，否则会被当成程序里的符号。

09

面试问题

点击每道题展开参考答案（先自测，再对照）。

  1. 基础如何查看寄存器？

    info registers（缩写 i r）打印全部通用寄存器；info registers rax rsp 看指定的；也可用 p $rax 读单个并参与表达式。寄存器名前要加 $。

  2. 基础如何查看当前栈？x/10gx $rsp 怎么理解？

    用 x 从栈顶 $rsp 开始读内存。x/10gx $rsp = 显示 10 个（10）8 字节单位（g）、十六进制（x），即从栈顶往下 80 字节按 64 位对齐排列，用于查看栈布局、返回地址、诊断栈溢出。

  3. 基础如何查看汇编？

    disassemble 反汇编当前函数并用 => 标出当前指令；disassemble /s 源码与汇编交错；x/i $rip 看当前单条指令；layout asm 开 TUI 汇编窗口单步跟随。

  4. 原理RIP、RSP、RBP 分别代表什么？

    RIP 是指令指针，指向下一条将执行的指令；RSP 是栈指针，始终指向栈顶；RBP 是帧基址指针，指向当前栈帧基准，局部变量常以它为基准偏移访问，并串起栈帧回溯链。

  5. 原理x 和 print 有什么区别？

    print 按变量/表达式的类型语义打印（知道对象结构）；x 把一段地址的原始字节按你指定的 N/F/U 硬解释，不关心类型。看具体变量用 p，看裸内存/栈/反汇编用 x。

  6. 进阶怎么用 GDB 验证「参数走寄存器、返回值在 RAX」？

    在函数入口断点，info registers rdi rsi 看到前两个整型参数；x/gx $rsp 看到 call 压入的返回地址；finish 或 p $rax 看到返回值。这样把 System V ABI 的传参/返回约定实测一遍。

  7. 进阶崩溃时 RIP 指向 0x0 或乱码说明什么？

    说明控制流被破坏：可能是空/野函数指针调用，或返回地址被栈溢出覆盖后 ret 跳到非法地址。此时结合 x/gx $rsp 看栈顶返回地址是否被写乱，往往能定位是哪次越界写破坏了栈。
