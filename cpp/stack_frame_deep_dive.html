Stack Frame：函数调用时栈到底发生了什么？

上一篇建立了「函数调用要解决 6 个问题」的全景。这一篇把镜头对准其中最核心的载体 —— 栈帧。我们会讲清 RSP / RBP 到底指向哪、函数进入与退出时栈如何变化、局部变量怎样映射到栈空间，以及优化选项如何让「教科书里的标准栈帧」变形甚至消失。

01

栈是什么，栈指针 RSP 是什么

先分清「栈这块内存」和「指向它的那个寄存器」

栈（Stack）

栈是每个线程独有的一段连续内存，由操作系统在线程创建时分配（Linux 默认主线程 8 MB）。它专门服务函数调用，特点有二：

  • 后进先出（LIFO）：只在一端「压入 / 弹出」；
  • 向低地址增长：x86-64 上「压栈」使地址变小，「弹栈」使地址变大。

栈指针 RSP（Stack Pointer）

RSP 是一个专用寄存器，永远指向当前栈顶（即最后被压入的数据）。它就是 CPU 眼里「栈现在到哪儿了」的唯一标记：

指令对 RSP 的影响含义
push raxRSP -= 8，再写入压 8 字节，栈往低地址长
pop rax读出，再 RSP += 8弹 8 字节，栈往高地址缩
sub rsp, 32RSP -= 32一次性开辟 32 字节局部空间
call fRSP -= 8（压返回地址）见 03 篇

关键直觉：RSP 减小 = 栈变大（占用更多空间）。这与「地址越小、栈越深」的方向一致，初学时容易反过来记，务必掰正。

02

栈帧与帧指针 RBP（Frame Pointer）

RSP 一直在动，于是需要一个「不动的锚点」来定位当前帧

栈帧（Stack Frame）

每一次函数调用，都会在栈顶「长」出属于它的一块区域，这就是栈帧（也叫 activation record）。它容纳这次调用的：返回地址、被保存的寄存器、局部变量、以及可能溢出的参数与临时数据。

帧指针 RBP（Frame Pointer / Base Pointer）

函数体执行时，RSP 会因为不断 push/pop 而变化。如果所有局部变量都用「相对 RSP 的偏移」来定位，偏移量会随代码执行不断改变，既难生成也难调试。于是引入一个在函数执行期间保持不变的锚点 —— RBP：

  • RBP 在函数序言里被设为「当前帧的基址」，之后整个函数体内不再变动；
  • 局部变量、参数都可以用 [rbp - N] / [rbp + N] 这种固定偏移访问；
  • 调试器（GDB）顺着 RBP 串成的链条，就能一层层回溯调用栈。
高地址 ↑
… 调用者的栈帧 …更高地址
返回地址[rbp + 8]
保存的旧 RBP← RBP 指向这里
局部变量 / 临时数据[rbp - 8], [rbp - 12]…
栈顶空闲区← RSP 指向这里
低地址 ↓（栈向此增长）

▲ 使用帧指针时的经典栈帧：RBP 锚定基址，RSP 追踪栈顶

注意：RBP 并非必需。它只是一种「方便定位」的约定；开启优化后编译器常常省掉它（见 §07）。所以「RBP 一定存在、一定指向栈帧」是错误的。

03

函数进入时：函数序言（Prologue）

建立本次调用的栈帧

函数刚进入时，编译器插入一段序言（prologue），负责搭好栈帧。最典型的三步：

push    rbp          # 1. 保存调用者的 RBP（旧帧基址），RSP -= 8
mov     rbp, rsp     # 2. 把本帧基址设为当前栈顶 → RBP 从此固定
sub     rsp, 32       # 3. 为局部变量一次性开辟 32 字节
① push rbp：把上一层的帧基址存进栈（以便返回时还原）
② mov rbp, rsp：本帧有了一个不动的锚
③ sub rsp, N：栈顶下移 N 字节，腾出局部变量区

sub rsp, 32 里的 32 不是固定值 —— 编译器按局部变量总大小 + 16 字节对齐要求计算得出（对齐规则见 04 篇）。有些函数没有局部变量，这一步会被省略。

⚠️ 这是典型示例，不是铁律

并非所有编译器、优化级别、ABI 都严格生成这三行。叶子函数（leaf function）、开了 -fomit-frame-pointer 的函数，序言可能只剩一条 sub rsp，甚至完全没有。

04

函数返回时：函数结语（Epilogue）

拆掉栈帧、恢复调用者、跳回去

与序言对称，函数末尾的结语（epilogue）负责把栈帧还原干净：

leave                 # 等价于：mov rsp, rbp ; pop rbp
ret                   # 弹出返回地址并跳回调用者
指令做了什么
mov rsp, rbp把栈顶抬回帧基址 —— 一步丢弃所有局部变量空间
pop rbp恢复调用者的旧 RBP，RSP += 8
ret弹出栈顶的返回地址到 RIP，跳回调用点

leave 只是把前两步打包成一条指令。有些编译器不用 leave，而是显式写 add rsp, 32 + pop rbp，效果相同。返回后，栈完全回到 call 之前的样子，仿佛这次调用从未占用过栈。

序言与结语严格配对：序言 push 了什么、sub 了多少，结语就要 pop 回来、加回去。任何一侧算错，返回后 RSP/RBP 就会错位，轻则数据乱、重则崩溃。这也是「栈平衡（stack balancing）」的由来。

05

栈帧内部：局部变量 / 返回地址 / 保存的寄存器

用固定偏移把 C++ 变量映射到栈空间

回到 add 的例子（-O0）。函数体里的 c、以及参数 a/b 的备份，都被放在相对 RBP 的固定偏移处：

int add(int a, int b) {
    int c = a + b;
    return c;
}

# -O0 汇编（简化，Intel 语法）
add:
    push    rbp
    mov     rbp, rsp
    mov     [rbp-20], edi     # 把参数 a 存进栈
    mov     [rbp-24], esi     # 把参数 b 存进栈
    mov     eax, [rbp-20]
    add     eax, [rbp-24]
    mov     [rbp-4], eax      # c = a + b，c 在 [rbp-4]
    mov     eax, [rbp-4]      # 返回值放 eax
    pop     rbp
    ret
内容位置谁放的
返回地址[rbp + 8]调用者的 call
保存的旧 RBP[rbp + 0]本函数序言的 push rbp
局部变量 c[rbp - 4]本函数
参数备份 a/b[rbp - 20]/[rbp - 24]本函数（从寄存器落到栈，方便调试）
callee-saved 寄存器局部区之上用到时序言里 push

注意参数 a/b 是先通过寄存器 EDI/ESI 传进来，再被存到栈上的 —— 这只是 -O0 为方便调试的做法。-O2 下它们通常全程待在寄存器，不会落栈。

06

栈空间如何随调用增长与回收

多层调用时，栈帧一层层叠上去

设想 main → add。随着调用深入，栈向低地址一层层生长；返回时逆序回收：

高地址 ↑
main 栈帧先建立
返回地址（回 main）call add 压入
add 保存的旧 RBPadd 的序言
add 局部变量 c← 当前 RSP 区
低地址 ↓

▲ 进入 add 时：main 帧在上，add 帧在下，RSP 在最低处

add 一旦 ret，它的整块栈帧被回收，RSP 抬回 main 帧，栈恢复到调用前。这种「叠上去、退回来」的对称性，正是递归和深层嵌套能正常工作的根本 —— 每层都有独立栈帧，互不覆盖。若调用层数太深（如无限递归），栈不断向低地址生长，最终撞上栈的边界 → 栈溢出（06 篇）。

07

-O0 / -O2 / -fomit-frame-pointer 的影响

「标准栈帧」会因优化而变形，甚至消失

选项对栈帧的影响
-O0忠实生成 push rbp / mov rbp,rsp，每个变量都有栈位置，最利于调试、最贴近教科书
-O2激进优化：变量尽量待寄存器、小函数被内联、无用局部变量消除，栈帧可能大幅缩水甚至不存在
-fomit-frame-pointer省掉 RBP 作帧指针，把它当普通通用寄存器用；局部变量改用 [rsp + N] 定位（-O1 及以上通常默认开启）

省略帧指针后的样子

# -O2 -fomit-frame-pointer：没有 push rbp / mov rbp,rsp
add:
    lea     eax, [rdi + rsi]   # 直接 a+b，连局部变量 c 都没有
    ret

看到没？add 是个叶子函数（不再调用别人），优化后连栈帧都不需要 —— 参数在 RDI/RSI，结果 lea 一步算好放 EAX，直接 ret。这就是「函数调用不一定产生栈帧」的直接证据。

省略帧指针的代价

好处：多释放一个通用寄存器、省两条指令。代价：基于帧指针的快速栈回溯失效。生产环境常配合 -fno-omit-frame-pointer 或依赖 .eh_frame/DWARF 的 CFI 信息让 GDB / perf 仍能回溯（见 06 篇）。

08

核心结论

  • 栈是线程私有、LIFO、向低地址增长的内存；RSP 永远指栈顶，RSP 变小 = 栈变大。
  • 栈帧是一次调用在栈上的占用区，装着返回地址、保存的寄存器、局部变量。
  • RBP 是可选的「帧基址锚点」，让局部变量用固定偏移访问、让 GDB 能回溯 —— 但它可被省略。
  • 序言建帧、结语拆帧，两者严格配对以保持栈平衡；leave = mov rsp,rbp; pop rbp。
  • 典型的 push rbp / mov rbp,rsp / sub rsp,N 不是铁律：叶子函数、-O2、-fomit-frame-pointer 都可能让栈帧变形或消失。
09

常见误区

❌ 每个函数都有固定的栈帧结构。 结构随编译器、优化级别、是否叶子函数而变，甚至没有栈帧。

❌ RBP 永远存在且永远指向栈帧。 -fomit-frame-pointer 会把 RBP 当普通寄存器，用 RSP 相对寻址。

❌ RSP 增大代表压栈。 恰好相反：push 让 RSP 减小，栈向低地址增长。

❌ 局部变量总在 [rbp - N]。 只在有帧指针时如此；省略 RBP 后用 [rsp + N]，优化后可能根本不在内存。

❌ 函数调用一定会开辟栈帧。 叶子函数在 -O2 下常常无栈帧，直接寄存器计算 + ret。

10

面试问题

点击每道题展开参考答案（先自测，再对照）。

  1. 基础什么是 Stack Frame？它包含哪些内容？

    一次函数调用在栈上占用的区域，通常含返回地址、保存的旧 RBP/callee-saved 寄存器、局部变量、溢出参数与临时数据。

  2. 基础RSP 和 RBP 分别是什么？

    RSP 是栈指针，始终指向当前栈顶，随 push/pop 变化；RBP 是帧指针，指向当前帧基址，函数执行期间保持不变，用于固定偏移寻址与栈回溯。

  3. 原理典型的函数序言/结语是什么？分别做了什么？

    序言 push rbp; mov rbp,rsp; sub rsp,N 建立栈帧；结语 leave; ret（= mov rsp,rbp; pop rbp; ret）拆掉栈帧并返回。

  4. 原理为什么 x86-64 上「push 让 RSP 减小」？

    因为栈向低地址方向增长。压栈占用更多空间，栈顶朝低地址移动，故 RSP 减 8。

  5. ABIRBP 是不是一定存在？省略它有什么利弊？

    不是。-fomit-frame-pointer 可省略。利：多一个可用寄存器、少两条指令；弊：基于帧指针的快速回溯失效，需靠 DWARF CFI。

  6. 进阶-O0 和 -O2 下同一函数的栈帧为何差别巨大？

    -O0 忠实落栈、保留每个变量位置便于调试；-O2 会把变量放寄存器、内联小函数、删除无用变量，栈帧大幅缩水甚至消失。

  7. 进阶为什么无限递归会栈溢出？请从栈帧角度解释。

    每层递归都压入一个新栈帧，栈持续向低地址增长且从不回收，最终越过线程栈边界触发保护页 → SIGSEGV / stack overflow。
