02

C 风格 cast 为什么"危险"

全能 cast 的五种尝试

C 风格 (T)expr 和函数风格 T(expr) 是全能 cast：编译器按固定顺序试五种组合，你在源码里看不出最终用了哪一种。

// C 风格 vs static_cast vs reinterpret_cast — 最短对照
const Base* b = getBase();
Derived* d = (Derived*)b;                 // 悄悄去 const + 下行，失败是 UB
Derived* s = static_cast<Derived*>(
    const_cast<Base*>(b));                 // 必须拆开，各步可搜
uint32_t bits = *reinterpret_cast<uint32_t*>(&f); // 别名 UB；改用 bit_cast

03

static_cast 完全详解

编译期、不检查

编译期转换，最常用，不做运行时检查。下行转错再解引用是 UB。

3.1 能做的转换

类型例子
数值 / 枚举static_cast<int>(3.14)、static_cast<int>(Color::Red)
void* → T*static_cast<int*>(malloc(4))
类层次上行安全，常可隐式
类层次下行不检查；你担保实际类型
用户定义转换 / rvalue触发 explicit 构造；static_cast<T&&>(x) 即 std::move

3.2 不能做的

  • 去 const / volatile → const_cast
  • 无关指针互转 → reinterpret_cast
  • 不相关类层次：下行能编译，访问是 UB

3.3 隐藏用法：触发用户定义转换

explicit 构造不能写 Money m = 100，但 static_cast<Money>(100) 和直接初始化可以。见 §8，不要在这里再堆一份 Money 类。

04

dynamic_cast + RTTI

RTTI 与失败语义

4.1 核心语义

运行时检查的下行 / 交叉转换。失败时：指针 → nullptr；引用 → 抛 std::bad_cast。源类型必须是多态（至少一个虚函数），因为要走 RTTI（vtable + type_info）。

4.2 用法

struct Animal { virtual ~Animal() = default; };
struct Dog : Animal { void bark(); };

if (Dog* d = dynamic_cast<Dog*>(a)) d->bark(); // 失败 nullptr
try {
    Dog& r = dynamic_cast<Dog&>(*a);            // 失败抛 bad_cast
} catch (std::bad_cast&) {}

4.3 性能开销与禁用

开销来自遍历 type_info 图，多继承 / 虚继承更慢。嵌入式和游戏引擎常 -fno-rtti 换二进制体积；代价是这条路径整段不可用。

4.4 dynamic_cast 的替代方案

替代何时
虚函数 / visitor开放层次，行为在类型上
std::variant + visit封闭类型集
枚举 tag + switch自己控布局
CRTP编译期就知道类型

const_cast 真实用法

只动 cv，不授予写权限

唯一能增删 cv（const / volatile）的 cast。它不授予写权限：只能「承诺对象本来就可写」。

5.1 唯一安全用法

对象本身非 const，只是当前引用带 const：对接保证不写的老 C API，或把 const 重载转调非 const。面试题里有惯用法，正文不重复那份 Container。

5.3 经典惯用法：const 与非 const 重载共享代码

06

reinterpret_cast 深坑

换标签，不改比特

「把这段比特当作另一种类型看」。不做数值转换，只换类型标签。

6.1 能做的（合法用法）

用法是否安全
整数 ↔ 指针实现定义
函数指针 ↔ void*（POSIX dlsym）POSIX 保证；ISO C++ 不保证
不相关指针互转能转，解引用通常违反严格别名 → UB
T* ↔ char* / std::byte*别名规则的例外，可读字节

6.2 严格别名规则（Strict Aliasing）⭐

通过类型 A 的指针访问类型 B 是 UB（char / byte 等例外）。float 位型用 memcpy / bit_cast。

07

隐式转换链 + 算术转换规则

提升先于算术转换

7.1 标准转换序列（4 类，按发生顺序）

  1. Lvalue Transformations — Lvalue→Rvalue / 数组→指针 / 函数→指针
  2. Promotion — char/short → int；float → double
  3. Conversion — int → long / 指针 → bool / 派生 → 基类
  4. Qualification — 加 const / volatile

7.2 整型提升（Integral Promotion）

比 int 窄的整型在算术里先变成 int（或 unsigned int）。提升是通常算术转换的第一步。

7.2b 整型宽度与最大值 — 标准只保证下限

标准只保证下限：short≥16，int≥16（桌面实际 32），long≥32，long long≥64。要 64 位写 int64_t / long long，不要用 long。

类型下限Win LLP64Linux LP64宏
int≥16（实际 32）3232INT_MAX
long≥323264LONG_MAX
long long≥646464LLONG_MAX

展开见 架构师卡片 ·「long 在不同平台多少位？」。协议字段用定宽类型。

7.3 整型转换（Integral Conversion）

  • 无符号目标：取模 2^N，定义行为
  • 有符号且塞不下：C++17 实现定义；C++20 起二进制补码

int i = -1; unsigned u = 1; i < u 为假：比较前 i 变成 UINT_MAX。

7.4 通常算术转换（Usual Arithmetic Conversion）

二元运算先提升，再找共同类型：有 long double / double / float 就跟浮点走；否则同符号取更高 rank，无符号 rank ≥ 有符号则转无符号。

7.5 经典陷阱集合

int n = 3.14;     // 截断为 3
int m{3.14};      // 编译错：列表初始化禁止窄化
int k = static_cast<int>(3.14);  // 意图明确

7.6 工具：现代检查

-Wall -Wextra -Wsign-compare -Wsign-conversion -Wconversion -Wfloat-equal；UBSan 查溢出和别名。完整旗标见 §16.4。

08

用户定义转换 + explicit

挡住隐式，最多一次用户定义

两种用户定义转换：转换构造 T(U)，转换运算符 operator U()。隐式序列里用户定义最多一次，否则 int→A→B 会组合爆炸。

8.1 隐式转换链规则

void f(B); f(42) 若要 int→A→B 两次用户定义，直接失败。写成 f(A(42)) 后只剩一次 A→B。

8.2 explicit 关键字（C++11）

class Vec {
public:
    explicit Vec(size_t n);
};
Vec v1 = 100;              // ❌ 隐式被挡住
Vec v2(100);               // ✅ 直接初始化
Vec v3 = static_cast<Vec>(100);  // ✅ 显式触发

8.3 explicit 的常见目标

资源类（避免 int→FileHandle）、领域 ID、智能指针。clang-tidy google-explicit-constructor 强制单参构造显式。

explicit operator bool 与 conversion operator

语境 bool，赋值拒绝

9.1 conversion operator（转换运算符）

operator double() 让 Money 能隐式进算术；加上 explicit 后只剩 static_cast<double>(m)。长例子与面试重复，不展开。

9.2 explicit operator bool — 重要惯用法

C++11 用它取代 safe-bool。if (x) 这种语境布尔转换即使 explicit 也走；bool b = x 和 x + 1 被挡住。

9.3 标准库案例

std::optional / 智能指针 / 流都用同一模式：条件判断自然，算术和整型提升进不去。

11

std::bit_cast (C++20)

按字节复制，不踩别名

11.1 背景：传统方法的问题

方法问题
reinterpret_cast 解引用严格别名 → UB
union 重叠C 允许 type-punning，C++ 不保证
memcpy正确，但不能 constexpr

11.2 std::bit_cast 完美解决

#include <bit>
auto bits = std::bit_cast<uint32_t>(f);           // 安全读位型
constexpr float pi = std::bit_cast<float>(0x40490FDA);

11.3 约束

两边 sizeof 相同且都是 trivially copyable。它复制出新对象，不是原地改类型。

11.4 真实工程用法

读 IEEE 位判断 NaN、把 4 字节按端序拼成 uint32_t。C++20 起按位重解释默认 bit_cast；reinterpret_cast 留给 char* 扫字节、函数指针、整数↔指针。

12

SFINAE 入门 + concepts

代入失败不是错误

12.1 什么是 SFINAE

SFINAE = Substitution Failure Is Not An Error：代入失败不报错，只把该候选移出重载集。这是模板按「有没有这个操作」分流的基础。

12.2 经典 SFINAE 写法（C++11/14）

返回类型写成 decltype(c.size())：没有 .size() 的类型会替换失败，落到数组重载。代码见面试。

12.3 enable_if 风格

用 enable_if_t<is_integral_v<T>> 把非整型移出候选。C++20 用 requires / concept 同一件事，诊断可读。

12.4 void_t 检查类型成员（C++17）

偏特化 void_t<decltype(declval<T>().size())> 探测成员。Detection Idiom 的骨架。

12.5 C++20 concepts —— SFINAE 终结者

concept Sizeable = requires(T t) { { t.size() } -> convertible_to<size_t>; }。错误信息是「不满足 Sizeable」，不是八屏替换失败。

12.6 真实工程：Detection Idiom

有 serialize 就调它，否则平凡类型按字节追加，再否则 static_assert。新代码直接 concept，不必再手写 void_t。

面试题集（21 道分层）

基础（必答） · 中级 · 高级（体现深度） · 速答示范（第 12 题）

点击每道题展开参考答案（先自测，再对照）。

15.1 基础（必答）

  1. 基础4 种 C++ cast 各做什么? 哪个有运行时检查?
    static_cast
    编译期已知安全的转换：数值类型、继承上行、void*↔T*、显式触发转换运算符。无运行时检查。
    dynamic_cast
    唯一有运行时检查：多态类型间安全下行 / 交叉转换，依赖 RTTI；失败时指针返回 nullptr、引用抛 bad_cast。
    const_cast
    增删 const / volatile 限定。
    reinterpret_cast
    底层位模式重解释：指针↔整数、不相关指针类型。
  2. 基础为什么不应该用 C 风格 cast?
    问题
    C cast 会依次尝试 const_cast / static_cast / reinterpret_cast 组合，意图不明、可能悄悄做危险的 reinterpret，且无法用 grep 搜索定位。
    对策
    C++ 四种 cast 各司其职、显式可搜索、受类型系统约束。
  3. 基础static_cast 与 dynamic_cast 的区别?
    static
    编译期完成、零运行时开销、不校验实际类型；多态下行若类型不符是 UB。
    dynamic
    运行时查 RTTI，安全但有开销，要求类型是多态的（含虚函数）。
  4. 基础const_cast 用在哪些场景?
    场景
    去 const 以对接老式 C API（确信不改）、在 const 成员函数中复用非 const 实现。
    红线
    修改一个真正 const 的对象仍是 UB —— const_cast 只能用于"对象本身非 const、只是当前引用带 const"的情况。
  5. 基础什么是隐式转换? 什么是显式转换?
    隐式
    编译器自动插入：整型提升、算术转换、派生→基、单参构造、转换运算符。
    显式
    程序员用 cast 或 explicit 主动触发。隐式方便但易出错，关键构造 / 运算符应标 explicit。
  6. 基础int / long 各多少位？跨平台要 64 位该用什么？
    标准
    只保证下限：short≥16，int≥16（实际 32），long≥32，long long≥64。
    平台
    Windows LLP64：int=long=32，LONG_MAX=2147483647。Linux LP64：long=64。
    实践
    要 64 位用 int64_t / long long，不要用 long。最大值宏：SHRT_MAX / INT_MAX / LONG_MAX / LLONG_MAX。

15.2 中级

  1. 中级整型提升与算术转换的关系?
    整型提升
    比 int 小的类型（char/short/bool/enum）先提升为 int / unsigned int。
    算术转换
    在提升之后，把两操作数转成共同类型（按 rank + 有无符号规则）。提升是通常算术转换的第一步。
  2. 中级什么是严格别名规则? 怎么合法做 type punning?
    规则
    不能通过不兼容类型的指针 / 引用访问对象（char / std::byte 例外），否则 UB；编译器据此做激进优化。
    合法手段
    memcpy、C++20 std::bit_cast、std::start_lifetime_as(C++23)；union 读非活动成员在 C++ 中并不保证。
  3. 中级explicit 关键字解决了什么问题?
    作用
    阻止单参构造 / 转换运算符参与隐式转换，避免意外转换（如 void f(MyString); f("x") 悄悄构造）与重载二义性。
  4. 中级explicit operator bool 与普通 operator bool 区别?
    explicit
    只在语境布尔转换（if/while/!/&&/||/?:）中生效，安全。
    普通
    参与所有隐式转换，危险：int x = obj; 会整型提升、obj1 == obj2 退化成 int 比较。
  5. 中级下列调用哪个重载? void f(int); void f(double); f(0u);
    答案
    0u 是 unsigned int。unsigned int→int 与 unsigned int→double 都属"转换"等级、优先级相同 → 二义性，编译错误。须显式 cast 消歧。

15.3 高级（体现深度）

  1. 高级dynamic_cast 的开销来源?
    来源
    运行时遍历继承层次比对 type_info（RTTI），多重 / 虚继承下需更复杂的运行时算法，外加 vtable 间接。比 static_cast 慢一到两个数量级。
  2. 高级std::bit_cast 与 reinterpret_cast 的区别? 什么时候用哪个?
    bit_cast
    按字节复制构造新对象，类型安全、可 constexpr、不违反别名；要求 sizeof 相等且 trivially copyable。
    reinterpret
    指针 / 引用类型穿越，解引用常违反严格别名 → UB。
    口诀
    "按位重解释"用 bit_cast，"指针类型转换"用 reinterpret_cast。完整对比见 §15.4。
  3. 高级SFINAE 是什么? 给一个 enable_if 的例子
    定义
    Substitution Failure Is Not An Error：模板替换失败不报错，仅把该重载移出候选集。
    例子
    template<class T, std::enable_if_t<std::is_integral_v<T>, int> = 0>
void f(T);   // 仅整型可调用；C++20 用 concepts/requires 更清晰
  4. 高级用 SFINAE / concepts 检查类型是否有 .size() 方法
    concept
    template<class T>
concept HasSize = requires(const T& t) {
    { t.size() } -> std::convertible_to<std::size_t>;
};
    C++17
    用 std::void_t + 偏特化检测表达式 decltype(std::declval<T>().size()) 是否合法。
  5. 高级"声明万能引用构造可能劫持其他构造" 怎么办?
    原因
    万能引用构造 template<class T> C(T&&) 对非 const 左值比拷贝构造 C(const C&) 更匹配，会被错误选中。
    修复
    用 requires / enable_if 排除自身类型（!std::same_as<std::decay_t<T>, C>），或提供精确重载，或 tag dispatch。
  6. 高级在 const 成员函数中如何重用非 const 版本的代码?（const_cast 惯用法）
    惯用法
    const T& get() const { /* 真正实现 */ }
T& get() { return const_cast<T&>(std::as_const(*this).get()); }
    让 const 版做实现、非 const 版转调，避免重复。
    C++23
    用 deducing this（auto&& self）一个函数即可搞定。
  7. 高级用户定义转换链最多允许几次? 为什么?
    答案
    一个隐式转换序列里最多 1 次用户定义转换。否则 A→B→C 链会组合爆炸、难以推理，标准禁止；需多步必须显式写。
  8. 高级列表初始化 int n{3.14} 为什么编译错而 int n = 3.14 不会?
    花括号
    列表初始化禁止窄化转换（double→int 丢精度）→ 编译错误。
    等号
    拷贝初始化允许窄化，只是截断为 3（可能伴随警告）。
  9. 高级编译器在重载决议时按什么顺序匹配类型转换?
    优先级
    精确匹配 > 提升 > 标准转换 > 用户定义转换 > 省略号 ...。同级出现多个最佳 → 二义性。
  10. 高级什么是"contextual conversion to bool"? 它与 explicit 的关系?
    语境转换
    在 if/while/for/!/&&/||/?: 语境中，对象会进行"语境布尔转换"，此时即使 operator bool 是 explicit 也会被调用。
    关系
    这正是 explicit operator bool 的设计点：只放行这些语境，禁止其它一切隐式 bool 转换。

15.4 速答示范（第 12 题）

问：std::bit_cast 与 reinterpret_cast 的区别? 什么时候用哪个?

答：

维度reinterpret_caststd::bit_cast (C++20)
语义把指针/引用看作另一种类型 (类型穿越)按字节复制并解释为新类型
严格别名解引用通常违反 → UB不依赖指针 → 安全
constexpr不能可以 (C++20)
对象生命周期不构造目标对象构造目标对象 (复制构造)
大小要求无源和目标 sizeof 必须相等
典型用途字节访问 (char*)、函数指针、整数↔指针浮点 ↔ 整数 bit 表示、序列化

规则："按位重解释" 用 bit_cast，"指针类型转换" 用 reinterpret_cast。
