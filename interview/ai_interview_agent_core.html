概览

Agent 基本架构跟 LLMChain 到底差在哪？
LLMChain 是静态流水线 —— 预定义的线性工作流，各执行逻辑与调用顺序均被硬编码固化，缺乏动态规划与自适应调整能力。Agent 是带大脑的项目经理 —— 由规划、记忆、工具使用和推理循环组成，能根据核心目标自主决定执行路径。核心差异在于自主性：LLMChain 的每一步都是写死的，Agent 的每一步都是动态决策的。
ReAct 模式里，记忆机制到底怎么落地？
三层记忆：(1) 短期记忆 —— 驻留在当前上下文窗口，实时保存对话历史与工具调用结果，保障本轮多步推理连贯；(2) 长期记忆 —— 以向量数据库形式存在，跨会话前先去向量库根据 Embedding 检索历史经验和用户偏好；(3) 务实落地方案 —— 业界主流是增加「摘要层级」，通过递归压缩旧对话，避免海量 Token 推高成本和稀释注意力。关键挑战是「防稀释」—— 对话越长，每条信息的注意力权重越低。
单 Agent 也能干活，为什么还要上多 Agent？
单 Agent 的核心痛点是注意力漂移 —— 处理跨领域极度复杂的长任务时，如果背负过多工具与指令，极易发生推理链断裂。多 Agent 的核心价值是专注与分工 —— 让每个 Agent 只盯自己那一亩三分地（如编码 Agent、审查 Agent、测试 Agent），提高容错率与领域专业度。但注意：80% 的场景只需要 Level 2 单 Agent（含 Producer-Critic），不需要上 Multi-Agent。只有当工具数量 > 15 或任务跨多个独立领域时，才考虑多 Agent。
多 Agent 常见的协作模式有哪些？
三种主流模式：(1) 中心化策略（高可控） —— 主控 Agent 如同大脑，负责任务拆解，分别派发给底层各个 Worker 子 Agent，执行后由中心汇总。适合需要强一致性的场景；(2) 流水线串联（强依赖） —— 上一个 Agent 的输出严丝合缝作为下一个的输入，常用于「构建 → 审查 → 修复」工程流；(3) 民主协作探讨（重策略） —— 多个 Agent 根据各自系统身份进行圆桌讨论后得出共识，仅在线上策略分析场景偶有使用。选择依据：一致性需求（中心化）、流程依赖（流水线）、决策质量（民主协作）。
多智能体系怎么防无限循环和通信爆炸？
三道防线：(1) 熔断阈值（物理级） —— 硬编码配置 Max Iterations 重试次数阈值，触发后强制抛出中止异常；(2) 状态机制（逻辑级） —— 为每次流转定义极其清晰的工作完成判断函数（Exit Condition），不达标不换阶段；(3) 摘要瘦身（内容级） —— Agent 网络互发消息强制经过 Token 级别语义总结，屏蔽闲聊，传输纯净 Payload。核心思想：从物理限制到逻辑判断到内容压缩，三层防线确保循环有终点、通信有边界。
工作流和自主智能体，到底该怎么选？
两种范式的选择取决于业务特性：(1) 静态工作流（求稳） —— 基于 DAG 或状态机路线写死，高度可靠可预期，适合核心业务线如报销单审计、规范化客服；(2) 自主智能体（求变） —— 放权让模型做黑盒调度、自我判断调用路径，适用于无边界探索性研究、开放式代码生成。核心心法：越靠近公司核心利润/风控业务，越要限制其自主行动空间；越偏向创意与研发环节，越要放权。
