Agent 调优实战面试题

Agent Tuning Interview — 分层归因、Bad Case 采样、Prompt 优化、模型选型、闭环迭代 5 道实战面试题

概览

场景设定：你做了一个 Agent 项目，上线之后效果一般，准确率一直在 60% 多徘徊上不去。面试官问：你接下来会怎么做？

准确率 60% 上不去，你会怎么排查？
先做分层归因，从成本最低的层开始修复。将 Agent 分为三层：质量层（知识库/数据）、工程层（Prompt/检索策略）、模型层（底层 LLM）。质量层最靠近数据库，修复成本最低。具体做法：人工抽取约 100 条 Bad Case，按问题场景分层采样（查询/操作/故障等），保证各类 Case 都能看到。分析完为每个 Bad Case 打标签，按优先级修复。
100 条怎么抽的？这个量够吗？
不是纯随机抽取，会按问题场景分层采样，保证各类 Case 都能看到（如查询类 30 条、操作类 30 条、故障类 20 条、边界 Case 20 条）。100 条在快速诊断场景下性价比很高 —— 与 500 条相比，比例差不了太多但成本低得多。关键是覆盖面，不是绝对数量。
实际效果如何？发现了什么问题？
之前服务台项目用这个方法处理，准确率从 63% 提升到 82%。发现的错误分布：
• 35% — 知识库过期（修复成本最低：清理/更新知识库）
• 25% — Prompt 缺关键约束（修复成本低：调整 Prompt）
• 20% — 检索模块问题（修复成本中：调整切片策略）
• 20% — 真正的模型能力问题（修复成本高：需要换模型或微调）

核心洞察：80% 的问题不需要改模型！通过清理知识库、调整 Prompt 和切片策略就能解决大部分问题。
那 20% 模型能力问题怎么处理？
会单独拎出这些 Case 作为评测集，对比测试不同模型（如 GPT-4 vs Claude vs 开源模型），计算 ROI（准确率提升 vs 成本增加）。通过 CoT 模板（Chain of Thought）提升指标，但仍有约 5% 左右问题需要人工兜底（设置降级策略，模型不确定时转人工）。

决策框架：如果换模型成本增加 3 倍但准确率只提升 2%，不如用人工兜底 + 持续优化知识库。
如何保证优化后效果不回退？
建立闭环迭代机制：优化后再抽 100 条新 Bad Case 检查归因分布变化。如果某类错误比例上升，说明引入了新问题，需要回退排查。持续补充新出现的 Case 类型，动态更新 Prompt 和检索策略。核心思想：Agent 调优不是一次性工程，而是持续迭代的闭环系统。

监控指标：
• 归因分布变化（知识库类错误是否反弹）
• 新增 Case 类型（是否有新的失败模式）
• 端到端准确率趋势（周级别跟踪）

方法论总结

步骤动作目标
1. 分层归因质量层 → 工程层 → 模型层从成本最低的层开始修复
2. 分层采样100 条 Bad Case，按场景分类快速定位主要问题类型
3. 标签化修复为每个 Case 打标签，按优先级修复系统性消除错误
4. 模型评测对模型能力问题单独建评测集ROI 导向的模型选型
5. 闭环迭代再抽 100 条验证归因变化确保优化不回退
面试高分关键：不要一上来就说「换更好的模型」。面试官想考察的是你的工程化思维 —— 分层归因、成本意识、闭环迭代。80% 的问题不需要改模型，这是最有价值的洞察。
