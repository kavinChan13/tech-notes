知识图谱概述

知识图谱（Knowledge Graph, KG）是一种用 图结构 来描述现实世界中实体及其…

1.1 定义

知识图谱（Knowledge Graph, KG）是一种用图结构来描述现实世界中实体及其关系的语义知识库。Google 于 2012 年提出 "Knowledge Graph" 概念，用于增强搜索引擎的语义理解。

核心思想：以结构化方式组织知识，使机器能够理解实体之间的语义关联。

1.2 三元组（Triple）

知识图谱的基本单元是三元组（Triple）：

(头实体 h, 关系 r, 尾实体 t)  或  (Subject, Predicate, Object)

示例：

  • (姚明, 出生地, 上海)
  • (Python, 创始人, Guido van Rossum)
  • (阿司匹林, 治疗, 头痛)

1.3 属性图模型 vs RDF

特性RDF（Resource Description Framework）属性图（Property Graph）
基本单元三元组 (s, p, o)节点 + 边 + 属性
数据模型基于 W3C 标准，使用 URI 标识节点/边可附带任意键值对属性
查询语言SPARQLCypher / Gremlin
SchemaRDFS / OWL 本体灵活，无严格 Schema
边的属性需要"具体化"(Reification)边可直接附属性
适用场景语义 Web、开放知识共享企业应用、推荐系统
代表Wikidata、DBpediaNeo4j、NebulaGraph

1.4 常见知识图谱

  • Freebase — Google 收购，后迁移至 Wikidata
  • Wikidata — 开源协作知识库，RDF 格式
  • DBpedia — 从 Wikipedia 自动抽取的结构化数据
  • ConceptNet — 常识知识图谱
  • NELL — 卡内基梅隆大学持续学习知识库
  • CN-DBpedia — 中文领域知识图谱
  • 三元组是知识图谱的最小单元：(h, r, t)，任何知识都可分解为此结构
  • RDF 适合标准化的跨系统共享；属性图更灵活，工业界应用更广
  • Schema 定义了知识的类型系统，如本体（Ontology）定义类层次和关系约束
  • 知识图谱 ≠ 图数据库：KG 强调语义，图数据库是存储引擎

2.2 Cypher 查询语言

Cypher 是 Neo4j 开发的声明式图查询语言，语法直观，以"ASCII 艺术"形式描述模式：

创建节点与关系

// 创建节点
CREATE (p:Person {name: '姚明', height: 226})
CREATE (c:City {name: '上海'})

// 创建关系
CREATE (p)-[:BORN_IN {year: 1980}]->(c)

查询

// 查询出生在上海的人
MATCH (p:Person)-[:BORN_IN]->(c:City {name: '上海'})
RETURN p.name, p.height

// 多跳查询：朋友的朋友
MATCH (a:Person {name: 'Alice'})-[:FRIEND*2]->(fof)
RETURN DISTINCT fof.name

// 最短路径
MATCH path = shortestPath(
  (a:Person {name: 'Alice'})-[*..6]-(b:Person {name: 'Bob'})
)
RETURN path

2.3 图数据库 vs 关系型数据库

维度关系型数据库 (RDBMS)图数据库
数据模型表、行、列节点、边、属性
关联查询JOIN（性能随深度急剧下降）图遍历（性能与数据量关系较小）
多跳查询多次 JOIN，SQL 复杂天然支持，语法简洁
Schema固定 Schema灵活/无 Schema
适用场景事务处理、结构化数据社交网络、推荐、欺诈检测
性能关键索引、表规模图结构、遍历深度
  • 图数据库的核心优势：多跳关系查询性能远超 RDBMS 的多表 JOIN
  • Neo4j 使用 Cypher，JanusGraph 使用 Gremlin，选型要看生态和规模
  • 原生图存储 vs 非原生图存储：原生使用免索引邻接(index-free adjacency)，遍历复杂度 O(1)
  • 分布式图数据库（NebulaGraph）通过图分区解决大规模图存储问题

知识图谱构建

知识图谱构建是将非结构化/半结构化数据转化为结构化三元组的过程：

3.1 构建流程

知识图谱构建是将非结构化/半结构化数据转化为结构化三元组的过程：

  1. 数据采集 — 爬虫、数据库导出、API 拉取
  2. 信息抽取 — NER、关系抽取、事件抽取
  3. 知识融合 — 实体对齐、实体消歧、属性融合
  4. 知识存储 — 导入图数据库
  5. 知识更新 — 增量更新、时效性维护

3.2 实体识别（NER）

命名实体识别（Named Entity Recognition）是从文本中识别出人名、地名、机构名等实体的任务。

主要方法

方法代表特点
基于规则正则表达式、词典匹配精度高、召回低、不可迁移
统计模型HMM、CRF需手工特征，CRF 长期主流
深度学习BiLSTM-CRF、BERT-CRF端到端，效果好
LLM 方案GPT-4 / Claude + PromptZero-shot 能力强，但速度慢

BiLSTM-CRF 架构

输入序列 → Embedding → BiLSTM → 发射分数矩阵 → CRF 层 → 标签序列

标注方案（BIO）:
B-PER  I-PER  O  O  B-LOC  I-LOC
 姚      明   出  生   上     海

3.3 关系抽取（RE）

关系抽取从文本中识别实体对之间的语义关系：

方法分类

  • 管道式 — 先 NER 再分类关系，误差传播
  • 联合抽取 — 同时识别实体和关系（TPLinker、CasRel）
  • 远程监督 — 用已有 KG 自动标注语料（Distant Supervision）
  • Few-shot RE — 少样本关系抽取（利用原型网络等）

3.4 事件抽取

事件抽取识别文本中的事件触发词（Trigger）和事件论元（Argument）：

示例："2024年3月，特斯拉在上海建立了第二座超级工厂。"

  • 事件类型：建设
  • 触发词：建立
  • 论元：主体=特斯拉，地点=上海，时间=2024年3月

3.5 LLM 辅助抽取

利用大语言模型进行知识抽取已成为主流趋势：

Prompt 示例：
"""
请从以下文本中抽取所有三元组，格式为 (实体1, 关系, 实体2)。

文本：乔布斯于1976年在加利福尼亚创立了苹果公司，
该公司总部位于库比蒂诺。

抽取结果：
(乔布斯, 创立, 苹果公司)
(苹果公司, 创立时间, 1976年)
(苹果公司, 创立地点, 加利福尼亚)
(苹果公司, 总部位于, 库比蒂诺)
"""

3.6 知识融合与对齐

  • 实体消歧 — "苹果"→ 苹果公司 or 水果？基于上下文判断
  • 实体对齐 — 跨知识库的同一实体映射（Entity Alignment），如 Wikidata 与 DBpedia
  • 属性融合 — 多源数据中同一实体的属性合并、冲突消解
  • 典型方法 — 基于嵌入的对齐（MTransE、GCN-Align）、基于翻译的跨语言对齐
  • NER 常用序列标注方法，BIO / BIOES 标注方案需能区分
  • BiLSTM-CRF 中，CRF 层学习标签间的转移约束（如 I-PER 不能跟在 B-LOC 后面）
  • 远程监督假设：若 KG 中存在 (A, r, B)，则包含 A 和 B 的句子可能表达关系 r
  • LLM 抽取优势在于 zero-shot 泛化性，但需注意幻觉和格式稳定性

知识图谱嵌入

知识图谱嵌入（Knowledge Graph Embedding, KGE）将实体和关系映射…

4.1 基本思想

知识图谱嵌入（Knowledge Graph Embedding, KGE）将实体和关系映射到低维向量空间，使得三元组的语义关系可通过向量运算表达。

4.2 TransE

最经典的翻译模型（Bordes et al., 2013）：

核心假设：h + r ≈ t

评分函数：f(h, r, t) = -‖h + r - t‖L1/L2

训练目标：正样本得分高，负样本得分低
损失函数：L = Σ max(0, γ + f⁻ - f⁺)（Margin-based ranking loss）

局限：无法处理一对多、多对一、多对多关系（1-N/N-1/N-N）。

4.3 TransR

将实体和关系投影到不同空间（Lin et al., 2015）：

h⊥ = h · Mr,   t⊥ = t · Mr

f(h, r, t) = -‖h⊥ + r - t⊥‖

Mr ∈ ℝk×d 是关系特定的投影矩阵

每种关系有自己的投影矩阵，可建模复杂关系。

4.4 DistMult

双线性模型，使用对角矩阵（Yang et al., 2015）：

f(h, r, t) = hT · diag(r) · t = Σ hi · ri · ti

特点：计算高效，但评分函数对称（f(h,r,t) = f(t,r,h)），无法建模非对称关系。

4.5 ComplEx

在复数空间上扩展 DistMult（Trouillon et al., 2016）：

实体和关系嵌入：h, r, t ∈ ℂd

f(h, r, t) = Re(Σ hi · ri · t̄i)

t̄ 为 t 的共轭复数 → 打破对称性

4.6 RotatE

将关系建模为复数空间中的旋转（Sun et al., 2019）：

t = h ∘ r,   其中 |ri| = 1（单位复数）

f(h, r, t) = -‖h ∘ r - t‖

∘ 表示 Hadamard 积（逐元素乘法）

可建模对称、反对称、逆、组合等多种关系模式。

4.7 嵌入方法对比

方法空间评分函数对称关系反对称关系逆关系组合关系
TransE实数-‖h+r-t‖✗✓✓✓
TransR实数-‖h⊥+r-t⊥‖✗✓✓✗
DistMult实数hTdiag(r)t✓✗✗✗
ComplEx复数Re(h·r·t̄)✓✓✓✗
RotatE复数-‖h∘r-t‖✓✓✓✓
  • TransE 核心思想 h + r ≈ t 最经典也最简单，但 1-N 问题是致命缺陷
  • DistMult 的对称性缺陷用 ComplEx 的复数空间解决
  • RotatE 是当前最强的浅层 KGE 方法之一，支持所有关系模式
  • 关系模式分类：对称、反对称、逆关系、组合关系，面试常问各方法的建模能力

链接预测

链接预测（Link Prediction）是知识图谱补全的核心任务：给定部分三元组 (h…

5.1 任务定义

链接预测（Link Prediction）是知识图谱补全的核心任务：给定部分三元组 (h, r, ?) 或 (?, r, t)，预测缺失的实体。

尾实体预测：给定 (h, r, ?)，对所有候选实体 t' 打分，排序取 top-k
头实体预测：给定 (?, r, t)，对所有候选实体 h' 打分，排序取 top-k

5.2 评估指标

指标定义说明
MRMean Rank正确实体排名的均值，越小越好
MRRMean Reciprocal Rank排名倒数的均值 = (1/|Q|) Σ 1/ranki，越大越好
Hits@1排名第1的比例精确命中率
Hits@3排名前3的比例top-3 命中率
Hits@10排名前10的比例top-10 命中率

Filtered 设置：评估时排除训练/验证集中已存在的其他正确三元组，避免误判。

5.4 应用场景

  • 推荐系统 — 预测 (用户, 可能喜欢, ?) → 推荐商品/内容
  • 药物发现 — 预测 (药物, 治疗, ?) → 发现潜在适应症（Drug Repurposing）
  • 社交网络 — 预测 (用户A, 可能认识, ?) → 好友推荐
  • 学术网络 — 预测 (论文A, 引用, ?) → 文献推荐
  • MRR 是链接预测最核心的指标，综合考虑了所有正确答案的排名
  • Filtered vs Raw 设置：Filtered 排除其他正确答案，更公平
  • FB15k 和 WN18 因信息泄露已弃用，应使用 FB15k-237 和 WN18RR
  • 药物发现中的链接预测是 KG 的高价值应用，面试热点

知识图谱推理

利用逻辑规则从已知事实推导新知识：

6.1 基于规则的推理

利用逻辑规则从已知事实推导新知识：

示例规则

// 传递性规则
(A, 父亲, B) ∧ (B, 父亲, C) → (A, 祖父, C)

// 对称性规则
(A, 配偶, B) → (B, 配偶, A)

// 组合规则
(A, 出生于, B) ∧ (B, 位于, C) → (A, 国籍, C)

方法

  • 手工规则 — 专家定义，精确但覆盖率低
  • 规则挖掘 — AMIE/AMIE+ 自动从数据中挖掘 Horn 规则
  • 可微分规则学习 — NeuralLP、DRUM，将规则学习转化为可微分优化问题

6.2 基于嵌入的推理

利用 KGE 模型的隐式推理能力：

  • TransE 系列通过向量运算隐式捕获传递性和组合关系
  • RotatE 通过旋转操作自然建模关系组合：r₁ ∘ r₂ = r₃
  • 优势：可扩展性好；劣势：推理过程不可解释

6.3 基于 GNN 的推理

利用图神经网络在图结构上进行归纳推理：

代表方法

方法思路特点
R-GCN关系感知的图卷积多关系图上的节点分类
CompGCN联合学习实体和关系嵌入支持多种组合操作
GraIL基于子图的归纳推理可泛化到未见实体
NBFNet广义 Bellman-Ford路径级推理，性能 SOTA

归纳推理 vs 转导推理

  • 转导推理（Transductive）— 训练和测试时图中的实体相同（TransE 等）
  • 归纳推理（Inductive）— 测试时出现新实体，模型需泛化（GraIL 等）
  • 规则推理可解释但覆盖率低；嵌入推理可扩展但不可解释；GNN 推理兼具两者优势
  • 归纳推理（对未见实体的泛化）是当前研究热点，GraIL 利用局部子图模式实现
  • R-GCN 的核心：对不同关系使用不同权重矩阵（或基分解降低参数量）
  • AMIE+ 挖掘的规则可与嵌入方法互补，形成混合推理系统

知识图谱 + LLM

方向一：KG 增强 LLM — 用知识图谱为 LLM 提供结构化知识，减少幻觉

7.1 两种融合方向

方向一：KG 增强 LLM — 用知识图谱为 LLM 提供结构化知识，减少幻觉

方向二：LLM 增强 KG — 用 LLM 的语言能力加速知识图谱的自动构建和补全

7.2 KG 增强 LLM（减少幻觉）

KG-Augmented Generation

  1. 用户提问 → 实体链接（将问题中的实体映射到 KG）
  2. 从 KG 中检索相关子图/三元组
  3. 将检索到的结构化知识注入 LLM Prompt
  4. LLM 基于知识生成回答
System: 你是一个基于知识图谱的问答助手。
        用以下知识回答用户问题，不要编造信息。

Context (from KG):
- (阿司匹林, 类型, 非甾体抗炎药)
- (阿司匹林, 作用机制, 抑制COX酶)
- (阿司匹林, 副作用, 胃肠道出血)
- (阿司匹林, 禁忌, 消化性溃疡)

User: 阿司匹林的副作用有哪些？

7.3 LLM 增强 KG（自动构建）

  • 实体/关系抽取 — LLM 作为零样本/少样本信息抽取器
  • 知识补全 — LLM 预测缺失三元组（作为评分函数）
  • 本体构建 — LLM 辅助定义 Schema 和类层次
  • 实体消歧 — 利用 LLM 的语义理解能力判断实体同一性

7.4 GraphRAG

GraphRAG（Graph Retrieval-Augmented Generation）是微软提出的将知识图谱与 RAG 结合的框架：

核心流程

  1. 索引阶段
    • LLM 从文档中抽取实体和关系，构建知识图谱
    • 使用 Leiden 算法对图进行社区检测
    • LLM 为每个社区生成摘要（Community Summary）
  2. 查询阶段
    • Local Search — 从问题相关实体出发，检索局部子图 + 关联文本
    • Global Search — 遍历所有社区摘要，适合全局性/主题性问题

GraphRAG vs 传统 RAG

维度传统 RAGGraphRAG
检索单元文本块（Chunk）实体 + 关系 + 社区摘要
全局理解弱（只看局部 chunk）强（社区摘要提供全局视图）
多跳推理困难天然支持（图遍历）
索引成本低高（需 LLM 抽取 + 社区检测）
适用场景事实型问答全局分析、多实体关联
  • KG+LLM 的核心价值：KG 提供可靠事实（减少幻觉），LLM 提供自然语言理解（降低构建门槛）
  • GraphRAG 的两种查询模式必须能区分：Local（实体相关的局部搜索）vs Global（社区摘要的全局搜索）
  • GraphRAG 的索引成本远高于传统 RAG，需要大量 LLM 调用来抽取实体和生成摘要
  • 知识图谱可以为 RAG 提供更精确的上下文，尤其适合多跳推理和实体关联问题

8.1 搜索引擎

Google Knowledge Graph（2012）是最广为人知的应用：

  • 搜索 "爱因斯坦" → 右侧知识面板展示结构化信息

Q1：什么是知识图谱？与传统数据库有什么区别？

知识图谱是一种用图结构描述现实世界中实体及其关系的语义知识库，核心数据单元是三元组 (头实体, 关系, 尾实体)。

与传统关系型数据库的区别：

  • 数据模型：RDBMS 用表存储，KG 用图（节点+边）存储
  • 关联查询：RDBMS 多表 JOIN 性能随深度急剧下降；图数据库通过指针遍历，多跳查询高效
  • Schema：RDBMS 需要固定 Schema；KG 灵活，可随时添加新实体/关系类型
  • 语义：KG 蕴含语义信息，支持推理；RDBMS 只存储原始数据
Q2：RDF 和属性图有什么区别？各有什么优缺点？

RDF（Resource Description Framework）：

  • W3C 标准，基于三元组 (Subject, Predicate, Object)
  • 使用 URI 全局唯一标识资源，查询语言为 SPARQL
  • 优点：标准化、跨系统互操作性好；缺点：边不能直接附属性（需 Reification），使用门槛较高

属性图（Property Graph）：

  • 节点和边都可以附带任意键值对属性
  • 查询语言如 Cypher（Neo4j）、Gremlin（Apache TinkerPop）
  • 优点：灵活、直观、工业落地容易；缺点：缺乏统一标准（正在制定 GQL 标准）
Q3：TransE 的核心思想是什么？有什么局限性？

核心思想：将关系建模为向量空间中的平移操作。对于正确的三元组 (h, r, t)，应满足 h + r ≈ t。

评分函数：f(h, r, t) = -‖h + r - t‖（L1 或 L2 范数）

训练：使用 margin-based ranking loss，拉近正样本、推远负样本。

局限性：

  • 1-N 关系：如 (中国, 首都, 北京) 没问题，但 (中国, 城市, ?) 有多个答案时，所有城市嵌入会被迫趋同
  • 对称关系：若 (A, 配偶, B) 和 (B, 配偶, A) 同时成立，需 r ≈ 0，无法区分
  • 自反关系：(A, 等于, A) 要求 r = 0

后续方法如 TransR（不同关系空间）、RotatE（复数旋转）解决了这些问题。

Q4：如何评估链接预测的性能？MRR 和 Hits@K 是什么？

链接预测的评估流程：对于测试三元组 (h, r, t)，将 t 替换为所有候选实体，计算评分并排序，记录正确实体的排名。

  • MR（Mean Rank）：正确实体排名的均值，越小越好
  • MRR（Mean Reciprocal Rank）：排名倒数的均值 = (1/N) × Σ(1/rank_i)，越大越好，是最核心的指标
  • Hits@K：正确实体排在前 K 位的比例，常用 K=1, 3, 10

Filtered vs Raw：Filtered 设置在排序时排除训练/验证集中已存在的其他正确三元组，避免将正确答案误判为错误，更公平。现在论文默认使用 Filtered 设置。

Q5：知识图谱的构建流程是怎样的？

知识图谱构建主要包含以下步骤：

  1. 数据采集：从多种来源（网页、数据库、文档、API）收集原始数据
  2. 信息抽取：
    • 实体识别（NER）：识别人名、地名、机构名等
    • 关系抽取（RE）：识别实体间的语义关系
    • 事件抽取：识别事件触发词和论元
  3. 知识融合：
    • 实体消歧：将同名异义实体区分开
    • 实体对齐：将不同来源中的同一实体合并
    • 属性融合：合并多源属性，解决冲突
  4. 质量评估：检查三元组的正确性和完整性
  5. 知识存储：导入图数据库（Neo4j / NebulaGraph 等）
  6. 持续更新：增量更新、过期知识淘汰
Q6：GraphRAG 与传统 RAG 有什么区别？

传统 RAG：将文档切分为文本块（Chunk），通过向量相似度检索相关块，注入 LLM 上下文。

GraphRAG：

  1. 索引阶段：用 LLM 从文档中抽取实体和关系构建知识图谱，使用 Leiden 算法做社区检测，为每个社区生成摘要
  2. 查询阶段提供两种模式：
    • Local Search — 从问题实体出发检索相关子图和文本
    • Global Search — 遍历社区摘要，适合全局性分析问题

核心优势：更强的全局理解能力（社区摘要）、天然支持多跳推理（图遍历）、更精确的实体关联。

劣势：索引成本高（大量 LLM 调用），维护更新复杂。

Q7：RotatE 是如何建模各种关系模式的？

RotatE 将关系建模为复数空间中的旋转，核心公式 t = h ∘ r，其中 |r_i| = 1（单位复数），∘ 为逐元素复数乘法。

  • 对称关系：r² = 1，即 r 的每个分量为 ±1（旋转 0° 或 180°）
  • 反对称关系：r² ≠ 1，旋转角度不为 0° 或 180°
  • 逆关系：r₂ = r₁⁻¹ = r̄₁（共轭复数，反向旋转）
  • 组合关系：r₃ = r₁ ∘ r₂（旋转角度可叠加）

相比 TransE 无法建模对称关系、DistMult 无法建模反对称关系，RotatE 是目前最全面的浅层 KGE 方法。

Q8：知识图谱如何与 LLM 结合来减少幻觉？

LLM 产生幻觉的根本原因是其知识存储在参数中，无法保证事实准确性。知识图谱提供外部可验证的结构化知识来解决此问题：

  1. 实体链接：将用户问题中的实体映射到 KG 中的节点
  2. 子图检索：从 KG 中检索相关三元组/子图作为上下文
  3. Prompt 注入：将结构化知识写入 System Prompt 或 Context
  4. 受限生成：要求 LLM 基于提供的知识回答，不要编造

优势：知识可追溯、可更新、可验证；挑战：实体链接准确性、KG 覆盖率有限。

Q9：归纳推理（Inductive Reasoning）和转导推理（Transductive Reasoning）有什么区别？

转导推理（Transductive）：

  • 训练和测试时图中的实体集合固定不变
  • 代表方法：TransE、DistMult、RotatE 等传统 KGE 方法
  • 对新出现的实体无法直接处理（需要重新训练）

归纳推理（Inductive）：

  • 测试时可以出现训练阶段未见过的新实体
  • 模型需学习通用的结构模式而非具体实体的嵌入
  • 代表方法：GraIL（基于局部子图结构）、NBFNet（基于路径）
  • 更接近真实场景（知识图谱持续新增实体）

归纳推理是当前研究的重要方向，因为实际应用中新实体的出现是常态。

Q10：知识图谱在推荐系统中解决了什么问题？

知识图谱在推荐系统中主要解决三个问题：

  1. 冷启动问题：新用户/物品缺少交互数据时，可通过 KG 中的属性和关系建立连接。例如新电影可通过导演、类型、演员等关系与用户已知偏好关联。
  2. 可解释性：KG 中的路径提供推荐理由。如"因为你喜欢《三体》(作者:刘慈欣) → 推荐《流浪地球》(作者:刘慈欣)"。
  3. 数据稀疏性：KG 提供了丰富的辅助信息，弥补了交互矩阵的稀疏性。

主要技术路线：

  • 嵌入方法（CKE）：用 KGE 增强物品表示
  • 路径方法（KPRN）：在 KG 上找用户到物品的路径并推理
  • 传播方法（RippleNet）：在 KG 上传播用户兴趣偏好
  • GNN 方法（KGAT）：利用图注意力网络聚合邻域信息
