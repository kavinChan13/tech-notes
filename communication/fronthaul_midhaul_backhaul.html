前传、中传、后传：Fronthaul / Midhaul / Backhaul

上一篇把基站拆成了 CU / DU / RU，它们之间用网络连接。这三段连接各有名字、各有截然不同的性能要求：前传（DU↔RU）、中传（CU↔DU）、后传（RAN↔Core）。理解它们的差异，尤其"为什么前传对延迟/抖动/带宽/同步如此苛刻"，是打开 CPRI/eCPRI 与 O-RAN 的钥匙。

Module 04 阅读 ~24 min 三段对比
01

三段承载全景

把 CU/DU/RU 之间的"线"命名

名字里的 "haul" 就是"搬运/牵引"。三段搬的东西完全不同——越靠近天线，搬的越是"贴近无线物理层的实时数据"，要求也越极端。

02

Backhaul 后传（RAN ↔ Core）

最"普通"的一段，就是常规 IP 承载

后传连接基站（CU）与核心网，搬运的是用户业务数据 + 核心网信令——本质就是 IP 包。它是三段里最"像普通互联网"的一段：

  • 数据：已经是面向用户的 IP 流量（上网、视频、语音的 PDU）。
  • 延迟：相对宽松（ms 级），因为无线实时处理已在 RAN 内完成。
  • 同步：要求最低。
  • 技术：标准 IP/MPLS/SR、光纤或微波承载，成熟廉价。
后传的工程重点是带宽、可靠性、成本，而不是极限低时延。它和 Module 01 讲的普通网络承载没有本质区别。
03

Midhaul 中传（CU ↔ DU）

承载 F1 接口，介于前传与后传之间

中传连接 CU 与 DU，承载 3GPP 定义的 F1 接口（对应 Option 2 拆分，切在 PDCP/RLC 之间）。此时数据已经是较高层的 RAN 协议数据（PDCP PDU），不再是原始基带采样。

  • 数据：RAN 内部的分组数据（比前传"抽象"，比后传"底层"）。
  • 延迟：中等（通常几 ms 量级），比前传宽松、比后传严。
  • 带宽：高，但远小于前传。
  • 技术：以太网 / IP 承载。
中传之所以"没那么苛刻"，正是因为 Option 2 把拆分点放得较高——高层数据经过压缩/聚合，带宽和时延压力都远小于"切在 PHY 里"的前传。这体现了 功能拆分 的核心权衡：拆得越高，传输越省心。
04

Fronthaul 前传（DU ↔ RU）

整个通信系统里最"变态"的一段

前传连接 DU 与 RU（Option 7-2x 拆分，切在 PHY 内部）。它搬运的是贴近无线物理层的实时数据——频域 IQ 采样。这段承载的要求堪称极端：

带宽巨大

Massive MIMO（64/128 天线）+ 大带宽 + 高采样率 → 前传要搬的 IQ 数据量惊人。传统 CPRI 下一个 100MHz 64T64R 小区前传可达几十甚至上百 Gbps。

延迟极低

无线的 HARQ 重传、调度有硬性时间预算。前传单向时延通常要求 ~100 µs 级（O-RAN 定义了 Category A/B 的时延窗口），远严于普通网络。

抖动极小

IQ 数据是"按时间刻度对齐"的，抖动会直接破坏信号。前传对包到达时间的抖动容忍度极小。

同步极严

DU 和 RU 必须频率 + 相位/时间都精确对齐（TDD 尤甚），靠 PTP/SyncE 达到 ns 级同步。

IQ 数据：无线信号用同相（I）和正交（Q）两路采样表示的复数基带样本。前传搬的就是这些采样（传统 CPRI 传时域 IQ，eCPRI/7-2x 传频域 IQ + 部分处理下沉到 RU 以省带宽）。IQ 的细节见 eCPRI 深入。

06

为什么前传最苛刻

根因是"它离无线物理层最近"

把因果链理清楚：拆分点越往下（越靠近 RF）→ 传的越是"未加工的物理层实时数据" → 数据量越大、时间越敏感 → 带宽/时延/抖动/同步要求越极端。

拆分点位置        传什么              代价
Option 2 (中传)  高层分组(压缩过)     省带宽、时延宽松
Option 7-2x(前传) 频域 IQ(部分下沉)   带宽大、时延µs级
Option 8 (旧CPRI) 时域 IQ(几乎原始)   带宽爆炸
这条因果链解释了整个后半主题：因为前传太苛刻，CPRI（Option 8）带宽扛不住 → 出现 eCPRI（7-2x） 把部分处理下沉到 RU 以省带宽 + 用以太网承载；因为要 ns 级同步 → 需要 PTP/SyncE；因为多厂商互通 → 需要 O-RAN Open Fronthaul。
07

承载技术选择

每段该用什么"搬运工"

  • 前传：对时延/同步最敏感 → 传统用 CPRI（专线式），5G/O-RAN 用 eCPRI over Ethernet（分组化、灵活、可用通用交换机），配合 VLAN + QoS 优先保障 + PTP/SyncE 同步。
  • 中传：以太网 / IP，承载 F1，QoS 适中。
  • 后传：成熟 IP/MPLS/SR，重带宽与可靠性。
🎯 本篇要点回顾
  • 前传=DU↔RU、中传=CU↔DU、后传=RAN↔Core，对应 Open FH / F1 / NG 接口
  • 越靠近天线，传的越是原始实时数据，延迟/带宽/抖动/同步要求越极端
  • 前传最苛刻：~100µs 时延、数十 Gbps 带宽、ns 级相位同步
  • 前传苛刻正是 CPRI→eCPRI 演进、PTP/SyncE、O-RAN 前传规范的根本动因
