01

4G / 5G 架构

Q1画出 5G 网络的整体架构：UE 到核心网。
P0必考
要点

UE(终端) → RAN(无线接入网, 5G 里的 gNB) → Core Network(5GC)。RAN 负责空口无线，核心网负责鉴权/会话/路由到数据网络。5G 相比 4G 引入 SBA 服务化核心网、NR 新空口、网络切片。

Q25G 三大应用场景是什么？
P1概念
要点
  • eMBB：增强移动宽带（高速率，视频/AR）。
  • URLLC：超可靠低时延（工业控制/自动驾驶）。
  • mMTC：海量机器通信（IoT 大连接）。
02

CU / DU / RU

Q3为什么要把基站拆成 CU/DU/RU？各自负责什么？
P0核心必考
要点
  • 拆分动因：集中化(降成本/协同)、云化(通用硬件)、灵活部署、多厂商。
  • CU：高层协议(PDCP/RRC 等)，可集中部署，处理时延不敏感的功能。
  • DU：实时基带(RLC/MAC/高PHY)，靠近站点，处理实时调度。
  • RU：射频 + 低PHY，装在天线侧，做数模转换与发射。
  • 时间尺度：RU(µs级实时) < DU(ms级) < CU(更松)。
Q43GPP Option 2 和 Option 7-2x 拆分点分别在哪？
P0深入
要点
  • Option 2：CU-DU 之间的拆分点（PDCP/RLC 之间），对应 F1 接口。
  • Option 7-2x：DU-RU 之间的拆分点（PHY 层内的低/高分割），是 O-RAN 前传采用的拆分，把部分物理层处理下沉到 RU，降低前传带宽。
陷阱

拆分点越靠近射频(如 Option 8/CPRI)前传带宽越大；7-2x 传频域 IQ 大幅省带宽。

Q5BBU/RRH/AAU 和 CU/DU/RU 是什么关系？
P1历史
要点

4G 时代：BBU(基带)+RRH(远端射频)，CPRI 连接；AAU=RRH+天线一体(Massive MIMO)。5G 把 BBU 进一步拆成 CU+DU，RRH/AAU 演进为 RU。是同一演进脉络的不同阶段。

03

前中后传

Q6Fronthaul / Midhaul / Backhaul 有什么区别？为什么前传最苛刻？
P0必考
要点
  • Fronthaul(DU↔RU)：传实时 IQ 相关数据，延迟~100µs、带宽数十Gbps、同步 ns 级——最苛刻。
  • Midhaul(CU↔DU)：F1 接口，RAN 分组数据，要求较高。
  • Backhaul(RAN↔Core)：用户/核心网数据，要求相对宽松。
  • 前传苛刻是因为承载的是接近射频的实时采样，对时延/抖动/同步极敏感。
04

CPRI / eCPRI

Q7OBSAI/CPRI/eCPRI 为什么会依次出现？eCPRI 解决了什么？
P0高频
要点
  • CPRI 传时域 IQ，带宽随天线数/带宽线性暴涨；到 5G Massive MIMO 时 CPRI 带宽不可承受、且是刚性专线、难开放。
  • eCPRI 两招：① 处理下沉 + 频域 IQ 大幅降带宽；② 以太网/分组化承载，灵活、可统计复用、支持多厂商。
Q8eCPRI 跑在 TCP 上吗？它和以太网是什么关系？
P0易错
要点
  • 不跑 TCP。eCPRI 通常直接封在以太网帧里(EtherType 0xAEFE)，也可选 over UDP/IP，但绝不用 TCP（TCP 重传/拥塞控制的延迟不可接受）。
  • eCPRI 是前传应用层协议，以太网是它的承载。
05

O-RAN 与接口

Q9O-RAN 是什么？和 3GPP 是什么关系？
P0必考
要点
  • O-RAN 是一套开放架构/标准体系（不是单一协议），目标：开放接口、虚拟化、智能化、多厂商互操作。
  • 与 3GPP 互补：在 3GPP 定义的 RAN 基础上，把接口开放化(尤其前传)、增加 SMO/RIC 等，不是取代 3GPP。
陷阱

别说"O-RAN 取代 3GPP"。O-RAN 复用 3GPP 的功能拆分(如 Option 7-2x)，只是把接口开放。

Q10Open Fronthaul 和 eCPRI 是一回事吗？
P0易错
要点

不是。Open Fronthaul 是 O-RAN 定义的开放前传接口/规范（含 CUS 平面、管理），eCPRI/以太网是它上面用的承载协议之一。关系：O-RAN ⊃ Open Fronthaul(接口) ⊃ eCPRI/Ethernet(承载)。

Q11O1 / E2 / A1 / F1 分别连谁、做什么、属于哪个面？
P0高频
要点
  • F1：CU↔DU，3GPP 原生中传接口。
  • O1：SMO↔各网元，管理面（NETCONF/YANG）——配置/故障/性能。
  • E2：Near-RT RIC↔CU/DU，近实时控制(10ms~1s)，如 KPM/RC。
  • A1：Non-RT RIC↔Near-RT RIC，下发策略/意图。
06

RIC

Q12Non-RT RIC 和 Near-RT RIC 有什么区别？rApp/xApp 是什么？
P1深入
要点
  • Non-RT RIC(≥1s，在 SMO 内)：策略/ML 训练/长周期优化，跑 rApp，通过 A1 下发策略。
  • Near-RT RIC(10ms~1s)：近实时控制，跑 xApp，通过 E2 控制 CU/DU。
  • 意义：把 RAN 智能开放给第三方应用，实现可编程、可优化的网络。
