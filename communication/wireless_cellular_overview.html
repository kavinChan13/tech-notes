01

无线通信的本质

把"有线的以太网"换成"空中的电磁波"

无线与有线在分层思想上相通（见 通信系统与协议总览），区别只在物理层的介质：有线是电/光信号在铜/光纤里跑，无线是电磁波在空中传播。这个区别带来一连串独特挑战：

信道共享空中是公共媒介，大家共用同一片频谱调度 / 多址（OFDMA）分配时频资源

1.1 频谱是被切成小块、逐块拍卖出去的

软件工程师对"稀缺"的直觉来自 CPU 和内存——不够就加机器。频谱不是：总量由物理定律固定，分配方式由国家法律固定，都不能用钱直接买到更多。可用频段大致是 600 MHz ~ 6 GHz 加 24 ~ 40 GHz 毫米波，还要与广播、雷达、卫星、Wi-Fi 共享；一家运营商能独占的连续带宽，中频约 100 MHz，低频只有 10 MHz 量级。

类比：频谱像城市主干道的车道。你能让车开得更快（高阶调制）、挨得更紧（提频谱效率）、上下叠层（MIMO），但不能凭空多修一条车道——修车道要国家批。

于是频谱效率（bit/s/Hz）成了全行业的核心 KPI。而当它触顶（香农极限就在那里），只剩两条路：去更高频段抢新带宽，或把小区做小、让同一块频谱被复用更多次——5G 两件都做了。

1.2 香农公式：加带宽是线性的，提信噪比是对数的

香农容量公式：C = B · log₂(1 + SNR)。C 是无差错传输的理论速率上限（bit/s），B 是带宽（Hz），SNR 是信噪比（线性值，不是 dB）。它给出的是上界——任何编码调制方案都不可能超过它，实际系统通常能做到它的 60%~80%。

它在工程上最重要的信息不是"容量有上限"，而是两个变量的量纲完全不同：B 在括号外（线性），SNR 在 log₂ 里（对数）。代几组数：

# C = B · log2(1 + SNR)，SNR 先从 dB 转成线性：SNR_lin = 10^(SNR_dB/10)

B = 20 MHz,  SNR = 20 dB (=100)   → 20e6 × log2(101)  = 133 Mbps
B = 20 MHz,  SNR = 30 dB (=1000)  → 20e6 × log2(1001) = 199 Mbps   ← SNR +10 dB，只多 50%
B = 100 MHz, SNR = 20 dB (=100)   → 100e6 × log2(101) = 666 Mbps   ← 带宽 ×5，容量正好 ×5
B = 400 MHz, SNR = 10 dB (=10)    → 400e6 × log2(11)  = 1384 Mbps  ← 信噪比很差，但带宽大就是赢

最后一行是 5G 战略的钥匙：毫米波信道条件差得多（路损大、一堵墙就断），但一个载波就有 400–800 MHz，中频拼死只有 100 MHz。用"差信道 + 大带宽"换"好信道 + 小带宽"，在香农公式下是划算的。

你想提升容量手段收益形态现实天花板

"信号满格却很慢"的解释就在右半张图里。满格说的是 SNR 好，而高 SNR 区间已进入平坦段——限制你的不是信号质量，是分到手的带宽。反过来小区边缘那段曲线很陡，每 1 dB 都值钱，那正是波束成形与功控要服务的区域。
面试加分点：补一句"带宽也不是无限有用"。功率固定时加带宽，噪声功率 N = N₀·B 同步上涨，容量收敛到与带宽无关的上界 C∞ ≈ 1.44·P/N₀。所以在功率受限的上行（手机只有百毫瓦），"多要带宽"的收益远不如下行——上下行不对称的根子在物理，不在协议设计。

1.3 路径损耗：频率翻倍就多丢 6 dB

路径损耗（Path Loss）：电磁波从发射天线传到接收天线过程中功率的衰减，单位 dB。自由空间公式 FSPL(dB) = 20·log₁₀(d) + 20·log₁₀(f) + 32.44（d 单位 km，f 单位 MHz）。两个 20·log₁₀ 意味着：距离翻倍多损 6 dB，频率翻倍也多损 6 dB。

原因不是空气吃掉了高频，而在接收天线的有效面积：增益固定时有效面积正比于波长的平方，频率翻倍波长减半、面积只剩四分之一，功率少 6 dB。同样尺寸的天线在高频上"接得少"。

# 自由空间路径损耗，距离统一取 1 km
FSPL(1 km, 700 MHz)   = 0 + 20·log10(700)   + 32.44 = 89.3 dB
FSPL(1 km, 3500 MHz)  = 0 + 20·log10(3500)  + 32.44 = 103.3 dB   ← 比 700M 多 14.0 dB
FSPL(1 km, 28000 MHz) = 0 + 20·log10(28000) + 32.44 = 121.4 dB   ← 比 700M 多 32.0 dB

# 那 14 dB 换算成"要多少站才能覆盖同样的面积"
# 城区实测的路径损耗指数 n 约 3.5（自由空间是 2），半径比 = 10^(-ΔL / (10·n))
半径比 = 10^(-14.0 / 35) = 0.40
面积比 = 0.40² = 0.16   →   站数 ≈ 1 / 0.16 ≈ 6.3 倍
口径说明：这个"6 倍站"只算了自由空间的频率项，并假设 n = 3.5、其余链路预算完全相同。真实规划还要叠加穿透损耗与人体阻挡，实际差距通常更大。看到"高频要多几倍站"的数字，先问口径。

毫米波那 32 dB 不能这样外推：主导因素已不是自由空间损耗，而是阻挡（blockage）——一堵墙、一辆卡车、甚至握手机的那只手，都能让链路从"能用"直接跌到"断开"。这是开关式行为，所以毫米波不是"覆盖一片区域"，而是"点亮若干视距热点"。

1.5 多径与衰落：无线信道是"时变"的

前面三节讲的是"平均意义上信号有多强"。真正的复杂性在另一件事：信号强度不是一个稳定的数，它在毫秒尺度上剧烈起伏。

多径（Multipath）：信号经直射、反射、绕射、散射走多条路径到达接收端。路径长度不同 → 相位不同，这些副本在接收天线处矢量相加：同相则增强，反相则相消。
一句话结论：无线信道是时变、频变、且只能被"估计"而不能被"读取"的信道。这解释了无线协议栈为什么塞满测量—反馈—自适应的闭环：测 CQI 选调制编码、出错靠 HARQ 重传、邻区更好就切换。有线里"链路要么通要么断"的二值假设在无线里不成立。
真实案例：一个"只在下午三点变慢"的工厂专网。产线 AGV 每天下午视频回传卡顿，RSRP 稳定、误块率不高。根因是换工装时一批金属料架被移到 AGV 路线与天线之间，形成强反射面，与直射的时延差恰好造成特定子带的深度衰落。无线问题的根因经常在物理世界里，而不在协议栈里——排查顺序是"先看信道，再看协议"。
02

为什么叫"蜂窝"网络

用空间复用把稀缺频谱用出最大容量

蜂窝（Cellular）把区域切成许多小格子（cell），每格由一个基站覆盖，相隔较远的小区复用同一段频率——用空间换容量。小区画成正六边形拼接像蜂巢，故名蜂窝。

小区（Cell）

一个基站覆盖的区域。城区小而密（容量优先），郊区大而疏（覆盖优先）。5G 还有覆盖几十米的小基站做热点增强。

切换（Handover）

跨小区移动时网络无缝转移连接。切换要够快够可靠，否则通话与视频会断——这对信令时延提出了硬要求。

2.1 频率复用：蜂窝这个名字的全部含义

先把"大功率单塔"算死：一座城市分到 100 MHz，一百万用户同时在线，人均 100 Hz——这不是"慢一点"，是数量级上不成立；加功率没用（香农是对数的），加天线也没用。唯一出路是让同一段频率在不同地方被同时使用，这之所以可行，是因为电磁波随距离衰减，隔得够远的同频基站在对方那里已弱到构不成有效干扰。

频率复用（Frequency Reuse）：把频谱分成 N 组，相邻小区用不同组，隔开一定距离再重复使用。N 称簇大小，六边形栅格下只能取 N = i² + i·j + j²，即 1、3、4、7、12、13、19……"蜂窝"指的就是这套六边形复用栅格，不是指基站长得像蜂巢。

簇大小 N 一头连容量、一头连干扰，是个纯取舍旋钮：单小区可用带宽 = 总带宽 / N，而同频复用比 Q = D/R = √(3N)（N 越大同频小区隔得越远、干扰越小）。下表 SIR 由 SIR ≈ Q⁴/6 估出（第一圈 6 个干扰源、路损指数取 4）：

2.3 从"噪声受限"到"干扰受限"：无线工程的分水岭

整章最重要、也最容易被忽略的一句：一旦开始复用频率，限制性能的就不再是噪声，而是自己网络里其他小区的信号。

噪声受限（Noise-limited）

单塔、无复用。性能由 SNR 决定，提功率就能提性能，因为噪声不会跟着涨。所有优化手段方向一致。

干扰受限（Interference-limited）

蜂窝的现实。性能由 SINR 决定，主要成分是邻区同频信号。提功率是零和游戏——你抬高的同时也抬高了邻区干扰，全网 SINR 几乎不变，所有优化手段从此都带副作用。

类比：噪声受限像在安静房间里小声说话，提高音量总有效；干扰受限像在满座餐厅里说话——你喊别人也喊，谁也没听得更清楚。餐厅的解法是隔断（定向天线）、分时段说话（调度）、约定谁何时安静（干扰协调）——蜂窝网络做的正是这三件事。
工程动作噪声受限世界里干扰受限世界里（现实）

2.4 小区分裂：把容量翻上去的标准动作，以及它的账单

话务量涨到扛不住时，标准动作是小区分裂（cell splitting）——把半径 R 的大小区换成若干半径 R/2 的小小区，并调低发射功率以保持相同的边缘强度。

03

三大件：UE / RAN / Core

整个蜂窝网络永远是这三段

UE（User Equipment）

手机、CPE、IoT 模组、车载模块……凡是接入网络的终端都是 UE，通过空口（Uu）与基站通信。

RAN（无线接入网）

由基站组成，负责无线侧的一切：收发电磁波、调度时频资源、编解码、加密、连接管理。本主题后半段全在讲 RAN 的内部结构。

Core（核心网）

网络的"大脑与管家"：认证鉴权、会话管理、移动性管理、计费，以及连接外部数据网络。4G 叫 EPC，5G 叫 5GC，基本都是数据中心里的软件。

一句话锚定：UE 是终端，RAN 是"把无线信号变成数据包"的接入网，Core 是"管用户与会话、通往互联网"的核心网。本主题聚焦 RAN。

3.1 三段的分界线到底画在哪

一次上网发生了什么

把三大件串成一个动作

  1. 开机注册：UE 搜小区，经基站向 Core 发起注册；Core 鉴权并记录 UE 位置。
  2. 建立会话：Core 建一条数据承载（PDU 会话），分配 IP。
  3. 数据传输：IP 包经空口 → RAN → 回传 → Core → Internet，返程相反。
  4. 移动切换：RAN 在小区间切换、Core 更新位置，连接不中断。
"控制面 / 用户面"的区分已经出现：注册、鉴权、建会话是控制面（信令），真正的上网数据是用户面。这个"面"会在 O-RAN 与通信软件架构里反复出现。

4.2 随机接入：为什么非它不可

前面几步 UE 都在"听"，随机接入是它第一次开口。它要四条消息，是因为必须同时解决两个互相纠缠的问题。

问题一：上行定时对齐

下行是一对多广播，各自同步即可；上行是多对一，基站要求所有 UE 的信号同时到达才能保持时域正交。但各 UE 距离不同、时延不同，各自按看到的时刻发就必然错位。

问题二：竞争解决

UE 还没有专用资源，只能在公共 PRACH 上碰运气，而可选前导只有 64 个。多个 UE 挑中同一个完全可能，网络必须能判断"我回复的到底是谁"。

5.1 五个网元各自在忙什么

理解 EPC 的关键是：每个网元的"形状"由它承载的负载性质决定，而这个形状恰恰是后来 5G 要打破的东西。

5.3 EPC 的痛点：不是功能不够，是形状不对

EPC 撑起了全球移动互联网，它的问题是在 5G 需求下才暴露的，而且都不是"缺某个功能"，是结构性的：

痛点具体表现5G 的回应

② 用户面无法独立下沉P-GW 是"控制 + 转发"的整体，下沉一个等于在每个边缘机房复制一整套复杂网元UPF 纯转发、可大量部署到边缘——这是 MEC 的前提
③ 点对点专用接口每两个网元一套专用协议，新增能力要改多个对端实现，标准化周期以年计SBA：统一 HTTP/2 + JSON，NRF 做服务发现
④ 拓扑写死在配置里没有服务注册与发现，扩容一台要改一圈配置NRF 注册与发现，实例可动态上下线
⑤ 一张网只有一套 QoS 策略给不了不同客户参数迥异、互相隔离的逻辑网络网络切片：见 §6.3
⑥ 专用硬件、纵向扩展多为专用板卡，扩容靠换更大的机器，弹性差云原生：容器化 + 横向扩展
面试加分点：被问"EPC 有什么问题"时不要答"功能不够 / 性能不行"——两个都不成立。准确说法是"功能没问题，问题是形状"：它把扩容维度不同的（①）、该下沉与该集中的（②）、演进速度不同的（③）绑在了一起。5GC 的每个设计动作都对应解开其中一处耦合。

6.2 为什么三者不能同时最优

三者必须"分开服务"而不是"一起满足"，是因为它们对同一批设计旋钮的要求方向相反——不是资源不够，是方向冲突。

类比：三者像货运卡车、救护车、一万辆自行车共用一条马路。卡车要宽车道；救护车要随时能通行，哪怕清空一条车道；自行车单个不占地方，但光在路口逐个登记就能瘫痪交通。没有"对三者都最优"的马路，只能划专用车道各自定规则——这就是网络切片。

3GPP 确实给了一些"同时服务"的机制，但每一个都是在承认冲突的前提下做的妥协：

  • 抢占（pre-emption）：URLLC 来了直接打断正在传的 eMBB 资源——等于明说两者只能有优先级。
  • 免调度上行（Configured Grant）：预配周期性资源省掉调度请求往返，代价是没数据时资源也空着——用确定的浪费换确定的时延。
  • 灵活子载波间隔与 BWP：同一载波上不同 BWP 配不同 numerology。最优雅的一招，但解决的是"能共存"不是"都最优"。
  • RedCap：为中档物联网裁剪的能力档位，承认了"用完整 NR 终端做传感器"在成本上不成立。
实现细节见 5G NR 物理层与 MAC 层。本篇只需一个判断："5G 同时支持 eMBB / URLLC / mMTC"的正确读法是"5G 定义了服务这三者所需的机制"，而不是"一次部署能把三者同时做到最优"。为 eMBB 调优的公网小区，URLLC 指标基本无从谈起。

6.3 网络切片：把冲突交给"分而治之"

网络切片（Network Slicing）：在同一套物理网络上划分出多个逻辑隔离、参数各自独立的端到端网络，各有自己的 QoS 策略、资源配额、甚至独立的 NF 实例。标识是 S-NSSAI，由 SST（切片/服务类型）与可选的 SD（区分同类型的不同租户）组成；标准化 SST 取值中 1 = eMBB、2 = URLLC、3 = MIoT。

逻辑很直接：一套参数满足不了三种诉求，那就让每种诉求有一套自己的参数。关键在"端到端"——切片必须贯穿 RAN、传输网、核心网，任何一段没隔离 SLA 就不成立：

切片要在哪一段落地隔离手段这一段没隔离的后果
RAN（空口资源）预留资源块配额、独立调度优先级、必要时独立小区或载波最难也最关键。空口资源是真正稀缺的，这里不隔离，一个下载视频的用户就能把工控切片的时延顶穿
传输网（前传/中传/回传）VLAN、专用波长、FlexE、带优先级的分组承载最容易被忘的一段：两个切片的流量在同一根光纤同一个队列里排队，时延抖动无从保证
核心网独立 NF 实例（尤其 UPF）、独立配额与策略相对最容易，5GC 本身就是云原生的——这也是切片常被"只讲核心网"的原因
面试加分点：指出切片最大的难点在 RAN 而不在核心网。"给切片 A 保证 20% 资源"在调度器里含义微妙——硬预留（没人用也空着）还是软优先（争抢时优先，但给不出硬保证）？多数商用实现做的是后者，于是"SLA 保证"实际是"统计意义上的优先"，签合同时这是关键区别。机制见 QoS、网络切片与边缘。

6.5 SA 与 NSA：为什么大家先上了"不完整的 5G"

两种组网的差别不在无线，而在控制面挂在谁身上、用哪个核心网。

7.1 破除"5G 就是快"

"5G 峰值 20 Gbps"对日常体验没有任何预测力，原因有三层，每层都能独立把体验拉回来。

① 峰值是实验室数字

20 Gbps 是 ITU 对 IMT-2020 的能力上界定义，达成它要聚合极大的毫米波带宽、极多空间流、且用户独占全部资源。它回答的是"技术最多能做到什么"。

② 频段决定天花板

你实际连的多半是 3.5 GHz 的 100 MHz，带宽只有毫米波的几分之一。手机显示 5G 图标，不代表你连的是高带宽载波。

③ 资源是分出来的

小区容量要被所有在线用户瓜分，凌晨与演唱会散场差几十倍很正常。这一项与制式无关，是蜂窝网络的固有性质。

8.1 基础（必答）

点击每道题展开参考答案（先自测，再对照）。

  1. 基础香农公式 C = B·log₂(1+SNR) 在工程上告诉了我们什么？为什么 5G 要去抢毫米波？

    公式本身给的是无差错传输的速率上界，实际系统能做到它的六到八成。但它在工程上最重要的信息不是"有上限"，而是两个变量的量纲完全不同：

    带宽 B：线性
    在 log 外面。带宽翻倍，容量就翻倍，没有折扣。
    信噪比 SNR：对数
    在 log₂ 里面。SNR 提高 10 dB（也就是 10 倍）容量只多几成——在高 SNR 区间边际收益极小。

    代几个数最直观：20 MHz / 20 dB 约 133 Mbps，把 SNR 抬到 30 dB 也只有 199 Mbps（+50%）；但把带宽加到 100 MHz，容量直接变成 666 Mbps（×5）。

    这就是毫米波的全部理由：它的信道条件明显更差（路径损耗大、易被阻挡、SNR 常年低迷），但一个载波就有 400–800 MHz 带宽，而中频拼死只有 100 MHz。用"差信道 + 大带宽"换"好信道 + 小带宽"，在香农公式下是划算的——400 MHz / 10 dB 能算出约 1.4 Gbps，远超 20 MHz 下再怎么优化信噪比的结果。

    加分点：补一句带宽也不是无限有用。发射功率固定时，加带宽会让噪声功率 N₀·B 同步上涨，容量最终收敛到 P/(N₀·ln2) 这个与带宽无关的上界。所以在功率受限的上行（手机只有百毫瓦量级）上，"多要带宽"的收益远不如下行——上下行不对称的根子在物理，不在协议设计。

  2. 基础为什么频率越高覆盖越差？能不能量化？

    先纠正一个常见的错误解释：不是空气把高频信号"吃掉"了（大气吸收在 Sub-6 和常用毫米波频段并不是主导因素）。真正的原因在接收天线的有效面积：天线增益固定时，有效接收面积正比于波长的平方。频率翻倍则波长减半，有效面积只剩四分之一，收到的功率就少 6 dB。

    自由空间路径损耗公式把它写死了：FSPL(dB) = 20·log₁₀(d) + 20·log₁₀(f) + 32.44（d 单位 km，f 单位 MHz）。两个 20·log₁₀ 意味着距离翻倍多损 6 dB，频率翻倍也多损 6 dB。

    量化到真实频点，同样取 1 km：700 MHz 是 89.3 dB，3.5 GHz 是 103.3 dB，差 14 dB；28 GHz 是 121.4 dB，比 700 MHz 差 32 dB。

    再把 14 dB 换算成站数：城区路径损耗指数取 n = 3.5，半径比 = 10^(−14/35) ≈ 0.40，面积比 = 0.16，同覆盖需要约 6 倍的站。

    答题时务必带上口径
    这个"6 倍"只算了自由空间的频率项，假设其余链路预算相同、n=3.5。真实规划还要叠加穿透损耗（3.5 GHz 穿墙明显更差）与人体阻挡，实际差距通常更大。不带口径的倍数是不可信的。
    毫米波不能这样外推
    它的主导因素已经不是自由空间损耗而是阻挡——一堵墙、一辆卡车、甚至握手机的那只手都可能让链路从"能用"直接跌到"断开"。这是开关式行为，不是连续衰减。所以毫米波的部署模型是"点亮若干视距热点"，不是"覆盖一片区域"。
  3. 基础"蜂窝"这个名字到底指什么？频率复用是怎么提升容量的？

    "蜂窝"指的是六边形频率复用栅格，不是指基站长得像蜂巢。

    先把单塔方案算死：一座城市分到 100 MHz，全城一个塔，一百万用户平分，人均 100 Hz。这不是"慢一点"，是数量级上不成立。而加功率没用（香农是对数的），加天线也没用（单点空分能力有限）。

    唯一出路是让同一段频率在城市不同地方被同时使用——这可行是因为电磁波随距离衰减，隔得够远的两个同频基站在对方那里已经弱到构不成有效干扰。于是：

    • 把频谱分成 N 组（簇大小），相邻小区用不同组，隔开一定距离后重复使用；
    • 六边形栅格下 N 只能取 i² + i·j + j²，即 1、3、4、7、12、19……；
    • 总容量 ≈ 单小区容量 × 小区数。只要愿意继续加站，容量理论上可以一直涨。

    代价是两条定量关系互相拉扯：单小区可用带宽 = 总带宽 / N（N 越大容量越低），而同频复用比 Q = D/R = √(3N)（N 越大干扰越小）。所以 N 就是一个"容量 ↔ 质量"的旋钮：GSM 时代常用 N=7（换来约 19 dB 的载干比），而 LTE/NR 干脆用 N=1 全频复用——放弃频域隔离，靠 OFDMA 的小区内正交、小区间调度协调和强纠错硬扛干扰。

  4. 基础UE 从开机到能上网，经历了哪些关键步骤？时间主要花在哪？

    五个阶段，前四个全是控制面信令，一个用户字节都没传：

    阶段做什么耗时量级
    ① 小区搜索与下行同步扫频段找 SSB，从 PSS/SSS 得到小区 ID 与定时，从 PBCH 读 MIB数十 ms ~ 数秒
    ② 读系统消息SIB1 给出 PLMN、小区是否禁止接入、随机接入参数数十 ms
    ③ 随机接入（Msg1–Msg4）拿到时间提前量 TA + 完成竞争解决~10 ms（一次成功）
    ④ RRC 连接 + NAS 注册鉴权进入 RRC_CONNECTED；双向鉴权、安全模式、位置登记数百 ms
    ⑤ PDU 会话建立选 UPF、分配 IP、下发转发规则、建立 DRB数十~数百 ms

    时间主要花在①的频段扫描和④的核心网往返上，而不是无线协议本身。①在完全冷启动时要扫整个频段，秒级很常见；④要多次往返并访问归属地签约数据库，漫游时可能跨国。

    一个能证明你真理解了的日常观察：飞行模式关掉后要等好几秒，但开着机进出电梯只要几百毫秒——后者不需要重新扫频段，也可能直接从 RRC_INACTIVE 恢复，跳过绝大部分 NAS 流程。

8.2 中级（区分熟练度）

  1. 中级为什么说蜂窝网络是"干扰受限"而不是"噪声受限"？这个转变改变了什么？

    因为一旦复用频率，限制性能的就不再是热噪声，而是自己网络里其他小区的同频信号。LTE/NR 用 N=1 全频复用，邻区就是同频干扰源，小区边缘的 SINR 甚至可能低于 0 dB——此时热噪声的贡献可以忽略不计。

    这个转变最要命的后果是：提高发射功率从"纯收益"变成了"零和游戏"。你抬高功率的同时也抬高了邻区收到的干扰，全网 SINR 几乎不变。从此所有优化手段都带副作用：

    动作噪声受限世界干扰受限世界（现实）
    提高发射功率覆盖变大，纯赚邻区边缘用户 SINR 变差；还可能把用户"吸"到过远小区，造成上行受限
    抬天线 / 减小下倾角传得更远，纯赚越区覆盖——宏站最常见的干扰源
    新增基站多覆盖一片容量涨了，但同时给周边引入新干扰源，邻区关系与参数要重做
    最实用的一条：RSRP 与 SINR 要分开看
    "RSRP 好但 SINR 差"是干扰受限网络的典型指纹，在用户侧表现为"信号满格但网速慢"。RSRP 只测服务小区参考信号的功率，测不出旁边还有几个同样强的邻区在同频发射。所以定位问题的第一步永远是分清覆盖问题（RSRP 低）还是干扰问题（RSRP 高、SINR 低）——这两者的解法方向相反：前者要加强信号，后者要压低并收拢信号。

    加分点：指出现代无线优化的主要工作已经不是"补覆盖"而是"控干扰"——把每个小区的能量约束在它该待的地方。以及 LTE/NR 敢用 N=1，本质上是把干扰问题从"物理隔离"转成了"调度问题"。

  2. 中级随机接入到底解决什么问题？为什么需要四步而不是一步？

    它同时解决两个互相纠缠的问题，缺一步都不行。

    问题一：上行定时对齐
    下行是一对多广播，UE 各自同步即可；上行是多对一，基站要求所有 UE 的信号同时到达才能保持时域正交。但各 UE 距离不同、传播时延不同，各自按自己看到的时刻发就必然错位。
    问题二：竞争解决
    UE 此时还没有任何专用资源，只能在公共的 PRACH 上碰运气，而可选前导只有 64 个。多个 UE 撞上同一个前导是完全可能的，网络必须能判断"我回复的到底是谁"。

    定时问题量化一下就知道有多严重：光速约 3.33 µs/km（单程）。距基站 0.1 km 和 3 km 的两个 UE，信号到达时刻差约 19.3 µs；而 NR 中频常用配置（SCS 30 kHz）下常规循环前缀只有约 2.3 µs。19.3 远大于 2.3，远处 UE 的符号会整个错位、糊到近处 UE 的下一个符号上，两个用户的数据一起报废。

    于是四步各司其职：

    • Msg1（UE→gNB）：随机挑一个 PRACH 前导发出去。基站据其接收时刻测出传播时延。
    • Msg2（gNB→UE）：RAR，下发时间提前量 TA 与上行授权 → 解决定时对齐。
    • Msg3（UE→gNB）：RRCSetupRequest，携带 UE 的唯一标识 → 报上"我是谁"。
    • Msg4（gNB→UE）：竞争解决消息，回显 Msg3 里的标识 → 一致者赢，不一致者退避重试。
    加分点：它还定义了小区半径的物理上限
    前导必须落在基站为它预留的接收窗口内，窗口长度由前导格式的循环前缀决定。距离太远的 UE 前导迟到超窗，基站根本收不到——这与"信号强度够不够"是两个独立的失败原因。一个远处的高增益 CPE 完全可能信号很好却接入不上。另外 NR 引入了 2-step RACH（把四步压成 msgA/msgB）来省时延，代价是竞争冲突时的处理更复杂。
  3. 中级EPC 有什么痛点？为什么说"问题不是功能不够"？

    先给结论：EPC 的功能是完整的、性能也撑起了全球移动互联网。它的问题是"形状"——把本不该绑在一起的东西绑在了一起。说"功能不够"或"性能不行"都会被追问打死。

    耦合后果5G 的解法
    控制面与用户面耦合在同一网元（S-GW/P-GW）两者扩容维度完全不同——视频流量涨要转发能力，IoT 涨要信令能力。绑在一起意味着任一维吃紧都得整机扩容CUPS：控制面是一组 NF，用户面只剩 UPF，独立扩缩
    该下沉的和该集中的耦合P-GW 是"控制 + 转发"的整体，下沉一个等于在每个边缘机房复制一整套复杂网元，成本不可接受UPF 纯转发、可大量部署到边缘 → MEC 的前提
    演进速度不同的东西耦合（点对点专用接口）每两个网元一套专用协议（GTP-C、Diameter），新增能力要改多个对端实现，标准化周期以年计SBA：HTTP/2 + JSON 服务化调用，NRF 服务发现
    拓扑写死在配置里没有服务注册发现，扩容一台要改一圈配置NRF 动态注册与发现
    整网一套 QoS 策略做不出"给这家工厂一张独立的网"网络切片

    加分点：指出这个"解耦"和软件工程里的微服务拆分完全同构，包括它带来的同一批新问题——服务发现、可观测性、版本兼容、调用链变长后的时延累积与故障放大。5GC 不是"更简单"，是把复杂度从"接口标准化"转移到了"分布式系统治理"。

  4. 中级CUPS 和 SBA 分别解决了什么？它们是同一件事吗？

    不是同一件事，也不在同一个维度上。混为一谈是这道题最常见的失分点。

    CUPS：纵向拆分（拆"面"）
    把控制逻辑与数据转发分开。控制面成为一组网络功能（AMF 管接入与移动性、SMF 管会话、AUSF/UDM 管鉴权签约、PCF 管策略），用户面只剩一个 UPF。解决的是扩容维度绑死与用户面无法下沉两个问题。
    SBA：横向重构（换"通信方式"）
    把网元之间的点对点专用接口换成服务化调用：能力暴露成服务，统一用 HTTP/2 + JSON，由 NRF 做注册与发现。解决的是接口演进慢与拓扑写死两个问题。

    一句话区分：CUPS 改的是"一个网元内部该不该拆成两半"，SBA 改的是"网元之间怎么说话"。两者正交——理论上可以只做 CUPS 不做 SBA（3GPP R14 在 EPC 上就是这么干的，用 Sx 接口 + PFCP 协议），也可以只做 SBA 不做 CUPS。5GC 是两个都做了。

    值得补的三点：

    • UPF 是唯一保留"点对点"的地方：用户面转发对性能极度敏感，不适合用 HTTP/2，所以 N3/N9 仍然是 GTP-U，控制它的 N4 用 PFCP。SBA 只覆盖控制面，这是有意为之。
    • CUPS 的真正价值在边缘：没有它，MEC 与低时延业务无从谈起——这比"扩容更灵活"重要得多。
    • SBA 的隐性收益是生态：从电信专有协议切到通用 Web 技术栈，意味着工具链、调试手段、人才池全部可以复用。

8.3 高级（体现深度）

  1. 高级eMBB / URLLC / mMTC 为什么不能同时最优？请从设计旋钮的层面说明。

    关键不是"资源不够"，而是三者对同一批设计旋钮的要求方向相反。逐个旋钮看：

    旋钮eMBBURLLCmMTC
    TTI / 调度粒度长 TTI、大传输块，摊薄控制开销短 TTI / 迷你时隙希望免调度
    码率与冗余高码率 + 256QAM，塞满每个符号低码率 + 重复传输，宁可浪费也要一次成功低码率（发射功率低、覆盖差）
    是否保持连接无所谓必须常连或预留资源必须深度休眠（电池撑十年）
    频段越高越宽越好，愿意去毫米波不要大带宽，要覆盖稳定窄带即可，但要极好的穿透（水表在地下室）

    其中两处是硬对立，不是程度差异：

    • "常连"与"深度休眠"：URLLC 要随时能发，mMTC 要绝大部分时间关着射频。同一个终端不可能两者兼得。
    • "短 TTI"与"高频谱效率"：短 TTI 意味着每个小数据块都要配一份控制信息，控制开销占比暴涨；把可靠性从 10⁻¹ 提到 10⁻⁵ 所需的冗余是数倍资源——这些资源直接从吞吐里扣。

    更强的论据是：3GPP 自己提供的"共存机制"每一个都是在承认冲突。抢占机制让 URLLC 直接打断正在传输的 eMBB 资源（明说了只能有优先级）；Configured Grant 用"没数据时资源也空着"这种确定的浪费换确定的时延；灵活 numerology 与 BWP 解决的是"能共存"而不是"都最优"；RedCap 则是承认了用完整 NR 终端做传感器在成本上不成立。

    最实用的一句结论
    "5G 同时支持三大场景"的正确读法是"5G 定义了服务这三者所需的机制"，不是"一次部署能把三者同时做到最优"。一个为 eMBB 调优的公网小区，URLLC 指标基本无从谈起——这也是企业客户往往需要专网或独立切片的根本原因。
  2. 高级网络切片解决什么问题？落地时最难的一段在哪？

    切片是上一题那个冲突的直接答案：既然一套参数无法同时满足三种诉求，那就让每种诉求拥有一套自己的参数，并保证它们互不影响。切片标识是 S-NSSAI（SST + 可选 SD），3GPP 为常见类型定了标准化 SST：1 = eMBB、2 = URLLC、3 = MIoT。

    关键在"端到端"三个字——切片必须贯穿 RAN、传输网、核心网三段，任何一段没隔离，SLA 就不成立：

    段隔离手段难度
    RAN（空口）资源块配额、独立调度优先级、必要时独立载波或小区最难，见下
    传输网VLAN、专用波长、FlexE、带优先级的分组承载中等，但最容易被忘
    核心网独立 NF 实例（尤其 UPF）、独立配额与策略相对最容易——5GC 本身就是云原生的
    最难的是 RAN，而不是核心网
    核心网侧起一组独立容器实例是成熟技术；但空口资源是物理稀缺的。"给切片 A 保证 20% 资源"这句话在调度器里含义很微妙：是硬预留（没人用也空着，浪费掉）还是软优先（有争抢时优先，但给不出硬保证）？大多数商用实现做的是后者，于是"SLA 保证"实际上是"统计意义上的优先"——这在签合同时是决定性的区别。
    第二容易踩的坑：传输网被忽略
    切片讨论常常只讲核心网和 RAN，结果两个切片的流量在同一根光纤、同一个队列里排队，端到端时延抖动完全无从保证。切片的木桶短板通常在那段没人认领的传输网上。

    加分收尾：切片真正改变的其实是商业模式——它让运营商第一次能把"一张有确定参数的逻辑网络"作为商品卖给企业客户，而不只是卖流量。技术难点与商业价值都集中在"隔离是不是真的"这一点上。

  3. 高级SA 与 NSA 怎么选？NSA 对 RAN 侧软件意味着什么？

    先说清差别不在无线，而在控制面锚点与核心网：NSA（Option 3x）控制面挂在 LTE 基站上、沿用 EPC，NR 只做辅节点；SA（Option 2）控制面在 gNB 上、用 5GC。

    运营商先上 NSA 的三个理由都很硬，不是技术偷懒：

    • 覆盖是硬伤：5G 主力频段 3.5 GHz 的覆盖半径只有 LTE 的几分之一。控制面若也放在 NR 上，用户一到边缘就掉网；NSA 把控制面留在覆盖好的 LTE 上，NR 只在信号好时贡献速率，体验反而更稳。
    • 时间窗口：不用等 5GC 建成就能商用，两三年内把"5G"这件事做出来是商业刚需。
    • 存量资产：EPC 是已经花过钱、跑得很稳的系统。

    代价也很明确：NSA 下切片、URLLC QoS、边缘分流全都跑不起来，因为这些能力都在 5GC 里。所以 NSA 只能服务"更快的手机上网"这一件事，5G 的结构性价值一个都拿不到。

    对 RAN 软件的三个影响（这是加分点）
    ① gNB 要实现 EN-DC 辅节点角色——承载分离、辅节点添加/修改/释放流程，复杂度不比独立组网低；② PDCP 要支持分流与重排序，数据在 LTE 与 NR 两条无线链路上乱序到达，重组逻辑是真实的踩坑点；③ 同一份软件要能在两种组网下降级运行，配置分支显著变多，测试组合翻倍。所以"NSA 比较简单"这句话对运营商成立，对写代码的人不成立。

    选型判据：只要目标业务需要切片、URLLC 或边缘分流，就必须 SA，没有中间路线；如果目标只是提升公众用户的下载速率，且 5G 连续覆盖尚未建成，NSA 在过渡期是理性的。行业整体方向是向 SA 收敛，但存量 NSA 与双模并存会持续相当长时间——这意味着 RAN 软件在可预见的将来仍要同时维护两套组网逻辑。

  4. 高级综合题：5G 到底比 4G 强在哪？（要求先破除"5G 就是快"）

    这道题考的是判断力。只答"更快"直接判定为不了解；照背 eMBB/URLLC/mMTC 只算及格。好的回答分三层。

    ① 先破除峰值速率误解。"20 Gbps"是 ITU 对 IMT-2020 的能力上界定义，达成它需要聚合极大的毫米波带宽、极多空间流、且用户独占全部资源。真实体验被三件事各自独立地拉回来：

    • 频段：你实际连的多半是 3.5 GHz 的 100 MHz，带宽只有毫米波的几分之一。按 3GPP 峰值公式算，FR1 100 MHz / 4 流 / 256QAM、TDD 下行占比约 7:3 时，现实峰值在 1.6 Gbps 量级，而不是 20 Gbps。
    • 站密度：3.5 GHz 比 1.8 GHz 多损十几 dB，室内穿墙后可能直接掉到只能跑最低档调制——"5G 反而比 4G 慢"在室内是真实存在的现象，而且不是故障。
    • 负载：小区容量要被所有在线用户瓜分，凌晨与演唱会散场差几十倍是正常的。这一项与制式无关，是蜂窝网络的固有性质。

    ② 再指出真正的结构性优势——共同点是4G 不是"做得慢一点"，而是架构上根本提供不了：

    时延的可控性
    注意是"可控"而不是"低"。灵活 numerology、迷你时隙、抢占机制让空口时延可以做短；更关键的是 UPF 能下沉到离用户几公里的边缘——4G 的 P-GW 是控制转发一体的整体，下沉成本不可接受。工业场景要的从来不是"平均快"，而是最坏情况有界。
    连接密度
    提高一个数量级（10⁵ → 10⁶ /km²），配合免调度传输与 RedCap 等轻量档位。4G 的随机接入与信令面是按"人"的数量级设计的，百万设备会形成信令风暴。
    网络切片带来的逻辑隔离
    4G 整网一套策略，做不出"给这家工厂一张参数独立的网"。这是三项里商业价值最大的一项。
    上行能力与部署形态
    灵活帧结构与上行增强让直播回传、机器视觉上云成为可能（这些业务是上行受限的）；CU/DU/RU 拆分与 O-RAN 让专网可以小规模自建，也给了运营商供应链谈判杠杆。

    ③ 最后补商业视角，这往往是拉开差距的一句：5G 最大的变化其实是从"卖流量给个人"转向"卖 SLA 给企业"。切片、专网、MEC 全都是为这件事服务的。这也解释了一个表面矛盾——消费者感知不强，但建设仍在大规模推进，因为它的目标客户本来就不是消费者。

    如果还想再加一分，可以诚实地补一句：这些结构性能力目前的商用兑现程度并不高（切片的"保证"多数是统计优先、URLLC 大规模公网部署仍少见）。指出"能力已具备、价值兑现仍在路上"，比一味唱好更能体现判断力。
