01

无线通信的本质

把"有线的以太网"换成"空中的电磁波"

无线通信和有线通信在协议分层上是相通的——都要寻址、都要可靠性、都要分层。区别只在物理层的介质：有线是电/光信号在铜/光纤里跑，无线是电磁波在空中传播。但这个区别带来一连串独特挑战：

无线的挑战为什么后果 / 应对
信道共享空中是"公共媒介"，大家都在用同一片频谱需要调度/多址（OFDMA）分配时频资源
衰落与干扰建筑遮挡、多径、移动带来信号忽强忽弱编码/重传（HARQ）、功控、波束成形
频谱稀缺频谱是国家拍卖的稀缺资源提升频谱效率：MIMO、高阶调制
移动性用户在小区间移动切换（handover）、位置管理
频谱 / 频段：无线用的电磁波频率范围。低频（如 700MHz）覆盖广、穿透好但带宽小；高频（如毫米波 mmWave 24GHz+）带宽大、速率高但覆盖近、易被遮挡。5G 同时用中频（Sub-6GHz）和毫米波来兼顾覆盖与容量。
02

为什么叫"蜂窝"网络

用空间复用把稀缺频谱用出最大容量

如果全城只用一个大功率发射塔，频谱很快就不够分。蜂窝（Cellular）的思路是：把区域切成许多小格子（cell），每个格子由一个基站覆盖，相隔较远的小区可以复用同一段频率——这就是"频率复用"，用空间换容量。小区形状画成正六边形拼接像蜂巢，故名蜂窝。

小区（Cell）

一个基站覆盖的区域。城区小区小而密（容量优先），郊区小区大而疏（覆盖优先）。5G 还有覆盖几十米的"小基站"（small cell）做热点增强。

切换（Handover）

用户从一个小区移动到另一个，网络无缝把连接转移过去。切换要足够快、足够可靠，否则通话/视频会断——这对信令时延提出了要求。

03

三大件：UE / RAN / Core

整个蜂窝网络永远是这三段

UE（User Equipment）

用户终端：手机、CPE、IoT 模组、车载模块……凡是接入网络的终端都是 UE。它通过空口（Uu 接口）与基站通信。

RAN（Radio Access Network，无线接入网）

由基站组成，负责无线侧的一切：收发电磁波、调度时频资源、编解码、加密、连接管理。本主题后半段（CU/DU/RU、前传、O-RAN）全是在讲 RAN 的内部结构。

Core（Core Network，核心网）

网络的"大脑与管家"：用户认证鉴权、会话/承载管理、移动性管理、计费、以及连接到外部数据网络（Internet）。4G 叫 EPC，5G 叫 5GC。核心网基本是数据中心里的软件（尤其 5G 全面云化）。

一句话锚定：UE 是终端，RAN 是"把无线信号变成数据包"的接入网，Core 是"管理用户与会话、通往互联网"的核心网。本主题聚焦 RAN，Core 只需知道它在 RAN 之后。
04

一次上网发生了什么

把三大件串成一个动作

  1. 开机注册：UE 搜索小区，通过基站向 Core 发起注册；Core 校验 SIM/鉴权，记录 UE 位置。
  2. 建立会话：UE 请求上网，Core 建立一条数据承载（PDU 会话），分配 IP。
  3. 数据传输：UE 的 IP 包经空口 → 基站（RAN）→ 回传 → Core → Internet；返程相反。RAN 负责无线段，Core 负责路由到外网。
  4. 移动切换：UE 移动时，RAN 在小区间切换、Core 更新位置，连接不中断。
注意"控制面"和"用户面"的区分已经出现：注册/鉴权/建会话是控制面（信令），真正的上网数据是用户面。这个"面"的概念会在 O-RAN 与通信软件架构里反复出现。
05

4G LTE 架构

eNB + EPC

4G 把上面的抽象落成具体网元：

部分网元职责
RANeNB（eNodeB，4G 基站）无线接入的全部功能，一个 eNB 是一个"整块"基站
Core (EPC)MME移动性管理、信令（控制面）
Core (EPC)S-GW / P-GW用户面数据转发、连接外网
Core (EPC)HSS用户签约数据库、鉴权
4G 的 eNB 是一个相对整体的基站（内部虽有 BBU + RRH，但对外是一体）。5G 的关键变化，就是把基站进一步拆分成 CU/DU/RU——这正是下一篇的主题。
这里只列了 EPC 的网元清单。它们各自的接口（S1-MME / S1-U / S5 / S11 / S6a）、GTP-C 与 GTP-U 的分工，以及"为什么控制面与用户面耦合会变成瓶颈"，深入见 Module 03 核心网演进：从 EPC 到 5GC 服务化架构。
06

5G NR 架构与三大场景

gNB + 5GC，服务化 + 云原生

5G 的无线叫 NR（New Radio），基站叫 gNB，核心网叫 5GC。5GC 采用服务化架构（SBA）——网元变成一组微服务（AMF 管移动性、SMF 管会话、UPF 转发用户面），全面云原生化。

eMBB

增强移动宽带。超高速率，服务高清视频、AR/VR。追求大带宽。

URLLC

超可靠低时延。工业控制、自动驾驶、远程手术。追求低时延 + 高可靠。

mMTC

海量机器通信。海量 IoT 传感器。追求海量连接 + 低功耗。

这三大场景解释了 5G 很多设计动因：URLLC 的低时延要求直接推动了 RAN 功能拆分（把处理下沉到靠近天线的 DU/RU） 与 严格的前传时间同步（PTP/SyncE）；eMBB 的大带宽 + Massive MIMO 又造成 CPRI 前传带宽爆炸、催生 eCPRI。后面几篇会一一展开。
5GC 这一段在本篇只给了骨架。CUPS 拆分、SBA 的 HTTP/2 + NRF 服务发现、N1–N9 参考点、UE 注册与 PDU 会话建立两条主流程，见 核心网演进；三大场景对应的 QoS 模型与网络切片见 QoS、网络切片与边缘；"云原生化"具体意味着什么见 电信云原生。

🎯 本篇要点回顾
  • 无线只是把物理层换成电磁波，带来信道共享、衰落、频谱稀缺、移动性等挑战
  • 蜂窝 = 用空间复用频率提升容量；切换保证移动不断线
  • 任何蜂窝网都是 UE → RAN → Core 三段；本主题聚焦 RAN
  • 4G：eNB + EPC；5G：gNB（CU/DU/RU）+ 5GC（服务化云原生）
  • 5G 三大场景（eMBB/URLLC/mMTC）是后续 RAN 拆分、前传演进、时间同步的根本动因
