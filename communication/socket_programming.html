01

Socket 是什么

应用与内核网络栈的门

Socket：操作系统给应用程序提供的网络通信端点抽象。你对它 read/write，内核负责底下的 TCP/IP/Ethernet。一个 socket 由 (协议, 本地IP:端口, 远端IP:端口) 唯一标识。

它把 Module 01 讲的分层封装/解封装全部藏在内核里——你只管把字节写进去、从里面读出来。

02

TCP 服务端 / 客户端流程

经典调用序列

服务端

socket() → bind() → listen() → accept()（阻塞等连接）→ recv()/send() → close()

客户端

socket() → connect()（触发三次握手）→ send()/recv() → close()

connect() 背后就是 TCP 三次握手；accept() 返回的是一条已建立连接的新 socket，监听 socket 继续收新连接。
03

TCP 代码骨架

最小可运行示例（Linux/C）

// 服务端（省略错误处理）
int lfd = socket(AF_INET, SOCK_STREAM, 0);
int opt = 1; setsockopt(lfd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));

struct sockaddr_in addr = {0};
addr.sin_family = AF_INET;
addr.sin_addr.s_addr = htonl(INADDR_ANY);
addr.sin_port = htons(9000);          // htons: 主机序→网络序(大端)

bind(lfd, (struct sockaddr*)&addr, sizeof(addr));
listen(lfd, 128);                     // backlog

int cfd = accept(lfd, NULL, NULL);    // 阻塞等一条连接
char buf[4096];
ssize_t n = recv(cfd, buf, sizeof(buf), 0);  // 可能只读到部分!
send(cfd, buf, n, 0);
close(cfd); close(lfd);
// 客户端
int fd = socket(AF_INET, SOCK_STREAM, 0);
struct sockaddr_in srv = {0};
srv.sin_family = AF_INET;
srv.sin_port   = htons(9000);
inet_pton(AF_INET, "127.0.0.1", &srv.sin_addr);
connect(fd, (struct sockaddr*)&srv, sizeof(srv));  // 三次握手
send(fd, "hello", 5, 0);
char buf[64]; recv(fd, buf, sizeof(buf), 0);
close(fd);
⚠️ 关键：TCP 是字节流，recv 返回值可能小于你期望的长度。必须循环收满，并配合 消息分帧（长度前缀等）才能还原一条完整消息。
04

UDP 代码骨架

无连接，收发即用

// 服务端
int fd = socket(AF_INET, SOCK_DGRAM, 0);   // SOCK_DGRAM = UDP
struct sockaddr_in addr = {0};
addr.sin_family = AF_INET; addr.sin_port = htons(9001);
addr.sin_addr.s_addr = htonl(INADDR_ANY);
bind(fd, (struct sockaddr*)&addr, sizeof(addr));

struct sockaddr_in cli; socklen_t cl = sizeof(cli);
char buf[2048];
ssize_t n = recvfrom(fd, buf, sizeof(buf), 0, (struct sockaddr*)&cli, &cl);
sendto(fd, buf, n, 0, (struct sockaddr*)&cli, cl);  // 回给来源
UDP 无 connect/accept（可选 connect 只是固定对端）。每次 recvfrom 收到的就是一个完整数据报，天然有边界——没有"粘包"，但可能丢包/乱序。eCPRI-over-UDP 就是这种模型。
05

TCP vs UDP 编程差异

一表看懂

维度TCP (SOCK_STREAM)UDP (SOCK_DGRAM)
连接需 connect/accept无连接
收发调用send/recvsendto/recvfrom
消息边界无（字节流，需分帧）有（每个数据报独立）
可靠性内核保证顺序/重传需应用自己处理丢包
适用配置/文件/管理面实时/低延迟/前传
06

阻塞 / 非阻塞与 I/O 多路复用

从一个连接到十万连接

  • 阻塞：recv 没数据就卡住。一线程一连接，简单但不扩展。
  • 非阻塞 + I/O 多路复用：用 epoll（Linux）一个线程管理成千上万 fd，哪个就绪处理哪个——高并发服务器的基础。
  • Reactor 模式：epoll 事件循环 + 回调分发，是绝大多数高性能网络框架（nginx、Redis、DPDK 上层）的骨架。
// epoll 事件循环骨架
int ep = epoll_create1(0);
struct epoll_event ev = { .events = EPOLLIN, .data.fd = lfd };
epoll_ctl(ep, EPOLL_CTL_ADD, lfd, &ev);
struct epoll_event evs[1024];
for (;;) {
  int n = epoll_wait(ep, evs, 1024, -1);
  for (int i = 0; i < n; i++) {
    if (evs[i].data.fd == lfd) { /* accept 新连接并加入 epoll */ }
    else { /* recv 数据、按协议分帧、处理 */ }
  }
}
07

工程要点

通信软件常踩的坑

  • 字节序：多字节字段发送前 htons/htonl，接收后 ntohs/ntohl（详见 二进制协议）。
  • 短读短写：send/recv 都可能只处理一部分，要循环。
  • SO_REUSEADDR：服务重启避免 "Address already in use"。
  • TCP_NODELAY：关闭 Nagle 降低小包延迟（实时场景常用）。
  • 半关闭 / SIGPIPE：对端关闭后写会触发 SIGPIPE，需处理。
🎯 本篇要点回顾
  • Socket 是应用与内核网络栈之间的端点抽象
  • TCP：socket/bind/listen/accept/connect/send/recv；字节流需分帧
  • UDP：sendto/recvfrom，天然有边界但不可靠
  • 高并发靠 epoll + Reactor 事件循环
  • 注意字节序、短读短写、TCP_NODELAY
