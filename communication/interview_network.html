01

分层模型

Q1OSI 七层和 TCP/IP 四层的对应关系？为什么要分层？
P0高频
要点
  • OSI：物理/数据链路/网络/传输/会话/表示/应用。TCP/IP：链路(网络接口)/网络/传输/应用（把会话+表示+应用合为应用层）。
  • 分层好处：解耦、各层独立演进、复用、易排障——每层只依赖下层服务、给上层提供服务。
  • 代价：分层有开销（每层封装头），极致性能场景会跨层优化。
陷阱

OSI 是参考模型（教学用），实际互联网跑的是 TCP/IP。别把两者混为一谈。

Q2数据从应用程序到网卡经历了什么？（封装过程）
P1概念
要点

逐层加头：应用数据 → +TCP/UDP头(段) → +IP头(包) → +以太网头/尾(帧) → 物理层比特流。接收端逐层解封装。这就是"协议栈"的工作方式。

追问

"协议"和"传输机制"是一回事吗？——不是。协议是双方约定的格式+规则；传输机制是承载它的通道（如 TCP/以太网）。同一协议可跑在不同传输上。

02

TCP / UDP

Q3TCP 为什么可靠？列出核心机制。
P0高频
要点
  • 序列号 + 确认(ACK)：保证顺序、检测丢失。
  • 超时重传：丢了重发。
  • 校验和：检测损坏。
  • 流量控制(滑动窗口)：不淹没接收方。
  • 拥塞控制(慢启动/拥塞避免)：不淹没网络。
  • 连接管理(三次握手/四次挥手)：建立/释放有序。
Q4为什么握手是三次、挥手是四次？TIME_WAIT 有什么用？
P0经典
要点
  • 三次握手：确认双方收发能力都正常；两次不够（无法确认客户端能收）。
  • 四次挥手：TCP 全双工，两个方向各自关闭；被动方 ACK 和 FIN 通常不能合并（还有数据要发），所以拆成四次。
  • TIME_WAIT(2MSL)：确保最后 ACK 到达、让旧连接的迷途报文消散，避免影响新连接。
陷阱

大量 TIME_WAIT 是主动关闭方的正常现象；高并发短连接服务器可用连接复用/SO_REUSEADDR 缓解。

Q5TCP 和 UDP 怎么选？UDP 为什么适合实时数据？
P0高频
要点
  • TCP：可靠、有序、有连接，适合文件/配置/网页——要求不丢不乱。
  • UDP：无连接、低开销、无重传，适合实时音视频/游戏/前传——宁可丢也不要等（迟到的重传数据对实时已无意义）。
  • 实时系统更怕延迟和抖动，TCP 的重传+拥塞控制会引入不可控延迟。
Q6什么是 TCP 粘包/拆包？怎么解决？
P1工程
要点

TCP 是字节流，没有消息边界，一次 recv 可能读到半条或多条消息。解决=应用层分帧：① 定长；② 分隔符；③ 长度前缀（最常用）。UDP 天然有边界，无此问题。

03

Ethernet / IP

Q7MAC 地址和 IP 地址的区别？一个包转发时它们怎么变化？
P0高频
要点
  • MAC：链路层，本地寻址，逐跳有效；IP：网络层，端到端逻辑寻址。
  • 转发中：源/目的 IP 全程基本不变（NAT 除外），而MAC 逐跳改写（每经一个路由器换成下一跳的 MAC）。
  • ARP 负责在同一网段把 IP 解析成 MAC。
Q8IP 地址靠什么找到主机？端口的作用是什么？
P1概念
要点

IP 定位主机（哪台机器），端口定位进程/服务（机器上哪个应用）。一个连接由五元组唯一标识：协议 + 源IP:端口 + 目的IP:端口。

04

Socket

Q9描述 TCP 服务端/客户端的 socket 调用流程。
P0必考
要点
  • 服务端：socket → bind → listen → accept → recv/send → close。
  • 客户端：socket → connect(触发三次握手) → send/recv → close。
  • accept 返回一条新连接 socket，监听 socket 继续收新连接。
追问

如何支持高并发？——非阻塞 + epoll(Reactor)，一个线程管理海量连接。

05

VLAN / QoS / MTU

Q10VLAN 解决什么问题？QoS 又是什么？
P1概念
要点
  • VLAN：在同一物理网络上做逻辑隔离，划分广播域，提升安全与管理性（如前传把 C/U/M/S 平面分 VLAN）。
  • QoS：对不同流量分级与优先调度，保证关键业务（如同步/控制面）的延迟与带宽。
Q11什么是 MTU？分片会带来什么问题？
P1工程
要点

MTU 是链路层单帧最大载荷（以太网默认 1500B）。超过要分片，分片增加开销、任一片丢失整包重传、还可能被防火墙丢弃。用 Path MTU Discovery 探测最小 MTU 避免分片；前传常用 Jumbo Frame 提升效率。

06

网络性能

Q12延迟、吞吐、抖动、带宽的区别？为什么实时系统最怕抖动？
P0高频
要点
  • 带宽=链路理论容量；吞吐=实际达到的速率；延迟=单程/往返耗时；抖动=延迟的波动。
  • 实时流(语音/前传)靠固定节奏播放/处理，抖动大会导致缓冲欠载/溢出、卡顿——比平均延迟更致命。
  • 关注尾延迟(p99/p999)而非平均，追求确定性。
