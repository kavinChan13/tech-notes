5G RAN：CU / DU / RU 与基站功能拆分

这是整个主题最核心的一篇。上一篇我们知道 RAN 由基站组成。现在打开基站这个"黑盒"：5G 为什么要把一个基站拆成 CU、DU、RU 三块？各自负责什么？它们之间怎么连？理解了这张拆分图，前传（Fronthaul）、eCPRI、O-RAN 就都有了归宿。

核心篇 ★★★★☆ Module 02 阅读 ~30 min 3GPP Split
01

从"一体基站"到"拆分"

为什么不能像 4G 那样一整块

4G 的 eNB 基本是"一体式"。到了 5G，一个基站要处理 Massive MIMO 的海量数据、要支持 URLLC 的超低时延、还要能云化部署——继续做成整块会遇到三个问题：

① 部署不灵活

有些功能希望集中部署（省机房、易协调、便于云化），有些必须靠近天线（实时处理）。一整块无法两头兼顾。

② 成本与扩展

把"高层协议处理"集中到数据中心，多个站点共享算力池，比每个站点堆一套硬件更省、更易扩容。

③ 开放与解耦

拆分后各模块可由不同厂商提供、按需组合——这正是 O-RAN 的前提。

于是 3GPP 把 gNB 在功能上拆成三段：CU（集中单元）、DU（分布单元）、RU（射频单元）。核心思想：按"实时性要求"把功能切开——越实时的越往下沉、越靠近天线；越不实时的越往上收、越可集中。

02

历史脉络：BBU / RRH / AAU

拆分不是凭空来的，是一路演进的结果

在 CU/DU/RU 之前，工程界已经经历了几代基站形态。先认识这几个"老名词"，才能看懂演进：

名词全称是什么
BBUBaseband Unit基带处理单元，做数字信号处理（调制/编码等），通常放机房
RRHRemote Radio Head远端射频头，做数模转换 + 射频，装在铁塔上靠近天线
AAUActive Antenna Unit有源天线单元 = RRH + 天线阵列一体化（5G Massive MIMO 常用）

演进逻辑：早期 BBU 和射频在一起 → BBU + RRH 分离（BBU 进机房、RRH 上塔，中间用 CPRI 连），这就是 C-RAN 的雏形 → 5G 进一步把 BBU 的功能再拆成 CU + DU，RRH/AAU 演变为 RU。

对应关系（不必死记，理解即可）：5G 的 CU + DU ≈ 原来的 BBU 功能被拆开；RU ≈ RRH/AAU 演进而来。"BBU 拆成 CU 和 DU"是理解 5G RAN 的关键一句。
03

CU / DU / RU 各干什么

按协议栈层次分工

5G 无线协议栈自上而下大致是：RRC / SDAP / PDCP → RLC / MAC / High-PHY → Low-PHY / RF。CU/DU/RU 就是把这个栈切成三段：

CU集中单元（Centralized Unit）。处理高层、非实时协议：RRC（连接管理）、PDCP（加密、排序）、SDAP。可放在边缘数据中心，一个 CU 管多个 DU。还常再分 CU-CP（控制面）与 CU-UP（用户面）。
DU分布单元（Distributed Unit）。处理实时性较强的中层：RLC、MAC（调度！）、High-PHY。对时延敏感，通常部署在靠近站点的机房。调度器在这里，是性能关键。
RU射频单元（Radio Unit）。处理最底层、最实时的 Low-PHY + 射频：FFT/IFFT、数模转换、波束成形、功放，直连天线。装在铁塔/杆上。
为什么这样切？越靠近天线的处理越"实时、越硬件密集"（必须在几十微秒内完成），所以下沉到 RU/DU；越靠上的处理越"控制、越可软件化、越可集中"，所以上收到 CU。拆分点本质是"实时性"与"集中度"的权衡。
04

3GPP Functional Split

在协议栈的哪一刀切下去

"到底在哪一层拆"不是唯一答案。3GPP 定义了 Option 1~8 共 8 种候选拆分点，越靠上拆（如 Option 2）对前传带宽/时延要求越低，越靠下拆（如 Option 7/8）实时处理越集中但前传压力越大。业界主流：

拆分切在哪用于前传要求
Option 2PDCP / RLC 之间CU ↔ DU（F1 接口）较宽松（中传 Midhaul）
Option 7-2xPHY 内部（Low/High-PHY 之间）DU ↔ RU（Open Fronthaul）很严（前传 Fronthaul）
Option 8PHY 与 RF 之间传统 CPRI 拆分极严（带宽爆炸）
记住两个主流拆分点：CU–DU 用 Option 2（对应 F1 接口、中传）；DU–RU 用 Option 7-2x（对应 Open Fronthaul、前传）。O-RAN 选择 7-2x 作为开放前传拆分点，正是在"前传带宽"和"多厂商互操作"之间取的平衡——这直接关系到 eCPRI 与 Open Fronthaul。
05

完整架构图

从核心网一路到 UE

把连接段的名字对上：CU↔Core 是回传（Backhaul，NG 接口）；CU↔DU 是中传（Midhaul，F1 接口）；DU↔RU 是前传（Fronthaul，用 eCPRI/Open Fronthaul）；RU↔UE 是空口。这三"传"就是 下一模块 的主角。

CU vs DU vs RU 对比

维度CUDURU
协议层RRC / SDAP / PDCPRLC / MAC / High-PHYLow-PHY / RF

面试："CU、DU、RU 分别干什么？为什么这样拆？"
答题框架：先说三段对应协议栈的高/中/低层；再点出拆分依据是"实时性 vs 集中度"的权衡；最后带出连接段（回传/中传/前传）和对应接口（NG/F1/Open FH）。能自然引出"前传对时延同步极敏感"就是加分项。
07

拆分带来的新问题

好处不是白来的

把一个基站拆成三块、用网络连起来，随之而来一堆新挑战——它们正是本主题后续章节存在的理由：

  • 前传成了瓶颈：DU↔RU 之间要传大带宽、超低时延的数据 → 催生 CPRI/eCPRI。
  • 时间同步要求极高：三块设备要"步调一致" → 需要 PTP/SyncE。
  • 多厂商如何互通：CU、DU、RU 可能来自不同厂商 → 需要 O-RAN 的开放接口。
  • 怎么统一管理：这么多网元要配置、监控 → 需要 NETCONF/YANG（O-RAN O1 接口）。
🎯 本篇要点回顾
  • 5G 把 gNB 拆成 CU（高层/非实时/可集中）、DU（中层/实时/调度）、RU（底层/最实时/射频）
  • 拆分依据 = "实时性 vs 集中度"的权衡；BBU 拆成 CU+DU，RRH/AAU 演进为 RU
  • 3GPP 主流拆分点：CU–DU 用 Option 2（F1/中传），DU–RU 用 Option 7-2x（Open FH/前传）
  • 连接段：Core↔CU 回传、CU↔DU 中传、DU↔RU 前传、RU↔UE 空口
  • 拆分带来前传瓶颈、同步、互通、管理四大新问题 → 后续章节逐一解决
