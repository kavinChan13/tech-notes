QoS、网络切片与边缘：端到端服务质量如何落地

上一篇里反复出现 5QI、QoS Flow、S-NSSAI 却没展开。本篇把它们串成一条完整的链：一个视频包从 App 出发，如何被打上标签、映射成空口的一条承载、在传输网上获得优先级，以及"网络切片"到底是营销词还是真有实现。

Module 03 阅读 ~15 min 5QI → DRB
01

端到端 QoS 链路总览

一个包要被"贴标签"四次

先说清一件容易混的事：网络机制篇讲的 QoS 是传输网视角——DSCP、VLAN PCP、队列调度、WFQ/PQ。那套机制在 3GPP 世界里依然存在，但只是链条中的一段。3GPP 有自己独立的一套 QoS 模型（5QI / QoS Flow / DRB），它比 DSCP 描述得更精细，因为它要管的不只是"优先级"，还包括空口的资源保障。

🎫 类比：把 QoS 想成机场的舱位体系。5QI 是票面的舱位等级（头等/商务/经济），它规定了你享受的服务标准；QoS Flow 是"同一舱位的一群乘客"，核心网按 QFI 把他们归到一起；DRB 是登机口到座位的那条实际通道，基站决定给这群人开几条通道、通道多宽；DSCP 则是行李在地面运输时贴的优先级标签——同一个人的行李和人走的是两套系统，但优先级要对得上，否则人到了行李没到。
QoS Flow：5GC 里 QoS 的最细粒度。一条 PDU 会话内部可以有多条 QoS Flow，每条用 QFI（QoS Flow Identifier，6 bit，写在 GTP-U 扩展头里）标识。同一条 PDU 会话内所有 QoS Flow 共享 IP 地址和 UPF 锚点，但可以有完全不同的时延/丢包保障。这是对 4G "EPS Bearer" 的关键改进：4G 里换 QoS 就要建新承载（重量级流程），5G 里只需在同一会话里加一条 Flow。
DRB（Data Radio Bearer）：空口上的承载。gNB 可以把多条 QoS Flow 复用到一条 DRB 上（N:1，省空口开销），也可以给关键流单独一条 DRB（1:1，保障最好）。这个映射决策权在 gNB，不在核心网——核心网只给出 QoS 参数，怎么用是接入网的自由。这也是为什么同一份 QoS 配置在不同厂商基站上表现不同。
02

5QI 表怎么读

三类保障、四个参数

5QI（5G QoS Identifier）：一个整数，指向一组标准化的 QoS 特征。标准 5QI（1–85 中的若干值）的特征由 3GPP TS 23.501 表 5.7.4-1 固定，网络与终端都内置这张表，所以信令里只传一个数字就够。非标准 5QI 需要显式传全部参数。

每个 5QI 定义五个东西：

参数含义为什么重要
Resource TypeGBR / Non-GBR / Delay-critical GBR决定 gNB 是否要预留空口资源，还是尽力而为
Priority Level调度优先级（数字越小越优先）拥塞时谁先被服务；也决定谁先被丢
PDB Packet Delay Budget从 UE 到 UPF 锚点的单向时延预算它是端到端预算，必须在各段之间分摊
PER Packet Error Rate可接受的丢包率上限（如 10⁻⁶）决定空口用几次 HARQ 重传、用什么 MCS
MDBVMaximum Data Burst Volume（仅 delay-critical GBR）在 PDB 内必须能一次吞下的突发量，工业控制场景关键

2.1 三种资源类型的本质差别

GBRNon-GBRDelay-critical GBR
空口资源按 GFBR 预留不预留，共享剩余预留 + 满足 MDBV 的突发能力
准入控制有：资源不足则拒绝建立无，永远能建有，且更严
超出速率超过 MFBR 被整形/丢弃拥塞时按优先级降速超出即视为违约

面试常问"GBR 好还是 Non-GBR 好"——这是个陷阱题。答案是"取决于业务对确定性的需求"：视频通话丢一帧无所谓但延迟不能大（GBR，PER 宽松 10⁻²）；文件下载慢一点无所谓但不能丢（Non-GBR + TCP 重传）。把所有业务都设成 GBR 是灾难——准入控制会让小区在低负载时就拒绝新用户，容量断崖式下降。真实网络里 90%+ 流量跑在 Non-GBR 的 5QI 9 上。
GFBR / MFBR / AMBR 三层速率：GFBR（Guaranteed Flow Bit Rate）是这条 QoS Flow 保证的最低速率，网络必须预留；MFBR（Maximum Flow Bit Rate）是这条流的上限，超出被整形；AMBR（Aggregate Maximum Bit Rate）作用在更大的范围——Session-AMBR 限制一条 PDU 会话内所有 Non-GBR 流的总和（由 SMF 交给 UPF 执行），UE-AMBR 限制该 UE 所有 Non-GBR 流的总和（由 gNB 执行）。注意：AMBR 只管 Non-GBR，GBR 流不计入。
03

URLLC 的 1 ms 谁分摊

一个被误读最多的数字

宣传里的"5G 时延 1 ms"几乎总是被误读。这个 1 ms 指的是空口用户面单向时延（UE 到 gNB），不是端到端，更不是"从手机 ping 到服务器"。而 5QI 里的 PDB 定义的是 UE 到 UPF 锚点的单向时延，比空口那段大得多。真正的端到端预算要这样分：

0.1–1 ms空口
（mini-slot、免调度授权、短 TTI）
~0.1 ms前传 RU↔DU
（20 km 光纤 ≈ 100 µs）
0.1–0.5 msDU/CU 处理
（协议栈 + 排队）
1–10 ms回传到 UPF
（距离决定，最大变量）
0.05–0.5 msUPF 转发
（软件转发 vs 硬件卸载）
? msUPF 到应用服务器
（不在 3GPP 管辖内）

看这张表就明白两件事：

  • 回传距离是最大的变量。UPF 放在省会机房，UE 在地级市，往返光纤 300 km 就是 3 ms 单向——光速物理下限，任何优化都动不了。这就是为什么低时延业务必须把 UPF 下沉（下一节）。
  • "1 ms" 只在空口成立，且有代价。要达到 0.5 ms 级空口时延，需要 mini-slot（2/4/7 符号而不是整个 slot）、免调度上行授权（不等调度请求）、更保守的 MCS（保证一次成功而不靠重传）。这些手段都是用频谱效率换时延——同一小区能服务的用户数大幅下降。
常见误区：把 PDB 当成"保证不超过的硬上限"。PDB 是统计意义上的目标，配合 PER 一起看才有意义——"99.9999% 的包在 PDB 内到达"。真正的硬实时（每个包都必须在期限内）5G 空口做不到，那是 实时系统与 TSN 的领域——后者能给出可证明的最坏时延上界，而 5G 只能给统计保证；两者怎么拼成端到端确定性见 DetNet 与跨域确定性。工业场景常见做法是 5G 提供"高概率低时延"，应用层再叠一层容错。

说到"哪一段分摊多少"，绕不开 O-RAN 的 Near-RT RIC：它以 10 ms–1 s 的周期做无线资源优化（切换策略、干扰协调、切片资源再分配），它不在单个包的转发路径上。而 UPF 下沉改变的是转发路径本身。两者分工清晰：RIC 优化"怎么调度"，UPF 位置决定"路有多长"。混淆这两点会导致方案选错——想降低传输时延却去调 RIC 策略，是白费功夫。

04

网络切片

从标识到真实的资源隔离

S-NSSAI（Single Network Slice Selection Assistance Information）：切片的标识，由 SST（Slice/Service Type，8 bit，标准值 1=eMBB、2=URLLC、3=MIoT、4=V2X）+ 可选的 SD（Slice Differentiator，24 bit，运营商自定义，用来区分同类型的不同客户）组成。UE 可以同时激活多个 S-NSSAI（最多 8 个），构成 Allowed NSSAI。

切片的信令流程不复杂：UE 在注册时带上 Requested NSSAI，AMF 拿签约数据比对，必要时问 NSSF 要 Allowed NSSAI 与对应的 AMF/切片实例，然后 UE 建立 PDU 会话时指定用哪个 S-NSSAI，SMF 与 UPF 按切片选择。难的不是选择，是隔离——同一套物理设备上，怎么让切片 A 的拥塞不影响切片 B。

层次隔离手段隔离强度代价
RAN 空口PRB 硬预留：给切片划定专属 PRB 区间强：其他切片再忙也不能碰预留但没用满就是纯浪费，容量利用率低
RAN 空口调度权重：按比例分配调度机会中：拥塞时按比例，空闲时可借用无法保证最坏情况，突发时仍会互相影响
RAN 处理独立 O-DU 实例 / 独立 CPU 核强硬件成本翻倍，运维实例数翻倍
传输网独立 VLAN + 队列 / VPN中配置量大，跨域协同难
传输网FlexE 物理时隙划分强：链路层硬切需要专用硬件，粒度粗（5 Gbps 步进）
核心网独立 SMF/UPF 实例强实例数与运维成本线性增长
核心网共享 AMF，仅逻辑隔离弱成本低，但信令风暴会串扰
取舍的本质是"预留 vs 超卖"，和云计算里一模一样。全硬预留 = 强隔离 + 低利用率 + 高成本；全共享 = 高利用率 + 无保障。真实网络几乎都在中间：关键切片（如公安、电网）用硬隔离，普通 eMBB 切片共享资源池并允许超卖，再用准入控制和监控兜底。这里没有"正确答案"，只有"这个客户愿意为确定性付多少钱"。
切片不是 VPN
常见误解是"切片就是给客户开个 VPN"。VPN 只做地址与路由隔离（我看不见你的流量），切片额外承诺性能隔离（你的拥塞不影响我的时延）。性能隔离要在空口、传输、核心网三层都落地才成立，而空口那层是最难也最容易被跳过的——如果只做了核心网的 UPF 隔离，卖出去的"URLLC 切片"在小区拥塞时照样抖动。
05

UPF 选择与边缘计算

把路缩短，而不是把车开快

上一节的时延预算表已经给出结论：回传距离是最大的可控变量。UPF 下沉就是把这个变量压小——UPF 不再放在省级核心机房，而是放在地市甚至基站机房，让流量就近出口到本地的应用服务器。

ULCL（Uplink Classifier）：一种 UPF 的角色。它坐在上行路径上检查目的地址，把匹配本地业务的流量分流到边缘的本地 UPF（进而到本地应用），其余流量继续送往中心的锚点 UPF 出 Internet。这样一条 PDU 会话可以有两个出口，UE 完全无感知——它的 IP 没变、会话没重建。另一种做法是 Branching Point + IPv6 多归属（一条会话多个 IPv6 前缀）。

下沉不是免费的，代价清单：

  • 运维实例数爆炸。一个省从 2 个 UPF 变成 50 个边缘 UPF，升级、监控、故障处理的工作量按实例数增长。这是电信云原生要解决的核心问题之一。
  • 会话连续性变复杂。UE 移动出边缘 UPF 的覆盖范围时，要按 SSC Mode 处理：Mode 1 锚点不变（简单但绕远路）、Mode 2 断开重建（IP 变，应用要能容忍）、Mode 3 先建新后断旧（平滑但要双通路并存一段时间）。选哪个是应用特性决定的。
  • 边缘机房条件差。空间、供电、散热都受限，没法放大机柜；这直接推动了 O-Cloud 这种"用通用服务器 + 容器承载网络功能"的路线。
  • 安全边界外移。边缘机房物理安全弱于核心机房，UPF 又是持有用户流量的节点，需要更强的加密与准入控制。
06

策略与计费

PCF 决策、SMF 转译、UPF 执行

三级分工是这样的：

PCF 决策基于签约、时段、位置、已用量、第三方请求（经 NEF），产出 PCC 规则：这个业务流用哪个 5QI、限速多少、怎么计费
SMF 转译把 PCC 规则翻译成 N4 规则（PDR 匹配条件 + QER 限速 + URR 上报触发），同时把 QoS 参数经 AMF/N2 送给 gNB
UPF 执行逐包匹配 PDR、按 QER 限速与标记、按 URR 累计用量并在阈值触发上报
gNB 执行把 QoS Flow 映射到 DRB、按 Priority 与 GFBR 做空口调度与准入
会话级控制流级控制
作用对象整条 PDU 会话会话内某条 QoS Flow / SDF
典型参数Session-AMBR、默认 5QI、DNN 级策略GFBR/MFBR、per-flow 5QI、免流标记
执行者UPF（总量限速）UPF（逐流限速 + 标记）+ gNB（空口保障）
变更成本低：改 AMBR 只需更新 N4高：新增 GBR 流可能触发空口准入、失败要回滚
典型用途套餐总带宽封顶视频通话保障、定向流量包、超量降速
在线计费 vs 离线计费：离线计费（CHF 收 CDR）只是事后统计，不影响转发；在线计费要预授权额度——UPF 拿到"你可以用 100 MB"的配额，用完必须先向 CHF 续额度，续不到就限速或断流。这意味着在线计费在数据面热路径上引入了一次控制面交互，配额设小了信令翻倍、设大了超量风险，是很现实的一个调优点。

7.1 切片数量爆炸的运维成本

标准允许 SST + SD 组合出上百万个切片，但真实网络里运营商通常只运营个位数到几十个切片。原因很朴素：每个切片都是一套需要独立配置、监控、SLA 核算、故障定位、容量规划的对象。切片数量翻倍，运维对象数量在 RAN、传输、核心网三个域都翻倍，而排障时的组合空间是乘法关系。

所以切片的真正约束不是技术上能不能切，而是：

  • 能不能自动化：切片从订单到开通必须是编排流程（SMO/NSMF 自动下发），手工配置的切片数上限大概是几个。
  • 能不能度量：SLA 要能按切片出报表，需要 RAN/传输/核心网都按切片打点，这是可观测性的硬要求。
  • 责任边界清不清：客户投诉时延超标，是空口拥塞、传输丢包还是应用自己慢？没有分段测量数据，这个争论永远无解。
端到端 SLA 的责任边界是切片商业化最现实的障碍。一条"20 ms 端到端时延"的承诺，横跨 UE 实现、空口、前传、传输网（可能是第三方）、核心网、边缘机房、客户自己的应用。合理的做法是分段承诺 + 分段测量：运营商只承诺"UE 到 N6 出口"这一段，并提供分段时延数据作为证据；应用侧的时延由客户负责。做不到分段测量，就没法签 SLA。
🎯 本篇要点回顾
  • QoS 链条：SDF → QoS Flow (QFI) → DRB → PRB 调度，外加传输网的 DSCP/PCP 一套并行标签，两套必须对齐
  • 谁决定 ≠ 谁执行：PCF 决策、SMF 转译、UPF 打标限速、gNB 做空口保障与 QFI→DRB 映射
  • 5QI 定义 Resource Type / Priority / PDB / PER / MDBV；GBR 有准入控制，滥用 GBR 会让容量断崖下降
  • "1 ms" 只描述空口；端到端预算里回传距离是最大变量，所以低时延要靠 UPF 下沉而非调 RIC
  • 切片 = 标识（S-NSSAI）+ 选择（NSSF）+ 隔离（RAN 预留/权重、FlexE/VLAN、独立 UPF），难点在空口隔离
  • ULCL 本地分流让一条会话有两个出口，UE 无感；代价是实例数、会话连续性（SSC Mode）与边缘安全
  • 切片数量的真实上限来自运维与可观测性，不是标准
