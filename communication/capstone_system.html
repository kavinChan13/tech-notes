一个完整通信系统案例：从管理到数据传输

这是整个主题的总复习。我们用一个 5G O-RAN 基站的开站与运行过程，把前面所有知识——NETCONF/YANG、O-RAN、Fronthaul、eCPRI、PTP/SyncE、TLS、协议栈——串成一条完整的因果链，回答"一个现代通信系统到底是怎么组成、怎么跑起来的"。

Module 10 阅读 ~26 min 总复习
01

全景系统图

一张图看懂整条链

四条线索：管理面(SMO→网元, NETCONF)、控制面(调度信令)、用户面(IQ/用户数据, eCPRI)、同步面(PTP/SyncE)。它们分工协作，缺一不可。
02

管理面：开站配置

一切从配置开始

新基站上电，第一件事不是发数据，而是被配置：

  1. SMO 通过 O1 接口连接 O-DU/O-RU，走 NETCONF over TLS，用 mTLS + 证书双向认证。
  2. 下发的配置遵循 YANG 模型定义的结构，用 edit-config 写入 candidate，校验后 commit 生效。
  3. 配置内容：小区参数、频点、功率、前传端口、同步方式等。
这解释了那个常见困惑——"NETCONF/YANG 为什么出现在 O-RAN 里？"：因为 O-RAN 需要标准化、多厂商的管理面，NETCONF/YANG 正是 O1 的承载。
03

同步面：先对表

数据传输的前提

配置好后，O-DU 和 O-RU 必须先同步时钟才能协同收发（见 PTP/SyncE）：

  • SyncE沿以太网物理层锁定频率。
  • PTP(1588)交换时间戳报文，对齐相位/时间到 ns 级，溯源 GNSS。
  • 没对齐前，TDD 上下行会互相干扰，数据面无法正常工作。
04

数据面：IQ 传输

真正的无线数据流

时钟对齐后，O-DU 与 O-RU 通过 Open Fronthaul 上的 eCPRI 传输数据：

  • U 平面：频域 IQ 采样封进 eCPRI 消息，over Ethernet 传输，带宽数十 Gbps。
  • C 平面：调度/波束控制信息，必须早于对应 U 平面数据到达。
  • O-RU 把频域 IQ 做 IFFT/射频处理，从天线发射为无线信号到 UE。
关键澄清：Open Fronthaul 是 O-RAN 定义的接口/规范；eCPRI/以太网是它上面用的承载协议。O-RAN ⊃ Open Fronthaul ⊃ eCPRI/Ethernet。
05

一次完整的通话

端到端串起来

  1. UE 通过空口(Uu)接入 O-RU。
  2. O-RU 将无线信号转成频域 IQ，经 eCPRI/Open Fronthaul 上传 O-DU。
  3. O-DU 做物理层/MAC 处理，经 F1(中传) 与 O-CU 交互高层协议。
  4. O-CU 经 Backhaul 连核心网，接入互联网/语音网。
  5. 全程 SMO 通过 O1 监控状态/告警/性能；RIC 通过 E2/A1 做智能优化。
前中后传各司其职：Fronthaul(DU↔RU, 最苛刻) / Midhaul(CU↔DU, F1) / Backhaul(RAN↔Core)。
06

两个报文的一生

回答用户最初的疑问

一个 eCPRI 数据包

频域 IQ → eCPRI 消息头(Type/PC_ID/SEQ) → 直接封进 以太网帧(EtherType 0xAEFE) → 物理层发出。不走 TCP，追求最低延迟，可选 over UDP。受 PTP 严格同步。

一个 NETCONF 请求

XML RPC(edit-config) → SSH/TLS 加密 → TCP 可靠传输 → IP 寻址 → 以太网。追求可靠与安全，不在乎多几毫秒。

同一个基站里，两类报文走完全不同的协议栈——这正是"协议要分层、平面要分离"的最好例证：数据面求快(eCPRI 直上以太网)，管理面求稳求安全(NETCONF→TLS→TCP→IP)。
07

知识地图总览

你现在能回答这些问题了

  • ✅ 现代 4G/5G 系统的组成：UE → RAN(CU/DU/RU) → 核心网。
  • ✅ CU/DU/RU 分工与 3GPP 拆分(Option 2 / 7-2x)。
  • ✅ Fronthaul/Midhaul/Backhaul 的区别与前传为何最苛刻。
  • ✅ OBSAI→CPRI→eCPRI 演进的动因(带宽/以太网化)。
  • ✅ O-RAN 是架构/标准体系，不是单一协议。
  • ✅ Open Fronthaul 与 eCPRI 的包含关系。
  • ✅ NETCONF/YANG 为何出现在 O-RAN(O1 管理面)。
  • ✅ eCPRI 包与 NETCONF 请求走不同协议栈。
  • ✅ C/C++ 通信工程师要掌握的 Socket/协议/性能/HA 知识。
把链路继续往右延伸：本案例走到 UE 就停了，但用户的数据包并没有走完。UE 发出的 IP 包经空口到 O-RU/O-DU/O-CU 后，还要沿 N3（GTP-U 隧道）送到 UPF，由 UPF 按 SMF 通过 N4/PFCP 下发的规则解封装、限速、计费，最后从 N6 出到 Internet；而这条隧道能存在的前提，是 UE 先在 AMF 完成注册、再由 SMF 建立 PDU 会话。完整链条见 Module 03 核心网演进：从 EPC 到 5GC，其中的 QoS 映射（5QI → QoS Flow → DRB）见 QoS、网络切片与边缘。
