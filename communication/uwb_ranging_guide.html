UWB 测距与授时

UWB 最常被误解成「另一种 Wi-Fi」——它的带宽只有几百 kbps 到几 Mbps，根本不是用来传数据的。它的价值在两件别人做不好的事：厘米级测距和纳秒级授时。理解这一点的关键是它的物理层设计——用 500 MHz 以上的超宽带宽换取极高的时间分辨率，代价是数据速率。这篇讲清测距原理、误差从哪来、以及在机器人协同里它该扮演什么角色。

01

UWB 到底是什么

先纠正最常见的误解

UWB（Ultra-Wideband，超宽带）的定义是：占用带宽 ≥ 500 MHz（或 ≥ 中心频率的 20%）的无线技术。工作在 6–8.5 GHz（也有 3.1–4.8 GHz 的低频段）。关键在于它用极低的功率谱密度（法规限制 −41.3 dBm/MHz）把能量摊在极宽的频带上——所以在别的系统看来，UWB 只是把底噪抬高了一点点，几乎不产生干扰，也因此可以和 Wi-Fi、5G 共存于同一空间。
Wi-Fi 像一个人在窄频段里大声喊——声音集中、传得远、但会盖过同频段的其他人。UWB 像把同样的信息用极轻的耳语铺满整个频率范围：每个频点上都轻得几乎听不见（不干扰别人），但把所有频点合起来，接收方仍能还原出信息。而且因为「铺得极宽」，它能极其精确地判断这声耳语是什么时刻发出的——这正是测距精度的来源。

1.1 为什么带宽宽 = 测距准

这是理解 UWB 的核心，也是最常被问到的原理题。时间分辨率与带宽成反比：

── 时间分辨率的物理关系 ─────────────────────────
时间分辨率 Δt ≈ 1 / 带宽 B
距离分辨率 Δd = c × Δt ≈ c / B      （c = 3×10⁸ m/s）

代入不同技术：
Wi-Fi 20 MHz   → Δt = 50 ns   → Δd = 15 m
Wi-Fi 80 MHz   → Δt = 12.5 ns → Δd = 3.75 m
5G   100 MHz   → Δt = 10 ns   → Δd = 3 m
UWB  500 MHz   → Δt = 2 ns    → Δd = 0.6 m
UWB  1 GHz     → Δt = 1 ns    → Δd = 0.3 m

★ 上面是「分辨两个独立回波」的能力。
  实际测距精度可以远好于分辨率（靠对首径的精细估计），
  典型 ±10 cm，视距条件下可到 ±3 cm。
「窄带做不出厘米级定位」是个物理限制，不是工程水平问题。基于 RSSI（信号强度）的定位（蓝牙、Wi-Fi 常用）精度通常是米级，因为信号强度受遮挡、天线方向、多径影响极大，且和距离的关系不稳定。基于时间的测距只依赖光速这个常数，所以只要能把时间测准就能把距离测准。UWB 的全部优势都来自「能把时间测得极准」这一点。面试里能从「带宽 → 时间分辨率 → 距离分辨率」推一遍，比背「UWB 精度 10 厘米」有价值得多。

1.2 能力边界

能力UWB 的表现说明
测距精度±3 ~ ±10 cm（视距）核心优势；NLOS 下劣化到几十厘米甚至米级
时间同步ns 级被严重低估的能力，见 §6
数据速率110 kbps ~ 6.8 Mbps（典型 850 kbps）不用来传业务数据
作用距离10 ~ 50 m（视距，取决于功率与天线）受功率谱密度法规硬性限制
穿透能力弱金属完全阻挡；混凝土衰减大
功耗单次测距 mJ 级比 GNSS 低，比 BLE 高；测距频率直接决定功耗
抗干扰强超宽带 + 极低功率谱密度，与窄带系统天然共存
把 UWB 当数据链路用是选型的经典错误。850 kbps 的速率连一路压缩视频都跑不动，更别说点云。正确的架构是「UWB 管定位和授时，Wi-Fi/5G 管数据」——两者并存而非替代。这个组合在机器人协同里特别有价值：UWB 提供的精确时间让「时间戳执行」范式能在无线场景落地，而数据仍走高速链路。
02

802.15.4z 物理层

脉冲、前导码与安全测距

2.1 脉冲无线电与 HRP

UWB 不用传统的连续载波调制，而是发射极短的脉冲（纳秒级宽度）。IEEE 802.15.4 定义了两种物理层，机器人和消费电子实际用的都是 HRP（High Rate Pulse repetition frequency）：

参数典型值影响
信道带宽499.2 MHz（部分信道 900 MHz+）直接决定时间分辨率
常用信道CH5（6489.6 MHz）、CH9（7987.2 MHz）CH9 各地区法规更普遍开放
PRF（脉冲重复频率）16 MHz / 64 MHz64 MHz 抗噪更好但功耗高
前导码长度64 / 128 / 1024 / 4096 符号越长测距越准、抗噪越强，但耗时耗电越多
数据速率110 kbps / 850 kbps / 6.8 Mbps测距报文很短，速率不是瓶颈
前导码长度是精度与开销之间最直接的旋钮。测距的本质是估计信号首径的到达时刻，前导码越长，接收端能做的相关积累越多，时刻估计越准、越抗噪。代价是每次测距占用的空口时间和能量都线性增加。工程上：静态高精度场景用长前导码（1024+），高频率测距的移动场景用短前导码（64/128）换更新率。这是「精度 vs 更新率 vs 功耗」三者的取舍点。

2.2 STS：802.15.4z 的核心增量

STS（Scrambled Timestamp Sequence，加扰时间戳序列）是 802.15.4z 相对 4a 最重要的新增。老版本的前导码是公开且固定的，攻击者可以提前重放一个伪造的前导码，让接收端算出「更近」的距离——这就是 中继/距离缩短攻击（relay / distance reduction attack），对「靠近自动解锁」这类应用是致命的。STS 用密钥派生的伪随机序列替代固定前导码，攻击者无法预测下一个序列，也就无法提前伪造。
STS 对机器人场景同样重要，但理由不同。消费电子关心的是防盗（车钥匙、门禁），机器人关心的是安全功能不能被欺骗——如果「人员接近时减速」这个安全逻辑依赖 UWB 测距，那么一个能伪造距离的攻击者就能让机器人在有人靠近时不减速。凡是把 UWB 测距结果接入安全链路的设计，都必须启用 STS，并且要走 802.15.4z 的安全测距模式而不是裸的 4a 模式。

测距方法：TWR / TDoA / AoA

三种原理，三种工程取舍

3.1 SS-TWR：单边双向测距

最直观的方法：A 发一个包，B 收到后回一个包，A 用往返时间减去 B 的处理时间，除以 2 就是单程时间。

── SS-TWR（Single-Sided Two-Way Ranging）─────────
A                                    B
│── Poll ──────────────────────────▶│  T_reply（B 的处理时间，B 自己测并告知 A）
│  t1（A 记录发送时刻）               │
│                                    │
│◀───────────────────── Response ───│
│  t4（A 记录接收时刻）               │

飞行时间 ToF = ( (t4 - t1) - T_reply ) / 2
距离 d = ToF × c

★ 致命问题：时钟频率偏差
A 和 B 的晶振各有偏差（典型 ±20 ppm）。
T_reply 由 B 用自己的时钟测量，A 用自己的时钟测 (t4-t1)。
两把尺子不一样长 → 相减产生误差。

误差 ≈ T_reply × (e_A - e_B)
若 T_reply = 500 µs，频差 40 ppm：
  误差 = 500 µs × 40e-6 = 20 ns → 距离误差 6 米！
SS-TWR 的问题像两个人用各自的秒表计时接力：你按下秒表跑出去，对方接到后按他的秒表计时休息了「5 秒」，再跑回来。但如果他的秒表偏快 1%，他说的「5 秒」实际只有 4.95 秒——你减去的 5 秒是错的，误差直接进入结果。而且他休息越久，误差越大。

3.2 DS-TWR：双边双向测距（工程首选）

DS-TWR 通过多一轮交互，让两边的时钟误差在数学上相互抵消：

生产系统一律用 DS-TWR，不要用 SS-TWR。SS-TWR 只在「回复时间极短且两端晶振都很好」时才勉强可用，而这两个条件在真实系统里很难保证（协议栈处理、中断延迟都会拉长回复时间）。DS-TWR 多一次报文换来一到两个数量级的精度提升，这笔交易在任何场景下都划算。如果某个方案宣称用 SS-TWR 达到厘米级精度，要追问它怎么处理时钟频差——常见答案是「先做频偏估计再补偿（CFO 补偿）」，那也是可行的，但复杂度并不比 DS-TWR 低。

3.3 TDoA 与 AoA

方法原理优点代价
TWR
（双向测距）		标签与每个基站各做一次双向交互，得到距离后三边定位不需要基站间同步；标签少时简单可靠容量差——每个标签都要占用空口做多次交互，标签数上去后更新率骤降
TDoA
（到达时间差）		标签只广播一次，多个基站记录各自的接收时刻，用时刻差反算位置（双曲线定位）容量极好——标签只发不收，可支持成百上千个；标签功耗低基站之间必须精确同步（ns 级），要么有线授时要么用参考标签校准
AoA
（到达角）		基站用多天线阵列测量信号相位差，算出来波方向单基站即可给出方向，配合测距可单站定位需要多天线与精确校准；多径环境下角度估计误差大
选型的分水岭是「标签数量」。少量标签（几个到几十个）且要求高更新率 → TWR，实现简单、不需要基站同步。大量标签（上百个）或标签要省电 → TDoA，但你必须先解决基站间的纳秒级同步问题——通常靠有线把基站串起来做时钟分发，这反过来又限制了部署灵活性。AoA 通常不单独用，而是和 TWR 组合（一次测距 + 一次测角 = 单基站定位），适合基站不便密集部署的场景。

天线延迟校准是量产环节最容易漏掉、后果又最严重的一步。信号从芯片输出到天线辐射出去、以及接收侧的反向路径，都有固定延迟（几十到几百纳秒），这个延迟直接以 30 cm/ns 的比例转成距离偏差。而且它每颗模组都不一样——PCB 批次、天线焊接、外壳材质都会影响。用芯片默认值的后果是所有测距结果系统性偏移几十厘米，且各设备偏移量还不同。正确做法是产线上逐台在已知距离下标定并把校准值烧进模组，这一步的成本必须在项目早期就规划进去。
多次测距应该取中位数而不是均值。因为 NLOS 误差是单向正偏的——遮挡只会让信号走更长的路，测得更远，绝不会更近。少数几次被遮挡的测量会把均值显著拉大，而中位数对这类单侧离群值天然鲁棒。更进一步的做法是取「最小的几次的平均」——因为最短的那些测量最接近真实的直线距离。这个技巧在实践中能把 NLOS 环境的精度改善一个档次。
05

多径与 NLOS

UWB 精度的真正天花板

在开阔视距下 UWB 能稳定做到几厘米；一旦进入真实环境（金属货架、机器人本体遮挡、人员走动），精度就取决于系统怎么处理多径和非视距。这才是不同 UWB 方案拉开差距的地方。

多径像在空旷大厅里喊话有回音：你的声音直接传到对方那里（直射径），同时也从墙壁、天花板反弹后陆续到达（反射径）。对方听到的是一串重叠的声音。要测「我们之间多远」，必须识别出最先到达的那一下（首径）——因为直线永远最短。如果直射被挡住了（NLOS），最先到达的就变成某条反射路径，算出来的距离必然偏大，而且你可能意识不到自己在测一条弯路。

5.1 首径检测

首径检测（First Path Detection）是 UWB 测距算法的核心。接收端得到的是一个信道冲激响应（CIR）——一串随时间分布的能量峰。最强的峰未必是首径（反射路径叠加后可能更强），所以不能简单取最大值，要在噪声门限之上找最早超过阈值的那个峰。UWB 的超宽带宽让这些峰在时间上分得开（分辨率 < 1 ns），这正是它能做到厘米级的原因；窄带系统的各条路径混成一坨，根本分不开。

5.2 NLOS 的识别与处理

手段做法效果
CIR 特征判别看首径能量与总能量之比、首径与最强径的时间差、CIR 上升沿陡峭程度能给出「这次测量可能是 NLOS」的置信度，据此加权或丢弃
冗余基站部署超过定位所需最少数量的基站（3 个可定 2D，实际部署 5–6 个）最有效——用一致性检验剔除偏离的那几个测距值（类似 RANSAC）
时序滤波卡尔曼滤波，用运动模型约束跳变抑制孤立的野值；但持续 NLOS 时滤波器会被带偏
多传感器融合与 IMU、轮式里程计、激光雷达融合工程上的标准答案——UWB 提供全局绝对位置消除累积漂移，IMU/里程计提供高频相对运动
UWB 和 IMU 的互补性是教科书级的。IMU 更新率极高（kHz）、短期精度好，但积分误差累积，几十秒就漂到不能用；UWB 更新率低（几 Hz 到几十 Hz）、单次有噪声，但没有累积漂移（每次都是绝对测量）。两者融合后：IMU 填补 UWB 测量之间的空隙并提供高频姿态，UWB 周期性把 IMU 的累积漂移拉回来。这个组合的效果远好于任何一方单独使用，也是移动机器人室内定位的主流方案。
金属环境是 UWB 的硬伤，要在选型阶段就评估。金属货架、金属机架、机器人自身的金属外壳都会完全阻断直射径（不是衰减，是阻断），此时只能靠反射路径，误差从厘米级劣化到米级。部署前必须做现场实测而不是照搬别处的精度数据。缓解手段：把基站装高（避开货架遮挡）、增加基站冗余度、以及在机器人上多点布置 UWB 天线（总有一个能看到基站）。如果实测发现大面积 NLOS，应该及早考虑换方案（激光 SLAM、视觉标记），而不是硬调 UWB。
06

UWB 授时：被低估的用法

它不只是定位技术

UWB 能把时刻测到纳秒级，这个能力反过来用就是授时：如果两个节点之间的距离已知（或可测），那么单向传播延迟也就已知，接收端就能把自己的时钟对齐到发送端。

为什么这件事对机器人协同至关重要：确定性保障体系 §4 讲过，端间协同的核心不是「指令传得多快」，而是「两台机器人对『现在几点』的理解是否一致」——因为协同精度 ≈ 时间同步精度 × 运动速度。两台 AGV 以 2 m/s 协同，时钟差 10 ms 就意味着位置错开 2 cm。而无线环境里，gPTP 那套（需要对称、稳定的链路延迟）很难用；UWB 恰好能同时给出「距离」和「精确时刻」，把这个问题一次解决。
这就像一群人靠互相击掌对表：击掌的瞬间双方都能感知到（传播几乎无延迟且延迟可测），于是可以用它作为共同的时间参考。而用普通网络对表就像靠喊话对表——你不知道声音传过来花了多久，也不知道每次是不是一样久。

6.1 精度量级对比

GNSS（GPS/北斗）ns 级室外室内完全不可用
NTPms 级普通 IT 网络对协同动作远远不够
「室内的 GNSS」是理解 UWB 授时价值的最好类比。室外机器人可以靠 GNSS 同时拿到位置和精确时间，室内则两样都拿不到——而 UWB 恰好在室内提供同样的两样东西。所以典型架构是：室外 GNSS + 室内 UWB，两者在建筑物出入口处平滑交接，上层应用拿到统一的「位置 + 时间」接口。这个设计让「时间戳执行」范式在全场景可用——不发「现在动」，而发「在绝对时刻 T 动」，从而把网络抖动问题转化成时间同步问题。
07

机器人场景的落地

该用在哪、不该用在哪

✅ 相对定位与编队保持

多台机器人互相测距，维持队形。UWB 的优势是不依赖外部基础设施——机器人之间直接互测即可，不需要事先部署基站。厘米级精度足以支撑协同搬运这类需要刚性约束的任务。

✅ 无线时间同步

见 §6。给「时间戳执行」范式提供时间基准，把协同精度问题从「网络抖动」转化为「时钟同步」——后者容易得多。

✅ 人员安全距离监测

工人佩戴 UWB 标签，机器人实时感知距离并分级减速/停止。相比视觉方案不受光照、遮挡、粉尘影响，相比激光雷达能区分身份（谁是授权人员）。必须启用 STS 防伪造（见 §2.2）。

✅ 全局位置校正（融合 IMU / 里程计）

UWB 提供无累积漂移的绝对位置，周期性校正 IMU 和轮式里程计的累积误差。这是移动机器人室内定位的主流组合。

✅ 自动对接与充电桩引导

最后一米的精确对位。UWB 测距 + AoA 测角可以给出方向与距离，引导机器人对准充电触点或料架。

❌ 传业务数据

850 kbps 的速率连一路压缩视频都跑不动。UWB 不是通信链路，数据必须走 Wi-Fi/5G。

❌ 大范围室外定位

作用距离几十米且需密集部署基站，室外应该用 GNSS/RTK。UWB 的定位是室内和局部区域的补充。

❌ 重金属遮挡环境下的高精度定位

金属完全阻断直射径，精度从厘米劣化到米级。选型前必须现场实测，实测不行就换激光 SLAM 或视觉标记。

7.1 部署要点

  • 基站布置要有几何多样性。三个基站共线时，垂直于该线方向的定位精度会极差（几何精度因子 GDOP 恶化）。基站应构成尽量大的多边形，且不共线不共面；2D 定位至少 3 个、实际部署 5–6 个以留冗余。
  • 装高、避开遮挡。基站装在货架顶部以上，让直射径尽量不被货物和机器人本体挡住。
  • 机器人上多点布天线。本体自身的金属结构会遮挡，单天线容易出现「转个身就丢」的情况；两到三个天线分布在不同朝向可显著提升可用率。
  • 逐台校准天线延迟并烧录。见 §4，这一步的成本要在项目早期规划。
  • 规划更新率与功耗。测距频率直接决定功耗与空口占用；移动快的场景需要更高更新率（10–50 Hz），静态盘点场景 1 Hz 就够。
  • 确认频段合规。UWB 的可用频段与功率各地区法规不同（6.0–8.5 GHz 的开放范围有差异），出货前需完成型式认证。

面试题集（12 道）

按难度分层，先自测再对照

9.1 基础（必答）

点击每道题展开参考答案（先自测，再对照）。

  1. 基础UWB 为什么能做到厘米级测距，而 Wi-Fi 不行？

    因为时间分辨率与带宽成反比：Δt ≈ 1/B，Δd = c × Δt ≈ c/B。

    技术带宽距离分辨率
    Wi-Fi 20 MHz20 MHz15 m
    Wi-Fi 80 MHz80 MHz3.75 m
    UWB≥ 500 MHz0.6 m（实际测距精度可达 ±3–10 cm）
    两个关键认知
    ① 基于时间的测距只依赖光速这个常数，所以时间测准了距离就准；而基于 RSSI（信号强度）的定位精度是米级，因为强度受遮挡、天线方向、多径影响极大。② 窄带做不出厘米级是物理限制，不是工程水平问题。
    补充：分辨率 ≠ 精度
    0.6 m 是「能分辨两个独立回波」的能力；实际测距精度靠对首径到达时刻的精细估计，可以远好于分辨率。
  2. 基础UWB 能不能用来传数据？它的定位是什么？

    不能。UWB 速率只有 110 kbps ~ 6.8 Mbps（典型 850 kbps），连一路压缩视频都跑不动，更别说点云。

    它的价值在两件别人做不好的事：

    • 厘米级测距（±3–10 cm 视距）
    • 纳秒级授时——这一项经常被忽略，但对机器人协同可能更值钱
    正确的架构
    「UWB 管定位和授时，Wi-Fi/5G 管数据」——两者并存而非替代。UWB 提供的精确时间让「时间戳执行」范式能在无线场景落地（不发「现在动」而发「在绝对时刻 T 动」），数据仍走高速链路。
    为什么不干扰别人
    UWB 用极低的功率谱密度（法规限 −41.3 dBm/MHz）把能量摊在 500 MHz 以上的频带上。在其他系统看来只是把底噪抬高一点点，所以能与 Wi-Fi、5G 共存于同一空间。
  3. 基础TWR、TDoA、AoA 各是什么？怎么选？
    方法原理优点代价
    TWR标签与每个基站各做一次双向交互，得距离后三边定位不需要基站间同步容量差——每标签多次交互，标签多时更新率骤降
    TDoA标签只广播一次，多基站记录各自接收时刻，用时刻差反算（双曲线定位）容量极好，标签只发不收、功耗低基站间必须 ns 级同步
    AoA基站用多天线阵列测相位差算来波方向单基站可给方向，配测距可单站定位需多天线与精确校准；多径下角度误差大
    选型分水岭是标签数量
    少量标签（几个到几十个）+ 高更新率 → TWR；大量标签（上百个）或要省电 → TDoA，但你得先解决基站间纳秒级同步（通常有线串起来分发时钟，这又限制了部署灵活性）。AoA 通常不单独用，而是和 TWR 组合成单基站定位。
  4. 基础什么是 STS？为什么机器人场景也需要它？

    STS（Scrambled Timestamp Sequence）是 802.15.4z 相对 4a 最重要的新增。

    要解决的问题：老版本的前导码公开且固定，攻击者可以提前重放伪造的前导码，让接收端算出「更近」的距离——即中继 / 距离缩短攻击。STS 用密钥派生的伪随机序列替代固定前导码，攻击者无法预测下一个序列。

    机器人场景的理由不同于消费电子
    消费电子关心防盗（车钥匙、门禁）；机器人关心的是安全功能不能被欺骗——如果「人员接近时减速」这个安全逻辑依赖 UWB 测距，能伪造距离的攻击者就能让机器人在有人靠近时不减速。
    规则
    凡是把 UWB 测距结果接入安全链路的设计，都必须启用 STS，并走 802.15.4z 的安全测距模式而非裸的 4a 模式。

9.2 中级（区分熟练度）

  1. 中级SS-TWR 有什么致命问题？DS-TWR 怎么解决的？

    SS-TWR 的问题是时钟频率偏差。A 发 Poll、B 回 Response，ToF = ((t4−t1) − T_reply)/2。但 T_reply 由 B 用自己的时钟测，(t4−t1) 由 A 用自己的时钟测——两把尺子不一样长。

    误差 ≈ T_reply × (e_A − e_B)
T_reply = 500 µs，频差 40 ppm（两端各 ±20 ppm）：
  误差 = 500 µs × 40e−6 = 20 ns → 距离误差 6 米

    而且回复时间越长误差越大——协议栈处理、中断延迟都会拉长它。

    DS-TWR 的解法
    用三次交互（Poll → Response → Final）构造对称的时间关系，把两端频差的一阶项在数学上抵消，残余误差降到 ps 级。代价是多一次报文，空口占用与功耗约增加 50%。
    结论
    生产系统一律用 DS-TWR。多一次报文换来一到两个数量级的精度提升，任何场景都划算。如果某方案宣称用 SS-TWR 达到厘米级，要追问它怎么处理频差——常见答案是 CFO 频偏估计补偿，可行但复杂度不比 DS-TWR 低。
  2. 中级UWB 的误差有哪几类？哪一类最容易在量产时被漏掉？
    误差源量级特性
    时间估计噪声±2–5 cm随机零均值，多次测量可平均消除
    时钟频差残余DS-TWR ±1 cm / SS-TWR 可达数米系统性，与回复时间成正比
    天线延迟未校准 ±30 cm 以上固定偏差，每颗模组不同
    多径 / NLOS软遮挡 +10–30 cm，金属 +1 m 以上单向正偏（只会更远不会更近）
    最容易漏掉的是天线延迟校准
    信号从芯片到天线辐射、以及接收侧反向路径都有固定延迟（几十到几百 ns），以 30 cm/ns 的比例直接转成距离偏差。而且每颗模组都不一样（PCB 批次、天线焊接、外壳材质都影响）。用默认值的后果是所有结果系统性偏移几十厘米且各设备偏移量还不同。必须在产线上逐台标定并烧录——这个成本要在项目早期规划。
    一个实用技巧
    多次测距取中位数而不是均值。因为 NLOS 误差是单向正偏的，少数被遮挡的测量会把均值显著拉大，而中位数对单侧离群值天然鲁棒。更进一步可取「最小的几次的平均」——最短的测量最接近真实直线距离。
  3. 中级什么是首径检测？NLOS 环境怎么处理？

    首径检测是 UWB 测距算法的核心。接收端得到的是信道冲激响应（CIR）——一串随时间分布的能量峰（直射径 + 各条反射径）。

    不能简单取最大峰——反射路径叠加后可能更强。要在噪声门限之上找最早超过阈值的那个峰，因为直线永远最短。UWB 的超宽带宽让这些峰在时间上分得开（< 1 ns），窄带系统则混成一坨根本分不开。

    NLOS 的四种处理手段：

    • CIR 特征判别——看首径能量占比、首径与最强径的时间差、上升沿陡峭度，给出 NLOS 置信度
    • 冗余基站（最有效）——部署超过最少所需数量，用一致性检验剔除偏离值（类似 RANSAC）
    • 时序滤波——卡尔曼滤波抑制孤立野值；但持续 NLOS 会把滤波器带偏
    • 多传感器融合（工程标准答案）——与 IMU、里程计融合
    UWB 与 IMU 的互补性
    IMU 更新率高（kHz）、短期精度好，但积分误差累积；UWB 更新率低、单次有噪声，但没有累积漂移（每次都是绝对测量）。融合后 IMU 填补空隙、UWB 周期性拉回漂移，效果远好于任一方单独使用。
  4. 中级为什么说 UWB 的授时能力可能比定位能力更值钱？

    因为端间协同的核心矛盾不是「指令传得多快」，而是「两台机器人对『现在几点』的理解是否一致」。

    协同精度 ≈ 时间同步精度 × 运动速度：两台 AGV 以 2 m/s 协同，时钟差 10 ms = 位置错开 2 cm；要控到 2 mm 就需要时钟差 < 1 ms。

    而无线环境里 gPTP 那套（需要对称、稳定的链路延迟）很难用。UWB 恰好能同时给出「距离」和「精确时刻」——距离已知则单向传播延迟已知，接收端就能把时钟对齐到 ns 级。

    「室内的 GNSS」
    室外机器人靠 GNSS 同时拿位置和精确时间，室内两样都拿不到——UWB 恰好在室内提供同样两样。典型架构：室外 GNSS + 室内 UWB，出入口平滑交接，上层拿到统一的「位置 + 时间」接口。
    为什么这很关键
    有了精确共同时间，就能用「时间戳执行」范式：不发「现在动」而发「在绝对时刻 T 动」。这样只要 T 在传输时延之外，网络抖动完全不影响动作精度——把「低时延+低抖动」的难题转化成「时钟同步准」这个容易得多的问题。

9.3 高级（体现深度）

  1. 高级给一个金属货架密集的仓库做 UWB 定位，你会怎么评估和设计？

    第一步是评估可行性，而不是直接设计。金属会完全阻断直射径（不是衰减，是阻断），此时只能靠反射路径，误差从厘米级劣化到米级。必须现场实测而不是照搬别处的精度数据——在最差的几个位置实测 NLOS 比例和误差分布。

    如果实测可行，设计要点：

    • 基站装高，装在货架顶部以上，让直射径尽量越过货物
    • 基站几何多样性——三基站共线时垂直方向精度极差（GDOP 恶化）；应构成尽量大的多边形，2D 至少 3 个、实际部署 5–6 个留冗余
    • 机器人上多点布天线——本体金属结构会遮挡，单天线容易「转个身就丢」
    • 用冗余做一致性检验剔除 NLOS 测距值（RANSAC 思路）
    • 与 IMU / 轮式里程计融合，UWB 只做低频的全局校正
    • 逐台校准天线延迟并烧录
    但要设一个止损点
    如果实测发现大面积 NLOS，应该及早换方案（激光 SLAM、视觉标记），而不是硬调 UWB。把「实测不达标就换方案」写进项目计划，比事后被迫返工好得多。
  2. 高级移动机器人的定位栈应该怎么分层？UWB 在里面是什么角色？

    典型是三层融合，每层补别层的短板：

    • 底层：IMU + 轮式里程计——更新率极高（kHz），提供高频相对运动与姿态。短板是积分误差累积，几十秒就漂到不能用。
    • 中层：激光 / 视觉 SLAM——提供环境相对定位，精度 1–5 cm，无需基础设施。短板是依赖环境特征，空旷或重复场景退化，算力开销大。
    • 上层：UWB（室内）/ GNSS-RTK（室外）——提供无累积漂移的全局绝对位置，把前两层拉回来。
    UWB 在栈里的独特位置
    「室内的绝对参考 + 精确时间源」。它不擅长的（高更新率、无需基础设施）由别层补；它擅长的（无累积误差、纳秒授时、不受光照粉尘影响）别层给不了——尤其授时，激光和视觉都提供不了。
    选型的三个前置问题
    ① 精度要求来自什么后果——「厘米级」若只为导航避障，激光 SLAM 就够；若是协同搬运的刚性约束才真需要 UWB。② 能不能改造环境——能装基站则 UWB 可选，不能则只能 SLAM。③ 需不需要精确时间——需要的话 UWB 的授时可能比定位更值钱，这一点最常被忽略。
  3. 高级前导码长度、更新率、功耗、精度这四者怎么权衡？

    它们是一个四角拉扯的关系，核心旋钮是前导码长度。

    测距的本质是估计信号首径的到达时刻。前导码越长 → 接收端相关积累越多 → 时刻估计越准、越抗噪 → 精度提升。但代价是每次测距占用的空口时间和能量都线性增加 → 同样功耗预算下更新率下降，或同样更新率下功耗上升。

    场景前导码更新率理由
    静态高精度（对接、标定）长（1024+）低（1 Hz）精度优先，不动就不需要高更新
    移动导航短（64/128）高（10–50 Hz）更新率优先，单次精度由融合滤波补偿
    电池标签盘点中极低（< 1 Hz）功耗优先；改用 TDoA 让标签只发不收
    还有一个容量维度
    TWR 模式下每次测距都要占用空口做多次交互，标签数 × 更新率 = 空口占用，很快就会撞到容量上限。此时要么降更新率，要么改用 TDoA（标签只广播一次，容量提升一两个数量级），代价是必须解决基站间的纳秒级同步。这个「容量墙」是 UWB 方案规模化时最先撞上的约束，规划时要按目标标签数先算一遍空口预算。
  4. 高级把 UWB 接入安全功能（人员防护）时，有哪些额外要求？

    一旦测距结果用于安全决策（人员接近则减速/停机），要求就从「定位精度」升级到「功能安全 + 信息安全」两条线。

    信息安全：必须启用 STS
    否则攻击者可用距离缩短攻击伪造「人还很远」，让机器人不减速。必须走 802.15.4z 的安全测距模式，不能用裸 4a。
    功能安全：要按失效导向设计
    关键是误差方向：NLOS 误差是单向正偏（测得比实际更远）——这恰恰是危险方向，因为「以为人还远」。所以不能简单用测距值，必须：① 用置信度低就按最坏假设处理（测不准就当人很近）；② 测距超时/丢失要当作「人可能很近」而非「人不在」——失效必须导向安全侧。
    架构上的补充
    UWB 不应作为唯一的安全手段。按 功能安全的思路，安全回路应该有独立的硬件通道（安全激光扫描仪、安全继电器、STO），UWB 作为「提前预警 + 身份识别」的增强层，而不是唯一依据。凡是「软件测出来的距离」都不应该是最后一道防线。
