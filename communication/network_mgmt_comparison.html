网络管理协议对比：NETCONF / RESTCONF / SNMP / gNMI

管理面不止 NETCONF。做横向比较：SNMP（老监控王）、NETCONF（配置强、事务化）、RESTCONF（NETCONF 的 REST 化）、gNMI（gRPC 流式遥测）。重点是它们在配置/状态/数据模型/实时性/可编程性/场景上的取舍，而非每个协议的所有细节。

Module 07 阅读 ~20 min 横向对比
01

四个协议一句话

先建立第一印象

SNMP

90 年代的经典监控协议。擅长读监控（get/trap）、拙于复杂配置。用 MIB 建模，UDP 承载。

NETCONF

配置强、事务化（candidate/commit），YANG 建模，XML/RPC，SSH/TLS。运营商/电信主流。

RESTCONF

把 NETCONF 的能力用 REST/HTTP + JSON/XML 暴露，对 Web/自动化友好，复用 YANG。

gNMI

Google 主导，gRPC + Protobuf，强在高频流式遥测（streaming telemetry），云原生/大规模数据中心常用。

关键洞察：它们大多共享 YANG 数据模型，区别主要在"传输 + 编码 + 交互范式"。这再次印证 Module 01 的思想——数据模型（YANG）与传输机制（NETCONF/RESTCONF/gNMI）是两个正交维度。
02

SNMP

监控之王，配置之短

  • 建模：MIB（OID 树）。承载：UDP（161 查询 / 162 trap）。
  • 强：读状态、告警 trap，设备普遍支持，轻量。
  • 弱：写配置能力差、无事务、安全较弱（v1/v2c 明文，v3 才加密）、大规模数据低效。
  • 现状：监控存量仍广泛，但新配置管理已让位给 NETCONF/gNMI。
03

NETCONF

配置管理的电信主力

  • 建模：YANG。承载：XML/RPC over SSH(830)/TLS。
  • 强：复杂配置、事务（candidate/commit/confirmed-commit）、锁、校验、丰富操作、安全。
  • 弱：XML 相对冗长；高频遥测不是它的强项。
  • 场景：运营商网络、O-RAN O1、前传 M 平面。详见 NETCONF 工程实践。
04

RESTCONF

NETCONF 的 REST 化身

  • 建模：同样 YANG。承载：HTTP(S) + JSON/XML，用 URL 定位数据节点，用 HTTP 动词（GET/POST/PUT/PATCH/DELETE）对应操作。
  • 强：对 Web/DevOps 工具链友好（curl 就能玩）、易集成。
  • 弱：没有 NETCONF 那么完整的事务/锁语义（简化版）。
# RESTCONF 读一个接口配置（对比 NETCONF 的 XML RPC）
GET /restconf/data/example-interfaces:interfaces/interface=eth0
Accept: application/yang-data+json
05

gNMI

为流式遥测而生

  • 建模：YANG（用 OpenConfig 模型居多）。承载：gRPC + Protobuf（HTTP/2）。
  • 强：Subscribe 流式遥测（设备按周期/变化持续推指标）——比 SNMP 轮询高效得多；二进制编码紧凑、性能好。
  • 操作：Get / Set / Subscribe / Capabilities。
  • 场景：大规模数据中心、云原生网络、需要高频监控的场合。
gNMI 的 Subscribe 是它相对 NETCONF/SNMP 的杀手锏：几万台设备每秒推一次关键指标，用 gRPC 流比逐个 poll 高效得多。

07

怎么选

场景驱动

  • 复杂配置 + 事务 + 电信/O-RAN → NETCONF。
  • Web/DevOps 集成、简单增删改查 → RESTCONF。
  • 大规模高频遥测 → gNMI。
  • 存量监控/告警 → SNMP（新项目少选它做配置）。
面试："NETCONF vs SNMP 有什么区别？"
答：SNMP 强于监控轮询、弱于配置、无事务、安全弱、MIB 建模；NETCONF 用 YANG 建模、强于复杂配置、有事务(candidate/commit)、走 SSH/TLS 更安全。现代网络配置管理已从 SNMP 转向 NETCONF/gNMI，SNMP 主要留在存量监控。
🎯 本篇要点回顾
  • 四者多共享 YANG，区别主要在传输+编码+交互范式
  • SNMP=监控强配置弱；NETCONF=配置强事务化；RESTCONF=REST 化；gNMI=流式遥测
  • O-RAN O1 选 NETCONF/YANG（+VES 遥测）
  • 选型看场景：配置事务→NETCONF，Web→RESTCONF，遥测→gNMI
