高性能通信：Ring Buffer / Zero Copy / Lock-Free

前传每秒要处理海量 IQ 数据、核心网要扛百万 PPS。本篇讲通信软件的性能利器：环形缓冲、无锁队列、零拷贝、内存池、批处理与 Cache 友好，并串成一条 NIC→处理→发送的高性能收发链路。面向 C/C++ 与嵌入式。

Module 09 阅读 ~24 min 低延迟 / 高吞吐
01

为什么普通写法不够快

性能杀手清单

  • 频繁内存分配：每包 malloc/free → 碎片 + 锁争用 + 不确定延迟。
  • 数据拷贝：内核↔用户态、层层 memcpy → 浪费 CPU 和内存带宽。
  • 锁争用：多线程抢一把锁 → 上下文切换、串行化。
  • Cache miss：数据结构不友好 → CPU 空等内存（几百周期）。
  • 逐包系统调用：每包一次 syscall → 开销大。
通信系统追求的是低延迟 + 确定性 + 高吞吐，上面每一项都要针对性优化。下面逐个拆。
02

Ring Buffer 环形缓冲

生产者-消费者的基石

Ring Buffer：固定大小的数组，用读/写两个下标（head/tail）循环使用。写到末尾就绕回开头。预分配、无需动态内存、天然生产者-消费者。

网卡驱动收包用的就是 RX ring；应用内部线程间传消息也常用它。容量取 2 的幂，下标用位与取模，极快。

// 单生产者单消费者 (SPSC) 环形队列骨架
template<typename T, size_t N>  // N 为 2 的幂
struct RingSPSC {
    T buf[N];
    std::atomic<size_t> head{0}, tail{0};   // 生产写 tail, 消费读 head
    bool push(const T& v) {
        size_t t = tail.load(std::memory_order_relaxed);
        if (((t + 1) & (N-1)) == head.load(std::memory_order_acquire))
            return false;                     // 满
        buf[t & (N-1)] = v;
        tail.store(t + 1, std::memory_order_release);
        return true;
    }
    bool pop(T& out) {
        size_t h = head.load(std::memory_order_relaxed);
        if (h == tail.load(std::memory_order_acquire)) return false; // 空
        out = buf[h & (N-1)];
        head.store(h + 1, std::memory_order_release);
        return true;
    }
};
03

Lock-Free 无锁队列

用原子操作代替锁

上面的 SPSC ring 已经是无锁的——靠 atomic + 内存序（acquire/release）保证可见性，避免互斥锁的开销和阻塞。

Lock-Free：多个线程并发操作，无需互斥锁，靠 CAS(compare-and-swap)/原子变量协调。优点：无锁竞争阻塞、延迟确定；缺点：难写易错（ABA 问题、内存序）。
  • SPSC（单生产单消费）最简单最快，前传/网卡场景常用。
  • MPMC（多生产多消费）复杂，一般用成熟库（如 moodycamel、DPDK rte_ring）。
  • 关键：正确的 memory_order，以及避免伪共享（head/tail 放不同 cache line）。
04

Zero Copy 零拷贝

别搬数据

Zero Copy：减少/消除数据在内核态与用户态、各缓冲区之间的拷贝，让数据"原地"被处理或直接 DMA 到目的地。
  • 内核技术：sendfile、splice、mmap —— 文件/socket 间直接传，不经用户态。
  • 用户态网络栈：DPDK / RDMA 把网卡数据直接 DMA 到用户态大页内存，绕过内核协议栈，是前传/高频交易的常用手段。
  • 做法：传指针/偏移而非拷贝内容；用引用计数管理共享缓冲。
前传/核心网转发面为了极致吞吐常用 DPDK：内核旁路 + 轮询 + 大页 + 零拷贝，单核就能转发数百万包/秒。
05

Memory Pool 内存池

预分配复用

Memory Pool：启动时一次性分配一大块内存，切成固定大小的块，运行期从池里"借还"而非 malloc/free。消除运行时分配的延迟抖动与碎片。

配合 Ring Buffer 用：包缓冲从内存池取，处理完归还。DPDK 的 mbuf pool 就是这个思路。

06

Batch & Cache 友好

摊薄开销 + 榨干 CPU

  • 批处理 Batch：一次收/发/处理一批包（如 recvmmsg、批量出队），把 syscall/同步开销摊到多个包上。
  • Cache 友好：结构体紧凑、按 cache line(64B) 对齐、避免伪共享；顺序访问优于随机；热数据聚在一起。
  • 预取 Prefetch：提前把下一个要处理的包拉进 cache（__builtin_prefetch）。
  • CPU 亲和 + NUMA：线程绑核、内存就近分配，避免跨 NUMA 访问。
07

收发全链路

把技术串起来

  • 网卡 DMA 把包写进 RX ring（零拷贝，缓冲来自内存池）。
  • 收包线程批量取出、按 协议分帧，通过无锁队列交给 worker。
  • worker 处理后放 TX ring，网卡 DMA 发出。全程不 malloc、不加锁、少拷贝。
这正是 DPDK/前传转发面的经典架构：Ring + Pool + Lock-Free + Zero Copy + Batch + Cache 友好，共同实现低延迟、高吞吐、确定性。
🎯 本篇要点回顾
  • 性能杀手：分配、拷贝、锁、cache miss、逐包 syscall
  • Ring Buffer：预分配、生产者-消费者基石
  • Lock-Free：原子操作代替锁，SPSC 最简；防伪共享
  • Zero Copy：sendfile/splice、DPDK/RDMA 内核旁路
  • 内存池 + 批处理 + cache 对齐 + 绑核 = 确定性低延迟
本篇讲的是"数据结构与单机手法"，还有一层是"模型与规模"。ring buffer、无锁队列、内存池解决的是每包开销；但"该开多少线程、会话怎么分片才能保证同会话有序、过载时怎么优雅劣化、单机到头之后状态往哪放"是另一组问题，而且海量连接 / 高报文率 / 低尾延迟三个目标的手段常常互相冲突（批处理是高报文率的头号手段，也是低尾延迟的头号敌人）。
