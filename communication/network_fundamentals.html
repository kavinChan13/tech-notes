Ethernet / IP / TCP / UDP：现代网络通信基础

上一篇建立了"分层"的心智模型，这一篇把它落到真正在跑的四个协议上。重点不是逐个背定义，而是理解它们如何层层配合，以及在真实通信系统里 TCP 和 UDP 到底该怎么选。

Module 01 阅读 ~34 min TCP vs UDP 粘包/拆包
01

一条数据的四层旅程

Ethernet → IP → TCP/UDP → Application 的配合

把上一篇的封装图落到具体协议：应用数据被 TCP/UDP 加上端口、被 IP 加上地址、被以太网加上 MAC，最后变成线上的信号。四个协议各司其职、层层嵌套：

Application决定数据"是什么意思"（HTTP、DNS、NETCONF…）
TCP / UDP用端口区分进程；TCP 额外负责可靠、有序、流控
IP用IP 地址做跨网络寻址与路由
Ethernet用MAC 地址在一段链路内投递帧
一个直觉：IP 负责"送到哪台主机"，端口负责"送到主机里的哪个程序"，MAC 负责"这一跳交给谁"。三种地址解决三个不同粒度的"给谁"。
02

Ethernet 与 MAC：链路层的投递

帧格式、MAC 地址、广播域

以太网（Ethernet）是今天最主流的有线链路层技术，无论数据中心还是 5G 前传都在用它。它工作在一段"链路"内，用 48 位的 MAC 地址标识网卡。

MAC 地址：网卡出厂即固化的 48 位硬件地址（如 a4:5e:60:...）。它是"物理身份证"，只在本地链路内有意义；跨网段投递靠 IP，不靠 MAC。

一个以太网帧的骨架（简化）：

+-----------+-----------+--------+-------------------+--------+
| 目的 MAC  | 源 MAC    | 类型   |      Payload      |  CRC   |
|  6 字节   |  6 字节   | 2 字节 |  46 ~ 1500 字节   | 4 字节 |
+-----------+-----------+--------+-------------------+--------+
                                  ↑ 这里装的通常是一个 IP 包
  • 类型字段：标明 Payload 里装的是什么（0x0800=IPv4，0x86DD=IPv6，0x8100=VLAN 标签…）。这正是"上层协议"与"下层承载"的接口。
  • CRC：帧尾校验，检测传输错误（错了直接丢，不重传——重传是上层的事）。
  • 广播域：同一以太网段内可以广播；跨网段需要路由器。VLAN 就是用来切分广播域的（见 下一篇）。
03

IP 与端口 Port

跨网络寻址 + 进程多路复用

IP（网络层）解决的是"如何跨越许多段链路，把包送到目标主机"。它是无连接、尽力而为的——不保证送达、不保证顺序，可靠性留给上层。

IP 地址：主机的网络身份

IPv4 是 32 位（192.168.1.10），IPv6 是 128 位。路由器根据目的 IP 逐跳转发。IP 只管"送到哪台主机"。

端口 Port：进程的门牌号

16 位（0~65535）。同一台主机上跑着浏览器、SSH、数据库……包到了主机后靠端口决定交给哪个进程。IP+Port 合起来叫 Socket 地址。

Socket：操作系统提供的网络编程抽象，一个 socket ≈ (协议, 本地 IP:Port, 远端 IP:Port)。你 send()/recv() 的对象就是它。一条 TCP 连接由五元组唯一确定：协议 + 源 IP + 源 Port + 目的 IP + 目的 Port。
面试常问："两个不同客户端连到服务器的同一个端口 80，服务器怎么区分？"答案：靠五元组——虽然目的 IP:Port 相同，但源 IP:Port 不同，内核据此区分成不同连接。Socket 编程细节见 Socket 网络编程 与 Linux 网络编程。
04

TCP：为什么可靠

连接、序号、确认、重传、流控、拥塞控制

TCP 在"不可靠的 IP"之上，用一整套机制造出一条"可靠、有序的字节流"管道。它的可靠不是魔法，而是这几件事叠加：

机制解决什么怎么做
连接管理双方建立/释放共识三次握手建连、四次挥手断连
序号 + 确认(ACK)知道哪些到了、哪些丢了每个字节有序号，接收方回 ACK
超时/快速重传丢包恢复没收到 ACK 就重发
校验和检测损坏校验错的段丢弃并重传
滑动窗口流量控制（别压垮接收方）接收方通告可用缓冲区大小
拥塞控制别压垮网络慢启动 / 拥塞避免 / BBR 等

三次握手 & 四次挥手（一图记住）

为什么建连要三次而不是两次？
答：两次无法让"服务器确认客户端也能收到"。三次才能让双方都确认对方的收发能力都正常，避免历史重复连接请求造成的错误建连。
TIME_WAIT 是干嘛的？
答：主动关闭方等 2·MSL，确保最后的 ACK 对方能收到、且旧连接的迷途报文在网络中消散，避免影响新连接。高并发短连接下 TIME_WAIT 过多是常见工程问题。
05

UDP：为什么低开销

无连接、不可靠、但快而简单

UDP 几乎是"在 IP 上薄薄加了个端口"：8 字节头，无连接、无握手、不保证送达、不保证顺序、不做流控。正因为"什么都不管"，它开销极小、延迟极低。

UDP 头（仅 8 字节）：
+----------+----------+--------+----------+
| 源端口   | 目的端口 | 长度   | 校验和   |
+----------+----------+--------+----------+
对比 TCP 头至少 20 字节 + 握手往返 + 状态维护

UDP 的优势

  • 无握手 → 零 RTT 起步延迟
  • 头小、无状态 → 省带宽、省内存
  • 一发一收，实现简单
  • 应用可自定义可靠性策略（想要什么补什么）

UDP 的代价

  • 可能丢包、乱序、重复
  • 无流控/拥塞控制 → 需应用自己节制
  • 可靠性要自己在应用层实现（如 QUIC、RTP）
为什么实时数据爱用 UDP？语音/视频/游戏里，"迟到的数据"比"丢一点数据"更糟——一帧旧画面重传过来已经没用了。宁可丢、不可等，所以选 UDP 并在应用层做补偿。5G 前传的 eCPRI 用户面同样是"实时优先"，也倾向无连接承载。
06

TCP vs UDP：工程上怎么选

这是通信软件里几乎每天都要做的决策

维度TCPUDP
连接面向连接（先握手）无连接
可靠性可靠、有序、不丢不重尽力而为，可能丢/乱序
头开销≥ 20 字节 + 状态8 字节，无状态
延迟握手 + 拥塞控制引入延迟低、可预期
流控/拥塞内置无（需自理）
适用文件、网页、配置管理、RPC语音/视频、游戏、DNS、遥测、前传
选型口诀："数据不能错、可以稍慢"→ TCP；"数据要快、旧了就丢"→ UDP。本主题里，NETCONF 管理面走 TCP（要可靠配置），而 eCPRI 用户面/实时遥测偏向无连接（要低延迟确定性）——这正是"协议选择服务于业务特性"的典型例子。
07

TCP 粘包 / 拆包与 message framing

初学者最常踩的坑，也是二进制协议设计的起点

很多人以为 send() 一次、对端 recv() 一次就能拿到"一条完整消息"。错。TCP 是字节流，没有"消息边界"的概念。你发的 3 条消息，可能被合并成一次收到（粘包），也可能一条消息被拆成两次收到（拆包）。

解决办法就是message framing（消息分帧），三种经典做法：

  1. 定长：每条消息固定 N 字节。简单但浪费/不灵活。
  2. 分隔符：用特殊字节（如 \r\n）分界。文本协议常用，但正文不能含分隔符。
  3. 长度前缀（TLV/LV）：消息头里放"后面还有多少字节"。二进制协议的主流做法。
UDP 不存在粘包问题——它保留消息边界（一个 sendto 对应一个 recvfrom），但每个数据报有大小上限。粘包本质是"TCP 是流不是消息"。如何设计带长度前缀的二进制协议，见 二进制通信协议设计与解析。
08

延迟 / 吞吐 / 抖动 / 带宽

评价一个通信系统好坏的四个核心指标

这四个词在通信系统里几乎无处不在（尤其 5G 前传对它们极其敏感），必须分清：

指标含义类比单位
带宽 Bandwidth链路理论最大传输能力马路有几车道bps（Gbps…）
吞吐 Throughput实际达到的传输速率实际每秒过多少车bps
延迟 Latency一个包从发到收的时间一辆车走完全程用时ms / µs
抖动 Jitter延迟的波动（不稳定程度）每辆车用时忽长忽短ms / µs

带宽 ≠ 吞吐

10 Gbps 带宽的链路，实际吞吐可能只有 6 Gbps——受协议开销、丢包重传、拥塞、对端处理能力限制。带宽是上限，吞吐是现实。

低延迟 ≠ 高吞吐

两者常常要权衡。批量攒一波再发能提升吞吐，却增加延迟；一有数据就发延迟低，却牺牲吞吐。通信系统设计常在两者间取舍。

为什么这四个指标对 5G 前传是"生死线"？前传（DU↔RU）传的是无线基带的实时 IQ 数据，延迟要求低到 ~100 µs 级、抖动要极小、带宽需求巨大（Massive MIMO）。这正是 CPRI 带宽压力、eCPRI 出现、以及 PTP/SyncE 时间同步的根本动因——后面 前传/中传/后传 与 PTP/SyncE 会展开。
🎯 本篇要点回顾
  • IP 找主机、端口找进程、MAC 找网卡；一条 TCP 连接由五元组确定
  • TCP 的可靠 = 连接 + 序号/ACK + 重传 + 校验 + 流控 + 拥塞控制
  • UDP = "IP + 端口"，无连接低开销，实时数据首选
  • TCP 是字节流会粘包/拆包，必须自己做 framing（长度前缀最常用）
  • 带宽/吞吐/延迟/抖动是评价通信质量的四把尺子，前传对它们极敏感
