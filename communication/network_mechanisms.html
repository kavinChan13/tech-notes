网络中的常见机制：VLAN / QoS / 路由 / 数据包

前两篇讲了"协议是什么、四层怎么配合"。这一篇回答一个更具体的问题：一个数据包在真实网络里到底是怎么一跳一跳走到目的地的？沿途会遇到 ARP、路由、VLAN、QoS、MTU 这些机制——它们也是理解 5G 传输网（前传/中传/后传承载网）的基础。

01

主线：一个包怎么走完全程

先看全景，再逐个机制拆解

假设主机 A（192.168.1.10）要访问另一个网段的服务器 B（10.0.0.5）。这个包不是"直达"的，而是被一台台设备接力：

最重要的直觉：IP 地址是"最终目的地"，全程不变；MAC 地址是"下一跳交给谁"，每经过一个路由器就被改写。交换机看 MAC 在同网段内转发，路由器看 IP 在网段间转发。理解这一点，整个网络世界豁然开朗。
02

ARP：从 IP 找 MAC

L3 地址与 L2 地址之间的桥

主机 A 知道要发给某个 IP，但链路层投递需要 MAC 地址。谁来把"IP → MAC"翻译出来？答案是 ARP（Address Resolution Protocol）。

ARP：在本地链路上广播"谁是 192.168.1.1？把你的 MAC 告诉我"，持有该 IP 的设备单播回复自己的 MAC。结果缓存在 ARP 表里（arp -a 可查），避免每次都问。
  • 目标在同网段 → 直接 ARP 出对方 MAC，帧的目的 MAC = 对方。
  • 目标在不同网段 → ARP 出默认网关的 MAC，帧先交给网关（路由器）。
这解释了"目的 MAC 逐跳改写"：A 发给 B（跨网段）时，帧的目的 MAC 其实是网关的 MAC，而不是 B 的。到了网关，路由器查路由表、把帧的目的 MAC 换成下一跳的 MAC，如此接力。
03

路由：跨网段转发

路由器如何决定"往哪个口送"

路由器的核心工作是查路由表：根据目的 IP，用"最长前缀匹配"找到对应的下一跳和出接口。

目的网段          下一跳          出接口
10.0.0.0/8       10.0.0.1        eth1
192.168.1.0/24   直连            eth0
0.0.0.0/0        203.0.113.1     eth2   ← 默认路由（其他都走这）

交换（L2）vs 路由（L3）

交换机在一个网段内按 MAC 转发（学习 MAC 表）；路由器连接不同网段，按 IP 转发。5G 传输网里，前传/中传/后传本质就是不同规模的 L2/L3 承载网。

静态 vs 动态路由

小网用静态路由手工配；大网用 OSPF/BGP 等协议自动学习拓扑、算最优路径。运营商核心网大量使用动态路由 + MPLS/SR 做流量工程。

04

VLAN：在一根线上切分广播域

逻辑隔离，不用为每个网络单独拉线

默认情况下，一个交换机下的所有口在同一个广播域——广播风暴、安全隔离都成问题。VLAN（Virtual LAN）用一个 12 位的 VLAN ID（802.1Q 标签）把一台物理交换机逻辑切分成多个互相隔离的网络。

带 VLAN 标签的以太网帧（802.1Q）：
+---------+---------+-----------+--------+---------+-------+
| 目的MAC | 源MAC   | 802.1Q Tag| 类型   | Payload | CRC   |
+---------+---------+-----------+--------+---------+-------+
                     ↑ 4 字节，含 VLAN ID + 优先级(PCP)

VLAN 解决什么

  • 隔离：不同 VLAN 间默认不能直接通信（要经路由）
  • 缩小广播域：抑制广播风暴
  • 灵活：按业务/租户划分，不受物理位置限制

通信系统里的应用

  • 用 VLAN 把管理面 / 用户面 / 同步流量隔离在不同虚网
  • O-RAN 前传网常用 VLAN + 优先级区分 C/U/S/M 平面流量
注意 802.1Q Tag 里还有 3 位 PCP（优先级）——这就衔接到下一个机制 QoS。前传网靠它保证实时流量优先。
05

QoS：拥塞时谁先走

带宽有限，就得排优先级

QoS（Quality of Service）是一组"在网络拥塞时按重要性区别对待流量"的机制。没有 QoS，语音包和下载包平等排队——语音就会卡。

层次标记字段说明
L2（以太网）802.1p PCP（3 位）VLAN 标签里的优先级，0~7
L3（IP）DSCP（6 位，在 IP 头）DiffServ，跨路由器的端到端优先级

QoS 的典型手段：分类（classification）→ 标记（marking）→ 排队/调度（queuing）→ 整形/限速（shaping/policing）。核心是"关键流量走高优先级队列，优先调度、优先保带宽"。

为什么前传网对 QoS 极度依赖？前传上同时跑着超低延迟的实时用户面（eCPRI IQ 数据）、时间同步（PTP）、和管理面（NETCONF）。它们的延迟/丢包容忍度天差地别，必须靠 VLAN + QoS 严格隔离并优先保障同步与用户面。这条线索会在 O-RAN 三平面 里再次出现。
本节讲的是传输网视角的 QoS（DSCP、PCP、队列调度）。3GPP 另有一套独立的、更精细的 QoS 模型——5QI / QoS Flow / DRB，它规定的不只是优先级，还包括空口资源保障。两套标签必须对齐，否则"空口保障了、回传照样抖"。完整链条见 Module 03 QoS、网络切片与边缘：端到端服务质量如何落地。
06

MTU 与分片

一个帧最多能装多少，装不下怎么办

MTU（Maximum Transmission Unit）：链路层一帧能承载的最大载荷，标准以太网是 1500 字节。数据中心/传输网常开 Jumbo Frame（~9000 字节）以降低开销、提升吞吐。
  • IP 包超过 MTU → 需要分片（fragmentation），到目的地再重组；分片会增加开销、放大丢包影响，通常尽量避免。
  • Path MTU Discovery：探测端到端路径上最小的 MTU，按它来发，避免中途分片。
  • TCP 用 MSS（= MTU − IP头 − TCP头）协商每段最大数据量。
前传承载常用 Jumbo Frame：eCPRI 承载大带宽 IQ 数据，大帧能显著降低"每帧固定开销"的占比，提升有效吞吐。这也是"带宽效率"话题的一部分（见 CPRI/eCPRI 演进）。
07

IPv4 vs IPv6

地址耗尽与协议简化

维度IPv4IPv6
地址长度32 位（~43 亿）128 位（几乎无限）
表示192.168.1.12001:db8::1
头部可变、含校验和定长、更简洁、无校验和（交给上层）
分片路由器可分片只在源端分片（路由器不分片）
配置DHCP / 手工支持 SLAAC 无状态自动配置
NAT普遍需要（地址不够）地址充足，弱化 NAT
5G 核心网与现代传输网大量采用 IPv6（及 SRv6 做流量工程）。理解 IPv6 的"头部简化、源端分片"有助于后面理解低开销承载的设计取向。
08

串起来：一次端到端追踪

把所有机制放回同一个故事

现在把本篇机制串成一个完整故事——A（192.168.1.10）访问 B（10.0.0.5）：

  1. A 发现 B 不在本网段 → ARP 出默认网关的 MAC。
  2. 封装帧：目的 IP=B，目的 MAC=网关。若走 VLAN，打上 VLAN 标签 + QoS 优先级。
  3. 交换机按 MAC 把帧送到网关口。
  4. 路由器查路由表，确定下一跳；若包超 MTU 则分片；改写目的 MAC 为下一跳，转发出去。
  5. 逐跳重复，直到最后一跳路由器 ARP 出 B 的 MAC，投递给 B。
  6. B 收到 → 逐层解封装（去以太网头 → 去 IP 头 → 去 TCP 头）→ 交给应用。
🎯 本篇要点回顾
  • IP 全程不变（送到哪），MAC 逐跳改写（这跳交给谁）
  • ARP 把 IP 翻译成 MAC；交换机看 MAC、路由器看 IP
  • VLAN 逻辑切分广播域，QoS 在拥塞时按优先级区别对待
  • MTU 限制帧大小，超了要分片；传输网常用 Jumbo Frame
  • 这些机制正是 5G 前传/中传/后传承载网的地基
