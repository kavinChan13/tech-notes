NETCONF / YANG：网络设备如何被配置和管理

管理面的主角来了。O-RAN 的 O1 接口和前传 M 平面都用 NETCONF/YANG——它俩到底谁干什么？这一篇把最容易混淆的一对概念讲透：YANG 定义"数据长什么样"，NETCONF 定义"怎么操作和传输这些数据"，并配上真实的 XML/RPC 例子。

Module 07 阅读 ~28 min 管理面核心
01

先讲清一件事

NETCONF 和 YANG 的分工

🍽 生活类比：餐厅点菜

YANG = 菜单的"格式规范"：规定菜单该有哪些字段（菜名、规格、可选配料、价格范围、哪些是必选）。NETCONF = 你和服务员的"交互协议"：怎么点菜（下单）、怎么查看当前订单、怎么改单、怎么确认。菜单定义结构（YANG），点菜流程操作数据（NETCONF）。

YANG：数据建模语言——定义设备的配置/状态数据有哪些字段、层级、类型、约束。
NETCONF：网络管理协议——定义如何获取、修改、提交、传输这些数据（一套基于 XML 的 RPC）。
核心关系：YANG → 定义数据模型（schema）；NETCONF → 操作并传输符合该模型的数据（instance）。二者是"schema 与 protocol"的关系，缺一不可。
02

为什么需要 YANG

从 SNMP/CLI 的痛点说起

在 YANG 之前，网络设备管理有两大老办法，各有硬伤：

  • CLI（命令行）：人友好，但机器难解析、各厂商语法不同、无标准结构，自动化困难。
  • SNMP + MIB：有结构（MIB），但擅长"读监控"、不擅长"复杂配置"，事务性弱、写操作差。

网络自动化时代需要的是：结构化、强类型、有约束、跨厂商一致、机器可读、支持复杂配置和校验的数据模型。这正是 YANG 的设计目标。

YANG 让"配置"从"一堆命令字符串"变成"一棵有类型、有约束、可校验的结构化数据树"。厂商用 YANG 发布自己设备的模型，管理系统据此自动生成/校验配置——这是网络可编程化的地基。
03

YANG：数据建模语言

看一个真实的 YANG 片段

YANG 用 container / list / leaf / leaf-list 等语句把数据组织成一棵树，并给每个字段定类型和约束：

// 一个简化的接口配置模型
module example-interfaces {
  namespace "urn:example:interfaces";
  prefix if;

  container interfaces {
    list interface {
      key "name";                    // 以 name 作为列表主键
      leaf name   { type string; }
      leaf enabled{ type boolean; default true; }
      leaf mtu    { type uint16 { range "68..9000"; } }   // 类型 + 约束
      leaf-list ip { type string; }
    }
  }
}
  • container：分组（无键的容器）。
  • list：可重复条目集合，需 key（像数据库表）。
  • leaf：叶子节点，一个具体字段 + 类型。
  • type / range / default：类型系统与约束——非法值（如 mtu=99999）会被拒绝。
YANG 还支持 grouping（复用）、augment（在别人的模型上扩展）、if-feature（能力开关）、rpc/notification（定义自定义操作与通知）。O-RAN 就是用 YANG 定义了 O-RU 的管理模型（o-ran-* 系列 YANG 模块）。
04

NETCONF：操作与传输

基于 XML 的 RPC over 安全传输

NETCONF 是一套基于 XML 的 RPC 协议：客户端（管理端/SMO）发 <rpc>，服务端（设备）回 <rpc-reply>。它的分层：

会话建立后，双方先交换 <hello> 声明各自支持的 capabilities（含支持哪些 YANG 模型）。之后就是一问一答的 RPC。

对照 Module 01 的封装思想：NETCONF over SSH over TCP over IP over Ethernet——NETCONF 是应用层协议，SSH/TLS 是安全传输，下面照旧是 TCP/IP/以太网。这与 eCPRI 的"薄封装、直接 over 以太网"形成鲜明对比：管理面要的是可靠与安全，不是极限低时延。传输细节见 NETCONF 工程实践。
05

核心 RPC 操作

看真实报文

<get-config>：读配置

<rpc message-id="1" xmlns="urn:ietf:params:xml:ns:netconf:base:1.0">
  <get-config>
    <source><running/></source>        <!-- 从 running 库读 -->
  </get-config>
</rpc>

<edit-config>：改配置

<rpc message-id="2" xmlns="urn:ietf:params:xml:ns:netconf:base:1.0">
  <edit-config>
    <target><candidate/></target>        <!-- 改到 candidate 库 -->
    <config>
      <interfaces xmlns="urn:example:interfaces">
        <interface>
          <name>eth0</name>
          <mtu>9000</mtu>                  <!-- 符合 YANG 约束 -->
        </interface>
      </interfaces>
    </config>
  </edit-config>
</rpc>
操作作用
<get>读取配置 + 状态数据
<get-config>只读配置数据（指定 datastore）
<edit-config>修改配置（merge/replace/create/delete）
<copy-config> / <delete-config>整库复制 / 删除
<lock> / <unlock>锁定 datastore，防并发冲突
<commit>把 candidate 提交到 running（事务）
06

Datastore 与通知

配置的"三个抽屉" + 主动上报

running

当前正在生效的配置。

candidate

草稿：先改这里，commit 后才生效。支持"改好一起提交"的事务。

startup

开机加载的配置（掉电保存）。

为什么要 candidate + commit？因为复杂配置往往要"一批改动一起生效"，中途半套配置可能让设备异常。candidate 让你先改草稿、校验无误再原子提交；还可配合 confirmed-commit（超时未确认自动回滚），避免把自己"配断网"。

Notification：设备主动上报

<notification xmlns="urn:ietf:params:xml:ns:netconf:notification:1.0">
  <eventTime>2026-08-12T09:00:00Z</eventTime>
  <link-down xmlns="urn:example:events">
    <interface>eth0</interface>
  </link-down>
</notification>

客户端可订阅事件流，设备在故障/状态变化时主动推送 notification——这就是管理面"监控/告警"的来源（O-RAN O1 里配合 VES 遥测）。

07

NETCONF vs YANG

一表终结混淆

维度YANGNETCONF
是什么数据建模语言（schema）网络管理协议（protocol）
回答"数据长什么样""怎么操作/传输数据"
产物.yang 模型文件<rpc>/<rpc-reply> XML 报文
类比菜单格式 / 数据库表结构点菜流程 / SQL 操作
独立性可被 NETCONF/RESTCONF/gNMI 复用依赖某个数据模型来传输
面试："NETCONF 和 YANG 什么关系？"
答：YANG 是数据建模语言，定义配置/状态的结构与约束；NETCONF 是承载协议，用 XML RPC 去获取/修改/提交符合 YANG 模型的数据。一个定义"数据长什么样"，一个负责"操作和搬运数据"。同一份 YANG 模型也能被 RESTCONF、gNMI 复用（见 管理协议对比）。
🎯 本篇要点回顾
  • YANG=数据模型(schema)，NETCONF=操作+传输协议(XML RPC)
  • YANG 用 container/list/leaf + 类型/约束把配置建成结构化树
  • NETCONF 四层：Content/Operations/Messages/Secure Transport(SSH/TLS)
  • 核心操作：get/get-config/edit-config/commit/lock；三种 datastore：running/candidate/startup
  • candidate+commit 提供事务；notification 提供主动上报
